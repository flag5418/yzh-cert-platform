## 一、核心思想

```
┌─────────────────────────────────────────────────────────────────┐
│                        YZH Core 框架层                           │
│           完全脱离任何业务逻辑，可独立编译、运行                    │
│                                                                  │
│  ┌──────────┐    ┌──────────────┐    ┌───────────┐    ┌────────┐│
│  │YZH.Stand │ → │YZH.DataBase  │ → │YZH.Api    │ → │YZH.Web ││
│  │(netstd2.0)│   │(netstd2.0)   │   │Core       │   │Core    ││
│  │纯抽象类   │   │ORM/Repo抽象  │   │中间件/JWT  │   │启动入口││
│  └──────────┘    └──────────────┘    └───────────┘    └───┬────┘│
└─────────────────────────────────────────────────────────────┼─────┘
                                                              │ 引用
┌─────────────────────────────────────────────────────────────┼─────┐
│                     业务模块层（按角色物理隔离）               │     │
│                                                              │     │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐      │     │
│  │   Admin      │  │   Auditor    │  │  Enterprise  │      │     │
│  │ Entities/    │  │ Entities/    │  │ Entities/    │      │     │
│  │ Controllers/ │  │ Controllers/ │  │ Controllers/ │ ←────┘     │
│  │ Services/    │  │ Services/    │  │ Services/    │            │
│  └──────────────┘  └──────────────┘  └──────────────┘            │
└───────────────────────────────────────────────────────────────────┘
```

**关键原则**：
1. YZH Core 能脱离业务独立启动（一个空壳 Web API 跑起来）
2. 业务模块以类库形式存在，被 YZH.Web.Core 引用后自动发现控制器
3. 每个角色（Admin/Auditor/Enterprise）物理隔离在自己文件夹
4. 角色之间不互相引用，通过 Core 框架提供的基类/接口交互
5. 原 Vol 代码只读、只 COPY，不做 mv/rm

## 三、YZH Core 框架层详解

### 3.1 YZH.Core.Stand（零依赖）

```
YZH.Core.Stand/
├── Models/
│   ├── BaseEntity.cs              ← 所有业务实体基类（Id, CreateTime, 属性变更通知）
│   ├── ApiResponse.cs             ← { code, message, data } 统一响应
│   ├── PageResult.cs              ← 分页结果
│   └── PageQuery.cs               ← 分页查询参数
├── Enums/
│   ├── ControlType.cs             ← 控件类型（文本框/下拉框/表格等）
│   ├── QueryOrderBy.cs            ← 排序方向
│   └── ApiStatusCode.cs           ← API状态码
├── Annotations/
│   ├── GridConfigAttribute.cs     ← 标记实体为GridConfig驱动
│   ├── ColumnMappingAttribute.cs  ← 列名映射
│   └── AutoIncrementAttribute.cs  ← 自增字段
├── Extensions/
│   ├── ExpressionExtensions.cs    ← 表达式树扩展
│   └── StringExtensions.cs
└── YZH.Core.Stand.csproj          ← TargetFramework=netstandard2.0
```

### 3.2 YZH.Core.DataBase（依赖 Stand）

```
YZH.Core.DataBase/
├── IRepository.cs                 ← 通用仓储接口（GetList/Add/Update/Delete）
├── BaseRepository.cs              ← 通用实现（表达式树动态过滤/排序）
├── BaseDbContext.cs               ← DbContext基类
├── IAuditEntity.cs                ← 审计接口
├── filterItem.cs                  ← 过滤条件模型（field, value, method）
├── SortItem.cs                    ← 排序条件模型
└── YZH.Core.DataBase.csproj       ← TargetFramework=netstandard2.0
```

### 3.3 YZH.Core.Web（依赖 Stand + DataBase，可独立启动）

```
YZH.Core.Web/
├── YzhWebBuilder.cs               ← 静态扩展类：builder.UseYzhCore(configure)
│                                     自动注册：
│                                     - JWT认证
│                                     - CORS
│                                     - 全局异常中间件
│                                     - 控制器（扫描当前程序集）
│                                     - DI 注册 IRepository<> → BaseRepository<>
│
├── Middlewares/
│   ├── GlobalExceptionMiddleware.cs   ← 全局异常捕获 → JSON响应
│   ├── RequestLogMiddleware.cs        ← 请求日志
│   └── CorsMiddleware.cs              ← 跨域处理
├── Filters/
│   └── GlobalExceptionFilter.cs       ← 全局异常过滤器（MVC层兜底）
├── Configuration/
│   ├── JwtSettings.cs                 ← JWT配置模型
│   └── AppSettings.cs                 ← 全局配置访问
├── YzhRoleModule.cs                   ← 角色注册扩展接口
│                                         各业务项目实现此接口来注入角色特定服务
└── YZH.Core.Web.csproj                ← Microsoft.NET.Sdk.Web, net8.0
```

## 四、业务层详解

### 4.1 CertPlatform.Web（启动入口）

```csharp
// Program.cs 关键代码
var builder = WebApplication.CreateBuilder(args);

// 使用 YZH Web Core 框架（自动装配全局中间件/JWT/异常处理）
builder.UseYzhCore(options =>
{
    options.JwtSecret = builder.Configuration["Jwt:Secret"];
    options.JwtIssuer = builder.Configuration["Jwt:Issuer"];
    options.ConnectionString = builder.Configuration.GetConnectionString("Default");
});

// 注册各角色模块
builder.Services.AddAdminModule();      // CertPlatform.Admin 提供的扩展
builder.Services.AddAuditorModule();    // CertPlatform.Auditor 提供的扩展
// builder.Services.AddEnterpriseModule(); // 未来

// ... 标准 ASP.NET Core 配置
var app = builder.Build();
app.UseYzhCoreMiddleware();  // 注册Core中间件
app.MapControllers();
app.Run();
```

## 七、关键差异 vs 之前设计

| 维度 | V1（错误） | V2（正确） |
|------|-----------|-----------|
| Core 独立性 | Core 不能独立启动 | Core 可以独立启动（空壳可跑） |
| 业务模块引用 | 业务 → Core 框架 | Web.Core → 业务（反向） |
| 角色隔离 | 角色文件夹为空壳 | 角色有独立 Entities/Controllers/Services |
| 命名规范 | `Cert.Platform.Xxx` | `CertPlatform.Xxx` |
| 启动流程 | 各角色自行启动 | 统一由 CertPlatform.Web 引用所有角色 |
| 框架扩展 | 无 | 通过 `AddAdminModule()` 等扩展注册 |

## 八、实施步骤

1. **yzh-core 层重构**
   - 清理当前 4 个项目（Stand/Database/Api/Web），确保 Core 可独立编译
   - 将 `YZH.Core.Api` 合并到 `YZH.Core.Web`，简化为 3 个项目
   - 确保 `yzh-core` 能以最小 mvc 跑起来

   - 创建 `CertPlatform.Web` 作为启动入口（引用所有角色）
   - 保留已有 `CertPlatform.Admin` 内容
   - 创建 `CertPlatform.Auditor` 骨架
   - 填充 Entities/Controllers 移植

3. **编译验证**
   - 先让 yzh-core 独立编译通过
   - 再让 certplatform-api 编译通过
