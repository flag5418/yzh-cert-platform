## 一、核心思想

```
┌──────────────────────────────────────────────────────────────────────────────────┐
│                              YZH Core 框架层                                      │
│               完全脱离具体业务，提供所有项目都需要的基础能力                         │
│                                                                                  │
│  ┌────────────┐     ┌─────────────────┐     ┌──────────────────────────────────┐ │
│  │YZH.Core    │ ──→ │YZH.Core         │ ──→ │YZH.Core.Web                     │ │
│  │.Stand      │     │.DataBase        │     │ ┌──────────────────────────────┐ │ │
│  │            │     │                  │     │ │ SysUser/SysRole 实体(定义)   │ │ │
│  │ 基础模型   │     │ 仓储/ORM抽象     │     │ │ UserController               │ │ │
│  │ 枚举/特性  │     │ 查询过滤模型     │     │ │ WeChatController             │ │ │
│  │ SysUser    │     │                  │     │ │ FileOperController           │ │ │
│  │ SysRole    │     │                  │     │ │ AuthorizeController          │ │ │
│  │ SysMenu    │     │                  │     │ │ ....                         │ │ │
│  │ SysLog     │     │                  │     │ └──────────────────────────────┘ │ │
│  └────────────┘     └─────────────────┘     └──────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────────────────────┘
                                           ↑ 引用
┌─────────────────────────────────────────┼─────────────────────────────────────────┐
│                              业务模块层 │ （按角色物理隔离）                        │
│                                          │                                          │
│  ┌──────────────┐  ┌──────────────┐  ┌──┴─────────────┐                           │
│  │   Admin      │  │   Auditor    │  │  Enterprise    │                           │
│  │ Controllers/ │  │ Controllers/ │  │ Controllers/   │                           │
│  │   Platform/  │  │              │  │                │                           │
│  │ Sys/ (部分)  │  │              │  │                │                           │
│  └──────────────┘  └──────────────┘  └────────────────┘                           │
└───────────────────────────────────────────────────────────────────────────────────┘
```

**核心原则**：

1. **YZH.Core.Web 不是空壳**，它是完整的基础框架，包含：
   - 用户认证（账号密码登录、微信登录）
   - 文件上传下载（MinIO 集成）
   - 用户权限（JWT + Role 过滤）
   - 系统管理（User/Role/Menu/Dictionary/Log）
   - 代码生成辅助接口

2. **SysUser/SysRole 等实体定义在 YZH.Core.Stand**，因为任何项目都需要这些基础实体，必须足够稳定，跨项目复用

3. **角色（Admin/Auditor/Enterprise）只包含差异化的业务**，Shared 部分已在 Core 中

4. **代码生成器（YZH.Builder）** → 我们**不使用**，原因：
   - Builder 是根据数据库表自动生成 Vol 框架代码（Controller/Service/.jsx）
   - 我们已抛弃 Vol 框架，使用 GridConfig 配置驱动
   - 生成的是已经废弃的 .jsx 文件，无实际价值

## 三、YZH.Core.Stand 中的框架实体

这些实体定义为**干净 POCO**（无复杂业务逻辑），跨项目复用：

```csharp
namespace YZH.Core.Stand.FrameworkEntities
{
    [Table("Sys_User")]
    public class SysUser
    {
        [Key] public int User_Id { get; set; }
        public string UserName { get; set; }
        public string UserPwd { get; set; }      // 密文
        public int Role_Id { get; set; }
        public int? Org_Id { get; set; }
        public byte Enable { get; set; }
        public DateTime CreateTime { get; set; }
    }

    [Table("Sys_Role")]
    public class SysRole
    {
        [Key] public int Role_Id { get; set; }
        public string RoleName { get; set; }
        public byte Enable { get; set; }
    }

    [Table("Sys_Menu")]
    public class SysMenu
    {
        [Key] public int Menu_Id { get; set; }
        public string MenuName { get; set; }
        public string Url { get; set; }
        public int ParentId { get; set; }
        public string Icon { get; set; }
        public byte Enable { get; set; }
    }
    // ... SysDictionary, SysLog, SysDepartment 等
}
```

## 四、YZH.Core.Web 能力一览

| 能力 | 控制器 | 说明 |
|------|--------|------|
| 用户登录 | `UserController` | 账号登录、验证码、Token签发 |
| 微信登录 | `WeChatController` | 扫码登录、UnionID绑定 |
| 文件上传 | `FileOperController` | MinIO 上传、下载、删除 |
| 权限验证 | `AuthorizeFilter` | JWT + RoleMenu 鉴权 |
| 系统管理 | `SystemManagerController` | 用户管理、角色权限 |
| GridConfig | `GridConfigController` | UI 配置 CRUD |

这些能力业务项目**无需重写**，直接使用即可。

## 五、代码生成器（YZH.Builder）评估

| 维度 | 说明 |
|------|------|
| 功能 | 根据数据库表结构，自动生成 Vol 框架的 Controller/Service/.jsx/Repository |
| 我们是否需要 | **否** |
| 原因 | 1. 我们已抛弃 Vol 框架，不再需要生成 .jsx<br>2. UI 已改为 GridConfig 配置驱动<br>3. 业务逻辑通过 Service/Repository 手写实现 |
| 处理方式 | 保留原项目代码，**不移植**到新架构 |

## 六、项目实施路径

### Phase 1：yzh-core 独立运行（核心优先）

```
目标：只编译 yzh-core 解决方案，就能启动一个空壳 Web API

步骤：
1. YZH.Core.Stand — 定义基础模型 + FrameworkEntities（SysUser等）
2. YZH.Core.DataBase — IRepository + BaseRepository + BaseDbContext  
3. YZH.Core.Web — UseYzhCore() + FrameworkControllers + 中间件
4. 空壳 Program.cs 测试：dotnet run，返回 200 OK
```

### Phase 2：certplatform-api 业务填充

```
目标：编译 cert-platform.sln，移植全部业务

步骤：
1. 创建 CertPlatform.Web（引用 YZH.Core.Web + 业务模块）
2. 创建 CertPlatform.Admin（移植现有 Vol Admin 代码）
3. 创建 CertPlatform.Auditor（创建实体/控制器/服务）
4. 创建 CertPlatform.Business（移植 Cert.Platform/ 业务逻辑）
5. 编译验证
```

### Phase 3：集成验证

```
1. Admin 端 API 正常调用
2. Auditor 端 API 正常调用
3. 微信登录/文件上传/权限验证 工作正常
4. 数据库迁移脚本生成
```

```
原 Vol 请求流程：
Client → VolController(JsonNormal) → ServiceBase(RepositoryBase) → EF → MySQL

新 YZH 流程：
Client → YZH.Core.Web(User/Auth) → Business.Service(Repository) → EF → MySQL
                     ↑
        Admin/Auditor Controller
```
