## 三、关键决策评估

### 3.1 队列框架（Queue）— 保留在 Shared

| 维度 | 分析 |
|------|------|
| 当前用途 | Office 文档异步转换（Doc→Docx, Xls→Xlsx） |
| 是否可提取到 Core | **不建议**。虽然抽象良好，但当前和 Office 转换耦合 |
| 建议位置 | `CertPlatform.Shared/Queue/` |
| 未来规划 | 如果后续有 3+ 项目使用队列，再提取到 `YZH.Core.Queue` |

**理由**：队列框架目前只支撑 Office 文档转换这一个场景，且依赖 LibreOffice Docker 环境。其他项目（如测绘）不需要文档转换能力。留在 Shared 更安全。

### 3.2 工作流引擎（WorkflowEngine）— 保留在 Shared

| 维度 | 分析 |
|------|------|
| 与业务耦合度 | **极高**。Skill 实现直接操作认证机构/标准/审核等实体 |
| 可复用性 | 低。其他项目（测绘/房产）不需要工作流引擎 |
| 建议位置 | `CertPlatform.Shared/WorkflowEngine/` |

**理由**：`CertSkillRegistry` 中定义的 Skill（getField/getTable）完全依赖本项目的实体定义，跨项目无意义。

### 3.3 通用实体 — 保留在 Shared

| 实体分类 | 位置 | 理由 |
|---------|------|------|
| SysUser/SysRole/SysMenu/SysLog | YZH.Core.Stand | 所有项目都需要的基础实体 |
| 认证机构/标准/审核/工作流/文档 | CertPlatform.Shared.Entities | 仅认证平台需要 |

### 3.4 Controllers 分层

| Controller | 位置 | 访问者 |
|-----------|------|--------|
| User/WeChat/Auth/FileOper | YZH.Core.Web | 所有角色 |
| 认证机构/标准/审核管理 | CertPlatform.Admin | 仅管理员 |
| 审核员审核任务/NC | CertPlatform.Auditor | 仅审核员 |
| GridConfig/SysConfig/AI监控 | CertPlatform.Shared | 所有角色 |
| 企业文档提交 | CertPlatform.Enterprise | 仅企业 |

## 六、实施步骤

### Phase 1：yzh-core 独立运行（核心优先）

```
目标：只编译 yzh-core.sln，就能启动一个空壳 Web API

步骤：
1. YZH.Core.Stand — 定义基础模型 + FrameworkEntities（SysUser等）
2. YZH.Core.DataBase — IRepository + BaseRepository + BaseDbContext
3. YZH.Core.Web — UseYzhCore() + FrameworkControllers + 中间件
4. 验证 cd yzh-core && dotnet run 返回 200 OK
```

### Phase 2：certplatform-api 业务填充

```
目标：编译 CertPlatform.sln，移植全部业务

步骤：
1. 创建 CertPlatform.Web
2. 创建 CertPlatform.Shared/Entities（移植认证机构/标准等）
3. 创建 CertPlatform.Shared/Queue（移植队列框架）
4. 创建 CertPlatform.Shared/WorkflowEngine（移植工作流引擎）
5. 创建 CertPlatform.Shared/Infrastructure（移植存储/消息服务）
6. 创建 CertPlatform.Shared/{IRepositories,IServices,Repositories,Services}
7. 编译验证
```

### Phase 3：角色控制器移植

```
1. Admin 端控制器移植（认证机构/标准/审核管理）
2. Auditor 端控制器移植（审核任务/NC/报告）
3. Enterprise 端创建骨架
4. 编译 + 集成测试
```
