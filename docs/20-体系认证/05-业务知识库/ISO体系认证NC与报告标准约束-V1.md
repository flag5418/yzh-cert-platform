## 二、NC（不符合项）标准要求

### 2.1 定义

> **Nonconformity** = 未满足要求（deviation from requirement）
> — ISO 17021-1 §3.11

NC 是审核过程中发现的企业管理体系与审核准则（标准条款）之间的偏差。

### 2.2 NC 分类（ISO 17021-1 §9.4.4.2）

| 类别 | 英文 | 定义 | 本系统枚举值 |
|------|------|------|-------------|
| 严重不符合 | Major Nonconformity | 对管理体系实现或保持能力有重大影响，可能导致认证不通过 | `major` |
| 轻微不符合 | Minor Nonconformity | 与审核准则的偏差，但不影响管理体系实现能力，需限期整改 | `minor` |
| 观察项 | Observation | 潜在的不符合或改进机会，不构成NC但需关注 | `observation` |

> **注意**：ISO 17021-1 标准文本只明确区分 major 和 minor，observation 是行业实践中常见的第三类。

### 2.3 NC 记录要求（ISO 17021-1 §9.4.4.2）

每个 NC 记录**必须**包含：

| 要素 | 说明 | 本系统对应 |
|------|------|-----------|
| 审核准则 | 对应的标准条款（如 ISO 9001 §6.1） | `clause_code` 或工作流节点引用 |
| 不符合描述 | 对偏差的具体描述 | `nc_description_template`（模板）/ 运行时生成 |
| 证据 | 支撑NC的客观证据 | `ent_extraction_result`（提取结果溯源） |
| 严重度 | major / minor / observation | `severity_if_violated` |

### 2.4 NC 的来源

NC 的判定有两种模式：

| 模式 | 说明 | 本系统对应 |
|------|------|-----------|
| 自动判定 | 工作流 DAG 执行提取+比对逻辑，自动发现偏差 | `cert_validation_rule` + `wf_workflow_definition` |
| 人工判定 | 审核员在现场审核中自行发现并记录 | `audit_nonconformity`（审核执行域） |

### 2.5 NC 生命周期（ISO 17021-1 §9.4.4.2 - §9.6）

```
发现NC（审核中）
  → 记录NC（含条款+描述+证据+严重度）
  → 企业整改
  → 跟踪验证（整改有效性确认）
  → 关闭NC / 升级为major（未整改）
```

## 三、审核报告标准要求

### 3.1 报告必须内容（ISO 17021-1 §9.4.6）

| # | 内容要素 | 本系统对应 |
|---|---------|-----------|
| 1 | 审核目标 | 报告章节（如"审核目的"） |
| 2 | 审核范围 | 报告章节（如"审核范围"） |
| 3 | 审核准则 | 报告章节（如"审核依据"） |
| 4 | 审核日期和地点 | 报告章节（如"审核概况"） |
| 5 | 审核组成员 | 报告章节（如"审核组"） |
| 6 | 审核发现（符合/不符合） | 报告章节（如"审核发现"） |
| 7 | 审核结论 | 报告章节（如"审核结论"） |

### 3.2 ISO 19011 §6.6 报告内容指导

ISO 19011 提供了更详细的报告指导：
- 报告应包含审核目标、范围、准则
- 审核活动概要（时间、方法）
- 审核发现（含符合/不符合项汇总）
- 结论和建议
- 报告分发清单

### 3.3 报告模板结构（行业标准实践）

典型的认证审核报告章节：

```
1. 封面（机构信息、认证标志）
2. 审核概况（日期、地点、组员）
3. 审核目的与范围
4. 审核准则（标准条款列表）
5. 审核过程与方法
6. 审核发现（符合性陈述 + 不符合项汇总）
7. 审核结论（是否推荐认证/保持认证）
8. 改进建议（如有）
9. 附件（NC清单、整改计划）
```

## 四、对本系统设计的约束总结

### 4.1 NC 规则配置模块

| 约束 | 标准依据 | 设计决策 |
|------|---------|---------|
| NC 必须关联到标准条款 | ISO 17021-1 §9.4.4.2 | 建立独立的 ISO 条款表，NC 检查项创建时可引入条款 |
| NC 必须区分严重度 | ISO 17021-1 §9.4.4.2 | 严重度可以由工作流引擎动态决定（如"完全缺失=major，部分缺失=minor"），配置页面不强制填写 |
| NC 应有描述模板 | ISO 17021-1 §9.4.4.2 | 模板字段保留在表中，后期填充 |
| **配置与执行分离** | 设计理念（非标准强制） | 配置页面只维护检查项清单，执行逻辑由工作流 DAG 承载 |

### 4.2 报告内容配置模块

| 约束 | 标准依据 | 设计决策 |
|------|---------|---------|
| 报告必须含审核目标/范围/准则/发现/结论 | ISO 17021-1 §9.4.6 | 通过报告章节列表定义，章节对应标准要求的内容要素 |
| 不同标准/阶段有不同报告模板 | 行业实践 | 模板表关联 standard_code + phase_code |
| 报告章节可配置 | 设计理念（非标准强制） | 章节列表 CRUD + 排序 |

### 4.3 关键设计边界

| 属于配置层（本阶段开发） | 属于执行层（工作流引擎，后期开发） |
|--------------------------|-------------------------------------|
| NC检查项清单维护 | NC判定逻辑（提取→比对→判定） |
| 报告模板+章节定义 | 报告内容生成（数据填充） |
| ISO条款维护 | 条款提取规则 |
| 严重度（可选配置） | 严重度动态决定（工作流节点条件输出） |
