# 文档预览链路改造方案 V1

> **版本**：V1.0 | **日期**：2026-08-25 | **状态**：设计稿（待实施）
>
> **定位**：文档预览链路的统一改造方案——转换层 LibreOffice 转 PDF、显示层 PDF+图片双分支、提取层 anydoc+OCR 兜底，全程无人工选型节点。
>
> **前置约束**：待当前代码清理完成后，开新分支实施，不在存量代码上直接改动。

---

## 一、背景与问题

### 1.1 当前预览链路

```
Office 文件（doc/docx/xls/xlsx/ppt/pptx）
    │
    ├─ 转换：docker exec yzh-libreoffice --convert-to docx/docx → 前端 vue-office 渲染
    └─ 提取：docker exec yzh-anydoc --convert-to Markdown → 数据落库
```

### 1.2 实测诊断结论

| 环节 | 结论 |
|------|------|
| LibreOffice 转换环节 | 基本合格，非问题主因 |
| **vue-office 渲染环节** | **格式混乱主因**：表格线消失、合并单元格失效、列表编号丢失 |

vue-office 对转换产物进行二次渲染时无法还原版式，属渲染引擎能力边界，修补成本高、收益低。**结论：绕开 vue-office 的 docx/excel 渲染分支**。

---

## 二、改造目标

1. word/excel/ppt 全部经 LibreOffice 统一转 **PDF**，前端统一 PDF 显示，图片文件单独处理；
2. 数据提取走 **anydoc**，扫描版自动转 **MinerU OCR**；
3. **全程无人工选型节点**，程序按退出码自动分流。

---

## 三、总体方案

固定三层架构：

```
转换层：LibreOffice 统一转 PDF（doc/docx/xls/xlsx/ppt/pptx → PDF）
显示层：前端仅 PDF + 图片 两分支（vue-office-pdf + iframe 降级 / el-image + img 降级）
提取层：anydoc 转 Markdown（管数据）+ MinerU 自动 OCR 兜底（管扫描版）
```

- 转 PDF 后 vue-office 二次渲染环节消失，格式丢失问题不再发生；
- PDF 管显示、anydoc 管提取，双产物并行互不依赖。

## 五、边界与接受项

| 边界 | 说明 | 应对 |
|------|------|------|
| PDF 文本不可选中 | 前端 PDF 预览无法直接复制文字 | 提取走 anydoc 互补，预览与提取解耦 |
| LibreOffice 边缘失真 | 页眉字体连写、页脚重复等极少数版式瑕疵 | 接受，不影响阅读与提取 |
| 扫描版 PDF | anydoc 退出码 1 | 程序自动转 MinerU OCR，无人工干预 |
| 转换耗时 | 统一转 PDF 后大文件耗时可能增加 | 复用现有 60s 超时与队列机制 |
