# AI提示词规则-功能设计-V1

> 状态：设计定稿（V1.0，2026-08-20）
> 定位：AI 节点（ai_node）提示词的统一契约文档，前端组织/验证、后端解析/执行的唯一依据。
> 关联文档：《工作流节点定义与属性抽象-V1.md》《图形化设计器-前端组件设计方案-V2.md》（AI 节点/提示词编辑器/引擎引用解析均以本文档为契约）。

---

## 一、功能概述

AI 节点提示词是工作流中唯一允许"自然语言定义复杂逻辑"的载体。本规则定义提示词的**三段式结构、占位符语法、输出契约、编译与依赖、前端编辑器与验证、安全边界**，作为前端组织/验证提示词、后端解析/执行提示词、引擎计算依赖图的唯一依据。

- **适用范围**：`ai_node`（AI 节点）提示词；后续如引入类循环能力（如集合批量处理），同样遵循本规则。
- **定位**：复杂逻辑（循环、多条件比对、结果组装等）用**自然语言描述**实现，**不引入模板语法**（if/for 表达式等）；功能 skill 只承担参数固定、功能固定的原子功能。
- **一句话契约**：用户写"要什么结果"（用户指令）+ 引擎注入"有什么数据"（数据上下文）+ 固定"怎么输出"（系统指令），三者拼成一次 LLM 调用。

## 二、业务背景与目标

### 2.1 背景

1. 用户裁决：去掉 loop 节点；功能性 skill 只做参数固定、功能固定的原子功能。
2. 复杂循环、复杂逻辑判断、比对、组装等复杂逻辑统一由 AI 节点提示词承担，功能节点不做复杂编排。
3. 因此需要一份**固定约定**的提示词规则，使同一能力在"设计器里可编辑验证"与"引擎里可解析执行"之间语义一致。

### 2.2 目标

- **可编译**：提示词中的 `{{别名}}` 可在保存时编译为 `{{code.端口}}` 落库，可逆可查。
- **可验证**：前端保存/测试时可做引用存在性、端口可见性、无环、长度等静态校验。
- **可执行**：引擎按依赖图（边 ∪ 提示词引用）解析引用、注入真实数据、组装三段提示词、调用 LLM、按输出契约校验结果。

## 三、占位符语法（前置条件）

### 3.1 占位符表格

| 写法（编辑器内） | 编译后（落库） | 含义 | 示例 |
|-----------------|---------------|------|------|
| `{{节点别名}}` | `{{code.result}}` | 引用该节点**默认结果端口** | `{{企业名称}}` → `{{get_field_n1.result}}` |
| `{{节点别名.端口名}}` | `{{code.端口名}}` | 引用该节点指定**可见端口** | `{{企业名称.fieldValue}}` → `{{get_field_n1.fieldValue}}` |
| `{{ctx.字段}}` | `{{ctx.字段}}` | 引用运行时上下文参数（保持不变） | `{{ctx.enterpriseCode}}` |
| `{{row.列名}}` | `{{row.列名}}` | 预留：集合/行级处理时引用当前行（本版未启用） | `{{row.标准编号}}` |
| `\{{` | `\{{` | 转义：字面量输出 `{{`，不参与引用解析 | `\{{` 输出 `{{` |

### 3.2 别名规则

- 节点别名（title）：中文 / 字母 / 数字 / 下划线，**禁止包含 `.` 与 `}`**（避免与端口语法、结束符冲突）。
- 全流程内节点别名唯一；重命名不影响引用（落库为 id，仅展示层映射别名）。
- 引用目标必须是**已存在节点**；引用端口必须是该节点 **visible 端口**（目录下发端口白名单内）。

### 3.3 端口白名单与默认结果端口

- 仅**可见（visible）端口**可被提示词引用；隐藏/内部端口禁止引用。
- **默认结果端口约定**：每个节点可声明一个 `result`（或 `content`）作为默认结果端口；`{{节点别名}}` 简写只映射默认结果端口，等价于 `{{节点别名.result}}`。
- 端口类型：`signal` 信号端口不可作为数据引用目标；`string/number/boolean/json/table` 等数据端口可引用。

## 四、三段式提示词结构（业务规则）

每份 AI 节点提示词由三段组成，前端按三段存储与展示，引擎按三段拼接后调用 LLM：

| 段 | 内容 | 编辑权限 | 说明 |
|----|------|---------|------|
| **系统指令** | 固定模板：角色 + 任务类型 + 输出要求 | 用户不可编辑（系统固定） | 保证输出稳定性与 JSON 模式行为一致 |
| **数据上下文** | 引擎自动注入引用真实值 | 用户不可编辑（引擎组装） | 由 `{{引用}}` 解析后按序注入；用户只写引用，不写数据 |
| **用户指令** | 自由编辑文本，可穿插 `{{引用}}` | 用户可编辑 | 描述"要什么结果"；复杂逻辑用自然语言描述 |

**三段分离理由**：

1. **前端只验证引用存在**：校验对象集中在用户指令段，系统指令/数据上下文不受用户输入影响。
2. **后端只做占位符替换**：数据上下文由引擎按引用清单注入真实值，不解析用户自然语言。
3. **LLM 输出稳定**：系统指令固定 → 输出格式可预期；数据上下文与用户指令分离 → 注入数据不污染指令语义。

## 五、输出契约

### 5.1 输出字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `content` | string | 主输出文本（默认结果） |
| `result` | string/number/boolean/json | 结构化结果（默认结果端口，与 content 同源或由内容提炼） |
| `confidence` | number（0-1） | 置信度，可选；LLM 无法给出时填 `null` |
| `status` | `success` / `failed` | 执行状态 |
| `error` | string | 失败原因（仅 failed 时返回） |

### 5.2 JSON 模式

- 节点配置可开启 **JSON 模式开关**，并声明**输出结构描述**（如 `{"合格": boolean, "说明": string}`）。
- 开启后系统指令追加"仅输出合法 JSON，符合以下结构：<结构描述>"，引擎按结构校验。
- 未开启 JSON 模式时，仅要求 `content` 非空。

### 5.3 校验失败重试

- 输出校验失败（JSON 解析失败 / 结构不符 / content 为空）→ 重试 **N 次（默认 1）**，每次携带上次错误信息要求修正。
- 重试仍失败 → 节点标记 `failed`，**如实返回**错误（含校验失败原因），**禁止静默降级**（如丢弃 content、假装成功、用空串代替）。

## 六、编译与依赖

### 6.1 编译规则

- **前端保存时**：`{{节点别名}}` 编译为 `{{code.result}}`，`{{节点别名.端口}}` 编译为 `{{code.端口}}`；`{{ctx.*}}`、`{{row.*}}` 原样保留；转义 `\{{` 保持字面量。编译结果随工作流 JSON 落库。
- **引用清单**：编译时生成该节点提示词的引用清单 `references: [{code, port}]`，随节点配置保存，供引擎与校验使用。

### 6.2 依赖图

- 引擎依赖图 = **连线边 ∪ 提示词引用**（提示词引用可作为"隐式依赖边"，跨分支引用无需连线）。
- 执行顺序：解析占位符 → 按依赖图执行被引用节点（先于本节点完成）→ 注入真实值 → 组装三段提示词 → 调用 LLM → 输出校验。

### 6.3 注入值序列化与截断

- 注入值统一序列化为 **JSON 紧凑文本**（去空格/换行），便于 LLM 稳定解析。
- **单值截断 2000 字符**；超长时输出摘要 + 标注 `"已截断"`（例：长文本取前 2000 字符并附 `...(已截断)`），**禁止静默丢弃整个值**。
- 表格类值（rows）按"列名=值"逐行紧凑序列化，超长同样按单值截断规则处理。

## 七、前端编辑器与验证

### 7.1 编辑器能力

- **插入引用下拉**：仅列出当前画布中节点的 **visible 默认结果/端口**，显示中文别名，插入后为 `{{别名}}` 或 `{{别名.端口}}`。
- **占位符高亮**：编辑器内识别 `{{...}}` 并高亮；非法/未解析引用标红。
- 系统指令段与数据上下文段只读展示（引擎模板预览），用户指令段可编辑。

### 7.2 保存强校验（5 条）

| # | 校验 | 规则 |
|---|------|------|
| 1 | 语法闭合 | `{{` 与 `}}` 成对闭合，无嵌套 `{{` |
| 2 | 别名存在 | 每个 `{{节点别名}}` 能解析到画布内存在的节点 |
| 3 | 端口存在且 visible | 引用端口在该节点 visible 端口白名单内 |
| 4 | 引用无环 | 提示词引用关系不形成环（引用图无环） |
| 5 | 循环内引用合规 | 若存在循环/行级作用域，仅允许 `{{row.*}}` 与已执行节点引用（本版未启用循环，规则预留） |

### 7.3 长度限制

- 单节点提示词总长 ≤ **4000 字符**（三段合计）。
- 单节点提示词引用数量 ≤ **50 个**。
- 超限保存/测试时报错并定位。

## 八、安全与边界

### 8.1 占位符白名单

- 仅替换：节点输出（`{{code.端口}}`）、上下文（`{{ctx.*}}`）、预留行级（`{{row.*}}`）。
- **禁止访问**：系统 Prompt、密钥/凭据、`$sys.*`、环境变量、文件系统路径等任何系统内部对象。
- 引擎在解析时只按白名单模式替换，未命中白名单的 `{{...}}` 一律报"引用不可解析"，不执行任何取值逻辑。

### 8.2 提示词 = 数据，不执行脚本

- 提示词内容仅为 LLM 输入文本，**永不作为脚本/表达式执行**；不注入 Shell、不加载模块、不读文件。
- 用户指令中的自然语言只影响 LLM 输出，不影响引擎控制流（控制流仅由连线与节点语义决定）。

### 8.3 版本边界

- **V1 不引入模板语法**（if/for/函数调用等表达式）：复杂逻辑用自然语言描述，交给 LLM 理解执行。
- 后续版本视使用情况再评估结构化语法（如条件表达式、集合算子），评估结论另行成稿，不并入本文档历史演进。

## 九、示例

### 9.1 示例一：简单引用（取企业名称组装）

```text
【系统指令】
你是企业体系审核助手。根据给定的数据上下文，完成用户指令要求，直接输出结果文本，不要解释过程。

【数据上下文】
企业名称：{{企业名称}}
审核标准：{{审核标准}}

【用户指令】
请输出一句话审核任务描述，格式为："针对【{{企业名称}}】依据【{{审核标准}}】开展体系审核"。
```

编译后（落库）：

```text
【数据上下文】
企业名称：{{get_field_n1.fieldValue}}
审核标准：{{get_field_n3.fieldValue}}

【用户指令】
请输出一句话审核任务描述，格式为："针对【{{get_field_n1.fieldValue}}】依据【{{get_field_n3.fieldValue}}】开展体系审核"。
```

### 9.2 示例二：两值比较判定（AI 承担复杂比较）

```text
【系统指令】
你是企业体系审核助手。根据数据上下文与用户指令，仅输出 JSON：{"合格": boolean, "说明": string}，不要输出其他内容。

【数据上下文】
人员数量：{{人员数量}}（人）
行业要求人数：{{行业要求人数}}（人）

【用户指令】
比较人员数量是否满足行业要求人数；若人员数量大于等于行业要求人数则合格，否则不合格，说明差异原因。
```

### 9.3 示例三：集合比对汇总（复杂逻辑由自然语言描述）

```text
【系统指令】
你是企业体系审核助手。根据数据上下文与用户指令，仅输出 JSON：{"缺失项": string[], "缺失数量": number, "说明": string}，不要输出其他内容。

【数据上下文】
应具备条款：{{条款清单}}（表格：条款编号, 条款名称）
已具备证据：{{证据清单}}（表格：条款编号, 证据名称）

【用户指令】
1. 将应具备条款与已具备证据按"条款编号"逐条比对；
2. 找出应具备但无对应证据的条款，列为缺失项；
3. 输出缺失项列表、缺失数量与总体说明。
```
