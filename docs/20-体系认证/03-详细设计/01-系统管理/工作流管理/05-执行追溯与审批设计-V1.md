# 执行追溯与审批设计 V1

> 日期：2026-09-27
> 状态：草稿，待评审
> 关联文档：工作流管理/01-核心引擎/工作流引擎-总体架构设计-V3.md
> 设计原则：专家购买的是"可信结论"，不是"执行日志"。追溯链必须连接三个锚点——规则、数据源、AI推理。

---

## 一、业务问题

当前工作流引擎执行后返回的只是 `NcResult`（success/error/result），专家无法回答三个关键问题：

| 问题 | 现状 | 目标 |
|---|---|---|
| **依据是什么** | 只有 RuleCode，无规则名称、无严重程度 | 显示规则中文名、条款号、违规严重级别 |
| **结论如何得出** | 节点输出有值，但不知道数据来源是哪份文件、哪条字段 | 每个 docField/docTable 节点都能追溯到具体文档和字段 |
| **AI 怎么想的** | 只有 PromptTokens 数值，无 prompt 原文 | 保存渲染后的完整 prompt 和使用的模型名 |
| **人是否认可** | 无审批环节 | 专家可批准/驳回/修改，并有意见和可信度 |

## 二、四层模型回顾

```
wf_execution_task              一次触发（含规则上下文快照）
  └─ wf_execution_task_item    一个检查项
       └─ wf_path_execution     一条路径
            └─ wf_node_execution 一个节点执行事实（含来源 + AI 证据）
                 └─ wf_node_approval 一个节点的审批记录（新增）
```

## 三、DB 层改动

### 3.1 wf_execution_task — 补规则上下文快照

```sql
ALTER TABLE wf_execution_task
  ADD COLUMN RuleName             varchar(200) NULL DEFAULT NULL COMMENT '规则中文名称（执行时快照）',
  ADD COLUMN SeverityIfViolated   varchar(20)  NULL DEFAULT NULL COMMENT '违规严重级别 major/minor/observation';
```

> 为什么快照：规则可能在执行后被修改，历史记录必须固定当时的规则名称和级别。

### 3.2 wf_node_execution — 补节点证据列

```sql
ALTER TABLE wf_node_execution
  -- 数据来源（docField / docTable 填写）
  ADD COLUMN SourceFileCode   varchar(200) NULL DEFAULT NULL COMMENT '源文件编码 cert_extraction_result.FileCode',
  ADD COLUMN SourceFieldName  varchar(200) NULL DEFAULT NULL COMMENT '源字段中文名（展示用）',
  ADD COLUMN SourceVersion    int          NULL DEFAULT NULL COMMENT '源文件版本号',
  -- AI 节点证据（ai_node 填写）
  ADD COLUMN AiModel          varchar(100) NULL DEFAULT NULL COMMENT 'LLM 模型名',
  ADD COLUMN AiPrompt         longtext     NULL DEFAULT NULL COMMENT '渲染后送 API 的完整 prompt（8KB 截断）',
  -- 审批后输出
  ADD COLUMN ApprovedOutputJson json       NULL DEFAULT NULL COMMENT '专家审批后最终输出（null=未审批或无修改）';
```

> AiPrompt 截断策略：超过 8000 字符时截断并追加 `[truncated, original=N chars]`，保证 JSON 合法、不撑爆行宽。

### 3.3 新增 wf_node_approval — 节点级审批记录

```sql
CREATE TABLE wf_node_approval (
  Id                bigint       NOT NULL AUTO_INCREMENT COMMENT '主键',
  Code              varchar(36)  NOT NULL COMMENT '全局唯一编码（GUID）',
  TaskCode          varchar(36)  NOT NULL COMMENT 'wf_execution_task.Code',
  NodeId            varchar(64)  NOT NULL COMMENT '节点 ID（与 wf_node_execution.NodeId 对应）',
  ApprverCode       varchar(36)  NOT NULL COMMENT '审批人编码（Sys_User.Code）',
  ApprverName       varchar(50)  NULL     COMMENT '审批人姓名（冗余，避免联表）',
  ApprovalStatus    varchar(20)  NOT NULL DEFAULT 'pending' COMMENT 'pending/approved/rejected',
  ApprovedAt        datetime     NULL     COMMENT '审批时间',
  Comment           text         NULL     COMMENT '审批意见',
  ManualResult      json         NULL     COMMENT '专家手动修改后的节点输出（JSON）',
  Confidence        decimal(5,2) NULL     COMMENT '专家可信度评分 0.00~1.00',
  IsDeleted         tinyint(1)   NOT NULL DEFAULT 0,
  DeleteBy          varchar(50)  NULL,
  DeleteTime        datetime     NULL,
  IsValid           int          NOT NULL DEFAULT 1,
  CreateTime        datetime     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UpdateTime        datetime     NULL,
  CreateBy          varchar(50)  NULL,
  UpdateBy          varchar(50)  NULL,
  PRIMARY KEY (Id),
  UNIQUE KEY uk_code (Code),
  UNIQUE KEY uk_task_node (TaskCode, NodeId),
  KEY idx_task (TaskCode),
  KEY idx_approver (ApprverCode)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci
  COMMENT='节点审批记录（专家对单个节点执行结果的认可/修改）';
```

> 唯一键 `(TaskCode, NodeId)` 保证每个节点每轮任务只有一个审批记录；审批可多次修改，只保留最新一条。

## 四、执行层改动

### 4.1 WfExecutionTaskService.BeginRunAsync — 补规则快照

解析完 configSnapshot 后，查 `cert_validation_rule` 取 RuleName / SeverityIfViolated，写入 task 行。

```csharp
var rule = await _db.GetOneAsync<ValidationRule>(x => x.RuleCode == ruleCode);
if (rule != null)
{
    task.RuleName = rule.RuleName;
    task.SeverityIfViolated = rule.SeverityIfViolated;
}
```

### 4.2 NodeDescription — 节点作用描述（设计器填写，专家可见）

 新增  字段，落库到 。设计器在创建/编辑节点时可填写该节点的"作用说明"，替代机械的 classCode 翻译，让专家理解每个具体节点实例的语义。

### 4.3 NodeExecutor.cs — docField / docTable 写入来源

**ExecuteDocFieldAsync** return 改为：

```csharp
return new Dictionary<string, object>
{
    ["fieldValue"]      = field.ExtractedValue ?? string.Empty,
    ["confidence"]      = confidence,
    ["source"]          = source,
    ["sourceFileCode"]  = field.FileCode,
    ["sourceFieldName"] = field.FieldName,
    ["sourceVersion"]   = field.VersionNumber,
};
```

**ExecuteDocTableAsync** 同理追加 `sourceFileCode / sourceVersion`。

### 4.4 AiNodeExecutor.cs — 写入 prompt 和模型名

在 `ExecuteAsync` 返回 `NodeExecutionResult` 前：

```csharp
result.AiModel  = _cachedSettings?.Model;
result.AiPrompt = renderedPrompt is not null
    ? renderedPrompt.Length > 8000
        ? renderedPrompt[..8000] + "\n...[truncated, original=" + renderedPrompt.Length + " chars]"
        : renderedPrompt
    : null;
```

### 4.5 WfExecutionTaskService.SaveNodeExecutionsAsync — 映射新列

从 `record.Output` 安全提取来源字段，写入 `WfNodeExecution` 新列：

```csharp
nodeExec.SourceFileCode   = TryGetStr(record.Output, "sourceFileCode");
nodeExec.SourceFieldName  = TryGetStr(record.Output, "sourceFieldName");
nodeExec.SourceVersion    = TryGetInt(record.Output, "sourceVersion");
nodeExec.AiModel          = record.AiModel;
nodeExec.AiPrompt         = record.AiPrompt;
```

`TryGetStr` / `TryGetInt` 为安全取 JSON 字典值的辅助方法，取不到返回 null，不抛异常。

### 6.4 审批交互流程

```
执行完成
   │
   ▼
结果展示（原始 AI 输出）
   │
   ▼ 专家点击"开始审批"
审批面板展开
   │
   ├─ 逐节点查看证据链（来源 / prompt / 输出）
   │
   ├─ 认可：标记「通过」，可信度打星
   ├─ 修改：编辑 ManualResult，标记「已修改」，可信度打星
   └─ 驳回：填写意见，标记「驳回」
   │
   ▼
最终结果 = 原始输出 OR 专家修改后输出（视配置而定）
```

> 关键设计：专家可以**覆盖** AI 的输出，但原始输出永久保留（`OutputJson` 不变），修改结果存入 `ApprovedOutputJson`，形成对比审计轨迹。

## 七、数据流全景

```
执行请求（含 RuleCode + EnterpriseCode）
         │
         ▼
wf_execution_task
  ├─ ConfigSnapshot     ← 锁定工作流定义
  ├─ RuleName / Severity ← 快照规则上下文
  └─ ResultSummary      ← 聚合 NC 结果
         │
         ▼
wf_path_execution
  └─ wf_node_execution
       ├─ OutputJson           ← AI 原始输出（永久保留）
       ├─ SourceFileCode/Name   ← 数据来源
       ├─ AiModel/Prompt       ← AI 推理证据
       ├─ ApprovedOutputJson   ← 专家修改后输出（可选）
       └─ wf_node_approval     ← 审批记录（独立表）
            ├─ ApprovalStatus
            ├─ Comment
            └─ Confidence
```

## 九、待决策事项

1. **AiPrompt 截断阈值**：8KB 是否合适？
2. **审批是否允许修改**：专家可以完全覆盖 AI 结果，还是只能 approve/reject？（建议允许修改，保留原始供对比）
