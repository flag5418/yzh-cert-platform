## 五、本轮已修复缺陷（6 项，含证据）

| # | 缺陷 | 根因 | 修复 | 证据 |
|---|---|---|---|---|
| 1 | **「文档」下拉为空（No data）** | 后端 `configured-rules` 原生 SQL 用了 snake_case 列名 `f.file_name`/`f.file_code`，真实表为 PascalCase `FileName`/`FileCode`；`SqlQueryAsync` 失败返回 `Result.Fail` 被吞 → **HTTP 200 + 空数组** | SQL 改 PascalCase 列名（`DocExtractionRuleService.cs`） | 接口由 `[]` → 2 条规则 |
| 2 | 下拉**选项文字仍为空** | 旧后端返回匿名对象（camelCase `ruleCode`/`fileName`），新后端改为 DTO 类默认序列化（PascalCase），前端 `d.ruleCode`/`d.fileName` 读不到 | ① DTO 加 `[JsonPropertyName]` camelCase（D-5 契约）② 前端双写兼容 | 接口返回 `ruleCode`/`fileName`；下拉显示「XASL-QM 质量手册.doc」等 2 项 |
| 3 | `WfSkill/filter`、`WfSkillCategory/filter` **400** | 框架 ORM 对 `IIsValid` 实体自动追加 `IsValid=1`/`IsDeleted=0`，而 `wf_*` 表只有 snake_case 旧列 → `Unknown column 'IsValid'` | DB 迁移 `20260917_wf_standard_columns.sql`（5 表 + 队列表）+ 实体按 `cert_sys_config` 惯例改为继承自动映射 | 两接口 200（Skill 5 条、分类 5 条） |
| 4 | 后端**启动期** `Sys_Menu`/`YzhQueueTask` 查询 1054 | 同上，`sys_config`/`sys_role`/`yzh_queue_task` 缺标准列 | DB 迁移 `20260917_sys_standard_columns.sql` | 启动正常，`health` 200 |
| 5 | 「测试提取」按钮 **404** | 前端 `handleTestDocExtract` 的 URL 漏了 `/Workflow` 前缀（同文件其他调用均带） | 改为 `/api/Workflow/DocExtractionRule/test-field`｜`test-table` | 旧路径 404 → 新路径 401（存在，需认证） |
| 6 | 画布不渲染 / 节点拖不进（历史轮次） | LogicFlow v2：① 构造后不调 `render()` 无 SVG ② `background` 传字符串被按字符索引展开触发 Preact indexed setter 异常 | 构造后渲染空图；`background` 改官方对象格式 | 画布 SVG 渲染 + 拖拽节点数 1→2 |

> 补充说明（第 3 项架构约定）：YZH 新架构通过 `BaseEntity`/`IIsValid` **统一启用禁用与软删除**，规范列名为 PascalCase（`IsValid`/`IsDeleted`）。凡实现 `IIsValid` 的实体，其表必须具备这两个标准列；`wf_*` 等由旧 DDL 迁入的表需补齐。实体侧按 `cert_sys_config` 惯例覆盖基类属性（**不写** `SugarColumn`）即自动映射。
