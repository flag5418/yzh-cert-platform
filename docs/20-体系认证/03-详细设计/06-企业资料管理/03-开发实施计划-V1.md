## 五、复核修订记录（实施期，滚动追加）

### R-1 ｜Q1 衍生结论②"机构直取"复核**不成立**（2026-09-28，G-4a 实施中实测）

| 项 | 内容 |
|----|------|
| 原假设 | 机构维度从 `cert_enterprise.OrgCode` 直取即可匹配模板行（门③ Q1 / G-0a） |
| 实测事实 | 两处 `OrgCode` **不同域**：企业行由建档钩子 `OnBuildingFilter` 写入的是**专家工作区节点** Code（`sys_organization.OrgType='VirtualOrg'`, `OrgLevel=2`，如 `66bbf572…` = 尚龙认证 · 王卿权）；管理端模板行 `cert_standard_directory_config.OrgCode` 写的是 `cert_certification_body.Code`（如 `906e8b2a…`）。按 (OrgCode, StandardCode, StageCode) 直查模板**必然落空** ⇒ 企业目录永远初始化不出来，`InitEnterpriseDirectoryAsync` 恒回"该机构未配置标准目录" |
| 桥接键 | `sys_organization(工作区).OrgCode` = 业务编码字符串（`'CB001'`）↔ `cert_certification_body.CbCode`（同域，UNIQUE）→ 取其 `Code` |
| 处置 | `EnterpriseFileService.NormalizeOrgCodeAsync(orgCode)` 三级解析：① 本身是机构 Code → 原样；② 是组织节点 Code → 节点 `OrgCode` → `CbCode` → 机构 `Code`；③ 遗留数据（`OrgCode` 里直接存了 `CbCode` 串）→ 按 `CbCode` 反查。**解析不到原样返回**，不猜机构，空态统一由模板查询回"该机构未配置标准目录，请先在管理端维护" |
| 落库口径 | 企业目录 config/file 行的 `OrgCode` 一律写**归一后的机构 Code**（与模板同域），uk 四列幂等判据因此稳定；`cert_enterprise.OrgCode` 保持工作区节点 Code 不变（专家端数据隔离用，`EnsureOwnedEnterpriseAsync` 口径不动） |
| 影响门 | 门⑥（OrgCode 写入完整）复核口径改为"工作区 Code 完整 + 目录域归一"，G7 验收按此执行 |

### R-2 ｜阶段键 `StageCode` 二次双域（2026-09-28，G-4a 实测暴露）

| 项 | 内容 |
|----|------|
| 现象 | `check/add` 提交后 `Applied` 为空 —— 关联项被 `validStages` 全部丢弃 |
| 根因 | `cert_cert_stage` 有 `Code`(GUID) 与 `StageCode`(业务码 `jd01`/`03`) 两列。目录模板/提取规则/提取结果/op_log **全部按 `Code` 存** `StageCode` 列；而 `EnterpriseStageController` 的校验集与树节点却用 `st.StageCode`（业务码）⇒ 关联行写业务码，与目录域永远对不上，G-4a 复制模板必然落空 |
| 处置 | 阶段键统一为 `cert_cert_stage.Code`：`checkTree` 节点合成键/`Extra.StageCode`、`check/add` 的 `validStages` 全改 `Code`（实测 3 关联项 2 初始化成功 + 1 正确回"该机构未配置标准目录"，重复提交幂等 = 槽位仍 167 行） |
| 遗留 | `cert_org_stage.StageCode` 仍存业务码（管理端「机构-阶段」页口径），与专家端关联无交集，本期不动；如需统一另立改造项 |
