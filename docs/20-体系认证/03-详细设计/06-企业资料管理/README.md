# 06-企业资料管理 — 已备齐标准格式材料的采集·提取·报告数据源

> **状态**：建设中（后端/页面骨架已落地，处于「去假存真」阶段）| **编制**：2026-09-28
> **产品端**：专家端 `cert-auditor`（页面 `src/pages/resources/`）
> **本册回答**：企业资料管理是什么、与 NC 检查/报告生成的关系、历史版本怎么管、当前实现缺口与修复路线。

## 一、模块定义（一句话）

> **企业已经按体系认证要求的表格格式准备好了一份材料清单/成册文件，本模块负责：采集归档 → 按后台「文档提取规则」提取成结构化数据（B-08/B-09）→ 供后台定义的 NC 检查规则与报告规则消费 → 自动形成 NC 检查报告和体系认证报告。**

## 二、与「05-企业资料规范化」的边界（最高频混淆点，先读）

| | **06-企业资料管理（本册，本期）** | **05-企业资料规范化（下一步）** |
|--|--|--|
| 企业手里的材料 | **已按标准格式填好**（成册/清单，命名规整） | **散乱资料**（扫描件、Word/Excel，命名混乱） |
| 要解决的问题 | 采集、归档、完整性检查、定向提取、版本与追溯、喂给 NC/报告 | 让散乱资料**变成**标准格式文档（画像→匹配→人工裁决→填充） |
| 核心引擎 | 转换队列 + **定向提取规则链**（已有域） | **匹配/裁决/填充引擎**（04/06/07 号册设计，未实现） |
| 人工角色 | 审核员上传、确认映射、看检查报告 | 裁决 AI 推荐的匹配结果 |
| 上传交互（P11 已裁决） | **标准 Tab 布局 + 双入口**：阶段级跨标准批量分发（文件名轻量匹配推荐）+ Tab 内补充上传（非本标准文件拒收） | 散乱文件由画像/匹配引擎推荐归属（重交互，下一期） |
| 两线汇合点 | 都落在 `cert_standard_directory_file` 的**企业行** + `StandardFileCode` 枢纽（D11 统一表架构是共享的**存储底座**，不是流程混用） | 同左 |

**判别口诀**：材料已经"长得像标准文档" → 走管理线直接采集提取；材料"不像/不全" → 才需要规范化线加工。**本期只做管理线；规范化是下一期。**
