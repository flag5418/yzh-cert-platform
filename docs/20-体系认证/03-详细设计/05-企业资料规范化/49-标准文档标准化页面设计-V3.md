## 一、★ 设计原则（本版的地基）

> 你的原话：
> 「我们是程序，但文档的规则判断和实施，是**维护人员的工作**，
> 我们只需要考虑**程序逻辑严谨性**，并不直接**包办所有人工的判断行为**……
> **我们只控制逻辑的正确性**，这是合理的」

### 1.1 拆成三句话

| # | 原则 | 含义 |
|:--:|---|---|
| **P1** | **判断权归维护人员** | 凡是**业务决策**（该不该、能不能、要不要），程序⛔ **不替人决定** |
| **P2** | **程序只保证逻辑严谨性** | 一旦人工做了选择，程序必须**一致地执行**，并**拦住自相矛盾的组合** |
| **P3** | **程序产出「建议」，人工「确认」后才成事实** | 与 `41-V3` 已定的裁定「**类型「预选≠已确认」**」**完全一致**（互相印证） |

### 1.2 ★ 三分法：把所有判定项分成三类

| 类 | 谁定 | 判据 | 例子 |
|---|---|---|---|
| **① 客观事实** | **程序** | 有唯一正确答案，可机器验证 | 文件是不是 PDF / 图片（anydoc 能不能解） |
| **② 业务决策** | **人工** | 无唯一答案，取决于业务意图 | **这份文档能不能被企业替换** |
| **③ 派生值** | **程序算** | 由 ① + ② 推出，⛔ 不可人工直接改 | `DocCategory`（fixed / editable）、状态三态 |

> ★ **V2 的错误就在这**：V2 §三 把「文档来源（可替换性）」写成了「**自动初判** + 人工可改」——
> 它其实是 **②业务决策**，⛔ 不是 ① 客观事实。**程序不该"初判"它**，只该**给个默认值让人工确认**。

## 二、★ `D-AA1` 裁定：「文档能否被替换」= **人工判断**

### 2.1 裁定

| 项 | 谁定 | 程序做什么 | 程序⛔ 不做什么 |
|---|---|---|---|
| **可替换性** | **人工**（维护人员） | ① 提供二选一开关 ② 给一个**保守默认值** ③ 选择后**一致执行** ④ 校验组合矛盾 | ⛔ **不自动推导**（不从文件名 / 内容 / 分类去猜） |

### 2.2 枚举（建议）

| 值 | 含义 | 你的话 |
|---|---|---|
| `standard_provided` | **标准自带**、不可替换 | 「不能被替换 ⇒ 这个文档就必须存在」 |
| `enterprise_provided` | **企业提供**、可替换 | 「可以被替换 ⇒ 需要找企业的文档来替代」 |

> ⚠️ 现有 DDL 默认值是 `enterprise_provided`（见 V2 §1.3）。
> **建议**：默认值保留（DB 不动），但**页面必须让用户显式确认一次**（P3：预选 ≠ 已确认），
> 并在状态判据里把「未确认」当成**未设置完成**。

### 2.3 程序**真正**要做的（= 你说的「逻辑严谨性」）

见 §五 校验清单。核心一句：**人工选了什么，程序就一致地做到底，并把矛盾的组合拦住。**

## 三、修订 V2 §三：两轴里，一轴程序判、一轴人工判

| 轴 | V2 的说法 | **V3 修正** |
|---|---|---|
| **A 可解析性** | 自动判定 | ✅ **程序判**（客观事实，`anydoc` 能不能解） |
| **B 文档来源（可替换性）** | 「自动初判 + 人工可改」 | ⛔ **改：纯人工判**（业务决策），程序只给默认值 + 校验 |

### 修订后的判定链

```
① 可解析性        ← 程序判（客观事实）
   ├─ 图片 / PDF（anydoc 解不了）  ⇒ 不可解析
   └─ doc / docx / xls / xlsx / txt ⇒ 可解析
        ↓
② 可替换性        ← ★ 人工判（业务决策，程序给默认值）
   ├─ 标准自带（不可替换）
   └─ 企业提供（可替换）
        ↓
③ DocCategory     ← 程序算（派生，⛔ 人工不直接改）
   可解析 且 需配锚点 ⇒ editable
   其余              ⇒ fixed
```

> ⇒ **页面只需给人工一个开关**（②），其余全自动。这也让页面更简单 —— 符合你「不要塞满一页」的要求。

## 四、★「谁判」总表（全页判定项过一遍）

> 这张表是**页面设计的直接依据**：页面**只让人工填「人工」那几行**，其余显示为只读或建议值。

| 项 | 谁定 | 依据 / 备注 |
|---|---|---|
| 文件可解析性 | **程序** | anydoc 能力 |
| `DocCategory`（fixed/editable） | **程序算** | 由 ①② 派生 |
| **可替换性** | ★ **人工** | **`D-AA1` 裁定** |
| 分组（`TagsJson`） | **程序建议 + 人工确认** | AI 语义分析（点 2） |
| 文档作用（`DocPurpose`） | **程序建议 + 人工确认** | AI 语义分析（点 2） |
| 锚点清单 | **程序** | 扫空白模板 |
| 锚点：数据源 | **人工** | 配置 |
| 锚点：操作方式与参数 | **人工**（扫描带出的参数直接带入） | 配置 |
| 全局填写规则（ai 汇聚） | **程序生成 + 人工可改** | ai 锚点汇聚（V2 §六） |
| 匹配提示词 `MatchPrompt` | **人工**（程序可给建议） | 固定文档的核心（V2 §八） |
| 指纹 `FingerprintJson` | **人工**（程序可给建议） | 不可解析文档的匹配依据（V2 Q10） |
| 状态三态 | **程序算** | 事实推论，⛔ 无「标记为完成」按钮 |
| 试填随机值 | **程序** | — |

> ★ 结论：**页面上的输入控件，应该只出现在「人工」那 6 行** —— 其余全是只读展示或建议值。
> 这是「简洁」的**结构性**保证，⛔ 不是靠调样式。

## 五、★★ 程序要负责的「逻辑严谨性」校验清单

> 这是你说「我们只控制逻辑的正确性」的**落地物**。
> 每条都必须是**程序能自动判、且必须拦住**的。

### 5.1 组合矛盾校验（拦住自相矛盾的选择）

| # | 条件 | 程序必须报 |
|:--:|---|---|
| C1 | 选了**可编辑** 但**没有空白模板** | 「未设置完成：可编辑文档需要空白模板（锚点只能从模板扫出）」 |
| C2 | 选了**标准自带（不可替换）** 但标准域里**没有这个文件** | **报错**：「不可替换 ⇒ 文档必须存在，但标准域未找到」 |
| C3 | 选了**企业提供（可替换）** 但**既无 `MatchPrompt` 也无 `FingerprintJson`** | **警告**：「可替换但无匹配依据 ⇒ 队列找不到企业文档」 |
| C4 | 有 **ai 锚点** 但**无全局填写规则** | 「未设置完成」（`D-AA1` 同轮裁定，V2 §六） |
| C5 | 有锚点**未配数据源** | 「未设置完成」 |
| C6 | `DocCategory='fixed'` 却**存在锚点** | **警告**（矛盾：固定文档不该有锚点） |

### 5.2 一致性校验（人工选了什么，程序就一致做到底）

| # | 人工选择 | 程序必须一致地做 |
|:--:|---|---|
| E1 | **标准自带（不可替换）** | ① **不**生成企业侧实例行 ② 队列**不**去企业资料里找 ③ 直接用标准域那份 |
| E2 | **企业提供（可替换）** | ① 队列**必须**去企业资料里找 ② 找不到时状态**明确**（⛔ 不是静默空）③ 匹配依据缺失时按 C3 报警 |
| E3 | **不可解析 + 企业提供**（营业执照） | ① ⛔ 不显示锚点 Tab ② **但必须**有匹配依据（C3 生效） |
| E4 | **可编辑** | ① 必须上传空白模板（C1）② 所有锚点配完（C5）③ ai 锚点 ⇒ 全局规则存在（C4） |

### 5.3 ⛔ 程序**不做**的（防止越界）

| # | 不做 |
|:--:|---|
| N1 | ⛔ 不根据文件名 / 内容**猜**可替换性 |
| N2 | ⛔ 不因「看起来像营业执照」就自动设成 `enterprise_provided` |
| N3 | ⛔ 不在人工未确认时**替他确认**（预选值必须标「未确认」） |
| N4 | ⛔ 不因缺少匹配依据就**静默跳过**（必须报 C3） |
