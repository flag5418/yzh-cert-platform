## 1. MVP 定义

**一句话**：1 家真实企业 + ISO9001 一个标准，30–50 份散乱资料 → 画像 → 匹配 → **人工逐条裁决** → 定向提取 → 字段级确认，全链路走通且可审计。

### 1.1 MVP 包含（In）

| # | 项 | 对应分册 | 说明 |
|---|----|----------|------|
| 1 | 9 张新表 + 既有表加列 + 字典 + 4 个全局配置键 | 02 | 脚本 1/2/3/5 |
| 2 | 企业资料库（文件夹树 + 文件 + 四段式上传 + 版本 + 预览） | 09 §3.1 | 复用转换队列 |
| 3 | 画像链（指纹预判 + LLM 画像 + 版本化落库） | 06 | `ent_doc_profile` 队列 |
| 4 | 匹配三阶段（召回 + 精排 + 仲裁，**`ent_norm_auto_confirm=0`**） | 04 | `ent_doc_match` 队列 |
| 5 | 裁决页（双视角 + 5 动作 + 证据展示） | 07 | 左树右表样板 |
| 6 | 契约页（五要素编辑 + 状态流 + 从规则批量种子） | 05 | 含 `CellPrompt/TablePrompt` 加列 |
| 7 | 裁决后触发定向提取 + 字段覆盖 | 06 §8、07 §4 | 复用既有提取链 |
| 8 | 审计时间线（最小充分） | 07 §5 | decision 只追加 |
| 9 | 计费接入（`ent_profile`/`ent_match`） | 06 §7.2 | 复用 `cert_ai_usage_log` |

| 项 | 去向 |

| 自动确认（`auto_confirm=1`） | 二期，先积累判例与评测集 |

| 批量裁决之外的智能建议 | 二期 |

## 2. 分期计划

### P0 — 地基（表 + 契约 + 静态能力）

```text
□ 脚本1 9张新表 / 脚本2 加列+配置键 / 脚本3 CellPrompt·TablePrompt
□ 实体类（Entities/Ent/ + Dir/StandardDocContract）+ 编译过
□ 契约 CRUD + 状态流 + 规则种子脚本4 + 冗余同步
□ 契约页（单表样板）+ 路由/菜单 + guards.mjs + sync_menu_urls
□ 验证 SQL 全绿（02 §8.2）
出口：ISO9001 配置下 60 个标准文件全部有 active 契约，DocPurpose 补齐
```

### P1 — 输入链（上传 → 转换 → 画像）

```text
□ 企业资料库页（左树右表）+ 四段式上传 + PathBuilder.EnterpriseFile 首次启用
□ ent_doc_profile 队列 + EntDocProfileTaskExecutor + 指纹预判 + LLM 画像
□ 画像列表页 + 重跑 + 无归属清单
□ 断链演练：无 Markdown → skipped；LLM 挂 → failed 重试
出口：1 家企业 30–50 份资料画像完成率 ≥ 90%，每份有 purpose + 字段 + 表格
```

### P2 — 匹配链（召回 → 精排 → 仲裁 → 裁决）

```text
□ ent_doc_match 队列 + 召回 R1–R3/R5 + 精排批调用 + 仲裁
□ 裁决页（双视角 + 5 动作 + 冲突置顶 + 证据预览）
□ 审计时间线 + 标准文件 MatchState 聚合回写
□ 评测集跑分（P5 金标准）→ 04 §10 指标
出口：Recall@10 ≥ 0.90；裁决动作全部留痕；冲突候选 100% 进人工
```

### P3 — 填充链（裁决 → 提取 → 字段确认）

```text
□ T7 定向提取接线（契约 RuleCode → 规则）+ CellPrompt/TablePrompt 注入
□ 字段覆盖（FieldOverrideJson 分离存储）+ 合并视图读取
□ 「企业暂缺」缺口清单 + InstanceState 进度
出口：裁决确认的文档自动产出提取结果，字段级确认可完成，原值/覆盖值可回放
```

### P4 — 加固与放量（二期入口）

```text
□ 评测集扩到 3 家企业 + 第二个标准
□ 按数据决定：auto_confirm 开关 / embedding（P2）/ OCR（P3）/ 企业端上传（P4）
□ 延展规划 09 号文的审计统计视图
```

**依赖顺序**：P0 → P1 → P2 → P3（严格串行，每期有独立出口，可随时停在任意期而不留半成品）。

## 5. 验收指标

### 5.1 功能验收（MVP）

| # | 验收项 | 标准 |
|---|--------|------|
| A1 | 全链路走通 | 1 家企业资料从上传到字段确认，全程无手工 SQL |
| A2 | 评测指标 | Recall@10 ≥ 0.90、Precision@1 ≥ 0.70、漏配率 ≤ 0.05（04 §10） |
| A3 | 安全底线 | 阈值以下/冲突候选 **0 条**被自动落标准文档（抽查 decision `IsAuto`） |
| A4 | 审计完整 | 任一归属可回放「谁何时依据什么改的」；decision 零 UPDATE/DELETE |
| A5 | 降级可用 | LLM 下线时：指纹链照常、人工指定照常、精排候选标 recall 不阻塞 |
| A6 | 数据规范 | 验证 SQL 全绿（无 Enable / utf8mb4_general_ci / 无 PhaseCode / decimal(3,2)） |
| A7 | 守卫与构建 | `guards.mjs` 0 违规、`npm run build` 过、后端编译 0 错误 |
| A8 | 溯源 | 任一字段值可点开证据并定位到源文档页/行（产物存在时） |

### 5.2 过程指标（上线后观测）

画像 P95 耗时 · 精排批次 P95 · LLM 失败率/JSON 解析失败率 · 人工采纳率（≥0.60）· 否决率按 DocCategory 分布 · 每 100 文件成本（`BusinessType` 汇总）。

## 6. 风险与对策

| # | 风险 | 影响 | 对策 |
|---|------|------|------|
| R1 | 扫描件无 OCR（P3 未决），画像 `skipped` 比例高 | 固定文档全靠人工指定 | MVP 明示限制；文件名指纹兜底；P4 前拍板 P3 |
| R2 | LLM 分数漂移导致重跑后结论变化 | 人工困惑、误替换 | 04 §9：confirmed 不重算、temperature=0、锚定样例校验、批次号隔离 |
| R3 | 自动确认开太早，错误归属污染提取结果 | NC/报告数据源被污染 | 首期 `auto_confirm=0`；开启前须 5.1-A2 达标 + 误配复盘为零 |
| R4 | `DocPurpose` 种子留空无人补，精排缺维 | 全部强制人工、队列堆积 | P0 出口强约束「60 份 DocPurpose 补齐」才进 P1 |
| R5 | 召回漏配（关键词覆盖不足） | 真配对根本没进候选 | `Keywords` 人工维护入口 + 反向召回 R5 + 漏配率纳入 A2 |
| R6 | 端点改名导致权限静默断裂 | 页面 403 | 09 §5：改名必重跑 ApiSync + 重关联 |
| R7 | 整实体覆盖写回引发列被冲掉（MarkdownPath 事故重演） | 数据损坏 | 列白名单纪律 + 代码评审检查项 |
| R8 | LLM 成本失控（批量重跑无上限） | 费用 | `ent_norm_max_calls` + 分批触发 + 费用页按 BusinessType 盯 |

## 7. 决策点关闭计划

| ID | 决策点 | 关闭时点 | 关闭方式 |
|----|--------|----------|----------|
| P1 | 阈值 0.85/0.50 | P2 开工前 | 用户拍板；默认值先落 `cert_sys_config`，可改 |
| P2 | 向量召回 | P4 | 用 P2/P3 真实漏配样本评估 R4 增益后决定 |
| P3 | OCR | **P0 期间（最迟 P1 前）** | 看样本中扫描件占比：>30% → P1 前接入，<10% → P4 |
| P4 | 上传主体 | P0 期间 | 首期默认审核员代传；企业端启用时机看业务 |
| P5 | 金标准样本 | P2 出口前 | 用户准备 + 人工标注，作为 A2 验收输入 |
| P6 | 固定文档清单 | P0 契约种子时 | 用户圈定清单，逐份配指纹 |

> **决策未关闭不阻塞 P0**（P0 只做表/契约/页面骨架）；P1 起 P3/P4 必须有结论，P2 起 P1/P5 必须有结论。
