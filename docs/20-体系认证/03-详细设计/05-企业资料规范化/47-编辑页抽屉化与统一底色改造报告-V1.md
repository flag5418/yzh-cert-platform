## 3. 逐条交付

### 3.1 ① 统一白色背景 ✅

**问题实测**：页面上同时存在**三种近白**，肉眼难分却各自成块：

| 位置 | 原值 | 表现 |
|---|---|---|
| `.app-body` | `--yzh-color-bg-page` `#f8fafc` | **中栏预览区整条灰带**（最显眼） |
| `.side__filters` / `.fnav` / `PreviewPane .source-bar` | `--yzh-color-bg-subtle` `#f9fafb` | 三条全宽浅灰带 |
| 左右两栏 / 顶行 | `--yzh-color-bg-container` `#fff` | 白 |

> ⚠️ **关键判断**：`#f8fafc` 与 `#f9fafb` **只差 1 个色阶**。既然前者被指为「灰」，后者同样是灰
> ⇒ **一起刷白**，不留「两种近白并存」。

**改后的口径（唯一，可照此复核）**：

| 层 | 颜色 | 说明 |
|---|---|---|
| 页面底（`.app-body`） | **白** | `--yzh-color-bg-container` |
| 全宽分区条 | **白** | 分区改由 `border-bottom` 表达，⛔ 不靠底色 |
| **带边框的卡片**（`.ac` / `.pm-mats`） | 保留 `bg-subtle` | 那是**卡片**不是页面底，有边框兜住 |
| 预览画布（`.doc-preview` / `.preview-content` / PDF 画布） | **透明** | 继承页面底；只有渲染出来的文档页带自己的白 |

**★ 一处必须记下来的坑（写进代码注释了）**：
`DocPreview` 自带 `.preview-content { background: var(--yzh-color-bg-page) }`，
编译后是 `.preview-content[data-v-A]`（特异性 **0,2,0**）。
页面若只写 `.pv__bd :deep(.preview-content)`，编译后**同样是 0,2,0** ⇒ **特异性打平**，
胜负由「两份 CSS 谁先注入」决定 ⇒ **构建顺序一变就翻盘**（症状：「昨天是白的今天是灰的」）。
⇒ 现在写成 **`.docfill .pv__bd :deep(...)`（0,3,0）**，确定性压过。
PDF 画布那条另需 `!important` —— `@vue-office/pdf` 在运行时写的是**内联**样式
（这是 S11「`!important` 仅允许出现在 `:deep()` 内」的**原意场景**）。

**改动文件**：`index.vue`（`.app-body` / `.side__filters` / `.fnav` / `:deep()` 三条）、`PreviewPane.vue`（`.source-bar`）。

### 3.2 ② 点「配置规则」改为右侧抽屉 ✅

**问题实测**：原来是**页内下半区**展开，且列表被压到 `flex: 0 0 320px`（只够 2 张卡片）。

**改法**：
- 新建通用组件 **`yzh.vue.core/src/components/layout/YzhDrawer.vue`**（照 `YzhDialog.vue` 的范式）。
  props 与 `YzhDialog` **同一套语义**（`size` 代 `width`，多 `direction`），
  额外提供 `closed` 事件（**离场动画结束后**才触发）。
- 三处登记：`components/layout/index.ts`、`src/index.ts`、**`scripts/guards.mjs` 的 `CLAUSE_EXEMPT.S07`**
  （照 `YzhDialog` 先例 —— 它自己必须包 `el-drawer`，否则每次都会给基线添一笔永久债务）。
- `AnchorSidePanel.vue`：**删掉 `embedded` / `visible` 双模式**（那是「页内下半区」时代的产物）
  与自带的 `.panel-header` / `.panel-footer` —— 标题与页脚统一由 `YzhDrawer` 提供，**行数净减**。
- `AnchorRuleTab.vue`：删 `.editor-part` / `.editor-hd` / `.editor-body` / `.list-part.with-editor`，
  列表重新占满整列；配置动作走抽屉**覆盖**在右侧。

**★ 一个容易漏的时序细节（已写进注释 + 单测）**：
抽屉关闭必须分两个事件处理，⛔ 不能用一个：

| 事件 | 时机 | 用途 |
|---|---|---|
| `close` | **立即** | 通知「要关了」 |
| `closed` | 离场动画**结束后** | 清掉 `currentAnchor` |

- 若在 `close` 里就清 ⇒ 抽屉滑出的 300ms 里**内容先消失**（肉眼可见的闪空）；
- 若**根本不清** ⇒ 「点 A → 取消 → 再点 A」时 `anchor` 引用没变、
  `AnchorSidePanel` 的 `watch` 不触发 ⇒ **面板里残留上一次的未保存编辑**。

### 3.3 ③ 全文规则改为右侧抽屉 ✅ + 编码自动生成 ✅

**改法**：
- 编辑区（原 `.pmpage` 页内块）搬进 `YzhDrawer`（`size="820px"`，提示词是长句，比锚点抽屉更吃宽度）；
  删掉原自带的 `.pm-ed__hd` 标题条（抽屉提供）。
- **删掉「编码」输入框**，改为 `genPromptCode()` 自动生成；
- **删掉「系统提示词」输入框** —— 设计 `41` §8.5.4 明确「一期用系统默认（角色设定），页面**不暴露**」。

**★ 用户这一点是**对的**，而且是「实现偏离设计」**：

> 设计 `41` §8.5.4 原文：
> 「**新建** | 「✎ 新建」= 建一条 `DocFillPrompt`（**`PromptCode` 自动生成**）+ 回写 `FillPromptCode`，
> **一步到位**，⛔ 不要求用户先去别的页面建提示词（打破先有鸡先有蛋）」
> 「`SystemPrompt` | 一期用系统默认（角色设定），页面**不暴露**；二期需要再放出来」

而改前实现要用户**手敲编码**（还要求小写字母开头、2~50 位）**+ 手填系统提示词** ⇒ 与设计不符。

**为什么「自动生成」只能落在前端（已实测后端契约）**：
`DocFillPromptController` 对 `add` 校验 `string.IsNullOrWhiteSpace(p.PromptCode)` ⇒
**后端不接受空编码**；而 `add` 由 CRUD 基类提供、**没有「代生成」钩子** ⇒ 前端生成是唯一选择。

**生成规则**（抽成纯函数 `components/promptCode.ts` + 7 条单测）：

```
dfp_ + Date.now().toString(36) + 4 位 base36 随机片段      ⇒ 当前长度 16
⇒ 恒满足后端 ^[a-z][a-z0-9_]{1,49}$
```

> ⛔ 不采用「模板名转拼音」：模板名是中文（如「质量手册」），转拼音要引依赖且极易撞码。
> 编码在本页只是**主键**，可读性由 `PromptName` 承担（版本表与下拉都显示名称）。

### 3.4 ④ 「为什么还有全局参数、锚点」→ **保留，不删** ⚠️

**这一条用户是误判，且与他自己第五轮的原话相反。**

素材区是设计 `41` **§8.5.2 + §8.5.6** 的明确要求，原文：

> §8.5.2 素材三组（用户第五轮原话即来自这里）：
> | # | 组 | 内容来源 | 点击插入什么 |
> |---|---|---|---|
> | ① | **锚点** | 本模板扫出来的全部锚点（`cert_doc_template_anchor`） | 锚点原文 token，如 `{{ENT_NAME}}`、`{{table:审核安排}}` |
> | ② | **企业参数** | 全局参数（`cert_fill_param_def`）+ 企业资料字段表达式 | `{{ENT_NAME}}`、`{{STD_NO}}` |
> | ③ | **填写方法** | 内置片段库（一期静态） | 写法约定文本，如「日期一律用 YYYY-MM-DD」 |
>
> §8.5.6 用户原话：「全文填写规格，我们应该分为上下结构，一块区域专门设计提示词需要的
> **锚点，全局参数，及填写方法**这些，下方才是我们的提示词，因为我们 3 栏，留给我们设置的空间有限。」

**为什么它必须留（不是「多余信息」）**：

1. **全文规则是「编辑器」不是「生成物」**。运行期引擎读的**正是**这份提示词原文；
   `{{ENT_NAME}}` 这类 token 是**手拼字符串**，最容易打错，而打错的后果是
   **引擎取不到值 ⇒ 静默留空**（不报错）。
2. **token 无法靠「AI 翻译」自动产出**：设计 `42` 号已裁定 ——
   锚点清单由引擎在 `{{__FILL__.anchors}}` 处**自动注入**，
   提示词里的 `{{ENT_NAME}}` 语义是**「给 ENT_NAME 这条锚点补一句说明」**，
   ⛔ 不是「声明这个锚点存在」。**「补一句什么说明」是业务判断，机器产不出来。**
3. **未知 token 标红**（编辑区下方「已引用」清单）恰恰是**两条通路的一致性检查器** ——
   手写了锚点表里没有的 token，立即可见。删掉素材区，这个检查器就失去了输入。

> ⚠️ 用户原话里的「**通过 AI 翻译自动生成**」在**一期不做**：
> 设计 `41` §8.5.4 只要求「`PromptCode` 自动生成」，⛔ 没要求「自动产出提示词正文」。
> 若要做「AI 起草提示词」，那是**新功能**（要设计、要提示词、要评测），
> 建议单独开一册，⛔ 不要混进这次 UI 改造。
