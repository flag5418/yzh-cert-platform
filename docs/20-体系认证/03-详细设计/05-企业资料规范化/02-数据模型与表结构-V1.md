## 1. 建模总则

| 规则 | 落地要求 | 依据 |
|------|----------|------|
| 表前缀 | 一律 `cert_`，**不复活 `ent_`** | 2026-09-25 裁决（README §3.3） |
| 主键 | `Id bigint AUTO_INCREMENT` + `Code varchar(36) UNIQUE`（GUID） | `BaseEntity` |
| 关联 | 只用 `Code`，`Id` 不进 WHERE/关联 | 双关键字准则 A |
| 审计 | `CreateTime/CreateBy/UpdateTime/UpdateBy`（框架统一填，子类禁止 `new` 覆盖） | `BaseEntity` |
| 软删 | `ISoftDelete` → `IsDeleted/DeleteBy/DeleteTime` | `数据库表设计-V2.md` §1.3.1 |
| 启用 | `IIsValid` → `IsValid int 0/1`；**任何表禁 `Enable`/`enable`** | 铁律九 |
| 字符集 | `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci` **逐表显式** | 铁律八 |
| 列名 | PascalCase，DB 列名 = C# 属性名 = TS 字段名，不写 `ColumnName` 映射 | 铁律（AGENTS.md ③） |
| 可信度 | `decimal(3,2) NULL`，0.00–1.00；`NULL` = AI 未给出或人工录入 | D8 |
| 阶段 | 一律 `StageCode` → `cert_cert_stage.Code`；**不使用** `PhaseCode`/`cert_phase_definition` | 2026-09-26 ⑩ |
| 扩展字段 | 复杂/易变结构用 `json`，避免频繁改表 | 旧企业档案 V1 §6 可借鉴项 |
| **YZH-STD-ENT 统一架构** | 标准侧与企业侧共用表，通过 `EnterpriseCode` 区分 | 用户裁决 2026-09-27 |

## 3. 新表清单与完整 DDL

**共 4 张新表**（YZH-STD-ENT 统一表架构下，复用既有标准目录表）：

| # | 表名 | 职责 |
|---|------|------|
| 1 | `cert_standard_doc_contract` | 标准文档契约（五要素 1/2/5 号） |
| 2 | `cert_ent_doc_profile` | 企业文档画像（字段/表格以 JSON 存储，减少表数） |
| 3 | `cert_doc_match_candidate` | 匹配候选（核心评分与冲突） |

### 3.1 `cert_standard_doc_contract` — 标准文档契约（五要素 1/2/5 号）

**职责**：承载「文档名称（引用侧）、文档作用、固定/可编辑分类、匹配与填充提示词、指纹规则、阈值策略」。字段/表格定义（3/4 号）**不在此表**，复用既有子表（见 §6）。

```sql
CREATE TABLE `cert_standard_doc_contract` (
  `Id` bigint NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `Code` varchar(36) NOT NULL COMMENT '业务键GUID',
  `CreateTime` datetime NOT NULL COMMENT '创建时间',
  `CreateBy` varchar(64) DEFAULT NULL COMMENT '创建人Code',
  `UpdateTime` datetime DEFAULT NULL COMMENT '更新时间',
  `UpdateBy` varchar(64) DEFAULT NULL COMMENT '更新人Code',
  `StandardFileCode` varchar(36) NOT NULL COMMENT '标准文件Code → cert_standard_directory_file.Code（契约宿主，一文件一契约）',
  `ConfigCode` varchar(36) NOT NULL DEFAULT '' COMMENT '目录配置Code → cert_standard_directory_config.Code（冗余，过滤用）',
  `StandardCode` varchar(36) NOT NULL DEFAULT '' COMMENT '标准Code → cert_iso_standard.Code（冗余）',
  `StageCode` varchar(36) NOT NULL DEFAULT '' COMMENT '阶段Code → cert_cert_stage.Code（冗余）',
  `DocName` varchar(200) NOT NULL COMMENT '标准文档名称（= 标准文件名，冗余供匹配读取，改名时同步）',
  `DocPurpose` text COMMENT '【要素2】文档作用：该文档在体系认证中的用途/审核关注点/数据来源说明，供画像与精排 LLM 理解',
  `DocCategory` varchar(20) NOT NULL DEFAULT 'editable' COMMENT '【分类】fixed=固定文档 / editable=可编辑文档 / hybrid=混合',
  `DocRole` varchar(20) NOT NULL DEFAULT 'required' COMMENT 'required=必需 / optional=可选 / reference=参考 / attachment=附件',
  `MatchPrompt` text COMMENT '【要素5a】匹配提示词：告诉 LLM 如何判断企业文档是否对应本文档（输出 JSON 契约见 04 分册 §4.3）',
  `SynthesisPrompt` text COMMENT '【要素5b】填充提示词：不可直接结构化的段落如何组织撰写',
  `FingerprintJson` json DEFAULT NULL COMMENT '【固定文档】指纹规则集：{"fileNames":[],"regex":[],"keyFields":[{"name":"","pattern":""}],"minScore":0.8}',
  `FileNamePattern` varchar(200) DEFAULT NULL COMMENT '标准文件名正则/通配（匹配侧兜底用，主用 cert_standard_directory_file.FilePattern）',
  `Keywords` varchar(500) DEFAULT NULL COMMENT '召回关键词，逗号分隔（人工可维护，提升召回率）',
  `AutoConfirmThreshold` decimal(3,2) DEFAULT NULL COMMENT '自动确认阈值（NULL=用全局默认，见 P1）',
  `ReviewThreshold` decimal(3,2) DEFAULT NULL COMMENT '人工复核下限，低于此值直接判为不匹配（NULL=全局默认）',
  `Status` varchar(20) NOT NULL DEFAULT 'draft' COMMENT 'draft=草稿 / active=生效 / archived=归档',
  `RuleCode` varchar(36) DEFAULT NULL COMMENT '关联提取规则Code → cert_doc_extraction_rule.Code（有则契约3/4号要素存在）',
  `Remark` varchar(500) DEFAULT NULL COMMENT '备注',
  `IsDeleted` tinyint(1) NOT NULL DEFAULT '0' COMMENT '软删除',
  `DeleteBy` varchar(64) DEFAULT NULL COMMENT '删除人Code',
  `DeleteTime` datetime DEFAULT NULL COMMENT '删除时间',
  `IsValid` int NOT NULL DEFAULT '1' COMMENT '1有效0无效',
  PRIMARY KEY (`Id`),
  UNIQUE KEY `uk_code` (`Code`),
  UNIQUE KEY `uk_standard_file_code` (`StandardFileCode`),
  KEY `idx_config_code` (`ConfigCode`),
  KEY `idx_standard_code` (`StandardCode`),
  KEY `idx_stage_code` (`StageCode`),
  KEY `idx_status` (`Status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci COMMENT='标准文档契约（五要素1/2/5）';
```

**设计要点**
- `uk_standard_file_code`：一文件一契约，`GetByCode` 之外的天然幂等键（新增 vs 更新按 `StandardFileCode` 分流，符合准则 A 精神——业务键定位）。
- `DocPurpose` 用 `text`：作用说明是给 LLM 读的自然语言，长度不可控。
- `MatchPrompt`/`SynthesisPrompt` 存**已渲染的稳定模板正文**，占位符走 `wf_prompt_template` + `PromptRenderer`（若某标准文档需要独立模板，`RuleCode` 挂接；为空则用全局模板）。
- 阈值列可空：默认值在 `cert_sys_config` 全局配置（`ent_norm_auto_threshold=0.85`、`ent_norm_review_threshold=0.50`），单文档可覆盖。

### 3.2 `cert_ent_doc_profile` — 文档画像主表（字段/表格内嵌 JSON）

```sql
CREATE TABLE `cert_ent_doc_profile` (
  `Id` bigint NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `Code` varchar(36) NOT NULL COMMENT '业务键GUID',
  `CreateTime` datetime NOT NULL,
  `CreateBy` varchar(64) DEFAULT NULL,
  `UpdateTime` datetime DEFAULT NULL,
  `UpdateBy` varchar(64) DEFAULT NULL,
  `FileCode` varchar(36) NOT NULL COMMENT '企业文件Code → cert_standard_directory_file.Code（EnterpriseCode != YZH-STD-ENT）',
  `EnterpriseCode` varchar(36) NOT NULL COMMENT '企业Code（冗余）',
  `StageCode` varchar(36) NOT NULL DEFAULT '' COMMENT '阶段Code（冗余）',
  `StandardCode` varchar(36) NOT NULL DEFAULT '' COMMENT '标准Code（冗余）',
  `ProfileVersion` int NOT NULL DEFAULT '1' COMMENT '画像版本（重跑递增，旧版留存供对比）',
  `DetectSource` varchar(20) NOT NULL DEFAULT 'ai' COMMENT 'fingerprint=指纹 / ai=LLM / manual=人工指定 / mixed=混合',
  `DocCategory` varchar(20) DEFAULT NULL COMMENT 'fixed/editable/hybrid（画像结论）',
  `DocPurpose` text COMMENT '【作用提取】AI 归纳的文档作用（200-500字）',
  `DocTypeGuess` varchar(100) DEFAULT NULL COMMENT 'AI 猜测的标准文档类别（如 质量手册/培训记录/营业执照），供召回排序',
  `FieldKeywords` varchar(1000) DEFAULT NULL COMMENT '字段关键词摘要（逗号分隔，召回用倒排）',
  `TableCount` int NOT NULL DEFAULT '0' COMMENT '识别到的表格数',
  `FieldCount` int NOT NULL DEFAULT '0' COMMENT '识别到的字段数',
  `FingerprintResultJson` json DEFAULT NULL COMMENT '指纹匹配明细：{"matched":true,"rules":["fileName:营业执照"],"score":0.92}',
  `ProfileStatus` varchar(20) NOT NULL DEFAULT 'pending' COMMENT 'pending/processing/completed/failed/skipped(无Markdown产物)',
  `ProfileMessage` varchar(1024) DEFAULT NULL COMMENT '失败原因',
  `SourceMarkdownPath` varchar(512) DEFAULT NULL COMMENT '本次画像所用 Markdown 产物路径（输入快照）',
  `ModelName` varchar(100) DEFAULT NULL COMMENT '使用的模型（qwen-turbo 等）',
  `PromptTokens` int NOT NULL DEFAULT '0' COMMENT '消耗tokens（对账用，明细在 cert_ai_usage_log）',
  `CompletionTokens` int NOT NULL DEFAULT '0',
  `Confidence` decimal(3,2) DEFAULT NULL COMMENT '画像整体可信度 0.00-1.00（作用与类别判断的综合分）',
  `FieldsJson` json DEFAULT NULL COMMENT '画像字段数组 [{name,key,value,dataType,position,confidence,isKeyField}]',
  `TablesJson` json DEFAULT NULL COMMENT '画像表格数组 [{index,name,header,rowCount,columnCount,position,confidence}]',
  `IsLatest` bit(1) NOT NULL DEFAULT b'1' COMMENT '是否最新画像版本（查询过滤位）',
  `IsDeleted` tinyint(1) NOT NULL DEFAULT '0',
  `DeleteBy` varchar(64) DEFAULT NULL,
  `DeleteTime` datetime DEFAULT NULL,
  `IsValid` int NOT NULL DEFAULT '1',
  PRIMARY KEY (`Id`),
  UNIQUE KEY `uk_code` (`Code`),
  UNIQUE KEY `uk_file_latest` (`FileCode`,`ProfileVersion`),
  KEY `idx_enterprise_std` (`EnterpriseCode`,`StandardCode`,`StageCode`),
  KEY `idx_status` (`ProfileStatus`),
  KEY `idx_category` (`DocCategory`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci COMMENT='企业文档画像主表（字段/表格内嵌JSON）';
```

**设计要点**
- **字段/表格内嵌 JSON**：`FieldsJson` 和 `TablesJson` 将画像的子行数据以 JSON 数组形式存储在主表中，**不再建独立的 `_field` 和 `_table` 子表**。原因：
  1. 减少表数量，简化查询与维护
  2. 画像数据本质上是"快照"，不需要独立的关系型查询
  3. LLM 输出本身就是 JSON 结构，直接存储减少序列化开销
  4. 匹配引擎只需要读取这些字段做相似度计算，不需要跨表 JOIN
- `uk_file_latest(FileCode,ProfileVersion)` + `IsLatest` 位：重跑画像时插入新版本行，旧版本物理保留（可审计），查询用 `IsLatest=1`。**与 `ent_file_version` 同一「只追加」哲学**。
- `DocTypeGuess` 是**召回用的粗粒度类别**（LLM 输出的标准文档类别词），不是 `StandardFileCode`——匹配未定时不允许预判归属（守住 D9）。
- `Confidence` 画像级 NULL 可空，遵循 D8。

### 3.3 `cert_doc_match_candidate` — 匹配候选（核心）

```sql
CREATE TABLE `cert_doc_match_candidate` (
  `Id` bigint NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `Code` varchar(36) NOT NULL COMMENT '业务键GUID',
  `CreateTime` datetime NOT NULL,
  `CreateBy` varchar(64) DEFAULT NULL,
  `UpdateTime` datetime DEFAULT NULL,
  `UpdateBy` varchar(64) DEFAULT NULL,
  `EnterpriseCode` varchar(36) NOT NULL COMMENT '企业Code（冗余）',
  `StageCode` varchar(36) NOT NULL DEFAULT '' COMMENT '阶段Code（冗余）',
  `StandardCode` varchar(36) NOT NULL DEFAULT '' COMMENT '标准Code（冗余）',
  `FileCode` varchar(36) NOT NULL COMMENT '⭐企业文件Code → cert_standard_directory_file.Code',
  `ProfileCode` varchar(36) DEFAULT NULL COMMENT '打分所依据的画像版本Code → cert_ent_doc_profile.Code（重算对比用）',
  `StandardFileCode` varchar(36) NOT NULL COMMENT '⭐标准文件Code → cert_standard_directory_file.Code',
  `RecallSource` varchar(30) NOT NULL DEFAULT 'keyword' COMMENT '召回来源：fingerprint / filename / keyword / category / vector / manual',
  `RecallRank` int DEFAULT NULL COMMENT '召回排名（同来源内）',
  `SemanticScore` decimal(3,2) DEFAULT NULL COMMENT '语义相似度 0-1（标题/摘要 embedding 或 LLM 判定）',
  `FieldMatchRatio` decimal(3,2) DEFAULT NULL COMMENT '画像字段 vs 契约字段定义命中率 0-1',
  `TableMatchRatio` decimal(3,2) DEFAULT NULL COMMENT '画像表格 vs 契约表格定义命中率 0-1',
  `RuleStrength` decimal(3,2) DEFAULT NULL COMMENT '规则强度 0-1（指纹命中=1.0，文件名强匹配≈0.8）',
  `Confidence` decimal(3,2) NOT NULL COMMENT '⭐综合可信度 0.00-1.00（公式见04分册 §5.2）',
  `ScoreStage` varchar(20) NOT NULL DEFAULT 'recall' COMMENT 'recall=仅召回 / ranked=已精排 / human=人工指定',
  `EvidenceJson` json DEFAULT NULL COMMENT '证据链 [{"type":"field","field":"企业名称","profileValue":"XX公司","contractFieldCode":"ENT_NAME","hit":true},…]',
  `Reasons` varchar(1000) DEFAULT NULL COMMENT 'AI 匹配理由（一句话，展示给人工）',
  `IsConflicted` bit(1) NOT NULL DEFAULT b'0' COMMENT '冲突标记（见04分册 §6 四类冲突）',
  `ConflictType` varchar(30) DEFAULT NULL COMMENT 'multi_source / multi_target / low_field_coverage / period_mismatch',
  `Status` varchar(20) NOT NULL DEFAULT 'pending' COMMENT 'pending=待精排 / scored=已打分 / recommended=系统推荐 / confirmed=已采纳 / rejected=已否决 / superseded=被更优候选替代',
  `RankBatchCode` varchar(36) DEFAULT NULL COMMENT '本轮打批次Code（同批结果可比，供排序与重算）',
  `IsDeleted` tinyint(1) NOT NULL DEFAULT '0',
  `DeleteBy` varchar(64) DEFAULT NULL,
  `DeleteTime` datetime DEFAULT NULL,
  `IsValid` int NOT NULL DEFAULT '1',
  PRIMARY KEY (`Id`),
  UNIQUE KEY `uk_code` (`Code`),
  UNIQUE KEY `uk_file_std` (`FileCode`,`StandardFileCode`),
  KEY `idx_target` (`StandardFileCode`,`Confidence`),
  KEY `idx_enterprise_std` (`EnterpriseCode`,`StandardCode`,`StageCode`),
  KEY `idx_status` (`Status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci COMMENT='企业文档↔标准文档匹配候选';
```

**设计要点**
- `uk_file_std`：同一对企业文档/标准文档**只保留一条候选行**，重跑打分 UPDATE 而非 INSERT，避免候选表爆炸；批次信息落在 `RankBatchCode`。
- 五个分维度分数 + 综合 `Confidence` 全部落库：人工判断页要展示「为什么是 72%」，不能只存结果。
- `idx_target(StandardFileCode,Confidence)`：**按标准文档视角**查「谁最像我」是最高频查询（用户第三步的人工干预正是这个视角）。
- `EvidenceJson` 结构在 04 分册 §4.3 给出 schema。

### 3.4 `cert_doc_match_decision` — 人工裁决与审计

```sql
CREATE TABLE `cert_doc_match_decision` (
  `Id` bigint NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `Code` varchar(36) NOT NULL COMMENT '业务键GUID',
  `CreateTime` datetime NOT NULL COMMENT '裁决时间',
  `CreateBy` varchar(64) DEFAULT NULL COMMENT '裁决人Code',
  `UpdateTime` datetime DEFAULT NULL,
  `UpdateBy` varchar(64) DEFAULT NULL,
  `EnterpriseCode` varchar(36) NOT NULL COMMENT '企业Code（冗余）',
  `StageCode` varchar(36) NOT NULL DEFAULT '',
  `StandardCode` varchar(36) NOT NULL DEFAULT '',
  `FileCode` varchar(36) NOT NULL COMMENT '企业文件Code',
  `StandardFileCode` varchar(36) NOT NULL COMMENT '标准文件Code',
  `CandidateCode` varchar(36) DEFAULT NULL COMMENT '所依据候选Code → cert_doc_match_candidate.Code；人工指定时为NULL',
  `Action` varchar(20) NOT NULL COMMENT 'accept=采纳 / reject=否决 / replace=改换来源 / manual=绕过候选手工指定 / unlink=解除已有关联',
  `BeforeStandardFileCode` varchar(36) DEFAULT NULL COMMENT '裁决前该企业文件的 StandardFileCode（变更留痕）',
  `ConfidenceUsed` decimal(3,2) DEFAULT NULL COMMENT '裁决时所见的可信度（快照）',
  `Reason` varchar(1000) DEFAULT NULL COMMENT '裁决理由（可选但推荐）',
  `FieldOverrideJson` json DEFAULT NULL COMMENT '字段级覆盖 {"ENT_NAME":{"value":"XX公司","source":"manual"}}',
  `Trigger` varchar(20) NOT NULL DEFAULT 'manual' COMMENT 'manual=人工 / auto_rule=高置信自动 / system_recalc=重算回退',
  `IsAuto` bit(1) NOT NULL DEFAULT b'0' COMMENT '是否自动动作（审计区分人机）',
  `IsDeleted` tinyint(1) NOT NULL DEFAULT '0',
  `DeleteBy` varchar(64) DEFAULT NULL,
  `DeleteTime` datetime DEFAULT NULL,
  `IsValid` int NOT NULL DEFAULT '1',
  PRIMARY KEY (`Id`),
  UNIQUE KEY `uk_code` (`Code`),
  KEY `idx_target` (`StandardFileCode`,`CreateTime`),
  KEY `idx_file` (`FileCode`),
  KEY `idx_enterprise_std` (`EnterpriseCode`,`StandardCode`,`StageCode`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci COMMENT='匹配人工裁决与审计（只追加）';
```

**设计要点**
- **只追加**：裁决不 UPDATE，改换来源 = 新增一条 `replace` + 旧候选置 `superseded`。审计天然完整。
- `BeforeStandardFileCode` + `Action` 支持任意时刻回放「这个标准文档的来源变迁史」。
- `IsAuto` 区分人机：延展规划 09 号文的审计体系可直接按此字段聚合。
- 完整审计（前后值 diff、操作上下文、是否影响 NC）在 07 号分册扩展；本表先保证**最小充分**。

用户提出的文档五要素，逐一落到字段：

**要素 3/4 的加列 DDL**（独立小脚本，随契约页实施）：

```sql
ALTER TABLE `cert_doc_field_def`
  ADD COLUMN `CellPrompt` text COMMENT '【要素3】该单元格填写提示词：取值口径/单位/枚举/示例，供 AI 提取与人工填写指引' AFTER `Description`;

  ADD COLUMN `TablePrompt` text COMMENT '【要素4】该表格填写规则：表头含义/行合并规则/必填列/示例行' AFTER `Description`;
```
