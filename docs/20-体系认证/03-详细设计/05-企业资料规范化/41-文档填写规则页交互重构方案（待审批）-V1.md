# 41 · 文档填写规则页交互重构方案（待审批）· V1

> **本文只解决一件事**：用户 2026-10-04 对「文档填写规则」页的第 4 条反馈 ——
> **「一个文档，第一步是判断该文档是哪种类型，针对类型才进行下一步的操作」**
> **「锚点的操作非常奇怪，点击锚点、设置规则、必填等好像没有什么效果」**
> **「还不如将锚点修改为卡片模式，方便显示状态，和操作按钮」**
>
> 同批反馈的另 3 条是**缺陷**（已修，见 §6），不在本文讨论范围。

---

## 0. 一句话结论

**整体成立**：用户的判断是对的 —— 本页的信息架构把「文档类型」这个**唯一的流程分叉点**
埋在了第 3 个页签里，而锚点用表格承载「状态 + 操作」本身就是错配。

**要裁决 2 条**（§4）：
- **D1**：类型选择放在「右栏常驻顶部」还是「独立第一步（步骤条）」？
- **D2**：锚点卡片默认**全展开**还是**折叠**？

---

## 1. 问题归因

| 用户原话 | 真实归因 | 性质 |
|---|---|---|
| 第一步应判断该文档是哪种类型 | `DocCategory`（editable / fixed）现在藏在**第 3 个页签「文档契约」**里；且**类型未定之前**页签组就已经渲染出来了 ⇒ 用户看到 4 个页签，不知道该先点哪个 | **信息架构错位** |
| 点锚点、设置规则、必填「好像没有什么效果」 | ① 「必填」是侧边栏里的 `el-switch`，**必须滚到底部点「保存规则」才生效** —— 开关拨了却什么都不发生；② 列表是**表格**，改完只有一个小徽标变化，变化太弱；③ 侧边栏 580px **盖住了中栏预览**，而配锚点恰恰要边看文档边配 | **反馈缺失 + 布局冲突** |
| 建议锚点改成卡片模式 | 表格一行只有 ~40px 高，塞不下「状态徽标 + 来源摘要 + 操作按钮」三样东西；卡片天然支持 | **呈现形式** |

**一句话**：不是功能没做，是**做在了用户看不见/够不着的地方**。

## 2. 方案总览

### 2.1 类型优先（把分叉点提到最前面）

**现状**（右栏）：
```
[页签] 锚点与字段规则 | 全文填写规则 | 文档契约 | 校验结果
                                  ↑ 类型在这里面
```

**改为**：
```
┌ ① 文档类型 ────────────────────────────────┐
│  ( • ) 可编辑文档        (   ) 固定格式（免填）│   ← 常驻，不占页签
│  要配填写规则              PDF/图片/扫描件      │
└────────────────────────────────────────────┘
[页签] 随类型变化
  editable → 锚点规则 | 全文规则 | 文档信息 | 校验结果
  fixed    → 指纹规则 | 文档信息
```

**关键点**：
- 类型选择器**常驻顶部**，任何页签下都看得见、随时可改（改完立即保存）。
- 选中类型**之前**，页签区显示一句引导（而不是 4 个点进去都不知道干嘛的页签）。
- 「文档契约」页签改名为 **「文档信息」**（它承载的是名称/角色/作用/标签/包含信息，
  而「分类」已经上移到顶部 —— 名字不改会让人以为分类还在里面）。
- 类型切换**立即落库**（走已有 `StandardDocContract/save`），复用刚修好的 JSON 归一。

### 2.2 锚点卡片化

**现状**：`YzhTable` 一行 + 点击弹侧边栏。

**改为**：卡片列表。

```
┌──────────────────────────────────────────────────┐
│ {{ENT_NAME}}                          ⚠ 未配来源 │  ← 标题：锚点原文（mono）+ 状态徽标
│ 标量 · 正文 · 字段 ENT_NAME                      │  ← 元信息：类型 · 位置 · 语义字段
│ 来源：全局参数 CERT_ORG_NAME → 落空留空          │  ← 来源摘要（人话，前端现算）
│ ──────────────────────────────────────────────── │
│ [配置规则]        [必填 ⚪]        [删除]        │  ← 操作行
└──────────────────────────────────────────────────┘
```

**卡片解决了什么**：
| 用户痛点 | 卡片如何解决 |
|---|---|
| 看不到状态 | 状态徽标放**标题行右侧**，一屏扫完 |
| 设置规则/必填没效果 | 「必填」改成**就地开关，拨动即存**（乐观更新 + toast），不再需要进侧边栏再滚到底保存 |
| 操作按钮够不着 | 操作按钮**贴在卡片上**，不用先点开什么 |
| 侧边栏盖住预览 | 「配置规则」仍开侧边栏，但**收窄到 420px**（只覆盖右栏，预览保持可见） |

**状态徽标口径**（互斥，优先级从高到低）：
1. `孤儿`（`IsOrphan`）—— 黄，换版后消失的锚点
2. `未配来源` —— 红，运行期必然留空
3. `必填` —— 蓝，已勾选必填
4. `已配` —— 绿，来源链完整

**保留现有能力**（⛔ 不删）：
- 顶部统计条（N 自动 / N 人工 / N 计算 / N 未配 / N 孤儿）
- 4 个快速筛选（全部 / 未配来源 / 必填 / 孤儿）
- 来源链编辑器（`AnchorSidePanel`）—— 它是本页最复杂也最不可替代的部分

## 3. 卡片字段规格

| 区域 | 字段 | 来源 | 说明 |
|---|---|---|---|
| 标题行 | `AnchorRef` | 锚点行 | mono 字体，长值截断 + `title` 悬浮全显 |
| 标题行 | 状态徽标 | 前端现算 | 见 §2.2 口径 |
| 元信息行 | `AnchorType` + `DomainKind` | 锚点行 | 如「标量」「域自动」 |
| 元信息行 | 位置 | `SheetName` / `HeaderKind` | Excel 表名 / 页眉页脚 / 正文 |
| 元信息行 | `FieldCode` | 锚点行 | 可空，空则不显示 |
| 来源行 | 来源摘要 | `SourceSpec` 前端现算 | 复用 `summarizeSourceSpec()` |
| 操作行 | 配置规则 | — | 打开 `AnchorSidePanel` |
| 操作行 | 必填开关 | `Required` | **就地保存**（`save-batch` 整行提交） |
| 操作行 | 删除 | — | 仅 `孤儿` / `未配来源` 显示，软删 |

## 4. 待裁决（2 条）

### D1 · 类型选择放哪里？

| 选项 | 形态 | 优点 | 代价 |
|---|---|---|---|
| **A（推荐）** | **右栏常驻顶部**（§2.1 图） | 改动小；类型与页签同屏，随时可改；不动 `el-tabs` 结构 | 右栏纵向多占 ~64px |
| B | 右栏改**三步步骤条**（① 判类型 → ② 配规则 → ③ 校验） | 流程感最强，最贴合用户「第一步是判断类型」的表述 | 改动大；「边看边配」的来回跳转变麻烦（步骤条不适合反复横跳） |

> **推荐 A 的理由**：本页的真实使用模式是**反复横跳**（看预览 → 改锚点 → 校验 → 回来改），
> 步骤条适合「一次性走完」的流程，用在反复横跳的场景反而增加点击。
> 而用户要的「第一步是判断类型」，A 已经满足：类型在**最上方**、**最显眼**、**未选时给引导**。

### D2 · 卡片默认展开还是折叠？

| 选项 | 说明 |
|---|---|
| **A（推荐）** | **全展开**（固定三行）。一屏 ~4~5 张卡；锚点规模在几十量级，靠筛选定位 |
| B | 折叠：默认只显示标题行，点击展开元信息/来源/操作 |

> **推荐 A**：卡片的价值就在「一眼看到状态和操作」；折叠会把操作按钮藏起来，等于把
> 刚修好的问题（够不着）又犯一遍。

## 6. 同批缺陷（已修，2026-10-04）

| # | 缺陷 | 根因 | 修法 |
|---|---|---|---|
| 1 | tab 页签贴边无 padding | EP 有 `.el-tabs--top ... .el-tabs__item:nth-child(2){padding-left:0}`（特异性 0,4,0）**强制抹掉首尾页签内边距**，上一轮又把 `nav-wrap` padding 归零 | `nav-wrap` 补 12px + item padding 加 `!important` 压过 EP |
| 2 | 重传模板后锚点「重复」 | `UpsertTemplateAsync` 只重置 `PublishStatus/ScanStatus/ViolationJson`，**旧锚点一条不删** ⇒ 新旧并存 | 换版（`SourceSha256` 变化）时**软删全部旧锚点**，由重扫按 `uk_tpl_anchor` 逐条复活 |
| 3 | 保存契约报 `Invalid JSON text: "The document is empty."` | 标签为空时前端提交**空串**，`cert_standard_doc_contract.TagsJson` 是 MySQL `json` 列 | 前端改发 `'[]'`；后端加 `ToJsonArray/ToJsonObject` **第二道闸** |

## 7. 验收口径

- [ ] 选中一个**从未配过契约**的文件 → 右栏顶部直接可见类型选择，页签区给引导而非 4 个空页签
- [ ] 切到「固定格式」→ 页签组**立刻**变为「指纹规则 / 文档信息」，且刷新页面后保持
- [ ] 锚点以卡片呈现，**每张卡都能看到状态徽标与操作按钮**，不需要点开任何东西
- [ ] 拨动「必填」开关 → **无需点保存**，toast 提示 + 徽标立即变化 + 刷新页面后仍为必填
- [ ] 「配置规则」打开侧边栏后，**中栏预览仍然可见**
- [ ] 重传空白模板 → 旧锚点消失，扫描后列表**只包含新文档里的 token**
