## 1. 三层同构清单

新增模块四件套（同名同路径）：

| 层 | 路径 | 说明 |
|----|------|------|
| Controller | `CertPlatform.Admin/Controllers/Ent/EnterpriseFileController.cs` 等 | 后端入口 |
| Service | `CertPlatform.Admin/Services/Ent/…` | 业务实现（Controller 薄壳） |
| API（前端） | `cert/cert-share/src/api/ent/{enterprise-file,ent-doc-profile,match-candidate,match-decision,standard-doc-contract}.ts` | 手写 API，用 `yzhApi` |
| Pages（前端） | `cert/cert-admin/src/pages/ent/{enterprise-file,match-review,standard-doc-contract}/` | 页面文件夹 |

**模块划分与文件命名**：

| 模块 | Controller | Service | api/ent/*.ts | pages/ent/* |
|------|-----------|---------|--------------|-------------|
| 企业资料库 | `EnterpriseFolderController`、`EnterpriseFileController` | `EnterpriseFileService`（含上传/版本） | `enterprise-file.ts` | `enterprise-file/` |
| 文档画像 | `EntDocProfileController` | `EntDocProfileService` | `ent-doc-profile.ts` | `ent-doc-profile/`（只读列表+重跑） |
| 匹配候选 | `MatchCandidateController` | `MatchRecallService`/`MatchRankService`/`MatchArbitrateService` | `match-candidate.ts` | 并入 `match-review/` |
| 匹配裁决 | `MatchDecisionController` | `MatchDecisionService` | `match-decision.ts` | `match-review/`（核心裁决页） |
| 标准文档契约 | `StandardDocContractController` | `StandardDocContractService` | `standard-doc-contract.ts` | `standard-doc-contract/` |

> **domain 取 `ent`**（企业资料域）：对应实体目录 `CertPlatform.Shared/Entities/Ent/`（02 §8.3 新建）与前端 `ent/` 目录，一处定名全域通用。

**实体位置**（02 §8.3）：`CertPlatform.Shared/Entities/Ent/`（EnterpriseFolder/EnterpriseFile/EnterpriseFileVersion/EntDocProfile…）、契约实体在 `Entities/Dir/StandardDocContract.cs`（与宿主同域）、匹配两表在 `Entities/Ent/`。

## 2. 后端结构与基类选型

| Controller | 继承 | 理由 |
|------------|------|------|
| `EnterpriseFolderController` | `TreeTableControllerBase<EnterpriseFolder, X>` | 纯树结构（文件夹树），照抄左树右表样板后端 |
| `EnterpriseFileController` | `YzhControllerBase<EnterpriseFile>` | 单表 CRUD + 分页 |
| `EntDocProfileController` / `MatchCandidateController` | `ControllerBase`（职能特殊） | 只读查询 + 重跑触发，无标准 CRUD 语义——**AGENTS.md ③ 允许**（按职能选用），但要在类注释写明理由 |
| `MatchDecisionController` | `ControllerBase` | 动作型端点（accept/reject/…），不暴露通用增删改 |
| `StandardDocContractController` | `YzhControllerBase<StandardDocContract>` | 单表 CRUD（含状态流转钩子） |

**服务层**：

```text
Services/Ent/
  EnterpriseFileService.cs        上传受理/版本/路径（PathBuilder 唯一入口 D10）
  EntDocProfileService.cs         C2 指纹 + C3 画像 + 落库（列白名单）
  MatchRecallService.cs           C4 多路召回（纯计算）
  MatchRankService.cs             C5 精排批调用 + 解析校验
  MatchArbitrateService.cs        C6 阈值/冲突分流
  MatchDecisionService.cs         C7 裁决事务（07 §3.5 六步）
  StandardDocContractService.cs   契约 CRUD + 状态校验 + 冗余同步
Tasks/Ent/
  EntDocProfileTaskExecutor.cs    队列消费（照抄 OfficeConvertTaskExecutor 模板）
  EntDocMatchTaskExecutor.cs      召回+精排任务
```

**新增队列任务类型**：`ent_doc_profile`、`ent_doc_match`，注册照抄 `CertPlatformAdminServiceExtensions.cs:54-61`，中文名同步 `CertQueueNotifier.cs:17-22`（02 §4.3）。

**回写纪律**（全模块统一）：状态回写用**指定列更新**（各表列白名单见 03 §4.3、07 §3.5），⛔ 禁止 `UpdateAsync(整实体)`；业务状态在 `ExecuteAsync` 内完成，`OnTaskStateChangedAsync` 不承载业务。

## 3. 端点定义

> 路由前缀 = Controller 名去 Controller；`ApiCode` = 路由全路径（改名即断权限关联，须重跑 ApiSync——AGENTS.md ②）。

### 3.1 企业资料库

| 方法 | 路由 | 说明 | 权限点 |
|------|------|------|--------|
| GET | `/EnterpriseFile/Page` | 分页（`YzhTable` 数据源，支持企业/阶段/文件夹过滤） | `EntFile/Query` |
| GET | `/EnterpriseFolder/Tree` | 文件夹树 | `EntFolder/Query` |
| POST | `/EnterpriseFolder/Save` | 新增/更新（`Code` 分流） | `EntFolder/Save` |
| POST | `/EnterpriseFolder/Delete` | 软删（按 `Code`） | `EntFolder/Delete` |
| POST | `/EnterpriseFile/UploadInit` `/UploadPart` `/UploadConfirm` `/UploadCancel` | 四段式分片（复用标准目录样板 226-307 模式） | `EntFile/Upload` |
| GET | `/EnterpriseFile/Versions` | 版本列表（只追加） | `EntFile/Query` |
| GET | `/EnterpriseFile/Preview` | 预览（PDF/Markdown 产物，签权直链） | `EntFile/Preview` |
| POST | `/EnterpriseFile/Delete` | 软删（按 `Code`） | `EntFile/Delete` |

### 3.2 画像

| 方法 | 路由 | 说明 | 权限点 |
|------|------|------|--------|
| GET | `/EntDocProfile/Page` | 画像列表（`IsLatest=1`） | `EntProfile/Query` |
| GET | `/EntDocProfile/Detail` | 主表 + 字段 + 表格（按 `ProfileCode`） | `EntProfile/Query` |
| POST | `/EntDocProfile/Reprofile` | 单文件重跑（入队 `ent_doc_profile`） | `EntProfile/Reprofile` |
| POST | `/EntDocProfile/BatchReprofile` | 批量重跑（分企业分批，限管理员） | `EntProfile/Reprofile` |
| GET | `/EntDocProfile/Unmatched` | 无归属清单（画像完成但零候选） | `EntProfile/Query` |

### 3.3 匹配与裁决

| 方法 | 路由 | 说明 | 权限点 |
|------|------|------|--------|
| POST | `/MatchCandidate/Trigger` | 触发企业/阶段级匹配（入队 `ent_doc_match`） | `MatchCandidate/Trigger` |
| GET | `/MatchCandidate/PageByTarget` | **按标准文档视角**取候选（04 §6.3 主查询） | `MatchCandidate/Query` |
| GET | `/MatchCandidate/PageByFile` | 按企业文件视角取候选 | `MatchCandidate/Query` |
| GET | `/MatchCandidate/ConflictList` | 冲突候选清单 | `MatchCandidate/Query` |
| POST | `/MatchDecision/Submit` | 裁决动作（body：`Action/FileCode/StandardFileCode/CandidateCode/Reason`） | `MatchDecision/Submit` |
| GET | `/MatchDecision/Timeline` | 单文件/单标准文档裁决时间线 | `MatchDecision/Query` |
| GET | `/MatchDecision/Audit` | 审计查询（人机/误配复盘，管理员） | `MatchDecision/Audit` |

### 3.4 契约

| 方法 | 路由 | 说明 | 权限点 |
|------|------|------|--------|
| GET | `/StandardDocContract/Page` `/Detail` | 契约查询 | `Contract/Query` |
| POST | `/StandardDocContract/Save` | 保存（按 `StandardFileCode` 分流 + active 前置校验） | `Contract/Save` |
| POST | `/StandardDocContract/Status` | 状态流转 draft→review→active→archived | `Contract/Save` |
| POST | `/StandardDocContract/Seed` | 批量种子（幂等） | `Contract/Seed` |
| POST | `/StandardDocContract/RefreshMirror` | 刷新冗余镜像列（05 §4.1） | `Contract/Save` |
| POST | `/StandardDocContract/AssistPurpose` | C10 AI 辅助生成 `DocPurpose` 初稿 | `Contract/Assist` |
| POST | `/StandardDocContract/TestMatch` | 选 1 份样本文件试跑指纹/精排（模板校验用） | `Contract/Test` |

**约定**：全部返回 `ApiResponse` 信封；业务失败 HTTP 200 + `success=false`（`22-接口返回规范-V1.md`）；新增 vs 更新按业务键分流（`GetByCode` / `StandardFileCode`），`Id` 不进 WHERE。

## 4. 前端页面与样板

| 页面 | 路由 | 样板 | 说明 |
|------|------|------|------|
| 企业资料库 | `/ent/enterprise-file` | **左树右表** `foundation/iso-standard/`（只抄 `logic.ts` 的 `dataLoader` 骨架） | 左树=文件夹，右表=文件，上传按钮走 `YzhFolderUpload` |
| 匹配裁决 | `/ent/match-review` | 左树右表变体（07 §2.2 结构） | 右侧候选列表 + 详情抽屉；证据预览定位 |
| 文档画像 | `/ent/ent-doc-profile` | 单表 CRUD `system/user/`（零手写内核） | 只读列表 + 重跑动作 |
| 契约维护 | `/ent/standard-doc-contract` | 单表 CRUD + 详情抽屉 | 五要素编辑；指纹/提示词测试按钮 |

**硬约束**（AGENTS.md ①）：
- 单表 CRUD **零手写** `handleAdd/handleSubmit/...`，一律 `useSingleTable` 内核派发；
- ⛔ 禁 `view-grid/VolBox/VolForm/VolProvider/axios`、`.vue` 内禁直接 `fetch(`；
- API 用 `yzhApi`，信封读取按 L1–L4 顺序（`22-接口返回规范`）；
- 字段名 PascalCase 逐字一致（`row.MatchState`、`formData.StandardFileCode`），写 camelCase → **渲染空行且无报错**。

**新增路由/菜单**：注册后必跑 `node scripts/guards.mjs`（R12 路由↔菜单双向）+ `./scripts/db/verify/sync_menu_urls.sh` 刷新菜单快照。

**P4 影响**：若企业端（`cert-enterprise`）启用上传，同款页面在其端复用（`cert-share` API 不变），仅路由与菜单归属不同；首期按「审核员代传」实施则企业端零改动。

## 5. 权限点与 ApiSync

1. 每个端点定 `ApiCode`（上表）；**新增接口后重跑 ApiSync 同步 `sys_api`**，再在角色-接口页关联（AGENTS.md ②）；
2. 菜单 + 按钮级权限点按 07 §7 三角色矩阵配置：企业端无 `MatchDecision/*`、审计仅管理员；
3. ⚠️ `sys_api` 若仍有 `Enable` 列，按铁律九迁移为 `IsValid` 后再配（README §3.3）；
4. 改端点/动作名 = ApiCode 变化 = 权限静默断裂 → **改名必须重跑 ApiSync + 重关联**，并在合并说明中显式声明。

## 6. 守卫与验收命令

```bash
# ① 前端守卫（0 违规，含 R12）
cd src/certplatform-web && node scripts/guards.mjs

# ② 动了路由/菜单 → 刷新菜单快照（否则 R12 基于过期数据）
./scripts/db/verify/sync_menu_urls.sh

# ③ 前端构建（含 vue-tsc 类型检查）
cd src/certplatform-web && npm run build

# ④ 后端编译 0 错误
dotnet build src/yzh-core/YZH.Core.Web   # 启动入口（项目引用 certplatform-api）

# ⑤ 数据库验证（02 §8.2：无 Enable 列 / utf8mb4_general_ci / uk_code / 无 PhaseCode / decimal(3,2)）
```

> 后端启停走 `scripts/backend/` 脚本，⛔ 禁手动 `kill` / 裸 `dotnet run`（项目全局规则 §十五）。
