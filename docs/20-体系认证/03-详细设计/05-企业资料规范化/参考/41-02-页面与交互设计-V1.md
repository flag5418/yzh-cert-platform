## 二、左树：五级 + 徽标

### 2.1 层级结构（26 号 §2.2 表格原文）

```text
● G4测试企业甲                        ← enterprise
   ● ISO 9001:2015                    ← standard   （循环的维度）
      ● 复审                          ← stage      点它 = 该标准该阶段【全量】规范化
         ● 4 记录文件                 ← folder     点它 = 该目录【全量】规范化
            ▸ 风险管理报告             ← file       点它 = 【单文件】规范化
              🔒 已锁定
            ▸ 内审计划
              ⚪ 未生成
```

> ★ 这是 **26 号 §3.6 唯一的 ASCII 原型**，本册**原样沿用**，仅补徽标（第 2.3 节）。

**五种节点与点击语义**：

| 节点 | `Type` | 点击 = 规范化范围 | 后端入参 |
|------|--------|------------------|---------|
| 企业 | `enterprise` | 该企业**全部标准** | `ScopeType = 'enterprise'` |
| 标准 | `standard` | 该企业 × 该标准**全部阶段** | `ScopeType = 'standard'` |
| 阶段 | `stage` | 该标准该阶段**全量** | `ScopeType = 'stage'` |
| 文件夹 | `folder` | 该文件夹**含子文件夹** | `ScopeType = 'folder'` |
| 文档 | `file` | ★ **单文件** | `ScopeType = 'file'` |

> ⚠️ **「标准」是循环的维度，不是「上传」维度** —— 26 号 §2.2 原文：
> 「⑤ 为什么树里没有『标准』：企业上传的原始资料是**标准无关**的。标准是**规范化阶段**才引入的维度 —— 这正是你说的『按每个标准循环企业的资料』。」

## 四、★ 一键规范化：三级粒度 + 干跑预览

### 4.1 粒度模型（26 号 §3.6 原文，正确且已按 Q-J 方案 A 落地）

```text
┌─ 范围（用户点的树节点）────────────────────────────┐
│  企业 / 标准 / 阶段 / 目录 / 单个文件              │
│  ↓ 展开成文件清单（后端 normalize/plan 计算）       │
│  yzh_queue  ← 一个范围 = 一个「批次」，只做统计与进度 │
│    ├── yzh_queue_task  ← 一个文件 = 一个任务（原子） │
│    ├── yzh_queue_task  ← 一个文件 = 一个任务        │
│    └── yzh_queue_task  ← 一个文件 = 一个任务        │
└────────────────────────────────────────────────────┘
```

> **Q-J 特别说明**（26 号原文，避免术语混）：
> ```
> 用户说的「一个文件的规范化是一个队列」
>   → 工程落地 = 一个文件 = 一个【任务】（yzh_queue_task）
> 用户说的「不同的范围是队列的范围不一样」
>   → 工程落地 = 范围 = 一个【批次】（yzh_queue）
> ```

### 4.2 ★ 干跑预览（范围卡片）是**强制前置**，⛔ 不能跳过

点「一键规范化」**不立即入队**，而是先调 `POST /normalize/plan` 拿一份**纯统计**结果：

| 显示项 | 后端字段 | 判定规则 |
|--------|---------|---------|
| 本次将规范化 N 个文档 | `TotalCount` | 展开后的文件清单长度 |
| · 新增 M | `NewCount` | `NormalizedPath` 为空 |
| · 重新生成 K | `RegenCount` | `NormalizedPath` 非空 且 `IsLocked = 0` |
| · **跳过 S（已锁定 🔒）** | `SkippedLockedCount` | `IsLocked = 1`（**26 号 S-6**） |
| · 跳过 T（无模板） | `SkippedNoTemplateCount` | 无 `cert_doc_template` 行 或 `PublishStatus ≠ 'published'` |
| · 跳过 U（无锚点） | `SkippedNoAnchorCount` | 锚点数 = 0（**25 号：42.5% 的文件属此类，UI 要说清「纯复制即可」**） |
| 范围完成率预览 | `ScopeCompletionPreview` | `Σ已写入 / Σ分母`（⛔ **不能平均子文档的完成率**，见 `41-01` §二·3） |
| 预计耗时 | `EstimateSeconds` | `TotalCount × ~15s` |
| ⚠ 警告清单 | `Warnings[]` | 如「3 个文档尚未上传空白模板」「2 个文档锚点全为示例数据」 |

> **为什么必须干跑**：26 号 S-8「失败可解释」+ S-1「幂等：连点两次 `[开始生成]`，产物不重复、版本不虚增」。
> 干跑是幂等的**前置验证** —— 用户在入队前就能看到「会跳过什么、为什么跳过」。

### 4.3 按钮态机（防重复提交）

```text
未生成 ──[一键规范化]──► 范围卡片(预览) ──[开始规范化]──► 入队中(按钮禁用+转圈)
   ▲                                                        │
   │                                                        ▼
   └──────────── 已生成 ◄── 批次完成 ◄── yzh_queue 进度 ◄───┘

已生成 ──[↻重新生成]──► 范围卡片 ──[开始]──► …（跳过已锁定项）
已锁定 ──[🔒锁定]──► 锁定态 ──[🔓解锁]──► 解锁态（写 cert_doc_normalize_action）
```

> ⚠️ **`[↻ 重新生成]` 与 `[▶ 一键规范化]` 是两个按钮，⛔ 不合并**：
> 「一键规范化」= 智能判定新增/跳过；「重新生成」= **强制重跑**（但仍跳过已锁定项 —— 26 号 S-6）。

| `ai` | AI 候选（`cert_doc_ai_suggestion`：多候选 + `SuggestionIndex` + `Reason`） | ★ `[换用其他候选]` `[预览原始文件]` |
| `manual` | 录入人 + 录入时间 + 理由 | `[查看操作留痕]` |

> **⭐ 25 号实测的关键事实要在 UI 里体现**：一期 **98.6% 的锚点是确定性来源**（`SourceKind ∈ {global, compute, replace}`），
> 真实企业资料来源（`profile`）**占比 0%**。
> ⇒ **界面默认排序应该是「确定性来源」优先展示，「AI 建议」折叠**，否则专家会觉得「怎么全是 AI 填的」，与事实不符。

### 5.2 交互二：更改数据来源（4 种方式）

| 方式 | 作用域 | 落库 | 是否重生成 | 前置校验 |
|------|--------|------|-----------|---------|
| **① 换来源（保留值）** | 本单元格 | `cert_doc_fill_value.SourceKind/SourceDetailJson/Confidence` + `IsOverridden=1` | ⛔ 否（只改账本标注） | 必须有 ≥2 个候选来源 |
| **② 手填值** | 本单元格 | `ValueText/ValueNumber/ValueDate` + `OverrideKind='value'` + `Reason` ⛔ 必填 | ✅ 是（重跑 NPOI 落笔） | `Reason` 非空 |
| **③ 改锚点规则（全局）** | ★ **该模板的所有企业** | `cert_doc_template_anchor.SourceSpec/WriteMode/FieldCode` | ⛔ 否（当前文件不变，下次生效） | ⚠️ 弹二次确认 + 显示「影响 N 家企业 / M 个历史产物」 |
| **④ 钉住此值** | 本单元格 | `IsPinned = 1` | ⛔ 否 | — |

> ⚠️ **方式 ③ 是最危险的操作，必须有影响面提示**。
> 参照 37 号 `Q-8` / 20 号 Q-3 的口径（「同一语义两处可写 ⇒ 静默不一致」）：
> **⛔ 本册 ⛔ 不在专家端页面编辑锚点规则**，只提供跳转按钮到 `cert-admin` 的 `MENU_00218`「标准文档填写规则」。
> ⇒ 这就是 22 号 `F-9`「锚点属性定义在后台，专家端只读 + 跳转」的落实。

**置信度连带规则**（`41-01` §三·R-C3）：

| 操作 | `Confidence` 变化 | `ConfidenceReason` |
|------|------------------|-------------------|
| ① 换来源 | 取新来源的分 | 若新来源是 `profile` → 写「取自《文件名》，未人工确认」 |
| ② 手填值 | **强制 1.00** | 清空 |
| ③ 改锚点规则 | ⛔ 本行不变 | ⛔ 本行不变 |
| ④ 钉住 | ⛔ 不变 | ⛔ 不变 |

### 5.3 交互三：全部重写

**触发**：抽屉右上 `[↻ 全部重写]`，或工具栏 `[↻ 重新生成]`。

**⭐ 五条不覆盖规则**（`41-01` §四 + `37` 号 §7.4 + `26` 号 S-6）：

| # | 规则 | 判据 | 界面反馈 |
|---|------|------|---------|
| **①** | **锁定的文件整份跳过** | `IsLocked = 1` | 预览条显示「跳过 2（已锁定 🔒）」 |
| **②** | **钉住的单元格跳过** | `IsPinned = 1` | 预览条显示「其中 5 个单元格已钉住，将保留」 |
| **③** | **人工改过的值默认保留** | `IsOverridden = 1` 且 `OverrideKind ∈ ('value','both')` | 弹窗让用户选「保留人工值（推荐）」/ 「全部覆盖」 |
| **④** | **示例数据必须清空** | `cert_doc_template_anchor.SampleData = 1` | ⛔ **不可跳过** —— 合规要求（25 号 Q-5） |
| **⑤** | **模板指纹未变则整轮跳过** | `cert_doc_template.SourceSha256` 未变 且 无规则变更 | 提示「模板未变化，是否仍要重跑？」（让人工决定） |

> ⚠️ **规则 ③ 的默认值必须是「保留人工值」**。
> 若默认覆盖，专家辛苦核对的 3 个单元格会在下次全量规范化时被冲掉 —— 这是最伤信任的设计。
