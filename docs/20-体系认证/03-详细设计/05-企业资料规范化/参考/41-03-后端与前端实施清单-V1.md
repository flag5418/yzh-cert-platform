### 1.4 ★ 可信度计算器（新增，26 号未定义算法）

**位置**：`CertPlatform.Auditor/Services/Ent/Normalize/CellConfidenceCalculator.cs`

```csharp
public static class CellConfidenceCalculator
{
    /// <summary>★ 口径见 41-01 §三·2</summary>
    public static (double Score, string Reason) Compute(
        string sourceKind,          // global/self/profile/compute/ai/manual
        double? sourceConfidence,   // profile/ai 的来源自身置信度
        bool isOverridden)          // 人工确认过 → 强制 1.00
    {
        if (isOverridden) return (1.00, "");                    // R-C3
        return sourceKind switch
        {
            "global" or "compute" or "replace" or "manual" or "self"
                => (1.00, ""),                                  // 确定性来源
            "profile" => sourceConfidence is null
                ? (0.50, "画像未给置信度，已降级")               // R-C2
                : (sourceConfidence.Value, "取自企业上传资料，AI 抽取，未人工确认"),
            "ai" => sourceConfidence is null
                ? (0.50, "AI 未给置信度，已降级")
                : (sourceConfidence.Value * 0.9, "来源为 AI 建议，未人工确认"),
            _ => (0.50, "未知来源类型，已降级")                  // ⛔ 兜底必须保守
        };
    }

    /// <summary>★ 文件级加权（41-01 §三·3：⛔ pending 行不参与，⛔ 不能平均子文档）</summary>
    public static double Aggregate(IEnumerable<double> filledConfidences) { ... }
}
```

> ⚠️ **`_ => (0.50, ...)` 兜底必须保守**：宁可标黄，不可默认绿。
> 这是 `AGENTS.md` 铁律三的精神延伸 —— **写错 `SourceKind` 是最容易犯的错**，
> 若兜底给 `1.00`，新枚举值上线后所有未知来源都会显示「高可信」，界面失去筛选意义。

### 1.5 ★ Resolver 扩展（一期不需要，但先留好位置）

**⛔ 一期不新增任何 Resolver**（25 号实测：`profile` 类占比 **0%**、`ai` 类 ≤0.1%）。

| 情况 | 现有 Resolver 是否够 | 处理 |
|------|-------------------|------|
| `global` / `replace` / `headerFooter` / `ai` | ✅ 4 个已够（Order 10/20/30/100） | 编排器第 ④ 步直接调 `IFillResolver.Resolve` |
| `profile` | ⚠️ 无 Resolver | **编排器第 ④ 步内联处理**（读 `FieldsJson`），⛔ 不新增 Resolver（22 号 F-15：`profile` 属「有序回退链的一环」，不是「一种新能力」） |
| `compute` | ⚠️ 无 Resolver | 同上，内联 |
| `manual` | ⚠️ 无 Resolver | 同上，内联 |

> **一期不新增 Resolver 的理由**：`IFillResolver` 的注释逐字写着
> 「**新增能力 = 新增一个 Resolver + 注册进 `DocumentFillEngine`，不要修改既有 Resolver 去兼容新语法**」。
> 而 `profile`/`compute`/`manual` **不是新能力**，是 `SourceSpec.sources[]` 里的**三种取值来源**。
> ⇒ 二期若要做「`profile` 提取规则可插拔」，再抽 `ProfileResolver`。

## 四、DTO 字段表

### A. `NormalizePlan`（端点 3/12 的返回）

| 字段 | 类型 | 说明 |
|------|------|------|
| `ScopeType` / `ScopeCode` / `ScopeName` | string | 范围 |
| `TotalCount` / `NewCount` / `RegenCount` | int | 文件数 |
| `SkippedLockedCount` / `SkippedNoTemplateCount` / `SkippedNoAnchorCount` | int | 三类跳过 |
| `ScopeCompletionPreview` | decimal(5,4) | 范围完成率（**先求和再相除**，⛔ 不能平均） |
| `KeepManualCount` / `KeepPinnedCount` / `SampleDataCount` | int | 重写时会保留/清空的量 |
| `EstimateSeconds` | int | `TotalCount × 15` |
| `Warnings` | `string[]` | 人话警告 |

### B. `NormalizeTreeNode`（端点 1）

`Code` / `Name` / `Type`（5 类）/ `Children` / `FillCompletion` / `FillConfidence` / `IsLocked` / `FillPendingCount` / `AnchorCount` / `HasTemplate` / `Sort`

### C. `FillValueDto`（端点 9 —— ★ 单元格明细抽屉的表格数据源）

`AnchorCode` / `AnchorRef` / `FieldCode` / `LocationKind` / `LocationDesc` / `ValueDisplay` / `SourceKind` / `SourceLabel` / `Confidence` / `ConfidenceReason` / `FillStatus` / `IsOverridden` / `IsPinned` / `WriteMode` / `SampleData` / `Sort`

### D. `FillValueDetailDto`（端点 10 —— Tab2 数据来源）

= `FillValueDto` + `EvidenceText` / `EvidencePageHint` / `SourceDetailJson`（5 级链）/ `Candidates[]` / `Actions[]`

### E. `NormalizeActionDto`（端点 17）

`Code` / `ActionType` / `ScopeType` / `ScopeCode` / `ScopeName` / `AnchorCode` / `BeforeJson` / `AfterJson` / `Reason` / `CreateBy` / `CreateTime` / `QueueCode`
