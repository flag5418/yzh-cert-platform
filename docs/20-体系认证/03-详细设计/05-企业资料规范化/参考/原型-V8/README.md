## 二、★ 三处核心变化

### ① 更少元素（你要的「不塞在一页」）

| | v7 | V8 |
|---|---|---|
| 列表列数 | **9 列** | **6 列** |
| 完成度 / 可信度 | 各占一列 | **并入状态标签**，不在列表铺开 |
| 类型 / 图标 | 图标列 + 类型列 | 合并进「类型」一列 |
| 说明文字 | 页内长段 | 全部收进页脚 `口径与规则说明` 浮层 |

### ② ★★ 规则可回链（V8 的核心新增）

v7 把「后台要配什么」**全部硬编码**了 —— 读者看不出这些值**从哪来、谁配的**。

V8 里**每个值都能点开看**：

```
点「查」或「这条类型从哪来？」
  ↓
┌ 字段来源 · RISK_POLICY ────────────────┐
│ 位置        正文·第 9 段                │
│ 来源        AI 推断                     │
│ 顶住        ○ 未顶住                    │
│ 依赖企业文件  是（更新时清空）            │
├────────────────────────────────────────┤
│ 这条规则来自后台哪个配置                  │
│ 配置项     数据源                        │
│ 落库列     cert_doc_template_anchor.SourceSpec │
│ 后台页面   标准文档标准化 › 锚点规则 › 数据源    │
│           [去后台看]                     │
└────────────────────────────────────────┘
```

**覆盖 10 个配置项**：文档类型 · 可替换性 · 分组 · 文档作用 · 匹配依据 · 空白模板 · 锚点 · 数据源 · 操作方式 · 全局填写规则。

### ③ 建议可覆盖（`49-V4` 的 P1）

**类型是程序给的，人工能改** —— 点类型旁的「改」即可覆盖。
覆盖后程序**只如实重算状态**，⛔ **不阻断**。

> 例：把「体系文件清单」（程序建议：固定）改成**可编辑** ⇒
> 状态立刻从「已设置」变成「正在设置 · 缺：空白模板」——
> 因为**锚点只能从空白模板扫出**，没有模板就配不了。**程序不拦你，只是如实告诉你后果。**

## 三、状态三态（唯一入口 `missing()`）

| 状态 | 判据 |
|---|---|
| **未设置** | 没做任何设置 |
| **正在设置** | 必需项未全过（列表直接写出「缺：…」） |
| **已设置** | 必需项全过 |

**必需项**（= `49-V4` §九 + 校验清单 C1~C6）：

| 类型 | 必需项 |
|---|---|
| **固定 + 标准自带** | **无** ⇒ **初始即「已设置」** |
| **固定 + 企业提供** | 分组 · 文档作用 · **匹配依据**（C3） |
| **可编辑** | **空白模板**（C1）→ 锚点扫描 → **锚点数据源**（C5）→ 有 ai 锚点则须有 **全局填写规则**（C4） |

## 六、继承自 v7 的部分（这些是 v7 做对的）
