# 41-01 · 数据模型与两个口径（V1）

> **性质**：📐 **实施规格**（表结构逐列 DDL + 口径定义），可直接照抄进 `scripts/db/`
> **铁律遵守**（`AGENTS.md`）：
> - DB 列名 = C# 属性名 = TS 字段名，**PascalCase 逐字一致**
> - ⛔ **禁 `Enable` 列**，启用唯一字段 = `IsValid`（int，0/1）
> - 唯一键**不含 `IsDeleted`**；建前查重**含已删行**并复活
> - 身份段（`OrgCode`/`EnterpriseCode`/`StandardCode`/`StageCode`）`NOT NULL DEFAULT ''`，⛔ 禁 NULL
> - 字符集 `utf8mb4` + **显式** `COLLATE=utf8mb4_general_ci`
> - `Code` 为唯一业务键；`Id` **零语义**（⛔ 永不入 WHERE / 关联 / add-update 分流）
> - 索引长度 ≤ InnoDB DYNAMIC 上限 **3072 B**（36 号 D7 实测踩过 `ERROR 1071`）

---

## 一、数据库变更

### 1.1 ★ 新表 ①：`cert_doc_fill_value` —— 单元格级取值账本

**为什么必须有**（`41-00` §二·缺口 2）：

| 现状 | 问题 |
|------|------|
| `FillValue.Confidence` | 构造 `OfficeFillHit` 时**被丢弃**（`OfficeFillModels.cs:246`） |
| `cert_doc_fill_log` | **聚合表**（JSON 汇总），⛔ 无「一行一锚点」 |
| `cert_doc_ai_suggestion` | **只管 AI 建议**；而 25 号实测 **98.6% 的锚点是确定性来源**（编号 444 / 日期 472 / 人名 315 / 公司名 22）⇒ **98.6% 的取值没有账本** |
| 「查看数据来源 / 改数据来源 / 全部重写」 | **无表可支撑** |

⇒ 这张表是**用户 2026-10-04 那句核心需求的物理载体**：
> 「每个文档有完成率和可信度的显示，可以针对任何单元格查看填写的数据来源，或更改数据来源或全部重写」

```sql
SET NAMES utf8mb4 COLLATE utf8mb4_general_ci;

-- ============================================================================
-- 表 A · cert_doc_fill_value —— 单元格级取值账本
-- ----------------------------------------------------------------------------
-- 职责：一次填充中，**每一个锚点**（含表格区域的每一个单元格）的
--       「值 + 来源 + 证据 + 可信度 + 人工覆盖」四元组。
-- ★ 与 cert_doc_fill_log 的关系：log 是**文件级汇总**（1 行/文件），
--   本表是**单元格级明细**（N 行/文件）。log 的每一个计数都能由本表聚合出来
--   ⇒ 本表是唯一真相源，log 是**物化的汇总**（列表页读 log，不做实时聚合）。
-- ★ 与 cert_doc_ai_suggestion 的关系：那张表是「AI 候选池」（多候选 + 人工选），
--   本表是「最终落笔账本」。建议值从候选池**选中后**才写进本表。
-- ============================================================================
CREATE TABLE IF NOT EXISTS `cert_doc_fill_value` (
  `Id`                bigint        NOT NULL AUTO_INCREMENT COMMENT '主键ID（⛔零语义，永不入 WHERE）',
  `Code`              varchar(36)   NOT NULL              COMMENT '★业务键 GUID（唯一键）',
  `CreateTime`        datetime      NOT NULL              COMMENT '创建时间',
  `CreateBy`          varchar(64)   DEFAULT NULL          COMMENT '创建人Code',
  `UpdateTime`        datetime      DEFAULT NULL          COMMENT '更新时间',
  `UpdateBy`          varchar(64)   DEFAULT NULL          COMMENT '更新人Code',

  -- ── 身份段（P13：NOT NULL DEFAULT ''，⛔ 禁 NULL）──
  `OrgCode`           varchar(36)   NOT NULL DEFAULT ''   COMMENT '认证机构Code（冗余，便于按机构查）',
  `EnterpriseCode`    varchar(36)   NOT NULL DEFAULT ''   COMMENT '★企业Code → cert_enterprise.Code',
  `StageCode`         varchar(36)   NOT NULL DEFAULT ''   COMMENT '★阶段Code → cert_cert_stage.Code',
  `StandardCode`      varchar(36)   NOT NULL DEFAULT ''   COMMENT '★标准Code → cert_iso_standard.Code',

  -- ── 宿主（三个维度定位一行）──
  `StandardFileCode`  varchar(36)   NOT NULL DEFAULT ''   COMMENT '★目标标准文档 → cert_standard_directory_file.Code',
  `TemplateCode`      varchar(36)   NOT NULL DEFAULT ''   COMMENT '模板 → cert_doc_template.Code',
  `AnchorCode`        varchar(36)   NOT NULL              COMMENT '★锚点 → cert_doc_template_anchor.Code',
  `FillLogCode`       varchar(36)   NOT NULL DEFAULT ''   COMMENT '本次填充留痕 → cert_doc_fill_log.Code',

  -- ── ① 值 ──
  `ValueType`         varchar(20)   NOT NULL DEFAULT 'text' COMMENT '值类型 text/number/date/bool/enum（与锚点 ValueType 同口径）',
  `ValueText`         text                               COMMENT '文本值（ValueType=text 时用）',
  `ValueNumber`       decimal(20,4) DEFAULT NULL          COMMENT '数值（ValueType=number 时用）',
  `ValueDate`         datetime     DEFAULT NULL           COMMENT '日期（ValueType=date 时用）',
  `ValueDisplay`      varchar(500)  NOT NULL DEFAULT ''   COMMENT '★按类型格式化后的展示值（120 字符截断，界面直接用，⛔ 不在前端二次格式化）',

  -- ── ② 来源（D1 取值来源 7 类，见 22 号 §四）──
  `SourceKind`        varchar(20)   NOT NULL              COMMENT '★global/self/profile/compute/ai/manual —— D1 取值来源（sibling 一期不用）',
  `SourceLabel`       varchar(200)  NOT NULL DEFAULT ''   COMMENT '★人话来源标签（如「企业基础信息 · 企业全称」），列表页直接显示',
  `SourceDetailJson`  json          DEFAULT NULL          COMMENT '★完整来源链 {paramCode,profileCode,originalFileCode,fieldPath,pageHint,tableHint} —— 供「查看来源」下钻',

  -- ── ③ 证据 ──
  `EvidenceText`      text          DEFAULT NULL          COMMENT '证据原文片段（≤500 字），一键可看',
  `EvidencePageHint`  varchar(50)   DEFAULT NULL          COMMENT '证据位置提示（如 P3 / 第2段 / 表2行3），⛔ 不做跨文档双向定位',

  -- ── ④ 可信度（★ 本册定义，见 §三）──
  `Confidence`        decimal(3,2)  NOT NULL DEFAULT 1.00 COMMENT '★单元格级可信度 0.00~1.00；确定性来源恒 1.00；AI 取模型给分；人工恒 1.00',
  `ConfidenceReason`  varchar(200)  NOT NULL DEFAULT ''   COMMENT '可信度依据（如「来源为 AI 建议，未人工确认」）；1.00 时留空',

  -- ── ⑤ 人工覆盖（★ 「更改数据来源」「全部重写」的落点）──
  `IsOverridden`      tinyint(1)    NOT NULL DEFAULT 0    COMMENT '★是否被人工改过值或改过来源（改来源不改值时，本行值不变但本位置 1）',
  `OverrideKind`      varchar(20)   NOT NULL DEFAULT ''   COMMENT '人工干预类型 value=只改值 / source=只改来源 / both=两者都改',
  `OverrideReason`    varchar(500)  DEFAULT NULL          COMMENT '改的理由（审计要求：⛔ 改值必须填理由）',
  `OverriddenBy`      varchar(64)   DEFAULT NULL          COMMENT '干预人Code',
  `OverriddenTime`    datetime      DEFAULT NULL          COMMENT '干预时间',
  `IsPinned`          tinyint(1)    NOT NULL DEFAULT 0    COMMENT '★是否「钉住」—— 全部重写时 ⛔ 跳过本行（人工确认过的值不被自动覆盖）',

  -- ── ⑥ 状态 ──
  `FillStatus`        varchar(20)   NOT NULL DEFAULT 'filled' COMMENT 'filled=已写入 / pending=待办（无值） / kept_as_is=未命中且保留原文 / removed=按 remove 清空',
  `WriteMode`         varchar(20)   NOT NULL DEFAULT 'overwrite' COMMENT '写入方式 replace/overwrite/append/remove（快照自锚点，便于审计回放）',
  `OriginalText`      text          DEFAULT NULL          COMMENT '★替换前的原文快照（WriteMode=replace 时必落）——支撑差异比对与回滚；⚠️ 这也是 25 号 Q-5「模板示例数据」的清理依据',

  -- ── ⑦ 位置（界面定位用）──
  `LocationKind`      varchar(20)   NOT NULL DEFAULT ''   COMMENT '位置类别 body/table_cell/header/excel_cell/excel_region/word_table_region（对齐 FillLocationKind）',
  `LocationDesc`      varchar(200)  NOT NULL DEFAULT ''   COMMENT '可读位置（如「正文·第 12 段」/「Sheet1!B7」）',
  `Sort`              int           NOT NULL DEFAULT 0    COMMENT '锚点序号（来自锚点表 Sort，保证展示顺序稳定）',

  -- ── 审计段 ──
  `Remark`            varchar(500)  DEFAULT NULL,
  `IsDeleted`         tinyint(1)    NOT NULL DEFAULT 0    COMMENT '软删除',
  `DeleteBy`          varchar(64)   DEFAULT NULL,
  `DeleteTime`        datetime      DEFAULT NULL,
  `IsValid`           int           NOT NULL DEFAULT 1    COMMENT '★1有效0无效（铁律九，⛔ 禁 Enable）',

  PRIMARY KEY (`Id`),
  UNIQUE KEY `uk_code` (`Code`),
  -- ★ 同一锚点在一份产物里只能有一行（表格行锚点用 Sort 区分，见 §一·4）
  UNIQUE KEY `uk_log_anchor` (`FillLogCode`,`AnchorCode`),
  -- ★ 列表页主查询：按「企业+标准+阶段」拉全部锚点（算完成率）
  KEY `idx_scope` (`EnterpriseCode`,`StandardCode`,`StageCode`),
  -- ★ 文件抽屉主查询：按「标准文档」拉锚点清单
  KEY `idx_std_file` (`EnterpriseCode`,`StandardFileCode`),
  -- ★ 「全部重写」按锚点找旧值
  KEY `idx_anchor` (`TemplateCode`,`AnchorCode`),
  -- ★ 「待办」清单
  KEY `idx_status` (`FillStatus`),
  -- ★ 低可信度筛选
  KEY `idx_conf` (`Confidence`),
  -- ★ 钉住的行（重写时批量跳过）
  KEY `idx_pinned` (`IsPinned`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci
  COMMENT='文档填充取值账本（★ 单元格级：值 + 来源 + 证据 + 可信度 + 人工覆盖）';

-- ⚠️ 索引长度自检：
--   uk_log_anchor = (36 + 36) × 4 = 288 B  ✅ 远低于 3072 B
--   idx_scope     = (36+36+36) × 4 = 432 B ✅
--   idx_std_file  = (36+36) × 4   = 288 B ✅
--   ⚠️ ⛔ 不要建 (EnterpriseCode,StandardCode,StageCode,StandardFileCode,AnchorCode) 的
--      联合唯一键 —— 5×36×4 = 720 B 虽未超限，但**语义错误**：同一锚点在一份产物里
--      只该有一行，产物身份已由 FillLogCode 唯一确定。

-- ----------------------------------------------------------------------------
-- 建表后验证（必须输出 1 行）
-- ----------------------------------------------------------------------------
SELECT TABLE_NAME, TABLE_COMMENT FROM information_schema.TABLES
 WHERE TABLE_SCHEMA='yzh_cert_platform' AND TABLE_NAME='cert_doc_fill_value';

-- ⚠️ 验证 SQL 必须用 CONVERT(... USING utf8mb4) COLLATE utf8mb4_bin —— AGENTS.md ③ 铁律
--    information_schema.COLUMN_NAME 排序规则大小写不敏感，直接 NOT REGEXP '^[A-Z]'
--    会永远返回 0 行（假阴性）。
SELECT TABLE_NAME, COLUMN_NAME FROM information_schema.COLUMNS
 WHERE TABLE_SCHEMA='yzh_cert_platform'
   AND TABLE_NAME IN ('cert_doc_fill_value')
   AND CONVERT(COLUMN_NAME USING utf8mb4) COLLATE utf8mb4_bin NOT REGEXP '^[A-Z]';
-- ↑ 必须返回 0 行。若返回有值 ⇒ 列名有小写，违反铁律三。
```

### 1.2 ★ 新表 ②：`cert_doc_normalize_action` —— 规范化动作留痕（只追加）

**为什么不能用行内 3 列**：26 号 A-2 要求「**解锁也留痕**」。`LockedBy`/`LockedTime` 只能记**最后一次**，
而解锁/重写/锁定是**反复发生**的动作 ⇒ 必须只追加表。

```sql
CREATE TABLE IF NOT EXISTS `cert_doc_normalize_action` (
  `Id`             bigint       NOT NULL AUTO_INCREMENT COMMENT '主键ID（⛔零语义）',
  `Code`           varchar(36)  NOT NULL                COMMENT '★业务键 GUID（唯一键）',
  `CreateTime`     datetime     NOT NULL                COMMENT '★动作发生时间（只追加，⛔ 永不 UPDATE）',
  `CreateBy`       varchar(64)  DEFAULT NULL            COMMENT '操作人Code',

  `OrgCode`        varchar(36)  NOT NULL DEFAULT ''     COMMENT '认证机构Code',
  `EnterpriseCode` varchar(36)  NOT NULL DEFAULT ''     COMMENT '企业Code',
  `StandardCode`   varchar(36)  NOT NULL DEFAULT ''     COMMENT '标准Code',
  `StageCode`      varchar(36)  NOT NULL DEFAULT ''     COMMENT '阶段Code',

  `ActionType`     varchar(20)  NOT NULL                COMMENT '★动作 lock/unlock/rewrite/pin/unpin/batch_run/batch_cancel（对齐 26 号 §9.4）',
  `ScopeType`      varchar(20)  NOT NULL DEFAULT ''     COMMENT '作用范围 file/folder/stage/standard/enterprise（对应 Q-I 的粒度）',
  `ScopeCode`      varchar(36)  NOT NULL DEFAULT ''     COMMENT '范围标识（文件/文件夹 Code）',
  `ScopeName`      varchar(200) NOT NULL DEFAULT ''     COMMENT '范围名称快照（如「4 记录文件」）',
  `TargetCode`     varchar(36)  NOT NULL DEFAULT ''     COMMENT '直接目标（文件 Code）；批量时留空',
  `AnchorCode`     varchar(36)  NOT NULL DEFAULT ''     COMMENT '锚点（改单元格来源时填；否则空）',
  `BeforeJson`     json         DEFAULT NULL            COMMENT '变更前快照 {IsLocked,SourceKind,ValueText,...}',
  `AfterJson`      json         DEFAULT NULL            COMMENT '变更后快照',
  `Reason`         varchar(500) DEFAULT NULL            COMMENT '★理由（unlock / rewrite ⛔ 必填，审计要求）',
  `QueueCode`      varchar(36)  NOT NULL DEFAULT ''     COMMENT '关联批次 → yzh_queue.QueueCode（batch_run / batch_cancel 时填）',

  PRIMARY KEY (`Id`),
  UNIQUE KEY `uk_code` (`Code`),
  KEY `idx_target` (`TargetCode`),
  KEY `idx_scope` (`EnterpriseCode`,`ScopeType`,`ScopeCode`),
  KEY `idx_action` (`ActionType`),
  KEY `idx_time` (`CreateTime`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci
  COMMENT='企业资料规范化动作留痕（锁定/解锁/重写/钉住/批量运行，★ 只追加永不 UPDATE）';
-- ⚠️ 本表 ⛔ 不建 IsDeleted（32 号 §八：「锁定状态机」要求动作历史永不可删）
--    ⇒ 误操作只能再写一条反向动作，不能删。
```

### 1.3 ★ 既有表加列 ①：`cert_standard_directory_file` 加 12 列

> 26 号 §4.2 只列了 5 列（`IsLocked`/`LockedBy`/`LockedTime`/`SourceProfileCode`/`SourceOriginalPath`），
> 且**只给列名不给类型**。本节补齐类型 + 补 7 列（进度 / 产物 / 状态 —— 列表页要显示完成率与可信度，**不能每次实时聚合 1271 行**）。

```sql
-- 脚本：scripts/db/20261004_doc_normalize_V1.sql
SET NAMES utf8mb4 COLLATE utf8mb4_general_ci;

ALTER TABLE `cert_standard_directory_file`
  -- ── ① 锁定（26 号 §4.2 的 3 列）──
  ADD COLUMN `IsLocked`           tinyint(1)    NOT NULL DEFAULT 0    COMMENT '★锁定后任何生成路径不得覆盖（26 号 S-6 锁定优先）' AFTER `ContractCode`,
  ADD COLUMN `LockedBy`           varchar(64)   DEFAULT NULL          COMMENT '锁定人Code',
  ADD COLUMN `LockedTime`         datetime      DEFAULT NULL          COMMENT '锁定时间',
  -- ⚠️ 解锁的 By/Time/Reason ⛔ 不设列 —— 解锁是多次动作，列只能记最后一次
  --    ⇒ 统一落 cert_doc_normalize_action（26 号 A-2「解锁也留痕」）

  -- ── ② 生成依据与溯源（26 号 §4.2 的 2 列）──
  ADD COLUMN `SourceProfileCode`  varchar(36)   NOT NULL DEFAULT ''   COMMENT '★生成依据：产出本次文件所用的画像 → cert_enterprise_doc_profile.Code（可多值时逗号分隔，最多 3 个）' AFTER `LockedTime`,
  ADD COLUMN `SourceOriginalPath` varchar(512)  DEFAULT NULL          COMMENT '★溯源展示：对应原始文件路径（冗余存储 ⚠️ ⛔ 生成过程绝不读它，违反即退回读原始文件）' AFTER `SourceProfileCode`,

  -- ── ③ 产物（本册新增：26 号未列，但「打包下载」必须有）──
  ADD COLUMN `NormalizedPath`    varchar(512)  DEFAULT NULL          COMMENT '★规范化产物路径 → enterprise-documents/ 库（PathBuilder.EnterpriseFile）' AFTER `SourceOriginalPath`,
  ADD COLUMN `NormalizedPdfPath` varchar(512)  DEFAULT NULL          COMMENT '产物 PDF（预览用；转换未完成时为空）' AFTER `NormalizedPath`,
  ADD COLUMN `NormalizedTime`    datetime      DEFAULT NULL          COMMENT '最近一次规范化完成时间' AFTER `NormalizedPdfPath`,

  -- ── ④ 进度（列表页显示完成率 / 可信度，⛔ 不做实时聚合）──
  ADD COLUMN `FillCompletion`     decimal(5,4)  NOT NULL DEFAULT 0.0000 COMMENT '★完成率 0.0000~1.0000（口径见 §二·1；⛔ Total=0 时记 0 不记 1）' AFTER `NormalizedTime`,
  ADD COLUMN `FillConfidence`     decimal(3,2)  NOT NULL DEFAULT 1.00   COMMENT '★加权可信度 0.00~1.00（口径见 §三·3）' AFTER `FillCompletion`,
  ADD COLUMN `FillAnchorCount`    int           NOT NULL DEFAULT 0      COMMENT '锚点总数（分母快照）' AFTER `FillConfidence`,
  ADD COLUMN `FillPendingCount`   int           NOT NULL DEFAULT 0      COMMENT '待办数（分子缺口）' AFTER `FillAnchorCount`;

-- ── 验证（应输出 12 行）──
SELECT COLUMN_NAME, COLUMN_TYPE, IS_NULLABLE, COLUMN_COMMENT
  FROM information_schema.COLUMNS
 WHERE TABLE_SCHEMA='yzh_cert_platform'
   AND TABLE_NAME='cert_standard_directory_file'
   AND COLUMN_NAME IN ('IsLocked','LockedBy','LockedTime','SourceProfileCode','SourceOriginalPath',
                       'NormalizedPath','NormalizedPdfPath','NormalizedTime',
                       'FillCompletion','FillConfidence','FillAnchorCount','FillPendingCount')
 ORDER BY ORDINAL_POSITION;
```

> ⚠️ **`DocCategory` / `MatchState` / `InstanceState` 已有**（`StandardDirectoryFile.cs:88/92/99`），**⛔ 不要重复加**。

## 二、★ 完成率口径（26 号未定义，本节定义）

### 2.1 唯一定义

```text
完成率 = 已写入锚点数 / 有效锚点总数
       = (FillAnchorCount − FillPendingCount) / FillAnchorCount
       = FillCompletion（物化在 cert_standard_directory_file）
```

| 项 | 规则 | 依据 |
|----|------|------|
| **分母** | `cert_doc_template_anchor` 中 `AnchorType ∈ (scalar, block, table, table_total, domain)` 且 `IsOrphan = 0` 的**行数** | 21 号 §6.2「模板即完成度的分母 —— 分母不用猜、不用 AI 估，模板一改分母自动跟着变，**就是锚点数**」 |
| 排除 | `IsOrphan = 1`（模板重传后消失的锚点） | 它已无落笔位置，算进分母会让完成率永远上不去 |
| **分子** | `cert_doc_fill_value` 中 `FillStatus = 'filled'` 的行数 | `kept_as_is` 与 `pending` 都不算「已写入」 |
| **`Total = 0`** | ⛔ 记 **0.0000**，⛔ **不是 1.0000** | `FillReport.Completion` 注释 + `OfficeFillReport.Completion` 注释 + 26 号 R-6「V1 曾出现 100% vs 0% 两套，已修」 |
| **区域填充** | ⛔ **不计入分母**（`OfficeFillRegionHit` 注释：「数据有几行就是几行，混在一起会让完成度失真」） | 同上 |
| **锁定的文件** | 完成率**照常显示**，但 UI 加 🔒 徽标 + tooltip「已锁定，重新生成时跳过」 | 26 号 S-6 |

### 2.2 三处口径必须一致（同一份数据，三个地方算出同一个数）

| # | 位置 | 现状 | 本册要求 |
|---|------|------|---------|
| 1 | `FillReport.Completion`（E1 文本引擎） | ✅ 已是 `Total == 0 ? 0.0 : Resolved / Total` | ⛔ 不改 |
| 2 | `OfficeFillReport.Completion`（E2 文件写入） | ✅ 已是 `Total == 0 ? 0.0 : Resolved / Total` | ⛔ 不改 |
| 3 | 企业端 `liveCompletion`（`FillParamValueController`） | ✅ 29.41% 实测一致 | ⛔ 不改 |
| 4 | **本册列表页聚合** | 🆕 | ⚠️ **读 `cert_standard_directory_file.FillCompletion`（物化列），⛔ 不实时聚合** |

> **为什么第 4 条要物化**：一份文档 1271 个锚点、668 份文档 ⇒ 实时聚合 = 每行一次 `COUNT(*)`，列表页直接卡死。
> 物化时机 = 编排器第 ⑦ 步（`41-03` §一），⛔ 不在查询时算。

### 2.3 三个层级的完成率（页面要显示三种，不能只一种）

| 层级 | 字段 | 口径 | 界面位置 |
|------|------|------|---------|
| **单锚点** | — | `filled` / `pending` | 单元格抽屉 |
| **单文档** | `cert_standard_directory_file.FillCompletion` | 上面的定义 | ★ 列表页「完成率」列（左树节点徽标同源） |
| **单范围**（目录/阶段/标准/企业） | 🆕 `GET /normalize/plan` 返回 | 该范围内 `Σ已写入 / Σ分母` | 范围预览条 |

> ⚠️ **范围级完成率的分母必须重新数，不能把子文档的 `FillCompletion` 求平均** ——
> 一份 3 锚点的文档和一份 500 锚点的文档，平均它们的完成率是错的。**必须先求和再相除。**

## 三、★ 可信度口径（26 号未定义，本节定义）

### 3.1 ⚠️ 先说清「两套可信度不是同一套」

| # | 体系 | 值域 | 落表 | 算法 | 本册是否用 |
|---|------|------|------|------|-----------|
| **①** | **定向提取字段可信度** | `decimal(3,2)` NULL | `cert_extraction_result.Confidence` | 04 号 §5 | ⛔ 间接（经画像 `FieldsJson`） |
| **②** | **画像置信度** | `decimal(3,2)` NULL | `cert_enterprise_doc_profile.Confidence` / `TagsConfidence` / `DocPurposeConfidence` | 33 号 `doc_content` 给分 | ✅ 作为 `profile` 来源的输入 |
| **③** | **匹配综合可信度** | `decimal(3,2)` | `cert_doc_match_candidate.Confidence`（**该表 0 行，未建**） | **04 号 §5.2 五维加权** | ⛔ **本册不用** |
| **④** | ★ **单元格级取值可信度** | `decimal(3,2)` | ★ **`cert_doc_fill_value.Confidence`** | **本节定义** | ✅ **本册主体** |

> **为什么 ③ 不能拿来用**：它是「这份企业资料**是不是**这份标准文档」的分数（五维：语义 0.35 + 字段 0.30 + 表格 0.20 + 规则 0.10 + 时效 0.05），
> 回答的是**文档级归属**问题。
> 用户要的是「**这个单元格的值可不可信**」—— 这是**取值链**问题，粒度差两个数量级。
> ⇒ **混用会导致「文档匹配 92% 但某个单元格是错的」无法表达。**

### 3.2 ★ 单元格级可信度定义（本册新增口径）

```text
Confidence = f(SourceKind, 来源自身的 Confidence, 是否人工确认)
```

| `SourceKind` | 公式 | 25 号实测占比 | `ConfidenceReason` 示例 |
|--------------|------|-------------|----------------------|
| `global`（全局参数） | **1.00** | 35.0%（编号 444）+ 37.1%（日期 472）≈ **72%** | 留空（确定性） |
| `compute`（计算/统计） | **1.00** | 派生清单表（4 文件占 36%） | 留空 |
| `replace`（企业属性直取） | **1.00** | 1.7%（公司名 22）+ 部分人名 | 留空 |
| `manual`（人工录入） | **1.00** | 认证日期等（一期 `F-11`） | 留空 |
| `self`（本文档内引用） | **1.00** | 一期不用（`F-13`） | 留空 |
| `profile`（企业资料画像取值） | **`SourceConfidence`**（画像 `FieldsJson[].confidence`） | ★ **0%**（25 号实测：⑤ 类一期占比 0%） | 「取自企业上传资料《内审计划》，AI 抽取，未人工确认」 |
| `ai`（AI 生成） | **`SourceConfidence` × 0.9** | ≤5 处（0.1%） | 「来源为 AI 建议，未人工确认」 |

**三条硬规则**：

| # | 规则 | 理由 |
|---|------|------|
| **R-C1** | ⛔ **`Confidence` 恒 `NOT NULL`**（与 `cert_extraction_result.Confidence` 的可空口径**相反**） | 可空 = 「不知道」；但「从全局参数取值」这件事**本身就是确定的**，留空会让 72% 的行显示「未知」，界面没法用 |
| **R-C2** | `SourceKind = 'profile'` / `'ai'` 时，`SourceDetailJson` **必须**含 `profileCode` 或 `suggestionCode`；否则 `Confidence` 强制打 **0.50** | 说不出来源的 AI 值 = 不可信，降级 |
| **R-C3** | 人工确认后（`IsOverridden = 1`），`Confidence` **强制置 1.00** | 人看过的东西就是可信的；⛔ 不保留模型原分（那会让人误以为还有风险） |

### 3.3 ★ 文件级可信度（列表页显示的那个）

```text
FillConfidence = Σ(Confidence_i) / N
```

⚠️ **三条防坑**（都是会被写错的）：

| # | 坑 | 正解 |
|---|-----|------|
| 1 | 把「已人工确认」和「AI 给分」一起平均 | ⛔ **可以一起平均**（人工已置 1.00，抬高均值是正确的 —— 人工确认过就是可信） |
| 2 | 把 `pending` 行（无值）算进分母 | ⛔ **不算**。只对 `FillStatus = 'filled'` 的行求均值。`pending` 的影响体现在**完成率**上，不体现在可信度上 |
| 3 | 用「文档级匹配置信度 ③」当文件级可信度 | ⛔ **两码事**（见 §三·1） |

**展示口径（三档配色，与 `04` 号阈值刻意不同）**：

| 区间 | 徽标 | 文案 | 建议动作 |
|------|------|------|---------|
| `≥ 0.95` | 🟢 绿 | 高可信 | 无需干预 |
| `0.70 ~ 0.95` | 🟡 黄 | 部分待确认 | 点开看黄/红单元格 |
| `< 0.70` | 🔴 红 | 需人工复核 | **列表页可按此筛选** |
| `FillConfidence = 1.00` 且 `FillCompletion = 0` | ⚪ 灰 | 无可填项 | 「该文档不含可填锚点，纯复制即可」（25 号：**42.5% 的文件属于此类**） |

> ⚠️ **阈值为什么不跟 `04` 号一样**（`04` 号是 `≥0.85 / 0.50–0.85 / <0.50`）：
> 因为 ④ 的分母里 **72% 是确定性来源恒 1.00**，若用 0.85 阈值，**几乎所有文档都是绿的**，界面失去筛选意义。
> ⇒ ④ 的阈值必须**更高**（0.95）才能把「少数 AI/画像来源」标出来。
> 这三个阈值落 `cert_sys_config`（`ent_fill_conf_high` / `ent_fill_conf_mid`），⛔ 不硬编码。
