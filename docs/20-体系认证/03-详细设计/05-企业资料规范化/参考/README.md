## 〇、为什么单独成册

`26` 号是**菜单级功能设计**（每个菜单一小节，粒度粗），`36` 号是**上游菜单的实施规格**（`MENU_AUD_11` 企业原始资料管理）。

菜单 ⑥ 的复杂度与 36 号同级，但**至今没有实施规格**：

| 项 | 26 号 §3.6 的实际覆盖度 |
|----|------------------------|
| 左树层级 + 页面布局 | ✅ 有（含 ASCII 左树示意） |
| 三级粒度 + 单文件原子任务 | ✅ 有（写得很好，Q-J 已按方案 A 落地） |
| 锁定机制 | ✅ 有（3 列 + Q-I 选项 A/B） |
| 数据库变更汇总 | ✅ 有（5 列新增，但只有列名无类型） |
| **完成率口径** | ⛔ **未定义**（§3.6 无；全文 3 处相关都不在 §3.6） |
| **可信度口径** | ⛔ **未定义**（只有列级 `Confidence`，算法在 `04` 号且属另一套体系） |
| **单元格级「查看来源 / 改来源 / 全部重写」** | ⛔ **全文未出现这三个交互** |
| **右区页面原型** | ⛔ **未定义**（§3.6 只有左树示意，无右区线框） |
| **后端端点的入参 / 出参** | ⛔ **未定义**（只有 6 个端点名，无 Controller / 无 schema） |
| **打包下载** | ⛔ **未定义** |

⇒ 这 4 个缺口 + 1 个未定义，正好对应用户 2026-10-04 的原话：

> 「每个文档有完成率和可信度的显示，可以针对任何单元格查看填写的数据来源，或更改数据来源或全部重写」
> 「能够自动上传或打包下载」

**本册就是补这 5 个洞的可执行规格**，并叠加一次**代码级现状核对**（见 `41-00`），纠正若干「文档说已做 / 代码里没有」的偏差。

## 六、一句话结论（先看这个）

> **本页面 100% 可做，且不需要新建任何 AI 能力** —— 规则、模板、锚点、画像、两个填充引擎、ZIP 打包**全部已建成**。
>
> **唯一的真缺口是「执行层」**：`WordFillWriter` / `ExcelFillWriter` 有 148 个单测全绿，但**零生产调用方**；`cert_doc_fill_log` 表建好了但**零代码写入**；`FillValue.Confidence` 在生成报告时被**丢弃**。
>
> ⇒ 一句话工作量：**补一个编排器（把已建成的零件串起来）+ 建一张单元格级取值账本（让可信度和溯源有地方落）+ 建一个页面（把按钮摆出来）= 16.5 人天。**
>
> 详见 `41-00`。
