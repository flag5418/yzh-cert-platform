## 一、本模块解决什么问题

| 输入 | 处理 | 输出 |
|------|------|------|
| 企业任意上传的散乱资料（扫描件 / Word / Excel / PDF，命名混乱、组织无序） | 固定文档指纹识别 → AI 画像提取 → 召回 + 精排匹配 → 人工裁决 → 定向提取填充 | 标准目录下、按标准文件名与标准格式组织的**标准文档实例**，每条数据带可信度与源文件溯源 |

**核心命题**：标准目录（`cert_standard_directory_file`）定义了「应该有什么文档、每个单元格该填什么」；企业资料库产生「实际有什么文档、实际填了什么」。本模块是连接两者的**匹配与填充引擎**，其枢纽字段 = `StandardFileCode`。

2. **引擎必须纯函数**：`DocumentFillEngine` 不读 DB / 不读时钟 / 不引 `YZH.Core.DataBase` ⇒ 同一输入必得同一输出，167 份文档批量填充**可重跑**。
3. **Resolver 按 `Order` 升序链式执行**：`AiGenerate(10)` → `HeaderFooter(20)` → `Replace(30)` → `GlobalParam(100 兜底)`。`GlobalParamResolver` 用 `IsClaimedByOthers` **主动拒收**前三类 token。
4. **★ 机构域有三个不同的 Code，别混**：`cert_certification_body.Code`（GUID，**配置归属**）≠ `Sys_Organization(VirtualOrg).Code`（**工作区**，数据归属）≠ `cert_enterprise.OrgCode`（= 工作区 Code）。桥 = `工作区.Code → 工作区.OrgCode(=CbCode) → CertificationBody.CbCode → CertificationBody.Code`，唯一实现 = `WorkspaceContextService.ResolveCertBodyCodeAsync`。
5. **取值决策唯一实现** = `ParamValueResolver`（`auto` 恒实时取档案且不落值表 / `both` 无企业值时自动带出档案作初值可改 / `manual` 回落 `DefaultValue`）—— ⛔ 两个控制器**不得各写一份**（已发生过，必然漂移且都不报错）。
6. **定义去重 `Specificity`**：指定标准 +2、指定阶段 +1，平手取先创建者 ⇒ 支持「不限标准的通用参数 + 某标准单独覆写同名参数」。

**★ 直答「填写 Skill 是否合理」**（`23` 号 **§〇.五**，用户 2026-10-02 反馈"没完全理解"后重答）：

> **思路对，载体错。** 「取值来源可插拔」✅ 对；但**叫 Skill** ⛔ 错 —— 在本项目 **Skill = 工作流画布节点类型**，有**三条硬绑定**：①必须登记 `wf_skill_reflection` ②每个参数必须声明 `BindMode`（`Link`/`LinkOrConstant`/`Enum`）③前端会渲染成画布方块。
> **一句话判据**：**Skill 是给"人要在画布上摆、要连线"的东西用的。填充取值，没有人会在画布上摆。**
> **正确载体**：`IValueResolver` + DI 注册表 —— 功能完全相同，差别只在"要不要在画布上摆"。
> **Skill 直觉没错，只是放错了层**：填充取值 0/4 命中判据 → Resolver；全局填写规则 3~4/4 → 可 Skill；模板扫描/分类/生成提示词 4/4 → Skill。

**⚠️ 一条实测债**：`cert_cert_stage` **只有 3 行**（`jd01` 初审 / `jd02` 预审 / `03` 复审），且 **`SortOrder` 全为 0** ⇒ **无法比较阶段先后**。这是「阶段区间式参数裁剪」做不了的原因（`G-20`），也是将来要还的债。
