## 〇、一句话

一份标准文档的「标准化」= **三步**：
① 系统判类型 + 语义分析（**自动**）→ ② 配**锚点**（数据源 × 操作）→ ③ 配**全局填写规则**。

页面同屏**只有两层**：**左 = 文档 / 右 = 2 个 Tab**。
所有配置细节（数据源参数、操作参数、提示词）**收进点击后展开的面板**。

## 二、核心概念

### 2.1 文档类型（自动判定）

| 文件 | 判定 | 类型 | 可否人工改 |
|---|---|---|---|
| 图片（jpg/png/…）、PDF（不可解析） | 自动 | **固定文档** | ⛔ **不可改** |
| doc / docx / xls / xlsx / txt … | 自动 | **可编辑文档** | — |

> 「非自动判定的固定文档 ⇒ 默认按可编辑处理」= 上表第 2 行。
> ⚠️ **实测现状**：库内 668 份标准文档 `FileType` = doc 567 / xls 44 / docx 36 / xlsx 20 / txt 1
> —— **0 份 PDF / 图片**。⇒ 固定文档这条分支**当前无真实数据**，属**为未来预留**。

**两种类型的差异**：

| | 固定文档 | 可编辑文档 |
|---|---|---|
| 锚点规则 Tab | ⛔ 无（没有可填的锚点） | ✅ 有 |
| 全局规则 Tab | ✅ 有（分组 + 作用，可改） | ✅ 有 |
| 初始状态 | **直接「已设置」**（信息全自动生成） | 「未设置」 |

### 2.2 语义分析产物（自动带出，可人工覆盖）

| 项 | 来源 | 可改 |
|---|---|---|
| **分组** | 首次打开原始文档时 AI 分析 | ✅ |
| **文档作用** | 同上 | ✅ |

> ⚠️ 二者**都不落「状态」判据的必需项**（固定文档除外）——
> 它们是**结论**，不是**配置**；配不出也不该卡住流程。

### 2.3 锚点（两类）

**2.3.1 数据源**（值从哪来）—— 见 `48` §2

| 数据源 | 配置项 |
|---|---|
| **全局参数** | 选一个 `param_code` |
| **AI 自动生成** | ① 带参数？（从全局参数选，可多个）② 关联文档？ ③ 提示词 |
| **AI 字段** | 同上 ①②③ |
| **AI 表格** | 同上 ①②③ + 列定义（扫描带出） |
| **AI 提示词** | 提示词文本 |
| （人工待办） | ⚠️ **不是并列选项** —— 它是来源链的兜底项（`48` §2.4） |

**2.3.2 操作**（值怎么写回去）—— 见 `48` §3

| 操作 | 定位方式 | Word | Excel |
|---|---|---|---|
| **单元格 更新** | 坐标 | ✅ `WordCell`（本轮已实现） | ✅ |
| **表格 更新** | 标记 + 补行 | ✅ | ✅ |
| （替换） | 模板标记 `{{}}` | ✅ | ✅ |
| （页眉替换） | 页眉内标记 | ✅ | — |

> ★ 参数**由文件类型自动分派**：同一个「单元格 更新」，Word 下显示「表 / 行 / 列」，
> Excel 下显示「Sheet / Cell」。**扫描带出的参数直接带入**（`48` §3.4）。

### 2.4 全局填写规则（★ 条件显示）

**规则**：

```
锚点里存在 ai 节点？
  ├─ 否 ⇒ ⛔ 整个区域不显示
  └─ 是 ⇒ ✅ 显示，并提供「自动分析」
             ⇒ 按 ai 节点生成一段可执行的提示词
             ⇒ 每一段可单独保存
```

**★ 为什么「条件显示」是本设计最省空间的一招**：
大部分标准文档**一个 ai 节点都没有**，却要为它们常驻一块「用不上的提示词编辑器」——
这正是「元素塞满一页」的主要来源。条件显示让**常见情况更干净**。

> ⚠️ **待确认**：「ai 节点」的判定口径 —— 是 `{{ai:xxx}}` 这种 token，
> 还是有 `SourceKind='ai'` 的锚点？（§7 Q2）

### 2.5 状态三态（唯一口径）

| 状态 | 判据 |
|---|---|
| **未设置** | 未做任何设置 |
| **正在设置** | 已开始，但必需项未全过 |
| **已设置** | 必需项全过 |

**必需项**：

| 类型 | 必需项 |
|---|---|
| **固定文档** | 无 —— 信息全自动生成 ⇒ **初始即「已设置」** |
| **可编辑文档** | ① 所有锚点**设置完成**（无「未配数据源」的锚点）<br>② 若有 ai 节点 ⇒ 全局填写规则**存在** |

> ⚠️ **与 `41-V3` 的一处冲突**（§7 Q4）：V3 §0.3 把「全文规则」列为**建议项**
> （理由：列为必需会让一批文档卡在「正在设置」）；
> 而本条把它列为**条件必需项**（有 ai 节点时）。
> 二者都自洽，但**不能同时成立** —— 需你裁定。

## 三、页面结构

```
┌ 顶栏（全局，已有）────────────────────────────────────────────────┐
├ 面包屑   标准 › 文件夹 › 文档名.doc                                ┤
├ 功能条   [自动填充] [测试] [预览]        ● 已设置 3/4   [保存]      ┤
├───────────────────────────────┬──────────────────────────────────┤
│ 左区 · 文档（默认只显示文档）    │ 右区 · 2 个 Tab                    │
│                               │ ┌[锚点规则]─[全局规则]──────────┐ │
│  ┌─────────────────────────┐  │ │                              │ │
│  │                         │  │ │  （Tab 内容）                 │ │
│  │      文档预览            │  │ │                              │ │
│  │   （空白模板 / 原件）     │  │ │                              │ │
│  │                         │  │ │                              │ │
│  └─────────────────────────┘  │ │                              │ │
└───────────────────────────────┴──────────────────────────────────┘
```

**只有两层同屏** —— 这是「简洁」的实现方式：

| 层 | 内容 | 何时出现 |
|---|---|---|
| **L1** | 左文档 + 右 2 Tab | 常驻 |
| **L2** | 点击某锚点 ⇒ **锚点设置面板**（抽屉） | 点击后 |
| **L2'** | 点击「预览」⇒ **填好的 PDF** | 点击后 |

> ★ 与 `41-V3` 的最大差异：V3 是**三栏 + 九宫格 4 菜单**（同屏元素多）；
> 本设计收成**左文档 + 右 2 Tab**，把「4 个功能页」压成「2 个 Tab」，
> 其余全部下沉到点击后的面板。**这是你要的「不用把元素全塞在一个页面」。**

## 四、交互流程

### 4.1 打开文档（首次）

```
选中文档
   ↓
① 类型分析（自动）  ⇒ 固定 / 可编辑
   ↓
② 语义分析（自动）  ⇒ 分组 + 文档作用
   ↓
右区默认落在「全局规则」Tab，直接显示 ② 的结果（可改）
   ↓
若为「可编辑文档」⇒ 用户切到「锚点规则」Tab 开始配锚点
```

> ★ 首次打开**默认显示语义分析结果**，是因为它**不需要用户做任何事**——
> 先让用户确认「系统看懂这份文档了没有」，再进入配置。
> 这与专家端原型「先给结论、再给操作」的顺序一致。

### 4.2 锚点规则 Tab

```
┌[锚点规则]─────────────────────────────┐
│  字段（12）          表格（2）          │
│  ⚓ ENT_NAME         ▦ 培训记录         │
│     ● 已配             ● 已配           │
│  ⚓ CREDIT_CODE      ▦ 风险清单         │
│     ○ 未配                              │
│  …                                     │
└───────────────────────────────────────┘
```

- 点击任意一项 ⇒ **锚点设置面板**（§4.3）
- 列表**按「字段 / 表格」分两组**（对应你说的「每个字段 / 每个表格」）
- 每项右侧一个状态点（已配 / 未配）

### 4.3 锚点设置面板（数据区域 + 操作区域）

**点击锚点后展开**（复用 `YzhDrawer`，右侧滑出）：

```
┌ 锚点设置 · ENT_NAME ──────────────────────┐
│ 位置  正文·第 3 段        （扫描带出，只读） │
│ 原值  {{ENT_NAME}}                        │
├── ① 数据区域 ─────────────────────────────┤
│  数据源  ○全局参数 ○AI自动生成 ○AI字段      │
│          ○AI表格   ○AI提示词               │
│  ┌ 选中「全局参数」时 ────────────────┐    │
│  │ 参数  [company_name        ▾]      │    │
│  └───────────────────────────────────┘    │
│  ┌ 选中「AI 字段」时 ─────────────────┐    │
│  │ ① 带参数？ [✓] → 参考字段 [经营范围][企业文化] │
│  │ ② 关联文档？[ ]                     │    │
│  │ ③ 提示词   [________________]      │    │
│  └───────────────────────────────────┘    │
├── ② 操作区域 ─────────────────────────────┤
│  操作方式  ○单元格更新 ○表格更新            │
│  ┌ 选中「单元格更新」+ Word 时 ────────┐    │
│  │ 表格序号 [0] 行 [2] 列 [3]          │    │
│  └───────────────────────────────────┘    │
│  ┌ 同一项 + Excel 时 ─────────────────┐    │
│  │ 工作表 [Sheet1] 单元格 [B3]          │    │
│  └───────────────────────────────────┘    │
├───────────────────────────────────────────┤
│                            [取消] [保存]   │
└───────────────────────────────────────────┘
```

**两个区域的分工**（= `48` 号的核心模型）：

| 区域 | 回答的问题 | 参数随什么变 |
|---|---|---|
| **① 数据区域** | **值从哪来** | 随「数据源类型」变 |
| **② 操作区域** | **值怎么写回去** | 随「操作方式 + 文件类型」变 |

### 4.4 自动填充 / 测试

**功能条上的两个按钮**：

| 按钮 | 行为 |
|---|---|
| **自动填充** | 按锚点**随机生成**一组值填入 ⇒ 操作者可**修改**、可**清空** |
| **预览** | 切换到**填好之后**的 PDF 预览画面 |

**★ 三条硬约束**（源自 `48` §4.2）：

1. 试填必须用 `KeepUnresolvedAsIs = true` —— 否则未命中的锚点会被**直接抹掉**，就看不到「哪些没填」了
2. 随机值必须**看得出是哪个锚点填的**（建议 `〔ENT_NAME〕Xk3f9`），纯随机串无法归因
3. 预览需要一次 `.docx → .pdf` 转换 ⇒ **有延迟**，需异步或复用产物缓存

**★ 自动填充的产物是「草稿」，不是「规则」** ——
它存在会话里（`OfficeFillRequest`），⛔ 不写回锚点配置。

### 4.5 全局规则 Tab

```
┌[锚点规则]─[全局规则]──────────────────┐
│  分组    [基础资料                    ] │  ← 自动带出，可改
│  文档作用 [用于初次认证的资质证明文件    ] │  ← 自动带出，可改
├────────────────────────────────────────┤
│  全局填写规则          ★ 条件显示        │
│  ┌────────────────────────────────┐    │
│  │ 素材（点击插入光标处）           │    │
│  │ ⚓[锚点] ▤[企业参数] ✎[填写方法]  │    │
│  ├────────────────────────────────┤    │
│  │ （提示词编辑区）                 │    │
│  │                                │    │
│  └────────────────────────────────┘    │
│  [自动分析]                    [保存本段] │
└────────────────────────────────────────┘
```

- **分组 / 文档作用**：自动带出，可改
- **全局填写规则**：⛔ **无 ai 节点时整块不显示**；有则显示，且提供「**自动分析**」（按 ai 节点生成提示词）
- **每一段可单独保存**（不做「一次性保存全文」）

> ★ 素材区三行（锚点 / 企业参数 / 填写方法）+ 横向滚动，是 `41-V3` §8.5.6 已定的设计
> （用户第五轮原话：「我们 3 栏，留给我们设置的空间有限」）。

### 4.6 保存

⚠️ **待确认**（§7 Q1）：你说「点击保存，进行自动保存」—— 这两者是矛盾的：
- **点保存** ⇒ 手动，有「未保存」状态
- **自动保存** ⇒ 无「未保存」状态，也就不需要 `41-V3` §4 的「三处未保存提醒」

**建议**：**点保存 + 面板内改动视为草稿**（与 `41-V3` §4 一致）。
理由：锚点设置是**结构性配置**，误改代价高；而「自动保存」会让「试填草稿」与「真配置」混在一起。

## 五、状态机

```
   ┌──────────┐   首次保存（哪怕只配一项）    ┌────────────┐
   │  未设置   │ ──────────────────────────→ │  正在设置   │
   │(未做设置) │                              │(必需项未全过)│
   └──────────┘                              └──────┬─────┘
                                                    │ 必需项全过
                             必需项被破坏             ▼
                    ←─────────────────────── ┌────────────┐
                                            │   已设置    │
                                            └────────────┘

   固定文档：初始即「已设置」（无必需项）
```

**关键**：状态**自动前进也自动回退**（删锚点 / 清空数据源 ⇒ 下一次读就退回）。
⛔ **没有「标记为完成」按钮** —— 完成是**事实的推论**，不是用户的声明（`41-V3` §0.2）。
