## 1. 人机分工边界（D9 落地）

| 环节 | AI 可做 | AI 不可做 | 人工做什么 |
|------|---------|-----------|------------|
| 画像 | 提取作用/字段/表格与分数 | —— | 抽查、重跑 |
| 召回+精排 | 产出候选、五维分数、证据、推荐 | **写归属** | —— |
| 归属确认 | `Trigger=auto_rule` 的高置信自动采纳（**仅当 `ent_norm_auto_confirm=1`，首期默认 0**） | 绕过阈值、绕过冲突位 | accept / reject / replace / manual / unlink |
| 定向提取 | 按规则抽值、给字段级可信度 | 写终值 | 字段级确认/覆盖 |
| 解除关联 | —— | —— | unlink |

**底线**：`Confidence < ent_norm_review_threshold` 的候选**永不自动落标准文档**；`IsConflicted=1` 必须人工。自动动作（若开启）与人工动作**落同一张 `cert_doc_match_decision`**，靠 `IsAuto` 区分——审计口径统一。

## 2. 裁决交互设计

### 2.1 双视角（两个入口，一套数据）

| 视角 | 入口 | 主轴 | 适用场景 |
|------|------|------|----------|
| **标准文档视角**（主） | 标准目录文件行 → 「匹配裁决」 | 目标标准文档 ← 候选企业文件列表 | 04 §6.3 的呈现：「ISO9001-质量手册需要归属，候选 A/B/C 谁上」 |
| **企业文件视角**（辅） | 企业资料库文件行 → 「归属」 | 该文件 ← 它想去的标准文档（含冲突提示） | 「这份扫描件该算营业执照还是许可证」（一源多目标） |

### 2.2 标准文档视角页面结构（照抄左树右表骨架）

```text
左树：目录配置 → 文件夹 → 文件（显示 MatchState 徽标）
右表：选中文件的候选列表
┌────────────────────────────────────────────────────────────┐
│ 目标：ISO9001-质量手册（必需·可编辑）  契约：已生效  [重新匹配] │
│ 当前归属：质量手册-QM-2026-v2.docx（conf 0.92，张三 09-27 采纳）│
├────────────────────────────────────────────────────────────┤
│ 排序：Confidence DESC，冲突候选置顶                          │
│ ┌────────────────────────────────────────────────────────┐ │
│ │ ● 92% 质量手册-QM-2026-v2.docx   [推荐] 已采纳          │ │
│ │   字段 8/9（缺 适用标准）表格 1/1 期间 ✓                  │ │
│ │   理由：…                    证据(3) → [预览定位]        │ │
│ │   [采纳] [否决] [改用其他来源]                           │ │
│ ├────────────────────────────────────────────────────────┤ │
│ │ ▲ 71% QM手册(旧版2023).docx     [期间矛盾 ⚠]            │ │
│ │   期间 2023 ✗（阶段为2026）  [采纳] [否决]                │ │
│ ├────────────────────────────────────────────────────────┤ │
│ │ 无候选 → [手工指定企业文件/文件夹]  [标记为「企业暂缺」]    │ │
│ └────────────────────────────────────────────────────────┘ │
│ 操作留痕（本文件的 decision 时间线，只读展开）               │
└────────────────────────────────────────────────────────────┘
```

**交互规则**：
1. 候选行必须**同时展示分数与理由+证据入口**——只给百分比不给理由的裁决是盲裁（04 §6.3 要求）；
2. 冲突候选（`IsConflicted=1`）置顶 + 红/黄徽标，**不允许被折叠默认隐藏**；
3. 「手工指定」（`Action=manual`）：文件选择器走企业资料库（含未入候选池的文件），选中后置信度留 NULL（D8：人工不编分）；
4. 「标记为企业暂无」：不产生 decision 行，而在标准文件 `MatchState` 记 `partial`（缺口清单，10 分册验收用）；
5. 每次动作弹「理由」输入框（可选但默认聚焦，`Reason` 推荐填写）——为 09 号文的「复盘学习」留料。

### 2.3 批量操作

| 操作 | 约束 |
|------|------|
| 批量采纳 | 仅限 `Confidence ≥ auto` 且 `IsConflicted=0` 的候选；**批量结果仍逐条写 decision**（审计不因批量而失真） |
| 批量否决 | 需二次确认，写 `Reason='批量否决'` |
| ⛔ 批量手工指定 | 不提供——手工指定必然是逐条判断 |

## 3. 五个裁决动作的语义与回写

| `Action` | 语义 | 候选侧回写 | 标准文件侧回写 | decision 行 |
|----------|------|------------|----------------|-------------|
| `accept` | 采纳该候选为归属 | 本候选 `Status=confirmed`；同目标其他候选 `Status=pending→rejected`？**否**——保留，但标 `superseded`（避免下次重算误导） | `MatchState→confirmed`；`cert_enterprise_file.StandardFileCode=目标` | 新增 1 行，`BeforeStandardFileCode` 记旧值 |
| `reject` | 否决该候选 | `Status=rejected` | 不变 | 1 行 |
| `replace` | 改换来源（已有归属换另一文件） | 新候选 `confirmed`；旧候选 `superseded` | 同 accept + 更新文件侧 `StandardFileCode` | 1 行（`Before…` = 旧标准文件/旧文件，见下） |
| `manual` | 绕过候选手工指定 | 目标文件若在池中 → 该候选置 `confirmed` 并 `ScoreStage=human, Confidence=NULL`；不在池中 → **直接建一条候选行**（`RecallSource=manual, ScoreStage=human`） | 同 accept | 1 行，`CandidateCode` 可 NULL |
| `unlink` | 解除已有关联 | 原 confirmed 候选 → `rejected`（`Reason='unlink'`） | 文件 `StandardFileCode=NULL`；`MatchState→scored` | 1 行 |

**统一回写事务**（`MatchDecisionService.SubmitAsync`，单事务内完成）：

```text
1. 校验（阈值/冲突位/权限/目标存在）
2. INSERT decision 行（快照 ConfidenceUsed、Before…）
3. 更新候选状态（指定列：Status/ScoreStage/Confidence/UpdateTime/UpdateBy）
4. 更新 cert_enterprise_file.StandardFileCode + MatchState（指定列）
5. 聚合回写 cert_standard_directory_file.MatchState（confirmed/partial）
6. （若 ent_norm_auto_extract=1）投递定向提取任务 T7 —— 事务外，失败可重试
```

> **列白名单纪律**（03 分册 §4.3 同源）：第 3/4/5 步全部指定列更新，⛔ 禁止 `UpdateAsync(整实体)`。

## 4. 字段级人工确认

归属确认（T6）之后，定向链产出 `cert_extraction_result`（字段级、带 `LabelTag=FieldCode`、可信度、源位置）。字段级干预：

| 场景 | 操作 | 落点 |
|------|------|------|
| AI 抽值错误 | 人工改值 | `cert_doc_match_decision.FieldOverrideJson` 追加 `{"ENT_NAME":{"value":"XX公司","source":"manual"}}` —— **不改 `cert_extraction_result` 原值** |
| AI 漏抽 | 人工补值 | 同上，`source=manual`，`position` 人工可选填 |
| 低可信字段批量复核 | 列表过滤 `Confidence < 0.7` 的字段逐条过 | 同上 |

- **原值与覆盖值分离**：`cert_extraction_result` 是「AI 说的」，`FieldOverrideJson` 是「人定的」，消费方（报告/证书）读**合并视图**（有 override 用 override，否则原值）——这是 09 号文「原值不灭」原则的最小实现。
- 字段级覆盖只在 `accept` 之后的文档上开放（未定归属的字段无意义）。

## 5. 审计模型与查询

### 5.1 记录什么

`cert_doc_match_decision` 每行 = 一次完整干预：

```text
谁(CreateBy) 何时(CreateTime) 对哪个文件(FileCode) 做了什么(Action)
依据什么(CandidateCode + ConfidenceUsed 快照 + EvidenceJson 在候选侧) 结果前后(BeforeStandardFileCode)
为什么(Reason) 人机(IsAuto/Trigger)
```

### 5.2 四类审计查询

| 查询 | SQL 语义 | 用途 |
|------|----------|------|
| 单文件归属变迁 | `WHERE FileCode=@c ORDER BY CreateTime` | 「这份文件为什么最后算质量手册」 |
| 单标准文档来源史 | `WHERE StandardFileCode=@s ORDER BY CreateTime` | 「质量手册的来源换过几次」 |
| 人机比 | `GROUP BY IsAuto` + 按 `Reason` 分布 | 评估是否该开自动确认 |
| 误配复盘 | `WHERE Action IN('reject','replace') AND Trigger='auto_rule'` | **自动确认若开，误配必须可一键回溯**（10 分册风险项） |

### 5.3 保留与清理

- decision 表**只追加、永不 UPDATE/DELETE**（`IsDeleted` 仅用于极少数误操作的软隐藏，且隐藏本身要留操作日志——首期直接禁止删除）；
- 无保留期裁决：认证业务周期长，审计数据量小（每文件每次干预 1 行），不做归档。

## 6. 证据溯源与跳转

| 层级 | 数据 | 跳转行为 |
|------|------|----------|
| 候选证据 | `EvidenceJson`（04 §4.4 schema：field/table/purpose 三类） | `type=field` → 打开企业文件**预览并定位**（`position.page/line` → PDF/Markdown 锚点）；`contractFieldCode` → 契约字段定义处 |
| 字段证据 | `cert_extraction_result.PositionInfo`（已有） | 同上，定位到源文档位置 |
| 画像证据 | `cert_ent_doc_profile_field.PositionInfo` | 同上 |

**实现约束**：
- 跳转依赖**转换产物**（PDF/Markdown）存在——源文件被删或产物过期时降级显示「源不可用」而非报错；
- 与延展规划 12 号文「点击即定位」为同一目标，本模块先做**页面内预览定位**（Markdown 行锚点 / PDF 页码），不做跨文档双向定位（12 号文能力，📋 后续）。

## 7. 权限与角色

| 角色 | 能力 | 权限点（`ApiCode`，实施时按菜单/接口注册） |
|------|------|------------------------------------------|
| 企业端（P4 若启用） | 上传、看自己的文件与画像、**不能裁决归属** | `EntFile/Upload`、`EntProfile/Query` |
| 审核员/专家 | 查看候选、裁决、字段覆盖 | `MatchCandidate/Query`、`MatchDecision/Submit`、`ExtractResult/Override` |
| 系统管理员 | 契约维护、阈值配置、批量重跑、审计查询 | `Contract/Save`、`SysConfig/Update`、`MatchDecision/Query`（全量） |

- 三点约束：① 裁决与字段覆盖**分开授权**（能裁决不等于能改值）② 审计查询仅管理员 ③ 企业角色**永远无** `MatchDecision/*`——归属是认证方与企业共同事实，企业不可自证；
- 菜单/路由注册后必须跑 `node scripts/guards.mjs`（R12 路由↔菜单一致性）+ `sync_menu_urls.sh`（AGENTS.md 强制）。

## 9. 禁止事项

| ⛔ 禁止 | ✅ 正确做法 |
|---------|------------|
| UPDATE/DELETE decision 行 | 只追加；纠错用新 `Action` 行 |
| 裁决时不写 `BeforeStandardFileCode` | 每次动作必留前后值 |
| 用整实体 `UpdateAsync` 回写文件/候选/标准文件 | 列白名单更新 |
| AI 分数低就人工「补个 0.9」 | 人工不改 `Confidence`；人工指定 = `ScoreStage=human` + NULL 分 |
| 覆盖值直接改 `cert_extraction_result` | `FieldOverrideJson` 分离存储 |
| 批量采纳包含冲突候选 | 批量前过滤 `IsConflicted=0` |
| 企业角色接触裁决接口 | §7 权限矩阵 + ApiCode 关联（改接口名须重跑 ApiSync） |
