### 2.3 DDL 整改脚本

```sql
-- rpt_report_section 新增 workflow_config 列
SET @col_exists = (SELECT COUNT(*) FROM information_schema.COLUMNS
  WHERE table_schema=DATABASE() AND table_name='rpt_report_section' AND column_name='workflow_config');
SET @sql = IF(@col_exists = 0,
  'ALTER TABLE rpt_report_section ADD COLUMN workflow_config TEXT NULL COMMENT ''章节工作流DAG JSON'' AFTER workflow_code',
  'SELECT "workflow_config already exists"');
PREPARE stmt FROM @sql; EXECUTE stmt; DEALLOCATE PREPARE stmt;
```

### 2.4 `section_config` JSON 结构定义

`cert_report_template.section_config` 存储的是模板的章节定义列表：

```json
{
  "sections": [
    {
      "sectionCode": "SEC-001",
      "sectionName": "审核概况",
      "sectionNameEn": "Audit Overview",
      "clauseCode": "4.1",
      "sortOrder": 1,
      "isActive": true
    },
    {
      "sectionCode": "SEC-002",
      "sectionName": "审核发现",
      "sectionNameEn": "Audit Findings",
      "clauseCode": "6.1",
      "sortOrder": 2,
      "isActive": true
    }
  ]
}
```

> 注意：`section_config` 是模板级别的章节定义模板，`rpt_report_section` 是章节实例（含工作流配置）。

## 七、两个模块的关系

```
                  cert_report_template
                  (报告模板: 模板级别定义)
                  ├── section_config (JSON: 章节定义列表)
                  │
                  └── 1:N → rpt_report_section
                            (报告章节: 实例级别配置)
                            ├── section_name (章节名称)
                            ├── clause_code (关联条款)
                            ├── workflow_config (工作流 DAG JSON) ← 新增
                            └── content (初始内容)
```

NC 规则与报告章节的关系：
- NC 规则（`cert_validation_rule`）用于审核过程中的不符合项判定
- 报告章节（`rpt_report_section`）用于审核报告的内容组装
- 两者通过 `workflow_config` / `rule_json` 存储工作流 DAG JSON
- 两者共用 Skill 体系（`get_field`、`compare`、`llm_judge` 等）
