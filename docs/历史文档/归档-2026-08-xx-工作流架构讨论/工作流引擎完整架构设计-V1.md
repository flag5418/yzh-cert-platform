# 工作流引擎完整架构设计-V1

> **目标**：构建队列驱动、异步节点执行、前置自检、双模式触发的工作流引擎

## 一、数据结构分层

### 1.1 工作流四大组成部分

```
workflow_
├── layout      （布局）  ──→ 节点位置、画布状态（仅前端，不落库）
├── topology    （拓扑）  ──→ 边关系、分支条件（从配置派生，可缓存）
├── config      （配置）  ──→ 节点定义、节点属性、端口声明（落库）
└── execution   （执行）  ──→ 运行时上下文、节点输出、状态追踪（队列落库）
```

### 1.2 落库 JSON 结构统一

```jsonc
// wf_check_rule.rule_config（配置） + wf_check_rule.execution_mode
{
  "version": "1.0",                    // 配置格式版本（非节点版本）
  "ruleCode": "...",
  "nodes": [
    {
      "nodeId": "start_n1",
      "nodeType": "start",             // start|end|branch|ai_node|loop|docField|docTable|skill
      "skillCode": "",                  // skill 节点才有
      "title": "开始",
      "x": 100, "y": 200,              // layout 部分（与拓扑无关）
      "inputPorts": [],                 // 来自元数据或 Skill 表
      "outputPorts": [],
      "config": { /* 面板参数 */ },
      "inputs": { /* 连线引用 */ }
    }
  ],
  "edges": [
    { "source": "start_n1", "target": "ai_n2", "sourceHandle": null, "targetHandle": null }
  ],
  "branches": [
    {
      "from": "compare_n3",
      "condition": { "field": "result", "op": "truthy" },
      "then": [
        { "nodeId": "branch_n4_true", "title": "满足条件" },
        { "nodeId": "branch_n4_false", "title": "不满足条件" }
      ]
    }
  ],
  "outputConfig": { "mergeMode": "array" }
}
```

**重要**：节点不再有 `color`/`icon`/`version` 属性。配色从分类（Skill 表 category）派生，版本号对配置无意义。

## 三、双模式触发 + 统一核心逻辑

### 3.1 场景对比

| 维度 | 模式 A：前端测试 | 模式 B：自动执行 |
|------|-----------------|-----------------|
| 触发方 | 审核员点击"测试节点" | 审核员上传文件后系统自动触发 |
| config 来源 | 前端序列化后的 JSON | 数据库 `wf_check_rule.rule_config` |
| 执行上下文 | 前端临时构造 | 从数据库查询机构/标准/文件编码 |
| 结果展示 | 前端弹窗/面板 | yzh_queue 进度 + SignalR/轮询推送 |
| 错误处理 | 显示错误信息 | 队列重试 + 失败通知 |

### 3.2 两种接口设计

```csharp
// ===== 接口 A：前端测试 =====
[HttpPost("api/workflow/test-node")]
[HttpPost("api/workflow/test-path")]
public async Task<IActionResult> TestNode([FromBody] TestRequest req)
{
    // req.WorkflowConfig = 前端传来的 JSON
    // req.NodeId = 待测试节点（可选；不传则测试从 start 到该节点的路径）
    var config = JsonSerializer.Deserialize<WorkflowConfig>(req.WorkflowConfig);
    var validator = new WorkflowValidator();
    var report = validator.Validate(config);  // 前置自检
    
    if (report.HasBlockingErrors)
        return Ok(new { status = "invalid", report });
    
    var context = new WorkflowContext { ... };  // 从 req 构造
    var result = await _engine.TestAsync(config, req.NodeId, context);
    return Ok(new { status = "ok", result, report });
}

// ===== 接口 B：自动执行 =====
[HttpPost("api/workflow/auto-execute")]
public async Task<IActionResult> AutoExecute([FromBody] AutoExecuteRequest req)
{
    // req.RuleCode / req.FileCode / req.OrgCode
    var rule = await _ruleRepo.GetByCodeAsync(req.RuleCode);
    var config = JsonSerializer.Deserialize<WorkflowConfig>(rule.RuleConfig);
    
    // 前置自检（强制）
    var report = _validator.Validate(config);
    if (report.HasBlockingErrors)
        return BadRequest(new { error = "工作流配置校验未通过", report });
    
    // 构造队列
    var queueReq = new YzhQueueManager.CreateQueueRequest
    {
        QueueType = "workflow_execute",
        QueueName = $"工作流执行-{req.RuleCode}",
        ScopeKey = $"{req.OrgCode}|{req.StandardCode}|{req.FileCode}",
        SourceType = "auto_verify",
        SourceId = req.FileCode,
        Tasks = BuildWorkflowTasks(config, req)  // 一个节点 = 一个队列任务
    };
    
    var (ok, error, queueCode, count) = await _queueManager.CreateQueueAsync(queueReq);
    return Ok(new { queueCode, totalNodes = count });
}
```

**WorkflowExecutionService** 是统一核心：

```csharp
public class WorkflowExecutionService
{
    // 统一执行入口
    public async Task<WorkflowRunResult> RunAsync(
        WorkflowConfig config, WorkflowContext context, 
        CancellationToken ct = default)
    {
        // 1. 拓扑排序
        var order = TopoSort(config);
        
        // 2. 按序执行节点
        var outputs = new Dictionary<string, NodeOutput>();
        foreach (var nodeId in order)
        {
            var node = config.FindNode(nodeId);
            var result = await ExecuteNodeAsync(node, outputs, context, ct);
            outputs[nodeId] = result;
            if (!result.Success && !node.ContinueOnError)
                return WorkflowRunResult.Failed(nodeId, result.Error);
        }
        return WorkflowRunResult.Success(outputs);
    }
    
    // 单节点测试（start → targetNode 路径）
    public async Task<WorkflowRunResult> TestNodeAsync(
        WorkflowConfig config, string targetNodeId, WorkflowContext context, CancellationToken ct)
    {
        // 提取从 start 到 targetNode 的子图
        var subGraph = ExtractSubGraph(config, targetNodeId);
        return await RunAsync(subGraph, context, ct);
    }
}
```

## 四、前置自检系统

### 4.1 校验项分级

```yaml
# Error Level（阻塞，不允许保存/执行）
ERROR:
  - NO_START_NODE:       缺少开始节点
  - NO_END_NODE:         缺少结束节点
  - CYCLE_DETECTED:      存在环（死循环风险）
  - INVALID_BRANCH:      分支条件引用不存在的字段
  - UNDEFINED_SKILL:     引用了未注册的 skillCode
  
# Warning Level（允许执行，需用户确认）
WARNING:
  - UNREACHABLE_NODE:    不可达节点（孤立节点，可能是预留）
  - MISSING_INPUT:       必填输入端口未连接/未填写
  - AI_NO_TEMPLATE:      AI 节点未配置提示词
  - OUTPUT_NOT_REFERENCED: 输出未被下游使用（可能是中间调试节点）
  
# Info Level（仅供参考）
INFO:
  - LONG_PATH:           路径过长（> 10 节点，考虑拆分）
  - HIGH_FANOUT:         单点出度 > 5（考虑合并分支）
```

### 4.2 校验器实现

```csharp
public class WorkflowValidator
{
    public ValidationReport Validate(WorkflowConfig config)
    {
        var report = new ValidationReport();
        
        // 1. 开始/结束节点存在性
        var starts = config.Nodes.Count(n => n.NodeType == "start");
        var ends = config.Nodes.Count(n => n.NodeType == "end");
        if (starts == 0) report.Add(Error("NO_START_NODE"));
        if (starts > 1) report.Add(Error("DUPLICATE_START"));
        if (ends == 0) report.Add(Error("NO_END_NODE"));
        
        // 2. 环检测
        var cycles = DetectCycles(config);
        if (cycles.Any()) report.Add(Error("CYCLE_DETECTED", cycles));
        
        // 3. 孤立节点检测（排除 start）
        var reachable = GetReachableFromStart(config);
        foreach (var node in config.Nodes.Where(n => n.NodeType != "start"))
        {
            if (!reachable.Contains(node.NodeId))
                report.Add(Warning("UNREACHABLE_NODE", node.NodeId));
        }
        
        // 4. 必填参数检查
        foreach (var node in config.Nodes)
        {
            var meta = _skillRegistry.GetMetadata(node.SkillCode);
            if (meta == null) continue;
            
            foreach (var input in meta.InputPorts.Where(p => p.Required))
            {
                if (!node.Inputs.ContainsKey(input.Name) || node.Inputs[input.Name] == null)
                    report.Add(Warning("MISSING_INPUT", node.NodeId, input.Name));
            }
        }
        
        // 5. 分支条件合法性
        foreach (var branch in config.Branches ?? new())
        {
            if (!ValidateBranchCondition(branch, config))
                report.Add(Error("INVALID_BRANCH", branch.From));
        }
        
        // 6. Skill 注册表匹配
        foreach (var node in config.Nodes.Where(n => n.NodeType == "skill"))
        {
            if (_skillRegistry.GetMetadata(node.SkillCode) == null)
                report.Add(Error("UNDEFINED_SKILL", node.NodeId, node.SkillCode));
        }
        
        // 7. AI 节点特殊校验
        foreach (var aiNode in config.Nodes.Where(n => n.NodeType == "ai_node"))
        {
            if (string.IsNullOrEmpty(aiNode.Config?.GetValueOrDefault("prompt")?.ToString()))
                report.Add(Warning("AI_NO_TEMPLATE", aiNode.NodeId));
        }
        
        return report;
    }
}
```

## 五、队列驱动异步执行

### 5.1 现有 yzh_queue 复用

核心复用现有 `YzhQueueManager` + `YzhQueueHostedService` 体系：

```
现有队列类型：
  file_convert    文件转换

新增队列类型：
  workflow_execute  工作流自动执行
  workflow_test     工作流前端测试（可选同步模式）
```

### 5.2 节点级任务设计

```
一个工作流 = 一个队列（yzh_queue）
    ├── 节点 1（compare）    → yzh_queue_task
    ├── 节点 2（docField）   → yzh_queue_task
    ├── 节点 3（ai_node）    → yzh_queue_task
    └── 节点 4（end）        → yzh_queue_task
```

**关键设计**：节点是串行等待执行的，不是并行的！

```csharp
// WorkflowQueueExecutor.cs - IYzhTaskExecutor 实现
public class WorkflowQueueExecutor : IYzhTaskExecutor
{
    public string TaskType => "workflow_node";  // 每个子任务类型为 workflow_node
    
    // payload 结构：
    // {
    //   "workflowQueueCode": "Q-20260821-xxxx",  // 所属工作流队列
    //   "nodeId": "compare_n3",
    //   "nodeIndex": 3,           // 拓扑序中的位置
    //   "subGraphNodes": [...],   // 子图节点配置（仅需要的部分）
    //   "workflowContext": {...}  // 工作流上下文
    // }
    
    public async Task<YzhTaskExecutionResult> ExecuteAsync(YzhQueueTask task, CancellationToken ct)
    {
        var payload = JsonSerializer.Deserialize<WorkflowNodePayload>(task.Payload);
        var workflowCtx = payload.WorkflowContext;
        
        // 检查前置依赖是否完成（查同一 queue_code 下的前置节点任务状态）
        if (!await AreDependenciesCompletedAsync(task))
        {
            return new YzhTaskExecutionResult 
            { 
                Success = false, 
                Message = "前置节点尚未执行完成",
                Retryable = true  // 可重试
            };
        }
        
        // 执行单个节点
        var nodeOutput = await _skillExecutor.ExecuteAsync(payload.NodeConfig, workflowCtx, ct);
        
        // 保存节点输出到队列 payload 或临时存储（供下游节点读取）
        await SaveNodeOutputAsync(payload.WorkflowQueueCode, payload.NodeId, nodeOutput);
        
        return new YzhTaskExecutionResult { Success = true };
    }
}
```

### 5.3 串行执行保证

由于工作流节点之间有严格的数据依赖（节点 3 的输入来自节点 2 的输出），**必须串行执行**。

**方案 A（推荐）：控制器串行分发**

```csharp
// WorkflowExecuteService.cs
public class WorkflowExecuteService
{
    public async Task<string> EnqueueWorkflowAsync(WorkflowConfig config, WorkflowContext context)
    {
        var queueCode = await CreateQueueAsync(config, context);
        
        // 把每个节点作为独立任务入队，但设置 DependencyTaskNo
        // 节点 N 依赖节点 N-1
        
        var tasks = new List<TaskItem>();
        var order = TopoSort(config);
        
        for (int i = 0; i < order.Count; i++)
        {
            var nodeId = order[i];
            var node = config.FindNode(nodeId);
            
            tasks.Add(new TaskItem
            {
                TaskType = "workflow_node",
                Payload = JsonSerializer.Serialize(new WorkflowNodePayload
                {
                    WorkflowQueueCode = queueCode,
                    NodeId = nodeId,
                    TopologyIndex = i,
                    DependsOnIndex = i > 0 ? i - 1 : null,  // 依赖前驱
                    NodeConfig = node,
                    WorkflowContext = context
                }),
                TaskId = $"{queueCode}_{nodeId}"  // 唯一标识
            });
        }
        
        await _queueManager.CreateQueueAsync(new CreateQueueRequest
        {
            QueueType = "workflow_execute",
            Tasks = tasks
        });
        
        return queueCode;
    }
}
```

**方案 B（依赖 yzh_queue 的串行消费 + 自定义 Exeecutor 内串行）**

```csharp
// 更实际的方案：队列 MaxConcurrent=1 保证串行
// YzhQueueOptions 为 workflow_execute 类型单独配置
services.Configure<YzhQueueOptions>(options =>

    // 全局 MaxConcurrent = 5（文件转换）
    // 但 workflow_execute 必须串行，需在 executor 内控制
});

// 实际做法：WorkflowExecutor.ExecuteAsync 内部查 DB 确认前置完成
public async Task<YzhTaskExecutionResult> ExecuteAsync(YzhQueueTask task, CancellationToken ct)
{
    var payload = JsonSerializer.Deserialize<WorkflowNodePayload>(task.Payload);
    
    // 等待前置节点完成（轮询 + 超时）
    var preNodeId = GetPredecessorNodeId(payload);
    if (preNodeId != null)
    {
        var completed = await WaitForNodeCompletionAsync(
            payload.WorkflowQueueCode, preNodeId, 
            timeoutSeconds: 300, ct);
        if (!completed)
            return new YzhTaskExecutionResult 
            { 
                Success = false, 
                Message = $"前置节点 {preNodeId} 执行超时",
                Retryable = false 
            };
    }
    
    // 执行当前节点
    return await ExecuteNodeAsync(payload, ct);
}
```
