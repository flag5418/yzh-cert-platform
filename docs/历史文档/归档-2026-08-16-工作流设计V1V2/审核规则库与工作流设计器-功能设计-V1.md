## 一、功能概述

### 1.1 两个核心功能

| 功能 | 页面 | 用户角色 | 一句话描述 |
|------|------|---------|-----------|
| **NC检查规则管理** | `/CertPlatform/WorkflowRules/Rules` | 管理员 | 按机构→标准→阶段维度维护NC检查项列表，每项绑定一个工作流 |
| **工作流可视化设计** | `/CertPlatform/WorkflowDesigner/Designer/:id` | 管理员 | 用 LogicFlow 画布拖拽 Skill 节点，配置 inputs/outputs/branches，发布为可执行 DAG |

### 1.2 核心业务逻辑（必读）

```
工作流定义（F-03 wf_workflow_definition）   ←  先创建，独立存在
       │
       │  workflow_code
       ▼
NC检查规则（cert_validation_rule.workflow_code）  ←  后绑定，引用工作流
       │
       │  审核员点击"执行审核"
       ▼
WorkflowEngine.RunAsync(workflowConfig, { enterpriseCode, phaseCode })
       │
       ├── get_field[label_tag]  → 查 B-08 WHERE enterprise_code=? AND label_tag=?
       ├── compare / date_diff   → 确定性计算
       ├── llm_judge             → AI 语义判断
       └── create_nc             → 写 B-07 不符合项
```

**关键设计决策**：
- 工作流定义是**独立实体**，先在"工作流列表"页创建，再用其 `workflow_code` 绑定到规则
- 规则页的"工作流"列是一个**只读引用**（显示 workflow_name），操作入口是"在设计器中编辑"
- B-08/B-09 的 `enterprise_code` 是**运行时注入**（来自审核任务上下文），设计器不配置

## 二、业务背景与目标

### 2.1 当前问题

1. 无工作流定义管理入口，管理员无法创建/编辑工作流
2. 规则列表页左侧树为空（因规则表无数据，树从规则反向构建）
3. 工作流设计器缺少 F-02 标签树形选择器，`get_field` 节点无法可视化配置
4. 测试沙箱无数据源（B-08/B-09 无 YZH 标准企业数据），无法验证工作流

### 2.2 目标

1. 提供工作流定义 CRUD 管理页面
2. 规则列表页左侧树从**参考数据表**（机构/标准/阶段）加载，规则数作为附加信息
3. 工作流设计器支持 F-02 标签树形选择器，节点属性表单完整
4. 提供测试沙箱，可注入 YZH 标准企业数据运行工作流

## 四、业务规则

### 4.1 工作流定义规则

| 规则 | 说明 |
|------|------|
| R1 | 工作流类型：`extraction`（提取）/ `validation`（校验）/ `report`（报告） |
| R2 | 工作流版本：每次 publish 递增，旧版本保留（支持回滚） |
| R3 | 工作流状态：`draft`（草稿）/ `published`（已发布）/ `archived`（已归档） |
| R4 | 同一 `workflow_code` 可有多版本，只显示最新+历史版本 |
| R5 | `IsActive=true` 的工作流才可被规则绑定 |

### 4.2 NC检查规则规则

| 规则 | 说明 |
|------|------|
| R6 | 一条规则必须绑定一个工作流（`workflow_code` 非空） |
| R7 | 规则按 机构→标准→阶段→条款 四级维度组织 |
| R8 | 同一 机构+标准+阶段+条款 组合下不允许重复规则编码 |
| R9 | 复制规则时，新规则 workflow_code 自动复制，需单独编辑 |
| R10 | 删除规则前检查是否有审核任务引用该规则 |

### 4.3 工作流设计器规则

| 规则 | 说明 |
|------|------|
| R11 | 工作流节点按四类划分：输入/确定性计算/AI/输出 |
| R12 | 连线时实时校验：上游 output_schema 端口名必须在下游 input_schema 中存在 |
| R13 | DAG 必须无环（拓扑排序失败则提示） |
| R14 | 保存前必须通过校验（DAG 合法性 + Skill 存在性） |
| R15 | 测试运行注入 `enterprise_code='YZH-STD-ENT'` 使用标准目录验证数据 |

### 6.3 错误处理规范

| 场景 | HTTP | response.status | message |
|------|:----:|:---------------:|---------|
| 工作流编码重复 | 409 | false | `工作流编码 {code} 已存在，请使用其他编码` |

## 八、边界与异常处理

### 8.1 无 B-08/B-09 数据时的行为

| 场景 | 当前行为 | 期望行为 |
|------|---------|---------|
| 工作流设计器测试运行，B-08 无数据 | `get_field` 返回"未找到"，测试失败 | 提示"未找到 B-08 数据，请先在 DocExtractionRule 页面保存提取规则" |
| 规则列表页左侧树为空 | 只显示"全部规则" | 仍显示机构/标准/阶段结构（从参考表加载），规则数为 0 |
| 新建规则时工作流下拉为空 | 只能手动输入编码 | 从 `api/workflow-definition/list?isActive=true` 加载下拉选项 |

### 8.2 工作流删除限制

- 有 NC 规则引用该工作流时，拒绝删除，返回引用规则列表
- 软删除（`enable=false`），不物理删除

### 8.3 前端缓存

- 菜单缓存 `inernalMenu` 在 Redis 中，修改菜单后需清除缓存（已处理）
- 树形数据建议在组件内缓存，避免每次展开都发请求
