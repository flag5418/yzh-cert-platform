## 三、设计推进节奏

```
第一层：概念与目的
  ├── 它是什么系统？服务于谁？
  ├── 数据的生命周期是怎样的？
  └── 产出：数据库设计-第1章 概念与目的

第二层：角色与职责
  ├── 谁在使用系统？各自需要什么数据？
  ├── 角色对数据的 CRUD 权限边界
  └── 产出：数据库设计-第2章 角色与数据边界

第三层：数据域划分
  ├── 系统有多少个独立数据域？
  ├── 域之间如何关联？
  └── 产出：数据库设计-第3章 数据域划分与关系

第四层：表清单 + 表关系
  ├── 每张表的职责、管理范围
  ├── 核心 ER 关系
  └── 产出：数据库设计-第4章 表清单与关系

第五层：字段设计 + 菜单映射
  ├── 每张表的具体字段、约束、索引
  ├── 每张表对应的前端菜单
  └── 产出：数据库设计-第5章 表结构 + 第6章 菜单映射
```

**每层讨论完成后冻结，下层讨论以冻结结论为基础。不允许跳跃。**

## 四、技术验证周策略

在骨架搭建前，需验证 5 个阻断级技术点：

| 编号 | 验证项 | 如果失败 |
|:---:|--------|---------|
| V1 | Vol Skill 能否生成可用 CRUD | 改用手写 Controller/Service |
| V2 | DeepSeek API 可用性 | 换腾讯混元/百度文心 |
| V3 | OCR 文件解析可行性 | 降级为人工录入 + 关键词提取 |
| V4 | MinIO 文件版本管理 | 改用本地文件系统 + 数据库记录 |
| V5 | 自建 Skill 与 Vol Skill 配合 | Skill 改为独立 Service 调用 |

**验证原则**：阻断级风险必须提前收掉，可控风险不做预研。
