## 一、我理解的您的核心思想（请确认是否准确）

### 1.1 产品哲学：「先让核心跑通，再逐步完善」

```
❌ 我之前的工作方式（过于追求大而全）：
   - 试图在文档阶段就设计完所有功能
   - 每个模块都深入分析到细节
   - 想要一次性产出"完美"的总体设计
   
✅ 您的正确方式（务实迭代）：
   - 总体设计 = 全景图 + 模块清单 + 核心任务定义
   - 不需要每个模块都深入设计细节
   - 先把一个核心功能做到极致 → 验证价值 → 再扩展下一个
```

### 1.2 什么是「核心任务」？

根据您的多次强调，我总结的核心任务是：

```
┌─────────────────────────────────────────────────────┐
│              🎯 第一阶段核心任务                     │
│                                                     │
│  「审核报告的自动生成」                               │
│                                                     │
│  包含以下能力链：                                     │
│                                                     │
│  1️⃣ 资料输入层                                       │
│     ├─ 文件上传（PDF/Word/Excel/TXT/图片）           │
│     ├─ OCR识别（通用文字 + 表格 + 结构化证件）        │
│     └─ 多格式数据提取和结构化                         │
│                                                     │
│  2️⃣ 数据处理层                                       │
│     ├─ 文件规则校验（是否符合报告要求的格式）         │
│     ├─ 文件完整性检查（哪些必需文件缺失）             │
│     ├─ 规则数据提取（从资料中提取关键字段）           │
│     └─ 逻辑判断（基于规则引擎的初步分析）             │
│                                                     │
│  3️⃣ AI智能层                                        │
│     ├─ AI填充（根据提取的数据+模板生成报告内容）      │
│     ├─ 内容增强（NC描述规范化、条款关联等）           │
│     └─ 报告质量评估（完整性/合规性评分）              │
│                                                     │
│  4️⃣ 输出层                                          │
│     ├─ 报告预览（在线查看）                           │
│     ├─ 导出（PDF / Word / Excel）                    │
│     └─ 版本管理（草稿→定稿→归档）                    │
│                                                     │
│  ✅ 成功标准：用户上传资料 → 一键生成可用的审核报告    │
└─────────────────────────────────────────────────────┘
```

### 1.3 为什么这是核心？

| 理由 | 说明 |
|------|------|
| **用户价值最大** | 解决审核员最大痛点（写报告耗时2-3天→30分钟） |
| **技术复杂度最高** | 涉及OCR+AI+模板引擎+多格式处理，是最难的部分 |
| **差异化最明显** | 竞品要么没AI，要么只有Web端，我们有移动端+AI |
| **商业变现直接** | 这是用户愿意付费的核心功能 |
| **其他功能依赖它** | 日历/语音/协作等功能都是锦上添花 |

### 1.4 非核心功能的处理原则

```
非核心功能 = 记录在总体设计中作为「模块清单」存在
            但不深入设计细节
            等核心验证成功后，再逐个击破

示例：

AuditPlan（工作日历）
  总体设计中写：
    "Mxx 审核计划与日历：支持审核员规划每日工作安排，
     日历视图展示活动记录，支持任务延期标记。
     【Phase 2 实现】"
    
  不需要现在写的：
    ❌ AuditPlanItem 的详细字段定义
    ❌ 日历UI组件的具体交互
    ❌ 提醒推送的实现机制
    ❌ 计划vs实际的对比算法
    
VoiceMemo（AI语音）
  总体设计中写：
    "Mxx AI语音助手：支持现场录音转文字，AI增强为规范文案。
     包含音频存储、STT转写、LLM后处理三件套。
     【Phase 1-2 实现】"
    
  不需要现在写的：
    ❌ VoiceMemo表的完整DDL
    ❌ 音频压缩和存储优化策略
    ❌ 流式转写的具体实现
```

## 四、核心任务的详细拆解（供您审视）

### 4.1 「报告自动生成」能力链详解

```
用户操作:
  [上传资料] → [系统自动分析] → [一键生成报告] → [预览/编辑] → [导出]
  
Step 1: 资料上传与接收
  ── 输入: 用户拖拽/选择文件（支持批量）
  ── 支持: PDF, Word(.docx), Excel(.xlsx), TXT, 图片(JPG/PNG)
  ── 处理: 
      ├─ 文件类型自动识别
      ├─ 文件大小校验（单文件≤50MB）
      ├─ 病毒扫描（可选，Phase 2）
      └─ 存入临时存储（MinIO/本地磁盘）

Step 2: OCR与数据提取（并行处理）
  ├── [营业执照/证件照片]
  │   └─ 结构化OCR → {企业名称, 统一社会信用代码, 法人, ...}
  │
  ├── [表格/检查表图片或Excel]
  │   └─ 表格OCR → 结构化数据 → 可能匹配ChecklistItem
  │
  ├── [Word/PDF文档]
  │   └─ 通用OCR + 版面分析 → 分段文本 + 表格提取
  │
  └── [历史报告(PDF)]
      └─ 语义OCR(LLM) → 提取历史NC清单 → 辅助本次审核关注点
      
  ⚠️ 注意: Step 2 中不同类型的OCR可以并行处理
  ⚠️ 注意: "语义OCR"依赖LLM，可能是较慢的操作，需异步处理

Step 3: 资料完整度分析
  ── 输入: Step 2的所有提取结果
  ── 对比: 检查表模板（该审核类型应该有的文件清单）
  ── 输出: 
      ├─ 完整度评分 (0-100%)
      ├─ 已有证据列表（哪些检查项已有支撑材料）
      └─ 缺失项列表（哪些必需文件未提供，风险等级）

Step 4: 报告生成（AI核心）
  ── 输入: 
      ├─ 企业信息（来自OCR或用户填写）
      ├─ 任务信息（审核类型/标准/日期范围）
      ├─ NC清单（如有检查表填写结果）
      ├─ 证据摘要（所有资料的要点提取）
      └─ 报告模板（对应审核类型的模板）
      
  ── 处理（调用DeepSeek API）:
      ├─ Prompt组装（注入上下文+模板格式要求）
      ├─ LLM生成（流式输出，实时显示进度）
      └─ 结果后处理（格式修正/章节分割/条款编号核对）
      
  ── 输出: 审核报告初稿（Markdown/JSON结构化数据）

Step 5: 报告预览与编辑
  ── PC端Web界面展示（富文本编辑器）
  ── 支持: 文字修改/段落调整/图片插入
  ── 版本自动保存（每次编辑创建新版本）
  ── 协作批注（Phase 2）

Step 6: 定稿与导出
  ── 用户确认"定稿" → 锁定版本
  ── 导出选项:
      ├─ PDF（正式交付格式，含水印）
      ├─ Word（可二次编辑）
      └─ Excel（NC清单/检查表汇总）
```

### 4.2 核心任务的技术挑战清单

| # | 挑战 | 难度 | 应对策略 |
|---|------|:----:|---------|
| T1 | **多格式文件解析**（Word/Excel/PDF） | 🔴高 | 使用Apache POI/.NET库 + pdf.js，分格式处理 |
| T2 | **OCR准确率**（特别是表格和证件） | 🔴高 | 多服务商对比测试，选最优；提供人工校正入口 |
| T3 | **AI生成的报告质量一致性** | 🔴高 | Prompt工程 + 输出模板约束 + 少样本学习 |
| T4 | **报告模板的可配置性** | 🟡中 | 初期3套固定模板（初审/监督/复评），后续再做模板引擎 |
| T5 | **大文件上传和处理性能** | 🟡中 | 分片上传 + 异步处理队列 + 进度推送 |
| T6 | **报告导出的格式保真度** | 🟡中 | 使用成熟的报表引擎（如iText/PDFSharp） |
