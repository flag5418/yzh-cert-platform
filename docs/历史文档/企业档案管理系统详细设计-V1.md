## 一、系统概述

### 1.1 业务目标

建立一个**机构-标准-阶段**三维管理的文件档案系统，支持：
- 文件夹树形结构管理
- 文件上传、下载、版本管理
- 拖拽操作简化用户流程
- 文件属性扩展（规则、校验、提取）
- 空间统计与文件计数

### 1.2 核心概念

```
┌─────────────────────────────────────────────────────────────────┐
│                        管理维度                                 │
│                                                                 │
│   机构 (Enterprise)                                             │
│     └── 标准 (ISOStandard)                                      │
│           └── 阶段 (CertStage)                                  │
│                 └── 文件夹树 (EnterpriseDocument)               │
│                       └── 文件 (EnterpriseFile)                 │
│                             └── 版本 (FileVersion)              │
└─────────────────────────────────────────────────────────────────┘
```

### 1.3 编码规则设计

#### 机构编码（EnterpriseCode）
```
格式：EB-{YYYYMMDD}-{6位随机}
示例：EB-20260808-A1B2C3
说明：EB = Enterprise Base，日期 + 随机数保证唯一
```

#### 标准编码（StandardCode）
```
格式：ISO-{标准号}
示例：ISO-9001:2015, ISO-13485:2016
说明：直接使用国际标准编号，便于识别
```

#### 阶段编码（StageCode）
```
格式：STAGE-{序号}
示例：STAGE-01, STAGE-02, ..., STAGE-09
说明：固定9个阶段，按认证流程顺序
```

#### 企业档案编码（EnterpriseDocCode）
```
格式：ED-{EnterpriseCode}-{Scope}-{ParentCode|ROOT}
示例：
  - ED-EB20260808A1B2C3-EB-ROOT      # 企业基础资料根目录
  - ED-EB20260808A1B2C3-PH-STAGE01   # 第一阶段隔离层根目录
  - ED-EB20260808A1B2C3-EB-QUALI     # 质量管理系统文件夹
  - ED-EB20260808A1B2C3-PH-STAGE01-APPL  # 申请文件文件夹
```

字段说明：
- `ED` = Enterprise Document
- `EnterpriseCode` = 所属企业编码（前缀）
- `Scope` = 资料层级（EB=企业基础/PH=阶段隔离）
- `ParentCode` 或 `ROOT` = 父文件夹编码或根标记

#### 文件夹编码（FolderCode）
```
格式：FD-{EnterpriseDocCode}-{序号}
示例：
  - FD-ED-EB20260808A1B2C3-EB-ROOT-001    # 企业基础资料下的第一个文件夹
  - FD-ED-EB20260808A1B2C3-PH-STAGE01-001  # 第一阶段下的第一个文件夹
```

字段说明：
- `FD` = Folder
- `EnterpriseDocCode` = 所属企业文档根目录编码
- `序号` = 3位数字，保证同级唯一

#### 文件编码（FileCode）
```
格式：FL-{FolderCode}-{FileNameHash}-{Version}
示例：
  - FL-FD-ED-EB20260808A1B2C3-EB-ROOT-001-B7A3F2-v1
  - FL-FD-ED-EB20260808A1B2C3-EB-ROOT-001-B7A3F2-v2
```

字段说明：
- `FL` = File
- `FolderCode` = 所属文件夹编码
- `FileNameHash` = 文件名哈希（6位，防止重名冲突）
- `Version` = 版本号（v1, v2, ...）

#### 版本编码（VersionCode）
```
格式：VR-{FileCode}-{VersionNumber}
示例：
  - VR-FL-FD-ED-EB20260808A1B2C3-EB-ROOT-001-B7A3F2-v1-001
  - VR-FL-FD-ED-EB20260808A1B2C3-EB-ROOT-001-B7A3F2-v1-002
```

字段说明：
- `VR` = Version
- `FileCode` = 所属文件编码
- `VersionNumber` = 版本号（3位数字）

```
拖拽流程：
1. 用户从外部拖拽文件/文件夹到页面
   ↓
2. 显示拖拽提示区域（高亮边框）
   ↓
3. 用户松开鼠标
   ↓
4. 前端解析文件夹结构
   ↓
5. 显示预览确认对话框（文件夹名、文件列表、大小）
   ↓
6. 用户确认后，后端创建文件夹结构并上传文件
   ↓
7. 更新右侧列表
```

**拖拽处理逻辑**：
```javascript
// 前端拖拽处理
function handleDrop(event) {
  const items = event.dataTransfer.items
  const entries = []
  
  for (let i = 0; i < items.length; i++) {
    const entry = items[i].webkitGetAsEntry()
    entries.push(entry)
  }
  
  // 递归读取文件夹结构
  readEntries(entries).then(structure => {
    // 显示预览确认
    showDropPreview(structure)
  })
}

// 递归读取文件夹
async function readEntries(entries) {
  const result = { folders: [], files: [] }
  
  for (const entry of entries) {
    if (entry.isFile) {
      const file = await new Promise(resolve => entry.file(resolve))
      result.files.push({
        name: entry.name,
        size: file.size,
        type: file.type,
        path: entry.fullPath
      })
    } else if (entry.isDirectory) {
      const dirReader = entry.createReader()
      const children = await new Promise(resolve => 
        dirReader.readEntries(resolve)
      )
      const childStructure = await readEntries(children)
      result.folders.push({
        name: entry.name,
        path: entry.fullPath,
        ...childStructure
      })
    }
  }
  
  return result
}
```

```
GET    /api/enterprise/{enterpriseCode}/folders

       获取文件夹详情

POST   /api/folder

PUT    /api/folder/{folderCode}
       更新文件夹（重命名、修改规则等）

       删除文件夹（递归删除子内容）

POST   /api/folder/{folderCode}/move
```

### 4.3 编码生成服务

```csharp
public interface ICodeGeneratorService
{
    // 文件夹编码
    string GenerateFolderCode(string enterpriseCode, string parentCode, int depth);
    
    // 文件编码
    string GenerateFileCode(string folderCode, string fileName);
    
    // 版本编码
    string GenerateVersionCode(string fileCode, int versionNumber);
    
    // 企业档案编码
    string GenerateEnterpriseDocCode(string enterpriseCode, string scope, string parentCode);
}

public class CodeGeneratorService : ICodeGeneratorService
{
    public string GenerateFolderCode(string enterpriseCode, string parentCode, int depth)
    {
        // 格式：FD-{EnterpriseDocCode}-{序号}
        var sequence = GetNextSequence($"folder_{enterpriseCode}_{parentCode}");
        return $"FD-{enterpriseCode}-{parentCode}-P{sequence:D3}";
    }
    
    public string GenerateFileCode(string folderCode, string fileName)
    {
        // 格式：FL-{FolderCode}-{FileNameHash}-{Version}
        var hash = ComputeFileNameHash(fileName);
        return $"FL-{folderCode}-{hash}-v1";
    }
    
    public string GenerateVersionCode(string fileCode, int versionNumber)
    {
        // 格式：VR-{FileCode}-{VersionNumber}
        return $"VR-{fileCode}-v{versionNumber:D3}";
    }
    
    private string ComputeFileNameHash(string fileName)
    {
        // 取文件名前6位字符的哈希，确保唯一性
        var bytes = Encoding.UTF8.GetBytes(fileName);
        var hash = MD5.HashData(bytes);
        return Convert.ToBase64String(hash).Substring(0, 6).Replace('/', 'X');
    }
}
```
