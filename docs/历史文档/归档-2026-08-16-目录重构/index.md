## 三、编写约束（功能设计文档强制规范）

> 宪法 §2.4.6 为本约束的宪法级总纲；以下为操作细则，冲突时以宪法为准。

1. **一个功能一个文档**：命名 `{功能名}-功能设计-V{N}.md`；修改非新增 → 同版本修订并在头部注明；设计变更 → 升版本号（V1→V2），旧版移 `历史文档/`。
2. **章节固定（11 章）**：必须按下方模板顺序与标题编写，**不得增删章节**（新增内容放"八、边界与异常处理"后追加编号章节，并在"章节变更记录"登记）。
3. **状态机**：文头 `状态` 取值唯一：`设计稿 → 评审中 → 实施中 → 已实施 → 已废弃`，与 TODO 计划联动。
4. **TODO 执行计划（硬性章节）**："十、TODO 执行计划" 必填，每项标注 `[ ] 未开始 / [~] 进行中 / [x] 已完成(日期)`；TODO 全部完成才可标"已实施"。
5. **表设计必含约束**："五、数据设计"每张表必须列出：用途、关键字段、索引、**唯一约束 DDL**（DB 层硬保障，不依赖逻辑控制）。
6. **接口必含错误处理**："六、接口设计"每个接口必须写：方法、路径、请求/响应结构、失败场景与错误返回。
7. **命名规范**：表名 `cert_`/`ent_`/`wf_` 前缀、字段 snake_case、接口 `/api/模块/动作`、常量全大写。
8. **关联文档必写**：文头"关联文档"必须列出前置/相关文档，不允许无来源设计。
9. **文档先行**：进入实施前必须完成本目录设计文档，**文档未完成不得实施**；实施后逻辑变化必须同步更新文档（状态头注明修订日期）。
10. **功能完成后文档留在本目录**（它是该功能的权威说明），不归档。
