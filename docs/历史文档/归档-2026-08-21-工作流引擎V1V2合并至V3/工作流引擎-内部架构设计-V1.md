## 〇、设计背景与驱动力

### 0.1 业务场景分析

工作流引擎的核心业务场景是**NC 不符合项检查**和**报告章节生成**。这两类场景有以下关键特征：

| 特征 | 说明 | 设计影响 |
|---|---|---|
| **多检查项并行** | 一个企业、一个标准、一个阶段下，有多个 NC 检查项需要独立执行 | 需要"执行项"层级，支持并行执行与失败隔离 |
| **单次执行不等于最终结果** | 企业可能频繁更换文档，需要多次执行 NC 检查或报告生成 | 需要任务版本管理，每次执行独立追踪 |
| **人工可修改自动结果** | 审核员有权直接修改自动生成的 NC 结论或报告内容 | 需要 `auto_result` + `manual_result` 双轨设计 |
| **审计追溯要求** | 系统必须证明"结论是如何来的"，NC 可追踪、报告可审计 | 完整的节点执行日志 + 翻译视图 |
| **报告需人工认可** | 最终交付的报告必须经过审核员确认 | 需要 `is_approved` 标记 |

### 0.2 三层任务模型的设计动机

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         三层任务模型（Why）                              │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  业务场景：某企业 ISO 9001 第一阶段审核                                   │
│                                                                         │
│  Task（任务）：对该企业执行 ISO 9001 第一阶段的完整检查                   │
│     │                                                                   │
│     ├── TaskItem（执行项-1）：NC 检查项 A（质量方针审查）                 │
│     │       └── 独立执行，独立失败不影响其他项                            │
│     │                                                                   │
│     ├── TaskItem（执行项-2）：NC 检查项 B（目标分解审查）                 │
│     │       └── 可并行执行                                               │
│     │                                                                   │
│     ├── TaskItem（执行项-3）：NC 检查项 C（管理评审审查）                 │
│     │       └── 失败可单独重试                                           │
│     │                                                                   │
│     └── TaskItem（执行项-N）：报告第 N 章生成                             │
│             └── 章节内容独立生成                                         │
│                                                                         │
│  关键决策：                                                              │
│  1. 为什么需要 TaskItem？                                                │
│     - 不同 NC 检查项是可以并行执行的，互不依赖                            │
│     - 某一项失败不能阻塞全部，需要独立重试                                │
│     - 每一项都是独立的结果单元（一条 NC 记录 / 一章报告）                  │
│                                                                         │
│  2. 为什么需要 wf_item_result？                                          │
│     - auto_result 保留自动生成内容（可追溯）                              │
│     - manual_result 允许人工修改（业务需要）                              │
│     - is_modified 标记哪些被改过（审计用）                                │
│     - is_approved 确认最终结论（质量控制）                                │
│                                                                         │
│  3. 为什么需要 wf_node_execution_translated？                            │
│     - wf_execution_log 是程序级日志，审核员看不懂                         │
│     - 需要翻译成"引用了什么资源、做了什么操作、得到了什么结果"             │
│     - 按维度存储（resource/operation/result），支持灵活展示               │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 0.3 关联设计原则

| 原则 | 说明 | 示例 |
|---|---|---|
| **Code 核心** | 每张表用 `code`（GUID）作为业务主键 | `wf_execution_task.code` |
| **Code 关联** | 子表关联父表只存 `xxx_code`，不冗余其他字段 | `task_item.task_code`，不存 `enterprise_code` |
| **无冗余** | 可通过 JOIN 获取的信息不重复存储 | `wf_node_output` 不存 `org_code` |
| **视图补充** | 关联查询通过 VIEW 封装 | `vw_execution_task_item` 补充 `task_type` |
| **快照隔离** | 节点标识字段从配置中快照，避免配置变更影响历史追溯 | `node_title`, `skill_name` |

### 1.3 模块职责与接口定义

```csharp
namespace YZH.Core.Workflow
{
    /// <summary>
    /// 入口：创建执行任务（TEST / NC_CHECK / REPORT_GENERATE）
    /// 对外：唯一创建执行上下文的入口
    /// </summary>
    public interface IExecutionTaskManager
    {
        /// <summary>创建执行任务</summary>
        Task<ExecutionTask> CreateAsync(CreateTaskRequest req);
        /// <summary>查询任务状态</summary>
        Task<ExecutionTask> GetByCodeAsync(string taskCode);
        /// <summary>取消任务</summary>
        Task<bool> CancelAsync(string taskCode, string reason);
    }

    /// <summary>
    /// 入口：创建执行项（NC 单项 / 报告章节）
    /// </summary>
    public interface IExecutionTaskItemManager
    {
        /// <summary>批量创建执行项</summary>
        Task<IReadOnlyList<ExecutionTaskItem>> CreateItemsAsync(string taskCode, IReadOnlyList<CreateItemRequest> reqs);
        /// <summary>获取任务下的执行项</summary>
        Task<IReadOnlyList<ExecutionTaskItem>> GetByTaskAsync(string taskCode);
    }

    /// <summary>
    /// 入口：拓扑排序，输出确定性的节点执行顺序
    /// 输入：workflow_config JSON  输出：nodeId[] 执行序列
    /// </summary>
    public interface ITopologyAnalyzer
    {
        IReadOnlyList<string> TopoSort(WorkflowConfig config);
        bool HasCycles(WorkflowConfig config, out List<string> cycle);
        IReadOnlyList<PathSegment> GetAllPaths(WorkflowConfig config);
    }

    /// <summary>
    /// 入口：按拓扑序执行节点，串联 Skill 调用与输出传递
    /// 输入：workflow_config + 执行上下文   输出：最终结果 + 执行日志
    /// </summary>
    public interface IWorkflowInterpreter
    {
        Task<WorkflowRunResult> RunAsync(string config, ExecutionTask task, CancellationToken ct);
    }

    /// <summary>
    /// 入口：队列驱动（节点级串行），解耦"执行卡"与"结果获取"
    /// 对接：YzhQueueManager（已有）/ IYzhTaskExecutor（已有）
    /// </summary>
    public interface IQueueDrivenExecutor
    {
        /// <summary>将工作流任务入队（yzh_queue）</summary>
        Task<string> EnqueueAsync(ExecutionTask task);
        /// <summary>队列消费回调（HostedService 触发）</summary>
        Task<TaskExecuteResult> ExecuteTaskAsync(YzhQueueTask queueTask);
    }

    /// <summary>
    /// 入口：AI 节点专用执行器（封装 LLM 调用、提示词组装）
    /// </summary>
    public interface IAiNodeExecutor
    {
        Task<AiNodeResult> ExecuteAsync(AiNodeContext ctx);
    }

    /// <summary>
    /// 入口：节点输出持久化（供下游/AI 消费）
    /// </summary>
    public interface INodeOutputStore
    {
        Task SaveOutputAsync(string taskCode, string taskItemCode, string nodeId, string portName, object value);
        Task<T> GetOutputAsync<T>(string taskCode, string taskItemCode, string nodeId, string portName);
        Task<IDictionary<string, object>> GetAllOutputsAsync(string taskCode, string taskItemCode, string nodeId);
    }

    /// <summary>
    /// 入口：业务结果存储（NC/报告产出物，支持人工修改）
    /// </summary>
    public interface IItemResultStore
    {
        Task SaveAutoResultAsync(string taskCode, string taskItemCode, ItemResult result);
        Task UpdateManualResultAsync(string itemResultCode, string userId, string userName, string manualContent);
        Task ApproveAsync(string itemResultCode, string userId, string userName, string remark);
        Task<ItemResult> GetLatestAsync(string taskCode, string itemCode);
    }

    /// <summary>
    /// 入口：执行日志查询（按任务聚合）
    /// </summary>
    public interface IExecutionLogQuery
    {
        Task<IReadOnlyList<ExecutionLogEntry>> GetByTaskAsync(string taskCode);
        Task<IReadOnlyList<ExecutionLogEntry>> GetByNodeAsync(string taskCode, string nodeId);
        Task<ExecutionTrace> GetTraceAsync(string taskCode);
        /// <summary>获取翻译后的业务日志</summary>
        Task<IReadOnlyList<TranslatedLogEntry>> GetTranslatedLogAsync(string taskCode, string taskItemCode);
    }

    /// <summary>
    /// 入口：翻译日志写入
    /// </summary>
    public interface ITranslatedLogWriter
    {
        Task WriteAsync(TranslatedLogEntry entry);
        Task WriteBatchAsync(IReadOnlyList<TranslatedLogEntry> entries);
    }

    /// <summary>
    /// 入口：Hub 推送实时执行事件
    /// </summary>
    public interface IWorkflowNotifier
    {
        Task NotifyNodeStarted(string taskCode, string nodeId);
        Task NotifyNodeCompleted(string taskCode, string nodeId, bool success, object output);
        Task NotifyTaskItemStarted(string taskCode, string taskItemCode);
        Task NotifyTaskItemCompleted(string taskCode, string taskItemCode, bool success, object result);
        Task NotifyTaskCompleted(string taskCode, bool success, object result);
    }
}
```

## 二、核心数据结构（五表体系）

### 2.0 表关系全景

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         存储层全景（5 表 + 3 视图）                       │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  wf_execution_task (顶层：任务上下文)                                     │
│       │ code                                                             │
│       ├───→ wf_execution_task_item (中层：执行项，支持并行)               │
│       │         │ code                                                   │
│       │         ├───→ wf_node_output (底层：节点输出)                     │
│       │         │                                                        │
│       │         └───→ wf_item_result (底层：业务结果)                     │
│       │                                                                  │
│       ├───→ wf_node_output (顶层节点，如汇聚)                             │
│       │                                                                  │
│       └───→ wf_node_execution_translated (底层：翻译日志)                │
│                                                                          │
│  视图（按需创建）：                                                       │

│                                                                          │
```

### 2.1 执行任务表 wf_execution_task

> **定位**：所有执行（测试/NC检查/报告生成）的上下文隔离单元。
> **关键字段**：`code` 业务主键，`config_snapshot` 防止配置变更影响执行中任务。

```sql
DROP TABLE IF EXISTS wf_execution_task;
CREATE TABLE wf_execution_task (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    code            VARCHAR(36) NOT NULL UNIQUE COMMENT '任务编码(GUID)',
    task_type       VARCHAR(20) NOT NULL COMMENT 'TEST | NC_CHECK | REPORT_GENERATE',
    task_status     VARCHAR(20) NOT NULL DEFAULT 'running' 
                    COMMENT 'running | completed | failed | cancelled',
    
    -- 执行上下文（JSON 快照，确保执行期间配置不变）
    config_snapshot JSON NOT NULL COMMENT '执行时的工作流配置快照',
    
    -- 关联业务（NC 规则 / 章节 / 企业）
    rule_code       VARCHAR(64) COMMENT 'cert_validation_rule.code',
    section_code    VARCHAR(64) COMMENT 'rpt_report_section.code',
    enterprise_code VARCHAR(50) COMMENT 'cert_application.enterprise_code',
    phase_code      VARCHAR(30) COMMENT '审核阶段',
    
    -- 关联队列（驱动执行）
    queue_code      VARCHAR(64) COMMENT 'yzh_queue.code',
    
    -- 结果摘要
    result_summary  JSON COMMENT '执行结果摘要(end 输出)',
    error_message   VARCHAR(2000) COMMENT '失败原因',
    
    -- 执行时间
    started_at      DATETIME NOT NULL,
    completed_at    DATETIME,
    duration_ms     INT COMMENT '执行耗时(ms)',
    
    -- 审计
    org_code        VARCHAR(50) COMMENT '机构编码',
    user_id         INT COMMENT '发起用户ID',
    user_name       VARCHAR(100) COMMENT '发起用户名',
    create_date     DATETIME DEFAULT CURRENT_TIMESTAMP,
    
    INDEX idx_type_status (task_type, task_status),
    INDEX idx_rule (rule_code),
    INDEX idx_enterprise (enterprise_code),
    INDEX idx_phase (phase_code),
    INDEX idx_queue (queue_code),
    INDEX idx_org_status (org_code, task_status)
) ENGINE=InnoDB COMMENT='工作流执行任务（TEST/NC_CHECK/REPORT_GENERATE）';
```

### 2.2 执行项表 wf_execution_task_item

> **定位**：一个任务下的独立执行单元（NC 单项检查 / 报告单个章节），支持并行执行、独立失败隔离。
> **为什么需要**：不同 NC 检查项可并行执行，某一项失败不能阻塞全部，需要独立重试。

```sql
DROP TABLE IF EXISTS wf_execution_task_item;
CREATE TABLE wf_execution_task_item (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    code            VARCHAR(36) NOT NULL UNIQUE COMMENT '执行项编码(GUID)',
    task_code       VARCHAR(36) NOT NULL COMMENT 'wf_execution_task.code',
    
    item_type       VARCHAR(30) NOT NULL COMMENT 'NC_ITEM | REPORT_SECTION',
    item_status     VARCHAR(30) NOT NULL DEFAULT 'pending' 
                    COMMENT 'pending | running | completed | failed',
    
    -- 业务项关联（纯 code 关联，不冗余其他字段）
    rule_item_code  VARCHAR(64) COMMENT 'cert_validation_rule_item.code(NC检查项)',
    section_item_code VARCHAR(64) COMMENT 'rpt_report_section.code(报告章节)',
    
    -- 队列（每项独立队列，支持并行）
    queue_code      VARCHAR(64) COMMENT 'yzh_queue.code',
    
    -- 执行路径（JSON 节点 ID 列表，当前项需执行的拓扑顺序）
    execution_path  JSON COMMENT '当前执行项的拓扑节点顺序',
    
    -- 结果
    result_summary  JSON COMMENT '执行项结果摘要',
    error_message   VARCHAR(2000),
    
    -- 执行时间
    started_at      DATETIME,
    completed_at    DATETIME,
    duration_ms     INT COMMENT '执行耗时(ms)',
    
    create_date     DATETIME DEFAULT CURRENT_TIMESTAMP,
    
    UNIQUE uk_task_item (task_code, item_type, rule_item_code, section_item_code),
    INDEX idx_task_status (task_code, item_status),
    INDEX idx_rule_item (rule_item_code),
    INDEX idx_queue (queue_code)
) ENGINE=InnoDB COMMENT='工作流执行项(NC单项/报告章节，可并行隔离)';
```

### 2.3 节点输出表 wf_node_output

> **定位**：每个节点的输出落库，供下游节点 / AI 节点调试 / UI 回查消费。
> **关联原则**：三层纯 code 关联（task → task_item → node），不冗余 enterprise_code / org_code 等可通过 task 关联的字段。
> **唯一约束**：`(task_code, task_item_code, node_id, port_name)` 确保同一任务同一节点同一端口只有一条输出。

```sql
DROP TABLE IF EXISTS wf_node_output;
CREATE TABLE wf_node_output (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    code            VARCHAR(36) NOT NULL UNIQUE COMMENT '输出编码(GUID)',
    
    -- 三层关联（纯 code，无冗余）
    task_code       VARCHAR(36) NOT NULL COMMENT 'wf_execution_task.code',
    task_item_code  VARCHAR(36) COMMENT 'wf_execution_task_item.code(NC/报告项才有)',
    
    -- 节点标识（快照，避免配置变更影响历史追溯）
    node_id         VARCHAR(64) NOT NULL COMMENT '节点拓扑ID',
    node_type       VARCHAR(30) NOT NULL COMMENT 'start/skill/ai_node/logic/loop/end',
    node_title      VARCHAR(128) COMMENT '节点显示名(快照)',
    
    -- Skill 关联
    skill_code      VARCHAR(64) COMMENT 'wf_skill.code(功能节点)',
    skill_name      VARCHAR(128) COMMENT 'Skill显示名(快照)',
    
    -- 输出端口
    port_name       VARCHAR(64) NOT NULL COMMENT '端口名(success/error/result)',
    data_type       VARCHAR(20) NOT NULL COMMENT 'string/number/boolean/json/table',
    
    -- 输出值（二选一）
    text_value      TEXT COMMENT '文本值(小尺寸)',
    json_value      JSON COMMENT '结构化值(大尺寸)',
    
    -- 执行信息
    execution_time_ms INT COMMENT '节点执行耗时(ms)',
    error_message   VARCHAR(1000) COMMENT '执行错误',
    
    create_date     DATETIME DEFAULT CURRENT_TIMESTAMP,
    
    -- 唯一约束：同一 task + task_item + node + port 只有一个输出
    UNIQUE uk_output (task_code, task_item_code, node_id, port_name),
    INDEX idx_task_node (task_code, task_item_code, node_id),
    INDEX idx_skill (skill_code)
) ENGINE=InnoDB COMMENT='节点输出(按任务+执行项隔离)';
```

### 2.4 业务结果表 wf_item_result

> **定位**：NC / 报告的最终产出物，支持人工修改（覆盖自动生成内容）和人工认可（确认最终结论）。
> **核心设计**：
> - `auto_result`：工作流自动生成（不可覆盖，保留原始证据）
> - `manual_result`：人工修改后的内容（用户可覆盖）
> - `is_modified`：标记哪些结果被改过（审计用）
> - `is_approved`：确认最终结论（质量控制）
> - `version`：版本号，每次修改 +1

```sql
DROP TABLE IF EXISTS wf_item_result;
CREATE TABLE wf_item_result (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
```

## 五、队列驱动执行引擎（核心）

### 5.1 设计动机

| 问题 | 同步执行 | 队列驱动 |
|---|---|---|
| 超时控制 | HTTP 超时（60s），长工作流易卡死 | 队列任务租约，自然超时回收 |
| 失败重试 | 手动/全量 | 单节点级重试（Retryable 分类） |
| 并发控制 | 无 | 信号量（SemaphoreSlim）限制背压 |
| 中断恢复 | 不支持 | 已执行节点输出落库，后续续跑 |
| 进度感知 | 无 | SignalR 实时推送节点状态 |
| 日志聚合 | workflow_instance_id 虚关联 | taskCode 强关联 |

### 5.3 节点级入队策略

```csharp
// IYzhTaskExecutor 实现 - 节点级
public class WorkflowNodeExecutor : IYzhTaskExecutor
{
    public string TaskType => "WF_NODE_EXEC";

    public async Task<TaskExecuteResult> ExecuteTaskAsync(YzhQueueTask queueTask)
    {
        var payload = JsonSerializer.Deserialize<NodeExecPayload>(queueTask.Payload);
        var task = await taskMgr.GetByCodeAsync(payload.TaskCode);
        
        // 查找待执行节点
        var targetNode = task.Config.FindNode(payload.NodeId);
        
        // 获取该节点输入（从 wf_node_output 读）
        var inputs = await outputStore.ResolveInputsAsync(
            task.Code, 
            payload.TaskItemCode,
            targetNode.Inputs, 
            task.WorkflowInputs);
        
        // 执行单节点
        var result = await skillExecutor.ExecuteSkill(
            targetNode.SkillCode,
            new SkillContext(inputs, task.Code, payload.TaskItemCode, payload.NodeId));
        
        // 落输出 + 写翻译日志
        await outputStore.SaveOutputsAsync(task.Code, payload.TaskItemCode, payload.NodeId, result.Outputs);
        await translatedLogWriter.WriteAsync(task.Code, payload.TaskItemCode, payload.NodeId, result);
        
        // 推送事件
        await notifier.NotifyNodeCompleted(task.Code, payload.NodeId, result.Success, result.Outputs);
        
        // 判断下一个节点（按拓扑 + 已执行节点）
        var nextNode = topology.GetNextExecutable(task.Config, payload.NodeId);
        
        if (nextNode == null)
        {
            // 当前 item 执行完成 → 写 wf_item_result
            var itemResult = aggregateResult(task, payload.TaskItemCode);
            await itemResultStore.SaveAsync(itemResult);
            return new TaskExecuteResult { IsCompleted = true, NextTaskType = "WF_END" };
        }
        
        // 返回下一个节点任务入队信息
        return new TaskExecuteResult 
        { 
            IsCompleted = false,
            NextTaskType = "WF_NODE_EXEC",
            NextPayload = JsonSerializer.Serialize(new NodeExecPayload 
            { 
                TaskCode = task.Code, 
                TaskItemCode = payload.TaskItemCode,
                NodeId = nextNode.NodeId 
            })
        };
    }
}
```

### 5.4 队列与现有 YzhQueueManager 对接

**现有能力复用**（`YzhQueueManager` / `YzhQueueTask`）：

| 现有机制 | 引擎使用方式 |
|---|---|
| 资源锁（resource_lock） | wf_execution_task 行级锁 + 并发队列隔离 |
| Semaphore 并发控制 | 限制同时执行的 NC 检查/报告数（系统参数可配置） |
| 租约 + 超时回收 | 长时间未完成的节点任务自动释放 |
| 指数退避重试 | AI 节点调用失败重试（3 次） |
| 取消 / 整队重跑 | 用户取消工作流执行 |

**引擎新增任务类型**：

