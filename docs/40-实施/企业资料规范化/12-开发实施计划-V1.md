## 3. 通用工程纪律与完成定义

**每个任务完成（DoD）必须全过：**

```bash
# ① 后端编译（sln 在仓库根）
dotnet build CertPlatform.sln -v q --nologo 2>&1 | grep -E " error |Build succeeded" | sort -u
# ② 改了后端 → 重启
./scripts/backend/restart-backend.sh
# ③ 前端守卫（含 R12 路由↔菜单）
cd src/certplatform-web && node scripts/guards.mjs
# ④ 动了路由/菜单 → 刷新快照
./scripts/db/verify/sync_menu_urls.sh
# ⑤ 前端类型 + 构建
npm run typecheck --workspace=@certplatform/admin && npm run build --workspace=@certplatform/admin
# ⑥ 动了 DB → 02 §8.2 验证 SQL（CONVERT+COLLATE 防假阴性口径）
```

**编码铁律（本模块高频踩坑点）：**

- 页面照抄 `pages/system/user/`（单表）/ `foundation/iso-standard`（左树右表，**只抄 logic.ts 的 dataLoader**）；⛔ 手写 handleAdd/Submit、view-grid/Vol*/axios/直接 fetch
- 后端按职能选基类：单表 `YzhControllerBase<T>`、树 `TreeTableControllerBase<T,V>`、动作型 `ControllerBase`（写明理由）
- **PascalCase 三处一致**（DB 列 = C# 属性 = TS 字段），写错渲染空行无报错
- 双关键字准则 A：定位/删除/更新/关联只用 `Code`；新增 vs 更新 = `GetByCode`/业务键分流
- 前端写操作一律 `expectOk(res, '…失败')`（F-2 失败必 throw），业务失败 = HTTP 200 + `success:false`
- **回写纪律**：状态回写用列白名单指定列更新，⛔ `UpdateAsync(整实体)`（MarkdownPath 事故教训）
- 新表：`utf8mb4` + 显式 `COLLATE=utf8mb4_general_ci`、`uk_code`、无 `Enable`、`StageCode`
- 改端点/动作名 = ApiCode 变 → 必重跑 ApiSync + 角色重关联（AGENTS.md ②）
- 长耗时一律入队，同步接口只做入队与查询

- **决策 P1–P6**：状态与关闭方式以 10 分册 §7 为准；本计划第 1.1 节给出的默认值即当前采用值，拍板改默认时同步改 10 分册。
