## 二、锚点模型逐条对照（vs 用户 2026-10-09 规格）

### 2.1 word / excel 区分

- **实现**：模板级区分（`cert_doc_template.FileKind` = docx/xlsx）。扫描分别走 `WordDocumentScanner.ScanAnchors` / `ExcelSheetScanner.ScanAnchors`，落库 `AnchorKind = token`（Word）/ `range`（Excel）。
- **评**：一个模板 = 一个文件，锚点无需逐条再标文件类型，设计成立。✅

### 2.2 字段 / 表格区分（表格数据 = JSON）

- **实现**：`AnchorClassifier` 按 token 内容判型：`{{table:xxx}}`→table、`{{ai:xxx}}`→block、`@PAGE`→domain(auto)、其余→scalar；`table_total` 刻意不猜，由人工在页面改。表格数据形态 = `OfficeFillRegion.Rows`（行×列二维 `FillValue`），列定义走 `ColumnsJson`。
- **评**：判型口径符合「规则必须正确，没有想当然」。但**表格锚点的生产落笔缺位**（G1）。

### 2.3 锚点针对字段

**Word（能取到哪些信息、如何填充）**

- 扫描产出：token 原文、判型、FieldCode、DomainKind、位置（正文·第 N 段 / 表格[R] 行 x 列 y / 页眉[I]，2026-10-05 起带行列号）、Context 片段。位置**仅供人确认、不落库**。
- 填充：跨 run 归一后替换 `{{token}}`，覆盖正文 / 表格格 / 页眉（页脚刻意不做，`WordFillWriter`）。
- ⚠️ 限制：同名 token 全文去重成**一条规则**（`uk_tpl_anchor` 口径 = AnchorKind+AnchorRef），正文与页眉同 token 只能同源同值，**不能按位置配不同来源**。→ 待裁 D3。

**Excel（坐标 / 替换 vs 覆盖）**

- **能取到逐格坐标**：`Sheet1!B3`（`CellReference`）。
- 用户场景「一个 cell 是一句话 xxx{{}}xxx」已精确实现：`WRITE_MODES` 把「覆盖（overwrite，整格换掉）」与「填充（replace，只换格内 token 其余保留）」做成用户显式选项；层 1 只认该字段、**绝不推断**；「覆盖」仅在格内恰好 1 个锚点时成立，多锚点退回填充并记待办（`FillValue.WriteMode` 注释）。✅

**分析取不到信息时手动补 row/col**

- 引擎侧有对应能力：`OfficeRegionKind.WordCell` = 人工指定 表格序号+行+列，越界必报不静默。
- ⚠️ **配置 UI 无入口**：抽屉 ③ 段只有 WriteMode/ValueType/NumberFormat/DefaultText/Required/FieldCode/Remark，没有 row/col/sheet 输入；通用「新增」可裸填 AnchorRef 插一行，但无结构化坐标表单。→ 缺口 G5。

### 2.4 锚点是表格

**Word**

- 设计：`{{table:Tag}}` 标签定位 + 行数数据驱动（不足克隆末行、多余写空串不删）。
- ⚠️ 书签 `ROW_xxx` **扫不出来**（NPOI 2.7.2 未暴露 bookmarkStart + 无真实模板样本，刻意先不做，`WordDocumentScanner` 注释）。

**Excel**

- 用户规格 = 起始坐标 + 结束坐标；**引擎实际 = 起始坐标 + 数据行数**（结束坐标由数据决定）。评：现设计更贴合数据驱动填表 → 待裁 D1（认可现设计 or 按原规格补结束坐标）。
- ⚠️ 规则页**没有配置起始行/列/工作表的 UI**；连续矩形数据区推断刻意未做（`ExcelSheetScanner` 注释：无样本时写启发式「风险高于收益」）。→ 并入 G5。

## 四、全局填写规则（多 AI 节点一次性执行）—— 核心缺口

用户规格：按 AI 节点生成一次性提示词 → 一次执行多个分散 AI 节点 → 得到每个节点内容 → 统一调用各节点填写规则落笔。

**已实现**：`ResolveAiAnchorsAsync` 把全模板 AI 锚点分组（当前 UI 无分组字段 ⇒ 实际恒一组 = 一次文档一次调用），逐锚点渲染「参数+提示词」成 Instruction，交 `AiFillPromptBuilder.BuildBatchAsync` 一次性装配（输出 schema 含 semantic/fields/tables 三段）。

**四个实测缺口（按严重度）**：

| # | 缺口 | 证据 | 后果 |
|---|---|---|---|
| G1 | **生产链表格锚点不落笔**：`OfficeFillRequest.Regions` 恒空；试填注释明写「与正式链逐字一致（正式链同样只产 Values）」；表格区域填充目前只在 Skill 链（`FillTableSkill`）存在 | 编排器 `FillPreviewAsync` L779-782 | `{{table:xxx}}` / table 型锚点在「一键规范化」产物里不会成表；且 `AnchorKeyOf` 对 `table:items` 被 `SplitFormat` 拆成 key=`table`，**所有表格锚点撞同一个键** |

## 五、实现亮点（超出规格的部分）

1. **自验收双保险**：写入后独立复扫残留 token（`LeftoverTokens` 与 `Pendings` 互为冗余校验），不一致即判 partial，不谎报成功。
2. **合规铁律**：`SampleData=1` 锚点无条件清空（实测模板含上一家企业 160+ 处真实姓名日期）。
3. **锚点锁 / 孤儿 / 换版复活**：`IsLocked` 冻结配置、重扫保留、消失锚点标 `IsOrphan` 不删。
4. **发布闸**：validate 红牌/黄牌 + `anchorReadiness` 四条件（已上传/已扫描/≥1 锚点/无未配无孤儿）作为自动填充与预览统一门槛；预览走「自动试填 → 人工改值 → Overrides 重跑」。
5. **测试覆盖扎实**：`sourceSpec.test.ts`（726 行）、`AiFillEndToEndTests`、`WordFillWriterTests`、`ExcelFillWriterTests` 等；历史三类静默失效（AI 认领顺序、WriteMode 不传、Section 判旧值）均已修复并留防回归注释。
