### 设计决策

| # | 决策 | 理由 |
| --- | --- | --- |
| **D1** | `CoreResourceQuery` **留在** `Shared/Domain/Scope/`，⛔ 不移动 namespace | 移动会改 **20+ 消费方**的 `using`；收益（目录美观）远小于风险。后续可整体归并 |

### 2.1 `OrgStageStandardNode`（统一内部契约）

```csharp
/// <summary>「机构 → 标准 → 阶段」树的唯一内部表示（⛔ 不是对外 DTO）</summary>
public sealed class OrgStageStandardNode
{
    public string Code { get; set; }              // 节点唯一 Code
    public string Name { get; set; }              // 显示名
    public string? ParentCode { get; set; }       // 父节点 Code（用于上溯装配）
    public OrgNodeKind Kind { get; set; }         // Org | Standard | Stage | Folder | File
    public int Sort { get; set; }                 // 排序主键
    public int VersionYear { get; set; }          // 排序兜底 ①（标准节点）
    public string? StandardCode { get; set; }     // 排序兜底 ② + 关联键
    public List<OrgStageStandardNode> Children { get; } = new();
    public Dictionary<string, object?> Extra { get; } = new();  // 派生列（各端点投影取用）
}
```

> **为什么用 `Extra` 而不是强类型字段**：各端点对外字段差异极大
> （T1 要 `configCode` / `phaseDefinitionCode`；T4 要 `FileCount` / `AnalyzingCount`；
> T5 要 `FillCompletion` / `InstanceState`）。强类型会造出 40+ 字段的"万能类"，
> 且每加一个端点就要改契约。`Extra` 让**契约稳定、投影自由**。

## 四 排序口径裁决结果（2026-10-13 已批）

> 用户原话：「**a 和 b 都是排序问题，按你的建议执行即可**」⇒ 两条均按设计建议执行。

| # | 问题 | **裁决** | 行为影响（须登记） |
| --- | --- | --- | --- |
| **A** | 企业排序主键 | **统一 `Sort → EnterpriseNo`**（`Sort` 是显式排序字段，管理员可控制；`Name` 对中文是按字符编码序，非拼音） | T4（原始资料页）企业顺序**变化** |
| **B** | 标准 `VersionYear` 方向 | **统一降序（新版在前）**（用户视角下新版标准更相关） | T4（原始资料页）标准顺序**变化** |

**白话说明（存档）**：

- **A**：两个页面显示**同一批企业**，原先一个按「排序号」排、一个按「名字」排。按名字排对中文不友好
  （实际按字符编码，不是拼音）。统一成「排序号」更可控。
- **B**：同一批标准，原先一个页面把旧版排前面、另一个把新版排前面。统一为**新版在前**。

> ⚠️ **两条都必然改变某一端的输出顺序** ⇒ 与出口判据「逐字段一致」冲突。
> **处置（已定）**：diff 脚本对**数组顺序**单列一项比对 —— 差异**仅**来自 A/B 两条
> ⇒ 登记为「有意修正」并留档；若差异来自**其他**原因 ⇒ 视为 bug，退回 1.B.6。

### 4.1 排序收敛策略（避免无谓的行为变更）

> ★ **原则**：**原有排序 ⇒ 替换为统一口径；原无排序 ⇒ 保持无排序**（⛔ 不新增）。

| 情形 | 处置 | 理由 |
| --- | --- | --- |
| 端点**本来就有**排序链，且口径与 §2.2 冲突 | **替换**为 `OrgStandardTreeAssembler.OrderXxx` | 这正是要消灭的分裂（A/B） |
| 端点**本来就有**排序链，口径已一致 | **替换**（等价改写） | 让「排序口径」只有一处实现 |
| 端点**本来没有**排序 | **保持没有**（⛔ 不加排序） | 加排序 = 改变输出顺序 = 无谓的行为变更 |

**实测落地**（1.B.6a · T1）：

- `phaseDefs` 原 `.OrderBy(Sort).ThenBy(StageCode)` ⇒ 改 `OrderStages(...)`（**等价**，无差异）；
- `linkedStandards` 原**无排序** ⇒ **保持无排序**（⛔ 不加 `OrderStandards`）；
- `orgs` 原**无排序** ⇒ **保持无排序**（⛔ 不加 `OrderOrgs`）。

⇒ **T1/T2 的响应逐字段 + 顺序完全一致**（无 A/B 差异）。
