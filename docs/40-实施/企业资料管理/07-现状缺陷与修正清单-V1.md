## 二、逐条详述

### B1 模板行查询条件错误 🔴

- **证据**：`EnterpriseFileService.FileCheckAsync` 第 80 行：
  `x => x.EnterpriseCode == "YZH-STD-ENT" && x.StageCode == stageCode && x.IsValid == 1`
- **实测**：`cert_standard_directory_config` 共 5 行，`EnterpriseCode` **全部为 NULL**（无一行等于 `'YZH-STD-ENT'`）⇒ 查询**必然 0 行**。
- **影响**：`FileCheck` 恒返回 `{standards: [], summary: 全 0}` ⇒ 页面"文件检查/缺失清单"永远为空；`GetPendingFilesAsync` 同理恒空。
- **修正**：统一谓词 `(EnterpriseCode == null || EnterpriseCode == YZH_STANDARD_ENTERPRISE_CODE)`；常量引用 `CertPlatformConstants`，禁止硬编码字符串。
- **验收**：02 §八 验证 SQL ① 返回 1；页面"就位检查"出现 167 项应上传。

### B2 队列任务类型错误 🔴

- **证据**：`EnterpriseFileService.ConfirmUploadAsync` 第 227 行：`new() { TaskType = "convert", Payload = … }`
- **实测**：`OfficeConvertTaskExecutor.TaskType => "file_convert"`（`IYzhTaskExecutor` 按 TaskType 匹配）⇒ `"convert"` **无执行器接管**。
- **影响**：任务永远停在 `pending` ⇒ `ConvertStatus` 永不更新 ⇒ 文件永远"转换中"，无 PDF/Markdown 产物。
- **修正**：统一 `TaskType = "file_convert"`。
- **验收**：Step3 后 `yzh_queue_task` 2 条/文件，`Status` 由 `pending→completed`。

### B3 队列载荷字段名不匹配 🔴

- **证据**：第 227 行载荷 `JsonSerializer.Serialize(new { fileCode, enterpriseCode, stageCode })`；执行器反序列化目标 `FileConvertPayload { Code, FileName, SourcePath, ConvertType }`（大小写不敏感但**名字也不同**）。
- **影响**：即使 B2 修好，`Code/FileName/SourcePath/ConvertType` 全空 ⇒ `DownloadSourceAsync` 取不到源 ⇒ 转换必失败。
- **修正**：与标准侧同款 `BuildConvertPayloads(f)`：每文件两条（`office2pdf` + `anydoc2md`），字段 `Code/FileName/SourcePath/ConvertType`。
- **验收**：产物 `PreviewPdfPath` / `MarkdownPath` 有值；MinIO 出现 `…/pdf/…pdf`、`…/markdown/…md`。

### B4 `trigger-extract` 硬编码假成功 🟠

- **证据**：`TriggerExtractAsync` 第 304-306 行：
  `file.ExtractStatus = "completed"; file.MaxConfidence = 0.95m;`（**无任何提取动作**）；`GetExtractionResultAsync` 第 316 行返回 `Fields = new object[0], Tables = new object[0]`。
- **影响**：页面会显示"提取完成/置信度 0.95"，纯造假；下游若据此判断将误判。
- **修正**：按 README **D10** —— 本模块**删除这两个端点**（或保留端点但返回 `ApiResponse.Fail("下游功能未实现")`），同步移除前端"提取结果抽屉"与 `logic.ts` 中相关方法。
- **验收**：代码内不再出现硬编码 `0.95`；页面无"提取"入口。

### B5 无下载/预览端点 🟠

- **证据**：`EnterpriseFileController` 10 个端点中无 `download` / `file-preview` / `file-markdown`。
- **影响**：上传成功后无法查看内容（企业资料是"给人看/给 NC 用"的，不可见等于不可用）。
- **修正**：新增三端点；校验统一 `DocumentLibraryPath.IsAllowedStoragePath`（**已含 `enterprise-documents/`**，无需改白名单）。
- **验收**：`/enterprise-documents/…` 路径可下载；`/etc/passwd` 之类被拒。

### B6 无多标准分发 🔴（需求 3 未实现）

- **证据**：全部现存逻辑都是"单文件/单标准"；`SuggestMappingsAsync` 只做 `FileName` 等值或 `Contains(FilePattern)`，而 `FilePattern` **实测 167/167 全为 NULL** ⇒ 实际恒不命中。
- **影响**：无法"一次上传 → 按标准分别归档"，更无法防止"非本标准文件被塞进所有标准"。
- **修正**：新增 `DispatchMatcher` + `upload/plan` + 分发提交（04 §四；06 T3.1–T3.7）。
- **验收**：混合文件夹样本 → 各标准仅收己方文件；未归属清单正确。

### B7 前端上传未接四段式 🔴

- **证据**：`resources/logic.ts` 第 210 行 `// TODO: 接入四段式上传（presign → upload → confirm → queue）`；`index.vue` 第 239 行"批量上传"的 `[确认上传]` 直接 `closeUploadDialog()`（**无任何请求**）；第 206-215 行 `confirmSingleUpload` 只弹 `ElMessage.success`。
- **影响**：三个上传入口全部无效（假成功提示）。
- **修正**：按 01 §四 / 04 §一 重写三个入口 + 分发预览弹窗。
- **验收**：上传后 DB 出现行、MinIO 出现对象、队列执行成功。

### B8 企业行 `Code` 字符串拼接 🟠

- **证据**：`FileCheckAsync` 第 88/105 行：`Code = $"{enterpriseCode[..8]}-{stageCode[..8]}-cfg"`、`Code = $"{enterpriseCode[..8]}-{tf.Code[..8]}"`。
- **影响**：① 违反双关键字准则 A（Code 应为唯一业务键，非可推导拼接）② 前 8 位相同即**碰撞**（GUID 前 8 位碰撞概率虽低但非零，且同一企业+同一阶段第一标准与第二标准会撞）；③ 与 `uk_code` 冲突直接 1062。
- **修正**：一律 `Guid.NewGuid().ToString()`（36 位）；禁拼接。
- **验收**：全库 `cert_standard_directory_file.Code` 均 36 位且唯一（`SELECT COUNT(*), COUNT(DISTINCT Code) …` 相等）。

### B9 前端目标文件夹硬编码 🟡

- **证据**：`resources/index.vue` 第 258-266 行：`<el-option label="1质量手册" value="1质量手册" />` 等 4 项写死。
- **影响**：与模板真实结构（含 `3制度文件（可根据企业实际修改）`、三级文件夹）不一致 ⇒ 用户无法把文件放进真实文件夹。
- **修正**：下拉数据源改为 `standard-directory` 返回的 `Folders`（按 `Depth/SortOrder` 缩进）。
- **验收**：下拉出现 11 个文件夹（含三级）。

### B10 `file-list` / `pending-list` 语义含混 🟡

- **证据**：`GetPendingFilesAsync` 第 38-59 行：以 `f.IsRequired && (IsNullOrEmpty(f.EnterpriseCode) || f.ConvertStatus == null)` 当"待上传"，且把 `EnterpriseCode` 与 `ConvertStatus` 混为一谈；`GetFileListAsync` 只按 `EnterpriseCode` 过滤，**未按 `StageCode`/`StandardCode`**。
- **影响**：跨阶段、跨标准串数据；"缺失"与"待上传"概念混淆。
- **修正**：改为 `stage-overview` + `standard-directory` 两个语义明确的端点（05 §二）。
- **验收**：切换阶段后右侧数据完全随之变化。
