# 日志与对象存储治理计划 V1

> **日期**：2026-10-17 ｜ **状态**：待审批（审批通过后才写码）
> **输入**：`../分析报告/XiHan日志体系借鉴与当前后端日志缺口评估-V1.md`（日志部分）
> **本文性质**：只做两件事——**把运行日志做到可在本地定位**、**把对象存储做到可切 OSS**。不引入 XiHan 依赖（其目标框架 net10.0），不重写基类，不进多租户 / 事件总线 / OTel。

---

## 〇、结论

两件事的本质相同：**抽象已经在、实现与出口缺失**。

| 领域 | 已具备 | 真正缺的 |
|---|---|---|
| 对象存储 | `IObjectStorage` 8 方法契约，≥20 个业务文件已只依赖接口；`StoragePath` 存的是**相对对象键**（无 endpoint / bucket / URL）；前端预览/下载均走 API（Blob + Authorization，`resources/logic.ts:1297` 注释明写「Authorization 头无法随裸链接发送」）⇒ **切 Provider 不动 DB、不动前端** | `AliyunOssStorage` 是**抛 `NotImplementedException` 的骨架**（`AliyunOssStorage.cs:24`，8 个方法全抛）；切 `Storage:Provider=aliyun-oss` 不会启动失败，而是**首个请求 500**；`DownloadAsync` 全量缓冲进 `MemoryStream`；`ExistsAsync` catch-all 把网络错误当成「文件不存在」 |
| 日志 | 运行日志已落 `Logs/backend-YYYYMMDD.log`（2026-10-17 阶段 0）；审计文本 + `sys_log` 表两条链 | 无级别分离 / 无 TraceId / 无保留策略；审计 `Timestamp` 用 `UtcNow`；审计双消费者；异常只进控制台流；`sys_log.Detail` 仅 `varchar(2000)` 装不下堆栈 |

**因此工作量远小于"重接一套存储"**：存储 A–D ≈ 2.5d（含迁移），日志 E–F ≈ 2.5d（含 TraceId 与异常收口），合计 **5.0d**；可延后的 G（审计表增强）再 1.0d。可拆成两次上线。

## 二、目标与非目标

**目标**

1. `Storage:Provider` 一处切换即可在生产使用阿里云 OSS；切换前后**业务代码、数据库、前端零改动**。
2. 存储故障能自我说明：错误信息必须带 provider / endpoint / objectKey / 根因（不再出现「文件不存在」掩盖网络故障）。
3. 运行日志：重启不丢、异常有堆栈、错误与常规分流、可被 TraceId 串联、有保留上限。
4. 迁移可回滚：MinIO 保留只读 ≥7 天，双读开关兜底。

**非目标（本期不做）**

- 前端直连 OSS / CDN 预签名下载（会绕过鉴权与审计；留作后续决策）
- OSS 分片上传（>500 MB 或弱网再立项）
- OpenTelemetry / ELK / Loki 外送
- 多租户、事件总线、ABP 式模块系统
- 引用任何 `XiHan.Framework.*` 包

## 三、分期与产出

### 阶段 A — 存储契约加固（0.5d）

1. `IObjectStorage` 增补两个成员（**只增不改**，避免 20 处调用点返工）：
   - `Task<ObjectContent> OpenReadAsync(string objectName, CancellationToken ct = default)`，`ObjectContent { Stream, long Length, string ContentType }`
   - 异常语义：新增 `ObjectNotFoundException`（仅 404/NoSuchKey 抛），其余异常**必须冒泡**
2. `MinioObjectStorage`：`DownloadAsync` 内部改用 `OpenReadAsync`（保留兼容）；`ExistsAsync` 只捕获「不存在」，其余记录并抛出；`CopyAsync` 改服务端 `CopyObject`（MinIO 支持则用，否则保留现实现并注释原因）。
3. `StorageOptions` 强类型（Provider / BucketName / Endpoint / Region / AccessKeyId / SecretAccessKey / UseSSL / RootPrefix），`appsettings.json` 增 `Storage` 与 `AliyunOss` 节；**密钥只走配置/环境变量，启动缺失即失败**。

**验收**：`Storage:Provider` 填一个不存在的值 ⇒ 启动即报错（不是请求期 500）。

### 阶段 B — OSS 实现 + 本地磁盘实现（1d）

1. `AliyunOssStorage`：按契约实现 8+1 方法（SDK：`Aliyun.OSS.SDK.NetCore`；若最终选腾讯 COS / S3 兼容则换 `AWS SDK S3` 实现，契约不变）。
2. 新增 `LocalDiskObjectStorage`（`Storage:Provider=local`，根目录 `Storage:Local:RootPath`）：
   - 开发机不再依赖 MinIO / Docker，顺带消灭 `NO_PROXY` 偏置与代理事故面；
   - CI 与契约测试默认用它。
3. 启动自检：`StorageSelfCheckHostedService`（`IHostedService`）启动时验证 bucket 可达 / 根目录可写；失败**中断启动**并打印 provider + endpoint。

**验收**：同一套契约测试在 `local` 与 `aliyun-oss` 两个 provider 上全绿。

### 阶段 C — 大文件与复制（0.5d）

1. `FileStorageController.Download` 改为 `OpenReadAsync` + `FileStreamResult`（`enableRangeProcessing: true`），消除全量缓冲；PDF 预览/Range 由框架处理。
2. OSS `CopyAsync` 用服务端复制；`DeletePrefixAsync` 用批量删除（OSS 单次 1000，与现实现一致）。
3. 明确对象键规范化：统一 `TrimStart('/')`，键内中文/空格**不做 URL 改写**（DB 里就是原文），仅签名时按 SDK 要求编码。

**验收**：100 MB 文件下载，进程内存峰值 < 200 MB（`dotnet-counters` 观测）；Range 请求返回 206。

### 阶段 D — 迁移与切换（0.5d）

1. `scripts/storage/migrate-objects.mjs`（或 C# 一次性命令）：按 5 张表的 `StoragePath` 生成清单 → 从 MinIO 流式复制到 OSS → 逐一比对 `长度 + ETag/内容哈希` → 输出差异报告。
2. **双读开关** `Storage:ReadFallback=minio`：OSS 取不到时回读 MinIO，命中即打 `WRN` 并计数（迁移期专用，切换稳定后关闭）。
3. 切换步骤：`Storage:Provider=aliyun-oss` → 冒烟 95 个对象 → 保留 MinIO 只读 7 天 → 关闭 fallback → 归档 MinIO 卷。

**验收**：95/95 对象哈希一致；抽样 10 个中文/空格/深层目录文件名下载成功；关掉 MinIO 后全站文件功能正常。

### 阶段 E — 日志 P1（1.5d）

1. **TraceId**：`TraceIdMiddleware`（`Activity.Current?.TraceId ?? TraceIdentifier`）写入 `HttpContext.Items` 与响应头 `X-Trace-Id`；注册在管线最前。
2. **运行日志落盘结构**：`Logs/app-YYYYMMDD.log`（Information+）与 `Logs/error-YYYYMMDD.log`（Warning+），按日滚动 + 单文件 100 MB + 保留 31/90 天；目录可配置 `Logging:Directory`（生产挂 volume）。
   - 方案：`Serilog.AspNetCore 8.0.3` + `Serilog.Sinks.Async 1.5.0`（均已核实存在，net8 线）。若评审否决新增依赖，则退化为「自研 `ILoggerProvider` + 内置滚动」，功能等价、代码量约 150 行。
3. **审计出口修正**（`YzhAuditLogger`）：去掉 `EnqueueAndTryFlush` 的第二个消费者（单消费者）；`Timestamp`/文件名改 `DateTime.Now`（铁律十；`DurationMs` 的 `UtcNow` 差值保留）；文本改**单行**（`时间 | 级别 | 用户 | 操作 | 状态 | 耗时 | IP`），可 `grep`。
4. **脱敏前置**：`SerializeParams` 保持现有「参数名白名单」，**本期不改成 JSON 序列化**（`LoginRequest.Password` 会明文落盘，见评估报告 B1）。

**验收**：重启后历史日志仍在；连续 3 天自动滚动并清理；日志行可 `grep` 单条请求；`X-Trace-Id` 与日志中的 TraceId 一致。

### 阶段 F — 日志 P2：盲区收口（1d）

1. 启动期：`builder.Build()` 之前用独立 logger 写 `Logs/boot-YYYYMMDD.log`（配置缺失、DB 连接失败、EntityConfig 路径错时**有得查**）。
2. 后台任务：`AppDomain.UnhandledException` + `TaskScheduler.UnobservedTaskException` + `HostOptions.BackgroundServiceExceptionBehavior` 显式配置，异常统一进 `error-*.log`。
3. 健康检查：`/health/live`（进程）与 `/health/ready`（DB / Redis / 存储自检），供脚本与运维使用；**不进** `sys_log` 审计。

**验收**：断开 MySQL 启动 ⇒ `boot-*.log` 有明确失败原因；人为让队列任务抛异常 ⇒ `error-*.log` 有堆栈、进程不崩。

### 阶段 G — 审计表增强（1d，可延后到上线后）

1. `sys_log` 增三列：`TraceId varchar(32)`、`ExceptionType varchar(200)`、`StackTrace mediumtext`；`Detail` 扩 `text`。**不加 `RequestParams`**（与 `Detail` 同义）。
2. `SysLogDbWriter` 写入三列；`YzhAuditingFilter` 把 TraceId 传入。
3. 前端日志页（`pages/system/log`）加「TraceId 搜索 + 仅看异常」筛选（后端 `/filter` 支持即可，页面走 `SingleTableCore` 默认能力）。

**验收**：前端报错截图 → 响应头 TraceId → `sys_log` 单行 → `error-*.log` 完整堆栈，四步闭环。

## 五、风险与回滚

| # | 风险 | 处置 |
|---|---|---|
| R1 | OSS 供应商锁定 | 契约先行的两实现（local/oss）+ 可替换 SDK；换供应商只新增 provider |
| R2 | 中文 / 空格 / 深目录 key 在 OSS 签名或迁移时出错 | 迁移前跑编码用例；键保持 DB 原值，不在 DB 侧改写 |
| R3 | 迁移期间新旧数据不一致 | 双读 fallback + 迁移后只读 MinIO 7 天 + 哈希校验 |
| R4 | 生产日志目录在容器只读层 | `Logging:Directory` 可配置 + 部署文档要求挂 volume；启动时自检可写 |
| R5 | 日志含敏感信息 | 本期不改 JSON 序列化（B1）；密码字段仍走参数名白名单；上线前复核 `sys_log.Detail` 抽样 |
| R6 | Serilog 引入后与现有输出重复 | 只保留 Serilog 单管道 + `writeToProviders:false` 明示；不改 `ILogger` 调用点 |
| R7 | 双读 fallback 长期不关 | 设为**上线后 7 天强制关闭**的检查项，写进部署手册 |
