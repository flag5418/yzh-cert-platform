## 零、强制约定

| 约定 | 内容 | 依据 |
|---|---|---|
| **返回信封** | 统一 `ApiResponse`：`{ code, data, message, success }`，HTTP 200 | `docs/10-YZH架构/22-接口返回规范-V1.md` |
| **成功判据** | 前端只看 `res.success === true`（不是 `code === 200`） | 同上 |
| **业务失败** | HTTP **200** + `success=false` + `code='错误码'` | 同上 |
| **命名铁律** | 所有字段名 PascalCase，DB 列名 = C# 属性名 = TS 字段名，**逐字一致** | AGENTS.md 铁律七 |
| **业务键准则** | 路径参数、前端传参、查询条件**只用 `Code`**，⛔ 绝不用 `Id` | AGENTS.md 准则 A |
| **禁止写法** | ⛔ `axios`；⛔ `.vue` 内直接 `fetch(`；⛔ 手写 `handleAdd`/`handleSubmit` 等 CRUD | AGENTS.md |
| **前端调用** | 一律 `yzhApi`（来自 `yzh.vue.core`） | AGENTS.md |
| **租户隔离** | `OrgCode` 一律从 `WorkspaceContextService.Resolve()` 取，⛔ 禁止从请求参数取 | `CertPlatform.Auditor/Services/WorkspaceContextService.cs` |

### 控制器清单（三层同构）

| 层 | 路径 | 说明 |
|---|---|---|
| 后端 Controller | `src/certplatform-api/CertPlatform.Auditor/Controllers/ExpertTask*.cs` | 挂在 `CertPlatform.Auditor`（专家端） |
| 前端 API | `src/certplatform-web/cert/cert-share/src/api/expert-task/*.ts` | 业务共享层 |
| 前端 Pages | `src/certplatform-web/cert/cert-auditor/src/pages/tasks/*` | 专家端页面 |

> **为什么放 `CertPlatform.Auditor` 而不是 `CertPlatform.Admin`**：这些端点全部是专家端业务，租户隔离走 `WorkspaceContextService`。管理端控制器不带这个上下文，放错项目会导致越权。

### 控制器继承

| 控制器 | 基类 | 理由 |
|---|---|---|
| `ExpertTaskController` | `YzhControllerBase<T>` | 单表 CRUD 骨架（自动获得 list/get/add/update/delete + `FilterCore` + `OnQueried` 钩子） |
| `ExpertTaskItemController` | `YzhControllerBase<T>` | 同上 |
| `ExpertTaskDataGapController` | `YzhControllerBase<T>` | 同上 |
| `ExpertTaskLogController` | `ControllerBase` | ★ **只读 + 追加**，无 CRUD 需求，继承基类反而要用钩子关掉一半功能 |
| `ExpertTaskQueueController` | `ControllerBase` | 同上（只读 + 取消/重试） |

> ⛔ **禁止裸 `ControllerBase` 承载单表 CRUD**（AGENTS.md ②：现存 10 个裸基类是坏榜样）。只有"无 CRUD 需求"的控制器才允许。

## 一、错误码表

| `code` | HTTP | 含义 | 前端处理 |
|---|---|---|---|
| `OK` | 200 | 成功 | — |
| `PARAM_INVALID` | 200 | 参数校验失败 | 提示 message |
| `BIZ_LOCKED` | 200 | **业务锁占用**（02 号 §6） | 提示占用中的任务编号 |
| `STANDARD_NOT_ASSIGNED` | 200 | 标准未分配给该企业该阶段 | 提示 |
| `CROSS_STANDARD_NOT_ALLOWED` | 200 | **局部任务跨标准**（D03） | 提示只能选一个标准 |
| `PARTIAL_ITEM_NOT_FOUND` | 200 | 勾选项无效或不属于该范围 | 提示 |
| `STAGE_INVALID` | 200 | 阶段无效 | 提示 |
| `NO_STANDARD_TEMPLATE` | 200 | 该标准无可用报告模板 | 提示（该标准被排除） |
| `DATA_GAP_UNRESOLVED` | 200 | **还有未处理缺口**（O2） | 弹补录清单 |
| `REVIEW_INCOMPLETE` | 200 | **还有未认可结果**（O3） | 跳转未认可列表 |
| `TASK_FROZEN` | 200 | 任务已批准，禁止写 | 提示 |
| `TASK_STATUS_INVALID` | 200 | 状态不允许该操作 | 刷新页面 |
| `ALREADY_REVIEWED` | 200 | 已被他人处理 | 刷新 |
| `CONCURRENT_MODIFIED` | 200 | 并发修改冲突 | 刷新 |
| `QUEUE_NOT_FOUND` | 200 | 队列不存在 | 提示 |
| `ITEM_NOT_IN_TASK` | 200 | 任务项不属于该任务 | 提示 |
| `EXPORT_FAILED` | 200 | 导出失败 | 提示 |
| `UNAUTHORIZED` | 401 | 未登录 | 跳登录 |
| `FORBIDDEN` | 403 | 无权限 | 提示 |
| `NOT_FOUND` | 404 | 资源不存在 | 提示 |

> **业务失败一律 HTTP 200**（信封规范）。HTTP 401/403/404 只用于真正的传输层问题。

## 二、`ExpertTaskController` — 任务

`[Route("api/ExpertTask")]` ｜ 继承 `YzhControllerBase<Task>`

### 2.1 基类自动提供（不重复定义）

| 端点 | 方法 | 说明 |
|---|---|---|
| `GET /api/ExpertTask/list` | `List` | 分页列表，**覆盖 `FilterCore` 加租户过滤 + 业务锁标记** |
| `GET /api/ExpertTask/{code}` | `Get` | 单条详情（含统计） |
| `GET /api/ExpertTask/config` | `Config` | 实体配置（表格列） |
| `POST /api/ExpertTask/add` | `Add` | ⛔ **本期不用**（任务创建走 `POST /api/ExpertTask`） |
| `POST /api/ExpertTask/update` | `Update` | 只允许改 `Remark` |
| `POST /api/ExpertTask/delete` | `Delete` | 只允许 `draft`/`cancelled` 态删除 |

### 2.2 自定义端点

#### `GET /api/ExpertTask/creatable-context`

**用途**：创建向导第 1 步，选完企业+阶段后校验 + 拉可选项。

**Query**：`EnterpriseCode`（必填）｜ `StageCode`（可选，空=全部阶段）

**Response**：

```json
{
  "code": "OK",
  "success": true,
  "data": {
    "locked": true,
    "lockedBy": {
      "taskCode": "a1b2c3...",
      "taskNumber": "TSK-20260929-0001",
      "taskType": "NC_CHECK",
      "taskTypeName": "NC 检查",
      "createName": "张三",
      "createTime": "2026-09-29 09:30"
    },
    "stages": [
      {
        "stageCode": "6b1c...",              // ★ cert_cert_stage.Code
        "stageName": "第二阶段审核",
        "stageCodeBusiness": "S2",           // StageCode 业务码（展示用）
        "standards": [
          { "standardCode": "9f2...", "standardName": "ISO 9001:2015", "hasReportTemplate": true },
          { "standardCode": "8a3...", "standardName": "ISO 14001:2015", "hasReportTemplate": false }
        ],
        "ruleCount": { "ISO 9001:2015": 32, "ISO 14001:2015": 18 }
      }
    ]
  }
}
```

**逻辑**：
1. 业务锁检查（`BIZ_LOCKED` 不抛异常，**返回 `locked=true` 让前端禁用**，因为前端要展示"哪个任务占着"）
2. 读 `cert_enterprise_stage`（该企业已分配的标准）
3. 对每个阶段，统计该 `(机构, 标准, 阶段)` 下的有效规则数（NC）与章节数（报告）
4. `hasReportTemplate`：查 `cert_report_template` 是否有可用模板

#### `GET /api/ExpertTask/selectable-items`

**用途**：创建向导第 2 步，勾选检查项/章节（局部任务）。

**Query**：`TaskType`（必填）｜ `StageCode`（必填）｜ `StandardCode`（必填，局部任务必须单标准）｜ `Keyword`（可选，模糊搜索）

**Response**：

```json
{
  "code": "OK", "success": true,
  "data": {
    "standardCode": "9f2...",
    "standardName": "ISO 9001:2015",
    "templateName": "ISO9001 报告模板 v2",
    "hasTemplate": true,
    "items": [
      {
        "itemCode": "7f8...",                 // ★ cert_validation_rule.Code
        "itemName": "文件控制程序",
        "itemNumber": "NC-ISO9001-001",
        "clauseCode": "3a4...",
        "clauseNumber": "7.5",
        "clauseTitle": "成文信息",
        "judgeMode": "auto",
        "workflowCode": "b1c...",              // 空 = 不可自动执行（前端标灰）
        "hasWorkflow": true,
        "selected": true
      }
    ]
  }
}
```

> **报告任务时字段差异**：`itemNumber` 为 null，用 `sortOrder`；`workflowConfig` 存在 `WorkflowConfig` 列（不是 `RuleJson`）。
> `hasWorkflow=false` 的项前端**标灰但允许勾选** —— 专家可能想跑（会走 `no_rule` 跳过），但要有提示。

## 三、`ExpertTaskItemController` — 任务项

`[Route("api/ExpertTaskItem")]` ｜ 继承 `YzhControllerBase<TaskItem>`

### 3.1 基类端点的定制

| 端点 | 定制点 |
|---|---|
| `list` | ⛔ **禁用**。列表必须经 `GET /api/ExpertTask/{code}/items`（要带任务态校验与统计聚合） |
| `get` | 覆写 `OnGot`：校验任务未冻结；返回带 `autoResult` 解析后的结构 |
| `update` | ⛔ **禁用**。必须走 `acknowledge` / `modify`（要记日志） |
| `add` / `delete` | ⛔ **禁用**（D20 不支持追加/删除） |
| `config` | 表格列定义 |

> ⛔ **禁止基类的 `add`/`update` 暴露出去**。审核类接口最怕"绕过日志直接改库"。

### 3.2 认可

#### `POST /api/ExpertTaskItem/{code}/acknowledge`

**Body**：`{ "Remark": "已核对原始文件，确认无误" }`

**Response**：`{ "code": "OK", "data": { "reviewStatus": "acknowledged", "reviewTime": "..." } }`

**逻辑**：02 号 §4.1

**错误**：`TASK_FROZEN` / `ALREADY_REVIEWED` / `CONCURRENT_MODIFIED`

### 3.3 修改（修改即认可，D11）

#### `POST /api/ExpertTaskItem/{code}/modify`

**Body**（字段可选，只传要改的）：

```json
{
  "Conformity": "nonconform",
  "Severity": "major",
  "ContentText": "文件控制程序未规定编号规则，且未规定版本控制方式",
  "EvidenceRef": "文件控制程序.pdf 第3节",
  "Remark": "补充：版本控制也缺失"
}
```

**Response**：

```json
{
  "code": "OK", "success": true,
  "data": {
    "reviewStatus": "modified",
    "isModified": true,
    "modifiedFields": ["Conformity", "Severity", "ContentText"],
    "ncAction": "created",              // created | cancelled | updated | none
    "ncCode": "nc1..."
  }
}
```

**逻辑**：02 号 §4.2 + 03 号 §5.3（NC 同步）

> **`ncAction` 让前端知道 NC 记录的连带变化** —— 结论从符合改成不符合时，专家会看到提示"已生成 NC 记录 NC-20260929-0001-ISO9001-01"。

**错误**：`TASK_FROZEN` / `ALREADY_REVIEWED`

#### `POST /api/ExpertTaskItem/batch-acknowledge`

**Body**：`{ "TaskCode": "...", "SubTaskCode": "...", "ItemCodes": ["...", "..."], "Remark": "本章节已核对" }`

**Response**：`{ "code": "OK", "data": { "acknowledgeCount": 5 } }`

**限制**：单次 ≤ 500 条，超出返回 `PARAM_INVALID`。

#### `POST /api/ExpertTaskItem/{code}/reset-content`

**用途**：报告章节的 [恢复为 AI 原文]。

**Body**：`{ "Remark": "恢复AI生成内容" }`

**逻辑**：`ContentText` = `AutoResult.content`，仍记一条 `MODIFY` 日志（04 号 §3.3）。

## 九、错误响应的统一处理

### 9.1 后端

```csharp
// 业务异常统一抛出，由全局过滤器转信封
throw new BizException("BIZ_LOCKED", "该企业在该阶段存在进行中的任务【TSK-20260929-0001】，请先完成后再操作");
```

HTTP 恒为 200，`success=false`，`code` 为本文件 §1 的错误码之一。

### 9.2 前端

```ts
// yzhApi 已内置信封解析（22 号规范），此处只列业务判断
const res = await expertTaskApi.approve(taskCode)
if (res.success) {
  ElMessage.success('任务已批准')
  router.push({ name: 'TaskList' })
  return
}

switch (res.code) {
  case 'REVIEW_INCOMPLETE':
    ElMessage.warning(res.message)
    // ★ 直接跳到未认可项
    openPendingDrawer(res.data.itemCodes)
    break
  case 'DATA_GAP_UNRESOLVED':
    ElMessage.warning(res.message)
    router.push({ name: 'TaskGapFill', params: { code: taskCode } })
    break
  case 'BIZ_LOCKED':
    ElMessage.error(res.message)
    refreshLockState()
    break
  default:
    ElMessage.error(res.message || '操作失败')
}
```

> ⛔ **禁用 `res.success` 之外的成功判据**。本项目信封有 `success` 字段（例外 E1 指的其他接口是 `{code,data,message}` 无 `success`）。本设计的接口全部走标准信封。
