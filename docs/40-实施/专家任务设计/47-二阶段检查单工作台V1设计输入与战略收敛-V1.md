## 一、竞争定位：写让给免费 AI，判钉死不放

### 1.1 行业现实（朋友信源，2026-10-21 沟通）

- 审核员已普遍用免费 AI 写检查单/报告，估计解决 **60-70% 内容**；
- 但剩余成本更累：**格式整理 + 准确率全文复核**（AI 一遍出长文，人有惰性，很难拿 100% 的完整思路去比对"它缺了啥"，一旦发现缺失就要回原始文档慢慢找或改提示词重生成）；
- AI 不可信的具体形态：**张冠李戴**（同一日期/同一描述安到错误对象）——它不是专案人员，没有上下文锚定。

### 1.2 战场裁决

> **审核员的工作不是写报告，"大概差不多可能就行了"；漏判的 30% 才追责。**

- 报告是低价值工种，免费 AI 已赢——**不在写作维度竞争**；
- 判定是高价值工种，追责所在，免费 AI 恰是漏判源（无清单约束 + 张冠李戴 + 不可复现）；
- 定价叙事一句话：**"免费 AI 让你快，我们让你敢签字。"**

### 1.3 写判双优势：为什么程序员恰好赢这一仗

| 维度 | 免费 AI 用法（对话式） | 我们的用法（工程式） |
|---|---|---|
| 提示词 | 每个审核员各写各的，质量玄学 | 规则固化：judge 清单是确定的要求侧 |
| 约束 | 无——AI 自由发挥 | 每格结构化：对象/时间/数值类型可校验 |
| 留痕 | 无——聊天记录不构成审核档案 | 每格带来源（文件+段落+原文摘录） |
| 可信度 | 无——要么全信要么全不信 | 每格带置信度；多 judge 分歧度可度量 |
| 可复现 | 换个审核员/换个 AI/换个日子，结果都不同 | 同输入同输出，可复现、可审计、可追责 |

**"不漂移"就是护城河**：签字的人要的不是"每次不一样的玄学"，是"每次一样的基线"。多 judge 融合的本质 = 把模型不确定性变成**可度量的分歧度**，分歧大的项正是要人复核的项——这与置信度是一回事的两面，共同支撑"只复核该复核的"。

### 1.4 judge 清单三通解药（对应用户已实现的 ValidationRule + judge 链路）

| 免费 AI 的痛点 | judge 清单的解法 |
|---|---|
| 惰性（人难比对 AI 缺啥） | ⛔ 不要人对比，**系统强制逐条**：填不满的标红，人的工作从"找 AI 漏了啥"变为"处理系统标红的项" |
| 漏判 30% 追责 | 清单 = "100% 要求"的可执行形式，漏一条 = 一行空着，看得见 |
| 张冠李戴 | 结构化信息项（对象/时间/数值）+ 来源锚定 ⇒ 审核员验证"引用位置对不对"，而非"信任内容对不对" |

## 二、原理裁决：检查项、证据链、报告的正确连接

### 2.1 四层关系（用户自疑"是否搞错"的裁决）

```
检查项(条款×要求×过程) --judge清单声明--> 证据实例(文档/记录/现场) --比对--> 判定(四态+NC) --取数--> 报告章节流
```

- **检查项** = 审核员视角，"审什么"，考前预印；
- **报告章节流** = 读者视角，"写什么"，产物组织；
- **章节消费判定结果，不消费证据链**。QR-04-72 检查单四列即报告主体，是 ACM 按过程分区的**格式选择**，不是普世原理；
- 一个检查项即使证据齐全也可能开 NC——**入场观察/访谈得到的实然与证据（应然）不符**。AI 只能读文档（应然侧），现场（实然侧）只能由人录入。这是 AI 的天花板，也是产品的诚实边界（明说"AI 只读文档、现场归你、判定归你"，比号称全能更可信）。

### 2.2 已识别的设计错位（待代码核对）

**证据链按判定需要组织（要求侧），不能按报告章节组织（产物侧）。** 错位后果：

1. 机构报告模板改版（叙事变）就要重组所有证据；
2. 判定缺不缺证据，系统无法自动发现缺口——缺口只能在"检查项需要什么"的维度上对齐。

> ⚠️ 此错位是 DAG 跑不通的可疑根因之一，核对项：证据链/ReportSection 的组织维度到底按条款要求还是按报告叙事。

## 三、NC 机制三结论（ACM 合同 + QR-04-72 实证）

1. **验证两方式**：书面（文档/记录评审）/ 追加现场访问，选择权在审核员，判据 = 整改证据形态；Minor 多书面，Major 多现场；一次访问可批量验证一批 NC（系统需**批量关闭**能力）。
2. **NC = 发证闸门，不是阶段闸门**：二阶段可先出"推荐认证"，发证等 NC 全关 + 认证决定委员会通过；一阶段开"问题项"（非 NC），未关不得进二阶段（QR-04-72-4 预印原文实证）；监督审核三大内容 = 上期 NC 验证 + 变更 + 抽样；升级链 = Major 超期 → 证书暂停 → 暂停后 3 个月未完成 → 撤销。
3. **NC 可多轮整改**：提交 → 验证 → 接受销项 / 打回（附理由）→ Round+1；1-2 轮常态。打回三因：治标不治本 / 根因没到 / 措施无验证方式。
4. **报告 = 组装产物，不是重新写作**：

| 报告部件 | 数据来源 | 自动化 |
|---|---|---|
| 头部 | 申请数据 + 审核任务 | 全自动 |
| 一阶段简述 | 一阶段问题清单 + 关闭记录 | 半自动 |
| 审核发现主体 | 检查单四列全文 | 原样导出 |
| NC 汇总清单 | NC 行判定 | 全自动 |
| NC 报告全文（五段式） | 各 NC 整改闭环记录 | 半自动 |
| 体系总体评价 | 审核组长人工 | AI 草稿 + 人工改 |
| 结论与推荐 | 认证决定委员会合议 | ⛔ 人工 |
| 签字 | 组长/技术负责人 | — |

隐藏坑：体系范围可能被现场证据修正（申请写"设计开发"但无设计记录）→ 系统须标记偏差，⛔ 不默默采用申请书原文。

## 四、v1 范围与路线

### 4.1 主产品（不变）：二阶段检查单工作台

预制检查单（机构模板预印四列）→ 证据归位（AI 填证据列，每格带来源+置信度）→ 疑点清单（标红项+NC 候选）→ 人工判定 → 成稿（报告组装器）。降险路径不变：先文档证据归位，现场采集先用简版补录表单。

### 4.2 先行件（新增）：审核员个人工作台

- 年度人日台账（180 天拆场次、余额提醒）
- 单场入场计划（CNCA 15 字段上报格式预置，2026-09-30 已生效 = 合规红利；提前 3 日报送提醒）
- 准备清单（要干什么/联系谁/得到什么）
- 入场后回填 → 沉淀企业档案

定位：**个人侧、月付制、不依赖机构采购**；同时是检查单引擎的企业档案数据地基（"联系谁→部门/人员、要干什么→过程、得到什么→证据占位"——正是"完成率恒 0%"的真缺口）。

### 4.3 获客三级火箭 + 信任四步

```
计划工具（天天用，建关系）→ 疑点清单（免费跑一次，触发付费）→ 检查单工作台（收主费）
```

信任四步：① 手工案例先行（朋友资料 + judge 清单人肉跑一场，记时间账+漏判账）② 寄生而非替代（上游结构化输入 + 下游漏判校验，兼容免费工作流）③ 免费单点钩子 = 疑点清单 ④ 边界写成卖点。

### 4.4 范围纪律

**一个标准跑通（ISO 13485），再多案例**——准确率、效率、省心，靠复现不靠功能面。

## 五之补、ACM QR-04-70/72 条款结构实证（2026-10-22 原文抽取）

> 抽取源：`docs/90-归档/案例资料/E_Documents except for the above parts.pdf`（p6-8 QR-04-70 一阶段；p9-49 QR-04-72 二阶段）；对照 GBT 42061-2022（40 页扫描件**无文本层**，条款树入库需 OCR；ACM 表单自带中英双语条款原文，可作 OCR 前的临时条款树源）。

1. **条款驱动坐实**：QR-04-72 按 13485 条款号逐行覆盖全树（4.1→8.5.3，约 70 个条款号），Requirements 列 = 中英双语条款原文 + ACM 审核要点。用户判断"整个检查就是针对条款的执行，逐个找答案检验符合"成立。
2. **阶段维度坐实**（用户"不同检查项对应不同阶段"）：一阶段 QR-04-70 是**主题式**检查项（"风险管理过程"涵盖 4.1.5/7.1 风险家族、"医疗器械文档"= 4.2.3、"设计开发控制"= 7.3…）——**这就是"多条款合并成一个检查项"的实证形态**；二阶段 QR-04-72 才是逐条 1:1。同标准两套粒度，检查项↔阶段必须 M:N。
3. **过程/区域维度坐实**：QR-04-72 按 Process Area 分组（首个区域 GM/MR，负责人=总经理兼管代呙小旭），组内逐条款。
4. **不适用条款 = 留行标注，不是删行**：7.3.1 行证据列原文"企业产品不需要设计和开发，不适用"；删减清单（7.3/7.5.3/7.5.4/7.5.5/7.5.7/7.5.9.2 六条）挂在 4.2.2 质量手册行，审核结论"删减合理"。⇒ **条款适用性是产品特定的**：预制检查单 = 全条款行 + 每行适用性标记，"理由是否成立"本身是检查项。
5. **N/R 选项实证**：一阶段表单大量使用"☑不需要 N/R"三态（需要/已提供/不需要）——适用性判定的 UI 原型。
6. **真实 NC 样本**（p16）：供应商年度评分 80 分，企业规则为"低于 60 分才送管理代表评审"，且供方绩效信息未汇总进管理评审输入 ⇒ 证据列直接判"不符合 ISO13485 5.6 e)"。⇒ NC 必须挂条款引用（可到子项级），判定列触发 NC 时条款号从映射表带出。
7. **证据可跨条款引用**（p19）：证据列原文"见采购部内审检查表，涵盖条款 7.4.1；7.4.2；7.4.3"——一份证据支撑多个条款行的真实形态，证据↔条款也是 M:N。
8. **一阶段产出 = 二阶段预制输入**：QR-04-70 已摸出企业过程清单（生产工艺流程 20 步 + 关键过程：流变、亲水涂层；特殊过程：拉线环焊接；外包过程：有）+ 多场所 + 组织架构 ⇒ 直接作为二阶段 Process Area 划分与取证路线的一手数据。

**预制检查单生成逻辑（v1 组装器规格）**：全条款行（GBT OCR 或 ACM 表单提取）× 企业适用性标记 × 机构检查项配方（合并/拆分/主条款）× 阶段开关。条款树是公共底座，机构配方是调味——再次实证 46 号文档"标准驱动、机构调味"。

## 五之二、标准模型：产品的真正核心资产（2026-10-22 战略判断）

> 用户判断："无论证据、检查还是内容，从机构差异变成了吃透标准文档"——不同机构其实都在针对标准做证据收集与合格判定；企业按标准准备材料（QR-04-72 证据列实证：质量手册 QM-2022、文件收发记录、风险管理报告、管评输入 a-l……全部对应标准条款的"应形成文件/应保持记录"）。

1. **机构差异收敛为配置层**：检查项合并粒度、Process Area 分区、阶段行组开关、NC 严重度口径 = 机构"调味"；底层的条款树 × 证据要求 × 判定准则 × 企业产物清单 = 全行业同一套"食材"，且**全部可从标准文档本身推导**。
2. **标准模型四要素**（每条款一行，机器可读）：

| 要素 | 来源 | 示例（5.6.1 管理评审） |
|---|---|---|
| 条款原文（中英） | GBT 42061 OCR（临时源=ACM 表单 Requirements 列） | "Top management shall review... at documented planned intervals" |
| 企业必须产物 | 标准"应形成文件/应保持记录"推导 + QR-04-72 证据列实证 | 管评程序/计划/签到表/报告（输入 a-l 十二项）/改进输出 |
| 证据收集要点 | ACM 表单 + 审核方法论文档化 | 输入是否覆盖 a-l 全项；签到是否亲笔；改进项是否闭环 |
| 判定准则 | 标准要求 + NC 样本反推 | 输入缺项（供方绩效未汇总进管评）= NC（p16 实证"不符合 5.6 e)"） |
| 适用性规则 | 产品/企业属性 | 全企业适用（对照 7.3 按产品标记不适用） |

3. **企业端镜像**：标准"应形成文件 X/应保持记录 Y" → 企业准备清单 → 企业档案"应然"基线 → 审核员端证据需求直接引用。**审核员要的证据，就是标准要求企业准备的**——一端导出、两端消费：企业资料规范化与检查单是同一标准模型的两个消费者。
4. **战略意义**：不需要集齐各机构检查单——ACM 一家 + GBT 原文足以建立 13485 标准模型。"吃透一个标准"= ~70 条款 × 四要素 = 一次建成、多机构/企业端/多案例复用的复利资产。产品策略：**标准模型做深，机构配置做薄**。

## 五之三、企业模板同源性与检查单配置机制核实（2026-10-22 三包对比 + 合同原文）

> 用户三个猜测：① 企业标准文档模板差异来自咨询公司但绝大部分雷同 ② 检查单不固定、按企业情况配置 ③ 机构给企业"开卷考试沟通"。

1. **模板同源性：坐实**（双尼 QES 117 文件 / 科斯亚 QMS 102 / 尚龙 13485 171 三包对比）：
   - **"壳"全行业统一**（标准逼的）：四层文档树（手册/程序/三阶或制度/记录）+ 核心程序集重合（文件控制/记录/内审/管评/采购/不合格/培训/标识/监测设备/顾客满意/纠正预防三家都有）+ 正文骨架一致（目的/范围/职责/控制程序）+ 连"文件分四阶、编号规则、管代审-总经批"都一致；
   - **"皮"差异 = 咨询公司模板**：编号规则（SN/QES-CX-10-2026 vs KSY-QMS-P-11 vs XASL-QP-001）、封面形态（双尼编号行式 / 科斯亚封面块+修订记录 / 尚龙正文式）、命名（文件信息管理 vs 文件化信息控制 vs 文件控制）；
   - **"馅"差异 = 标准差异**：尚龙 13485 多出忠告性通知和召回、医疗器械不良事件报告、设计开发、计算机软件确认、风险管理——医械法规专用程序。
2. **检查单按企业配置：坐实**——ACM/QR-04-72-4 A/0 表单壳固定（受控表单 + 四列 + 全条款行预印），内容全按企业配置：不适用条款清单（7.3/7.5.3/7.5.4/7.5.5/7.5.7/7.5.9.2 按产品裁）、认证范围行（导管鞘管体 + IAF MD9 A.1.7 无源非植入）、Process Area 按企业架构（GM/MR）、负责人实名（呙小旭）、证据列全是该企业文件号（QM-2022/QP-007-01）。合同佐证：*"The audit will be carried out against **agreed audit criteria**"*。**配置输入来自一阶段 QR-04-70**（摸范围/多场所/架构/过程/不适用条款）。
3. **"开卷考试"沟通：部分坐实，边界须校准**——制度化沟通真实存在（合同：ACM 主动联系企业提供与认证相关信息；一阶段 readiness review 出报告后约定二阶段日期；科斯亚目录名"打印后签到表手签/企业填写并提供校准报告"=咨询按审核预期帮企业备考）。但开卷止于**考纲**（范围/标准/过程/日程/要准备的记录类型），不及**考题**（具体检查项/抽样计划/NC 触发点）——泄露检查表是公正性事故。⇒ 产品落点：企业端"准备清单"（考纲侧）合法且有价值；检查单全文归机构。
4. **意外修正：NC 定义 vs 资料缺口**——ACM 合同 Major NC 定义原文：*"where there is a lack of evidence to demonstrate that a clause within a standard has been met. For example, **no evidence, records or documents can be found**"*。⇒ "声称做了但审核时找不到记录"= Major NC；"还没做/未提交"= 补录清单。GapDetector 与 NC 的分流口径按此校准：**分流点 = 企业是否声称符合（应然侧有无承诺）**，修正此前"资料缺口≠NC"的粗糙表述。

## 五之四、企业内审强制性与内审软件市场（2026-10-22 查证）

1. **双强制**：
   - ISO 13485 8.2.4（shall）：文件化内审程序 + 基于风险的审核方案（考虑过程/区域状况重要性及以往结果）+ 规定准则/范围/频次/方法 + 保留记录（过程/区域/结论）；**审核员不应审核自己的工作**；受审核区域管理者采取纠正措施无不当拖延，后续活动验证措施并报告验证结果（闭环）。
   - **新版《医疗器械生产质量管理规范》**（药监局 2025 年第 107 号公告，2025-11-04 发布，**2026-11-01 施行**，2014 版同时废止）：第一百二十八条——建立内审程序，确定审核准则/范围/频次/参加人员/方法/记录要求/**纠正预防措施有效性评定**，制定内审计划，形成审核报告，对不合格采取纠正预防措施；第十九条管代组织"质量管理体系自查"；第一百二十九条管评程序+报告+改进措施。
   - ⇒ 内审对二三类械企是**法规 + 标准双强制**，且新 GMP 把"纠正预防措施有效性评定"写进强制项。
2. **内审员资格边界**：标准不强制证书，强制"能力 + 独立性"（不审自己工作）；人员不足可请外部人员参与，但企业自身体系管理人员应参与。实证高频不符合项：审核周期超 12 个月、独立性失效、方案未基于风险策划、只发现表面问题——**全部是软件可防的痛点**。
3. **独立内审软件 = 空档**：国内无形成品类的独立产品（OA 模板页 / Excel / 飞书多维表格自管为主）；国际独立品类（AuditBoard、Ideagen）面向财务合规内审，不对口 ISO 体系审核；ISO 体系审核功能寄生在大而贵的 eQMS（ETQ/AssurX/MasterControl/Qualio/Greenlight Guru/QAD EQMS）。⇒ **"条款驱动的检查表 + NC 闭环"在 ISO 体系内审场景无成品**——与认证侧"证据→判定"空档同源，是同一引擎的企业侧镜像。
4. **时间窗**：新 GMP 2026-11-01 施行前，企业须按新准则更新程序文件并重做内审——企业侧工具的黄金窗口；第六条"鼓励企业推进数智化转型" + 第四十六条电子记录要求 = 软件管内审有法规背书（销售话术）。
5. **模板种子**：双尼内审包（4 张部门检查表 Q/E/S 前缀 + SN-QR-34 NC 报告 + 内审报告 + 管评 CC-QR-38 全套）= 企业内审模块第一套真实模板。
6. **⚠️ 连带影响**：新 GMP 132 条 = "法规层"从 0 变有，标准模型四要素中的"企业必须产物"须按新 GMP 重算；13485 条款结构不变但法规映射层必须补（B6 缺口升级为紧急）。
7. **边界**：企业内审是企业自查（合法且必须），产品做"条款驱动检查表 + NC 闭环"不构成审核外挂；与认证侧产品保持数据/话术隔离（41 号文档原则）。

## 五之五、不符合项报告（NC 卡片）字段实证（2026-10-22 择宽竞企模板）

> 用户截图：择宽竞企《不符合项报告》（GB/T 19001 内审场景）。确认三层结构第三层：检查单 ↔ 判定列 NC/OFI ↔ 独立五段式文书（双尼 SN-QR-34 同款）。

**五段式字段清单（NC 卡片 schema）**：

| 段 | 字段 | 备注 |
|---|---|---|
| 头部 | 受审核部门、陪同人员、问题发生地点、审核日期 | 部门维度再次实证（P0①） |
| 事实 | 不符合事实陈述（原文摘录） | 四要素事实只摘录不生成 |
| 定性 | 不符合文件（手册/程序/其它）、标准、条款号、**不符合类型（文件/实施）**、严重程度（严重/一般） | ★ 文件/实施 = 应然/实然在 NC 层的落地：文件类 = 文件本身不符（写错/缺失），实施类 = 文件对但执行不符 |
| 整改 | 原因分析、纠正措施、预期完成日期、受审核部门负责人签字 | 企业回填 + 签字 |
| 验证 | 纠正措施完成情况、内审员验证结论、结案、内审员签字 + 日期 | **双向签字留痕**（内审员 + 部门负责人，每段都签） |

**两种机构组装模式**（壳固定、组装不同，实证 47 号"机构调味"）：
- ACM = 检查单四列即报告主体（NC 写进判定列/证据列，QR-04-72 单 artifact）；
- 择宽/双尼 = 检查单 + 独立不符合项报告 + 内审报告三件套。
⇒ 底层数据同构（检查项 × 证据 × 判定 × NC），**产物组装层必须模板化**——这正是"缺产物组装层"的实证。

**数据模型落点**（cert_expert_nc_result 缺字段，P1① 补全）：不符合类型（file/implementation）、陪同人员、问题发生地点、预期完成日期、实际验证日期、结案状态、双向签字（企业负责人/内审员 + 时间戳）。

**标准无关性**：模板条款号 7.5.3 是 9001 编号（13485 对应 4.2.5 记录控制）——**NC 卡片结构与标准无关，标准只决定条款号和企业产物清单** ⇒ 标准模型驱动的又一实证（卡片一套，标准多换）。

## 五之六、内审记录作为证据源与两端直服战略（2026-10-22 用户合成 + 内审检查表实证）

> 用户截图：内审检查表 8.5.1（生产和服务提供的控制）行，证据列 = 生产计划明细（4 个批次/数量/计划完成日期/关键工序"打钉"/作业依据或规程）。用户战略合成：证据从企业内审记录获取；内审资质若强制将挤压咨询中介；市场变两端（企业端+审核员端）；审核员核心=找证据（AI 可行 80%+）+判断（AI 难）；我们的路=标准模型+证据链双深挖+审核员周边软件。

1. **内审记录的三重身份**（校准"证据从内审记录获取"）：① 本身是审核对象（13485 8.2.4 / 新 GMP 128 条，内审记录必查）；② **运行记录的索引**（截图实证：8.5.1 行的生产计划明细是运行记录，内审检查表只是引用它）；③ ⛔ 不能被认证机构直接采信——独立性要求审核员必须独立验证，不是抄内审结论。⇒ 产品形态：企业内审时把运行记录结构化挂到条款（8.5.1 ← 生产计划），审核员入场直接看到"这家有什么记录、内审查过什么、发现过什么"——**找证据时间缩短，验证仍独立完成**。这是内审模块与审核员工作台之间独特的数据衔接。
2. **"内审干掉咨询"的机制校准**：方向对（中介变薄、两端直服），但机制要说准——干掉咨询代写业务的是**标准模型+模板库让企业自助**（企业文档大同小异已实证），不是内审资质本身；会做内审 ≠ 会建体系（手册/风险/法规识别更难），咨询的"建体系"业务不会被资质直接干掉。另："国家强制内审人员资质上岗"目前**无据**（ISO 不强制证书、GMP 要求能力未强制资质），是假设不是事实，产品规划不能建立在它上面；且新 GMP 2026-11-01 施行会先催生一轮咨询需求（企业改文件）。
3. **★ 护城河的完整表述**（用户原话"没有专用 agent，AI 连条款要求都不理解"）：免费 AI 卡在 70% 的原因是两条腿都没有——**不懂条款**（无标准模型）**+ 找不到证据**（无企业档案结构）。我们的两条腿 = 标准模型四要素 + 证据链结构化。判定权永远在人（受限 AI），AI 做归位/比对/提示。
4. **产品结构收敛为三块**：① 审核员主产品 = 二阶段检查单工作台（找证据+判断辅助）；② 审核员周边 = 检查计划制定 + 入场计划（180 天人日台账）+ 提醒（先行件，个人侧月付）；③ 企业端 = 内审管理（条款驱动检查表 + NC 闭环 + 管评，证据结构化工厂）。③ 产出的证据索引直接服务 ①——**企业端是审核员端的数据地基**，两端同一引擎。
5. **边界**：企业内审数据与认证审核数据必须分区（独立性/公正性，41 号文档原则）——产品可做"引用+验证"不可做"采信"。

## 五之七、内审员人群、证书性质与获客渠道（2026-10-22 查证）

1. **证书性质**（用户观察核实）：内审员证 = **培训机构培训合格证**——无国家统一发证、无全国统一查询平台、3 年有效期（部分机构终身）；≠ CCAA 注册外审员（全国统考 + 执业准入 + 可跨企业执业）。企业招标/供应商审核常要求"具备内审员"⇒ 培训市场火爆的根源。**证证明"受过培训"，不证明"能干活"**。
2. **职责六步闭环**：年度/专项内审计划 → 编制检查表（重点/样本/时间安排）→ 现场审核（文件评审/现场检查/访谈）→ 开具不符合项 → 整改跟踪验证有效性 → 编写报告归档；独立性 = 不审自己工作；内审员通常为各部门兼职。
3. **与认证的四个连接点**：① **认证必查项**（13485 8.2.4 / 新 GMP 128：机构审核员必看内审计划/检查表/不符合项报告/关闭情况）② 外审前的自我审查（申请认证前自己先查一遍）③ 内审记录 = 认证审核的证据基础（8.5.1 实证）④ 内审结果 → 管理评审输入 → 持续改进（认证看的就是这条链）。
4. **⚠️ 反模式实证（销售话术直接用）**：行业文章原话——"不少企业的内审做成填表，检查表照抄模板，不符合项只写文件格式问题，整改都是加强培训。这样的内审在现场核查时说服力不足。"⇒ 产品 pitch："你的内审，经得起认证机构翻吗？"
5. **商业落点**：① 内审员 = 企业端产品核心 persona，其六步工作流与软件工作流一步不差；② **培训机构 = 获客渠道**——培训教方法（怎么编检查表/开 NC）不教工具不建体系，学员回企业照样面对苦活 ⇒"持证学员工具包"是天然分销（to B via to C）；③ 证书 3 年复训周期 = 天然再营销节奏；④ 咨询进化路径：代写文件（被标准模型产品化挤压）→ 培训发证（活着）→ 高端辅导（活着）⇒ 产品对培训机构的角色 = 工具供应商/渠道伙伴，不抢生意。

## 五之八、180 天规则与外审人才流向企业（2026-10-22 查证）

1. **规则事实**（校准：180 天是**上限不是下限**）：2026 实施的新版《质量管理体系认证规则》（环境/职业健康等五项同步）：每个审核员现场审核人日 **≤180 天/周期年**（含实习审核员、不含境外）+ 年持证 **≤50 张** + 两阶段间隔 ≥5 天 + 专职审核员全程参与 + 认证费用直付机构。打击对象：无节制排期、兼职"赶场式"审核。
2. **传导链**：人日封顶 → 收入封顶（三体系外审员年收入 10-30 万，与持证人日强相关）→ 机构业务量不变须**扩编**（且必须配专职）→ 外审岗短期需求上升；长期看：出差多/压力大/担责/收入见顶 vs 企业体系岗路径通高层（体系工程师→主管→经理→质量总监/管理者代表）→ 人才流向企业是理性选择。用户"企业招 ISO 专家因为 180 天"的因果校准：企业招聘的直接驱动 = 自身合规（新 GMP 2026-11-01 施行）+ 外审人才溢出；180 天是外审侧推力，两者叠加成流。
3. **产品含义**：① 流进企业的前外审员 = **企业端种子用户**（懂检查单/NC/判定逻辑，零教育成本，且会在企业内部推动工具化）；② 他们没离开审核——内审/二方审核（供应商审核）/客户审核仍是引擎同场景，**二方审核是衍生场景**；③ 180 天 = 机构产能天花板，效率工具直接扩大有效产能（隐含的机构侧价值）；④ 计划工具的"180 天人日台账"从周边功能升级为**合规刚需**（排期不能超、持证不能超 50，在岗审核员人人要管自己的配额）；⑤ 两端直服被劳动力市场验证：人才与痛点向企业端迁移，审核员端是职业入口——人迟早流到企业侧，流过去还是你的用户。

## 五之九、第二次升级突破点裁决（2026-10-22 战略收敛）

> 用户定位：3 个月闭门造车后说服不了自己有市场；本次业务分析为"第二次软件升级/转换"找突破点。

1. **突破点裁决**：不做"更大的企业资料规范化"（价值单薄），做**标准驱动的检查项生成 + 判定引擎**——以吃透标准为核心，这是软件唯一亮点，护城河所在。
2. **专家 vs 咨询公司（三件事分答）**：
   - **建合规文档**：专家个人能，垂直深度够；咨询公司赢在模板库与效率——但模板库已实证大同小异，工具补齐后**个人专家 ≈ 咨询公司**；
   - **培训**：能，无资格强制（企业内训/标准解读个人专家可做）；
   - **内审**：⚠️ 有边界——ISO 允许请外部人员参与内审，但"建体系的人审自己建的"客观性会被认证机构质疑（不是禁止，是说服力问题）⇒ 必须角色隔离。"专家一条龙"有合规裂缝，工具 + 角色分离才是正解。
   - 另：小企业"管代+体系专员一个人扛全部认证事务"是常态 ⇒ 企业端软件替代的就是这个人的重复劳动。
3. **企业端分层策略（用户提议，裁决为可执行）**：
   - ⛔ 全套企业 QMS 不做——需求真实，但单人团队做不完（记录原因，不是否认需求）；
   - ✅ **NC 预检查**（与审核员同引擎）= 认证前自检，正是内审员证的官方用途（"申请外审前的自我审查"）；价值锚 = 对标咨询公司一次预审（数千至数万），**软件把成本降到接近零**；话术："认证机构来之前，先知道自己几斤几两"；
   - ✅ 小功能打包：认证时钟（监督倒计时/证书到期/新 GMP 2026-11-01 节点）+ 迎审准备（一/二阶段前准备什么）——定位是**钩子不是卖点**（每周打开的理由；⛔ 不做成提醒工具，那是红海）；
   - 审核员版与企业版 = **同一引擎两个配置**（企业版 = 应然侧自检；审核员版 = 独立验证引用），不是两个产品。
4. **★ 第三类用户（补上）：独立专家/小型咨询**——被挤压的咨询生态里活下来的是工具增强的个体；你的软件 = "单个专家的咨询公司"（标准模型+模板库+判定引擎）；对他们按企业收费，且他们服务企业时带上工具 = 兼作渠道。合规边界：被辅导企业不得由关联机构审（36 号文档红线），工具方中立不管此事。
5. **结论陈述（解决"说服不了自己"）**：今日五轮实证构成完整证据链——① 需求实证：审核员端（朋友熬夜写报告+漏判追责恐惧+180 天产能天花板）；企业端（新 GMP 时间窗+内审双强制+咨询被挤压后自助需求+人才流入）② 竞争实证：免费 AI 卡 70%（不懂条款+找不到证据两条腿都没有）；体系内审软件空档 ③ 护城河：标准模型四要素+证据链 ④ 冷启动：尚龙材料人肉试跑+疑点清单钩子+朋友首案例。

## 五之十、价值层修正：免费 AI / 检查表 / 产品信任层（10-23，用户挑战后裁决）

**用户挑战**："你的试跑只验证了条款→文档映射，但免费 AI 就能做；且现在的检查表已整合所有依据、自动形成审核证据——产品还有什么用？"

**裁决：挑战成立，护城河叙事必须修正——归位层不是壁垒，判定层才是。**

1. **机制透明化（48 号试跑复盘）**：试跑中"按条款找到文件"靠的是三样不专有的东西——① 企业自己的编号体系（04-记录文件按 9001 章编号、表单号 `KSY-QMS-P-17-01` 自带条款映射）② 审核员通用领域知识（每类条款的常规证据类型）③ 读内容确认。任何带文件访问能力的 AI 均可复现。**把"AI 能映射条款"当卖点 = 不值钱。**
2. **"检查表已整合所有依据"的边界**：检查表预制的是**要求侧**（条款原文 + 证据槽 + 判定列，ACM QR-04-72 实证）；**证据侧永远为空**——填的是这家企业的文件号与事实。⇒ 检查表越完善，越把"找到的证据可不可信"变成唯一瓶颈。
3. **免费 AI 的六个真实缺口（= 产品位置）**：① 无来源锚点（不能点开原文比对）② 无覆盖率保证（读了多少不知道）③ 无声称-证据比对（跨文档一致性）④ 无模板态/记录态区分 ⑤ 无判定留痕（不构成审核档案）⑥ 会漂移（同输入不同输出）。
4. **一句话定位：免费 AI 生产证据草稿，产品生产证据信任。** 对应朋友原话"AI 解决 60-70% 但复核更累"——产品打的是剩余 30-40%（格式整理/准确率核对/不敢下结论），不是那 70%。
5. **48 号报告价值重定位**：证明的不是"AI 能映射条款"（ commoditized ），而是 ① 声称-证据比对可系统化（e) NC 候选）② 引用完整性/雷同检测是低成本自动检查 ③ 模板态/记录态必须区分——前两条 = 疑点引擎规则样例，第三条 = 数据模型。

## 六、下一步：人肉试跑协议（不等 DAG）

**目标**：用一场真实二阶段资料验证"漏判防护"价值，产出销售物料 + 规则校准 + 第一次自信。

1. **取材**：朋友一场已完成二阶段的完整资料（企业体系包 + 他可分享的已填检查单/报告）。
2. 对照组：让他用惯用的免费 AI 生成一份检查单（记录他实际花的耗时）。

   - **漏判账**：对照组漏了哪些项（对照朋友原版检查单），其中几条够开 NC；

4. 产出物：① 疑点清单样例（给下一个审核员看的钩子）② 规则修订清单 ③ 一页案例（时间账+漏判账）。
