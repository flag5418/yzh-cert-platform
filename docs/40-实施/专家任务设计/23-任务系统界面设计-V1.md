## 零、一句话

**3 个菜单、5 个界面**，全部按「任务 = 执行容器 / 检查项 = 长期实体 / 结果 = 多轮」这条主轴设计；
**任务系统负责「建 → 找 → 跑队列」，结果菜单只负责「审批 + 导出」**。

## 二、五个界面

### 2.1 任务中心 `/tasks` —— 任务列表

**默认排序：创建时间倒序（最新的任务在最上）。**

- **列（8 列，尽量少）**：任务编号 / 名称（同格两行）· 企业 · 阶段 · 分类 · **执行状态** · 进度 · **创建时间** · 操作
- **筛选（只留 2 个）**：搜索框（任务编号 / 企业名模糊）· 执行状态
- **分页**：每页 10 条（可选 20 / 50），底部显示「共 N 条」
- **操作**：详情 · 提交执行（仅 `draft`）· 暂停队列（仅 `running`）· 重试失败项（仅 `failed`）· 看结果（仅 `completed`）

**⛔ 明确不做**（2026-09-30 用户裁决，理由：**核心精力放在核心任务，不在边缘功能浪费时间**）：

| 砍掉的 | 理由 |
|---|---|
| ~~导出任务清单~~ | 对专家没有意义 |
| ~~复核状态列 + 筛选~~ | **错位** —— 复核状态是「结论层面」概念，下沉到结果菜单的每条结论 |
| ~~标准数 / 来源列~~ | 进详情看即可，列表不承载 |
| ~~阶段 / 分类 / 企业下拉筛选~~ | 一个专家没那么多想查的任务，**复杂查询不是重点** |
| ⛔ 不含认可 / 修改 / 批准 / 导出结果 | D31 —— 那是结果菜单的事 |

### 2.2 新建任务向导 `/tasks/create` —— 4 步

| 步 | 内容 | 关键点 |
|---|---|---|
| 1 | **企业 + 阶段 + 分类** | ★ **分类放在这一步**（业务锁需要它，且决定候选来源）；下方「系统告知」卡片显示已有任务数 / 生效检查项数 / 历史平均轮次；**业务锁实时判定**（可创建=绿条，被锁=红条 + 禁用下一步） |
| 2 | **任务来源** | `NEW` 开启全新 / `REDO` 重新执行（整体）/ `PATCH` 局部更新 |
| 3 | **检查范围** | `FULL` 全部 / `PARTIAL` 指定 + 勾选表（条款 / 检查项 / 标准 / **上次结论** / **上次检查时间** / 系统建议） |
| 4 | **确认创建** | 任务名称（必填）+ 摘要（将创建 1 任务头 · N 子任务 · M 队列项 · N 队列） |

**两个入口**（对应你的「整体和局部开启任务」）：
- 「创建新任务」→ 第 2 步默认 `NEW`
- 「从已有任务出发」→ 第 2 步默认 `REDO`，第 3 步复用上次勾选

**勾选预置规则**（来源 × 范围决定）：

| 来源 | 范围 | 预勾选 |
|---|---|---|
| NEW | FULL | 全勾（灰显） |
| NEW | PARTIAL | 不预勾选 |
| REDO | FULL | 全勾（灰显） |
| REDO | PARTIAL | 全勾，专家取消不需要的 |
| PATCH | — | 只预勾选「上次有新文件的」「上次不符合未关闭的」 |

### 2.3 任务详情 `/tasks/:code` —— 4 个 Tab

顶部：任务头（8 个指标卡）+ 进度条 + 操作按钮组
**按钮可用性由三层状态推导**：`draft` 才可提交执行 · `running` 才可暂停队列 · `completed` 才可归档 · 取消在任何未归档状态可用。

| Tab | 内容 |
|---|---|
| **标准子任务** | 子任务 Code / 标准 / 检查项数 / 执行状态 / 队列状态 / 完成·失败 / 启停 |
| **执行队列** | 每个标准 1 张队列卡：队列 Code · 总数 · 完成 · 失败 · 重试 n/N · 并发 · 耗时 + 进度条 + `启动`/`暂停` |
| **运行日志** | 时间线，见 §四 |
| **数据缺口** | 条款 / 检查项 / 缺口说明 / **阻断级别** / 处理状态 / 补录 |

### 2.4 NC 检查结果 `/nc-results` —— 左树右表

- **左树**：企业 → 阶段 → 任务（**恒 3 级**，「标准」不进树）
- **右表**：勾选 / 条款 / 检查项 / **标准**（列 + 顶部筛选）/ 结论 / **责任部门** / 复核状态 / 操作（修改 · 历史）
- **固定三件事**：勾选 → **批量审批** · 单行 → **直接修改** · 顶部 → **整体导出**（Excel / Word）
- ⛔ 点「企业」或「阶段」节点 → **右表留空**，不发请求

### 2.5 报告结论 `/report-results` —— 与 NC 同构

- 右表：勾选 / **章节号** / 章节名称 / 标准 / **生成方式** / 复核状态 / 操作
- **生成方式三档**：`自动生成` / `引用 NC 结果` / `人工撰写` —— 决定专家审核时的心理预期

### 2.6 ★ 别搞混：「执行状态」与「复核状态」

这两个词最容易误解，一次说清：

| | **执行状态** `ExecStatus` | **复核状态** `ReviewStatus` |
|---|---|---|
| 管的人 | **机器** | **专家** |
| 取值 | `draft` / `pending_run` / `running` / `completed` / `failed` | `not_started` / `pending_review` / `reviewed` / `modified` |
| 人话 | **跑完没有** | **看完没有** |
| **决定业务锁？** | ✅ **是**（`completed` 即解锁） | ❌ **否，完全不影响** |
| **出现在哪** | **任务列表 / 任务详情** | **只在两个结果菜单的每条结论上** |

> ⚠️ **`cert_expert_task.ReviewStatus` 字段保留**（不删，避免改表），但**不进任何界面**。
> 任务详情页只用一个**待办数字**代替：`待审批结论 19 / 24` —— 点「查看 NC 结果」去处理。

## 三、我替你定的决策（★ 请逐条确认，不同意直接说）

| # | 决策 | 理由 | 备选 |
|---|---|---|---|
| **D-A** | 任务中心用 **3 个子路由**（`/tasks`、`/tasks/create`、`/tasks/:code`），不用弹窗/抽屉 | 向导 4 步 + 详情 4 Tab 内容多，弹窗放不下；子路由可分享链接、可刷新 | 弹窗 / 抽屉 |
| **D-B** | **「分类」放在向导第 1 步**，不在菜单上隐含 | 业务锁按「企业+阶段+**分类**」判定，第 1 步就必须知道分类；且决定候选取 `cert_validation_rule` 还是 `cert_report_section` | 由入口菜单带入（任务中心建的都算 NC） |
| **D-C** | **「提交执行」与「启动队列」拆成两个动作** | 一个任务可能挂 2 个队列（2 个标准），**允许分批跑**（先跑 ISO 9001，确认没问题再跑 ISO 14001） | 提交即全跑 |
| **D-D** | 任务详情 **4 个 Tab**，含「数据缺口」 | 缺口直接决定"哪些项跑不出结果"，专家必须看得见 | 缺口只进日志 |
| **D-E** | 结果菜单右表**加「责任部门」列**，**值先全部显示 `—`** | ✅ **用户 2026-09-30 已确认**：列先加、数据先空，以后补数据不改表结构 | 暂不加列 |
| **D-G** | 任务列表**默认创建时间倒序** | ✅ **用户 2026-09-30 已定**：最新任务在最上 | 按状态排 |
| **D-H** | 任务列表**分页**（每页 10） | ✅ 已定：一个专家没那么多想查的任务 | 无限滚动 |
| **D-I** | 任务列表**只留 2 个筛选**，删掉导出 | ✅ 已定：**查询不是重点** | 保留完整筛选 |
| **D-J** | **任务层不出现「复核状态」** | ✅ 已定：它属结论层面，下沉到结果菜单；字段保留但不进界面 | 列表加复核状态列 |
| **D-F** | 报告结论的**「生成方式」三档**要显示 | 专家看到「人工撰写」就知道这章要自己写，不会白等自动结果 | 不显示 |

## 四、日志埋点清单（★ 你要求「多埋点日志」）

**四级、22 个事件**，全部落 `cert_expert_task_log`，字段含
`TaskCode` / `QueueCode` / `ItemCode` / `Level` / `Event` / `Message` / `Payload` / `CostMs` / `CreateTime`。

| 级别 | 事件 |
|---|---|
| **任务级** | `task.created` · `task.lock.acquired` · `task.submitted` · `task.progress` · `task.paused` · `task.resumed` · `task.finished` · `task.cancelled` · `task.archived` |
| **范围级** | `scope.resolved` · `item.derived`（复用 N / 新建 M）· `item.orphan.cleaned` |
| **队列级** | `queue.created` · `queue.started` · `queue.paused` · `queue.progress` · `queue.finished` |
| **项级** | `item.extract.ok` · `item.extract.retry` · `item.extract.fail` · `item.judge.ok` · `item.judge.nc` · `item.skip` · `gap.created` |

**三个埋点原则**：
1. **进队列、出队列、状态跃迁**必打 —— 出问题能一眼看出卡在哪一步。
2. **`CostMs` 必带** —— 耗时异常是提取失败的前兆。
3. **`Payload` 存关键入参**（文件路径、版本戳、规则 Code），但**不存文件内容**。
