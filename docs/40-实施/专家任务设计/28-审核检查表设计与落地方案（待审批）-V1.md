## 一、结论速览

| 问题 | 结论 |
|---|---|
| **是否仍在人工编写？** | **是。** 传统体系审核的检查表就是审核员**人工逐条填写**（[12 §1.1](12-业务全景图-任务平台-V1.md) 明确把"审核员人工填写检查表"列为要替代的对象）。触发样本 51 页、`审核证据`列几乎全为人工访谈/现场记录。 |
| **是否常用的一环？** | **是，且比 NC / 报告更基础。** 检查表是**每次审核必产的记录**（CNAS 认可要求，[15 号 P0-7](../../50-扩展/规划与优先级/15-规模化架构升级与优先级矩阵-V1.md) 称其为"CNAS 必杀项，之前遗漏"）；NC 是它的**子集**（可能为 0），报告是它的**汇总统计**。频率：检查表 ≥ 报告 > NC。 |
| **是否按"标准+阶段"固定？** | **分两层：配置层=固定（机构+标准+阶段[+条款]）；执行层=不固定（企业+审核次）。** 与现有 `cert_validation_rule`（NC 规则）、`cert_report_section`（报告章节）、`cert_standard_directory_config`（资料清单）**同构**——见 §三。 |
| **能否按现系统实施？** | **可以，且无需新建规则引擎。** 检查表所需的绝大部分数据模型**已存在**（见 §四），缺口只有 3 处（§六）。 |

## 二、业务关系：检查表是 NC 与报告的"上游母集"

```
        ┌─────────────────────────────────────────────┐
        │  审核检查表（逐条款：要求 → 证据 → 判定）        │  ← 母集，每次必产
        └───────────────┬─────────────────┬───────────┘
       判定=nonconform   │                 │ 汇总统计（符合X/不符合Y/不适用Z）
              ▼           │                 ▼
     ┌────────────┐       │        ┌────────────────┐
     │  NC 记录    │       │        │  体系认证报告    │
     │（子集，可0条）│       │        │（章节正文+统计）  │
     └────────────┘       │        └────────────────┘
```

- **NC**：检查表中 `判定 = nonconform` 的行 → 生成 `cert_nc`（[03 §1.1](03-详细设计-NC检查-V1.md)）。
- **报告**：工作流节点 `stat_checklist → 统计检查表结果（符合X/不符合Y/不适用Z）`（`docs/20-体系认证/01-总体设计/核心工作原理-V1.md:359`）。
- **推论**：**检查表规则 = NC 规则的上位**。一套"要查哪些条款、怎么判、什么严重度"的配置，同时驱动检查表与 NC；报告只消费检查表的判定结果。

## 三、"是否按标准+阶段固定"——分两层回答

| 层 | 固定维度 | 现有承载 | 说明 |
|---|---|---|---|
| **配置层**（查哪些 / 怎么判） | **机构 + 标准 + 阶段（+ 条款）** | `cert_validation_rule`（NC 规则，字段 `OrgCode/StandardCode/PhaseCode/ClauseCode/JudgeMode/SeverityIfViolated`）；`cert_report_section`（报告章节，三元组 `OrgCode/StandardCode/PhaseCode`）；`cert_standard_directory_config`（资料清单，`OrgCode+EnterpriseCode+StandardCode+StageCode`） | **固定**。同一标准+阶段，对所有企业用同一套检查项清单。 |
| **执行层**（证据 / 判定结果） | **企业 + 阶段 + 标准 + 规则** | `cert_expert_nc_item`（检查项，四元组 `EnterpriseCode/StageCode/StandardCode/RuleCode`）×`cert_expert_nc_result`（多轮结论） | **不固定**。每家企业每次审核各产一套证据与结论。 |

**已存在的"标准+阶段级检查表锚点"**：`cert_standard_phase_config`（表 `StandardPhaseConfig.cs`）自带 `RequiredClauses`（必查条款）+ `RequiredFiles`（必交文件）两列 —— 语义上**正是检查表的"应查条款清单"**。该表**当前 0 行、无引用**，可直接启用，无需建新表。

> ★ 结论：**检查表规则按"标准+阶段"固定是对的，且现系统已有对应配置位**；不要新建平行规则表（触犯"核心资源唯一入口"口径，见 `docs/30-项目规则/跨端共享与核心资源检索规则-V1.md`）。

## 五、定位与边界（避免与产品方向打架）

| 维度 | 定位 | 理由 |
|---|---|---|
| **主数据源** | ⛔ **不是**。主数据源仍是"企业文档流程化提取"（[12 §1.1](12-业务全景图-任务平台-V1.md)） | 否则等于退回被替代的"人工填写"老路 |
| **交付物 / 记录物** | ✅ **是**。检查表 = 认证交付与认可留痕产物（CNAS/ISO 19011） | 报告与 NC 都由它派生 |
| **人工项兜底** | ✅ **是**。访谈 / 现场观察 / "某设备是否存在" 类条目天然 `JudgeMode=manual` | 系统已建模，检查表能把这块接住 |
| **不做** | 审核计划 / 人天 / 证书 / 收费 等证明周期管理 | [12 §1.3](12-业务全景图-任务平台-V1.md) 本期不做 |

## 六、实现方案（三处增量，复用为主）

### 增量①：检查表视图 + 导出（核心）

- 数据源：现有 `cert_expert_nc_item` + `cert_expert_nc_result`（按 `CurrentResultCode` 取当前轮）+ JOIN `cert_iso_clause` 取"要求"。
- 列头按检查表格式：`过程/区域｜条款｜要求｜审核证据｜NC/OFI`。
- **分组**：按"过程/区域"分组（依赖增量③）；无该维度时降级为按条款号排序（[21-架构判断](21-架构判断-V1.md)：部门配置降级为可选）。
- 导出 Word/Excel，套 `ACM/QR-04-72` 式表单模板（可复用报告模板引擎的导出管线）。
- 复用点：`ExpertResultPanel.vue` 的列表 + 导出；`ExpertResultController` 的 CSV/导出（`:1058`）。

### 增量②：审核证据可人工编辑

- `cert_expert_nc_result.EvidenceRef` / `ContentText` 已支持编辑（`ExpertResultPanel` 编辑表单已有"客观证据/不符合描述"）。
- 补：允许 `JudgeMode=manual` 的条目**无 AI 产出即可手填证据+判定**（当前 manual 走 `MarkSkipped(manual_mode)`，需改为"待人工填写"而非"跳过"）。

### 增量③：补"过程/区域（部门）"维度

- `ResponsibleDept` 从占位改为可配：建议挂在 `cert_validation_rule`（配置层）上，按标准+阶段批量指定"该条款归属哪个部门/过程"。
- 依据：[后台结构审查与产品形态评估-V1.md](../../40-实施/分析报告/后台结构审查与产品形态评估-V1.md) 标为 **★★★最高**（"检查表若只能按条款编号输出 → 现场没法用"，**单标准也需要**）。

## 十、附：体系认证全流程与本系统定位

> 本节回答"检查表/NC/报告这几个阶段，在整个体系认证里到底站在哪"。★ **当前阶段 = 审核实施（现场审核）阶段**：审核员拿"检查表"逐条款采集证据并判定 → 不符合变成 **NC** → 全部判定汇总成 **报告**。它是整个认证里**唯一直接产出审核结论**的一段，也是本系统聚焦的核心。

### 10.1 图 A · 体系认证全生命周期（ISO 17021）与本系统覆盖

```
 阶段              认证机构 / 审核员做的事                企业侧          本系统
──────────────────────────────────────────────────────────────────────────────────
 ① 认证准备        申请受理 · 合同评审 · 定审核方案         提交申请
   (受理/合同)     审核计划 · 审核组 · 人天计算
 ② 文件评审        一阶段审核（审体系文件）         ←── 上传体系文件 ──→   ✅ 资料规范化
   (一阶段)        ← 预审：文件齐不齐、对不对                              + 预审(规则校验)
                                                                          └ 数据入库
 ③ 现场审核        ★ 二阶段审核（现场）                                  ▲▲▲ 当前阶段 ▲▲▲
   ├ 检查表         逐条款：要求→证据→判定   ┐                              ✅ 检查表(新增)
   ├ NC 检查        不符合 → 开 NC           ├─ 现场配合 · 受审核            ✅ NC 检查(核心)
   └ 报告生成       汇总统计 → 章节正文      ┘                              ✅ 报告生成(核心)
──────────────────────────────────────────────────────────────────────────────────
 ④ 不符合整改      审核员验证整改 · 关闭 NC    ←── 企业提交整改证据 ──→    ⏳ 本期不做
 ⑤ 认证决定        技术委员会 / 认证决定人                                  ⛔ 不做
 ⑥ 发证            证书颁发（3 年有效）                                     ⛔ 不做
 ⑦ 监督审核        SV 每年 1 次（可缩小范围）                               🔶 局部任务场景
 ⑧ 再认证          RC 满 3 年                                               🔶 不做周期模型
```

**读图要点**：整个认证是「准备 → 文件评审 → 现场审核 → 整改 → 决定 → 发证 → 监督 → 再认证」的长链；本系统只做**第 ②③ 段**（+ ③ 的上游数据准备），其余为管理层功能，明确不在本期（[12 §1.2/§1.3](12-业务全景图-任务平台-V1.md)）。

### 10.3 图 C · 当前阶段放大：检查表是母集，NC 与报告是下游

```
                  审核检查表（逐条款记录）
        ┌────────────────────────────────────────────┐
        │ 过程/区域 │ 条款 │ 要求 │ 审核证据 │ 判定     │
        └───────────────────┬────────────────────────┘
                            │ 每行判定 ∈ {conform, nonconform, observation, na}
          ┌─────────────────┼──────────────────┬─────────────┐
          ▼                 ▼                  ▼             ▼
      conform           nonconform        observation       na
       （符合）            （不符合）         （观察项/OFI）   （不适用）
      留痕留档              │                  │           留痕
                            ▼                  ▼
                      NC 记录 cert_nc      观察项
                     （可 0 条）
                            │
                            └────┐
                                 ▼
        报告章节 = 汇总统计（符合 X / 不符合 Y / 不适用 Z）+ 正文
```

**三者关系**：检查表 = **母集**（每次审核必产）｜NC = **子集**（判定不符合的行，可能 0 条）｜报告 = **汇总**（统计检查表结论 + 正文）。

### 10.4 当前阶段在认证中的地位（总览表）

| 维度 | 当前阶段（审核实施 + 报告） |
|---|---|
| 生命周期位置 | 第 ③ 段（现场审核）；上游 = 文件评审/资料规范化，下游 = 整改 → 认证决定 → 发证 |
| 产出 | 检查表、NC、审核报告 —— **全部审核结论都来自这一段** |
| 消费方 | 认证决定委员会、企业（整改）、后续监督/再认证 |
| 频率 | 检查表 ≥ 报告 > NC（每企业每阶段都走） |
| 本系统定位 | **聚焦这一段做深**（"工具型辅助系统"），不做认证决定/发证/周期管理 |
| 配置 vs 结果 | 配置层按「机构+标准+阶段」**固定**；结果层按「企业+审核次」**不固定** |
