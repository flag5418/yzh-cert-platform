### 3.2 ★ B6：`NodeExecutor` 取数口径缺陷修复（阻塞项，0.5 人天）

**实测缺陷**（`NodeExecutor.cs` `ExecuteDocFieldAsync` / `ExecuteDocTableAsync`）：

```csharp
// 现存代码
var field = (await _db.GetOneAsync<ExtractionResult>(x =>
    x.FieldCode == fieldCode && x.EnterpriseCode == enterpriseCode)).Data;
// ⛔ 无 StandardCode 过滤  → 多标准串数据
// ⛔ 无 IsValid=1 过滤    → 读到归档的旧版本（★最严重：拿旧文件数据算新结论）
// ⛔ 无 FileCode 过滤     → 多份文件时取到哪份不确定
```

| 缺陷 | 后果 | 严重度 |
|---|---|---|
| 无 `IsValid = 1` | 文件替换后旧版本被 `InvalidateActiveAsync` 归档，但这里仍可能取到 → **拿旧文件的数据算出新结论** | ★★★ |
| 无 `StandardCode` | ISO9001 的规则读到 ISO14001 的提取值 | ★★★ |
| 无 `FileCode` | 同企业多份文件含同名字段时不确定 | ★★ |

**修复方案（二选一）**：

| 方案 | 做法 | 评价 |
|---|---|---|
| **甲（推荐）** | 改 `ExecuteDocFieldAsync` / `ExecuteDocTableAsync`：优先从 `context.ExtractionData` 读（由 `WorkflowInterpreter` 预置），回落到查库（补全三个过滤条件） | 单一取数口径，且 `context` 便于测试与调试 |
| 乙 | 只在执行前用 `GetActiveAsync`（按企业+标准+阶段）预热缓存，`docfield` 从缓存读 | 同甲，但缓存需额外管理 |

> ⚠️ `src/yzh-core/` 是框架层，**可以改**（AGENTS.md 第 11 条），但 `NodeExecutor` 在 `CertPlatform.Admin/Services/Workflow/`（业务层），改起来无框架层阻力。

### 5.3 状态机实现

```csharp
// 状态流转表（集中定义，避免散落在各处）
private static readonly Dictionary<(string from, string to)[]> AllowedTransitions = new()
{
    new[] { "draft", "gap_detected" },
    new[] { "draft", "pending_run" },
    new[] { "draft", "cancelled" },
    new[] { "gap_detected", "pending_run" },
    new[] { "gap_detected", "cancelled" },
    new[] { "pending_run", "running" },
    new[] { "pending_run", "cancelled" },
    new[] { "running", "pending_review" },
    new[] { "running", "cancelled" },
    new[] { "pending_review", "approved" },
    new[] { "pending_review", "running" },      // rerun
    new[] { "pending_review", "cancelled" },
    new[] { "failed", "pending_run" },          // 重新提交
    new[] { "failed", "cancelled" },
};

private void EnsureTransition(string current, string target)
{
    if (!AllowedTransitions.Any(t => t[0] == current && t[1] == target))
        throw new BizException("TASK_STATUS_INVALID",
            $"任务状态不能从「{current}」变更为「{target}」");
}
```

## 十二、验收总清单（对应 01 号 §七）

> 专家选企业+阶段 → 系统告知缺 3 个字段 → 专家补录 2 个、跳过 1 个 → 提交 → 队列跑出 5 条结果（4 条正常 + 1 条跳过）→ 专家改 1 条认可 4 条 → 批准 → 导出 Excel 5 个 Sheet（按标准分）→ 每条结果都能查到谁在什么时候改了什么

| 步骤 | 验收点 | 对应 S |
|---|---|---|
| 选企业+阶段 | 锁态正确（无任务/有任务两种） | S2 |
| 缺 3 个字段 | 完备性检查产出 3 条 gap，标"影响 N 条规则" | S3 |
| 补录 2 个 | `cert_extraction_result.ValueSource='manual'` + 日志 | S3 |
| 跳过 1 个 | `GapStatus='skipped'` | S3 |
| 提交 | 队列按标准拆分 | S4 |
| 跑出 5 条 | 4 条 `ok/ng` + 1 条 `skipped(data_gap)`，`autoResult=null` | S4 |
| 改 1 条 | `ReviewStatus='modified'` + 逐字段 diff 日志 | S5 |
| 认可 4 条 | `ReviewStatus='acknowledged'` + 日志 | S5 |
| 批准 | 全部 `pending=0` → `approved` + 冻结 | S5 |
| 导出 5 Sheet | 3 标准 + NC 侧 2 Sheet，汇总含"未检查" | S5 |
| 追溯 | 从结论 → `cert_expert_task_log` 时间线 → NC 记录 | S5 |
