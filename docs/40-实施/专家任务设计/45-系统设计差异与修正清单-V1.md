# 45-系统设计差异与修正清单 V1

> 来源：2026-10-21 战略讨论（见 44 号文档）发现的系统设计偏差。
> 用法：「现有设计」摘自 28-43 号文档系列；「修正认知」是讨论后的正确模型；「待补充」列留给实施时逐条填写（做什么、谁做、何时、关联哪个文档）。
> 优先级说明：P0=不修则产品逻辑错误；P1=影响完整度；P2=优化项。

## A. 检查项维度模型（检查项与部门交叉问题）

| 编号 | 设计项 | 现有设计 | 修正认知 | 级别 | 待补充 |
|---|---|---|---|---|---|
| A1 | 检查项维度 | 条款 × 部门 × 过程（36 号），三标准 M:N | **条款 × 过程 × 部门 × 阶段 × 品类**五维；「阶段」必须是一等公民维度而非后补字段 | P0 | |
| A2 | 各阶段检查表 | 未见分阶段模板 | 四类模板：一阶段（准备度，**无 NC**）、二阶段（全覆盖）、监督（抽样+上期 NC 整改+变更）、再认证（全覆盖+历史）；同一过程在不同阶段检查项不同 | P0 | |
| A3 | 一阶段 NC 概念 | NC 检查体系（03 号）未区分阶段性质 | 一阶段输出「二阶段前需解决的问题」清单，**不开 NC**；NC 判定仅限二阶段/监督/再认证 | P0 | |
| A4 | NC 归属 | NC 数据模型（18 号）缺部门归属 | NC 必须带**结构化的部门字段**（非自由文本），支撑整改任务自动分派 | P1 | |
| A5 | 过程 vs 部门 | 已有 ProcessAreaName 且「过程/区域≠部门」结论正确 | 保持：检查项挂「条款×过程」，执行层才映射「部门×陪审人」；确认真实案例表格的负责人字段按此建模 | P1 | |
| A6 | 陪审安排 | 06 号表设计未见陪审人 | 新增陪审人维度：按部门分派（尚龙「陪审人员」表为真实样本），与检查项执行绑定 | P1 | |
| A7 | 部门主数据 D28 | 36 号记录为前置阻塞 | 仍阻塞，且 13485 品类化后口径不变：先解部门表再谈检查项落地 | P0 | |

## B. 证据链（13485 判定正解）

| 编号 | 设计项 | 现有设计 | 修正认知 | 级别 | 待补充 |
|---|---|---|---|---|---|
| B1 | 应然侧基准 | 证据三源（31/35/36 号）：认证资料=应然、原始资料=实然一半、现场=实然另一半 | 三源模型正确，但**判定基准必须显式化为「要求库」**：标准条款 + 法规条目 + 企业文件承诺三合一，检查项才能挂要求。现有 GapDetector 判定的对照物需从「资料」升级为「要求」 | P0 | |
| B2 | AI 角色边界 | JudgeMode/AI 节点承担判定 | **AI 只做三件事：归位（证据挂到检查项）、比对（证据 vs 要求）、提示缺口**；不得生成证据、不得自动出结论 | P0 | |
| B3 | NC 人工拍板 | NC 生成链路未见人工确认状态机 | NC = **候选态**（证据摘要+条款依据+差距描述）→ 审核员确认/否决/改写 → 生效；人工确认记录即尽职留痕证据 | P0 | |
| B4 | 采集方式 | 证据收集流程化（31 号） | 必须**检查项驱动**（每个检查项一个采集任务：拍照/录音/文档/记录抽样），四要素绑定（时间/地点/对象/来源方式）；离线采集、联网同步 | P0 | |
| B5 | 录音授权 | 未见 | 录音涉及员工声音，须**单独告知同意**环节 + 产品内授权留痕（个人信息保护） | P0 | |
| B6 | 要求库数据结构 | 规则引擎以参数/rule_json 为主 | 13485 规则库四层知识：条款层（ISO 13485/YY 0287）+ 法规层（27 项目录式，带版本与受控状态）+ 企业文件层 + 专家经验层；**先做法规层种子（尚龙案例已有）** | P0 | |

## D. 产品形态与定位

| 编号 | 设计项 | 现有设计 | 修正认知 | 级别 | 待补充 |
|---|---|---|---|---|---|
| D1 | 全体系通用 | 专家任务设计为通用平台（多标准） | **收敛为 ISO 13485 单标准垂直**（44 号结论）；通用框架保留，规则库全部垂直重构；单品类起步（第一类/简单器械） | P0 | |
| D2 | 规范化时序 | 企业资料规范化定位模糊（贯穿审核） | 规范化发生在**认证申请前**（企业建体系）；一阶段=审查暴露缺口；一~二阶段之间=整改；二阶段=验证实然；监督=变更控制增量。产品窗口据此重排 | P0 | |
| D3 | 企业端模块 | 企业资料规范化单一功能 | 拆两模块：**「建体系」**（规范化+文档树体检，认证前窗口）+ **「养体系」**（变更跟踪+监督倒计时+历史 NC 整改台账，监督阶段） | P0 | |
| D4 | NC 预检查时机 | NC 检查挂在审核执行 | 增加**一~二阶段之间**的企业自查窗口（企业最愿意买的预检点） | P1 | |
| D5 | 180 天台账 | 未见 | 审核员侧仪表盘：全口径现场天数（含实习/专业实习/见证，不含境外、非现场、产品服务认证）；超限预警=审核员个人刚需 | P1 | |
| D6 | 机构侧功能 | 43 号起讨论机构复核 | 降为第三层：先审核员端（漏斗）+ 企业端（利润），机构端（复核/报送）在案例积累后进入；报送四 SLA 作为机构侧钩子设计但不立项 | P2 | |
| D7 | 检查项=工作流 | 一个检查项=一个工作流（34/35 号） | 编排模式可保留；但 13485 垂直后，规则库从「参数化配置」转为「四层知识库 + 版本管理」，工作流只做执行层 | P1 | |
| D8 | 部门维度落地 | D28 阻塞 | 13485 品类下仍需部门主数据；评审人/陪审人/整改人全部挂部门 Code | P0 | |
