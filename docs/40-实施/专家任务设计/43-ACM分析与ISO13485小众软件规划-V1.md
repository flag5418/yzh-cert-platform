## 一、结论速览

| # | 问题 | 结论 |
|---|---|---|
| 1 | ACM 是不是真机构？ | **是**。英国主体 2022 年成立，IAS MSCB-345，中国 22 个分支，2023 年中国新发 6,313 张证书。属于**挑战者**，不是 SGS / TÜV / BSI 一档。 |
| 2 | 1000+ 专家是不是 13485 审核员？ | **不是**。官网写 500+ auditors；1000+ 更可能是全标准 / 兼职专家网络。**13485 只是子集**。 |
| 3 | 13485 新发证少，是不是不能做？ | **不是**。新发证只影响增量；存量每年监督审核、三年再认证，审计事件远多于新发证。真正要算的是 **单项目人工工作量 + 专家座位 + 付费意愿**。 |
| 4 | 13485 小众软件能不能做？ | **能做**，但定义必须是 **“13485 审核证据与 NC 工作台”**，不是 eQMS。 |
| 5 | ACM 能不能作为唯一客户？ | **不能**。ACM 是设计伙伴 / 案例 / 背书；市场要放到更广的 13485 审核员、咨询师、企业。 |
| 6 | 先做什么？ | **3 条款 × 3 NC 的 MVP**，3 位审核员试点，6 个月见付费信号。 |
| 7 | 为什么只做一两个标准？ | 复杂标准（13485 / IATF 16949 / ISO 22000 等）**专家稀缺、风险高、工具空白、付费意愿高**；ISO 9001 这类通用标准会被通用 AI 工具压价。**做深一个，比做全十个更值钱。** |
| 8 | 产品最难的部分是什么？ | 不是模型，是 **专家愿不愿意用**。朋友和成都专家反馈：专家电脑水平很基础，机构也没给好工具 ⇒ 产品必须极简、零培训、能导出 Word。 |
| 9 | 「做一两个标准」这个判断成立吗？ | **半成立**。⛔「竞品也只做一两个」不成立——实测 4 家宣称 9–14 个标准；机构采购常按“支持标准数”比价。⇒ 必须区分 **「宣称覆盖」（宽）与「深度交付」（窄）**（§8.5）。 |
| 10 | 真正的分界是「标准」吗？ | **不是**。是 **「应然 vs 实然」**：手册/程序文件（应然）可被 AI 生成、已被 ¥990/年 打穿；记录/证据/NC/报告（实然）必须来自真实数据、尚未商品化。**定位 = 做所有标准的实然侧**（§4.6）。⚠️ 实然侧再分：**运行记录不可生成；事实文档可从原始资料提取**（§4.6.5）。 |
| 11 | 对外能不能说“AI 帮你验证结论”？ | **⛔ 绝对不能说**。等于对干了 20 年的审核员说“你可能判错了”。改为 **“查漏 / 判定尺度一致 / 证据可追溯”**（§5.10）。 |
| 12 | 有没有比“谁付钱”更硬的问题？ | **有两条**：① **数据合规**（企业资料上传 = 客户机密离开机构，13485 还可能含患者/临床数据）② **责任归属**（AI 判错谁担责 ⇒ 必须“建议→签核→留痕”）（§9.8）。 |
| 13 | 13485 的“代价大”具体指什么？ | ⛔ 不是“证书被撤销”，是 **“判定错一次，机构与审核员要担责”**。所以机构买的是**风险转移**，不是效率——这才是 13485 能收高价的真实原因。 |

**一句话**：

> **ACM 是设计伙伴，不是市场；13485 是复杂标准专业工具的起点，不是全部标准。**
>
> **真正要卖的不是“标准”，是“实然侧的证据链与判定”——这条线跨所有标准，这才是市场。**
>
> **企业端不是“模板生成”，是“事实文档 + 预 NC”：从原始资料提取事实、逐句绑定出处、缺证据标缺口。**

### 2.3 对产品的五个含义

1. **不要按 1000 个座位设计**。先按 20–50 个 13485 审核员 + 数百个咨询师设计。
2. **13485 是楔子；Q/E/S 是 ACM 的大盘，但通用标准付费意愿低，不作为你的第二标准首选**。引擎要标准无关，领域包按标准替换。
3. **13485 在中国是分包**。证书主体、认可标识、认证决定、审核数据归属，必须先核实。
4. **1000+ 专家网络的痛点是校准和一致性**。买家更可能是技术评审 / 质量负责人，不是每个审核员。
5. **ACM 是挑战者**，需要差异化和产能；工具能帮忙，但机构采购慢、合规要求高。

### 2.4 为什么“新发证数”不是核心指标

| 指标 | 为什么不是核心 | 更该看什么 |
|---|---|---|
| 新发证数 | 只代表增量；存量证书每年监督、三年再认证，审计事件更多 | **审计事件数** = 存量 × 监督频次 + 再认证 + 新发证 |
| 证书总数 | 只代表企业数，不代表审核工作量 | **单项目人工工作量**（人日、文档量、NC 数） |
| 专家总数 | 不代表 13485 审核员数，也不代表付费座位 | **13485 审核员 / 技术评审 / 咨询师座位** |
| 机构数量 | 不代表采购意愿 | **谁痛、谁付钱、谁签字** |

**结论**：13485 的生意逻辑不是“每年新增多少证”，而是：

1. 存量企业每年都要监督审核；
2. 复杂标准单项目人工工作量大；
3. 专家稀缺、工具空白，愿意为“省时间 / 少返工 / 不漏项”付费；
4. 一个专家一年做多个项目，**座位价值 > 证书增量**。

> **新发证是“增量信号”，不是“市场大小”。** 对复杂标准，存量复审 + 单项目工作量才是基本盘。

## 三、ACM 作为渠道 / 伙伴：价值与边界

### 3.1 能给你的价值

| 价值 | 具体内容 | 怎么用 |
|---|---|---|

| 试点场景 | 2–3 个真实 13485 项目 | 验证省时、NC 采纳率、复核返工 |
| 背书 | 试点成功后的机构证明 | 对咨询师 / 企业销售时的信任资产 |

### 3.2 必须看清的边界

| 边界 | 说明 | 应对 |
|---|---|---|
| 13485 体量小 | 2023 年新发 70 张 | 不把 ACM 当唯一市场；扩到咨询师 / 企业 / 其他 CB |
| 13485 依赖分包 | AXE（意大利）分包 | 先核实证书主体 / 认可标识 / 数据归属；不深度绑定 |
| 采购慢 | 机构供应商准入、安全审查、合同流程 | 先做小试点；咨询师端先走 |
| 收入冲突 | CB 按审核人日收费，工具省时间可能减少计费人日 | 卖“产能 / 一致性 / 复核效率”，不卖“少审几天” |
| 公正性 | 审核工具不能变成咨询工具 | 审核 / 咨询两条产品线隔离；同一客户禁止两头服务 |
| 专家是网络不是员工 | 1000+ 专家可能多为兼职 / 合作 | 先做个人价值，再做机构推广；不能强制采用 |

### 3.3 合作原则

1. **标准产品 + 付费试点**，不做定制外包。
2. **不签独家、不卖源码、不接受超低价**。
3. **数据 / 案例授权写进合同**：匿名化、不训练、不宣传客户名。
4. **试点有明确成功标准**：省时 ≥30%、NC 采纳率 ≥50%、2/3 人愿意第二次使用。
5. **审核 / 咨询分线**：同一客户不得“既咨询又审核”。

## 四、市场边界：ACM 不是市场

### 4.1 中国 13485 基本盘

| 口径 | 数量 | 说明 |
|---|---:|---|
| 中国医疗器械生产企业 | **3.3 万家左右** | NMPA 2024：32,752 家；行业口径 34,894 家 |
| 全球 ISO 13485 证书 | **32,963 张**（2023） | ISO Survey 2023；中国数据缺失，实际更高 |
| 全球 13485 认证场所 | **5.3 万个** | ISO Survey 2023 |
| 中国 13485 证书 | **万级** | 估算；中国是增长最快市场之一（约 27%/年） |
| 13485 审核员 / 咨询师 | **数千人** | 估算；分散在各 CB、咨询公司 |

### 4.2 ACM 的审计事件量级

- 2023 年中国新发 13485：**70 张**（只是增量）。
- 存量按 **200–400 张**估算；每年监督 + 再认证 + 新发证，审计事件约 **300–600 个/年**。
- 13485 审核员可能 **20–50 人**；1000+ 专家里 13485 只是小部分。
- 如果按 3,000–5,000 元/年/人、30–50 个座位算：**9–25 万元/年**。
- **结论**：ACM 的 13485 座位市场，仍然养不活一个产品；它的价值是 **试点 / 案例 / 背书**，不是收入大盘。

> 注意：这里算的是 **ACM 一家**。真正的市场是“所有 13485 审核员 + 咨询师 + 企业”，不是 ACM 的证书增量。

### 4.3 TAM / SAM / SOM（估算，需验证）

| 层级 | 假设 | 年收入潜力 |
|---|---|---:|
| TAM（企业口径） | 3.3 万家企业 × 10% 付费 × 5,000 元 | ~1,650 万元 |
| SAM（企业+咨询师） | 1–2 万家 13485 企业 + 2,000–5,000 咨询师 | ~1–3 亿元 |
| SOM（3 年） | 200–500 个付费账户 × 3,000–10,000 元 | **60–500 万元 ARR** |

> 更贴近本产品的算法：**2,000–5,000 名 13485 审核员 / 咨询师 × 20% 付费 × 3,000–5,000 元 = 120–500 万元/年**；加上企业自查，3 年做到 **300–800 万元 ARR** 是合理上限。

> 这是一个 **2–5 人小团队可以活得很好的小生意**，不是 VC 级平台。正好符合“小众软件”的定位。

### 4.4 结论

- **ACM = 设计伙伴 / 案例 / 背书 / 首批试点**。
- **市场 = 更广的 13485 审核员、咨询师、企业**。
- **Q/E/S = 通用标准，付费意愿低，不作为第二标准首选**。
- **第二标准 = 另一个复杂标准**（IATF 16949 / ISO 22000 / ISO 17025 / ISO 27001），按专家资源选，不按 TAM 选。

### 4.5 标准选择矩阵：只做“复杂、风险高、工具空白”的标准

| 标准 | 复杂度 | 风险 / 责任 | 专家稀缺 | 工具空白 | 付费意愿 | 建议 |
|---|---|---|---|---|---|---|
| ISO 9001 | 低 | 低 | 低 | 低 | 低 | **应然侧不做；实然侧可做**（审核量最大，见 §4.6） |
| ISO 14001 / 45001 | 中 | 中 | 中 | 低 | 中 | 不做主战场 |
| **ISO 13485** | **高** | **高** | **高** | **高** | **高** | **第一标准** |
| IATF 16949 | 很高 | 很高 | 很高 | 高 | 很高 | 第二候选（有汽车专家） |
| ISO 22000 / FSSC 22000 | 高 | 高 | 中高 | 中 | 高 | 第二候选（有食品专家） |
| ISO/IEC 17025 | 高 | 高 | 高 | 中 | 中高 | 第二候选（有实验室专家） |
| ISO/IEC 27001 | 高 | 高 | 中 | 中（工具多） | 高 | 暂不优先（竞争拥挤） |

**选择规则**：

1. 先看 **有没有 5–10 位专家**愿意共建 / 试点；
2. 再看 **单项目人工工作量**是否足够大（≥2 人日报告 / 检查表）；
3. 再看 **工具空白**（专家是否“没见过类似工具”）；
4. 最后看 TAM。

> ⛔ 不要按“证书数量最多”选标准；那是 ISO 9001 的逻辑，不是复杂标准的逻辑。

### 4.6 定位的真正分界：应然 vs 实然（V3 核心重构）

§4.5 的矩阵按“标准”选，**方向只对了一半**。真正的分界不在标准之间，而在**同一本标准内部的两类产物**。

#### 4.6.1 两类产物

| 产物 | 性质 | 能否模板 / AI 生成 | 现状 |
|---|---|---|---|
| 手册、程序文件、作业指导书 | **应然**（应该怎么做） | ✅ 能 | **已被 ¥990/年 打穿**（`iso.figo.cn` 普惠版） |
| 记录、表单、证据、NC、报告 | **实然**（实际做了什么） | ⚠️ **运行记录不可生成；事实文档可从原始资料提取**（见 §4.6.5） | **尚未商品化**（`isopilot.it` 只能靠人工顾问补位） |

**关键事实**：**9001 也有实然侧**（记录、内审、管理评审、供应商评价）；**13485 也有应然侧**（手册、程序文件、设计开发文档模板）。所以这不是“标准 A vs 标准 B”。

> **⛔ 把定位说成“我做 13485”会招来“那你只做一个小市场”。**
> **✅ 应该说“我做所有标准的实然侧——证据、判定、报告；应然侧我不做，因为那已经没利润了”。**

这句话同时解决三件事：① 市场从“1 个标准”变成“全部标准”；② 解释了为什么 figo 卖 990 而 isopilot 必须配顾问；③ **与“成都专家质疑 AI 生成是伪需求”和解**——他质疑的是应然侧，本产品不做应然侧。

#### 4.6.2 13485 的“代价大”要精确表述

| 常见说法 | 正确读法 |
|---|---|
| “13485 证书被撤销代价很大” | ❌ 不准确。证书撤销影响投标/出口，但不直接导致停产 |
| “13485 判定错一次，机构和审核员要担责” | ✅ **这才是真相**。漏判设计开发缺陷 → 产品上市后出事故 → 追责到审核员 |

⇒ **机构买的是“风险转移 / 免责证据”，不是效率。** 这才是 13485 能收高价的真实原因，也解释了 `isopilot.it` 为什么必须配“人工顾问签核”——**责任必须有人承担**。

#### 4.6.3 三个机构不要混（常见概念错误）

| 机构 | 性质 | 管什么 | 对企业的意义 |
|---|---|---|---|
| **CNCA**（认监委） | 政府行政机关 | 认证机构的**行政审批 / 发牌照** | 管机构，⛔ 不管企业 |
| **CNAS**（认可委） | 技术认可机构 | 认证机构的**能力认可**（ISO 17021） | 决定证书能否带 CNAS / IAF 标志 |
| **NMPA**（药监局） | 政府监管 | **产品注册 / 备案 + GMP 体系核查** | ★ **这才是“能不能卖”的强制关口** |

- **ISO 13485 是自愿性国际标准**（第三方认证机构发证）；**GMP 是强制性法规**（药监核查）。二者完全不同。
- ⛔ **不能说“13485 需要 CNCA / CNAS 质检”**。正确说法是“发证机构须有 CNCA 批准 + CNAS 认可”。
- ⚠️ 这句话一旦说错，后面所有技术判断的可信度都会被专家重新评估。

#### 4.6.4 换版窗口期：ISO 9001:2026 已发布

| 事实 | 影响 |
|---|---|
| **ISO 9001:2026 于 2026-09-16 正式发布**（第六版，2015 以来首次全面修订，通常 3 年过渡期） | **全行业换版**：老玩家的存量 9001 知识库作废，起跑线被拉平 |
| ISO 9001 全球证书 **超 160 万张**（+8.94%/年） | 实然侧审核量最大 |
| 全国认证机构 **1,216 家**（2025 年末） | 机构端客户池 |

⇒ **这是“平台化”最硬的理由，比“多标准”更硬**：如果标准写死在代码里，现在就要重写一遍引擎；如果标准是配置，只换配置包。
⇒ **第一版就必须配置驱动**，否则一年后返工。

#### 4.6.5 实然侧再分两类：运行记录 vs 事实文档（V4 核心修正）

“实然侧不能生成”这句话只对了一半。实然侧至少分两类：

| 类型 | 例子 | 能否 AI 生成 | 硬条件 |
|---|---|---|---|
| **运行记录** | 检验记录、培训签到、生产记录、内审记录、CAPA 记录、设备使用记录 | ❌ **不能** | 必须真实发生；只能采集 / 检查 / 补录（补录也要有原始依据） |
| **事实文档** | 管理评审报告、供应商评价报告、风险分析报告、内审报告、工艺验证报告、质量目标达成分析、法规符合性自查报告 | ✅ **可以有条件生成** | 每个事实有来源；缺证据标“缺口”；人工确认后导出 |
| **应然文件** | 手册、程序文件、作业指导书 | ✅ 能 | 模板化；已被 ¥990/年 打穿 |

**关键区别**：

- **模板生成**：输入“企业名称 / 人数 / 设备清单”，输出固定格式文件；**没有事实，也没有出处**。
- **事实文档**：输入企业原始资料（质量手册、程序、记录、表单、邮件、扫描件、Excel），输出 **有出处的文件**；每一句事实都能点回原文；缺证据的地方不猜，直接标“缺口 / 待补”。
- **预 NC**：用同一套条款规则扫描事实文档和原始资料，输出 **证据缺口 / 一致性冲突 / 潜在 NC**；这是“事实文档”比模板生成多出来的价值，也是它能收费的原因。

**一句话**：

> **不是“帮你写文件”，是“把你已经发生的事，整理成有出处的文件，并告诉你哪里还缺证据”。**

**合规边界（与 40 号一致）**：

- ✅ 从已有记录提取事实、汇总、分析、生成报告草稿；
- ✅ 缺证据 → 标缺口 / 待补；
- ❌ 编造未发生的事实（时间、地点、人物、数值）；
- ❌ 生成运行记录 / 签到 / 检验数据 / 管理评审决议；
- ❌ 无出处直接写结论、一键全部通过。

> 例：**管理评审报告可以生成，但“评审决议 / 行动项”必须来自真实会议记录**；没有会议记录 → 标缺口，不生成。

## 五、产品定义：13485 审核证据与 NC 工作台

### 5.1 一句话定位

> **给 ISO 13485 审核员 / 咨询师用的“审核证据与 NC 工作台”：把条款、证据、发现、报告连成一条可追溯的线。**

> ⚠️ **13485 是楔子，不是边界**。上面这句是**首发产品的表述**；产品本质（见 §4.6）是 **「所有标准的实然侧」**。对外讲首发版可以只说 13485，对内做架构必须按“标准可替换”设计（§5.9）。

### 5.2 不做什么

| 不做 | 原因 |
|---|---|
| 全量 eQMS | 红海；文档控制、培训、CAPA、电子签名太重 |
| 文档控制 / 文控系统 | 不是审核员的核心痛点 |
| CAPA 工作流 | 企业侧需求，和审核工作台不是同一产品 |
| 自动判定 / 自动发证 | 责任红线；AI 不能替代审核员判断 |
| 生成运行记录 / 倒签 | 40 号红线；伪造认证档案 |
| 一上来做 Q/E/S/13485 多标准 | 内容做不深；先做 13485 |
| 通用“什么文档都能填” | 撞大模型厂商，没壁垒 |
| 只做模板生成 / 固定格式套模板 | ¥990/年红海；没有事实与出处，不是本产品 |
| 无出处的 AI 作文 | 等于伪造；事实文档必须逐句可追溯 |

### 5.3 三层产品

| 层 | 内容 | 先做吗 |
|---|---|---|
| **Evidence Pack** | 13485 条款树、证据矩阵、NC 库、报告模板、术语 | 先做（两端共用） |
| **Audit Workbench** | 资料导入、条款映射、证据缺口、NC 草稿、报告导出 | 专家端前台 |
| **Enterprise Fact Document + Pre-NC** | 企业事实文档、证据缺口、预 NC、整改建议 | **企业端前台；可与专家端并列首发**（共用引擎，按渠道选先后） |

### 5.4 买家与用户

| 角色 | 是谁 | 关心什么 | 优先级 |
|---|---|---|---|
| 经济买家 | CB 技术评审 / 质量负责人；咨询公司老板；企业质量 / RA 负责人 | 一致性、返工、产能、风险 | 高 |
| 主要用户 | 13485 审核员、咨询师 | 少写报告、少漏项、快上手 | 高 |
| 间接受益人 | 技术评审、企业 QA/RA | 报告质量、整改方向 | 中 |
| 首批试点 | ACM 技术评审 + 3 位 13485 审核员 | 真实项目省时 | 最高 |

> **不要只卖“省时间”给 CB**：CB 按人日收费，省时间可能减少收入。对 CB 要卖“**产能 / 一致性 / 复核效率**”。

### 5.5 价值主张

- 报告 / NC 编写时间 **减少 ≥30%**。
- 条款覆盖 **100% 可检查**，不漏项。
- NC 措辞 **标准化**，减少复核返工。
- 新专家 **上手更快**，降低带教成本。
- 证据链 **可追溯**，应对 CNCA / CNAS 检查。
- **不是“AI 替代审核员”**，是“审核员的副驾”。

### 5.6 与现有资产映射

| 现有资产 | 在 13485 工作台里的用途 |
|---|---|
| DAG / 工作流 | 审核准备 → 证据采集 → 判定 → 报告 |
| 证据链 | 条款 → 证据 → 发现 → 报告 |
| NC 结果表 | NC 草稿、严重度、条款引用 |
| 报告章节 | 报告段落 / 结论 |
| 文档提取 | 审核证据表、文件、记录的导入与结构化 |
| 多租户 / 权限 | CB、咨询师、企业三类租户隔离 |
| 审核留痕 | AI 建议 vs 人工修改、确认人、时间戳 |

### 5.7 护城河

不是模型，是**内容 + 案例 + 专家 + 工作流**：

1. 13485 条款树 / 证据矩阵。
2. 真实 NC 库（匿名化）。
3. 报告模板 / 检查表。
4. 医疗法规 / GB/T 42061-2022 的映射。
5. 5–8 位专家组成的审校委员会。
6. 审核留痕与可追溯性。

### 5.8 专家是“电脑小白”：产品必须极简

朋友和成都专家的反馈：**专家对计算机使用很基础，机构也没给好工具**。这不是缺点，是产品要求：

| 要求 | 具体做法 |
|---|---|
| 零培训 | 10 分钟视频 + 一页纸；打开就会用 |
| 3 步完成 | 建项目 → 传资料 → 确认 NC / 报告 |
| 不暴露 DAG | 审核员只看任务；DAG / 规则在后台 |
| 默认模板 | 条款、证据、NC、报告都有默认值 |
| 一键导出 | Word / PDF；格式按机构模板 |
| 大按钮 / 中文 / 少层级 | 不要“平台感”，不要多级菜单 |
| 自动保存 / 防丢 | 断网、误关、上传失败可恢复 |
| 离线 / 低带宽 | 现场可用；照片 / 扫描先本地缓存 |
| 错误可撤销 | 不惩罚误操作 |
| 人工确认 | AI 建议，审核员点头才算 |

> **复杂留给自己，简单留给专家。** 后台可以复杂，前台必须像微信一样简单。

### 5.9 平台化四层架构：“平台做宽、服务做深”如何同时成立

用户的核心判断是：**平台要可配置（让机构自己配），但服务只能专注一两个标准。** 这两件事看似矛盾，用四层分离就能同时成立。

| 层 | 内容 | 变化频率 | 谁维护 | 是否护城河 |
|---|---|---|---|---|
| **证据层** | 证据类型、来源、可读性、采集方式 | 极低 | **你** | ★★★ 核心资产 |
| **判定层** | 规则引擎（完备性 / 一致性 / 符合性） | 低 | **你** | ★★★ 核心资产 |
| **标准映射层** | 条款 → 证据要求 → 判定规则 | **高**（9001:2026 即活例） | 标准包（可配置） | ★ 可替代 |
| **表单层** | ACM `QR-04-72` 这类机构表单格式 | 中 | 客户可配 | — |

**铁律**：

> **标准只出现在映射层。** ⇒ 加一个标准 = 加一个映射包，⛔ **不是加一个引擎**。

**三条推论**：

1. **护城河在证据层 + 判定层，不在标准数量**。所以“只做深 1–2 个标准”不会削弱壁垒——壁垒本来就不在标准上。
2. **加标准不等于加研发**。第 3 个标准的边际成本应 ≤ 第 2 个的 30%（§6.5 已有此验收指标）。
3. **“让机构自己配”有反噬**：机构里**没有“配置工程师”这个岗位**。配置能力越强，客户越配不明白，最后都变成“你帮我配”。
   ⇒ 平台可配置，但**必须配“标准包”**（预置规则库 + 证据映射 + 检查表模板），配置只做微调。
   ⇒ **卖的是标准包，⛔ 不是配置器。**（符合项目铁律：不把内部准备负担转嫁给用户）

### 5.10 对外表述红线（V3 新增，最高优先级）

#### 5.10.1 ⛔ 禁用表述

> ~~“让 AI 验证专家的结论，他们并不能确保个人经验一定正确。”~~

**这句话在商业沟通上等于自杀**——你在对一个干了 20 年的审核员说“你可能判错了”。他会立刻关闭对话，而且审核圈很小，负面口碑传播比广告快。

从产品逻辑上也站不住：**机器最弱的恰恰是“判得准”**（设计开发是否充分、风险管理是否闭环、临床评价是否足够）。拿最弱的点去挑战最强的点，必输。

#### 5.10.2 ✅ 替代表述：机器的优势是“不漏、不漂、可查”

| 优势 | 具体是什么 | 为什么人做不到 |
|---|---|---|
| **完备性** | 59 条款 × 13 部门逐项核对证据 | 人脑记不住，靠检查表也会漏（项目实测数据） |
| **一致性** | 同一审核员跨企业、跨时间的判定尺度 | 经验会漂移，情绪会影响 |
| **追溯性** | 证据 ↔ 条款双向映射，哪条没证据、哪条证据多余 | 手工做不完，只能抽样 |

**话术模板**：

| 场景 | ⛔ 不要说 | ✅ 要说 |
|---|---|---|
| 产品介绍 | “AI 帮你验证结论对不对” | “AI 帮你查漏、帮你保持前后一致、帮你把证据链拉通” |
| 面对资深审核员 | “你的经验可能错” | “人脑记不住 59 条款 × 13 部门，这不是能力问题” |
| 面对机构 | “AI 判定更准” | “降低复核返工和漏项风险” |

#### 5.10.3 产品形态：工作台，不是判定器

| 形态 | 客户怎么看 | 结果 |
|---|---|---|
| AI 判定器 | **对手**，处处挑错 | 抵触、弃用 |
| **审核工作台**（证据归集 + 条款映射 + 完备性检查 + 报告生成，AI 是其中一个功能） | **工具** | 接受、复用 |

> 工具和对手，只差一个定位。

### 5.11 企业端：事实文档 + 预 NC（V4 新增）

#### 5.11.1 一句话定义

> **把企业原始资料中的事实提取出来，生成“有出处的事实文档”（即你说的“事实文件”），并跑一遍预 NC：缺什么证据、哪里前后矛盾、哪些条款可能被开 NC。**

这不是“模板生成”，也不是“代写作文”。**文档是交付物，预 NC 才是价值。**

#### 5.11.2 首批事实文档（建议只选 1 个）

| 文档 | 输入 | 输出 | 适合度 |
|---|---|---|---|
| **供应商评价报告** | 供应商名录 / 资质、来料检验、不合格记录、交期 / 投诉 | 供应商分级、评价结论、风险与整改 | ★★★ **首发**：输入边界清楚；对应 7.4.1 真实 NC；容易验证 |
| 管理评审报告 | 质量目标、内审、CAPA、投诉、供应商绩效、法规变化 | 输入 / 输出 / 决议 / 行动项 | ★★ 第二批：价值最高，但跨部门数据多，且决议必须真实存在 |
| 风险分析报告 | 产品特性、临床 / 法规、生产 / 供应商、投诉 / 不良事件 | 风险清单 / 控制措施 / 剩余风险 | ★ 第三批：专业性强，需专家背书 |
| 工艺验证报告 | IQ/OQ/PQ 记录、参数、偏差 | 验证结论 / 偏差 / 附件 | ★ 第三批：技术性强 |
| 内审报告 | 内审计划 / 检查表 / 发现项 | 内审报告 / 不符合 / 整改 | ⚠️ 必须有真实内审记录；不能凭空生成 |

**首发建议**：**供应商评价报告 + 7.4.1 预 NC**。  
**理由**：它是“事实文档”里边界最清楚的一类；企业一定有供应商、来料、不合格记录；而且直接命中案例中的 7.4.1 NC。

#### 5.11.3 预 NC 的输出

| 字段 | 说明 |
|---|---|
| `ClauseCode` | 条款号 |
| `GapType` | 缺证据 / 不一致 / 过期 / 未评价 / 记录缺失 |
| `RiskLevel` | 高 / 中 / 低（按条款风险 + 证据关键度） |
| `EvidenceNeeded` | 需要补什么证据 |
| `SourceQuote` | 现有资料中的出处（原文 / 页码 / 单元格） |
| `DraftNc` | 可选：NC 草稿（人工确认后使用） |
| `SuggestedAction` | 整改建议（不承诺“包过”） |

#### 5.11.4 与专家端的关系：同引擎，两个前台

| 维度 | 企业事实文档端 | 专家证据链端 |
|---|---|---|
| **核心引擎** | 提取 / 事实表 / 条款映射 / 证据规则 / 预 NC | **同左** |
| **前台** | 企业上传 → 事实文档 → 缺口报告 | 审核员采集 → 证据链 → NC / 报告 |
| **买家** | 企业 QA / RA、咨询公司 | 审核员、CB、咨询公司 |
| **渠道** | 企业直销 / 咨询 / 协会 | 审核员 / 机构 |
| **关系** | **首发现金流** | **第二前台 / 长期壁垒** |

> **不是转行，是同一个证据链引擎先卖给企业。**

### 6.2 输入 / 输出

**输入**：

- 审核证据表（PDF / DOCX / XLSX）。
- 质量手册、程序文件、作业指导书。
- 生产记录、检验记录、供应商名录、采购记录。

**输出**：

- 条款覆盖清单（已查 / 未查 / 证据不足）。

- 报告章节草稿。

### 6.3 概念数据模型

| 实体 | 关键字段 | 说明 |
|---|---|---|
| Standard | Code, Name, Version | ISO 13485:2016 / GB/T 42061-2022 |

> 字段命名按项目铁律：PascalCase、业务键 `Code`、审计人字段存用户 `Code`；这里只给概念模型，落库前按 38 号 DDL 规范细化。

### 6.4 人工确认与留痕

- AI 只做：**提取、映射、缺口提示、NC 草稿**。
- 审核员必须：**确认 / 修改 / 驳回**。
- 留痕：`AiSuggestion`、`HumanValue`、`ConfirmedBy`、`ConfirmedTime`、`SourceQuote`。
- ⛔ 不做“一键全部通过”；⛔ 不自动生成未发生的记录。

### 6.5 验收指标

| 指标 | 目标 | 怎么测 |

## 八、商业模式与定价

| 客户 | 产品 | 价格假设 | 优先级 |
|---|---|---|---:|
| 13485 咨询师 | 工作台 | **3,000–10,000 元/年** | 1 |
| 13485 审核员 | 工作台 | **2,000–5,000 元/年** | 2 |
| 认证机构 | 技术评审 / 质量中台 | **5–20 万元/年 + 座位** | 3 |
| 医疗器械企业 | 审前自查 | **5,000–30,000 元/年** | 4 |
| 专家委员会 | 内容共建 | 顾问费 / 分成 | 支撑 |
| 单项目 | 按次 | **300–1,000 元/项目** | 补充 |

### 8.1 三年粗略模型（假设，需验证）

| 年份 | 咨询师 | 企业 | CB | 估算 ARR |
|---|---:|---:|---:|---:|
| 第 1 年 | 20 | 10 | 2 个试点 | **15–40 万元** |
| 第 2 年 | 100 | 30 | 2 个合同 | **100–150 万元** |
| 第 3 年 | 300 | 100 | 3 个合同 | **250–450 万元** |

> 这是一个小生意。**不要按平台估值烧钱**；按现金流管理。

### 8.2 定价原则

1. **咨询师先付费**：他们客户多、频率高、最容易感知价值。
2. **企业通过咨询师卖**：避免审核员推荐企业端（41 号 ADR-41-03）。
3. **CB 按合同 + 座位**：不要只按人头；机构预算和采购流程不同。
4. **无限使用加 fair use**：LLM / 存储成本可能打穿。
5. **不承诺“包过 / 少审人日”**：只承诺省时、覆盖、可追溯。

### 8.3 与 41 号一致

- 审核员端和企业端**合同独立、数据域独立、获客独立、时点隔离**。
- 审核员**不得推荐**企业端、不得返佣。
- 企业数据在“提交认证申请”前对认证租户零可见。
- 工具定位是“辅助分析”，不是认证机构 / 咨询机构。

### 8.4 收费逻辑：按“复杂度 / 风险 / 省下的工时”定价

| 价值锚 | 算法（假设） | 定价含义 |
|---|---|---|
| 审核人日成本 | 1 个审核人日 1,000–3,000 元 | 省 1–2 人日 = 1,000–6,000 元/项目 |
| 复核返工 | 技术评审 0.5–1 人日/项目 | 少返工 = 500–3,000 元/项目 |
| 漏项风险 | 一次 CNCA / CNAS 不符合 = 远高于软件费 | 合规价值 > 省时价值 |
| 专家带教 | 新专家 3–6 个月上手 | 缩短 1 个月 = 数千元 |

**定价原则**：

- 复杂标准可以比通用标准贵 **2–3 倍**；
- 审核员按座位，咨询师按项目包，企业按年；
- 不按“证书数量”收费，按 **项目数 / 座位数 / 模板包** 收费；
- 先证明省 1 人日，再谈年费；
- 专家“小白”不一定接受年费 ⇒ 可以 **按项目付费 + 年费封顶**。

### 8.5 双层报价：纠正“竞品只做一两个标准”的误判

**用户原判断**：其他做体系认证的软件公司也只能服务一两个标准。
**实测结论**：⛔ **不成立**。

| 产品 | 公开宣称覆盖 |
|---|---|
| `isopilot.it`（UESE ITALIA） | 9 个体系 / 68 项目录 |
| `rotix.io`（英国） | 11 个标准 |
| `iso.figo.cn`（中国） | 14 个体系 |
| ACM（认证机构自身业务范围） | 13+ 个 |

**为什么它们敢宣称这么宽**：**模板化覆盖的边际成本极低**——一个标准的条款结构是固定的，套模板就能宣称“支持”。

**为什么这件事很重要**：**机构采购常按“支持标准数”打分比价**。只写“支持 1–2 个”，第一轮筛选就出局。

⇒ **正确做法：双层报价，把“覆盖”和“深度”拆开卖。**

| 层 | 内容 | 覆盖 | 定价逻辑 |
|---|---|---|---|
| **广度包** | 标准条款库 + 检查表模板 + 报告模板 + 证据清单 | **10+ 标准** | 低价引流（数千元级） |
| **深度包** | 证据映射 + 判定规则 + 完备性校验 + NC 草稿 | **1–2 标准** | 高价（万元级 / 座位 / 项目） |

> **一句话**：广度包负责“不被比价淘汰”，深度包负责“赚到钱”。

### 8.6 天花板测算：只做 13485 个人版撑不起公司

| 口径 | 假设 | 说明 |
|---|---|---|
| 中国医疗器械生产企业 | **3.3 万家** | NMPA 2024：32,752 家 |
| 其中做 13485 认证 | 5,000–10,000 家 | 估算 |
| 对应审核员（含兼职） | 1,000–2,000 人 | 估算 |
| 付费转化 | 10% | 乐观 |
| 年费 | ¥3,000 | 保守 |

**⇒ 30–60 万元/年。这就是只做 13485 个人版的天花板。**

**审核员付费能力参考（2026 行情）**：

| 项 | 数据 |

## 九、ACM 合作方案

### 9.1 合作定位

**设计伙伴（design partner），不是客户，也不是独家渠道。**

- 周期：3–6 个月。
- 目标：拿真实案例、试点反馈、背书。
- 不签独家；不卖源码；不做定制外包。

### 9.2 试点设计

| 项 | 设计 |
|---|---|
| 试点人数 | 3 位 13485 审核员 + 1 位技术评审 |
| 试点项目 | 2–3 个真实 13485 项目 |
| 周期 | 4–6 周 |
| 费用 | 免费试点或 5,000 元象征性付费 |
| 交付 | 3 条款证据包、NC 草稿、报告章节、试点报告 |
| 成功标准 | 省时 ≥30%、NC 采纳率 ≥50%、2/3 愿意第二次使用 |
| 数据 | NDA；匿名化；不训练；不宣传客户名 |

### 9.3 数据与 IP

1. **NDA 先签**：客户资料、审核记录、NC、报告。
2. **匿名化**：企业名、人名、供应商名、批号全部替换。
3. **不训练**：未经书面同意，不把客户资料用于模型训练。
4. **案例授权**：单独书面授权，明确用途、范围、期限。
5. **模板版权**：ACM 的模板 / 表单，明确许可；不能默认归你。
6. **数据留存**：默认只存提取结果；原件 30–90 天删除。

### 9.4 公正性

- 审核工具 / 咨询工具**两条产品线**。
- 同一客户**不得**既用咨询版又用审核版。
- AI 不自动判定、不自动发 NC、不自动发证。
- 审核员签字，系统留痕。
- 认证机构不得向客户推荐企业端工具（41 号）。

### 9.5 收入冲突

对 CB 的话术：

- 不是“少审几天”，是“**同样时间做更多项目**”。
- 不是“替代审核员”，是“**新专家更快上手、报告更一致**”。
- 不是“减少人日收费”，是“**减少复核返工、降低不符合风险**”。

### 9.6 给 ACM 的一页纸

**What**：13485 审核证据与 NC 工作台。

**Why**：

- 专家一致性：NC 措辞、条款引用、证据要求标准化。
- 复核效率：技术评审少改报告。
- 新专家上手：带教周期缩短。
- 条款覆盖：不漏项，应对 CNCA / CNAS 检查。

**Pilot**：

- 3 位审核员 + 1 位技术评审。
- 2–3 个真实项目，4–6 周。
- 2 次现场旁观 + 20 份匿名 NC + 3 份报告。

**Data**：

- NDA；私有化 / 本地部署；匿名化；不训练；可删除。

**Success**：

- 省时 ≥30%；NC 采纳率 ≥50%；2/3 第二次使用。

**Not**：

- 不是 eQMS；不自动判定；不生成运行记录；不做咨询认证一条龙。

### 9.7 案例推广：3 个案例就够

| 案例 | 证明什么 | 素材 |
|---|---|---|
| ACM 试点 1 | 审核员省时 ≥30% | 前后工时、审核员证言 |
| 成都专家试点 | 非 ACM 专家也能用 | 10 分钟上手、第二次使用 |
| 企业审前自查 | 企业愿意付费 | 审前发现缺口、整改闭环 |

> 案例不必多，**3 个真实、可量化、可匿名**的案例，比 30 个 logo 更有用。

### 9.8 三个空白（V3 新增，必须在 P0 之前填）

用户的商业模式（专家端自愿购买 + 企业端走咨询公司 / 协会）**结构是对的**，但有三处尚未回答。

#### 9.8.1 空白一：谁付钱？

| 问题 | 现状 | 风险 |
|---|---|---|
| 审核员愿意自费吗？ | **未验证**。行业惯例是工具支出由机构报销 | 若自费意愿低，“不依赖机构推广”的路径会断 |
| 咨询师愿意付吗？ | 大概率愿意（客户多、频率高） | 但他们会计入项目成本、压价 |
| 机构愿意付吗？ | 愿意，但采购慢、要准入审查 | 3 个月无合同是常态 |
| **企业愿意为“事实文档 + 预 NC”付吗？** | **未验证**；建议 3 家企业试点 | 若只愿按“代写”低价付，产品会被锚定在模板价 |

**⇒ 必须做的最小验证**：

- 找 5 位审核员，问：“**如果这个工具一年能省你 8 天写报告，你愿意自己掏 3,000 块吗？**” —— 答案是“愿意”，路径成立；是“得让所里买”，就必须改走机构版。
- 找 3 家企业，问：“**审前自查 + 供应商评价报告，如果少一次 NC 返工，你愿意付 5,000–10,000 吗？**” —— 愿意，企业端可做首发；只愿付 990，就回到模板价，⛔ 不做。

#### 9.8.2 空白二：数据合规（最硬的一条）

审核员把企业资料上传到 SaaS，等于**客户机密离开了机构**。

| 风险点 | 说明 |
|---|---|
| 保密协议 | 机构与审核员签的保密协议，通常**禁止把客户资料交给第三方处理** |
| 个人信息 | 13485 资料可能含**患者数据、临床评价数据** ⇒ 触《个人信息保护法》《数据安全法》 |
| 跨境 | 若用境外模型 / 境外云，构成数据出境 |
| 供应商准入 | 机构对 IT 供应商有安全审查要求（见 §10.2 第 5 问） |

**⇒ 架构级要求（⛔ 不能上线前再补）**：

1. **私有化 / 本地部署选项**（至少给机构版）
2. **数据不出境**（模型与存储境内）
3. **可签数据处理协议（DPA）**
4. **敏感字段脱敏**（患者信息、临床数据）
5. **原件 30–90 天删除**，只留提取结果（§9.3 已定）

> ⚠️ 如果第一版就设计成“资料必须上传云端”，后面加私有化等于重写。**这是架构决定，不是功能决定。**

#### 9.8.3 空白三：责任归属

| 场景 | 后果 |
|---|---|
| AI 漏判，审核员照抄 | 产品上市后出事故 → 追责到审核员 → 他怪工具 → 弃用 + 差评 |
| AI 误判（多报 NC） | 企业申诉 → 审核员被质疑专业性 → 弃用 |

**⇒ 产品必须内置的边界**：

> **AI 只提供建议 → 审核员签核 → 全程留痕**（`AiSuggestion` / `HumanValue` / `ConfirmedBy` / `ConfirmedTime` / `SourceQuote`，见 §6.4）

这既是法律需要，也是**让专家敢用的前提**。`isopilot.it` 配“人工顾问签核”就是这个逻辑——**责任必须有人承担**。

### 9.9 隐藏的利益冲突：两条线必须三隔离

如果同一套工具**既卖给审核员、又通过咨询公司卖给企业**，那么当这家企业正好由这个审核员审核时，**你就在同时服务甲乙双方**。

| 隔离维度 | 要求 |
|---|---|
| **产品线** | 审核版 / 咨询版独立，功能与文案不共用 |
| **数据域** | 企业数据在“提交认证申请”前，对认证租户**零可见**（§8.3 已定） |
| **客户名单** | 两条线不共享客户信息，不交叉推荐 |

**触发场景**：企业用咨询版做完规范化 → 找 ACM 认证 → 正好派到这个审核员 → 若他用审核版看到同一份数据，**公正性直接崩**。

> ⛔ 一旦被质疑，连解释的立场都没有。**三隔离是产品架构，不是运营纪律。**
