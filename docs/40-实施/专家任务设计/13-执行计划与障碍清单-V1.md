### 13.1 R1「`cert_expert_task` 缺 `IsValid`」→ 误报，但已补说明

> | `LifecycleStatus='archived'/'voided'/'cancelled'` | 这次执行归档/作废/取消（12 号 D27，**不影响 `IsValid`**） |

### 13.2 R2「`cert_expert_task_queue` 缺 `OrgCode`」→ 误报字段，但发现真问题（★ 已批量修正）

**核查结果**：`cert_expert_task_queue` 第 4 行**已有** `OrgCode`（评审位置说错）。但发现它写的是 `DEFAULT NULL` —— **这才是真问题，且 8 张表全都有**。

**采纳并扩大范围**：06 号固定列模板 + 8 张新表全部改为 `NOT NULL`，并新增验证 SQL §7.1 ⑥。

**为什么 `NOT NULL` 是必须的**（SQL 三值逻辑）：

```sql
-- 若 OrgCode 可为 NULL：
SELECT * FROM cert_expert_task_queue WHERE OrgCode = 'WS001';
--  ⛔ OrgCode IS NULL 的行查不出来（NULL = 'WS001' → NULL，不是 true）
--     这批行成为"隐形数据"：专家会问"我建的队列呢？"且 SQL 不报错
```

**配套要求**：应用层所有 `Insert` 必须从 `WorkspaceContextService.Resolve().OrgCode` 取，⛔ 禁止从 DTO 传入。

> ⚠️ 存量表的 `OrgCode` 保持 `DEFAULT NULL` 不动（沿用历史约定且实际都有值，改动面大无必要）。**新表从严**。

| 触发 | **个别**章节 `WorkflowCode` 为空 | 整份模板都没配 |

| 后果 | 5 个正常 + 1 个模板示例，任务照常完成 | 全部用示例，工作台频繁进非正常路径 |
