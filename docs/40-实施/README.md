## 一、这层放什么（准入判据）

| 放 | 不放 |
|---|---|
| 在制品设计（尚未落地的模块设计稿、待审批方案） | 已成体系的**完整设计** → `20-体系认证/` |
| 开发/实施/TODO 计划 | 架构规范与编码约定 → `10-YZH架构/` / `30-项目规则/` |
| 分析报告 / 评估 / 审计 / 诊断（一次性） | AI 偏好与工程习惯 → `00-工程体系/` |
| 缺陷修复方案与修复记录 | 尚未排期的方向性讨论 → `50-扩展/` |
| 一次性执行记录、验收证据 | 已失效的历史 → `90-归档/` |

> **一句话**：这里的文档**天生会过期**。做完 → 成果提炼进 `20-体系认证/`，过程文档进 `90-归档/`。
> ⛔ 不要把本层当长期知识库使用。

## 三、本层 ↔ 其他层的关系

| 层 | 回答的问题 |
|----|------|
| `00-工程体系/` | 我（AI）该按什么偏好与工程约定干活 |
| `10-YZH架构/` | 架构**应该**是什么样（核心知识库） |
| `20-体系认证/` | 业务**应该**是什么样（真实完整设计） |
| `30-项目规则/` | 编码时**不可违反**的硬约束 |
| **`40-实施/`（本层）** | 现在**在做**什么 / 还没做什么 |
| `50-扩展/` | 以后**可能**做什么（未排期） |
| `90-归档/` | 过去**实际**是什么样、怎么走到今天的 |

## 四、维护约定

1. **新增文档**：先判断是否真属本层（见 §一）；属则在本目录 `README.md` 或对应子目录 README 的清单表登记（文件 | 一句话职责 | 状态）。
2. **状态取值**：`⬜ 待实施/待审批/待拍板/待核实` · `🔄 进行中/living` · `✅ 已完成` · `⛔ 作废`。
3. **过期即迁**：被取代的旧版 → `90-归档/旧版本/`；已落地的设计 → 提炼进 `20-体系认证/`；一次性执行记录 → `90-归档/旧版本/归档-<日期>-<主题>/`。
4. **归档批次目录**：`90-归档/旧版本/归档-YYYY-MM-DD-<主题>/`，与被迁源同构（`40-实施/分析报告/` → `归档-…/40-实施/分析报告/`），保留可回退路径。
