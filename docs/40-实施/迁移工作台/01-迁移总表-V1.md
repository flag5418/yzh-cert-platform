## 一、一句话结论

> **前端已全面铺开，后端业务层几乎为空。**
>
> 新前端 `certplatform-web` 已建 38 个页面、25 个 API 文件；
> 而新后端 `certplatform-api` 的 51 个 `.cs` 文件中，**只有 1 个业务控制器**
> （`Admin/Controllers/Foundation/ISOClauseController.cs`），
> `Shared/Controllers`、`Shared/Services`、`Shared/Repositories`、`Shared/Data`、
> `Shared/WorkflowEngine` 五个目录**全部为空**。

这个错位是当前迁移的核心特征：**迁移工作量的 90% 集中在后端**。

## 七、前后端错位清单

> 这是本表最有价值的一节。错位分两类，**修复动作完全不同**。

### 7.1 A 类 —— 路由失配（后端存在，前端调错）

**修复成本低**：只改前端 `api/*.ts` 里的路由字符串。

| 前端页面 | 前端实际调用 | 后端实际路由 | 影响 |
|---------|-------------|-------------|------|
| `system/user` | `/api/Sys_User/*` | `api/System/User` | 无法加载数据 |
| `system/dictionary` | `/api/Sys_Dictionary/*`<br>`/api/Sys_DictionaryList/*` | `api/System/Dictionary` | 无法加载数据 |
| `system/menu` | `/api/Sys_Menu/getPageData`<br>`/api/Sys_Menu/getTree` | `api/System/MenuManagement` | 无法加载数据 |
| `system/log` | `/api/Sys_Log/*` + import 不存在的 `@share/api/system-log` | ❌ 控制器不存在 | **编译失败** |
| `system/param` | `/api/Sys_Parameter/*` | ❌ 控制器不存在 | 无法加载数据 |
| `foundation/iso-clause` | `/api/Foundation/ISOClause/getPageData` | `api/Foundation/ISOClause`（无 `getPageData`） | 查询 404 |

### 7.2 B 类 —— 后端缺失（前端已建，后端没有）

**修复成本高**：需要完整迁移后端控制器。

| 前端页面 | 期望后端 | 实际 |
|---------|---------|------|
| `system/config`、`workflow/sys-config` | 系统参数控制器 | 不存在（且双表待决策） |
| `system/api`、`system/role-api` | 接口权限控制器 | 不存在（3 张表未建） |
| `workflow/*`（17 个页面） | 14 个业务控制器 | 均不存在 |
| `foundation/*`（3 个页面） | 3 个业务控制器 | 均不存在 |

### 7.3 可用页面统计

| 类别 | 数量 |
|------|:----:|
| 前端页面总数（`cert-admin`） | 38 |
| **后端支撑完全可用** | **4**（organization / role / role-menu / role-user） |
| 后端存在但路由失配 | 4（user / dictionary / menu / iso-clause） |
| 后端完全缺失 | 30 |

> **一句话**：38 个页面里，**真正端到端跑通的只有 4 个**。
