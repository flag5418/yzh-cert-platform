# 历史项目地图 — 按图索骥

> **版本**：V1.0 | **日期**：2026-09-12 | **状态**：生效
>
> **用途**：这是旧 Vol 架构的**唯一检索入口**。给 AI 一份地图，让它能定位旧代码、
> 理解旧业务，并知道新架构该写成什么样。

```
你的问题                              →  看哪一节
────────────────────────────────────────────────────────

```

> 需要旧资料时，**从本目录进入**。

### 旧 YZH-Framework 是什么

`src/old/server/YZH-Framework/` 是**更早一版的框架尝试**（`YZH.System` 命名空间），
包含 `SystemDepartmentController` / `SystemDictionaryController` / `SystemLogController` /
`SystemMenuController` / `SystemRoleAuthController` / `SystemRoleController` /
`SystemUserController` / `CrudController`。

它与当前的 `src/yzh-core/` **不是同一套东西**。当前 YZH.Core 是重写版，命名空间为 `YZH.Core.*`。
旧 YZH-Framework 的设计文档归档在
[`../../90-归档/历史项目/旧YZH-Framework/`](../../90-归档/历史项目/旧YZH-Framework)。
**迁移时不要参照它**，只可作为"当初为什么没走通"的经验。

## 九、迁移时的阅读顺序

拿到一个模块（以"标准目录管理"为例）：

| 步骤 | 读什么 | 目的 |
|:----:|--------|------|
| ① | `Admin/Platform/StandardDirectoryController.cs`（494 行） | 旧有哪些端点、业务规则 |
| ② | `Cert.Platform/Services/` 下同名 Service | 业务逻辑细节 |
| ③ | `YZH.Entity/Admin/` 下对应实体 | 字段与表结构 |
| ④ | `vol.web/src/views/cert/admin/business/Standard/DirectoryManager/` | 页面交互 |
| ⑤ | [`../../10-YZH架构/07-开发流程.md`](../../10-YZH架构/07-开发流程.md) | 新架构怎么写 |
| ⑥ | [`../../10-YZH架构/04-数据契约.md`](../../10-YZH架构/04-数据契约.md) | 前后端数据格式 |
| ⑦ | 参照 `foundation/iso-clause` 三件套 | 唯一已迁移的样板 |

> ⚠️ **不要照搬旧端点命名**。旧架构端点自由定义（`getPageData` / `getList` / `save`…），
> 新基类固定 10 个端点（`config` / `filter` / `add` / `update` / `delete` / `export` /
> `import` / `import/template` / `action/{methodName}` / `toggle-valid`）。
