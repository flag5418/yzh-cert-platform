## 二、五个能直接改模型的发现

### 2.1 5W1H 才是"证据"的字段模板（图 9）

我们 02 号方案把 `EvidenceItem` 设计成 13 个字段（CheckItemCode/DocCode/Anchor/Excerpt/…），那是**系统字段**。

但审核员脑子里的字段只有六个：**什么产品（What）、什么地点（Where）、什么时间（When）、谁（Who）、什么情况（Why）、多少数量（How many）**。

这两个层次不该混。正确做法：

```
EvidenceItem = 系统字段（定位用：DocCode / Anchor / Excerpt）
             + 事实字段（写句用：What / Where / When / Who / Why / HowMany）
```

**判断一条证据能不能用，先看这六个是否填齐**——比现在靠模型自由发挥"未见记录"要硬得多。而且这六个字段大部分能从抽取结果里直接取：`Where`=部门/车间、`When`=日期、`Who`=签署人、`HowMany`=RowCount、`What`=对象名、`Why`=事由。

**这是一个立刻能落地的修补**：给 `cert_evidence_item` 加 6 个字段，缺字段的不许进证据句。

### 2.2 乌龟图是"证据组织"的天然框架（图 26）

这才是本次最大的收获。

我们一直按**条款**组织证据，所以线索总在"条款 → 找什么文档"这条别扭的路上。而审核员的实际思路是按**过程**走的：

| 乌龟图方位 | 该问什么 | 对应证据 |
|---|---|---|
| 尾部 · 输入 | 这个过程的输入是什么、从哪来 | 订单/合同/领料单/采购申请 |
| 头部 · 输出 | 输出什么、交付给谁 | 检验报告/入库单/交付记录 |
| 左前脚 · 执行者 | 谁做、有没有资格 | 岗位职责/培训记录/资格证 |
| 右前脚 · 资源工具 | 用什么设备/软件/环境 | 设备清单/校准证书/工装台账 |
| 左后脚 · 方法程序 | 按什么做 | 程序文件/作业指导书/工艺卡 |
| 右后脚 · 绩效评价 | 做得怎么样、怎么衡量 | 目标/KPI/统计分析/合格率 |
| 核心 · 过程本身 | 过程怎么流转 | 流程图/工艺路线/批记录 |

**注意这张表：它把"找什么"从"条款"换成了"方位"。** 一个检查项（如 8.4.1 采购）落到乌龟图上，六个方位各要 1–2 份证据，一共 8–12 条，天然完整、天然不重不漏。

而现在的系统是"条款 → 文档类型"，缺一个方位就整块空着，还发现不了。

**建议**：`cert_clause_attr` 增加一维 `TurtleSlot`（in/out/who/what/how/measure），把每个条款挂到某个方位。这样召回就从"找条款对应文档"变成"找过程某方位的文档"，命中率会完全不同。

### 2.3 "应/宜"是条款的强制度，而且可机械识别（图 31）

| 词 | 含义 | 后果 |
|---|---|---|
| **应** | 强制要求 | 必须审，可开不符合项 |
| **宜** | 推荐建议 | 可提示改进，一般不开不符合项 |
| **可** | 允许 | 不作为判定依据 |

这是**条款属性的一个必填维度**，而且是唯一能从标准原文里用正则抽出来的属性（"应/宜/可"三个字就在句子里）。

它的作用很直接：**系统给建议时，"宜"类条款永远不该出"不符合"**。这能挡掉相当一部分误报。

同时它给"可判定度 A/B/C"补了一个乘数：A 级 + "宜" → 只提示；A 级 + "应" → 可出结论。

### 2.4 速查表四列 = 条款的证据四维（图 32、33）

审核员手里的速查表长这样：

| 条款号 | 条款关键词 | 审核要点 | 常见不符合项 |
|---|---|---|---|

以及模板版：

| 文件要求 | 实施要求 | 记录要求 | 改进要求 |
|---|---|---|---|

**这四列正是"证据形式"这一维的细分**（05 号 §2.2 说这是唯一必须人工配的维度）：

- **文件要求** → 查有没有规定（程序/制度/指导书）→ 对应"制度依据"角色
- **实施要求** → 查有没有做（现场/操作/标识）→ 对应"现场证据"角色
- **记录要求** → 查有没有留痕（表单/台账/清单）→ 对应"执行证据"角色
- **改进要求** → 查有没有变好（NC 闭环/目标达成）→ 对应"结论证据"角色

**四列 vs 我们的四角色，1:1 对上。**这说明 02 号的四角色设计是对的，只是没落到条款属性上。

而"**条款关键词**"这一列是我们**完全缺失**的——它是"在文档里搜什么词才能找到证据"的检索词表。现在召回靠条款号和过程名，所以永远找不到。**这一列补上，召回问题能解决一半。**

### 2.5 "填空模板"证实了"装配优于生成"（图 29）

培训里直接教：

> 事实描述：在（地点）发现（问题），记录显示（造假），当事人称（原话）。
> 理由：未对____实施有效监视，导致____。

**审核员自己写报告就是填空。**所以 05 号说的"报告是装配不是生成"，不是我的发明，是行业做法本身如此。

这也直接解释了 97 号那个现象：为什么我们的输出读起来不像审核员——因为我们在"生成句子"，而审核员在"填空格"。

## 三、这份材料对我们现有设计的三处纠偏

### 3.1 "个别记录缺失"不等于不符合（图 16）

图 16 说得很清楚：**孤立、偶发的问题，个别记录缺失但整体流程受控 → 只算一般不符合，甚至不算不符合。**

而现在的系统，因为召回丢掉了 86% 的记录类文档，就写"未见记录、未提供样本"——这是**把"我没找到"当成了"企业没有"**。

两件事必须分开：
- 我召回失败 → 系统缺陷，必须在诊断里标 `RecallMiss`，不能进证据；
- 企业确实没有 → 事实缺失，可作疑点，但要看覆盖矩阵（缺 1 份 vs 缺 90% 是两回事）。

**这条如果早立，四次实跑全都不会输出"未见记录"。**

### 3.2 依据和事实必须"对位"（图 19）

培训给了一个硬判据：**培训记录 → 7.2 能力**，不是 7.1.2 人员。

这意味着"事实类型 → 条款"存在一张确定的映射表，而不是靠模型判断。建这张表（20–30 行），就能挡住"串条款"这个老毛病。

### 3.3 一个检查项只出一个问题（图 20）

系统现在一个检查项出 2–3 条疑点，是把多个问题挤在一起。按图 20 的规则，**应该拆成 N 条独立证据 + 每条独立判定**。

这也是"证据条目化"（02 号的核心主张）的又一个外部依据。

## 四、8D 在体系认证里的位置

你提到"体系认证中有个 8D 模型"。先说清它是什么、在哪：

### 4.1 8D 的八个步骤

| 步骤 | 内容 | 谁做 |
|---|---|---|
| D0 | 紧急反应（临时围堵） | 企业 |
| D1 | 成立跨职能小组 | 企业 |
| D2 | **描述问题（5W1H）** | 企业 |
| D3 | 临时遏制措施 | 企业 |
| D4 | **根本原因分析（5Why / 鱼骨图）** | 企业 |
| D5 | 制定永久纠正措施 | 企业 |
| D6 | 实施并验证 | 企业（审核员验证） |
| D7 | 预防再发生（横展、更新体系文件） | 企业 |
| D8 | 小组认可与关闭 | 企业 |

### 4.2 它跟审核的关系：**在审核之后，不在审核之中**

对照图 30 那张表，8D 落在第 6 阶段"**审核后续活动：不符合根本原因分析及纠正措施验证**"，跟末次会议、编制报告都不在同一段。

所以结论很明确：

> **8D 是"企业侧"的产物，不是"审核员侧"的产物。** 你在做的产品是审核员工具，8D 不是它的核心。

但它对产品有两个真实用途：

1. **接口**：审核员开不符合项 → 企业交 8D → 审核员要验证闭环。系统可以帮审核员做"8D 报告与不符合项的对应校验"（D2 的事实是否就是我的不符合项、D6 有没有验证证据、D7 有没有横展到同类过程）。
2. **语言复用**：8D 的 D2 用的就是 5W1H，与审核证据完全同一套语言。所以证据字段设计一次，两处都能用。

### 4.3 不要做的事

- ❌ 不要做"AI 自动生成 8D 报告"——那是给企业做咨询，越界（95 号 R-C 的同类问题）；
- ❌ 不要把 8D 塞进核心流程——它在你现在的卡点（证据组织）之外，会把工期拉长。

**优先级：8D 是 P2，等证据链跑通再说。**

## 六、这份材料的局限（用之前要知道）

1. **它是培训视频，不是标准**。图 5 说"符合 ISO 9001 第 8.4.1 条"，图 13 引"ISO 9001:2015 第 7.1.5 条"，措辞偏 ISO 体系；GB/T 的条款号一致，但**表述以国标原文为准**。
2. **图 12 的三种表述（"未能提供""未按要求执行"）是最常见的不符合项写法，但正好是 95 号 R-A 禁止在"证据发现层"使用的话术**。两者不矛盾：那些是**结论层**的写法，不是事实层的。写文档时必须分层，否则模型会把结论当事实输出（这正是现在四次实跑的病根）。
3. **乌龟图源自汽车行业（IATF 16949）**，用在 19001/24001/45001 上属于方法借用，不是标准强制要求。但作为"证据组织框架"完全可用，因为审核员就是这么想的。
4. 图 14–15 的"严重不符合三种情况"含"系统性造假"，这是**判定**，不是识别。系统只能提示"模板痕迹"，不能下"造假"结论。
