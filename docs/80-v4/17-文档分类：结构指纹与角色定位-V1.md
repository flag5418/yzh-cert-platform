# 17 · 文档分类：结构指纹与角色定位（V1）

> **本文定位**：V4「文档分类」的唯一权威分析文档。此前多次口头解释（为什么分类失效、为什么不能靠文件名、四级文件是什么）反复重复 —— 全部收敛到本文，不再重复解释，只引用本文。
>
> **一句话结论**：本次 V4 的最大改变 = 文档分类从「**标准条款匹配**」彻底改为「**结构指纹 + 角色定位**」。分类判据不采信文件名/标题猜测，只采信原文可核验的结构证据。

---

## 一、问题现象（用户实测）

`管理评审记录.doc` 提取结果：

- 只有 1 条 `9.3` Finding；
- `DocSections: []`（文档自身章节全空）；
- `Chapters: ["9"]`（把标准第 9 章当成了文档章节）；
- 文档里明明有两小节（`行政、销售、采购` / `生产、质量、仓储`），一个字没提。

### 三层根因（缺一不可）

| 层 | 根因 | 现状证据 |
|---|---|---|
| **① 路由** | 分类靠**文件名子串**猜 | 文件名含「管理评审」→ `FromFileName` 命中 `AuditProfile` |
| **② 提取 Schema** | 提取产物**没有「文档章节」这一维** | `doc_extract_audit` 输出只有单一 `AuditProfile` 对象，`DocSections` 恒空 |
| **③ 已解析但未用** | `DocProfileJson.Toc` 已带 `CharStart/CharEnd`，提取阶段**没用** | 实测 `Toc` 2 节带偏移，`Sections` 却空 |

**结论：这不是 bug，是链路设计缺「文档章节结构」这一维 + 分类靠猜。**

### 根因的根因（最要命）

> 线上 `{{doc_profile}}` 注入的是**确定性画像**（`EnterpriseDocProfileBuilder.Build`），
> 其 `DocType` 由 `GuessDocType` 纯文件名子串匹配产出，且 `DocProfileJson` **不含 `ExtractionMode`**；
> 能产 `ExtractionMode` 的 `doc_profile` LLM 提示词 **只在 Admin「试跑」用，线上不跑**
> （`DocExtractRuleController.cs:395` 明写）。
>
> ⇒ 线上路由**必然**落到 `FromFileName` 文件名兜底。**分类 = 猜。**

**用户原话**：「我们文档的分类完全没有任何作用，不能识别关键的质量手册……不能准确区分类型，后续的工作就是瞎乱猜。」
**用户裁定**：「我不希望以后再听到兜底，那是就猜。专家花钱买我们的系统是要严谨，不能靠幻觉。」

## 二、行业定义核实（联网结论，校正认知）

### 2.1 四级文件结构（**国内认证行业实操分类**，非 ISO 正式术语）

| 级别 | 名称 | 层次 | 典型文件 | 结构特征 |
|---|---|---|---|---|
| 一级 | 质量手册 | 宪法 / 纲领层 | 质量手册、管理手册 | 颁布令 + 方针目标 + 组织职责 + **条款对照表** + 程序索引 |
| 二级 | 程序文件 | 跨部门过程规则层 | XX控制程序、XX管理程序 | **六段式骨架**：目的 / 适用范围 / 职责 / 工作程序 / 相关记录 / 相关文件 |
| 三级 | 作业文件 | 岗位作业执行层 | 作业指导书、操作规程、管理制度、规范、工艺卡、外来文件 | 单岗位工序 + 参数 + 判定标准；或「第X条」条款式 |
| 四级 | 记录 / 表单 | 证据层 | 各类记录、台账、表格 | 表格 + 实例数据（日期/数值/签名） |

### 2.2 三条分类实质依据

1. **文件面向未来（规定要求）** vs **记录反映过去（证明执行）** —— 记录不得随意修改。
2. **空白表单 = 受控模板**；填写后 = **正式记录**。二者结构相同，仅「有无实例数据」之别。
3. **手册承诺框架并「引用」程序编号**（不重复程序内容）；**程序文件管跨部门流程**（不写操作细节）。

### 2.3 强制性认知校正（易错点）

- **ISO 9001:2015 已取消强制质量手册**（统一术语「成文信息」）—— 不能假设「所有企业都必有手册」。
- **ISO 13485:2016 强制要求质量手册（4.2.2）**，并须概述体系文件结构。
- 「四级文件」是**国内行业实操说法**，不是 ISO 术语；标准号里找不到。

## 三、V4 转向：从「条款匹配」到「结构指纹 + 角色定位」

### 3.1 v3 困境（为什么必须抛弃条款匹配）

企业资料**不全、不成套、无条款号**是常态。若分类依赖「文档覆盖了哪些标准条款」，文档不全 ⇒ **无法归类**（v3 的死结）。而且用户明确要求：

> 「**不要依赖标准条款号**，假如企业的文档不是这个规则，每个企业的资料都不一样，我们就搞不定了，
> 得靠**文档的本身的内容和条款的解释**来匹配。」

### 3.2 新判据：结构指纹 + 角色定位

| 维度 | 来源 | 说明 |
|---|---|---|
| **结构指纹** | 代码（确定性） | 从 Markdown 提**客观可核验**结构证据（颁布令/六段式/条款对照表/表格密度/实例数据…），**零幻觉、零模型成本** |
| **角色定位** | 指纹（+ LLM 复核） | 依据命中的指纹判定 `DocType` / `ExtractionMode`；**必须回引命中的指纹当证据** |
| **判不出** | —— | 显式标 `unclassified` → **待人工确认**（⛔ 不猜、⛔ 不兜底） |

> 「有了明确的定义，才能按语义去正确识别，才能找到如何获取信息。」—— 用户

## 四、结构指纹表（可核验；判据全部来自原文客观证据）

> 权重：**高** = 单条即可定性；中 = 需 ≥2 条同族；低 = 辅助。
> 命中口径：`Key` 唯一标识；`Evidence` 记录命中的原文片段/位置（供人工复核）。

### 4.1 质量手册（`manual`）—— **特殊、必须有的核心文件**

| Key | 判据（原文客观证据） | 权重 |
|---|---|---|
| `manual.issue_order` | 开头 30% 内出现「颁布令 / 发布令 / 批准页 / 批准令 / 签署页」 | 高 |
| `manual.policy_objective` | 同时有「质量方针」与「质量目标」小节 | 高 |
| `manual.clause_mapping` | 存在「标准条款号 ↔ 手册章号」对照表（表格内同时出现 `4.x/5.x…` 与章号） | 高 |
| `manual.org_duty` | 有「组织机构 / 职责权限 / 组织架构」节且含多部门职责 | 中 |
| `manual.procedure_index` | 有「程序文件清单 / 程序目录 / 相关文件」且列出多个程序名 | 中 |
| `manual.std_chapter_span` | 顶层章节号覆盖标准 4–10 中 **≥5 个章** | 中 |

**判定**：命中 ≥2 条**高权重**，或 1 条高 + 2 条中 ⇒ `manual`。

### 4.2 程序文件（`procedure`）

| Key | 判据 | 权重 |
|---|---|---|
| `procedure.six_section` | 同时出现「目的」「适用范围」「职责」「工作程序/程序内容/工作内容/工作流程」「相关记录/相关文件」中 **≥4 段** | 高 |
| `procedure.cross_dept` | 正文出现 ≥2 个部门名且为「XX部负责/主管」 | 中 |
| `procedure.no_param_table` | **无**大量工艺参数表（区别于作业指导书） | 低 |

**判定**：`procedure.six_section` 命中（≥4 段）且非 `manual` ⇒ `procedure`。

### 4.3 作业指导书（`work_instruction`）

| Key | 判据 | 权重 |
|---|---|---|
| `wi.steps_or_params` | 出现「操作步骤/作业步骤/工艺参数/技术参数/操作要点」 | 高 |
| `wi.judgement` | 出现「判定标准/合格标准/检验标准/不良判定」 | 中 |
| `wi.single_station` | **无**六段式骨架（`procedure.six_section` 未命中） | 中 |

**判定**：命中 `wi.steps_or_params` 且非 `procedure` ⇒ `work_instruction`。

### 4.4 管理制度 / 规范（`policy`）

| Key | 判据 | 权重 |
|---|---|---|
| `policy.article_style` | 正文以「第X条」编号 | 高 |
| `policy.chapter_article` | 同时有「第X章」与「第X条」 | 中 |

### 4.5 记录 / 表单（`record`）

| Key | 判据 | 权重 |
|---|---|---|
| `record.table_density` | Markdown 表格行 / 总行 ≥ **0.30** | 中 |
| `record.instance_data` | 表格内出现实例值（日期/数值/人名）且非空数据行 ≥ 3 | 高 |
| `record.blank_form` | 表格结构存在但实例数据行占比低（**空白表单**） | 中 |
| `record.audit_or_review` | 出现「内审 / 管理评审 / 审核发现 / 不符合项」⇒ 走 `audit_profile` | 高 |
| `record.has_sections` | 有 ≥2 个文档小节标题（⇒ 提取须逐节承载） | 中 |

**判定**：`record.instance_data` 或 `record.table_density` ⇒ `record`；含 `record.audit_or_review` ⇒ `audit_profile`。

### 4.6 文件索引 / 清单（`index`）

| Key | 判据 | 权重 |
|---|---|---|
| `index.entry_list` | 条目列表（编号 + 名称），**无正文段落** | 中 |
| `index.toc` | 目录结构（标题 + 页码/章号），无正文 | 中 |
| `index.document_control` | 出现「受控文件清单 / 文件发放 / 文件回收 / 记录清单」⇒ 走 `document_control` | 高 |

### 4.7 组织环境 / 相关方清单（`context_list`）

| Key | 判据 | 权重 |
|---|---|---|
| `context.parties` | 「相关方」+ 清单 | 高 |
| `context.factors` | 「外部因素 / 内部因素」+ 清单 | 高 |

### 4.8 无标准相关性（`none`）

| Key | 判据 | 权重 |
|---|---|---|
| `none.non_qms` | 财务 / 人事 / 销售 / 考勤 / 后勤 等非 QMS 制度，且无体系结构指纹 | 中 |

## 五、角色定位与路由（一条链，无分支兜底）

```
Markdown 原文
   │
   ▼  ① 结构指纹（代码，确定性，零模型成本）
Fingerprints[]  ──►  ② 确定性角色定位（指纹规则表）
   │                   ├─ 置信度 ≥ 0.8：直接定 DocType/ExtractionMode（ClassSource=fingerprint）
   │                   └─ 置信度 < 0.8：③ LLM 角色定位复核（输入=指纹+Toc+关键片段，必须回引指纹）
   │                        └─ LLM 不可用/输出非法：保留确定性结果；仍判不出 ⇒ unclassified
   ▼  ④ 路由（只认 ExtractionMode）
ExtractionMode  ──►  doc_extract_* 提示词
   └─ unclassified / 缺失 ⇒ 「待人工确认」，⛔ 不猜、⛔ 不按文件名兜底
```

**硬规则**：

1. `EnterpriseDocExtractionRouter.Resolve` **只读 `ExtractionMode`**；⛔ **删除 `FromFileName` / `FromDocType` 关键词兜底**。
2. 判不出 = `unclassified` ⇒ 线上按「待人工确认」跳过（可人工在页面改画像后重跑）。
3. LLM 角色定位**必须回引命中的指纹 Key** 作为 `Evidence`；无指纹支撑的结论不予采信。

## 七、为什么「章节概要 + 章节原文」都要

用户原话：

> 「我们为什么要有章节的概要显示，因为我们给审核员提供证据发现的时候，如果不总结，直接原文显示出来，
> 又臭又长，浪费审核员的时间；但我们**还得保留原文**，因为我们**生成报告的时候要原文引用**。」

⇒ 设计为**双轨**：

- **概要**（`Summary`）：模型产，短，进审核员视图；
- **原文锚段**（`CharStart/CharEnd`）：代码按偏移切片，**零模型成本**，报告期原样引用。

## 八、验收（详见 `18-文档分类改造-测试计划-V1.md`）

1. **分类正确性**：质量手册 / 程序文件 / 作业指导书 / 记录 各 ≥1 份样本，`DocType` 与人工判断一致。
2. **零兜底**：构造一份「判不出」的文档，验证 `ExtractionMode=unclassified` 且**不按文件名猜**。
3. **章节承载**：`管理评审记录.doc` 重跑后，`Sections` 出现 2 节（`行政、销售、采购` / `生产、质量、仓储`），概要非空。
4. **原文锚段**：任取一节，按 `CharStart/CharEnd` 回取原文与页面一致。
5. **不回归**：原有质量手册（`manual_chapter`）链路不受影响。
