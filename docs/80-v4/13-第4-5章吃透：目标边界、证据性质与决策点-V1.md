## 一、4–5 章的证据性质（锁死的第一条边界）

1. 4–5 章内容（方针、目标、范围、职责权限、内外部因素、相关方需求）是**企业必须提供的**，审核员观察不出来。
2. 这些文件**在一阶段（文件评审）就必须完成**，不是靠与审核员沟通才临时有的。
3. 这些文件是**第一阶段制定完成、且实施满 3 个月**之后，才进入第二阶段（现场审核）。
4. 我们处理的是**第二阶段之后**的事情：二阶段取证 → 生成报告草稿。

**推论**：对 4–5 章而言，"文档证据"是主证据。ACM 三份报告的 4–5 章，每段 evidence 都在引用具体文件（手册某章 / 清单名+编制批准日期 / 程序文件号 / 任命书）。面谈段**当前直接忽略**，不做、不标。

**再补一条审核员角色的现实**：审核员 2–3 天要开会、拍照，**不可能写 2–3 万字现场发现**；他们真正关注的是**风险**——给企业过认证有责任风险，所以要签的是**不符合项**，不是埋头写发现。系统要做的，是把文档证据自动组装好，帮审核员快速核对"**文档有没有、企业有没有按自己写的文档执行**"。

## 二、完整证据流水线（定稿）

```
预处理（配置期，一次）                          ← 新增，第一刀先做它
  文档 → 按篇章切分（复用 Toc 锚点）→ 每篇章"语义精简"成要点 + 记录篇章位置
       → 产出「精简索引」

运行期（审核端，按检查项）
  ① 审核发现：条款 → 命中索引篇章 → 取精简要点（需原文则回取锚段）
     → 输出「该条款命中的企业实际信息」            ← 现在做，唯一指标 = 找得准
  ② 证据生成：发现 → 精简成 400–500 字，每条款一段   ← 后做
  ③ 组织/合并：多标准合并 + 同标准多条款合并         ← 最后做；前期单标准可暂缓

两层分工（两件事，不混）
  配置期（后台）：属性池 + 文档提取规则 + 语义精简 + 位置索引   ← 不依赖最终计划
  运行期（审核端）：审核计划 → 检查项 → 按规则和属性组织          ← 计划建好后才能做
```

## 三、已定稿的口径

### 3.1 审核员现场发现：移出当前范围

- 不提、不做、不标"待现场"。当前只做"企业文档 → 审核发现"这一条。
- 之所以不是现在做，是因为 4–5 章证据 80–90% 在文档里，且文档侧现在还是断的；先打穿文档侧。

### 3.2 条款合并：前期只做单标准，跳过特例

- 多标准同条款合并（3 体系 4.1 合一）≠ 同标准多条款合并（4.4.1+4.4.2→4.4），是两个独立问题。
- 生成阶段**每个条款一段、先分后合**；合并放最后独立阶段。
- **前期只做单标准（科斯亚 QMS）**，不适用条款、删减条款、多标准合并等**特例一律跳过**，不猜。

### 3.3 审核发现 vs 证据生成：两阶段，先发现

- **审核发现** = 从条款找回的企业实际信息；核心是**找得准**（不串条款、不遗漏、不多加多余条款信息）。
- **证据生成** = 把发现精简成 400–500 字；后做。
- 找得准不准，考验的是**文档属性 + 文档提取规则**，这是属性池的核心。

## 七、两条硬约束（新增，决定第一刀形态）

1. **性能**：手册 4–5 万字，逐条款/整篇喂 LLM 超过 120 秒出不来 → 必须**先语义精简 + 记录篇章位置**，运行期只取命中片段。
2. **审核员角色**：80–90% 证据来自文档；审核员关注风险/不符合项，不写长文。系统价值 = 组装文档证据、助其核对"文档是否落实"。
