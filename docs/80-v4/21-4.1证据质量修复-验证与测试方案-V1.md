### 4.3 行为验证（重跑 4.1 并检查装配快照）

```sql
SELECT ti.Code AS TaskItemCode, ti.CheckItemCode, ti.Status, ti.LastAnalyzedAt, d.ClauseNumbers
```

### 6.2 慢环节无法定位（缺分段计时）

事实：全仓 `DurationMs` **只统计 LLM 调用本身**（`result.DurationMs = llmResponse.DurationMs`），**无装配分段计时**。因此「具体慢在哪」当前**无法结论**。

方向判断：找证据（画像 + RM 匹配 + 白名单过滤 + 清洗）全是纯 C# 内存/DB，单条款应为毫秒级；耗时只可能在 ① 两段式 LLM 调用（`RunTwoStageAsync`）② 首次文档提取（离线）③ 逐条款串行。

**建议**：加 `Stopwatch` 分段（取明细 / 装配 / 两段 LLM），写回 `cert_check_analysis` 或日志，方可定论。
