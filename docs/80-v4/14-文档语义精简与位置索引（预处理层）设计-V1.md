# 14 · 文档语义精简与位置索引（预处理层）设计 · V1

> **定位**：13 号定稿后，第一刀从"按条款喂 LLM"改成"先建预处理层"。本文是预处理层的设计，落地前先按 §4 核对现状。
> **一句话结论**：手册 4–5 万字不能整篇/逐条款喂 LLM（120 秒+超时）；先离线把手册压成"篇章 → 要点 → 位置"的**精简索引**，运行期按条款命中索引取片段，需原文时按锚点回取。

---

## 一、为什么是它（根因）

质量手册 4–5 万字，之前"按条款逐个喂 LLM"每个都超过 120 秒出不来。根因是**没切分、整篇重复喂**：每条条款都带上全量手册。

解法是两层拆开：**离线预处理一次**（切分 + 语义精简 + 记位置），**运行期只取命中片段**。这也正好是规则驱动模型里"提取方式 E1/E2/E3"在性能约束下的实现载体——规则不变，只是提取不再逐条款重复喂整篇。

## 三、两层设计

### A. 离线预处理（配置期，一次）

1. **切分**：按 `DocProfileJson.Toc` 的 `CharStart/CharEnd` 把手册切成大篇章（用户口径：记录"**大概**位置"即可，不必精确到字）。
2. **语义精简**：每个篇章用 LLM 压成结构化要点：
   - 篇章标题 + 覆盖条款号；
   - 关键内容摘要（因素类别 / 职责 / 过程 / 方针原文等，按篇章类型）；
   - 关键**原文锚段引用**（哪段原文可原样回取）。
3. **落库**：每篇章一条精简记录，带 `锚点 + 条款号`，可溯源回原文。

### B. 运行期（审核端，按检查项）

1. 条款 → 命中精简索引中的篇章（按条款号）。
2. 取精简要点；需"原样"（如 4.3 范围、5.2.1 方针）时按 `CharStart/CharEnd` 回取原文锚段（**0 模型**回补）。
3. 组织"审核发现"。**绝不整篇喂 LLM。**

## 四·五、已确认结论（2026-11-23 只读核对，未改代码）

1. **手册已经抽好了，不用重做**：科斯亚《01管理手册QMS.doc》在 `cert_document_extraction` 已有 `doc_clause_extract` 产物，59 条，每条带 `Excerpts`（原文摘录）+ `ExcerptLocations`（原文位置）。4.1 / 4.2 / 4.3 / 5.2.1 / 5.3 五条直接对得上。
2. **4.4 / 5.1 对不上的根因是"对号方法不一致"**：
   - 手册抽出来的是**细号**：`4.4.1`、`5.1.1`、`5.1.2`（没有 `4.4`、`5.1` 粗号，也没有 `4.4.2`）。
   - ACM 报告（裁判）按**粗号**写：`4.4`、`5.1`。
   - 代码里有两套"对号"：`CertTaskService.IsClauseOrDescendantMatch` 认父子（`4.4` 能命中 `4.4.1`）；而 `CertCheckContextBuilder.ParseClauseSlices`（给 AI 拼上下文那条）**只认完全相同**（`wantedNumbers.Contains(number)`），所以 `4.4`、`5.1` 拿到的是**空资料**。
3. **结论**：第一刀不是"重新语义精简"，而是两处小修——① 统一"对号"为父子都认；② 补"细号并粗号"（`4.4.1 → 4.4`；`5.1.1+5.1.2 → 5.1`）。这两处改完，7 条里 5 条已通、2 条补上，4–5 章"找回"基本就齐了。

## 五、第一刀验收（预处理层跑通）

- 科斯亚 4.1–5.3 七条，能从精简索引找回对应内容，**不串条款、不遗漏、不多加**；
- 运行期单条款调用**不整篇喂手册**，耗时从 120 秒+ 降到秒级；
- 手册"原样段"（4.3 范围、5.2.1 方针）通过锚段回取原文，**不靠模型编**。

---

## 六、与规则驱动的关系（避免误解）

预处理层只是**执行载体**，不改规则驱动的结论：

- 规则仍定义在"证据形态 × 文档分类"上，不写死在章节号；
- `E1 条款摘录 / E2 表头抽行 / E3 摘要` 仍是不变的提取方式；
- 变的只是**调用方式**：从"逐条款重复喂全篇"变成"先索引、后命中取片段"。
