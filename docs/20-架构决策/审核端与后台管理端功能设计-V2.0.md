# 体系认证平台 —— 审核端 & 后台管理端 功能设计

> **版本**：V2.0 | **日期**：2026-07-28
>
> **定位**：本文档描述「审核端」和「后台管理端」两个 PC Web 端的功能设计。
>
> **前提确认**：
> - 技术栈：.NET Core + Vue 3 + MySQL + MinIO
> - 纯 PC Web 端（不做移动端）
> - AI 工作流采用开源方案（Dify / n8n），不自研引擎
> - 核心模型：以企业为中心，企业 → 阶段 → 任务
> - 企业资料分两层：企业基础资料（共享）+ 阶段资料（隔离）
> - 后台通过标准文件目录 + Skill 提取 + 工作流规则构成核心引擎
> - 所有 AI 结果可编辑，有可信度标注，人工有最终裁决权
> - Phase 1 仅支持 ISO 9001 一种标准，预设规则，不开放自定义

## 一、核心业务模型

### 1.1 企业生命周期

```
企业创建
  │
  ▼
初审 Stage 1 ──→ 初审 Stage 2 ──→ 一监 ──→ 二监 ──→ 再认证
  │ (完成)         │ (完成)         │ (进行中)│ (待开始)
  │                │                │          │
  ▼                ▼                ▼          ▼
阶段资料隔离      阶段资料隔离      阶段资料   阶段资料
（已归档）        （已归档）        （工作区）  （未生成）
```

### 1.2 企业资料分层模型

这是本文档最核心的模型变更。企业资料分为两层：

| 层级 | 内容 | 生命周期 | 可见范围 | 数据隔离 |
|------|------|---------|---------|---------|
| **企业基础资料** | 营业执照、质量手册、程序文件、组织架构图、资质证书 | 随企业存续，可更新 | 全阶段共享 | 所有阶段引用同一份 |
| **阶段资料** | 该阶段的运行记录、检查记录、证据附件、NC 整改证据、审核报告 | 随阶段创建，阶段归档后冻结 | 仅该阶段可见 | 不同阶段完全隔离 |

**阶段间引用规则**：
- 当前阶段可**只读引用**往期阶段的 NC 汇总（如「上一轮 NC 是否已关闭」）
- 不可修改往期阶段的资料
- 企业基础资料更新时，所有阶段引用的是最新版本

### 1.3 核心数据结构

```
企业 (Enterprise)
  ├── 基础信息（名称、信用代码、联系人、认证范围）
  ├── 企业基础资料（共享层）
  │   ├── 营业执照
  │   ├── 质量手册
  │   ├── 程序文件汇编
  │   ├── 组织架构图
  │   └── 资质证书 / 许可证
  │
  ├── 阶段列表（初审S1 → 初审S2 → 一监 → 二监 → ...）
  │   └── 每个阶段下：
  │       ├── 阶段资料（隔离层）
  │       │   ├── 运行记录（管理评审、内审计划、合规评价等）
  │       │   ├── 检查记录（本次审计任务的产出）
  │       │   ├── 证据附件（现场照片、抽样记录等）
  │       │   ├── NC 整改证据
  │       │   └── 审核报告
  │       │
  │       ├── 审计任务（可新建多个）
  │       │   └── 状态：排队中 → 执行中 → 完成
  │       └── 报告任务（可新建多个）
  │           └── 状态：排队中 → 执行中 → 完成
  │
  └── 归档状态：待执行 / 已归档
```

### 1.4 双路径模式

系统支持两种使用路径，共享底层引擎：

| 路径 | 适用场景 | 流程 |
|------|---------|------|
| **轻量路径** | 用户只想上传资料→分析完整度→生成报告 | 自动创建临时企业和当前阶段，完成后自动归档 |
| **完整路径** | 审核员管理长期客户，完整生命周期 | 手动建企业 → 手动建阶段 → 手动建任务 → 执行 |

轻量路径可随时升级为完整路径（临时企业转正）。

### 2.8 NC 管理页

**NC 设计原则**：Phase 1 保持轻量，不做复杂 ISO 规则匹配，AI 辅助生成。

**功能目标**：NC 全生命周期管理与整改跟踪。

**NC 列表字段**：

| 字段 | 说明 |
|------|------|
| NC 编号 | 自动生成，如 NC-2026-001 |
| 严重度 | 🔴 Major / 🟡 Minor / 🔵 Observation |
| 关联条款 | 审核员从检查表导航中自动带入，或手动输入条款号 |
| 描述 | 审核员用自然语言描述问题 → AI 辅助生成标准 NC 文本 |
| 状态 | 开启 → 整改中 → 待验证 → 已关闭 |
| 到期日 | 整改截止日期 |
| 负责人 | 企业对接人 |

**NC 生成流程**：

```
审核员在检查表判定为"不符合"
  → 弹窗：一键开 NC
  → 自动带入：当前条款号（如 7.2.1）
  → 审核员输入事实描述（业务语言）：
    "车间有3名焊工没有培训记录"
  → AI 辅助润色：
    "组织未能提供焊接岗位人员（3名）的培训记录，无法证明其具备相应能力。"
  → 审核员审阅、修改确认 → 保存
  → 可选：从企业基础资料关联证据文件
```

**NC 详情包含**：
- NC 基本信息
- 关联证据列表
- 整改记录时间线（含版本追溯）
- 审核员验证操作（通过/退回）

### 3.5 规则引擎配置（File Checklist）

**功能目标**：定义"企业应该提交哪些文件"以及"文件内容应该满足什么条件"。

**配置规则的口语化描述**：通过工作流编辑器，选中 `[标签]` 字段，加入条件节点，用自然语言描述条件。

```
示例规则：
「如果管理评审记录的评审日期 距离当前阶段审核日期 超过12个月，标记为风险项」

工作流节点表达：
  [ISO9001_初审S1_管理评审记录_评审日期] → 条件节点 → 输出
    条件：DATEDIFF(month, [评审日期], [阶段审核日期]) > 12
    结果：标记为风险项 "管理评审记录超过12个月有效期"
```

**规则测试沙箱**：每条规则支持输入模拟数据，输出执行结果，配置员可验证逻辑是否正确。

### 3.6 AI 工作流管理（Dify 集成）

**集成方式**：嵌入模式，Dify 作为编排引擎内核，不替换 Dify 原生保存机制。

### 4.2 核心 AI 场景

```

  → 调用 Skill: ocr_biz_license
  → 提取字段：企业名称、统一信用代码、法人、地址、注册资本
  → 自动填入企业信息表单
  → 标注可信度 → 用户确认/修改 → 保存
```

#### 场景 2：文件字段自动提取


### 4.3 AI 可信度策略

| 场景 | 可信度标注策略 | 说明 |
|------|--------------|------|
| 营业执照 OCR | 字段级可信度，阈值 90% 以上自动填入 | 低于 90% 时高亮提示人工确认 |
| Word/PDF 提取 | 字段级可信度，根据提取算法给出 | 模糊字段建议人工核查 |
| 报告生成 | 段落级可信度 | 告诉用户哪段可靠性高、哪段需要重点核对 |
| NC 润色 | 不标可信度，改为「AI 建议」标注 | 审核员必须确认后才能保存 |
