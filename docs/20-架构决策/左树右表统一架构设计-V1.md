# 左树右表统一架构设计（V1）

> **版本**：V1.1 | **日期**：2026-09-08 | **状态**：已定稿，强制执行
>
> 本文档定义：前后端统一控制器架构、配置驱动 UI 规范、统一 API 命名、数据契约、生命周期钩子。
> **本文件为 TreeTable 和单表 CRUD 架构的唯一权威表述**；所有相关编码必须对齐本文。
> 违反本文档的代码不得合入主分支。
>
> **V1.1 变更**：新增 `/filter`、`/export`、`/import` API；新增 `/tree/action/{name}` 树节点自定义操作；新增生命周期钩子虚函数（单表 + 树节点）。

## 三、后端 — YzhControllerBase\<V\>（单表 CRUD）

### 3.1 职责

负责所有单表 CRUD 操作：分页查询、新增、修改、删除、配置获取。

### 3.2 统一 API 清单

| API | 方法 | 请求体 | 响应 | 说明 |
|---|---|---|---|---|
| `/config` | GET | - | `ApiResponse<EntityConfig>` | 获取页面配置（表格+工具栏+表单） |
| `/page` | POST | `PageRequest` | `ApiResponse<PagedResult<V>>` | 分页查询 |
| `/add` | POST | V entity | `ApiResponse<V>` | 新增 |
| `/update` | POST | V entity | `ApiResponse<V>` | 修改 |
| `/delete` | POST | `string[] codes` | `ApiResponse<string>` | 批量删除（codes[]） |
| `/action/{methodName}` | POST | V entity | `ApiResponse<object?>` | 行操作（自定义按钮触发） |
| `/filter` | POST | `FilterRequest` | `ApiResponse<PagedResult<V>>` | 前端传过滤条件，后端自动拼 SQL 查询 |
| `/export` | POST | `ExportRequest` | `FileStreamResult` | 导出完整表结构数据（不受 GridConfig 限制） |
| `/import` | POST | `IFormFile` | `ApiResponse<ImportResult>` | 批量导入数据（用于快速数据更新） |
| `/import/template` | GET | - | `FileStreamResult` | 下载导入模板 |

### 3.3 EntityConfig — 表格页面配置（新增约束）

> **约束**：所有单表页面的 UI 必须由 `EntityConfig` 驱动，前端不允许硬编码工具栏按钮、搜索字段、行操作。

```csharp

    public int LayoutColumns { get; set; } = 2;

    /// <summary>工具栏按钮配置</summary>
    public ToolbarConfig Toolbar { get; set; } = new();

    /// <summary>行操作按钮配置</summary>
    public RowButtonConfig RowButtons { get; set; } = new();

    /// <summary>搜索条件配置</summary>
    public List<SearchFieldConfig> SearchFields { get; set; } = new();

    /// <summary>表格列定义</summary>
    public List<DefineColumn> Columns { get; set; } = new();

    /// <summary>表格是否只读（true=仅查看，隐藏所有编辑按钮）</summary>
    public bool ReadOnly { get; set; } = false;

    /// <summary>是否显示复选框列</summary>
    public bool CheckboxSelection { get; set; } = true;

```

### 3.4 FilterRequest — 前端过滤请求模型

> **设计目标**：前端将搜索栏的用户输入封装为 `FilterRequest`，后端自动解析并生成 SQL WHERE 子句，无需手动拼条件。

```csharp
/// <summary>前端过滤请求（后端自动拼 SQL）</summary>
public class FilterRequest
{
    public int Page { get; set; } = 1;
    public int PageSize { get; set; } = 20;
    public string? SortField { get; set; }
    public string? SortOrder { get; set; }

    /// <summary>
    /// 过滤条件集合
    /// 后端自动将每个 FilterItem 解析为 SQL 条件
    /// 多个条件之间为 AND 关系
    /// </summary>
    public List<FilterItem> Filters { get; set; } = new();
}

/// <summary>
/// 过滤项（前端传入，后端自动解析为 SQL）
/// </summary>
public class FilterItem
{
    /// <summary>字段名（对应实体属性或数据库列名）</summary>
    public string Field { get; set; } = string.Empty;

    /// <summary>操作符：eq/ne/gt/gte/lt/lte/like/in/between/isnull/isnotnull</summary>
    public string Operator { get; set; } = "eq";

    /// <summary>值（多值操作为逗号分隔，如 in: "1,2,3"）</summary>
    public string? Value { get; set; }

    /// <summary>第二个值（between 时使用）</summary>
    public string? Value2 { get; set; }
}
```

> **约束**：
> - `/filter` 与 `/page` 功能重叠时，**优先使用 `/filter`**，逐步废弃 `/page`
> - 后端必须自动解析 `FilterItem.Operator`，不允许手动 switch/case 每个字段
> - 前端通过 `EntityConfig.SearchFields` 知道有哪些搜索字段和对应操作符

### 3.8 ExportRequest / ImportResult — 导出导入模型

```csharp
/// <summary>导出请求</summary>
public class ExportRequest
{
    /// <summary>过滤条件（同 FilterRequest.Filters）</summary>
    public List<FilterItem> Filters { get; set; } = new();

    /// <summary>导出格式：excel/csv</summary>
    public string Format { get; set; } = "excel";

    /// <summary>导出字段（为空表示导出全部）</summary>
    public string[]? Fields { get; set; }
}

/// <summary>导入结果</summary>
public class ImportResult
{
    /// <summary>总行数</summary>
    public int TotalRows { get; set; }

    /// <success>成功行数</summary>
    public int SuccessRows { get; set; }

    /// <summary>失败行数</summary>
    public int FailedRows { get; set; }

    /// <summary>错误详情</summary>
    public List<ImportError> Errors { get; set; } = new();
}

public class ImportError
{
    public int RowIndex { get; set; }
    public string Field { get; set; } = string.Empty;
    public string Message { get; set; } = string.Empty;
```

> **约束**：
> - **导出必须是完整表结构**：导出时按实际数据库列生成 Excel，不受 `EntityConfig.Columns`（GridConfig）限制
> - **导入必须是批量更新**：前端上传 Excel 文件，后端解析并批量 insert/update
> - 导入模板 `/import/template` 提供标准化模板文件

### 3.9 单表生命周期钩子（虚函数：子类可覆盖）

> **设计目标**：子类通过覆盖以下虚函数，在**不修改基类代码**的前提下注入业务逻辑。

```csharp
public abstract class YzhControllerBase<V> : ControllerBase
{
    // ══════════════════════════════════════════════════════════
    //  查询钩子
    // ══════════════════════════════════════════════════════════

    /// <summary>构建查询条件（覆盖以实现自定义过滤逻辑）</summary>
    protected virtual List<FilterItem> OnBuildingQuery(RequestCondition[]? conditions)
    {
        return conditions?.Select(c => new FilterItem
        {
            Field = c.Field,
            Operator = c.Operator,
            Value = c.Value
        }).ToList() ?? new List<FilterItem>();
    }

    /// <summary>查询后钩子（字典翻译、字段格式化、脱敏等）</summary>
    protected virtual void OnQueried(PagedResult<V> result) { }

    /// <summary>配置加载后钩子（注入动态配置）</summary>
    protected virtual void OnConfigLoading(EntityConfig config) { }

    // ══════════════════════════════════════════════════════════
    //  新增钩子
    // ══════════════════════════════════════════════════════════

    /// <summary>
    ///     新增前校验（返回 false 可取消操作）
    ///     覆盖此方法实现：唯一性检查、业务规则校验、数据填充等
    /// </summary>
    protected virtual Task<(bool ok, string? msg)> OnBeforeAdd(V entity)
        => Task.FromResult<(bool, string?)>(true, null));

    /// <summary>新增后事件（数据已入库，事务内）</summary>
    protected virtual Task OnAfterAdd(V entity) => Task.CompletedTask;

    // ══════════════════════════════════════════════════════════
    //  修改钩子
    // ══════════════════════════════════════════════════════════

    /// <summary>
    ///     修改前校验（返回 false 可取消操作）
    ///     覆盖此方法实现：状态检查、并发校验、权限校验等
    /// </summary>
    protected virtual Task<(bool ok, string? msg)> OnBeforeUpdate(V entity)
        => Task.FromResult<(bool, string?)>(true, null));

    /// <summary>修改后事件（数据已入库，事务内）</summary>
    protected virtual Task OnAfterUpdate(V entity) => Task.CompletedTask;

    // ══════════════════════════════════════════════════════════
    //  删除钩子
    // ══════════════════════════════════════════════════════════

    /// <summary>
    ///     删除前校验（返回 false 可取消操作）
    ///     覆盖此方法实现：关联数据检查、级联操作、权限校验等
    /// </summary>
    protected virtual Task<(bool ok, string? msg)> OnBeforeDelete(string[] codes)
        => Task.FromResult<(bool, string?)>(true, null));

    /// <summary>删除后事件</summary>
    protected virtual Task OnAfterDelete(int count) => Task.CompletedTask;

    // ══════════════════════════════════════════════════════════
    //  提交后钩子
    // ══════════════════════════════════════════════════════════

    /// <summary>
    ///     提交后钩子（事务已完成，可执行通知/缓存清理等外部操作）
    ///     在 Add/Update/Delete 成功后都会调用
    /// </summary>
    protected virtual Task OnAfterCommitted() => Task.CompletedTask;

    // ══════════════════════════════════════════════════════════
    //  自定义校验
    // ══════════════════════════════════════════════════════════

    /// <summary>自定义校验（覆盖以实现复杂业务逻辑校验）</summary>
    protected virtual string? OnCustomValidate(V entity) => null;

    // ══════════════════════════════════════════════════════════
    //  导入导出钩子
    // ══════════════════════════════════════════════════════════

    /// <summary>构建导出数据（覆盖以自定义导出字段和格式）</summary>
    protected virtual async Task<Result<List<V>>> BuildExportData(List<FilterItem> filters)
    {
        // 默认使用分页查询逻辑，不分页获取全量
        var filters_ = OnBuildingQuery(null);
        var result = await Entity.GetPageAsync(new PagerOptions
        {
            Page = 1,
            PageSize = int.MaxValue,
            Filters = filters_
        });
        return result.Success
            ? Result<List<V>>.Ok(result.Data!.Items.ToList())
            : Result<List<V>>.Fail(result.Error);
    }

    /// <summary>处理导入数据（覆盖以自定义解析逻辑）</summary>
    protected virtual async Task<Result<ImportResult>> ProcessImport(List<V> entities)
    {
        var importResult = new ImportResult { TotalRows = entities.Count };
        foreach (var entity in entities)
        {
            var (ok, msg) = await AddCore(entity);
            if (ok) importResult.SuccessRows++;
            else
            {
                importResult.FailedRows++;
                importResult.Errors.Add(new ImportError
                {
                    RowIndex = importResult.SuccessRows + importResult.FailedRows,
                    Message = msg ?? "未知错误"
                });
            }
        }
        return Result<ImportResult>.Ok(importResult);
    }
}
```

> **约束**：
> - 所有 `OnBefore*` 钩子返回 `(false, "错误消息")` 可**取消操作**，友好提示用户
> - 所有 `OnAfter*` 钩子在**事务内**执行，如果钩子内抛异常会触发事务回滚
> - `OnAfterCommitted` 在**事务外**执行，适合发送通知、清理缓存等非数据操作
> - 覆盖钩子时**可以调用 base.Xxx()** 保留基类默认行为

### 3.10 业务控制器使用钩子示例

```csharp
[Route("api/[controller]")]
public class SysUserController : YzhControllerBase<Sys_User>
{
    public SysUserController(EntityService<Sys_User> service, IUserContext userContext)
        : base(service, userContext) { }

    /// <summary>新增前：检查用户名唯一性</summary>
    protected override async Task<(bool ok, string? msg)> OnBeforeAdd(Sys_User entity)
    {
        if (await Entity.Exists(u => u.UserName == entity.UserName))
            return (false, $"用户名 [{entity.UserName}] 已存在");
        return (true, null);
    }

    /// <summary>新增后：发送欢迎通知</summary>
    protected override async Task OnAfterAdd(Sys_User entity)
    {
        await _notificationService.SendWelcomeAsync(entity.UserName);
    }

    /// <summary>删除前：禁止删除超级管理员</summary>
    protected override async Task<(bool ok, string? msg)> OnBeforeDelete(string[] codes)
    {
        var hasSuperAdmin = await Entity.Exists(codes, u => u.RoleId == 1);
        if (hasSuperAdmin)
            return (false, "不能删除超级管理员账号");
        return (true, null);
    }

    /// <summary>查询后：翻译角色名称</summary>
    protected override void OnQueried(PagedResult<Sys_User> result)
    {
        var roleIds = result.Items.Select(u => u.RoleId).Distinct().ToList();
        var roleNames = _roleService.GetRoleNames(roleIds);
        foreach (var item in result.Items)
            item.RoleName = roleNames.GetValueOrDefault(item.RoleId, "未知");
    }
}
```

## 四、后端 — TreeTableControllerBase\<T, V\>（左树右表）

### 4.1 职责

在 `YzhControllerBase<V>` 基础上新增树能力，继承获得全部单表 CRUD。

```
T = 树节点实体（可来自 table / view / 多表组合）
V = 表格实体
```

### 4.2 继承关系

```csharp
public abstract class TreeTableControllerBase<T, V> : YzhControllerBase<V>
    where T : class, ITreeEntity, new()
    where V : class
```

### 4.3 统一 API 清单（树专用 + 继承）

| `/filter` | POST | `FilterRequest` | `ApiResponse<PagedResult<V>>` | 过滤查询（自动注入树过滤） | **覆盖逻辑** |
| `/add` | POST | V | `ApiResponse<V>` | 表格新增 | 继承 |
| `/update` | POST | V | `ApiResponse<V>` | 表格修改 | 继承 |
| `/delete` | POST | `string[]` | `ApiResponse<string>` | 表格删除 | 继承 |

### 4.4 TreeTableConfig — 左树右表页面配置

> **约束**：`TreeTableConfig` 由 `config` GET 接口返回，前端据此渲染整个页面。

```csharp
public class TreeTableConfig
{
    /// <summary>表格配置（复用 EntityConfig）</summary>
    public EntityConfig TableConfig { get; set; } = new();

    /// <summary>树配置</summary>
```

```csharp
    {
        if (string.IsNullOrEmpty(methodName))
            return BadRequest(ApiResponse.Fail("操作名称不能为空"));

        if (!_treeActions.TryGetValue(methodName.ToLowerInvariant(), out var handler))
            return BadRequest(ApiResponse.Fail($"树操作 [{methodName}] 未注册，请检查 RegisterTreeAction 调用"));

        var result = await handler(entity);
        return ApiResponse.Ok(result);

            .FirstOrDefault(c => c.Field == TreeConfig.RelateField);

        if (treeFilter != null)

            var conditions = request.Conditions
                .Where(c => c.Field != TreeConfig.RelateField)

                Value = treeFilter.Value,
                Operator = "eq"

            request.Conditions = conditions.ToArray();

        else

                    Items = Array.Empty<V>(),
                    Total = 0
                });
            // "all" → 不过滤，返回全部
```

### 6.1 CrudPageLogic\<V\> — 单表 Logic 基类

```typescript
/**
 * 单表 CRUD Logic 基类
 * 所有单表页面必须继承此类，不允许重新实现 loadPage/add/update/delete
 */
export abstract class CrudPageLogic<V extends Record<string, any>> {
    // ──── 状态 ────
    rows = ref<V[]>([])
    pagination = reactive({ page: 1, pageSize: 20, total: 0 })
    loading = ref(false)
    config = ref<EntityConfig | null>(null)

    // ──── 必须配置 ────
    abstract controllerName: string

    // ──── 统一查询 ────
    async loadConfig(): Promise<void> {
        const res = await yzhApi.get<EntityConfig>(`/api/${this.controllerName}/config`)
        this.config.value = res
    }

    async loadPage(params?: Partial<PageParams>): Promise<void> {
        this.loading.value = true
        try {
            const res = await yzhApi.post<PagedResult<V>>(`/api/${this.controllerName}/page`, {
                page: this.pagination.page,
                pageSize: this.pagination.pageSize,
                ...params
            })
            this.rows.value = res.items
            this.pagination.total = res.total
        } finally {
            this.loading.value = false
        }
    }

    // ──── 统一写入 ────
    async add(entity: Partial<V>): Promise<void> {
        await yzhApi.post(`/api/${this.controllerName}/add`, entity)
        await this.loadPage()
    }

    async update(entity: Partial<V>): Promise<void> {
        await yzhApi.post(`/api/${this.controllerName}/update`, entity)
        await this.loadPage()
    }

    async delete(codes: string[]): Promise<void> {
        await yzhApi.post(`/api/${this.controllerName}/delete`, codes)
        await this.loadPage()
    }

    async executeAction(methodName: string, entity: V): Promise<void> {
        await yzhApi.post(`/api/${this.controllerName}/action/${methodName}`, entity)
        await this.loadPage()
    }

    // ──── Split 数据方法（增量更新，不重新请求）────
    protected removeRowByCode(code: string): void {
        const idx = this.rows.value.findIndex(r => (r as any).code === code)
        if (idx >= 0) {
            this.rows.value.splice(idx, 1)
            this.pagination.total = Math.max(0, this.pagination.total - 1)
        }
    }

    protected replaceRowByCode(code: string, row: V): void {
        const idx = this.rows.value.findIndex(r => (r as any).code === code)
        if (idx >= 0) this.rows.value.splice(idx, 1, row)
    }

    protected insertRow(row: V): void {
        this.rows.value.unshift(row)
        this.pagination.total++
    }
}
```

### 6.2 TreeTableLogic\<V\> — 左树右表 Logic 基类

```typescript
/**
 * 左树右表 Logic 基类
 * 继承 CrudPageLogic<V> 获得全部单表能力，叠加树能力
 */
export abstract class TreeTableLogic<V extends Record<string, any>>
    extends CrudPageLogic<V> {

    // ──── 树状态 ────
    treeData = ref<TreeNode[]>([])
    treeLoading = ref(false)
    selectedNode = ref<TreeNode | null>(null)
    treeTableConfig = ref<TreeTableConfig | null>(null)

    // ──── 加载配置（覆盖：获取 TreeTableConfig）────
    async loadConfig(): Promise<void> {
        const res = await yzhApi.get<TreeTableConfig>(`/api/${this.controllerName}/config`)
        this.treeTableConfig.value = res
        this.config.value = res.tableConfig
    }

    // ──── 树加载 ────
    async loadTreeRoot(): Promise<void> {
        this.treeLoading.value = true
        try {
            const res = await yzhApi.post<{ rows: TreeItemDto[] }>(
                `/api/${this.controllerName}/tree/root`
            )
            this.treeData.value = res.rows.map(dto => this.dtoToNode(dto))
        } finally {
            this.treeLoading.value = false
        }
    }

    async loadChildren(node: TreeNode): Promise<TreeNode[]> {
        const res = await yzhApi.post<{ rows: TreeItemDto[] }>(
            `/api/${this.controllerName}/tree/children`,
            { parentCode: node.code, level: node.extra?.level ?? 0 }
        )
        const children = res.rows.map(dto => this.dtoToNode(dto, node))
        node.children = children
        return children
    }

    // ──── 树→表格联动（核心方法，统一实现）────
    async onNodeClick(node: TreeNode): Promise<void> {
        this.selectedNode.value = node
        await this.loadPageWithTree(node.code)
    }

    async loadPageWithTree(treeCode: string): Promise<void> {
        const cfg = this.treeTableConfig.value
        await this.loadPage({
            conditions: [{
                field: cfg?.treeConfig.relateField ?? 'parentId',
                value: treeCode,
                operator: 'eq'
            }]
        })
    }

    async loadPageWithoutTree(): Promise<void> {
        // 未选中树节点时：按 NoSelectionBehavior 决定
        const cfg = this.treeTableConfig.value
        if (cfg?.treeConfig.noSelectionBehavior === 'empty') {
            this.rows.value = []
            this.pagination.total = 0
        } else {
            await this.loadPage()  // 显示全部
        }
    }

    // ──── 树节点 CRUD ────
    async addTreeNode(data: Partial<TreeNode>): Promise<void> {
        await yzhApi.post(`/api/${this.controllerName}/tree/add`, data)
        await this.loadTreeRoot()  // 刷新树
    }

    async updateTreeNode(data: Partial<TreeNode>): Promise<void> {
        await yzhApi.post(`/api/${this/controllerName}/tree/update`, data)
        await this.loadTreeRoot()
    }

    async deleteTreeNode(code: string): Promise<void> {
        await yzhApi.post(`/api/${this.controllerName}/tree/delete`, [code])
        // 从树中移除节点
        const { tree } = treeOps.removeSubtree(this.treeData.value, code)
        this.treeData.value = tree
        // 如果删除的是当前选中节点
        if (this.selectedNode.value?.code === code) {
            this.selectedNode.value = null
            await this.loadPageWithoutTree()
        }
    }

    // ──── 页面初始化 ────
    async init(): Promise<void> {
        await this.loadConfig()
        await this.loadTreeRoot()
        await this.loadPageWithoutTree()
    }

    // ──── DTO → TreeNode 映射（子类可覆盖）────
    protected dtoToNode(dto: TreeItemDto, parent?: TreeNode): TreeNode {
        return {
            code: dto.code,
            name: dto.name,
            parentCode: dto.parentCode,
            nodeType: dto.nodeType,
            isLeaf: dto.isLeaf,
            extra: { ...dto.extra, level: (parent?.extra?.level ?? -1) + 1 },
            children: []
        }
    }
}
```

## 九、消除双调用机制

### 9.1 问题

el-tree lazy 模式下，点击节点展开时会自动调用 `loadChildren` 填充子节点；同时 `onNodeClick` 触发表格数据加载。如果两个调用使用同一接口，则产生双调用。

### 9.2 解决方案

```
┌─────────────────────────────────────────────────────────────────────┐
│                        职责分离                                      │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  tree.loadChildren(node)                                            │
│       │                                                             │
│       ▼                                                             │
│  POST /tree/children  →  只填充 node.children（更新树结构）         │
│                                                                     │
│  ─────────────────────────────────────────────────────────────     │
│                                                                     │
│  onNodeClick(node)                                                  │
│       │                                                             │
│       ▼                                                             │
│  loadPageWithTree(node.code)                                        │
│       │                                                             │
│       ▼                                                             │
│  POST /page { conditions: [{parentId: node.code}] }  →  刷新表格    │
│                                                                     │
│  ═══════════════════════════════════════════════════════════════   │
│  两个接口职责完全不同，不存在重复调用                                 │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

## 十、开发约束（强制）

### 10.1 后端约束

| # | 约束 | 说明 |
|---|---|---|
| 1 | 单表控制器必须继承 `YzhControllerBase<V>` | 不允许直接继承 ControllerBase |
| 2 | 左树右表控制器必须继承 `TreeTableControllerBase<T,V>` | 不允许直接继承 ControllerBase |
| 3 | 业务差异只能通过覆盖 virtual 方法实现 | 不允许绕过基类直接暴露新 API |
| 4 | 所有 API 必须遵循统一命名规范 | `/config /page /add /update /delete /tree/*` |
| 5 | 树接口返回必须是 `TreeItemDto` | 不允许返回数据库实体或匿名对象 |
| 6 | `/config` 必须返回完整配置 | 前端据此渲染页面，不允许前端硬编码 |
| 7 | 行操作必须通过 `RegisterRowAction` 注册 | 不允许在 Controller 中暴露额外 POST 方法 |
| 8 | 树节点操作必须通过 `RegisterTreeAction` 注册 | 使用 `/tree/action/{name}` 统一入口 |
| 9 | 实体必须实现 `ITreeEntity`（树实体） | Code/ParentCode 字段约定 |
| 10 | 生命周期钩子必须通过覆盖 virtual 方法实现 | 不允许绕过钩子直接操作数据库 |

### 10.2 前端约束

| # | 约束 | 说明 |
|---|---|---|
| 1 | 单表 Logic 必须继承 `CrudPageLogic<V>` | 不允许重新实现 loadPage/add/update/delete |
| 2 | 左树右表 Logic 必须继承 `TreeTableLogic<V>` | 不允许重新实现树加载/联动逻辑 |
| 3 | 工具栏/搜索栏/行操作必须由配置驱动 | 不允许在 Vue 模板中硬编码按钮 |
| 4 | 操作列按钮必须由 `RowButtonConfig` 驱动 | 不允许在模板中固定"编辑""删除" |
| 5 | 树操作按钮（添加/重命名/删除）必须由 `TreeConfig` 驱动 | 不允许在模板中固定 |
| 6 | 页面加载后必须先调 `loadConfig()` | 获取配置后再渲染页面 |
| 7 | 树与表格必须使用分离的 API 接口 | 不允许同一接口同时服务树加载和表格加载 |
| 8 | 删除/修改后使用 Split 方法增量更新 | 不允许重新请求整个 `/page` |
