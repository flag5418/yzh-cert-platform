## 三、真正的聚合 bug：精确匹配

当前 `CertTaskService.ProjectDocSlices`：

```csharp
var no = NormalizeNumber(...);
if (!clauseNos.Contains(no)) continue;
```

`clauseNos` 来自计划明细的 `ClauseRefsJson`。

### 3.1 三种情况

| 检查项 | 提取结果 | 当前结果 |
|---|---|---|
| 4.1 | 4.1 | 命中 |
| 8.5 | 8.5.1、8.5.2…8.5.6 | **不命中，AuditFindings=0** |
| 4.1 | 4.1.4、4.1.5 | **不命中** |
| 8.5.1 | 8.5.1 | 命中 |

这就是“按条款汇总”当前最大的问题：**父条款查不到子条款**。

### 3.2 应该怎么匹配

请求条款 `R`，提取条款 `N`：

1. `N == R`：命中；
2. `N` 是 `R` 的后代（`N.StartsWith(R + ".")`）：命中；
3. `R` 是 `N` 的后代（`R.StartsWith(N + ".")`）：只在没有 1/2 命中时作为 fallback，避免父条款整章内容污染子条款；
4. `RelatedClauses` 扩展：如 `8.5.1-h` 额外取 `8.6`、`8.5.5`；`8.5.1-c` 额外取 `8.6`；
5. 去重：同一文档同一段落只保留一条；不同文档保留来源。

### 3.3 这不是提取问题

99 份文档已经提取完成，8.5 有 40 份命中；现在缺的是**检查时的条款家族聚合**，不是重新提取。  
所以当前不需要重跑 99 份文档，先改聚合规则即可。

## 四、属性池仍然只是补字段

8.5.1 进一步确认，属性池不需要推翻，补 4 组即可：

### 4.1 `RequiredDocs`

8.5.1 需要：

- 生产和服务提供控制程序；
- IPQC/来料作业指示书；
- 设备台账/保养记录/运行环境记录；
- 特殊过程/关键过程确认记录；
- 首件/巡检/生产日报/工序流转卡；
- 8.6 放行记录；
- 8.5.5 交付后记录。

### 4.2 `FactKindExpectation`

8.5.1 应出现：

- `document`：程序、作业指导书；
- `record`：设备保养、首件、巡检、生产日报；
- `result`：特殊过程确认结论、放行结论；
- `reference`：工艺文件/图纸/BOM 引用。

### 4.3 `DoubtPolicy`

8.5.1 允许：

- `missing_result`：只有程序，没有记录；
- `not_implemented`：只有职责，没有执行；
- `partial_coverage`：a–h 某项缺；
- `maturity_gap`：再确认周期/记录不足；
- `reference_gap`：工艺文件/图纸/BOM 没有引用关系。

禁止：

- “标准没写环境安全，所以企业不该写”；
- “记录格式不好看”；
- “审核员可能不认可”。

### 4.4 `RelatedClauses`

8.5.1 关键跨条款：

- `8.5.1-c` → `8.6` 放行记录；
- `8.5.1-h` → `8.6` 放行、`8.5.5` 交付后；
- `8.5.1-f` → `7.1.5` 监视测量资源（适用时）；
- `8.5.1-d` → `7.1.3` 基础设施、`7.1.4` 环境。

这不是新表，只是在条款属性里加 `RelatedClauses`。

## 五、文档类型优先级

99 份文档里，有的封面/内审检查表也提取出 25–40 条条款，容易造成“假命中”。  
建议聚合时按文档类型排序：

1. 手册；
2. 程序文件；
3. 三阶作业指导书；
4. 记录/表单；
5. 封面、汇编、内审检查表（只作参考，不作为主证据）。

当前 `cert_enterprise_doc` 没有 `DocType`，可先从 `RelFolderPath` / 文件名推断；后续再加 `DocType`。
