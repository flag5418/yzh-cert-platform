# 文档分类与提取：完整提示词与提取内容 V1

> 本文件是可直接落库的规格：**分类提示词（1 条）+ 六型提取提示词（6 条）+ 各型字段清单 + 空表/扫描件判定 + 调用量估算**。
> 前提结论来自 06/07 号实证：报告里只有 31–45% 的文档真的出场；程序/三阶只需要"文件名 + 编号 + 一句概括"；手册只取 7 处事实；记录只抽被引用的那几份。

---

## 零、总体流程（一次上传，三步处理）

```
① 分类（每份 1 次轻调用，只喂文件名+前 1500 字）
   → doc_type / 相关性 / 过程域 / 是否空白 / 提取模式
② 分型提取（按 doc_type 走六型之一，大部分是规则解析，模型只兜底）
   → 事实条目（键/值/位置/原文锚点）
③ 落库 + 质量标记（空表、扫描件、低置信 → 不进"抽看"句式）
```

关键设计：**分类用模型，提取尽量不用模型。** 因为报告对多数文档只需要元数据（文件名、编号、标题），不需要正文理解。

## 一、分类提示词（完整版）

**输入**：`{文件名}`、`{所在目录}`、`{前 1500 字}`（空白则给"文本为空/仅图片"）
**调用**：每份文档 1 次（约 1,200 token 输入、150 token 输出）

```
你是体系认证资料分类助手。下面是一份企业提供的资料，请判断它在认证审核中的作用。
只输出 JSON，不要解释。

【输入】
目录层级：{rel_path}
文件名：{file_name}
正文前段：{text_head}
文本量：{chars} 字 / {pages} 页

【判断规则】
1. doc_type 取其一：
   - 手册：管理手册、质量手册、体系手册（含方针、范围、组织架构、职责、工艺流程）
   - 程序：程序文件、控制程序（"XX 控制程序"）
   - 三阶：作业指导书、管理办法、制度、规程、规范
   - 记录：已填写的表单、台账、检查表、报告（有日期/签名/数据）
   - 清单：受控文件清单、记录清单、法规目录、合格供应商名录、设备台账
   - 证照：营业执照、许可证、资质证书、校准证书、检验报告、人员资格证书
   - 空表：只有表头和空白栏，没有填写内容
   - 无关：与体系认证无关（如产品宣传、财务报表、私人文件）
2. relevance：体系相关 / 弱相关 / 无关。判断依据是"是否可能作为某条款的审核证据"。
3. process_domains 可多选，从固定值域里挑（不要自造）：
   management/design/purchase/production/inspection/metrology/warehouse/
   sales/after_sales/hr/env_safety/other
4. purpose：一句话（不超过 30 字）说明这份文件"规定了什么"或"记录了什么"，用报告里的口吻写，
   例如"明确了采购与供方管理要求""记录了 2026 年度培训实施情况"。
5. filled：已填写 / 空白模板 / 扫描件（文本量极低但有图像时判扫描件）。
6. extract_mode 取其一：
   - A_manual（手册：整篇定位）
   - B_meta（程序/三阶：只取元数据）
   - C_items（清单：逐条）
   - D_fields（记录/证照：按类型抽字段）
   - E_conclusion（结论类报告：抽结论与要素）
   - skip（无关/空表/无法识别）
7. confidence：0–1。低于 0.6 时在 reason 里写清不确定的原因。

【输出 JSON】
{
  "doc_type": "", "relevance": "", "process_domains": [], "purpose": "",
  "filled": "", "extract_mode": "", "confidence": 0.0, "reason": ""
}
```

**为什么只用前 1500 字**：文件类型主要由文件名 + 首段结构决定（"XX 控制程序"、"受控文件清单"、"培训记录表"），全文读完不改变结论，但成本差 10 倍。实测 06 号里三套资料的目录名本身就带类型信息，文件名准确率极高。

## 二、A 型 · 手册提取（整篇定位 7 处）

**输入**：整篇手册文本（分段编号后喂入，一次即可，手册一般 1–6 万字）
**输出**：7 类定位事实 + 原文段落

```
你是体系认证审核助手。下面是一份《管理手册》。任务：只抽取审核报告真正会引用的 7 类事实，
不要概括全书，不要评价，不要编造。找不到的项输出 null。

【必须抽取的 7 项】
1. 方针：质量/环境/职业健康安全方针原文（逐字，不改写）
2. 目标：可测量的目标条目（含指标值与统计周期，若有）
3. 范围：体系覆盖的产品/服务、场所地址、是否多场所
4. 删减：不适用条款及理由（原文）
5. 组织与职责：部门清单 + 每个部门 1 句职责（原文摘句，不要合并改写）
6. 工艺流程：关键过程、特殊过程、外包过程（逐项列出，没有则 null）
7. 手册自身元信息：手册编号、版本、发布日期、编制/审核/批准人

【规则】
- 原文引用必须是连续原文，允许截取，不允许改写、不允许拼接不相邻句子。
- 每一项给出 locator（所在章节号或标题）。
- 同一事实出现多处时，取最完整的一处。
- 输出严格 JSON，不要 markdown。

【输出 JSON】
{
  "policy": [{"text":"", "locator":""}],
  "objectives": [{"text":"", "indicator":"", "period":"", "locator":""}],
  "scope": {"products":"", "sites":"", "multi_site":true/false, "locator":""},
  "exclusions": [{"clause":"", "reason":"", "locator":""}],
  "departments": [{"name":"", "duty":"", "locator":""}],
  "processes": {"key":[], "special":[], "outsourced":[]},
  "meta": {"doc_no":"", "version":"", "issue_date":"", "prepared_by":"", "approved_by":""},
  "missing": ["policy","objectives",...]
}
```

**注意**：A 型**不做全文摘要**。06 号实测：手册 347–494 段里只有 1–4% 进报告，摘要没有用，只需要这 7 处。

## 三、B 型 · 程序/三阶提取（零模型，纯元数据）

报告对程序文件的写法是固定的：

> "组织编制了《外部提供过程、产品和服务控制程序》KSY-QMS-P-15，明确了采购和供应商管理的控制要求。"

需要的只是 **文件名 + 编号 + 一句话概括**。这三样都能从文件名/封面/首段标题拿到，**不需要模型读全文**。

**规则提取（建议用代码，不用 LLM）**

| 字段 | 来源 | 规则 |
|---|---|---|
| 文件名 | 文件系统 | 去掉扩展名 |
| 文件编号 | 文件名 / 封面首 3 行 | 正则 `[A-Z]{2,6}[-/][A-Z0-9]{2,}[-/]?\d{1,4}` |
| 版本 | 封面 | 正则 `[A-Z]/\d`、`版本[:：]\s*\S+` |
| 发布日期 | 封面/页脚 | 日期正则 |
| 概括 | **文件名去壳** | "《XX控制程序》" → "XX 控制要求"；动词映射见下表 |
| 适用部门 | 正文"适用范围"段 | 正则抓部门名 |

**概括句的动词映射（固定表，不用模型）**

| 文件名形态 | 概括动词 | 例 |
|---|---|---|
| XX 控制程序 | 明确了 XX 的控制要求 | 采购控制程序 → 明确了采购与供方的控制要求 |
| XX 管理办法 | 规定了 XX 的管理要求 | 客户拜访管理办法 → 规定了客户拜访与维护的管理要求 |
| XX 作业指导书 | 规定了 XX 的作业方法 | 焊接作业指导书 → 规定了焊接的作业方法与参数 |
| XX 管理制度 | 明确了 XX 的管理规定 | 仓库管理制度 → 明确了仓储与标识的管理规定 |

只有文件名无法判断"管什么"时（约 10–15%），才补一次极小调用：只喂文件名 + 第一段，让模型补一句。

## 四、C 型 · 清单提取（规则解析为主）

适用于受控文件清单、记录清单、法规目录、合格供应商名录、设备台账、校准台账。

**输出统一为条目表**：

```
{
  "list_type": "doc_list|record_list|law_list|supplier_list|equipment_list",
  "columns": ["序号","文件名称","编号","版本","状态"],
  "items": [{"no":"1","name":"","code":"","version":"","date":"","status":""}],
  "total": 0,
  "summary_sentence": "共列入 N 份文件，现行有效"
}
```

**解析要点**：xlsx 直接读单元格；doc 的表格用 `python-docx` 读 `table.cell`；无表格的清单（一行一条）按行切分并正则取列。**不需要 LLM**，除非列头缺失且列序不明，此时 1 次小调用判断列语义。

报告里的用法固定两种："共 N 项 / 现行有效" 或 "抽看其中 N 项：1、… 2、…"。

## 五、D 型 · 记录与证照提取（按记录类型定字段）

**核心原则：字段清单按"记录类型"定义，不按表格结构定义**（企业文档一般不是表格，是一行一条记录，06 号已证实）。

### D1 培训记录

```
字段：姓名 | 部门 | 岗位 | 培训主题 | 培训类型(入职/在岗/专项/转岗) | 日期 | 学时 | 考核方式 | 考核结果 | 讲师/机构
报告句式："抽查如下：1、张××，生产部，2026-03-12 参加《岗位技能培训》，考核合格"
```

### D2 检验/试验记录

```
字段：产品名称 | 规格型号 | 批次/工单号 | 检验项目 | 标准要求 | 实测值 | 判定 | 检验员 | 日期 | 检验阶段(进货/过程/成品)
报告句式："抽看 3 批次成品检验记录，检验项目含外观、尺寸、性能，判定均为合格"
```

### D3 校准证书

```
字段：设备名称 | 型号规格 | 出厂编号/资产编号 | 证书编号 | 校准机构 | 校准日期 | 有效期至 | 校准结论 | 不确定度
报告句式："外径千分尺，型号 (0~25)mm，证书编号 ××，有效期至 2027-03-01，结论合格"
```

### D4 合同/采购

```
字段：合同名称 | 合同编号 | 供方 | 需方 | 标的(品名/型号) | 数量 | 金额 | 履行期限(起-止) | 交货地点 | 签署日期 | 双方签章
报告句式："《散装水泥运输合同》：甲方××，乙方××，标的 P.O 42.5R，期限 2025-12-26 至 2026-12-25，双方盖章签字"
```

### D5 管理评审

```
字段：评审日期 | 主持人 | 参加部门/人员 | 评审输入项(逐条) | 评审输出/决议(逐条) | 结论(有效/需改进) | 上次决议落实情况
报告句式："以上措施的有效性在 2026-09-27 管理评审中进行了评价，评价结论为有效"
```

### D6 内部审核

```
字段：审核日期 | 审核范围 | 审核依据 | 审核组长/组员 | 受审部门 | 不符合项数量 | 不符合条款 | 整改状态 | 结论
报告句式："查见《内部审核报告》，审核目的、范围、依据齐全，开出不符合项 N 项，均已整改验证"
```

### D7 证照/资质

```
字段：证照名称 | 证号/统一社会信用代码 | 持有人 | 发证机关 | 有效期(起-止) | 许可范围/等级
报告句式："《营业执照》统一社会信用代码 91320412MA21WN6P1P，经营范围含…，有效期长期"
```

**提取方式（优先级）**

| 优先级 | 手段 | 适用 |
|---|---|---|
| 1 | 表格/单元格直读 | xlsx、doc 表格 |
| 2 | 行内正则 | 一行一条记录（"姓名：×× 日期：××"） |
| 3 | 页面 OCR | 扫描件（证照、手签表单） |
| 4 | LLM 兜底 | 只有 1–3 都失败时，按上面字段清单抽，输出 JSON + 原文锚点 |

**LLM 兜底提示词（D 型通用，按需调用）**

```
你是审核证据抽取助手。下面是一份《{record_type}》的文本（可能是表格行、也可能是自然语言段落）。
按给定字段抽取，只填文本中明确出现的内容；文本没写的字段填 null，禁止推测。

【字段】{fields}
【文本】{text}

【规则】
1. 每个字段必须给 evidence 片段（原文连续 10–40 字），用于回溯。
2. 日期统一为 YYYY-MM-DD；无法确定年月日时按原文保留并标注。
3. 数值保留原单位，不要换算。
4. 多个同类记录时逐条输出，最多 {limit} 条（默认 10）。
【输出】
{"records":[{"字段":..., "evidence":..., "confidence":0.0}], "record_count":0}
```

## 六、E 型 · 结论类报告提取

适用：管理评审报告、内审报告、合规性评价报告、目标达成统计、纠正措施验证。

```
你是审核证据抽取助手。这份是《{report_type}》。只抽"结论性事实"，不要复述过程描述。

【字段】
1. 结论：原文的结论句（"评价结论为有效""体系运行总体符合"），逐字
2. 日期：报告的出具/评审日期
3. 依据：评价所依据的标准/法规/文件清单
4. 要素：报告中列出的主要评价项目（逐条，各不超过 20 字）
5. 问题：发现的不符合/不足（数量 + 简要）
6. 后续：决议/改进措施（数量 + 简要）

【规则】结论句必须原文连续；找不到结论句时给 null 并在 missing 里标注。
【输出】JSON，每项带 locator。
```

## 七、F 型 · 现场型（不做提取，只做登记）

现场观察、访谈、测量、拍照——这些**没有文档来源**。系统只提供：

| 字段 | 说明 |
|---|---|
| 检查项 | 条款 + 部门 + 审核员 |
| 现场记录 | 审核员手填 / 语音转写 |
| 附件 | 照片（带时间地点）、录音片段 |
| 结论 | 符合 / 不符合 / 观察项 |

报告里对应"询问××，表示明确自己的职责""现场查见××"这类句子，由人工输入或语音转写生成，**模型不参与**。

## 八、空表与扫描件：必须先判，否则报告会编

06 号实测：尚龙 7 份、科斯亚 3 份记录是空表/近空表。

**判定规则（提取前执行）**

| 条件 | 判定 | 处理 |
|---|---|---|
| 字数 < 60 且无图像 | 空白模板 | 只登记"表单已建立"，不进抽看句 |
| 字数 < 200 且有图像 | 扫描件 | OCR；仍失败则转人工登记 |
| 表格单元格非空率 < 20% | 空白模板 | 同上 |
| 字数正常 | 正常 | 走对应型提取 |

报告里对应两种写法：空白 → "现场查见《××记录表》，已规定记录项目与保存要求"；正常 → "抽看 N 份，明细如下…"。

## 九、调用量估算（200 份文档 / 3 标准）

| 步骤 | 调用 | 说明 |
|---|---|---|
| 分类 | 200 次小调用 | 每次 1.2k 输入、150 输出，约 24 万输入 token |
| A 手册 | 3–6 次 | 每份手册 1 次 |
| B 程序/三阶 | 0–10 次 | 90% 靠规则；仅文件名不可判时补 |
| C 清单 | 0 次 | 纯解析 |
| D 记录 | 20–40 次 | 只对"被引用概率高"的 6 类记录做兜底 |
| E 结论 | 5–10 次 | 管评、内审、合规性各 1–2 次 |
| **合计** | **约 230–270 次** | 其中 200 次是廉价分类 |

对比 04 号原方案（200 文档 × 3 标准 = 600 次全条款提取），**主要成本从"理解全文"移到"分类 + 少量兜底"**，且 90% 的文档只走规则。

## 十、与 07 号的关系

| 07 号（条款侧） | 本文件（文档侧） |
|---|---|
| 按证据形态分 6 型（A–F） | 按文档类型分 7 类，映射到同一套型 |
| 决定"该写什么句式" | 决定"该抽什么事实" |
| 输出：段落骨架 + 槽位 | 输出：事实条目 |

**两边共用同一套型编号**，这样"条款 8.5 在生产部 + 检验记录"能直接定位到 D2 字段清单，不需要中间翻译层。
