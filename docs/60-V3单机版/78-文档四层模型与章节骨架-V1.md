# 78-文档四层模型与章节骨架-V1

> 目的：把文档提示词从“按文件格式写”改成“按标准大章节 + PDCA + 文档角色 + 提取深度写”。
> 这样标准改版、换标准时，只改章节映射，不用重写文档提示词。

---

## 0. 结论

1. **文档要求的第一层不是文件格式，而是标准大章节。**
   13485 的 4/5/6/7/8 五章，对文档的要求是相对固定的；条款只在章节默认之上做局部覆盖。

2. **大章节对应 PDCA 角色。**
   - 4 质量管理体系：P，体系文件与文件/记录控制；
   - 5 管理职责：P，方针目标、职责权限、管理评审；
   - 6 资源管理：P/D，培训、基础设施、工作环境；
   - 7 产品实现：P/D，设计、采购、生产、标识、防护、放行、监视测量；
   - 8 测量分析改进：C/A，内审、产品监视、不合格、数据、纠正预防。

3. **文档分四层，提取深度不同。**
   手册/方针只做“条款锚点 + 可引用片段”；程序只做“结构化摘要 + 相关表单”；制度/指导只做“适用对象 + 验收准则”；记录只做“字段 + 实际行 + 填写状态”。

4. **标准改版/换标准，只换 `StandardChapterMap`。**
   文档提示词按 `DocRole + ExtractionDepth` 复用；条款提示词按 `ChapterProfile + ClauseProfile` 组装。

---

## 1. 三层坐标

```text
第一层：标准大章节 / PDCA
        ↓ 固定文档要求
第二层：文档角色（手册 / 程序 / 制度指导 / 记录）
        ↓ 固定提取深度
第三层：条款局部覆盖（适用性、条件、证据契约）
```

**不要从“这份文件长什么样”出发；要从“这一章要求企业有什么文档、这些文档证明什么”出发。**

## 2. 13485 章节骨架

| 章节 | PDCA | 固定文档要求 | 典型文档 | 默认提取深度 |
|---|---|---|---|---|
| `4` 质量管理体系 | P | 质量手册、程序文件清单、文件控制、记录控制 | 手册、QP-001、QP-002、记录清单 | 手册 `citation_only`；程序 `structured`；记录 `fact_profile` |
| `5` 管理职责 | P | 方针目标、职责权限、管理评审 | 手册、QP-003、QP-004、方针目标 | 手册/方针 `citation_only`；程序 `structured`；记录 `fact_profile` |
| `6` 资源管理 | P/D | 培训、基础设施、工作环境 | QP-005、QP-006、QD-001、培训/设备/环境记录 | 程序 `structured`；制度 `criteria`；记录 `fact_profile` |
| `7` 产品实现 | P/D | 设计、采购、生产、标识、防护、放行、监视测量 | QP-011、QP-012、QP-021、QP-018、QP-014、QP-020、QP-024、作业指导书、记录 | 程序 `structured`；指导 `criteria`；记录 `fact_profile` |
| `8` 测量分析改进 | C/A | 内审、产品监视、不合格、数据、纠正预防 | QP-007、QP-024、QP-013、QP-026、QP-025、内审包/检验记录 | 程序 `structured`；记录 `fact_profile`；组合证据 |

**章节默认要求是“底线”，条款只覆盖差异：**
- `8.2.6` 在 8 章默认“产品监视 + 记录”，额外要求“接收准则、放行人、检测设备”；
- `7.5.1` 在 7 章默认“生产程序 + 作业指导 + 批记录”，额外要求“基础设施、标识包装、制造数量、批准流通数量”；
- `7.4.1` 在 7 章默认“采购程序 + 供方记录”，额外要求“评价准则、监视、再评价”；
- `8.3.2` 在 8 章默认“不合格程序 + 处置记录”，额外要求“交付前、让步、法规符合性”。

## 3. ChapterProfile 结构

```json
{
  "StandardCode": "dfca5483-f83c-4999-b773-3624de5f7cf7",
  "ChapterCode": "8",
  "ChapterName": "测量、分析和改进",
  "PDCAPhase": ["C", "A"],
  "DocumentRequirements": [
    {"DocRole": "procedure", "Purpose": "规定内审、产品监视、不合格、数据、改进"},
    {"DocRole": "record", "Purpose": "提供实施证据"},
    {"DocRole": "audit_pack", "Purpose": "内审计划/检查表/不合格报告/内审报告组合"}
  ],
  "DefaultExtractionDepth": {
    "procedure": "structured",
    "record": "fact_profile",
    "audit_pack": "fact_profile"
  },
  "ClauseRefs": ["8.2.1", "8.2.2", "8.2.3", "8.2.4", "8.2.5", "8.2.6", "8.3.1", "8.3.2", "8.3.3", "8.3.4", "8.4", "8.5.1", "8.5.2", "8.5.3"]
}
```

`ChapterProfile` 是**标准级配置**，不是企业级配置。换标准时只新增一套 ChapterProfile。

## 4. ClauseProfile 继承

```json
{
  "ClauseCode": "8.2.6",
  "ChapterCode": "8",
  "Inherits": "ChapterProfile:8",
  "Overrides": {
    "EvidenceContract": {
      "EvidenceItems": [
        {"DocRole": "procedure", "EvidenceRole": "establishment", "NamedExample": "过程和产品监视测量程序"},
        {"DocRole": "work_instruction", "EvidenceRole": "criteria", "NamedExample": "成品检验作业指导书"},
        {"DocRole": "record", "EvidenceRole": "implementation", "NamedExample": "成品检验记录"}
      ],
      "MustHaveFields": ["产品名称", "规格型号", "批号", "检验项目", "检验结果", "接收准则", "检验员", "放行人"],
      "Frequency": "每批",
      "ReportUse": ["sample", "coverage", "counter"]
    }
  }
}
```

**规则：**
- 条款没有写的，继承章节默认；
- 条款只写“差异”：条件、适用性、必备字段、频次、覆盖、报告用法；
- 不把整章要求重复写进每条条款。

## 5. DocLinkGraph：文档之间怎么引用

```text
手册 ── expands ──> 程序
程序 ── references ──> 相关文件（程序间）
程序 ── references ──> 相关表单（QR/PR/OR）
制度/指导 ── implements ──> 程序要求
记录 ── evidences ──> 程序/制度/指导
报告 ── cites ──> 手册/程序/指导/记录
```

**边类型：**

| 边 | 含义 | 来源 |
|---|---|---|
| `expands` | 手册展开为程序 | 手册章节引用 |
| `references` | 程序引用其他程序/表单 | 程序“相关文件/相关表单” |
| `implements` | 制度/指导落实程序要求 | 制度/指导“相关文件” |
| `evidences` | 记录证明执行 | 记录反引程序/表单 |
| `cites` | 报告引用文件 | 报告审核证据列 |

**关键：** 程序文件的“相关文件/相关表单”是现成的边，不需要模型猜。

## 6. 四层文档模型

| 层 | DocRole | 提取深度 | 只抽什么 | 不抽什么 |
|---|---|---|---|---|
| L1 手册/方针 | `manual` / `policy` | `citation_only` | 章节→条款锚点、关键承诺句、引用程序 | 不全文抽取、不逐句总结 |
| L2 程序 | `procedure` | `structured` | 目的、范围、职责、程序要点、相关文件、相关表单 | 不逐条抄程序正文 |
| L3 制度/指导 | `work_instruction` | `criteria` | 适用对象、检验项目、验收标准、抽样/判定、涉及记录 | 不抽无关管理段落 |
| L4 记录 | `record` | `fact_profile` | 关键字段、实际行、批次/日期/结论/签署、填写状态 | 不编造未填数据、不推断执行 |

**DocFact 统一字段：**

```json
{
  "DocClass": "manual | procedure | work_instruction | record | policy",
  "DocRole": "establishment | implementation | criteria | support",
  "Purpose": "",
  "Scope": "",
  "Responsibilities": [],
  "RelatedDocs": [],
  "RelatedForms": [],
  "Applicability": "",
  "FillStatus": "filled | partial | blank | absent | unreadable",
  "SampleRows": []
}
```

## 8. 提示词怎么组装

### 8.1 文档提示词

```text
DocPrompt = DocRole
          + ChapterProfile.DocumentRequirements
          + ExtractionDepth
```

不再按“记录类/程序类/制度类”各写一大套字段，而是：
- `DocRole=procedure` → 只问目的/范围/职责/程序要点/相关文件/相关表单；
- `DocRole=work_instruction` → 只问适用对象/检验项目/验收标准/抽样/记录；
- `DocRole=record` → 只问关键字段/实际行/填写状态；
- `DocRole=manual` → 只问章节锚点/承诺句/引用程序。

### 8.2 条款提示词

```text
ClausePrompt = ChapterProfile
             + ClauseProfile
             + EvidenceContract
```

条款提示词只写“这条比章节默认多要求什么”，不重复整章。

### 8.3 标准改版/换标准

| 变化 | 改什么 | 不改什么 |
|---|---|---|
| 13485 改版 | `StandardChapterMap` 的章节号/条款号 | 文档提示词、DocRole、ExtractionDepth |
| 换 9001 | 新增 9001 的 ChapterProfile（4~10 章） | 四层文档模型、DocLinkGraph |
| 换 14001/45001 | 新增对应 ChapterProfile，映射到 P/D/C/A | 文档角色与证据角色 |

**这就是“标准改版不重写提示词”的关键：提示词按章节角色复用，不按标准号复制。**

## 9. 跨标准映射

| PDCA | 13485 | 9001 | 14001 | 45001 |
|---|---|---|---|---|
| P | 4、5、6、7.1~7.4 | 4、5、6、7、8.1~8.4 | 4、5、6.1、6.2、8.1 | 4、5、6.1、6.2、8.1 |
| D | 7.5 | 8.5 | 8.1 | 8.1 |
| C | 7.6、8.2 | 9.1 | 9.1 | 9.1 |
| A | 8.3、8.4、8.5 | 9.2、9.3、10 | 9.2、9.3、10 | 9.2、9.3、10 |

**章节号不同，但文档角色和证据角色相同：**
- P：方针/目标/职责/策划/程序；
- D：作业指导/操作记录；
- C：监视测量/内审/检查记录；
- A：不合格/纠正/改进记录。
