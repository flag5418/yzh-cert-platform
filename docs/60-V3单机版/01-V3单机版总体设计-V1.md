# V3 单机版 · 总体设计与实施计划 V1

> 文档定位：V3 的唯一权威设计文档。AI 接手 V3 任务时读这一份即可。
> 与 V2 的关系：V2（`docs/70-V2设计/`）不删除、不修改，作为**论证材料与经验来源**保留；V3 是产品形态与目标函数的重新定义，不是 V2 的续作。
> 依据来源：`docs/70-V2设计/依据/CNCA-QMS-01-2025-全文提取.txt`、`docs/90-归档/案例/脱敏版/`（真实审核记录）、四份国标 PDF。
> 状态：设计稿，待确认项见附录 B。

## 0. 一句话

**一个 Windows 便携版小工具：读审核员手上的企业认证资料，按条款与部门的归属，自动写出带出处、带抽样、带覆盖声明的审核记录与报告草稿，审核员只改几个字就能签发。**

---

## 1. 定位与边界

### 1.1 定位

| 项 | 定义 |
|---|---|
| 产品形态 | Windows 便携版（zip + 启动器 + 本地 localhost 浏览器），零依赖、免安装、无需管理员权限 |
| 用户 | 第三方认证机构的审核员（个体执业者，按人天计费，报告写作是无偿加班） |
| 付费方 | 审核员个人（按份 / 包年），不是机构 |
| 交付物 | Word 报告草稿 + 审核记录表 + 不符合项卡片草稿 |
| 核心价值 | 把审核员 4–8 小时的无偿写作时间压到 30 分钟以内；输出**敢签字** |
| 数据边界 | 原始资料只在本机；仅必要片段送模型分析，不留存 |

### 1.2 三个不变的产品原则

1. **不编造**：每个事实槽位必须挂 `SourceRef`，无出处不出句。
2. **不判定**：结论词由审核员确认，系统只给候选 + 证据。
3. **不替代**：只覆盖"材料可支撑"的部分，现场与访谈留给审核员。

### 1.3 本期明确不做

手机端 / 企业端账号 / 多租户 / 权限矩阵 / 审批流 / 消息通知 / 队列服务 / Redis / MinIO / Docker / 机构私有化部署 / 多语言 / 性能优化 / UI 美化。

| 归档不可编辑要求 | CNCA 10.3 | 导出即冻结 |

### 2.4 已踩过的教训（不要重犯）

1. **不要先建平台**：模块地图、权限、审批、菜单，全部是"做完了却卖不掉"的部分。
2. **不要用编造换覆盖率**：证据 0 份时不硬卡，但也绝不凭空生成。
3. **不要按"条款 1:1"生成报告**：真实报告的单位是"部门 × 条款组"。
4. **不要三套表名并存**：V3 只有一套表，旧表一律不引用。
5. **不要微调模型**：改为"抽取 + 规则 + 措辞"，可复现、可评测、成本低。

## 3. 六条硬约束

| # | 约束 | 违反后果 |
|:--:|---|---|
| C1 | 每个事实槽位必须有 `SourceRef`（文件 + 页码 + 原文片段哈希） | 伪造审核记录，法律责任 |
| C2 | 找不到证据时，只允许输出"未见/待确认"，禁止输出"符合" | 同上 |
| C3 | 结论词（符合/基本符合/不符合/不适用）必须由人确认后才进入报告 | 责任错位 |
| C4 | 生成单位是 `部门 × 条款组`，不是单条款 | 报告变成碎话，不像人写的 |
| C5 | 报告导出即快照，导出后不 joins 实时数据（CNCA 10.3 不可编辑） | 归档失效 |
| C6 | 不引入任何需要管理员权限、后台常驻服务、容器运行时的依赖 | 安装率归零 |

## 4. 三层结构（整套设计的骨架）

```
L1 条款层     条款 → 要素（要求什么，与部门无关）
                例：7.5 要素 = 标识 / 格式载体 / 评审 / 批准 / 发放回收 / 作废

L2 归属层     (部门 × 条款) → 该部门该条款查什么证据、证据类型、角色
                例：7.5 × 行政部 → 受控文件清单、发放回收表、审批签署
                    7.5 × 生产部 → 现场作业文件版本、生产记录表受控性

L3 记录层     (部门 × 条款组) → 一段审核记录 = 若干句子 + 引用证据 + 结论候选
                ← 这才是报告里的一格
```

**为什么要三层**：同一条款在不同部门的证据完全不同；而报告又要按部门成段。只有把"要求（L1）—归属（L2）—成段（L3）"拆开，才能既复用条款又不写成外行话。

| `DeptHintJson` | json | 常见承接部门（建议值，不强制） |

### 5.2 `ElementsJson` 结构

```json
[
  {
    "elementCode": "7.5-E1",
    "text": "成文信息有唯一标识（编号/标题）",
    "judgeLevel": "A",
    "evidenceTypes": ["受控文件清单", "文件首页"],
    "factKeys": ["docNo", "title"],
    "wordingTpl": "查见《{title}》（文件编号：{docNo}）",
    "missingTpl": "未见《{title}》的编号标识"
  }
]
```

- `evidenceTypes`：该要素需要哪几类证据（用于检索）
- `factKeys`：需要从证据里抽哪些事实字段（对应 `cert_evidence.FactKey`）
- `wordingTpl` / `missingTpl`：齐备与缺失两种措辞（模板只做拼装，不生成事实）

## 6. 生成流程（五步）

```
① 取归属   PlanRow → 展开 ClauseGroup → 查 cert_clause_dept 得每个 (部门,条款) 的证据清单
② 取证     按 (DeptCode, ClauseCode, evidenceTypes) 在 cert_evidence 召回；同时取该条款切片
③ 判齐备   逐要素评三态：complete / partial / missing（判的是证据齐备度，不是条款符合性）
④ 填槽     按句式模板生成句子；事实全部来自 cert_evidence.FactValue + SourceRef
           齐备 → 依据句 + 查见句 + 抽样句
           部分 → 写已有 + "未见××，需现场确认"
           缺失 → 不出"符合"，标记待确认
⑤ 拼段     按 ClauseGroup 顺序合并；同一 DocCode 只引用一次；末尾给结论候选 + 覆盖声明
```

**关键分工**：

| 角色 | 做什么 |
|---|---|
| 代码 | 召回证据、判齐备度、拼句、算覆盖、给结论候选 |
| 模型 | 只在"语义匹配"和"措辞润色"两处介入，不改事实、不改结论 |
| 人 | 确认结论词、补充现场证据、签发 |

### 7.1 七种句式

| # | 句式 | 真实例句（节选） | 槽位 | 来源 | 程序化 |
|:--:|---|---|---|---|:--:|
| S1 | 定位 | 行政部负责人：林峰，陪同人：冯磊，审核人：王芳，2026 年 8 月 3 日 | 部门/负责人/陪同/审核员/日期 | 计划 + 访谈 | ✅ |

| S3 | 查见 | 查见《管理手册》（文件编号：XXKJ-QESM-2025）版本 A/1，2025 年 9 月 1 日发布，编制：行政部，审核：杨凯，批准：郑伟 | 名称/编号/版本/发布日/编制/审核/批准 | `Kind=fact` | ✅ |
| S4 | 抽样 | 抽 1：培训时间 2025.9.16，项目：三标准培训，地点：会议室，讲师：罗勇，签到：赵**、孟** | 样本 × 关键字段 | `Kind=segment` + 表格抽取 | ✅ |

### 7.2 要素拆解示例（GB/T 19001-2016 7.5 成文信息）

| 要素 | 要求 | 级别 | 证据 | 缺失措辞 |
|---|---|---|---|---|
| E1 | 成文信息有唯一标识 | A | 受控文件清单、文件首页 | 未见《X》的编号标识 |
| E2 | 标识含日期/作者等说明 | A | 文件首页、版本记录 | 文件未见发布日期与编制人 |
| E3 | 格式与载体适配 | A | 文件本体、载体信息 | 文件无法识别版本/载体 |
| E4 | 发布前经评审 | B | 会签单、审批记录 | 发布前未见评审记录 |
| E5 | 发布前经授权批准 | B | 批准签署 + 岗位授权表 | 批准人非授权人员（依据《岗位授权表》） |
| E6 | 发放/回收受控 | A | 发放回收一览表 | 未见发放回收记录 |
| E7 | 作废/外来文件受控 | A | 作废清单、外来文件清单 | 未见作废文件处理记录 |

### 7.3 同条款不同部门（7.5 的两段）

| 部门 | 查什么 | 证据 | 生成的句子 |
|---|---|---|---|
| 行政部 | 文件控制体系 | 受控文件清单、发放回收表、审批签署 | 查见《受控文件清单》…抽查 3 份发放记录，签收齐全 |
| 生产部 | 现场文件是否有效版本 | 工位悬挂文件版本、记录表受控号 | 现场查见 3 个工位悬挂的作业指导书均为 A/1 版，与受控清单一致 |

> 若按"条款 → 一段"生成，这两段必然搅在一起。这是三层结构存在的唯一理由。

### 7.4 "未见"的二分法（必须写进代码）

| 情形 | 判定 | 措辞 |
|---|---|---|
| 抽样范围内未见文件/记录 | 待确认（不是不符合） | "抽样范围内未见××，待现场确认" |
| 现场核实确不存在 | 不符合 | "现场查见未配置××，不符合××条款 N" |

两者在报告里几乎同形，法律后果完全不同。**这条不允许交给模型判。**

## 8. `SourceRef` 规范

```
sourceRef = {
  "doc":   "DOC-0001",
  "file":  "质量手册.docx",
  "page":  3,
  "anchor":"3.2 文件控制",
  "hash":  "sha1:9f2c...",
  "text":  "查见《管理手册》（文件编号：XXKJ-QESM-2025）版本 A/1"
}
```

规则：

1. 每个事实槽位必须有 `sourceRef`；`text` 是**原文片段**（用于校验，不是给人看的摘要）。
2. 报告预览时点击可跳原文；导出 docx 时保留为批注或脚注（可选开关）。
3. `hash` 用于导出后校验：若原文与哈希不符，报告标记"证据已变更"。
4. 没有 `sourceRef` 的句子，生成阶段直接拒绝落库（C1 闸门）。

## 10. 审核计划最小模型

不做排期、不做人天计算、不做抽样公式。只要一张表：

```
项目 → 计划行（部门 × 条款组 × 审核员 × 方式 × 顺序）
```

**归属矩阵怎么来**：

1. 从手册/程序/岗位职责抽"部门职责摘要"；
2. 用条款的 `DeptHintJson` 与职责做语义匹配，产出 `primary` / `related` **建议**；
3. 审核员在界面上确认/调整（10 分钟内完成）；
4. 确认结果写回 `cert_clause_dept.Source = manual`。

## 11. 技术形态与打包

### 11.1 运行方式

```
启动器 exe（单文件）
  ├─ 自包含 .NET（win-x64，self-contained，用户无需装运行时）
  ├─ 本地 HTTP 服务（127.0.0.1，自动选空闲端口）
  ├─ SQLite 单文件库（数据放程序目录 data/）
  ├─ 打开默认浏览器
  └─ 退出时保留后台或做托盘（择一）
```

### 11.2 依赖清单（零外部依赖）

| 能力 | 方案 | 不引入 |
|---|---|---|
| 运行时 | `dotnet publish -r win-x64 --self-contained` | ✗ .NET 安装包 |
| 数据库 | SQLite（`Microsoft.Data.Sqlite` / SqlSugar SQLite） | ✗ MySQL、✗ Docker |
| 缓存 | 进程内字典 | ✗ Redis |
| 文件存储 | 本地目录 | ✗ MinIO |
| Word 输出 | OpenXML 直出 docx | ✗ LibreOffice |
| PDF 解析 | 纯 .NET 库（如 PdfPig） | ✗ 外部二进制 |
| 扫描件 OCR | 便携 tesseract（可选增强包） | ✗ 预装 |
| `.doc` 转换 | 要求另存为 `.docx` | ✗ Office 依赖 |

### 11.3 Windows 必须处理的细节

1. 中文路径与空格：全部 UTF-8 + 引号，禁用裸字符串拼接。
2. 杀软误报：早期用便携 zip，不做安装器；后期再考虑签名。
3. 端口占用：启动器自动探测空闲端口。
4. **每日自动备份**：把 SQLite 文件复制到 `data/backup/{yyyyMMdd}.db`，保留 7 天。
5. 离线降级：无网时只做解析 + 模板拼装，标注"待联网生成措辞"，不崩溃。

### 11.4 交付形态

| 包 | 内容 | 体积 |
|---|---|---|
| 主包 | exe + 前端静态资源 + 模板/规则 JSON | 约 150–250MB |
| 增强包 | tesseract（chi_sim）+ 可选解析器 | 约 60MB，按需下载 |

## 12. 验收指标（金标集方法）

用专家提供的**过程数据**建金标（终版报告只能评"像不像"，检查清单与草稿才能评"对不对"）：

| 指标 | 目标 | 测法 |
|---|---|---|
| 条款覆盖 | 100% | 生成结果 vs 计划条款清单，做差集 |
| 事实句采纳率 | ≥80% | 逐句 diff，统计事实被改动比例 |
| 判定一致率 | ≥90% | 与专家报告条款级三态混淆矩阵 |
| 单份报告耗时 | ≤30 分钟 | 真实试用计时 |
| 零编造 | 100% | 抽 50 句，逐句回指 `SourceRef` |

**评测集最低配置**：5 份完整项目（企业资料包 + 计划 + 检查清单 + 终版报告 + 草稿）。
