# 文档提取误映射抽检 V1

> 对象：全量 99 份企业文档的 `cert_document_extraction`
> 重点：4.1、8.5.1
> 结论：**聚合层已修好；现在主要问题转回提取层——模型会把“提到条款号 / 文件名相近 / 制度类内容”误标成该条款事实。**

## 二、8.5.1 抽检

8.5.1 当前 93 条发现，来自 40 份含 8.5 的文档。明显误标 5 份：

| 文档 | 提取的“8.5.1 原文” | 判定 |

| `02公司财务管理制度.doc` | 现金、银行、记账凭证、会计报表 | **误标**，属财务资源，不是生产服务提供 |

这些文档的共同特征：

1. 文件名与 8.5.1 无关；
2. 提取出的 `Anchor` 是章节标题或制度条款；
3. 内容没有生产/服务受控条件、设备、人员资格、过程确认、防错、放行等要素；

- b 监视测量资源：有设备保养，但缺计量器具校准/检定证据；

## 三、根因

### 3.1 提取提示词只做“条款匹配”，不做“文档适用性判断”

当前 `DocExtractPromptService.FallbackTemplate` 的核心要求是“逐条摘录原文”，没有要求模型先判断：

- 这份文档的**主题/目的**是什么；
- 它**适用于哪些条款**；
- 文中出现“4.1”“8.5.1”时，是**在讲该条款要求**，还是**只是引用条款号**；
- 出现“培训”“财务”“考勤”“销售”时，是否真的属于该条款的受控条件。

结果：模型按关键词/条款号字面匹配，产生大量误标。

### 3.2 没有 `DocType`

`cert_enterprise_doc` 没有 `DocType`，提取时无法区分：

- 手册；
- 程序文件；
- 作业指导书；
- 记录/表单；
- 封面/汇编/清单；
- 内审/管理评审记录。

不同文档类型对同一句话的证据力完全不同。

### 3.3 没有 `FactKind`

当前 `Excerpts` 只是文本数组，没有区分：

- `requirement`：规定应做什么；
- `result`：实际识别/评价结果；
- `record`：记录已执行；
- `reference`：只是引用/索引；
- `extra`：条款外内容；
- `exclusion`：明确不适用。

模型只能把“提到”当成“事实”。

### 3.4 整篇 15k 分块导致跨条款污染

`ClauseExtractExecutor` 还是 `ChunkChars=15000` 整篇分段，模型在一段里同时看到 4.1、6.1、7.2、8.5.1，容易把相邻条款内容互相串。

## 四、修正规则

### 4.1 提取前先做文档适用性判断

每份文档先输出：

```json
{
  "DocType": "manual|procedure|work_instruction|record|index|audit_record|review_record|other",
  "DocPurpose": "",
  "PrimaryClauses": ["8.5.1"],
  "SecondaryClauses": ["8.5.2"],
  "NotApplicableClauses": ["4.1"],
  "ReferenceOnlyClauses": ["6.1.1"]
}
```

提取时只允许在 `PrimaryClauses / SecondaryClauses` 下产出事实；`ReferenceOnlyClauses` 只产出 `reference`，不产出 `fact`。

### 4.2 提取提示词增加“三问”

对每一条摘录先问：

1. 这句话是在**规定要求**，还是在**记录结果**？
2. 这句话是**直接讲本条款**，还是**只是提到条款号/文件名**？
3. 这份文档的**主题**是否真的属于本条款？

三问不过，不产 `fact`，最多产 `reference` 或 `extra`。

### 4.3 `FactKind` 必填

```text
requirement | result | record | reference | extra | exclusion
```

- `requirement`：手册/程序中的“应”；
- `result`：因素清单、风险评价、管理评审结论；
- `record`：检验报告、保养记录、生产日报；
- `reference`：记录清单、文件清单、条款引用；
- `extra`：培训课程名、财务/考勤/销售制度；
- `exclusion`：不适用说明。

### 4.4 聚合层过滤规则

1. `DocType=index` 的文档不进入 `AuditFindings` 主表；
2. `ReferenceOnlyClauses` 只作为引用，不作为事实；
3. 同名副本按 `FileName` 去 `(1)` 后去重；
4. 同一条 `Snippet` 在多份文档重复时只保留优先级最高的一份；
5. 优先级：手册 > 程序 > 作业指导书 > 记录 > 内审/管理评审 > 清单/封面。

### 4.5 先抽检再重跑

不建议立刻重跑 99 份。先做：

1. 用 4.1、8.5.1 两份抽检集验证 `DocType + FactKind + 三问`；
2. 通过后再对 8.5 组重跑；
3. 最后再全量重跑。

---

## 五、结论

1. **聚合层问题已解决**：8.5 能汇总 8.5.1–8.5.6，4.1 能汇总 4.1.4/4.1.5。
2. **当前主要问题在提取层**：4.1 有 3 份弱/误标，8.5.1 有 5 份明显误标。
3. **根因不是模型能力，而是提示词没要求“文档适用性 + 事实类型 + 三问”。**
4. **修正顺序**：先 `DocType + FactKind + 三问` 抽检 4.1/8.5.1，再重跑 8.5，最后全量。
5. **证据列仍按符合项写**：误标文档不进入证据正文，只作为疑点/引用线索。
