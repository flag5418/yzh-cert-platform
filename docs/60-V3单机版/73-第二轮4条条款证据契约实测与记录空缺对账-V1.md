# 73-第二轮 4 条条款证据契约实测与记录空缺对账-V1

> 目的：换 4 条“报告里有具体批次/供应商/不合格处置/校准编号”的条款，验证 `EvidenceContract` 能不能落到实际记录，而不是只对报告结论。
> 运行方式：Qwen-plus，temperature 0.2，提示词 = `cert_prompt_template.Id=1`（V2.0）+ 属性池 10 条。
> 本次只生成契约，未写库。案例：尚龙 13485；报告 `尚龙-ACM二阶段-结构化.md`；记录根 `4记录文件`。
>
> **2026-11-14 用户裁决后的修正**：
> 1. 空白模板可能只是格式，真实数据可能在 ERP/其他系统。文档侧只写“模板存在、抽样为空”，**不判缺失、不补数据、不编造**，剩余交审核员。
> 2. NC 不从文档反推；NC 怎么开是审核员设计的，**不作为核心目标**，报告 NC 只作验证样本。
> 3. 核心是“读懂条款、抓准证据、按文档分类整理成证据包”，**不是找到文档把原文丢给审核员**。
>
> 因此本文件第 4 节 `report_only`、第 6 节 A1/B1 只保留为“对账观察”，**不再作为生产建议**。新的输出模型见 `74-条款证据契约的文档事实边界与证据包输出-V1.md`；三列对照表见 `75-4条条款证据契约与真实证据对照表-V1.md`。

## 5. 这一轮暴露的 5 个问题

### F1 契约只写“应该有”，没有接“有没有”

4 条契约都默认记录“已填”。但文件夹实际是空白模板。`JudgementRules` 写“仅模板未填写 = 缺失”是对的，可报告又说符合；真正需要的是：

- `Required`：条款要求有没有这条证据；
- `InstanceStatus`：`filled / partial / blank / absent`；
- `Source`：`folder / report / both`；
- `Match`：`exact / partial / report_only / missing / not_applicable`。

没有这四个状态，契约和文档画像接不上。

### F2 契约的证据名和文件夹的记录名对不上

契约写“生产记录”，文件夹是 `PR-025/027/028`；契约写“不合格品处置记录”，文件夹是 `QR-020/021/022/024/025`；契约写“设备校准记录”，文件夹是 `QR-006/007/041/042`。需要 `Alias/Code` 映射，否则模型只能靠语义猜。

### F3 报告是独立证据源，不是“文件夹的总结”

`7.5.1/8.3.2/7.6` 的报告数据在文件夹里找不到对应填写记录。只跑文件夹会判“缺失”，这是假阴性。`report_only` 必须是一等匹配状态，不能并到 `missing`。

### F4 证据包仍然缺失

`7.4.1` 不是一份“采购记录”，而是“准则 + 名录 + 评定 + 绩效监视 + 再评价 + NC 处置”；`7.6` 是“台账 + 计划 + 校准记录 + 标识 + 软件确认”；`8.3.2` 是“通知 + 评审 + 处置 + 让步 + 验证”。契约仍是 `EvidenceName[]` 平铺，合成规则没有落。

### F5 `7.4.1` 的紧固件 NC 证明契约能抓真实缺口

报告 NC 说“未提供紧固件供应商识别和监视评价证据”；文件夹 `OR-008` 只有 5 类供应商，没有紧固件。契约 `Coverage=全供应商` + `EvidenceName=供方绩效监视记录/再评价报告` 正好能抓这个缺口。这是本轮唯一“契约与报告 NC 对上”的案例，说明契约不是只会误判，也能抓真问题。

## 6. 需要你决定的事（3 件）

### 决定 A：空白模板 + 报告有实际数据，条款结论怎么定

- **A1. 以报告为准，记 `report_only`，条款可判符合**（推荐）。理由：报告是审核证据，文件夹只是留档；不能因为留档空白就否定现场证据。
- **A2. 以文件夹为准，空白 = 缺失**。会把 `7.5.1/8.3.2/7.6` 全判缺失，和报告冲突。
- **A3. 双结论**：条款结论按报告，另出“记录留档完整性” warning。推荐在 A1 上加这个 warning。

### 决定 B：`7.4.1` 的紧固件 NC 算不算契约抓到的真缺口

- **B1. 算 C5 企业缺口**（推荐）：名录没有紧固件供应商，也没有绩效监视/再评价，报告 NC 成立。
- **B2. 算 C2 文档画像缺口**：文件夹没有采购记录，无法枚举紧固件，属于提取不到，不是企业没有。
- **B3. 算 C1 契约过宽**：契约要求“全供应商”，但企业只对关键件做供方评定。不推荐，报告已经开 NC。

### 决定 C：`EvidenceContract` 是否增加 `InstanceStatus/Source/Match`

- **C1. 增加三个字段**（推荐）：每个 `EvidenceItem` 带 `Required / InstanceStatus / Source`，匹配层产出 `Match`。这是把“条款期望”和“文档事实”接起来的最小改动。
- **C2. 不加，靠匹配层临时算**：契约保持纯期望，文档画像出事实，匹配器算状态。实现简单，但契约卡看不到“有没有”。
- **C3. 只加 `Source`**：只区分 folder/report，不记 filled/blank。会丢掉“空白模板”这个关键状态。

## 7. 结论

这一轮证明：**问题不只是契约过宽，而是契约与文档画像没有握手。**

- 契约说“应该有生产记录/不合格处置/校准记录”；
- 文档画像说“有空白模板”；
- 报告说“有实际批次/不合格/校准编号”；
- 三者没有 `Required / InstanceStatus / Source / Match` 这四个状态，所以只能靠人读报告补齐。

下一步建议：先做 **A1 + B1 + C1**，把 4 条契约卡改成 `EvidenceBundle`，每个成员带 `Required / InstanceStatus / Source`，再重跑。这样才能验证“条款约束 → 证据期望 → 记录事实 → 报告结论”的闭环，而不是继续在 `EvidenceName[]` 上打补丁。
