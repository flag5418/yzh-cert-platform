## 一、这次新增的判断

双尼案例验证了 67 号的核心结论，同时补了五个新判断：

1. **记录的第一索引不是条款，而是“审核区域/部门”**。报告按 `GM/MR`、`行政人事财务`、`资源提供与基础设施管理（购销部）`、`销售部（销售过程/产品验证）`、`购销部（采购过程）` 五个区域组织证据；记录却按 `1组织环境、2目标、3风险、5人力、9文件、10记录、11顾客、13采购、14监视测量、19法规、20环境因素、23应急、24危险源、25职业健康` 这些“程序章节”散放。
2. **“目录章节”和“标准条款”必须分开**。`13采购控制程序` 不是标准 8.4，`11与顾客有关` 同时服务 8.2 和 9.1.2，`19法律法规` 同时服务 E6.1.3 和 E/S9.1.2。目录号是文件分类，标准条款是审核依据，不能混成一个字段。
3. **QES 三体系必须带标准前缀**。同一份培训记录同时是 `Q7.2/E7.2/S7.2`，只写 `7.2` 无法区分 Q/E/S；报告本身用 `Q8.2`、`E6.1.2`、`H8.1.4` 写法。
4. **部门要拆“责任部门 / 保存部门 / 参与部门”**。记录一览表把客户满意度、合同评审、供应商记录标为“财务部保存”，但实际执行是“购销部/销售部”；报告审核区域又写“行政人事财务”“销售部”“购销部”。只给一个 `OwnerDept` 会把“谁保存”误当“谁执行”。
5. **空白/预填模板不是证据，时间覆盖缺口才是证据**。`14-1采购检验报告` 有“OK”结果但供应商、材料、日期全空；`14-2客户验收报告` 有“合格”但客户、合同全空。反过来，`02-01质量目标达成统计表` 1–6 月有数、7–8 月空白，报告据此开 9.1.1 不符合。记录提取必须同时输出“填写状态”和“缺哪些期间”，不能只数行。

### 3.2 记录部门 vs 报告区域：不是一对一

| 记录里的写法 | 报告里的写法 | 处理建议 |
|---|---|---|
| 总经理/管理者代表 | 管理层/GM-MR | 直接映射 |
| 综合部 | 行政部/行政人事财务 | 别名映射；记录里几乎不写“行政部” |
| 财务部 | 行政人事财务（支持）/采购评审 | 报告没有独立财务区域；财务部多作为合同/供应商评审参与方 |
| 购销部 | 销售部 或 购销部（采购） | **不能只靠部门名**；必须结合目录章节/过程区域区分销售与采购 |
| 销售部 | 销售部/销售过程 | 直接映射 |
| 全公司 | 多个区域 | 作为 `RelatedDepts`，不是单一 `OwnerDept` |
| 供应商/客户 | 外部相关方 | 是对象，不是内部部门 |

**这是当前 `OwnerDept` 单字段最大的问题**：同一份记录里“购销部”既可能是销售，也可能是采购；同一份客户满意度记录“财务部保存、购销部执行、销售部使用”。必须拆成：

- `OwnerDept`：谁执行/谁对记录内容负责；
- `KeeperDept`：谁保存（记录一览表/封面/表尾）；
- `RelatedDepts`：谁参与评审、会签、使用；
- `ProcessArea`：审核计划/报告里的区域，不由记录内容猜。

## 六、跨案例对照：科斯亚 vs 双尼

| 维度 | 科斯亚（ISO9001） | 双尼（QES 三体系） | 结论 |
|---|---|---|---|
| 企业类型 | 生产型（制钉） | 销售型（油烟净化设备销售） | 记录类型随业务模式变，不能固定一套字段 |

## 七、对 67 的修正：记录模型升级为“4 轴 + 证据单元 + 完整性”

### 7.1 四轴索引

一条记录在进入报告前，必须先归到四个轴：

| 轴 | 字段 | 来源 | 作用 |
|---|---|---|---|
| 1 目录章节 | `CatalogGroup` | 目录/程序编号，如 `13采购控制程序` | 记录属于哪本程序/哪类业务 |
| 2 标准大章 | `StandardScopes` + `ClauseRefs` | 标准条款，如 `Q8.4/E8.1/S8.1.4` | 记录服务哪些标准、哪些条款 |
| 3 审核区域 | `ProcessArea` | 审核计划/报告区域，如 `销售部/采购过程` | 报告按部门写时，记录归哪个区域 |
| 4 部门角色 | `OwnerDept`、`KeeperDept`、`RelatedDepts` | 表单内容/记录一览/会签 | 谁执行、谁保存、谁参与 |

当前 `OwnerDept + PrimaryClauses` 只覆盖了第 4 轴的一半和第 2 轴的一个字符串，不够。

### 7.3 新增字段与理由

| 字段 | 理由 | 双尼证据 |
|---|---|---|
| `CatalogGroup` | 目录是程序章节，不是标准条款 | `13采购控制程序` ≠ 8.4；`11与顾客有关` 同时 8.2/9.1.2 |
| `ProcessArea` | 报告按区域写，记录按部门写 | 报告 5 个 Process Area |
| `StandardScopes` / `ClauseRefs` | QES 三体系条款号重复 | 培训 = Q/E/S7.2；合规 = E/S6.1.3/9.1.2 |
| `KeeperDept` | 保存部门≠执行部门 | 客户满意度/合同/供应商记录一览标“财务部保存”，执行是购销部 |
| `RelatedDepts` | 会签/参与部门要保留 | 合同评审有财务部、综合部、购销部 |
| `TimeCoverage` | 报告用“7/8 月空白”开不符合 | 目标统计、管理方案统计 |
| `RecordState` 扩展 | 预填模板不是证据 | `14-1/14-2` 有 OK/合格但对象空 |
| `Warnings` 扩展 | 记录与报告版本不一致是常态 | 满意度 2 vs 3；供应商 5 vs 3；管评 5/12 vs 5/13 |

### 7.4 不要新增

- 不要新增 `ReportRole/ReportDepth` 到每条记录；它们是文档路由属性。
- 不要新增 `AuditConclusion`；记录只给事实，审核结论由报告/检查项生成。
- 不要让模型输出 `ReportPresence`；必须由报告索引代码计算。
- 不要给所有记录硬塞 `Production*` 字段；双尼没有生产。
- 不要把 `OwnerDept` 当唯一部门字段；保存/参与要分开。

### 7.5 记录如何证明“正在执行”

审核员不是看“表长得对不对”，而是看“这件事有没有按计划重复发生、有没有对象和结果、有没有例外”。记录侧要能支撑五问：

| 五问 | 记录字段 | 双尼证据 |
|---|---|---|
| 有没有依据 | `LinkedDoc`/`CatalogGroup`/`Signoff` | 年度培训计划、程序文件、作业指导书 |
| 有没有对象 | `Rows/Samples` 的对象、部门、客户/供应商 | 合同评审客户、供应商、培训参加人、检查区域 |
| 有没有发生 | `Period`、`TimeCoverage.Present`、`Samples.Date` | 7 场培训、5 次环境检查、6 条劳保 |
| 有没有结果 | `Result/Conclusion`、`Signoff` | 考核合格、检查符合、评审同意、评分 90 |
| 有没有例外 | `Warnings`、`RecordState`、`Missing` | 7/8 月空白、预填模板、12/06 劳保不在文件 |

**注意**：这五问只输出“事实和缺口”，不输出“符合/不符合”。是否符合由报告/检查项结合条款判断。比如 `02-01` 只能输出“1–6 月有数、7–8 月空白”，不能自己写“目标监视不符合”。

## 八、记录提示词 V2.3 规则

### 8.1 先分类，后抽行

1. 先读目录/文件名，填 `CatalogGroup`；
2. 再读表头/表尾，填 `OwnerDept/KeeperDept/RelatedDepts`；
3. 再按标准大章填 `StandardScopes/ClauseRefs`；
4. 再判断 `RecordType/TableShape/RecordState`；
5. 最后才抽 `Rows/Samples/Narrative`。

**禁止**先抽行再猜类型；否则宽表会被当行表、叙述报告会被当表格、预填模板会被当证据。

### 8.2 填写状态五态

| `RecordState` | 含义 | 处理 |
|---|---|---|
| `blank` | 只有表头，无数据 | `Rows=[]`，`Warnings=[blank_form]` |
| `prefilled_template` | 有默认 OK/合格/√，但对象/日期为空 | 不能当证据，`Warnings=[template_prefilled]` |
| `partial` | 部分行/部分期间有数据 | 保留已有，`TimeCoverage.Missing` 写缺口 |
| `filled` | 对象/日期/结果/签署齐全 | 正常抽 `Samples` |
| `narrative` | 段落报告 | `Narrative`，`Rows=[]` |

### 8.3 时间覆盖

- `Period`：记录声称覆盖的期间；
- `TimeCoverage.Present`：实际有数据的月份/日期；
- `TimeCoverage.Missing`：表头有但数据空的月份/日期；
- 宽表必须按列检查，不能只看行；
- 报告用空白期间开不符合时，`Warnings=[coverage_gap]`。

### 8.4 部门三角

- `OwnerDept`：编制/执行/记录内容负责；
- `KeeperDept`：记录一览/封面/表尾标注的保存部门；
- `RelatedDepts`：评审/会签/使用部门；
- 不要求模型把 `OwnerDept` 强行改成报告区域名；`ProcessArea` 由审核计划/后端映射。

### 8.5 条款引用

- `PrimaryClauses` 保留兼容，但新增 `ClauseRefs`；
- QES 必须写 `Standard` + `Clause`，不能只写 `7.2`；
- 同一记录可有多条 `ClauseRefs`，不强制一个主条款。

### 8.6 抽样

- `Samples` 1–5 条，报告候选样本；
- `Rows` 保留全量/前 30 行；
- 清单类 `Samples` 取 3–5 个典型条目；
- 培训/检查表按“场次/次数”拆 `Records`，不压成一条；
- `SampleCount` 不等于报告抽样数；报告可能抽 3 条，文件有 7 条。

### 8.7 叙述报告

- `RecordType=narrative_report`：`Rows=[]`；
- `Narrative.Summary` ≤80 字；
- `Narrative.Metrics` 只放原文数字；
- `Narrative.Conclusion` 只抄原文结论；
- `Signoff` 保留编制/审核/批准/日期。

## 九、报告消费链改造

### 9.1 按部门/区域过滤

`BuildModeExcerpt` 现在只读 `Records` 前 3 条，不按部门过滤。报告按 5 个区域写，必须改成：

```
BuildModeExcerpt(record, processArea)
  -> 只取 ProcessArea 匹配，或 OwnerDept/RelatedDepts 命中区域别名的记录
  -> 输出 Samples/Narrative/Rows，而不是 raw Records JSON
```

### 9.2 记录摘录格式

按记录类型输出不同句式：

- 清单：`《X》编号…，共 N 条，覆盖…；典型条目：1）…2）…`
- 事件表单：`抽见《X》N 份：1）日期…对象…项目…结果…结论…人员…`
- 检查表：`《X》检查表，受审核部门…审核时间…审核员…检查项…判定…`
- 叙述：`《X报告》，期间…样本…指标…结论…`
- 预填模板：`《X》为预填模板，对象/日期为空，不作为证据`
- 覆盖缺口：`《X》1–6 月有数据，7–8 月空白`

### 9.3 覆盖缺口直接进报告

`TimeCoverage.Missing` 应作为报告上下文的一部分，而不是只放在 JSON 里。报告 9.1.1 的“7、8 月无统计数据”就是由这个字段驱动。

### 9.4 `ReportPresence` 仍由代码算

双尼报告和记录版本不一致，更不能让模型猜“报告有没有引用”。继续用报告索引：

```
ReportClause + RecordName + RecordCode + Usage + SampleCount + LineNo
```

### 9.5 部门别名表

后端需要一张企业级部门别名表：

```
综合部 -> 行政部/行政人事财务
财务部 -> 行政人事财务（支持）
购销部 -> 销售部 / 购销部（采购），需 ProcessArea 区分
总经理/管理者代表 -> 管理层/GM-MR
全公司 -> 多区域
```

这张表不能写死在提示词里；从企业组织架构/审核计划取。

## 十、验证方案

### 10.1 用双尼 5 个样本重跑

| 记录 | 验证点 | 报告 Oracle |
|---|---|---|
| `02-01质量目标达成统计表.xls` | 1–6 月有数、7–8 月空白；能否输出 `TimeCoverage.Missing` | 9.1.1 不符合“7、8 月无统计数据” |
| `11-3/11-4客户满意度` | 能否拆 2 家、平均 91、报告 3 家/98 的差异 | 9.1.2 报告 3 家/98；记录 2 家/91 |
| `13-4/13-5供应商` | 能否输出 5 家，并标记报告 3 家不一致 | 8.4 报告 3 家（双尼科技/惠普/得力） |
| `14-1/14-2检验/验收` | 能否判 `prefilled_template`，不把 OK/合格当证据 | 8.6 报告未引用这两份 |
| `5.内审管评/管理评审` | 能否拆计划/输入/会议/报告/改进/输出；日期 5/12 vs 报告 5/13 | 9.3.1 报告 5/13 |

### 10.2 验收指标

| 指标 | 目标 |
|---|---|
| `DeptRecall`：报告区域对应的记录是否找到 | ≥ 90% |
| `CoverageGapRecall`：7/8 月空白是否识别 | 100% |
| `TemplateFalseEvidence`：预填模板被当证据 | 0 |
| `SampleRecall`：报告抽样对象是否在候选样本 | ≥ 90% |
| `StandardClauseAccuracy`：Q/E/S 前缀是否正确 | ≥ 90% |
| `VersionMismatchFlag`：记录/报告差异是否标记 | 100% |

### 10.3 不要用“文件完整”当验收

- 双尼 `4 记录表单` 不是报告全部证据；
- 报告用的供应商、合同、满意度、体检、电梯、消防卡，部分不在目录；
- 验收要看“报告句能否被记录字段支撑”，不是“文件里有没有这张表”。

## 十一、结论

1. **67 号的“证据单元”结论成立**：报告不是整表搬运，是抽样 + 字段 + 结论。
2. **双尼补上了“部门/区域”这一层**：报告按 5 个 Process Area 审，记录按程序章节散放；部门别名和“执行/保存/参与”必须拆开。
3. **QES 三体系必须带标准前缀**：`7.2` 不是唯一条款，`Q7.2/E7.2/S7.2` 才是完整引用。
4. **“大章节分类”要分两层**：目录程序章节（`CatalogGroup`）+ 标准大章（`StandardScopes/ClauseRefs`），不能混。
5. **空白/预填模板不是证据，时间覆盖缺口才是证据**：`RecordState + TimeCoverage + Warnings` 是记录类的新三件套。
6. **记录集不等于报告证据全集**：科斯亚和双尼都出现了“报告有、目录无/版本不同”；`ReportPresence` 必须由代码算，`content_mismatch` 必须保留。

本轮只做跨案例分析和规则修正，未改提示词、未改代码。下一步建议先拿双尼 5 个样本验证 V2.3 字段，再决定是否改 `record_profile` 和 `BuildModeExcerpt`。
