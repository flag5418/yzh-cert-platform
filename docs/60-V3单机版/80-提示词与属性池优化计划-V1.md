# 80-提示词与属性池优化计划-V1

> 目标：把“条款证据契约 → 文档轻量事实 → 审核证据”打通。
> 原则：先冻结数据形状，再改提示词；先影子验证，再写库；不一次性重写 12 份文档提示词。

---

## 0. 现在能不能做

| 改动项 | 现在能否做 | 前提 | 建议 |
|---|---|---|---|
| 文档提示词修改 | **可以做草稿和影子测试**，不建议直接覆盖生产行 | 先定 `DocFact` 轻模型 | 先改 `doc_extract_record_profile`（Id10）一份 |

## 1. 现状缺口（已核实）

### 1.1 条款契约生成了，但审核检查没消费

`CertCheckContextBuilder.RenderClauseInfo()` 当前只渲染 9 个属性：

```text
ClauseIntent / Obligation / Applicability / ApplicabilityCondition /
Process / Severity / EvidenceForm / EvidenceFamily / Role
```

**没有 `EvidenceContract`。** 所以 `audit_check` 只能看到“条款意图/过程/证据形态”，看不到“期望证据项、必备字段、频次、覆盖、交叉检查”。

### 1.2 文档命中是原文摘录，不是结构化事实

`RenderDocHits()` 当前输出的是：

```text
《文件名》
  位置：...
  摘录：原文片段
```

没有 `DocRole / FillStatus / SampleRows / Coverage / NameAliases / Applicable`。模型只能从原文里自己判断“这份记录是空白还是已填”，容易把“模板存在”写成“已实施”。

### 1.3 条款提示词的边界话术与新契约冲突

`ClauseAttrPromptService` 正文里仍写着：

> ⛔ 不产出「企业应提供哪些资料」、⛔ 不产出「审核员怎么取证」

但 `EvidenceContract` 实际上就是在定义“期望证据”。这句话会让模型不敢写契约，必须改成：

> `EvidenceContract` 只定义“这条款期望什么证据”，不写企业有没有、不写符合性。

### 1.4 审核检查的输出契约有两套

`wf_prompt_template.audit_check` 模板末尾要求：

```text
conclusion / summary / audit_evidence / clause_evidence /
recommendation / confidence / nc_suggestion / severity_suggestion /
evidence_codes / doubts / nc_draft
```

`CertCheckContextBuilder.RenderOutputContract()` 的 onsite 分支只要求：

```text
conclusion / summary / recommendation / confidence /
nc_suggestion / severity_suggestion
```

**两套契约不一致**，模型会按其中一套输出，解析另一套时丢字段。必须先统一。

## 2. 目标结构

```text
ChapterProfile（章节默认）
   ↓
ClauseProfile（条款覆盖）
   ↓
EvidenceContract（期望证据项 + 依赖 + 交叉检查）
   ↓
DocFact（文档轻量事实）
   ↓
AuditEvidence（审核证据：证据项 → 事实 → 缺口）
```

### 2.1 条款侧：只保留 10 个属性，升级 `EvidenceContract`

**不新增顶层属性。** 现有 10 条属性已经够用，问题在 `EvidenceContract` 内部太浅。

建议新 schema：

```json
{
  "ContractVersion": "v3",
  "EvidenceItems": [
    {
      "ItemId": "E1",
      "DocRole": "procedure | work_instruction | record | manual | policy",
      "EvidenceRole": "establishment | implementation | criteria | support",
      "Name": "内部审核程序",
      "NameAliases": ["内部审核控制程序"],
      "Required": true,
      "Condition": "",
      "ExpectedFields": ["审核范围", "审核准则", "审核员", "频次"],
      "Frequency": "每年至少一次",
      "Coverage": "全部门",
      "ReportUse": ["coverage", "counter"]
    }
  ],
  "Dependencies": [
    {"Clause": "4.2.5", "Role": "evidence_rule", "Use": "记录控制要求"},
    {"Clause": "7.5.9", "Role": "support", "Use": "追溯"}
  ],
  "CrossChecks": [
    {
      "CheckId": "C1",
      "Question": "计划中的审核员与检查表中的审核员是否一致",
      "Docs": ["内审计划", "内审检查表", "内审报告"],
      "MismatchUse": "doubts"
    }
  ],
  "AuditorRules": [
    "模板存在但抽样为空 = template_only，不判未执行",
    "报告里的批次数据只能作 report_only，不回填文档事实"
  ]
}
```

**关键变化：**
- `EvidenceType/EvidenceName` 扁平数组 → `EvidenceItems[]` 嵌套；
- `MustHaveFields` → 每个 `EvidenceItem.ExpectedFields`；
- 新增 `Dependencies[]`（条款间引用）；
- 新增 `CrossChecks[]`（多文档一致性检查）；
- `JudgementRules` → `AuditorRules`，明确“给审核员用，不给提取用”；
- 新增 `NameAliases`（报告名 vs 文件名不一致时用）。

**属性池只改一行：**
- `cert_clause_attr_def.Code='EvidenceContract'` 的 `PromptHint` / `Remark` 改成上面的 schema；
- 不新增 `EvidenceDependencies` / `CrossChecks` / `DocRole` 等顶层属性。

### 2.2 文档侧：轻模型 6 问

**记录类（record）只问 6 个问题：**

```json
{
  "DocClass": "record",
  "CoreRole": "生产过程自检记录",
  "KeyFields": ["产品名称", "型号", "批号", "数量", "检验项目", "检验结果"],
  "FillStatus": "filled | partial | blank | template_only | unreadable",
  "SampleRows": [{"RowRef": "第2行", "Values": {"批号": "20260623"}}],
  "Coverage": "全量 | 抽样 | 无实例"
}
```

**程序类（procedure）只问 6 个问题：**

```json
{
  "DocClass": "procedure",
  "CoreRole": "规定生产和服务提供的控制要求",
  "Scope": "适用于手动轮椅车生产过程",
  "KeyControls": ["生产计划", "作业指导", "过程确认", "标识", "放行"],
  "RelatedForms": ["PR-025", "PR-026", "PR-028"],
  "RelatedDocs": ["QP-020"]
}
```

**指导类（work_instruction）只问 6 个问题：**

```json
{
  "DocClass": "work_instruction",
  "CoreRole": "规定成品检验的检验项目和接收准则",
  "Applicable": "手动轮椅车成品",
  "InspectionItems": ["外观", "尺寸", "装配", "制动"],
  "AcceptanceCriteria": ["符合产品技术要求"],
  "RelatedRecords": ["QR-027"]
}
```

**手册/方针（manual/policy）只问 4 个问题：**

```json
{
  "DocClass": "manual",
  "CoreRole": "质量手册，覆盖体系范围和删减",
  "ClauseAnchors": ["4.1", "4.2", "5.1"],
  "KeyCommitments": ["建立并保持质量管理体系"],
  "RelatedProcedures": ["QP-001", "QP-002"]
}
```

**不要再按“记录/程序/制度/内审/文件控制/作业指导/组织环境/方针”写 12 套字段。**
按 `DocRole + ExtractionDepth` 复用，4 套足够。

### 2.3 审核证据侧：按契约找证据，不按原文写作文

`audit_check` 的输入改成三块：

```text
## 条款与证据契约
条款正文 + ChapterProfile + ClauseProfile + EvidenceContract

## 企业文档事实
按 EvidenceItem 聚合的 DocFact：
- 文档名 / 编号 / DocRole / FillStatus / SampleRows / Coverage
- NameAliases 匹配结果
- RelatedForms

## 现场证据
访谈 / 照片 / 抽样 / ERP 截图
```

`audit_check` 的工作顺序改成：

1. 先按 `EvidenceItems` 逐项找 `DocFact`；
2. 每项输出 `evidence_used`：`item_id / doc_code / match / fact`；
3. 空白模板输出 `coverage_gap: template_only`，不写“缺失/未执行”；
4. 报告/ERP 数据输出 `report_only`，不进文档事实；
5. 最后才写 `audit_evidence` 和 `conclusion`；
6. `CrossChecks` 不一致只进 `doubts`，不直接判 NC。

建议新增输出字段：

```json
{
  "evidence_used": [
    {
      "item_id": "E1",
      "doc_code": "QR-015",
      "doc_name": "内部审核计划",
      "match": "exact | alias | partial | missing",
      "fact": "2026.05.15–16，组长尚月永，组员王倩，五部门"
    }
  ],
  "coverage_gap": [
    {
      "item_id": "E3",
      "gap": "template_only | blank | partial | not_found",
      "note": "成品检验记录模板存在，抽样为空"
    }
  ],
  "report_only": [
    {
      "item_id": "E3",
      "source": "report",
      "note": "报告有 2026-06-23 批次 100 台，文件夹无对应记录"
    }
  ]
}
```

## 3. 分阶段计划

### P0 · 冻结形状（0.5 天）

**做什么**
- 冻结 `EvidenceContract v3` schema；
- 冻结 `DocFact` 4 套轻模型；
- 冻结 `AuditEvidence` 输出字段；
- 用 5 条条款手工写 5 张“oracle 契约卡”，作为后续 A/B 基准。

**产出**
- `81-EvidenceContract-v3与DocFact轻模型-冻结稿.md`
- `81-5条条款Oracle契约卡.json`

**验收**
- 5 条条款每条至少 3 个 `EvidenceItem`；
- 每个 `EvidenceItem` 有 `DocRole / EvidenceRole / Required / ExpectedFields`；
- `8.2.4` 有 `CrossChecks`；`7.5.1` 有 `Dependencies`（7.5.9）；`4.2.5` 作为 `evidence_rule` 出现在 `8.2.4/8.2.6` 的依赖里。

### P1 · 文档提示词影子改造（1–2 天）

**做什么**
- 新增影子提示词 `doc_fact_record_v3`，不覆盖 Id10；
- 先跑 5 条条款涉及的记录：`PR-025/027/028`、`QR-015~019`、`QR-037/027/028/038`、`QR-020/021/022/024/025`、`QR-006/007`；
- 输出 `DocFact`，与人工事实表对比 `FillStatus` / `SampleRows` / `Coverage`；
- 通过后再改 `doc_extract_process_profile`（Id9）、`doc_extract_work_instruction_citation`（Id14）、`doc_extract_policy_profile`（Id16）。

**不做什么**
- 不一次性改 12 份；
- 不把旧提示词删除；
- 不把报告数据写进 DocFact。

**验收**
- `FillStatus` 准确率 ≥ 90%（以 79 号文档事实为基准）；
- `8.2.6` 的 `QR-038` 必须标 `partial` + 产品对象不一致；
- `7.6` 的 `QR-006` 必须标 `partial`，不能标 `filled`；
- 所有空白模板标 `template_only`，不标 `missing`。

### P2 · 条款属性池与契约提示词改造（1 天）

**做什么**
- 改 `cert_clause_attr_def.Code='EvidenceContract'` 的 `PromptHint/Remark` 为 v3 schema；
- 改 `clause_attr_gen`（Id1）的边界话术：
  - 删除“⛔ 不产出企业应提供哪些资料”；
  - 改成“`EvidenceContract` 只写期望证据，不写企业事实、不写符合性”；
- 用 5 条条款重新生成契约，与 P0 的 oracle 卡对比。

**不做什么**
- 不新增顶层属性；
- 不把 `JudgementRules` 继续当提取判定；
- 不写 `cert_clause_attr` 生产行，先存 `/tmp` 或影子表。

**验收**
- 5 条契约均输出 `ContractVersion=v3`；
- `EvidenceItems` 数量 ≥ 3；
- `8.2.4` 输出 `CrossChecks`（审核员名单一致性）；
- `8.2.6` 的 `Applicability` 保持 `general`，不因“植入性医疗器械”整条抬成 conditional；
- `7.5.1` 的 `Dependencies` 包含 `7.5.9`；
- `4.2.5` 在 `8.2.4/8.2.6` 的 `Dependencies` 中作为 `evidence_rule`。

### P3 · 审核证据链路改造（2–3 天）

**做什么**
- 改 `CertCheckContextBuilder.RenderClauseInfo()`：追加 `EvidenceContract`；
- 改 `RenderDocHits()`：优先输出 `DocFact`，原文摘录只作补充；
- 改 `RenderOutputContract()`：与 `audit_check` 模板统一，加入 `audit_evidence / clause_evidence / evidence_used / coverage_gap / report_only`；
- 改 `wf_prompt_template.audit_check` 正文：按 `EvidenceItems` 找证据，不按原文写作文；
- 保留旧路径开关，A/B 可回退。

**不做什么**
- 不让 `audit_check` 从空白模板推断“未执行”；
- 不把报告里的批次数据回填成 DocFact；
- 不把 `CrossChecks` 不一致直接判 NC。

**验收**
- 5 条条款都能输出 `evidence_used`；
- `8.2.4` 能组合 4 份内审文档，输出“本次内审结论”，而不是只读 1 份；
- `8.2.6` 能明确标出“报告有 5 批、文件夹记录为空”；
- `8.3.2` 能明确标出“报告有进货不合格、文件夹处置记录空白”；
- `7.6` 能明确标出“报告有 4 台校准、台账半填”；
- 审核证据每句话可指回 `DocFact / report_only / onsite`，无编造“已实施”。

### P4 · 写库与页面（1 天）

**做什么**
- 写 `cert_prompt_template` 新版本行（保留旧行）；
- 写 `cert_clause_attr_def` 的 `EvidenceContract` 提示；
- 生成 5 条条款属性到影子表，验收后再写 `cert_clause_attr`；
- 页面显示 `EvidenceItems / Dependencies / CrossChecks / FillStatus / report_only`。

**验收**
- 页面能逐条查看契约卡与文档事实；
- 旧提示词可回退；
- 5 条条款跑通后，再扩到 13485 其余条款。

## 4. 测试矩阵

| 条款 | 测什么 | 关键判据 |
|---|---|---|
| `7.5.1` | 空白批记录 + 报告批次 | `template_only` 不写成 `missing`；报告 3 批只进 `report_only` |
