## 二、本轮两条关键结构修正

### 2.1 `doc_extract_clause_full`：父条 + 分点必须挂路径

旧输出把 4.1.3 的 a/b 和 4.1.5 的 a–d 拍平成 `a–f`，父条 4.1.5 反而丢失；6.1 又把父条和 a–d 正文重复。修正后：

| 字段 | 规则 |
|---|---|
| `SubClause` | 必须写完整路径：`4.1.5`、`4.1.5-a`，禁止只写 `a` / `b` |
| `ParentSubClause` | 顶级子条写条款号（`4.1`）；分点写最近父条（`4.1.5`） |
| 父条目 | 带 a–d 的父条必须保留，即使只有引出句；父条 Text 不超过 80 字，禁止并入 a–d 正文 |
| 分点 | 每个 a–d 独立条目，不得拍平到 `a–f` |
| `ExtraFacts` | 非编号标题（QMS 范围、生产地址、不适用说明）放这里；不计入 Coverage |
| 标准外分点 | 如 5.1.1 的 `k)` 放 `ExtraFacts`，不计入 Coverage |
| Coverage | `Declared = SubClauses 条数 + Missing 条数`；`Covered = SubClauses 条数`；不得把父条与分点重复计数 |

### 2.2 `doc_extract_audit`：删除系统结论，只留原文事实

旧输出在 `Findings` 里写 `Conclusion: OK / 一般不符合 / 需改进项`，这会把“审核发现”污染成“审核结论”。修正后：

| 字段 | 规则 |
|---|---|
| `Findings[]` | 只有 `ClauseNumber`、`Finding`（原文事实）、`Evidence`、`RecordMark`（原文判定栏） |
| `RecordMark` | 只抄原文判定栏（OK/NG/空白）；没有就空字符串；**不是系统结论** |
| `RecordConclusions` | 只抄原文结论，逐字或近逐字；不做二次判断 |
| 禁止输出 | `Conclusion`、符合、不符合、充分、缺失、需改进项、一般不符合、建议 |
| `ClausesCovered` | 纯编号，不带 `Q：` / `Q:` / `E：` / `m：` 前缀 |

**下游铁律**：`RecordConclusions` 只是“记录里的原文结论”，不是审核证据；证据生成只读 `Findings`，不得把 `RecordConclusions` 当符合项。

## 四、残留问题与下一步

### 4.1 必须补代码侧 `DocExtractGuard`

提示词已经能守住样本，但以下三类仍会随文档漂移，不能只靠提示词：

| 风险 | 代码侧处理 |
|---|---|
| 分点路径漏 `ParentSubClause` | 数字子条默认父条=条款号；`x.y.z-a` 默认父条=`x.y.z`；校验失败则丢弃或标记 |
| Coverage 计数不一致 | 解析层重算 `Covered=len(SubClauses)`、`Declared=len(SubClauses)+len(Missing)`，不信任模型数字 |
| 父条 Text 带 `- a` / `a）` | 按 `a)/a）/b)/b）…` 截断到第一个标记前；截断后为空则只留标题句 |
| 非编号标题混入 `SubClauses` | `SubClause` 不匹配 `^\d+(\.\d+)*([a-z])?$` 时移到 `ExtraFacts` |
| 审核提取出现 `Conclusion` | 解析层直接拒绝该字段；只接受 `ClauseNumber/Finding/Evidence/RecordMark` |

### 4.2 运行时接入顺序（不在本轮做）

```text
1. DocExtractPromptService 支持按 ExtractionMode 选 5 条新提示词
2. ClauseExtractExecutor 按 DocProfile.ExtractionMode 路由
3. ContentJson 增加 SubClauses / ParentSubClause / ExtraFacts / Processes / FormFields / IndexEntries / AuditProfile
4. 手册按 DocSectionIndex.ReadRange 送完整小节，不再整篇 15k 切
5. 先跑 99 份提取并人工抽检，再跑发现/疑点预分析
6. 最后才改证据提示词
```

### 4.3 本轮未做的事

- 未改 `DocExtractPromptService`、`ClauseExtractExecutor`、`DocumentExtractionService`。
- 未把新输出写回 `cert_document_extraction.ContentJson`。
- 未跑 99 份全量；只跑 12 个调用。
- 未改最终证据提示词；`audit_check` / `doc_clause_extract` 保持原样。
- 未点企业资料页“重新分析”；当前按钮仍会重跑旧提示词。

## 五、验收口径

这一轮可以认为“提示词方向基本稳定”，但还不能认为“运行时已改造完成”。判断标准：

- 4.1 / 4.3 / 5.1 / 6.1 的 `SubClause` 全部带父条路径，Coverage 与实际条数一致。
- 5.1.1-k、4.3 的 QMS/地址/不适用说明进入 `ExtraFacts`，不污染标准覆盖率。
- 内审/评审不再输出 `Conclusion`；`RecordConclusions` 只作原文记录。
- 程序/记录/索引三类输出字段名固定：`OutputRecords`、`FormFields`、`IndexEntries`。
- 上述四条在 99 份抽样中不出现批量漂移，才进入运行时接入。
