# 4.1 审核证据提示词对照测试记录 V1

> **后续方案**：本文验证“发现+疑点+证据”三合一的极限；更稳的主线是 [39 号文](./39-审核证据三段式-发现·疑点·证据-V1.md) 的三段式：先只跑发现，再跑疑点，最后跑证据。4.1 的“只跑发现和疑点”实测见 39 号文。

> 目的：不改程序，先用同一份企业质量手册 4.1 原文，手工验证“标准约束 + 章级属性 + 条款属性 + 文档事实”能否产出可进入审核报告的审核证据。
> 测试对象：`01管理手册QMS.doc` 的 Markdown 版（`/tmp/manual.md`，66,578 字符），4.1 段共 516 字符，含 4.1.1–4.1.5 + a–d。
> 模型：qwen-plus，temperature 0.2，max_tokens 3000，强制 JSON。

---

## 一、测试结果总表

| 版本 | 输入 | 事实数 | 结论 | 主要问题 |
|---|---|---:|---|---|
| V0 旧方式 | 只给 4.1.1–4.1.3 三条摘录 | 3 | `nc` | 把“没记录”判成不符合；证据是条款转述 |
| V1 全量+章属性 | 完整 4.1 + 章/条款属性，先归集后写作 | 11 | `ofi` | 事实齐了，但证据正文混入“未获取/无记录”负向语句 |

## 二、四个版本的关键输出

### 2.1 V0：旧方式为什么不行

输入只有：

- 4.1.1 各级负责人应理解顾客和国家法规，确定内外部因素；
- 4.1.2 外部因素包括法律法规、技术、竞争、市场、文化、社会、气候变化、经济；
- 4.1.3 内部因素包括价值观、文化、知识、绩效和成功因素。

模型输出：

> 查阅《质量手册》第 4.1 条款，其中明确列出 4.1.1…4.1.2…4.1.3…  
> 未见手册或其他受控文件中对上述内外部因素的具体识别结果、监视方法或评审频次作出规定；亦未提供任何监视记录或评审记录…  
> `conclusion: nc`

问题不是模型不会写，是**输入只有三条，模型只能把条款转述一遍，然后把缺口判成 nc**。

### 2.2 V1：事实齐了，证据开始按主题组织

V1 把完整 4.1 给模型，并要求先抽事实、再覆盖、再写证据。输出 11 个事实：

- 4.1.1 各级负责人确定内外部因素；
- 4.1.2 外部因素清单；
- 4.1.3 内部因素清单；
- a 分析市场/行业竞争对手/外部供方，认识行业地位；
- b 分析内部能力/技术/管理水平，明确战略目标；
- 4.1.4 管理者代表组织监视评审；
- 4.1.5 辨识正面/负面要素；
- 4.1.5-a 国家法规政策变化→发展目标；
- 4.1.5-b 相关方理念价值观→相关方关系；
- 4.1.5-c 员工要求→发展战略/承诺；
- 4.1.5-d 资源配置→服务和管理进步。

审核证据已经按“组织背景→外部因素→内部因素→气候变化→监视评审→决策使用”组织，不再逐条罗列 4.1.1/4.1.2。

但 V1 的证据正文仍出现：

> 无任何记录类证据被引用或提及，仅存在职责分配。  
> 均为原则性表述，未见具体决策实例或输出痕迹。

这违反“审核证据只写已获得事实，缺口放 doubts”的要求。

### 2.3 V2：标准约束优先，反而判成 pass

V2 只给标准 4.1 两个要求点 + 完整手册，要求区分标准要求和企业细节。输出：

- `4.1-P1` → `documented`；
- `4.1-P2` → `documented`（因为手册 4.1.4 写了职责）；
- `conclusion: pass`；
- 审核证据按 4.1.1/4.1.2/4.1.3/4.1.5/4.1.4 逐条罗列。

这说明：**只讲“标准约束优先”不够，必须同时有“文件化 ≠ 已实施”的硬门禁。** 否则模型会把“手册规定了”当成“已经做了”。

### 2.4 V3：硬门禁把结论拉回 ofi

V3 加入：

- 4.1-P1 = document；
- 4.1-P2 = implementation；
- 只有职责规定 → `documented_not_implemented`；
- 没有记录/会议/访谈 → 只能 `ofi`/`onsite_needed`，不能 pass；
- 未找到记录 ≠ nc。

输出：

- 4.1-P1 `documented`；
- 4.1-P2 `documented_not_implemented`；
- `conclusion: ofi`；
- 但仍然只抽了 10 个事实（4.1.5 被并进 a–d），证据正文仍有“未获取任何实际执行证据”。

### 2.5 V4：目前最接近可用的一版

V4 再收紧：

- 事实必须正好 11 个，4.1.5 父规则单独保留；
- 审核证据只写“已获得的正面事实”；
- “未提供/未获取/无记录”只能进 doubts；
- 审核证据不得出现 4.1.1/4.1.2 等手册条款号；
- 每句话必须能回指事实列表；
- 不得出现“服务导向、良好、完善、健全”等评价词。

输出：

- 11 个事实，全部 `documented`，只有 4.1.4 是 `documented_not_implemented`；
- `4.1-P1 documented`，`4.1-P2 documented_not_implemented`；
- `conclusion: ofi`；
- 审核证据按“组织背景→外部因素→内部因素→气候变化→监视评审→决策使用”六段；
- 正文不再出现“未获取/无记录”；
- doubts 单独一条：“未提供监视和评审记录、会议纪要或访谈证据，无法确认是否实际执行”。

## 三、V4 暴露出的真正边界

### 3.1 手册 4.1 只有“规定”，没有“实际识别结果”

V4 的“组织背景”仍然写成：

> 公司各级负责人应充分理解顾客和国家法规，确定影响公司战略目标和发展方向实现的各种内、外部因素和环境、安全状况。

这是**手册要求**，不是“公司已经识别了什么”的事实。手册 4.1 没有写：

- 公司实际识别的外部因素具体是哪些（政治、法律、经济、社会文化、技术、行业竞争、气候变化…）；
- 公司实际识别的内部因素具体是哪些（企业文化、价值观、知识技术积累、经营绩效、财务、综合资源、人力、生产运营资源…）；
- 监视评审的频次、参加人、输出、决策使用实例。

真实报告的“识别的外部因素有政治环境、法律、经济…”“经与潘明海沟通…”“定期进行内外部环境识别评价及目标指标统计”来自**访谈、记录、其他文件**，不是手册 4.1 本身。

### 3.2 所以 4.1 文档型证据的天花板是“已规定”，不是“已实施”

在只有手册 4.1 的条件下，最多只能写：

> 查见《质量手册》4.1 节规定：各级负责人应确定影响战略目标的内外部因素；手册列明外部因素包括法律法规、技术、竞争、市场、文化、社会、气候变化、经济；内部因素包括价值观、文化、知识、绩效和成功因素；手册规定管理者代表组织监视和评审；手册提出将因素用于目标、相关方、员工和资源配置。

不能写：

> 公司识别的外部因素有政治环境、法律、经济…  
> 公司进行了监视和评价，并将结果用于经营决策。

除非有管理评审记录、内外部因素分析表、会议纪要或访谈证据。

### 3.3 这不是提示词能补的，是证据供给问题

V4 已经证明：提示词可以把“条款转述”改成“按主题组织”，可以把“没记录=nc”改成“ofi”，可以把“手册写了=pass”改成“documented_not_implemented”。

但提示词不能把手册里没有的“实际识别结果/监视评审记录”变出来。要继续接近真实报告，必须补：

1. 手册 4.3 的范围/地址/产品（组织背景）；
2. 营业执照/企业基础信息（成立日期、信用代码、法人、面积）；
3. 内外部因素分析表/相关方清单（实际识别结果）；
4. 管理评审计划/输入/会议纪要（监视评审实施）；
5. 最高管理者/管理者代表访谈（决策使用）。

## 四、V4 的可复用提示词骨架

```text
## 唯一要求源：标准
{标准条款原文 + 版本}

## 章级属性
ChapterRole / ChapterPurpose / ChapterQuestion /
EvidenceDirections / WritingPattern / CrossChapterLinks

## 条款属性
RequirementPoints（每个点标 ImplementationType=document|implementation）
SourcePriority（手册 > 程序 > 记录 > 报告 > 访谈 > 观察）
OrganizationSlots（证据按什么主题组织）
CommonDistortions（禁止事项）
MaturityRule（文件生效/记录覆盖≥3个月）

## 唯一事实源：企业文档
{文档编号/版本/生效日期 + 原文段落，必须含子条款和分点}

## 硬门禁
1. 每个事实带 source_clause + fact_kind=requirement|result|record + status。
2. 文件型要求点：有规定即可 documented。
3. 实施型要求点：只有职责规定只能 documented_not_implemented；有记录/访谈才 implemented。
4. pass 条件：所有 implementation 点均 implemented；否则 ofi/onsite_needed。
5. 未找到记录 ≠ nc；只有明确事实证明未满足才 nc。
6. 审核证据只写正面已获得事实；缺口全部进 doubts。
7. 审核证据不得出现手册条款号；按主题组织；每句话可回指事实。

## 输出
facts[] / requirement_coverage[] / audit_evidence / conclusion / doubts[]
```

## 五、结论

1. **方向基本正确**：V4 已能做到 11 个事实全覆盖、按主题组织、`documented` 与 `implemented` 分开、结论 `ofi`，比当前系统的“3 条摘录 + 一句话 pass”明显更接近审核报告。
2. **4.1 文档型证据只能到“手册规定”层**：真实报告里的组织背景、实际识别结果、监视评审执行，必须从 4.3/营业执照/分析表/管理评审记录/访谈中补，不能靠提示词编。
3. **标准约束必须配硬门禁**：只说“以标准为准”会把 `documented` 当 `implemented`，判成 pass；必须显式执行 `ImplementationType + status + pass gate`。
4. **报告只学语言**：V4 的段落顺序可参考报告，但事实全部来自手册；标准换版时，只换 RequirementPoints/ChapterProfile，不依赖旧报告。
5. **下一步**：先用同一套 V4 提示词测 4.3（范围/地址）、5.1（方针/职责）、6.1（风险清单/程序）、8.5（作业记录），确认“文档事实型条款”和“实施记录型条款”的差异；再决定程序改造。

## 六、标准换版时的行为

| 变化 | 系统应做什么 |
|---|---|
| 新标准发布 | 重新解析标准 Markdown，生成新的 `RequirementPoints` 和 `ChapterProfile` |
| 条款号变化 | 按新标准条款号重建映射，不沿用旧报告条款号 |
| 新增要求 | 在属性池新增要求点，旧企业文档按新要求点重新覆盖 |
| 旧报告不可用 | 只保留 `style_pack`（分段/起句/动词），不保留事实/结论 |
| 企业资料不变 | 仍从企业文档抽事实；不因标准换版而编事实 |

**核心：标准是要求源，企业文档是事实源，报告只是语言源。** 这样新标准发布、审核员不给参考报告时，系统仍能靠标准约束生成证据框架。
