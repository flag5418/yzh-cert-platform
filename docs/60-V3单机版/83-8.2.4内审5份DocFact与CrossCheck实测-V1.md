# 83-8.2.4内审5份DocFact与CrossCheck实测-V1

> 日期：2026-11-15  
> 阶段：P1 第二次影子测试  
> 目的：验证 8.2.4 能否由多份内审文档组合出结论，而不是单文档提取。

---

## 1. 测试对象

| 文档 | 编号 | 作用 | FillStatus |
|---|---|---|---|
| 内部审核计划 | `QR-015` | 审核范围、部门、组长/组员、日程 | `filled` |
| 内审会议签到表 | `QR-016` | 首次/末次会议人员 | `filled` |
| 内部审核检查表 | `QR-017` | 分部门、分条款检查记录 | `filled` |
| 内审不合格报告 | `QR-018` | 不合格事实、纠正措施、验证 | `filled` |
| 内部质量审核报告 | `QR-019` | 审核综述、不合格统计、结论 | `filled` |

**结论：5/5 均已填写，8.2.4 是唯一可以做“多文档组合证据”的条款。**

## 2. 单份文档事实

### 2.1 `QR-015` 内审计划

```json
{
  "审核时间": "2026.05.15-16",
  "审核部门": ["总经理", "综合部", "生产部", "供销部", "质量部"],
  "审核组": {"组长": "尚月永", "组员": ["王倩"]},
  "日程": [
    {"日期": "2026.05.15", "审核人员": "王倩", "受审部门": "总经理"},
    {"日期": "2026.05.15", "审核人员": "尚月永", "受审部门": "供销部"},
    {"日期": "2026.05.16", "审核人员": "王倩", "受审部门": "综合部"},
    {"日期": "2026.05.16", "审核人员": "尚月永", "受审部门": "生产部"},
    {"日期": "2026.05.16", "审核人员": "尚月永", "受审部门": "质量部"}
  ]
}
```

**关键事实：**计划里**没有董晶晶**；生产部由尚月永审核。

### 2.2 `QR-016` 签到表

- 首次会议：总经理尚月永、管理者代表王倩等；
- 末次会议：总经理尚月永等；
- **签到栏为空**（原件为人名手签，文本转换后不可见）。

**结论：**签到表能证明会议人员范围，但不能证明手签；`FillStatus=filled` 指表格有人员信息，不指手签可见。

### 2.3 `QR-017` 检查表

- 管理层：王倩，2026.05.15，4.1，合格；
- 供销部：尚月永，2026.05.15，7.5.8，**不合格**（半成品储存区无物料状态标识）；
- 综合部：王倩，2026.05.16，4.2.4，合格（陪同董晶晶）；
- 生产部：**董晶晶**，2026.05.16，7.5.9，合格；
- 质量部：尚月永，2026.05.16，7.6/8.2.6/8.3，合格。

**关键事实：**检查表出现**董晶晶**，且生产部由董晶晶审核。

### 2.4 `QR-018` 内审不合格报告

```json
{
  "受审核部门": "生产部",
  "部门负责人": "王倩",
  "不合格描述": "生产车间半成品储存区有多种型号，未发现物料状态标识，不符合 7.5.8",
  "内审员/日期": "董晶晶 2026.05.16",
  "条款": "7.5.8",

  "实际完成": "2026.05.17",

```

**关键事实：**不合格报告的内审员是**董晶晶**，不是计划里的尚月永。

## 3. CrossCheck 结果

| 编号 | 检查问题 | 结果 | 事实 |
|---|---|---|---|
| `C1` | 计划/检查表/报告的审核员是否一致 | **不一致** | 计划：组长尚月永，组员王倩；检查表：生产部董晶晶；不合格报告：董晶晶；报告：组长尚月永，审核员王倩 |
| `C2` | 受审核部门是否一致 | **基本一致，名称有变体** | 计划/报告：总经理、综合部、生产部、供销部、质量部；检查表：管理层、供销部、综合部、生产部、质量部 |
| `C3` | 不合格数量是否一致 | **一致** | 检查表 1 项（7.5.8）；不合格报告 1 项；内审报告 1 项，无严重不合格 |
| `C4` | 审核员是否审核本部门 | **无法从文档验证** | 计划称生产部由尚月永审；检查表/不合格报告由董晶晶审；无独立性声明；尚月永同时是总经理 |
| `C5` | 不合格闭环是否完整 | **一致** | 2026.05.17 完成标识+培训；尚月永 2026.05.17 验证“整改充分有效” |

**注意：**`C1` 是本次最重要的组合事实，单读 `QR-015` 或 `QR-019` 都发现不了；必须 `QR-015 + QR-017 + QR-018 + QR-019` 一起读。

---

## 4. 能组合出的结论

```text
本次内审：
- 2026.05.15-16，范围覆盖总经理、综合部、生产部、供销部、质量部；
- 审核组长尚月永，计划组员王倩；
- 实际检查表/不合格报告出现第三名审核员董晶晶；
- 不合格 1 项：生产部半成品储存区无物料状态标识，7.5.8，一般；
- 2026.05.17 完成标识和培训，尚月永验证“整改充分有效”；
- 内审报告结论：体系基本符合审核准则，并得到较为有效实施；
- 报告未提董晶晶，计划也未列董晶晶；
- 无独立性声明，无法从文档验证“内审员未审核本部门工作”。
```

**这与真实报告 8.2.4 的证据结构一致：**报告不是读一份文档，而是把计划、检查表、不合格报告、内审报告组合起来，再写“内审实施符合标准要求”。

---

## 5. 对 P3 的要求

1. `RenderDocHits()` 必须能同时给多份文档的 `DocFact`，不能只给单文档原文；
2. `CrossChecks` 要消费 `QR-015/017/018/019` 的审核员字段，不一致只进 `doubts`；
3. `coverage_gap` 不写“未审核本部门”，只写“无独立性声明/无法验证”；
4. 组合结论必须标来源：
   - “1 项不合格”来自 `QR-019`；
   - “7.5.8 一般不合格”来自 `QR-018`；
   - “董晶晶审核生产部”来自 `QR-017/018`；
   - “计划只列王倩”来自 `QR-015`。

## 6. 结论

| 指标 | 结果 |
|---|---|
| 5 份内审文档 `FillStatus` | 5/5 `filled` |
| 能否组合出本次内审结论 | 能 |
| 能否发现名单冲突 | 能，`C1` 不一致 |
| 能否发现不合格闭环 | 能，`C3/C5` 一致 |
| 单文档能否发现 | 不能，必须多文档 |

**P1 记录类轻模型通过。** 下一步可进入 P2：把 `EvidenceContract` 定义和 `clause_attr_gen` 边界话术改成 v3，重跑 5 条契约。
