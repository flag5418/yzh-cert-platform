## 一、分析基座：PDCA 是第一原理（〔U-11〕①）

> 〔U-11〕原话锚点："任何标准都是从领导开始的，有策划，有执行，有改进……国家在制定标准的时候，是有严格的逻辑和顺序的，并尽量统一了各个标准，不同的标准针对不同的方向，采取的措施和写法都是类似的。"

**这是设计的出发点，不是装饰**：写作套路之所以跨标准类似，是因为所有 GB/T 标准被国家刻意统一在同一骨架上；同一 PDCA 环节回答的是同一类问题，所以证据类型、动词、句式才收敛。提示词的组织主轴 = **环节**，统计（句长/引用率/结论率）只做验证，不做设计依据（此前把统计当主轴是表面化，〔U-11〕⑤）。

### 1.1 环节 → 证据逻辑链

| PDCA 环节 | 9001/24001/45001 | 42061（13485） | 该环节回答什么 | 证据重心 | 写作重心 | 实测对应（验证） |
|---|---|---|---|---|---|---|
| 输入：情境 | 4 组织环境 | 4.1–4.2 | 企业是什么、体系覆盖什么 | 手册、营业执照、场所清单 | 陈述 + 原文引用 | 4–5 章手册引用率最高（10%/20%） |
| 锚：领导 | 5 领导作用 | 5 管理职责 | 谁负责、承诺了什么 | 手册、任命书、方针 | 结论句 + 职责点名 | 5 章结论率 27–31% |
| P 策划 | 6 策划 | 7.1（产品实现策划部分） | 目标怎么定、风险怎么识别 | 程序、目标分解表、风险清单 | 点名制度 + 引用 | 6 章引用率最高（33%/11%） |
| D 前提：支持 | 7 支持 | 6 资源管理 | 人机料法环够不够 | 台账、培训/校准记录 | 条目归纳 + 抽样明细 | 培训/校准类最集中 |
| D 执行 | 8 运行 | 7.2–7.5 产品实现 | 活怎么干、受控没有 | 生产/检验记录、合同 | 过程描述 + 抽样 + 判定 | 全书最厚（42,283 / 15,840 字）；8.4/8.5/8.6/8.7 字段完全不同 |
| C 检查 | 9 绩效评价 | 8.1–8.4 监视测量 | 怎么查、查到什么 | 内审/管评/合规评价报告 | 结论为主、接近整句搬运 | 结论率最高（14–20%） |
| A 改进 | 10 改进 | 8.5 | 出了问题怎么改 | 不合格记录、纠正验证 | 数量 + 处置 + 验证结论 | 结论率 22–23% |

> 13485 的 7 章兼 P/D、8 章兼 C/A：以条款内容判环节（7.1→P；7.5→D；8.2→C；8.3/8.5→A），不按章整体归类（承接 14 号文）。

### 1.2 大标题是章节的核心分类（〔U-14〕）

> 〔U-14〕锚点："5.0、6.0 这些感觉没什么实际内容的大标题其实是整个章节的核心分类，几个字条款都是围绕这个大标题的核心来展开的。"

- 大标题（章标题）= 本章核心语义的命名，就是 §1.1 表中"该环节回答什么"的出处，**批级写作重心的第一来源**。
- 深读顺序固定**先章后款**：先分析大标题核心语义 + 大标题×子条款的关系（本章围绕什么展开、子条款怎么分工），再逐条款读；**禁止孤立读条款**——只看条款内容会产生理解误差（〔U-14〕）。
- 条款侧判定（看什么文件、检查点、证据来源分型）一律在章核心语义框架内下结论：同类要求在不同章下语义不同（如"成文信息"在 4 章 vs 7.5 章）。
- 落地：深读卡首字段 = "章核心语义"；条款↔文档对照的条款侧需求也按章框架校验。

### 1.3 三处实证（验证，非来源）

| # | 实测 | 说明 |
|---|---|---|
| 1 | 句长 27–39 字跨三家企业、两套标准、七个章全线稳定 | 骨架由环节决定，不由标准决定——〔U-11〕"写法都是类似的"的量化证据 |
| 2 | 每份报告最厚章都是 D 环节（尚龙第 7 章=产品实现 42,283 字；科斯亚第 7 章=支持 15,840 字） | 章号随标准变、环节不变 |
| 3 | 引用率/结论率分布与环节一一对应（P 引用最高、C/A 结论最高） | 写法重心是**环节的函数** |

### 1.4 条款的两个先决属性（逐条款从 GBT 原文分析得出，〔U-12〕）

> 〔U-12〕锚点："一个条款要区分它的分类（章节）……只有少部分实施需要采样分析，其他都是从企业文档中原样长出来……审核员不可能去反驳，然后让企业按审核员要求从新写。"

| 属性 | 取值 | 从标准原文怎么判 | 对生成的影响 |
|---|---|---|---|
| **章节分类** | 所属环节/章（领导/策划/支持/执行/检查/改进） | 条款所在章与上下承接关系 | 决定批级写作套路（§2.2）；同章内条款写法可能类似。**须逐条款登记进属性池/深读卡** |
| **证据来源** | 文档原生（绝大部分） / 采样分析（少部分） / 现场观察（少量） | 情态词与动词："应制定/应形成/最高管理者应确保…"→文档原生；"应实施/应保留记录/应进行…验证"→采样分析；无法从文档得到的（协商参与等）→现场观察 | **文档原生型**：证据 = 企业文档原样长出（原样引用/点名/照实组织），只确认存在性与符合性，不评判内容、不输出重写建议（方针/制度/指导书/改进措施均如此）；**采样分析型**：抽样三件套 + 判定；**现场型**：人工录入 |

与 A–F 形态的关系：文档原生 ≈ A/B/C 型为主，采样分析 ≈ D/E 型为主，现场 = F 型。分型在逐条款深读时确定，判据 = 标准原文（情态词/动词映射，国标对比已有底稿），**不靠猜**。

## 二、提示词方向设计

### 2.1 总方向：提示词装工序，知识装注入件

提示词本身只写"把事实变成证据段"的固定步骤；标准原文、条款深读卡、格子套路、事实条目、风格包全部是注入件。知识错了改注入件，工序错了才改提示词，回归评测分开做（对齐 14 号文三类提示词边界）。

### 2.2 分段：批次按 PDCA 环节切（≈按章，〔U-10〕"每一章一个提示词我觉得合理"）

| 批次 | 章 | 批级写作套路（该批条款共用的重心） |
|---|---|---|
| 领导批 | 4–5 | 原样引用方针/职责/任命 + 结论句；**少抽样** |
| 策划批 | 6 | 点名制度 + 引用文件名；目标/风险清单条目 |
| 支持批 | 7 | 台账条目归纳（"共 N…"）+ 抽样明细（三件套） |
| 执行批 | 8 | 过程描述 + 抽样明细 + 判定；**批内按形态细分**（8.4 合同字段 / 8.5 过程参数 / 8.6 判定 / 8.7 数量台账） |
| 检查批 | 9 | 报告类结论逐字引用 + 日期/要素 |
| 改进批 | 10 | 数量 + 处置 + 验证结论 |

**两层结构**：批（环节）定写作重心，格（证据形态 A–F）定字段与句式（07/14 号文成果保留为批内细则）。运行时 = 每批一次调用；维护上 = 1 条主提示词骨架 + 每批注入件。换标准不改提示词，换机构只换风格包。

### 2.3 主提示词骨架：6 区块 + 工序六步

| 区块 | 内容 | 位置 |
|---|---|---|
| ① 角色与边界 | ACM 审核证据组织助手；只建议不判定（X7）；不许生成新事实 | 骨架 |
| ② 输入清单 | 标准原文 → 条款深读卡 → 企业文档事实 → 现场证据 + 风格包 | 骨架（清单）+ 注入（内容） |
| ③ 工序六步 | 见下 | 骨架 |
| ④ 写作规则 | **四类句式 + 批级套路 + 格子套路直接写进正文**（〔U-11〕④，不再外挂句式模板表工件） | 骨架 |
| ⑤ 红线 X1–X7 | 含"引用即原文"（X2）、"无实证锚点的检查点不进入生成"、**"文档原生型只确认存在性与符合性，不评判内容、不输出重写建议"**（〔U-12〕③：审核员不能否认企业文档） | 骨架 |
| ⑥ 输出契约 | clause_evidence + finding_ids + 疑点 + 建议稿标注 | 骨架 |

**工序六步**（底稿→报告六道工序的指令化，即"条款和文档怎么组合"的答案）：

```
1 归并：输入事实按（条款，检查点）归并，与条款无关的一律丢弃
2 收窄：按深读卡的抽样量收窄样本，写抽样三件套（声明句 + 逐条明细 + "如…等"）
3 改写：按本条款的批级套路 + 格子套路改写口吻，动词只用封闭集（查见/见/提供/抽见/现场查见/与X面谈）
4 补套：补档案四件套（编号 + 版本 + 编制/审核/批准 + 发布日期）
5 引用：报告类结论逐字引用带引号，一字不改（X2）
6 判定：判定语从封闭枚举选；无现场证据或无实证锚点 → 留白待确认（X7）
```

## 三、重新定位（〔U-13〕）：条款↔文档对照是主链路

> 〔U-13〕锚点："咨询公司整理文档的时候，都快把条款写到每个文档上了……他们很难按标准漏写任何一个文档的，我们的工作就是对照条款找到，按审核员的习惯组织仅此而已。"

### 3.1 事实基点

企业文档体系（咨询公司按标准代建）**本身就是按条款组织的**：文档名/编号/受控清单/目的段几乎自带条款归属；标准要求的文档很难缺。⇒ 条款↔文档映射**企业侧已经做完**，系统的第一动作是**读文档自带的条款信号**，不是从零推理"这个条款该看什么文档"。

### 3.2 主链路（三步，修正后）

| 步 | 内容 |
|:--:|---|
| 1 对照 | **条款↔文档对照主数据**：文档侧信号（文件名 / 编号 / 受控清单条目 / 手册条款数组 / 目的段——17 号文 `process_clause_map` 方法扩展到全部文档类型）× 条款侧需求（深读卡"看什么文件"）双向对账；缺口标"推导/待补" |
| 2 找到 | 按对照表召回该条款的文档与事实（复用 doc_clause_extract / 文档画像 / 文档提取） |
| 3 组织 | 按审核员习惯组织：批级套路 + 格子套路 + 工序六步——"仅此而已" |

- **文档原生型条款**（〔U-12〕绝大部分）：第 2 步即基本完成证据内容（原样引用/点名/照实组织），第 3 步只是套句子骨架；
- **采样分析型条款**（少部分，集中在 D 环节执行批）：进入抽样三件套 + 判定；
- **现场型**：人工录入带入。

### 3.3 对既有设计的影响

| 项 | 修正 |
|---|---|
| 条款深读卡 | 保留（§四），重心收缩：核心产出 = "该条款对应哪些文档" + 证据来源分型 + 少部分采样条款的检查点；**不为文档原生型条款展开复杂检查点推理** |
| 主线工件 | 新增：条款↔文档对照主数据（§五 缺口 #2 前置） |
| 提示词 | 不变（§二）：知识在注入件，提示词装工序；"找到"的准确性由对照主数据保证，"组织"的准确性由套路保证 |

## 四、条款逐项深读方案（核心分析工作，〔U-11〕⑤）

> 〔U-11〕锚点："针对条款的逐项阅读，还有整个体系认证针对 gbt 的研究分析不到位，光看程序逻辑针对我们整个程序帮助并不大。"
> 学习方式唯一 = 分析实际企业文档 + 最终报告，从实证学条款（〔U-9〕①、〔U-11〕①），不向用户索取知识、不把条款理解做成产品功能（〔U-9〕②）。

### 4.1 深读卡片结构（每条款一张）

```
{条款}
├─ 章核心：大标题语义 + 本章子条款分工（先章后款，〔U-14〕；首字段）
├─ PDCA 位置：在哪个环节；与上下条款的承接（策划定了什么 → 执行要用什么 → 检查查什么 → 改进改什么）
├─ 章节分类：登记进属性池（写作套路主轴，〔U-12〕①）
├─ 证据来源：文档原生 / 采样分析 / 现场观察（判据 = 标准原文情态词与动词，〔U-12〕②；决定生成策略）
├─ 本条款回答的问题（1 句）
├─ 检查点 × 3–8：问什么 / 看什么文件 / 抽什么记录 / 看什么现场 / 判定基准
├─ 证据配方：挂属性池（EvidenceFamily / EvidenceForm / Role / Process）+ 抽样量 + 覆盖期
├─ 写法：所属批次的写作重心 + 槽位句式（进提示词正文）
└─ 实证锚点：三套报告该条款真实段落 ≥1 处；无 → 标"推导"并隔离，不混入实证区
```

**深读方式（先章后款，〔U-14〕）**：先读大标题核心语义与大标题×子条款关系 → 再逐条款读标准原文（`语料md/国标/`）→ 预填卡片 → 用三套报告该条款真实写法（`语料md/报告/`）验证修正 → 定稿。顺序：9001 先行 → 24001/45001 同号复用 + 差异标注（同构/名词替换/增补/加严，国标对比已有 30 组）→ 42061 兼环处理。

### 4.2 与属性池的关系（〔U-11〕③"单独一张完善提示词"）

| 层 | 载体 | 内容 |
|---|---|---|
| 结构骨架 | 属性池（已有） | EvidenceFamily / EvidenceForm / Role / Process 等 9 条 |
| 语义血肉 | **条款深读卡（单独一张）** | PDCA 位置 / 回答问题 / 检查点五要素 / 实证锚点 |

- 同键挂接：`(StandardCode, ClauseCode)`，与属性池一次查询取全。
- 分析期载体建议用**一张工作表**（可逐条评注、审核员可读），定稿后入 DB（形态待 §五 确认）。
- 三个用途：① 提示词注入件；② 条款→文档匹配规则源（"看什么文件/抽什么记录"直接喂召回）；③ 后续对外解释的底稿。

### 4.3 GBT 整体研究分析清单（不只逐条款）

| # | 分析件 | 内容 | 现状 |
|---|---|---|---|
| 1 | 四标准骨架对照 | 章 → 环节映射表（含 13485 兼环处理） | 本文 §1.1 已立骨架，需逐章核实补全 |
| 2 | 同号条款跨标准语义对照 | 30 组差异（同构/名词替换/增补/加严）落进深读卡 | 国标对比已有成果，需落到卡片 |
| 3 | 体系级证据流 | 方针→目标→方案→记录→评价→改进的证据闭环；跨条款数据逐字一致是机器可查的强校验依据 | 未做 |
| 4 | 部门 × 环节矩阵 | 检查项定位（哪个部门在哪个环节被查什么） | 国标对比已有矩阵，需对齐深读卡 |

### 六之一、一周冲刺：第 8 章试点验收（2026-11-13 ~ 11-19，〔U-16〕④）

**要回答的唯一问题**：主提示词能不能把"条款 + 文档事实"组织成审核员 3 秒认可的科斯亚第 8 章证据段。

| 日 | 任务 | 产出 |

**验收口径（事先定死，防"感觉不行"式否决）**：

| 指标 | 门槛 | 性质 |
|---|---|---|
| 事实可溯源 | 生成段每个事实能指回具体文档/记录，100% 可溯源 | 硬 |

| 盲评 | 审核员群混排盲评，接受为"可用初稿"的比例 | 主观定夺 |

**裁决规则**：硬指标全绿 + 盲评过关 ⇒ 方向确认，铺开全条款；硬指标不绿 ⇒ 先区分"提示词问题"还是"事实供给问题"（后者可修，不算失败）；两轮修正后仍不过 ⇒ 失败形态本身（哪类条款败、怎么败）作为方向更换的实证输入。

**轻量产品形态（审核员端，一个引擎两个功能）**：① 证据建议稿（选条款 → 三产物，标注"建议稿"）；② 提交前自动复核（审核员自己的报告跑机器四查 + 一致性 + R1–R10 → 问题清单）——对应〔U-16〕②签字终身责任 / 飞检自保刚需。

**诚实风险（直说）**：最大风险不是提示词，而是 D3 前的**事实备料**（科斯亚 8 章事实条目整理不到位则提示词无法公平验证）；次风险是 8 章本身是最难章——8 章过了其余章大概率过，8 章不过按时间盒即高风险信号。
