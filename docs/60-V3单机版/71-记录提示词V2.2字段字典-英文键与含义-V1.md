# 71-记录提示词 V2.2 字段字典（英文键 + 中文含义）-V1

> 对应提示词：`doc_extract_record_profile`，V2.2，`cert_prompt_template.Id=10`
> 落库脚本：`scripts/db/fix/20261114_doc_mode_prompts_v2_2.sql`
> 原则：JSON key 一律英文；本文件中文只解释含义，不作为字段名。
> 上游：`70-条款证据契约与记录匹配-3条试点-V1.md`。V2.2 的核心不是加字段，而是按 `DocClass` 分三种对象。

---

## 0. 怎么读这份 JSON

先看 `DocClass`，再看对应对象：

| `DocClass` | 含义 | 读哪个对象 |
|---|---|---|
| `record` | 一份表单/记录，正文是行数据 | `Records[]` |
| `catalog` | 目录/清单，正文是“名称+编号+版本+日期+部门” | `Records[0]` 汇总 + `Catalog` |
| `set` | 治理证据包，多份文档组成一次内审/管评 | `Records[0]` 汇总 + `RecordSet` |

`Records` 始终有 1–3 条，保证旧消费链可读；目录和包的细节在 `Catalog` / `RecordSet`，不再塞进 `Rows`。

## 1. 顶层字段

| 英文键 | 类型 | 含义 | 取值/示例 |
|---|---|---|---|
| `DocType` | string | 文档大类，本提示词固定 | `record` |
| `DocClass` | string | 记录对象分型，V2.2 新增 | `record` / `catalog` / `set` |
| `DocTitle` | string | 文档标题，原文优先 | `质量记录清单` |
| `StandardRelevant` | bool | 是否与标准相关 | `true` |
| `Extractable` | bool | 本类型专属事实是否可提取 | `true` |
| `ClauseEligible` | bool | 是否允许做条款级提取；非手册固定 false | `false` |
| `ExtractReason` | string | 为什么能/不能提取，一句话 | `记录表单，提供执行证据` |
| `ProcessArea` | string | 业务过程区域，八选一 | `检验过程` |
| `DocSections` | string[] | 文档自身章节/小节，不是标准条款 | `["1 目的","4 工作流程"]` |
| `Chapters` | string[] | 标准父章节，不写叶子 | `["4","8"]` |
| `OwnerDept` | string | 执行/受审部门 | `质量部` |
| `SupportDepts` | string[] | 参与/支持部门 | `["生产部"]` |
| `DocUse` | string | 文档用途，固定 | `evidence` |
| `ReportRole` | string | 报告角色，固定 | `evidence_source` |
| `ReportDepth` | string | 报告消费深度，固定 | `sample` |
| `ReportSummary` | string | 一句话说明记录了什么、谁执行/谁记录；≤60 汉字 | `记录成品检验的日期、型号、数量、检验项目和判定结果。` |
| `ReportUse` | string | 固定文本；不在提取阶段判断报告是否引用 | `作为记录证据来源；是否被报告引用由后续报告索引判定。` |
| `PrimaryClauses` | string[] | 直接支撑的标准叶子条款，1–2 条 | `["8.2.6"]` |
| `SupportClauses` | string[] | 间接支撑的标准叶子条款，0–2 条 | `["7.5.9.1"]` |
| `Metadata` | object | 文档身份信息，只取原文 | 见 1.1 |
| `CoveragePeriod` | object | 记录/台账/审核的覆盖期间 | 见 1.2 |
| `Warnings` | object[] | 结构化告警 | 见 1.3 |
| `Records` | object[] | 记录/汇总记录，1–3 条 | 见 2 |
| `Catalog` | object/null | 目录结构；仅 `DocClass=catalog` | 见 3 |
| `RecordSet` | object/null | 治理包结构；仅 `DocClass=set` | 见 4 |

### 1.1 `Metadata`

| 英文键 | 类型 | 含义 | 示例 |
|---|---|---|---|
| `DocCode` | string | 文件编号/表单编号 | `XASL-QR-027` |
| `DocVersion` | string | 版本号 | `A/0` |
| `EffectiveDate` | string | 生效日期 | `2026-02-05` |
| `IssuedBy` | string | 编制/发行部门 | `质量部` |
| `ApprovedBy` | string | 批准人/批准角色 | `尚月永` |

规则：原文没有给空字符串，不许编造。

### 1.2 `CoveragePeriod`

| 英文键 | 类型 | 含义 | 示例 |
|---|---|---|---|
| `Start` | string | 覆盖开始日期 | `2026-05` |
| `End` | string | 覆盖结束日期 | `2026-07` |

只给记录/台账/证书/审核/清单；程序、指导书、制度给空字符串。

### 1.3 `Warnings[]`

| 英文键 | 类型 | 含义 |
|---|---|---|
| `Code` | string | 告警代码，见下表 |
| `Message` | string | 一句话说明 |

| `Code` | 含义 |
|---|---|
| `missing_metadata` | 缺编号/版本/日期/批准 |
| `missing_owner_dept` | 缺执行/责任部门 |
| `ambiguous_type` | 文档类型判不出 |
| `multi_chapter` | 一份文档跨多个标准章节 |
| `blank_form` | 空白模板 |
| `code_conflict` | 同号两名、页脚错号、编号缺失 |
| `catalog_mismatch` | 清单与实物不一致 |
| `auditor_inconsistent` | 计划/检查表/报告的审核员名单不一致 |
| `cross_product` | 产品/型号与审核范围不符 |
| `ambiguous_scope` | 适用范围无法判断 |
| `rows_truncated` | Rows 超过 30 行已截断 |
| `report_only` | 文件夹无实际记录，报告有实际数据 |
| `other` | 其他 |

## 2. `Records[]`（运行记录 / 汇总记录）

| 英文键 | 类型 | 含义 | 示例 |
|---|---|---|---|
| `RecordName` | string | 记录/表单名称 | `成品检验记录` |
| `DocSection` | string | 该记录在文档中的真实小节号 | `4.2` |
| `ProcessName` | string | 具体过程名 | `成品检验` |
| `OwnerDept` | string | 执行/责任部门 | `质量部` |
| `Applicable` | bool | 产品/型号/工艺/范围是否适用 | `false`（跨产品时） |
| `HasInstance` | bool | 是否有实际数据行/日期/签名/数量/批次/结论 | `true` |
| `ZeroEvent` | bool | 原文是否明确“无发生/无投诉/无事故” | `false` |
| `Coverage` | string | 实际覆盖的日期/型号/批次/数量/对象 | `2026-05-08 至 2026-07-09；3 型号；5 批` |
| `FormFields` | string[] | 表单字段名，原文表头优先 | `["产品名称","生产批号","检验项目","检验结果","检验员"]` |
| `Period` | string | 记录期间 | `2026-05` |
| `Batch` | string | 批次/批号 | `SYⅣ100-SL01A` |
| `RowCount` | int | 原文非空数据行总数 | `39` |
| `Samples` | object[] | 报告抽样用，1–3 条，必须从 `Rows` 选 | 见 2.1 |
| `Rows` | object[] | 所有非空数据行，最多 30 行 | 见 2.1 |
| `Signoff` | string[] | 原文签署角色/姓名 | `["检验员 尚月茂","审核 空白"]` |
| `LinkedDoc` | string | 原文提到的关联文件 | `成品检验作业指导书` |
| `EvidencePointers` | string[] | 原文真实记录/表单名 | `["成品检验记录"]` |
| `RecordState` | string | 填写状态 | `blank` / `partial` / `filled` |

### 2.1 `Samples[]` / `Rows[]` 行结构

| 英文键 | 类型 | 含义 | 示例 |
|---|---|---|---|
| `Date` | string | 日期 | `2026-06-23` |
| `Batch` | string | 批次/批号 | `SYⅣ100-SL01A` |
| `Values` | string[] | 该行关键值，按“字段：值”写 | `["数量：100","检验结果：合格"]` |
| `Conclusion` | string | 原文结论栏 | `合格` |
| `Signoff` | string | 原文签署 | `检验员 尚月茂` |

规则：
- `Samples` 1–3 条；空白模板 `[]`。
- `Rows` 最多 30 行；超过 30 行保留前 30 行，`Warnings` 记 `rows_truncated`。
- 目录型不要把 100 条塞进 `Rows`，用 `Catalog`。

## 3. `Catalog`（目录/清单对象）

仅 `DocClass=catalog` 时填写；否则 `null`。

| 英文键 | 类型 | 含义 | 示例 |
|---|---|---|---|
| `CatalogType` | string | 目录类型 | `record_list` / `file_list` / `ledger` / `unknown` |
| `Count` | int | 目录条目总数，不是 `Items` 条数 | `100` |
| `Items` | object[] | 前 10 条条目，按原文顺序 | 见 3.1 |
| `Missing` | string[] | 清单有、实际文件没有的编号/名称 | `["XASL-OR-011","XASL-PR-006"]` |
| `Extra` | string[] | 实际文件有、清单没有的编号/名称 | `["XASL-QR-038"]` |
| `CodeConflicts` | object[] | 同号两名/页脚错号，最多 10 条 | 见 3.2 |
| `RetentionFields` | object | 目录是否有保存期限/检索/处置三列 | 见 3.3 |
| `Notes` | string | 目录其他事实，一句话 | `清单无保存期限列` |

### 3.1 `Items[]`

| 英文键 | 类型 | 含义 | 示例 |
|---|---|---|---|
| `Name` | string | 记录/文件名称 | `成品检验记录` |
| `Code` | string | 编号 | `XASL-QR-027` |
| `Version` | string | 版本号 | `A/0` |
| `EffectiveDate` | string | 生效日期 | `2026-02-05` |
| `Dept` | string | 编制/责任部门 | `质量部` |
| `Retention` | string | 原文保存期限；没有给空字符串 | `5 年` |

### 3.2 `CodeConflicts[]`

| 英文键 | 类型 | 含义 | 示例 |
|---|---|---|---|
| `Code` | string | 冲突编号 | `XASL-PR-007` |
| `Names` | string[] | 同号对应的不同名称 | `["设备报废申请表","设备维修记录"]` |
| `Message` | string | 冲突说明 | `同号两名` |

### 3.3 `RetentionFields`

| 英文键 | 类型 | 含义 | 示例 |
|---|---|---|---|
| `HasRetention` | bool | 目录是否有保存期限列 | `false` |
| `HasRetrieval` | bool | 目录是否有检索方式列 | `false` |
| `HasDisposition` | bool | 目录是否有处置方式列 | `false` |

只回答“目录里有没有这三列”，不推断程序文件有没有规定。

## 4. `RecordSet`（治理证据包）

仅 `DocClass=set` 时填写；否则 `null`。

| 英文键 | 类型 | 含义 | 示例 |
|---|---|---|---|
| `SetType` | string | 包类型 | `internal_audit` / `management_review` / `other` |
| `Period` | string | 包覆盖期间 | `2026-05-15 至 2026-05-16` |
| `Owner` | string | 包负责人/组长 | `尚月永` |
| `Members` | object[] | 包内文档清单，最多 10 条 | 见 4.1 |
| `Coverage` | object | 实际覆盖的部门/条款/过程 | 见 4.2 |
| `Findings` | object[] | 不合格/观察项，最多 10 条 | 见 4.3 |
| `Closure` | object | 关闭信息 | 见 4.4 |
| `Consistency` | object | 跨文档一致性 | 见 4.5 |

### 4.1 `Members[]`

| 英文键 | 类型 | 含义 | 示例 |
|---|---|---|---|
| `Name` | string | 文档名 | `内部审核计划` |
| `Code` | string | 文档编号 | `XASL-QR-015` |
| `Status` | string | 文档状态 | `filled` / `blank` / `missing` |
| `Evidence` | string | 关键证据一句话 | `5 部门、日期、条款、组长/组员` |

### 4.2 `Coverage`

| 英文键 | 类型 | 含义 | 示例 |
|---|---|---|---|
| `Departments` | string[] | 实际受审/覆盖部门 | `["总经理","综合部","生产部","供销部","质量部"]` |
| `Clauses` | string[] | 实际覆盖的条款 | `["4.1","4.2.5","8.2.4"]` |
| `Processes` | string[] | 实际覆盖的过程 | `["文件控制","生产","采购"]` |

### 4.3 `Findings[]`

| 英文键 | 类型 | 含义 | 示例 |
|---|---|---|---|
| `Source` | string | 来源文档 | `内审不合格报告` |
| `Description` | string | 不合格/观察描述 | `半成品储存区未发现物料状态标识` |
| `Clause` | string | 标准条款 | `7.5.8` |
| `Category` | string | 分类 | `一般` / `严重` / `观察` |
| `Closure` | string | 关闭情况 | `2026-05-17 已验证关闭` |

### 4.4 `Closure`

| 英文键 | 类型 | 含义 | 示例 |
|---|---|---|---|
| `Date` | string | 关闭日期 | `2026-05-17` |
| `Verifier` | string | 验证人 | `尚月永` |
| `Evidence` | string | 关闭证据 | `标识到位，整改充分有效` |

### 4.5 `Consistency`

| 英文键 | 类型 | 含义 | 示例 |
|---|---|---|---|
| `AuditorRoster` | string | 计划/检查表/报告审核员名单是否一致 | `consistent` / `inconsistent` / `unknown` |
| `Note` | string | 差异说明 | `计划组员王倩；检查表生产部由董晶晶审；报告未提董晶晶` |

## 5. 三个读法示例

### 5.1 `QR-010` 目录

- `DocClass=catalog`
- `Records[0].RecordState=filled`
- `Catalog.Count=100`
- `Catalog.CatalogType=record_list`
- `Catalog.Items` 只有前 10 条
- `Catalog.RetentionFields.HasRetention=false`
- `Catalog.Missing` / `Extra` / `CodeConflicts` 记录账实差异
- `Rows` 不应装 100 条

### 5.2 内审包

- `DocClass=set`
- `RecordSet.SetType=internal_audit`
- `RecordSet.Coverage.Departments` 5 个部门
- `RecordSet.Findings` 1 项 7.5.8
- `RecordSet.Closure.Date=2026-05-17`
- `RecordSet.Consistency.AuditorRoster=inconsistent`

### 5.3 `QR-038` 跨产品终检

- `DocClass=record`
- `Records[0].Applicable=false`
- `Records[0].HasInstance=true`
- `Records[0].RecordState=filled`
- `Records[0].Coverage="1 份；表头为空"`
- `Warnings` 含 `cross_product`

## 6. 当前不做的事

- 不在提取阶段判断“符合/不符合”。
- 不在提取阶段判断“报告有没有引用”；`ReportPresence` 不输出。
- 不在提取阶段做条款-文档匹配；匹配由报告侧 `EvidenceMatch` 做。
- 不把目录 100 条全塞进 `Rows`；目录用 `Catalog`。
- 不把内审包压成一张表；包用 `RecordSet`。
