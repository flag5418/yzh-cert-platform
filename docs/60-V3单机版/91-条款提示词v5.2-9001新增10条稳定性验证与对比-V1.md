## 二、验证集与文档事实层

### 2.1 文档事实层结果

- 38/38 `JSON_OK`。
- FillStatus 人工核对：37/38 正确，错误 1 条。
- 主要分布正常：
  - 程序/制度/作业指导类：`filled`，未出现把程序当记录的问题。
  - 空白表单：`template_only`，未编造“已执行记录”。
  - 部分填写记录：`partial`，如发放回收表、合同评审、进料/出厂检验报告、顾客满意度分析报告。

### 2.2 唯一明确错判：`07记录清单` 被判 `template_only`

- 实际原文：53 条记录编号 + 记录名称 + 保存期限，均有值；只是“序号”列空。
- DocFact 输出：`FillStatus=template_only`，`SampleRows=[]`。
- 下游后果：`7.5.3.2 F8` 写成“记录清单为模板，表格中无实际记录条目（全为空行）”，与原文直接冲突；`D3` 又据此推断记录编号无法追溯。
- 根因：DocFact 把“序号列空”当成“整表空白”，没有按“任一业务字段有值”判断。
- 这是本轮最值得先修的文档层错误；1/38 = 2.6%，虽然仍在 ≥95% 边界内，但影响面大。

**文档层建议规则：**
1. `template_only` 只能在“所有业务字段均为空”时使用；序号为空但记录编号/名称/期限有值，不能判模板。
2. 只要任一业务字段有值，至少 `partial`；关键字段全部有值，判 `filled`。
3. `SampleRows` 为空但正文存在多行业务值时，必须回查原文，不能只依赖表头结构。

### 3.2 Findings：事实准，引用不稳

- 事实正确：42/43，只有 `7.5.3.2 F8` 明确错误。
- 原文引用：
  - exact 15 条
  - near 14 条（表格换行、`**`、`<br>` 归一后命中）
  - 非连续 14 条：7 条含 `...` / `……`，7 条表格行重排后无法连续命中
  - 合计 exact+near **29/43 = 67.4%**
- 典型引用问题：
  1. `8.5.2 F1` 引用“著作权声明”来说明“已建立标识与可追溯性控制程序”，引用位置错，虽然原文存在，但不支撑结论。
  2. `7.2 F5/F6`、`8.5.4 F2/F3`、`9.1.2 F3`、`9.3.2 F4/F5` 的 `OriginalQuote` 含 `...` 或 `……`，属于多段拼接，不是连续原文。
  3. `8.2.2 F2` 只引“符合”两个字，信息量过低，无法定位到具体法规要求。
  4. `9.3.2 F2/F3` 把输入项标题当证据，标题存在不等于输入数据存在。
  5. `8.6 F3` 把“进料检验批准人潘明海”推断为“授权放行人”，属于范围外推断。
- `WhatItProves` 过强：
  - `7.2 F1` 说“明示 7.2 全部四款”，原文对应 a/b/c 与“保留文件化信息”，不能直接说全部四款。
  - `7.2 F3` 说“直接支撑 a/b/c/d 四款”，评价表主要支撑 b/d，a/c 需要岗位能力矩阵和培训有效性。

## 七、稳定化方案：提示词冻结，加 5 个运行时校验器

不建议继续往 v5.2 里加“某条款某文档”的规则。当前错误主要不是模型不会读，而是输出字段缺少硬约束。建议按下面 5 个校验器做代码层收口。

### 7.1 DocFactValidator（文档层，P0）

规则：
1. `template_only` 仅当所有业务字段为空；序号空但记录编号/名称/期限有值，不得判模板。
2. 任一业务字段有值 → 至少 `partial`；关键字段全有值 → `filled`。
3. `SampleRows=[]` 但正文存在多行业务值时，回查原文并重新判定。
4. 对 `list` 类，至少检查“编号/名称/期限”三列是否全空；不能只看序号列。

预期拦住：`07记录清单` 误判。

### 7.2 QuoteValidator（引用层，P0）

规则：
1. `OriginalQuote` 必须能在原文中 exact 或归一化后连续命中；`...` / `……` 直接判失败。
2. 禁止引用页眉页脚、著作权声明、目录、修订记录等非正文内容。
3. `field_present` 的引用必须包含“字段名 + 字段值”，不能只引“符合”两字。
4. `document_exists` 的引用必须来自目的/范围/程序内容章节，不能只引文件头。
5. 引用长度过短（如 <10 字）时必须带 `DocLocation` 的字段名和上下文。

预期拦住：8.5.2 F1、8.2.2 F2、7.2 F5/F6、8.5.4 F2/F3、9.1.2 F3、9.3.2 F4/F5。

### 7.3 ClauseItemValidator（条款条目层，P0）

规则：
1. 允许的条目编码必须来自条款属性池/条款 ToC，不能用模型自己生成的 `ClauseContext.ClauseItems` 反推。
2. 无 a/b/c 的条款统一用 `main`；`ClauseItemRef=[]` 判失败。
3. 注、示例、注2 来源（如 7.1.6 的 a/b）不得当成要求项。
4. 条款原文只有 a/b 时不得出现 c/d；8.2.2 只有 a/b，8.5.4 无条目，7.1.6 无要求条目。

预期拦住：7.1.6 的 a/b/c 虚构、8.5.4 空数组；同时修正 8.2.2/7.1.6 的 `ClauseItems` 缺失。

### 7.4 DoubtTypeValidator（疑点类型层，P0）

规则：
1. `blank_template` 仅当关联 finding 的 `FillStatus=template_only`；对 filled/partial 判 blank_template 直接降级。
2. `missing_signature` 仅当文档已填写、签名字段为空；整表 blank_template 时不得用。
3. `date_conflict` 必须出现至少 2 个日期，且顺序/区间确实冲突；单日期只能 `no_traceability` / `scope_mismatch`。
4. `report_only` 仅用于关联 finding 为 `report` 类；没有报告类证据时不得用。
5. `inconsistent_person` 必须有两个具体人员且事实矛盾；不同角色签署、职责重叠改用 `scope_mismatch`。
6. `DoubtType` 与 `FillStatus` 不一致时，输出降级为 `no_traceability`，并保留原文描述。

预期拦住：7.5.3.2 D3/D4、8.2.2 D1/D2、8.5.4 D1/D3、8.6 D3、9.1.2 D2、9.3.2 D2/D3、10.2.1 D2、7.1.6 D1/D2。

### 7.5 AssemblyValidator（组合层，P0）

规则：
1. `CanFormEvidence=true` 必须同时满足：`Gap` 为空；所需 doc class 全部出现；至少 1 份 `filled` 的实施记录（record/report）。
2. 只有 procedure / work_instruction，没有实施记录 → 最高 `partial`。
3. 所需记录为 `template_only` 或 `partial` → 最高 `partial`。
4. `Gap` 非空时不得 true。
5. `MinDocs` 不能替代“记录实例”；文件存在不等于执行。

预期拦住：8.5.4 A1、8.2.2 A2、8.5.2 重跑 A1、7.5.3.2 A3。

## 八、复测门槛

加校验器后，用同一 15 条复测两轮，建议验收线：

| 指标 | 门槛 |
|---|---|
| JSON_OK | 15/15 |
| DocFact FillStatus | ≥95%（56 份至少 54 份正确） |
| Finding 事实正确 | ≥95% |
| OriginalQuote exact+near | ≥90% |
| Doubt 实质性有效 | ≥85% |
| DoubtType 正确 | ≥85% |
| Assembly true 精确率 | 100%（true 不允许有 Gap 或只有程序） |
| run-to-run 数量波动 | 单条款 F/D/A 变化 ≤1 |

只有达到这组门槛，才建议把 v5.2 写库；否则继续停留在“影子提示词 + 运行时校验”阶段。

## 九、最终判断

- **文档事实层：有条件通过。** 分类和填写状态基本可靠，空白模板没有编造；但必须修 `07记录清单` 的“序号空 = 整表空”规则。
- **条款证据发现：事实通过，引用不通过。** 关键人、日期、数量、结论大多准确，但表格类文档的 `OriginalQuote` 拼接严重，不能直接给审核员作为“原文证据”。
- **疑点：实质通过，类型不通过。** 大多数疑点有现场核查价值；但 `blank_template`、`missing_signature`、`date_conflict`、`report_only` 四类被混用，必须先校验类型。
- **证据组合：不通过。** `CanFormEvidence=true` 仍偏向“文件存在即可”，没有真正要求“已填记录 + 条件满足”。
- **稳定性：不通过。** 同一输入重跑，6/10 条款数量变化，`9.3.2` 扩容 2 倍，不能称为稳定提示词。

**建议下一步：不扩写 v5.2，按第七节实现 5 个校验器；先离线跑 15 条，再重跑 10 条两轮。校验器通过后再考虑写库。**
