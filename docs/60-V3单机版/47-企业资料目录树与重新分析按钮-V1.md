## 二、页面设计

### 2.1 左侧

```text

```

### 2.2 右侧顶部工具栏

```text
[搜索文件名/文件夹] [只看需处理] [处理进度] [刷新] [重新分析] [上传文件]
```

「重新分析」建议做成**主按钮 + 下拉**：

```text
重新分析
  ├─ 重新画像（只更新文档类型/章节/部门/过程）
  ├─ 重新画像 + 提取（推荐）
  ├─ 仅重新提取（沿用现有画像）
  └─ 仅重新分析选中文件
```

默认全量：`重新画像 + 提取`。  
如果当前有选中文件，默认只处理选中文件。

### 2.3 右侧文件表

## 三、「重新分析」按钮行为

### 3.1 三种模式

| 模式 | 做什么 | 何时用 |
|---|---|---|
| `profile` | 只重跑 `doc_profile`，更新 `DocProfileJson` | 改了画像规则，不想重跑事实 |
| `extract` | 沿用现有画像，只重跑提取 | 画像已稳定，换了提取提示词 |
| `full` | 先画像，再按 `ExtractionMode` 提取 | 默认，推荐 |

### 3.2 范围

- 未选中文件 → 整家企业（默认）；
- 选中文件/文件夹 → 只处理选中范围；
- 提供“只处理失败/未提取/过期”的快捷选项。

### 3.3 异步与进度

- 按钮点击后不阻塞页面；
- 返回 `BatchCode`；
- 顶部显示 `分析中 x/y`；
- 失败文件单独列，可重试；
- 完成后刷新树和文件表。

### 3.4 防重复

- 同一 `BatchCode` 不允许并发生成；
- 同一 `FileCode` 正在 `running` 时，再次点击只提示“正在分析”；
- 已 `done` 的文件可强制执行 `full`，但需 `Force=true`。

## 四、接口设计

## 五、后端流程

```text
点击「重新分析」
  → 校验企业/计划
  → 查 cert_enterprise_doc（IsDeleted=0）
  → 过滤：未转换/转换失败 → 先转换
  → 按 FileCodes 入队
  → 每份文档：
       1) 有 MarkdownPath？没有则转换
       2) 跑 doc_profile（mode=profile/full）
       3) 按 ExtractionMode 路由：
            clause_full → 按条款小节提取
            process_profile → 过程画像
            record_profile → 记录画像
            index_only → 索引
            audit_profile → 审核/评审画像
       4) 写 cert_document_extraction
       5) 更新 ExtractStatus/ExtractTime/PromptVersion
```

关键：**复用 `MarkdownPath`，不重新上传、不重新 OCR/转换**；只有缺 Markdown 时才补转换。

## 七、去重与重复副本

当前根目录有一份 `01管理手册QMS.doc`，`01-手册` 下也有一份；`(1)` 副本也存在。

规则：

1. 上传时按 `EnterpriseCode + Sha256` 判重；
2. 同 hash → `IsDuplicate=1`，`DuplicateOf=已有 FileCode`；
3. `IsDuplicate` 文档默认不参与提取/召回；
4. 页面上标“重复副本”，提供“删除/保留”操作；
5. 不物理删除，软删可回滚。

需要确认 `cert_enterprise_doc` 是否有 `Sha256` 列；现有代码用到 `row.Sha256`，应有。

## 十、结论

1. **“重新分析”按钮比重新上传更合适**：复用已有 PDF/Markdown，可重复、可回滚、成本低。
2. **目录树不用新造**：`RelFolderPath` 已有 24 个文件夹，现有 `buildFileTree` 可直接复用。
3. **按钮要分三种模式**：只画像 / 只提取 / 画像+提取；默认全量，支持选中和失败重试。
4. **要区分首次提取和重新分析**：首次用「开始提取」，后续用「重新分析」。
5. **必须做重复副本标记**：根目录手册与 `01-手册` 手册重复，`(1)` 副本也要去重。
6. 因为用户正在改企业资料页面，前端改动先不动；先按本文接口/字段/交互契约对齐，页面改完再接。
