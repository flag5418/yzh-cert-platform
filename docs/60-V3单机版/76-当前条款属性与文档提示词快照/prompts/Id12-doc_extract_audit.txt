## 通用属性补充（本提示词也必须遵守）

1. **输出顺序**：先通用属性（DocType、DocTitle、StandardRelevant、Extractable、ClauseEligible、ExtractReason、ProcessArea、DocSections、Chapters、OwnerDept、SupportDepts），再 DocUse/ReportRole/ReportDepth/ReportSummary/ReportUse，最后才是类型专属字段。
2. **Extractable 只表示本类型专属事实是否可提取**：false 时仍必须输出 DocType、DocTitle、StandardRelevant、ProcessArea、DocSections、Chapters、OwnerDept、SupportDepts、Metadata、ReportSummary、ReportUse、Warnings；类型专属数组给空。它**不等于**“条款能不能提取”。
3. **ClauseEligible 非手册一律 false**：本提示词不输出条款事实；条款提取只由手册 clause_full 负责。非手册文档即使有条款号，也只用于 PrimaryClauses/SupportClauses 定位。
4. **文档章节与标准条款严格分开**：
   - `DocSections` 只写文档自身章节/小节，逐字抄画像 `Toc` 或正文标题，如 ["1 目的","4 工作流程","5 作业内容"]；没有章节给 []。
   - `Chapters` 只写标准父章节（如 ["4","8.5"]），不写叶子；`PrimaryClauses`/`SupportClauses` 只写标准叶子条款。
   - ⛔ 文档正文里的 4.1、5.1、5.2 等编号只是文档章节号，**不得因为编号相同就直接当成标准条款**；必须按标准条款标题和正文含义判断，语义不一致时只放进 `DocSections`。
   - `KeyControls[].DocSection` / `Records[].DocSection` 写该事实在文档中的真实小节号，找不到给空串；`Clause`/`PrimaryClauses` 仍然只写标准条款号。
5. **Metadata 只取原文**：DocCode / DocVersion / EffectiveDate / IssuedBy / ApprovedBy 取自封面、页眉、修订栏、审批栏；原文没有给空字符串，不许编造。
6. **CoveragePeriod 只给记录/台账/证书/审核/清单**：Start/End 写原文覆盖期；程序、指导书、制度等不适用时给空字符串，不许把发布日期当覆盖期。
7. **Warnings 是结构化数组**：元素形如 {"Code":"missing_metadata","Message":"未识别到文件编号"}；没有问题时给 []。Code 只用 missing_owner_dept / missing_metadata / ambiguous_type / multi_chapter / blank_form / other。
8. **ReportSummary 只写一句、≤60 个汉字**：说明这份文件规定/记录了什么、谁执行/谁记录；不写符合性、不写建议、不写“已实施”。
9. **不判断符合性**：不写符合/不符合/充分/缺失/满足要求/需改进；只回答“这份文档是什么、有什么”。
10. **ProcessArea 只能是以下八类之一**：GM/MR、行政人事、销售过程、采购过程、生产过程、检验过程、仓储/设备、未标注；不得自造“不合格品控制”“文件控制”等新值。不合格品处置按发生环节归入生产过程或检验过程；判不出给“未标注”。

## 硬规则
1. 角色固定 `DocUse=audit_record`、`ReportRole=audit_evidence`、`ReportDepth=verbatim`；不得写成过程画像或记录抽样。
2. `AuditType` 只能是 internal_audit / management_review；`PrimaryClauses` 对应 9.2 或 9.3.1，`SupportClauses` 留空。
3. `Findings` 只写原文审核记录/评审记录中的事实陈述；不得改写为“企业已实施”。
4. `RecordMark` 只抄原文判定栏；没有写空字符串；不得把 OK/NG 当成系统结论。
5. 不输出 `Conclusion`、符合、不符合、充分、缺失、需改进项、一般不符合、建议；`RecordConclusions` 只抄原文结论，不做二次判断。
6. 管理评审中的“存在的主要问题”可以放 Findings，但只抄原文，不得自行分类为“需改进项”。
7. `Scope` 只写原文列出的受审部门/范围；`SupportDepts` 从 Scope 中取真实部门，最多 6 个。
8. 不编造人名、日期、结论；没有就留空数组或空字符串。
9. 不输出 `ReportPresence`；`ReportUse` 固定写“作为内审/管理评审二线证据；是否被报告引用由后续报告索引判定”。
10. 只输出 JSON：第一个字符必须是 {，最后一个字符必须是 }。
