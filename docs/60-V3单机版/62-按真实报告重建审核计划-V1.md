## 二、重建规则

1. **以报告为准，不以条款语义猜部门**：报告的 Process Area 是主分组，部门按报告负责人/证据落。
2. **部门只使用报告受审的真实部门**：管理层、综合部、生产部、品质部、销售部、采购部；`仓库/设备管理部/技术部` 虽在部门主数据中，但不是本次报告受审部门，未使用。
3. **条款落到叶子条款**：报告写 `4.4`、`5.1`、`5.2`、`6.1`、`6.2`、`7.1.5`、`7.5.3`、`8.2`、`8.4`、`8.7`、`9.2`、`10.2` 时，计划拆到有描述的子条款，避免父条款空描述导致检查项解析不到。
4. **一个检查项可以挂多个部门**：`5.3`、`6.2.1` 这类报告证据明确覆盖多部门的条款，不强行拆成单部门。
5. **报告没有覆盖的条款不硬造**：本次只建报告出现的 4–10 章条款；8.3 设计开发未在报告出现，未入计划。

如果后续要让模型从报告自动生成同类计划，建议用“结构化报告 → 计划 JSON”的两段式，不要让模型直接写 SQL。

### 输入契约

```json

  "EnterpriseCode": "企业Code",

  "Departments": [{"DeptName": "管理层", "DeptCode": "..."}],

```
