# 三者关系模型：条款属性池 · 文档结构 · 证据提示词（环形）

> 这份文档只回答一个问题：三个东西各自是什么、谁调用谁的哪个属性、闭环怎么转。不写实现。

---

## 一、先把三个东西的"问句"分开

这是整个模型能自圆其说的前提：**三者各回答一个不同的问题，问句不重叠，就不需要互相猜测。**

| 层 | 它回答的问题 | 它不知道什么（边界） | 产物形态 |
|---|---|---|---|
| **L1 条款属性池** | 这条**要求什么**、严到什么程度、该往哪找 | 不知道企业有什么资料、不知道句子怎么写 | 结构化属性（键值） |
| **L2 文档结构** | 这份资料**是什么**、里面有哪些**事实** | 不知道条款、不知道报告句式 | 画像 + 事实条目 |
| **L3 证据提示词** | 怎么用这些事实**回答这条要求** | 不生产事实、不定义要求 | 一段建议稿 |

三者只有 L3 同时看得到 L1 和 L2。**L1 与 L2 之间不直接对话**——它们唯一的接触点是"条款相关"这一个标记。这是刻意的：一旦让属性池去猜文档、让文档去猜条款，两边都会开始编。

## 二、环形关系图

**图见 `三者关系图-属性池·文档结构·证据提示词-V1.png`（同目录，另有可编辑 `.html`）。文字版如下：**

```
                 ┌──────────────── 回归校准（指标 → 版本）────────────────┐
                 │                                                      │
                 ▼                                                      │
      ┌──────────────────┐   ①约束：覆盖点/句式/定位   ┌──────────────────┐
      │ L1 条款属性池     │ ─────────────────────────▶ │ L3 证据提示词     │
      │ 要求什么          │                            │ 怎么回答          │
      │                  │ ◀───────────────────────── │                  │
      └──────────────────┘   ④反馈：哪些属性没被用      └──────────────────┘
              │  ▲                    （该删/该补）              │  ▲
   ②检索键   │  │ ⑤反查：哪些槽位                           ③供给 │  │ ⑥反馈：
 条款×过程域  │  │  缺事实（该补提取）                    事实条目 │  │ 该补字段
              ▼  │                                              ▼  │
      ┌──────────────────┐                                     │
      │ L2 文档结构       │ ────────────────────────────────────┘
      │ 资料里有什么事实   │
      └──────────────────┘
```

四条正向、两条反向，共六条边。**每条边只传一种东西**，传两种就会糊：

| 边 | 从 → 到 | 传什么 | 不传什么 |
|---|---|---|---|
| ① 约束 | L1 → L3 | 必覆盖点、义务强度、证据形态（定句式）、过程域（定取数范围） | 不传原文长句、不传文档名 |
| ② 检索键 | L1 → L2 | 只传"条款 × 过程域" | 不传句式、不传严重度 |
| ③ 供给 | L2 → L3 | 事实条目（谁/做了什么/何时/多少/结论） | 不传"该写什么结论" |
| ④ 反馈 | L3 → L1 | 某属性被消费次数 = 0 → 删；某槽位填不满 → 补属性 | 不传风格偏好 |
| ⑤ 反查 | L3 → L2 | 缺哪些槽位的事实 → 补提取模式/字段 | 不传条款原文 |
| ⑥ 回归 | 报告样本 → L1/L3 | 覆盖率、溯源率、长度、结论率四项指标 → 版本号 | 不直接改内容 |

## 三、属性怎么被调用（逐条对照）

这是"相互属性如何调用"的具体答案：**L3 的每一段提示词，只消费下表中列出的属性；表外的一律不读。**

### 3.1 L1 → L3（条款属性被谁吃）

| L1 属性 | L3 里的用处 | 消费位置 |
|---|---|---|
| `ClauseIntent` 意图 | 决定这一段"要证明的那件事" | 任务说明第一句 |
| `Obligation` 义务强度（应/宜/可） | 决定结论句强度：应→"符合"；宜→"建议"；可→"可考虑" | 结论句模板 |
| `Applicability` / `ApplicabilityCondition` | 不适用时直接输出"不适用，理由…"，不生成证据 | 前置判断 |
| `Process` 过程域 | 决定去哪些部门/哪些文档里找 | 取数范围 |
| `EvidenceForm` 证据形态（A–F） | 决定句式族与篇幅（手册类原文引用、记录类抽样、结论类判定） | 句式选择 |
| `Role` 功能角色（R1–R7） | 决定结构骨架（先写什么后写什么） | 骨架选择 |
| `Severity` 严重度 | 只在"不符合"分支用，符合段不用 | 不符合分支 |
| `AuditQuestion` 待答问题 | 作为"这一段必须回答的几个问句"清单 | 骨架的槽位清单 |

> `MergeMode` 不进这张表——它属于计划层，不属于提示词层的输入。

### 3.2 L2 → L3（文档事实被谁吃）

| L2 属性 | 用处 | 消费位置 |
|---|---|---|
| `clause_related` | **闸门**：false 直接不进候选池 | 候选集过滤 |
| `extract_need` | false 则只用画像（文件名/用途），不读正文 | 取数深度 |
| `doc_category`（手册/程序/指导书/记录/资质/报告） | 决定该文档提供"骨架事实"还是"抽样事实" | 槽位匹配 |
| `process_domains` | 与 L1 的 `Process` 求交，命中才入候选 | 检索键 |
| 事实条目（`who/what/when/where/how_many/conclusion/source`） | 填进骨架的槽位 | 填充 |
| `confidence` + `source`（页码/锚点） | 低于阈值则标注"待核"，并保留溯源 | 溯源标注 |

### 3.3 谁都不读的（故意留白）

- 条款原文长句：只在"引用型"句式里按需取一小截，不进属性；
- 文档全文：只在 L2 提取时读，L3 只见事实条目；
- 机构风格：只属于 L3 的风格包，不进 L1/L2。

## 四、角色拆成两条轴：写什么结构 · 怎么找证据

你说得对，一个"角色"实际是两件事，必须分开定义：

- **轴 A｜写作结构**：这一段由哪几个槽位组成、什么顺序、必须出现哪几类要素；
- **轴 B｜取数路径**：这类内容通常存在于哪几类文档、用什么键去捞、捞不到时的降级路径。

两者组合才是"角色"。同一角色在不同企业，轴 A 不变、轴 B 变（资料齐不齐）。

| 角色 | 轴 A：写作结构（槽位顺序） | 轴 B：取数路径（先→后→降级） | 是否需要现场 |
|---|---|---|---|
| **R1 情境与范围** | 企业概况 → 认证范围 → 场所/人数 → 与备案一致性 → 结论 | 营业执照/备案凭证 → 手册范围章 → 场所清单 → **降级**：访谈确认 | 轻微（场所查看） |
| **R2 领导与承诺** | 方针 → 职责任命 → 目标 → 资源承诺 → 结论 | 手册方针页 → 任命书/组织结构 → 目标分解表 → **降级**：管评记录反推 | 访谈为主 |
| **R3 策划** | 风险/因素/危险源清单 → 评价方法 → 措施 → 目标 → 评价结论 | 程序文件 → 风险清单/环境因素清单 → 目标表 → **降级**：内审发现反推 | 否 |
| **R4 支持/资源** | 岗位与能力要求 → 培训/资质 → 设施设备 → 校准/维护 → 抽样结论 | 岗位说明书 → 培训记录/证书 → 设备台账 → 校准证书 → **降级**：现场查看设备铭牌 | 是（设备/现场） |
| **R5 运行/实现** | 合同/订单 → 策划（工艺/作业指导） → 过程参数 → 检验/放行 → 抽样结论 | 合同 → 作业指导书 → 生产记录 → 检验记录 → 放行单 → **降级**：现场观察 + 访谈 | 是（核心） |
| **R6 绩效评价** | 内审方案 → 内审发现 → 管评输入输出 → 合规性评价 → 结论 | 内审报告 → 管评报告 → 合规性评价记录 → 目标统计 → **降级**：无 | 否 |
| **R7 改进** | 不合格事实 → 原因分析 → 措施 → 验证 → 关闭结论 | 不合格台账 → 纠正措施单 → 验证记录 → **降级**：内审不符合项 | 否（验证可现场） |

**读法**：轴 A 决定"提示词骨架"，全机构通用；轴 B 决定"这一段的候选文档从哪来"，随企业与机构变。L3 提示词 = 轴 A 骨架 + 轴 B 的取数结果（事实条目）。

## 五、案例验证：槽位填充率说明结构是真的

用三份报告 101 个条款块，按角色统计"槽位出现率"：

| 角色 | 块 | 文件引用《》 | 日期 | 数量 | 结论词 | 抽样动词 | 职责点名 |
|---|---:|---:|---:|---:|---:|---:|---:|
| R1 | 13 | 54% | 38% | 8% | 77% | 15% | 23% |
| R2 | 13 | 31% | 38% | 0% | 62% | 23% | 46% |
| R3 | 6 | 67% | 67% | 33% | 83% | 17% | 17% |
| R4 | 19 | 63% | 47% | 16% | 84% | **63%** | 26% |
| R5 | 23 | 74% | **13%** | 26% | 57% | 35% | 17% |
| R6 | 22 | **86%** | 41% | 14% | 86% | 23% | 45% |
| R7 | 5 | 40% | 40% | 0% | 80% | 40% | 40% |

四条可用结论：

1. **每个角色的槽位分布都不一样**，说明"角色"确实是有效分类，不是硬套章节。
2. **R4 抽样动词最高（63%）**——资源类靠抽样，提示词必须给"抽几份、抽什么字段"的指令。
3. **R6 文件引用最高（86%）**——绩效评价几乎句句挂文件名（内审报告、管评报告），提示词必须强制"引用出处"。
4. **R5 日期覆盖率只有 13%**——不是报告不写日期，而是运行类段落用"记录编号/批次"代替日期。这说明 R5 的必填槽是"记录标识"而不是"日期"，**按日期去校验 R5 会误判**。

这三条直接落成 L3 的"每角色必填槽位表"，也落成质量校验规则（校验项按角色不同，不能全局一刀切）。

## 六、闭环怎么转（一次完整循环）

```
企业上传资料
   → L2 画像（clause_related / extract_need / category / process_domains）
   → L2 提取（按模式：手册 7 处 / 元数据 / 条目 / 字段 / 结论 / 不提取）
审核计划（条款 × 部门 × 审核员）
   → 证据单元 = 条款 × 过程域
   → L1 读该条款属性（+ 按标准口径卡）
   → ②检索键：用 Process ∩ process_domains 取事实条目
   → ①约束：Role 定骨架、EvidenceForm 定句式、Obligation 定结论强度
   → L3 生成建议稿（含溯源锚点）
审核员编辑 / 锁定
   → ④某属性长期 0 消费 → 删属性
   → ⑤某槽位长期无事实 → 补提取字段或补文档类型
   → ⑥四项指标回归 → 提示词升版
```

**这套环之所以能转，是因为三层各自可独立重跑**：换标准只重跑 L1，换企业只重跑 L2，换机构只重跑 L3 的机构包。任何一层改了，另外两层不受牵连。

## 七、三个连接键（唯一允许的耦合点）

| 键 | 定义 | 用在哪 | 错了会怎样 |
|---|---|---|---|
| **K1 证据单元 = 条款 × 过程域** | 一个检查项对应一个证据单元 | L1↔L2 检索、L3 输出粒度 | 用"条款"单键 → 一个条款跨 4 个部门只能出一段，部门差异被抹平 |
| **K2 事实槽位 = 事实条目字段 × 骨架槽位** | 字段名必须一一对上（who↔责任主体…） | L2→L3 填充 | 字段名不对 → 填充率为 0 且**不报错**，只表现为"段落很空" |
| **K3 角色 × 形态 = 模板编号** | 如 `R5-D`（运行-记录型） | L3 模板选择 | 用章号代替角色 → 换标准全废（13485 章号错位） |

## 八、这套模型怎么算"自圆其说"（三条自检）

1. **问句不重叠**：L1 只答"要求什么"，L2 只答"有什么事实"，L3 只答"怎么答"。任何一层越界都算模型错误。
2. **属性可被追踪**：每个属性必须能在 L3 找到消费点，找不到就删；每个槽位必须能追到 L2 的字段，追不到就补。这是 ④⑤ 两条边存在的原因。
3. **案例可回放**：拿任一真实条款块，能反推出"用了哪个角色、哪个形态、哪些事实条目、哪条属性"。101 个块里目前能回放约 78%（22% 缺溯源，主要因双尼列切分缺陷）。
