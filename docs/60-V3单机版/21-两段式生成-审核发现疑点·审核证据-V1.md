# 两段式生成：审核发现·疑点（平台）→ 审核证据（机构）V1

> **V1.1 修订（2026-11-10）**：① 疑点拆成「文档级 / 检查项级」两个产生点（文档结构化时就判自身缺陷）；② 第 3 类提示词按**检查项**调用、按**条款**落段；③ 术语暂不定名，先实现逻辑，命名等专家朋友试用后再定。

> 这是对 14 号「三类提示词」的一次修订。改成两段式后，提示词实际是 **4 类**，但换来三件事：换机构不用重跑、可以做预 NC、发现与疑点对企业端也能用。

---

## 一、为什么必须拆成两段

| 问题 | 一段式（发现+证据一次出） | 两段式 |
|---|---|---|
| 换机构 | 全部重跑 | 只重跑第 2 段 |
| 判定与事实 | 混在一段文字里，看不出哪句是事实、哪句是推论 | 第 1 段只出事实与疑点，不含判定 |
| 预 NC | 做不了（结论藏在文字里） | 第 1 段的疑点直接就是预 NC 候选 |
| 企业自查 | 用不了（报告语体是给审核员的） | 第 1 段的发现/疑点可原样给企业看 |

一句话：**发现与疑点跟机构无关，证据才跟机构有关**。混在一起等于把平台级资产和机构级资产绑死。

---

## 二、提示词从 3 类变 4 类

| # | 提示词 | 层级 | 输入 | 输出 | 跑几次 |
|---|---|---|---|---|---|
| 1 | 条款属性 | 平台 | 条款原文 | 11 属性 | 每条款 1 次，一次建好 |
| 2 | 文档内容 | 平台 | 文档 MD × 标准 | 类型/过程/提取事实 | 每文档×标准 1 次 |
| 3 | **审核发现 + 疑点** | **平台**（按章节规则） | 条款 + 该条款文档发现 + 要求物清单 | 发现[] + 疑点[]（含出处） | 每检查项 1 次 |
| 4 | 审核证据 | **机构** | 第 3 段结果 + 挂接证据 + 机构方案 | 报告段落文字（不含判定） | 每条款段 1 次 |

第 3 类的产物是**可直接复核的结构**，第 4 类只做"把结构写成话"。这样机构方案（ACM 的口吻、篇幅、句式）永远碰不到事实层。

---

## 三、疑点有两个产生点，不能合成一处

| 产生点 | 时机 | 判据 | 例子 | 落在哪 |
|---|---|---|---|---|
| **文档级** `DocDoubt` | 文档结构化时（每文档×标准） | 只看这一份文档 + 它对应的条款 | 检验报告日期 2024-11（超 12 个月）、结论栏空白、无签字盖章、报告编号跳号、校准证书过期 | 文档画像 |
| **检查项级** `ClauseDoubt` | 第 3 类执行时（每检查项） | 条款要求物 vs 全企业已提取事实的差集 | 8.4 要求供方评价记录，全企业 0 条；6.1.3 要求法规清单，未见该文件 | 检查项 |

**为什么要分两处（你第 4 点成立）：**

- 结构化时**已经知道这份文档对应哪些条款**，所以"这份报告过期没有、结论空不空"当场就能判，不必等检查项跑；
- 这类缺陷是**单文档可判**的，与"企业整体缺某类记录"不是一回事；
- 早判的价值：文档一上传就出问题清单，企业能立刻补，不用拖到入场前。

检查项级则必须等文档都分析完才能做差集——这是它只能后置的原因。

**文档级疑点的判据（可规则化，不用模型）：**

| 判据 | 检查方式 |
|---|---|
| 日期过期 | 抽取日期，与审核基准日比（可配阈值，如 12 个月） |
| 关键字段空 | 结论/结果/数量/签名栏为空 |
| 缺签批 | 应有签字/盖章的位置为空 |
| 编号跳号 | 记录编号不连续 |
| 数量不足 | 条款要求抽 3 份，该文档只提供 1 份 |

这五条都是"看这一份文档就能判"，所以放在结构化里最省。

## 三之二、第 1 段的输出结构（检查项调用、条款落段）

一次调用单位 = **检查项**；产物 = 该检查项下**逐个条款**的段落结构（条款号来自检查项的 `Clauses`）：

```
FindingSet（检查项 X）
├─ 条款 8.4
│   ├─ 发现[]：{ 事实, 出处(文档/页码/原文≤100字), 过程, 置信度 }
│   ├─ 疑点[]：{ 类型, 文本, 来源(doc|clause), 依据, 状态=待核查 }
│   └─ 覆盖：要求物 3 项 / 找到 2 项 / 缺 1 项
└─ 条款 8.4.1 …（同结构）
```

**只有事实，没有形容词。** 不许出现"良好""有效""基本符合"——那是第 4 类的事。

疑点带 `来源`，因为两种疑点的处置不同：文档级的（如某份报告过期）补一份即可；检查项级的（如根本没记录）要补一类。

## 四、疑点规则按章节分册（你第 1 点）

通用三类（有过程无记录 / 缺文件 / 记录不完整）打底，再按角色挂章节专属规则：

| 角色 | 章节 | 专属疑点规则（示例） |
|---|---|---|
| R1 情境 | 4.1–4.3 | 内外部环境识别表是否存在、是否近 12 个月评审；相关方清单是否含气候变化要求 |
| R2 领导 | 5.1–5.3 | 方针是否签发、是否覆盖三标准；职责权限是否文件化；管理者代表是否指定 |
| R3 策划 | 6.1–6.3 | 风险/机遇清单是否与部门对应；目标是否分解到部门且有测量方法；变更是否留记录 |
| R4 支持 | 7.1–7.5 | 人员能力矩阵、培训记录、设备校准证书有效期、文件清单与发放记录、知识清单 |
| R5 运行 | 8.x | 各过程记录连续性与完整性；外包/供方评价；标识与追溯；放行记录 |
| R6 绩效 | 9.x | 监测数据是否按月/季；内审覆盖是否全条款全部门；管评输入输出是否齐全 |
| R7 改进 | 10.x | 不合格是否闭环（原因/措施/验证）；纠正措施是否横向展开 |

规则写成**规则条目**（可增删），不是写进提示词正文——这样加一条规则不用改提示词。

## 五、第 2 段：审核证据（机构方案）

输入四样（18 号已定）：第 1 段的发现与疑点、挂接的现场证据、条款属性/原文、机构风格方案。

输出的硬约束：

- **不写判定**。段末"符合 GB/T X 第 X.X 条"由检查项结论渲染。
- 疑点为"待核查"时，语气降档（"未见异常记录"而不是"经查符合"）。
- 疑点"已核实"→ 走不符合分支；"已排除"→ 补一句"经查已提供"。
- 篇幅与句式由机构方案定（ACM 一版，别家另开一版）。

## 六、三阶段数据流与重跑边界

```
① 文档分析（每文档×标准）      → 事实条目（缓存，文档不变就不重跑）
② 发现+疑点（每检查项）        → FindingSet（条款+文档不变就不重跑）
③ 审核证据（每条款段）          → 段落文字（机构方案或挂接证据变了就重跑）
```

重跑判定只看上游有没有变：

| 变更 | 要重跑 |
|---|---|
| 新增/替换文档 | ① → ② → ③（文档级疑点随 ① 重算） |
| 改条款属性 | ② → ③ |
| 换机构方案 | **只 ③** |
| 审核员挂接现场证据 | **只 ③** |
| 改检查项结论 | 无需重跑（判定是渲染出来的） |

这条边界是这次拆分最实际的收益：**换机构、补现场证据这两种最高频动作，都只碰最后一段。**

## 七、产品意义：从"写报告"变成"预检查"

第 1 段的产物不依赖报告语体，所以可以直接给两类人用：

| 使用者 | 拿到什么 | 价值 |
|---|---|---|
| 审核员 | 发现 + 疑点 + 预 NC 候选 | 入场前知道该查什么，入场后少漏项 |
| 企业 | 发现 + 疑点（去掉审核口吻） | 自查整改清单，认证前就能补 |

预 NC 不是"判不合格"，而是"这 3 个条款的资料里有缺口，可能构成不符合"。**判定权仍在人手里**，但企业能提前看到，这比事后开 NC 有用得多。

也正因为这一点，这个工具的定位从"审核报告助手"扩到"预检查 + 报告"，对企业端和审核员端都能落地——而两端的共同底座就是平台级的第 1 段。

## 八、已确认 / 待定

**已确认：**

1. 疑点规则维护界面放后台管理端，不暴露专家端。
2. 第 3 类按**检查项**调用，按**条款**落段（一次出多段）。
3. 术语暂不定名：逻辑先落地，中文标签留配置，等专家朋友试用后给建议。代码里先用中性英文（`Finding` / `Doubt` / `EvidenceText`），界面文案后改。

**待定：**

1. 「编号跳号」「数量不足」这两条要读整本记录，是否一期就做？还是先只做「过期 / 字段空 / 缺签批」三条？
2. 文档级疑点的日期阈值（12 个月）是全平台一个值，还是按记录类型分（培训记录 12 个月、校准证书 12 个月、内审 12 个月）？
3. 企业端先看到文档级疑点（早），检查项级疑点要不要也开放给企业？
