# 属性池收敛与证据两段提示词定位 V1

> 依据 2026-11-10 的三点裁决：①`Artifacts`/`EvidenceChain` 不属于属性池；②审核证据要拆成「分析提示词 + 编写提示词」两段；③属性配置页要能勾选标准/条款批量重跑并逐条查看编辑。
> 上一版（11 属性，见 `24-属性池A2A3实施记录与样例校准-V1.md`）已被本文收敛为 **9 属性**。

## 一、属性池最终 9 条（只留可量化/可参数化的）

| # | Code | 名称 | 类型 | 值从哪来 | 消费方 |
|--:|---|---|---|---|---|
| 1 | `ClauseIntent` | 条款作用 | text | 条款原文 | ③分析（判断事实够不够回答要求）、④编写（段首定调） |
| 2 | `Obligation` | 约束强度 | dict shall/should/may/note | 原文情态动词 | ④编写（"应/宜/可"措辞与判定尺度） |
| 3 | `Applicability` | 适用性 | dict general/conditional | 原文限定语 | ②文档（过滤该条款要不要查企业） |
| 4 | `ApplicabilityCondition` | 适用条件 | text | 原文限定语 | ③分析（不适用时不判缺失） |
| 5 | `Process` | 过程域 | json | 条款语义 | ②文档（文档→条款的检索方向）、③分析（按过程取事实） |
| 6 | `Severity` | 严重度 | dict critical/major/minor | 后果判断 | ③分析（疑点定级）、④编写（措辞强度） |
| 7 | `EvidenceForm` | 取证形态 | dict cite/sample/site/interview | 动作词 | ④编写（**决定句式**：引用式/抽样式/现场式/访谈式） |
| 8 | `EvidenceFamily` | 条款族 | dict f1/f2/f1f2 | 动作词（⛔ 不按章号） | ④编写（引用 or 抽样 or 两者） |
| 9 | `Role` | 功能角色 | dict r1–r7 | 功能（⛔ 不按章号） | ④编写（**决定骨架**：这一段按什么顺序说事） |

**移出的两条**（`IsValid=0`，历史保留）：

| 移出项 | 新归属 | 理由 |
|---|---|---|
| `Artifacts`（企业应提供哪些资料） | ③分析提示词 | 是"从企业资料里认出什么"，随企业事实变，不是条款的固有属性 |
| `EvidenceChain`（审核员怎么取证） | ③分析提示词 | 取证剧本属审核策略，同一机构不同审核员写法不同 |

> 一句话记法：**属性池回答"这条款要什么"，不回答"去哪找、怎么问"。** 后者属提示词。

## 二、页面改造（`/cert/clause-attr`）

### 2.1 布局（2026-11-10 二次调整后）

```
┌ 顶部操作栏 ────────────────────────────────┐
│ 条款属性配置            [编辑提示词] [AI 预生成] │   ← 两个入口同一行、居右
├ 条款详情（编号 / 标题 / 路径 / 已采用 N 项）──┤
├ 条款原文 ──────────────────────────────────┤
├ 条款属性 ────────────────────── [＋添加属性] ┤
│  名称 [Code] 类型 ················  [移除]  │   ← 只列"已采用"，无 checkbox、无"启用"
│  └ 值编辑器（按属性类型自动切换控件）        │
│                                            │
├ 保存条（sticky 置底）───────────────────────┤
│ 3 项待保存              [撤销修改] [保存]   │
└────────────────────────────────────────────┘
```

**为什么去掉 checkbox / 启用**：

| 原设计 | 问题 | 现设计 |
|---|---|---|
| 池内 9 条全列出 + 勾选框 | 未采用的属性也占一整块，屏幕全是不相干内容；"勾选"和"填值"两种采用方式并存，语义重叠 | 只列已采用的；用「＋添加属性」从池里挑；行内「移除」 |
| 每行一个「启用」开关 | 与 `IsValid` 重复，用户不知道什么时候该关；关了也不删，列表依旧占位 | 删掉；不要这条就「移除并保存」 |
| 值来源（固定/参考）下拉 | 9 条全部 `fixed`（`Artifacts`/`EvidenceChain` 移出后已无 reference），控件纯噪音 | 删掉；新增行一律 `fixed` |
| 撤销/保存在属性标题行右侧 | 属性多时按钮被滚出屏幕，改完找不到保存 | sticky 置底保存条 |

### 2.2 批量生成：50 条不是给用户看的

服务端单请求硬上限 50 条（防一次跑太久触发网关超时），但**前端自动按 50 切片连续执行**：

```
用户选 60 条  →  第 1 批 50 条 → 返回 → 第 2 批 10 条 → 合并结果
```

| 能力 | 说明 |
|---|---|
| 范围 | **不选 = 跑该标准全部叶子条款**（9001 60 / 13485 70）；选了 = 只跑所选 ⇒ 「条数」输入框已删除（冗余） |
| 全选 | 一键选中整标准，自动分批跑完 |
| 只跑当前条款 | 弹窗内快捷按钮（等价于在工作台重跑这一条） |
| 进度 | `已 50 / 60 条 · 42s`，不再只显示"生成中…" |
| 停止 | 点停止 = 当前批跑完即停，**已写入的属性全部保留**（批次之间独立事务） |
| 失败隔离 | 单条失败只标红该行，「查看」可跳回该条款手改 |
| 结果表 | 固定高度 320px，**表内滚动**（原来会顶出弹窗） |

## 三、证据要两段（这是本轮最重要的结构裁决）

```
条款属性（9 条）
      │
      ├──► ③ 分析提示词  ── 产出「证据发现（事实+出处）+ 疑点」   ← 平台，不随机构变
      │        ↑ 输入：条款属性 + 企业文档事实
      │
      └──► ④ 编写提示词  ── 产出「审核证据」段落                ← 机构方案（ACM 一套）
               ↑ 输入：③的发现 + 审核员现场证据 + 条款属性
```

| 段 | 只做什么 | 不做什么 |
|---|---|---|
| ③ 分析 | 把事实对齐到条款要求；标出"有过程无记录/缺文件/记录不完整"；带 `DocId+页码` 出处 | 不写形容词、不写"符合"、不排段 |
| ④ 编写 | 把③的发现按 `Role` 骨架 + `EvidenceForm` 句式写成报告语体 | 不重新判事实、不改结论、不补没出处的内容 |

**为什么这么拆**：换机构只重跑④；补现场证据只重跑④；③可复用于企业自查；④的口吻才需要按机构调。

### `Role` → 段落骨架（④ 的场景格式，先按 ACM 归纳）

| 角色 | 条款例子（9001） | 骨架顺序 | 主形态 |
|---|---|---|---|
| r1 情境 | 4.1 / 4.2 / 4.3 | 组织与相关方描述 → 引用了哪份文件 → 范围界定结论 | cite |
| r2 领导 | 5.1 / 5.2 / 5.3 | 方针原文要点 → 职责与权限文件 → 最高管理者/管代访谈确认 | cite + interview |
| r3 策划 | 6.1 / 6.2 / 6.3 | 识别/评价结果 → 措施与责任 → 目标数据 → 有效性 | cite（+ 少量 sample） |
| r4 支持 | 7.1 / 7.2 / 7.3 / 7.5 | 资源配置 → 能力与培训 → 文件受控 → 抽 1–3 份实例 | cite + sample |
| r5 运行 | 8.1–8.7 | 流程与准则 → 抽 3 份记录（逐份写要素）→ 放行/交付结果 | sample 为主 |
| r6 绩效 | 9.1 / 9.2 / 9.3 | 方案/频次 → 抽 1 次完整闭环 → 数据与结论 | cite + sample |
| r7 改进 | 10.1–10.3 | 不符合项实例 → 原因与措施 → 验证有效性 | sample 2–3 例 |

> 这张表是**骨架**，细节由条款原文灌入（`ClauseIntent` + 原文）填充，所以一套骨架能跨部门用。
