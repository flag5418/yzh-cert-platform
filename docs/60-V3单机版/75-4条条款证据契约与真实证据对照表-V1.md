# 75-4条条款证据契约与真实证据对照表-V1

> 目的：把“契约生成内容”和“真实证据”放在同一张表里，便于直接比较。
> 口径：文件夹事实只写文档里能看见的；报告列只作对账，不作为提取事实；不推 NC。
> 条款原文来自 `cert_iso_clause`（13485，2016）。

---

## 0. 先给结论

这一轮暴露的不是“契约写得太宽”，而是三类更具体的问题：

1. **契约漏了条款里的硬要求**
   - `7.5.1` 漏了 `基础设施鉴定`、`标识和包装`、`制造数量/批准流通数量`、`7.5.9 可追溯性`；
   - `7.4.1` 漏了 `采购信息/采购订单`、`未满足要求的供方处置`；
   - `8.3.2` 漏了 `进货检验/退货/报废`，且 `Coverage=全批次` 过宽；
   - `7.6` 漏了 `设备不符合要求时以往测量结果有效性评估`、`防护/保护`、`软件确认与风险相适应`。

2. **文件夹事实大多是空白模板**
   - `7.5.1`：`PR-025/027/028` 全部 `template_only`；
   - `7.4.1`：`OR-008/010` 已填，`OR-006/007` `template_only`；
   - `8.3.2`：`QR-020/021/022/024/025` 全部 `template_only`；
   - `7.6`：`QR-006` `partial`，`QR-007/041/042` `template_only`。

3. **条款之间引用没有进契约**
   - `4.2.5` 是横向 `evidence_rule`，不是独立检查项；
   - `7.5.1` 引用 `7.5.9`（可追溯性）、`7.6`（设备）、`8.2.6`（放行）、`8.3.2`（不合格）；
   - `7.4.1` 引用 `4.2.4/4.2.5`、`7.4.2/7.4.3`；
   - `8.3.2` 引用 `8.3.1/8.3.3/4.2.5`；
   - `7.6` 引用 `4.2.4/4.2.5`、`7.5.1/8.2.6`。

## 7. 文档提示词轻量化

### 7.1 现在的问题

V2.2 记录提示词 10,183 字节，字段字典很长，按“记录格式”展开。不同咨询公司/企业格式差异大，格式字段越细，越容易失效。

### 7.2 轻模型：只回答 6 个问题

| 问题 | 字段 | 约束 |
|---|---|---|
| 这是什么文档 | `DocClass` | `policy/procedure/work_instruction/record/catalog/report/audit_pack` |
| 它证明什么 | `CoreRole` | 一句话，如“证明生产批记录”“证明供方评价” |
| 关键字段是什么 | `KeyFields` | 最多 8 个，只取能定位事实的字段 |
| 有没有实际填写 | `FillStatus` | `filled/partial/blank/absent/unreadable` |
| 能看到哪些样本 | `SampleRows` | 只放实际行；空就空 |
| 覆盖到什么范围 | `Coverage` | 能看见的才写；空白写 `unknown` |

### 7.3 文档层不做的事

- 不猜 ERP/其他系统有什么；
- 不补批次/日期/数量/人员；
- 不判“缺失/不符合/NC”；
- 不按行业格式穷举字段；
- 不把原文段落整段交给审核员。

### 7.4 条款层要做的事

- `EvidenceItems[]`：角色、名称、期望字段、是否必需、条件；
- `Dependencies[]`：依赖条款、角色、用途；
- `CrossChecks[]`：与哪些条款交叉核对、核对字段；
- `AuditorRules`：给审核员用，不给提取阶段用；
- `FactBoundary`：只定义期望，不判断企业有没有。
