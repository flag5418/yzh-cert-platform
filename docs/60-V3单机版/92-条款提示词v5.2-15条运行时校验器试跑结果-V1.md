但校验器只能“拦”，不能“修”。提示词本身仍然会跑出不同粒度、不同数量的结果；校验器的作用是保证坏结果不进库，不是让 v5.2 变稳定。

## 二、校验器规则与运行命令

```bash
cd /Volumes/Expand/wangqingquan/Documents/work/体系认证平台
python3 scripts/tools/validate_clause_findings.py \
  --results /tmp/clause_findings_9001_final.json /tmp/clause_findings_9001_10.json \
  --docfacts /tmp/doc_facts_9001.json /tmp/doc_facts_9001_2.json \
  --meta /tmp/cert9001_md/meta.json /tmp/cert9001_md2/meta.json \
  --clauses /tmp/clause15.tsv \
  --out /tmp/validation_15.json
```

五类规则：

1. **DocFactValidator**：`template_only` 但表格数据行已有业务值 → 报错；序号空不等于整表空。
2. **QuoteValidator**：`OriginalQuote` 必须 exact 或归一化后连续命中；省略号、空引用、低信息、版权/声明类样板文字 → 报错。
3. **ClauseItemValidator**：`ClauseItemRef` 必须来自条款正文允许的条目；无编号条款必须 `main`；“注”里的 a/b 不得当要求项。
4. **DoubtTypeValidator**：`blank_template`/`missing_signature`/`date_conflict`/`report_only` 必须和关联 finding 的 `FillStatus`/`DocClass` 一致；单日期不得判日期冲突。
5. **AssemblyValidator**：`CanFormEvidence=true` 必须 `Gap` 为空、required doc class 齐全、至少 1 份 `filled` 的 record/report。

## 五、P1 修复清单

### 5.1 ClauseItemRef（16 项）

| 条款 | 问题 | 结论 |

这 16 项全部为真实结构问题，不需要再放宽规则。`ClauseItemRef` 必须来自条款属性池/条款 ToC，不能用模型自己输出的 `ClauseContext.ClauseItems` 反推。

### 5.2 QuoteValidator（21 条 finding）

- 18 条非连续：表格行重排、跨段拼接、表头改写。
- 2 条低信息：`8.2.2 F2/F3` 只引“符合”等短词。
- 1 条样板文字：`8.5.2 F1` 引“著作权声明”。

典型：
- `7.2 F5/F6`、`8.5.4 F2/F3`、`9.1.2 F3`、`9.3.2 F4/F5` 含 `...`/`……`。
- `7.2 F4` 引用的是简化表头，不是原文双语表头。
- `8.5.2 F2/F3/F5`、`7.5.3.2 F1/F3`、`9.1.2 F2` 表格归一后仍无法连续命中。

**处理建议：** P1 不直接丢弃 finding，进入“引用待修复队列”。能自动从原文重新截取就修复；不能修复则标 `quote_unverified`，该 finding 不作为报告原文证据，但仍可用于内部疑点提示。

## 七、误报校准说明

首版 DocFact 规则曾命中 14 份 `template_only`，其中 13 份是空白模板的预印标签被误当业务值。已收窄为“同一行同时出现编号（KSY/QMS/WI-）和时间/期限（20xx/年）”，最终只命中 `07记录清单`，与人工核对一致。

QuoteValidator 首版按严格连续命中统计 32 项，去掉列表符号和表格分隔线后为 29 项、去重 21 条，与人工核对的“18 条非连续 + 2 条低信息 + 1 条样板文字”一致。

ClauseItemValidator 的 16 项全部与条款正文核对过，未发现误报。

## 八、建议

1. **v5.2 冻结，不扩写。** 当前问题不是提示词缺规则，而是输出缺少硬约束。
2. **P0 直接作为写库门禁：** DocFact 错判、Assembly true 过强、DoubtType 硬错误、无 RelatedFindings，一律拒绝。
3. **P1 进入修复队列：** 引用不连续先重取原文；ClauseItemRef 错先改成 `main` 或属性池条目；不要直接丢弃 finding。
4. **P2 人工复核：** `inconsistent_person` 这类角色/职责问题，不自动判定。
5. **先修文档层 07 记录清单规则**，再复测；否则 7.5.3.2 整条会被一份 DocFact 带偏。
6. **复测验收线：**
   - P0 = 0；
   - P1 finding 占比 ≤5%，且全部可修复或标 `quote_unverified`；
   - P0 门禁通过率：Doubts ≥85%、Assemblies ≥95%、DocFacts ≥98%；
   - 单条款 run-to-run F/D/A 波动 ≤1。

达到这组门槛，再把 v5.2 写库；当前仍建议“影子提示词 + 校验器门禁”。
