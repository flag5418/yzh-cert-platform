# 66-文档模式提取输出字段字典-V1

## 一、先分清四层结构

分析提取结果时，不要只看 `PrimaryClauses` 一个字段。当前产物分为四层：

| 层级 | 位置 | 说明 |
|---|---|---|
| 提取行 | `cert_document_extraction` 表 | `PromptCode`、`PromptVersion`、`ExtractStatus` 等，回答“用什么提示词、跑成功没有” |
| 顶层 JSON | `ContentJson` | `DocMeta` + `ExtractionMode` + `ModeOutput` + `Clauses` |
| 公共属性 | `ContentJson.ModeOutput` 根节点 | 所有文档都必须输出的通用属性 |
| 类型专属 | `ContentJson.ModeOutput` 内 | 过程、记录、索引、审核等各自字段 |

模式提取的产物 `Clauses` 固定为空数组；条款事实不在 `Clauses` 里，而在 `ModeOutput` 里。手册逐条款仍使用 `Clauses[]`。

## 二、顶层 `ContentJson` 结构

```json
{
  "DocMeta": {
    "FileName": "03机器设备维修记录表.doc",
    "StandardCode": "iso9001",
    "StandardName": "GB/T 19001-2016 质量管理体系 要求",
    "Model": "qwen-plus",
    "SourceSha256": "……",
    "SourceVersion": 1,
    "MarkdownSha256": "……",
    "ExtractionFingerprint": "……",
    "ExtractionMode": "record_profile",
    "PromptCode": "doc_extract_record_profile",
    "PromptScope": "stored",
    "ExtractedAt": "2026-11-14T11:28:52+08:00",
    "Chunks": 1
  },
  "ExtractionMode": "record_profile",
  "ModeOutput": {
    "DocType": "record",
    "DocTitle": "机器设备维修记录表",
    "DocSections": [],
    "Chapters": ["7.1"],
    "PrimaryClauses": ["7.1.3"],
    "SupportClauses": [],
    "Records": []
  },
  "Clauses": []
}
```

| 字段 | 类型 | 含义 |
|---|---|---|
| `DocMeta` | object | 本次提取的元信息，不参与业务判断 |
| `DocMeta.FileName` | string | 源文件名，含扩展名 |
| `DocMeta.StandardCode` | string | 标准短码，如 `iso9001` |
| `DocMeta.StandardName` | string | 标准全名 |
| `DocMeta.Model` | string | 本次调用的模型 |
| `DocMeta.SourceSha256` | string | 源文件哈希；用于判断文件是否被替换 |
| `DocMeta.SourceVersion` | int | 源文件版本号 |
| `DocMeta.MarkdownSha256` | string | 转换后 Markdown 哈希；用于判断转换文本是否变化 |
| `DocMeta.ExtractionFingerprint` | string | 提取指纹；输入、提示词、模型任一变化都会变 |
| `DocMeta.ExtractionMode` | enum | 本次实际使用的提取模式 |
| `DocMeta.PromptCode` | string | 实际使用的提示词代码 |
| `DocMeta.PromptScope` | enum | `stored` 库内提示词 / `fallback` 代码兜底 / `missing` 缺提示词 |
| `DocMeta.ExtractedAt` | datetime | 提取完成时间，本地时间 |
| `DocMeta.Chunks` | int | 送模型时分了几段；`1` 表示未分段 |
| `ExtractionMode` | enum | 与 `DocMeta.ExtractionMode` 同源，方便顶层读取 |
| `ModeOutput` | object | 模式提示词原样 JSON；所有业务字段在这里 |
| `Clauses` | array | 模式提取固定为空；手册逐条款才有内容 |

### 2.1 `ExtractionMode` 枚举

| 值 | 含义 |
|---|---|
| `clause_full` | 手册逐条款提取 |
| `process_profile` | 程序文件/流程文件画像 |
| `record_profile` | 记录/表单画像 |
| `index_only` | 文件索引 |
| `document_control` | 文件控制类文档 |
| `work_instruction_citation` | 作业指导书引用 |
| `policy_profile` | 制度/规范/管理办法 |
| `context_list` | 组织环境/相关方清单 |
| `audit_profile` | 内审/管理评审记录 |
| `none` | 判定与标准无关或无需提取 |
| `legacy` | 旧链，逐步淘汰 |

## 三、`ModeOutput` 公共字段

以下字段所有模式都必须输出；`Extractable=false` 时也必须保留这些字段，只把类型专属数组置空。

| 字段 | 类型 | 含义 | 分析要点 |
|---|---|---|---|
| `DocType` | enum | 文档类型 | 用于路由和报告深度；见 §五枚举 |
| `DocTitle` | string | 文档标题，取封面/首页/页眉 | 不是文件名 |
| `StandardRelevant` | bool | 是否与当前标准相关 | `false` 时不进入检查上下文 |
| `Extractable` | bool | 本类型专属事实是否可提取 | `false` 不等于整份文档没用，公共属性仍保留 |
| `ClauseEligible` | bool | 是否允许做逐条款提取 | 当前只有手册为 `true`；非手册固定 `false` |
| `ExtractReason` | string | 为什么相关/可提取/不相关 | 用于排查误判 |
| `ProcessArea` | enum | 业务过程域 | 只能选八类；见 §五枚举 |
| `DocSections` | array<string> | 文档自己的章节/小节，逐字抄目录或正文标题 | 例如 `["1 目的","4 工作流程","5 作业内容"]`；没有章节给 `[]` |
| `Chapters` | array<string> | 标准父章节，如 `["4","8.5"]` | 不是文档章节；后端会把 `7.1.3` 归一到 `7.1` |
| `OwnerDept` | string | 归口/执行部门 | 必须是企业真实部门；没有写“未标注” |
| `SupportDepts` | array<string> | 配合部门 | 只写原文出现的真实部门 |
| `DocUse` | enum | 文档在报告中的使用方式 | 见 §五枚举 |
| `ReportRole` | enum | 文档在报告中的角色 | 见 §五枚举 |
| `ReportDepth` | enum | 报告引用深度 | 见 §五枚举 |
| `ReportSummary` | string | 一句话摘要，说明文档规定/记录什么、谁执行 | 不写符合性结论 |
| `ReportUse` | string | 报告拿它证明什么/怎么用 | 不写“已引用/已实施” |
| `PrimaryClauses` | array<string> | 标准主条款，叶子条款 | 必须按标准条款语义判断，不得直接抄文档章节号 |
| `SupportClauses` | array<string> | 标准支撑条款，叶子条款 | 只写正文直接支撑；间接影响不挂 |
| `Metadata` | object | 原文元数据 | 见 §三.1 |
| `CoveragePeriod` | object | 记录/台账覆盖期 | 见 §三.2；程序/制度不适用给空串 |
| `Warnings` | array<object> | 结构化告警 | 见 §三.3 |

### 3.1 `Metadata`

| 字段 | 类型 | 含义 | 取值规则 |
|---|---|---|---|
| `DocCode` | string | 文件编号 | 只取封面/页眉/修订栏；没有给空串 |
| `DocVersion` | string | 版本号 | 只取原文；没有给空串 |
| `EffectiveDate` | string | 生效/实施日期 | 只取原文；没有给空串 |
| `IssuedBy` | string | 编制/发布部门或组织 | 只取原文；没有给空串 |
| `ApprovedBy` | string | 批准人 | 只取原文；没有给空串 |

### 3.2 `CoveragePeriod`

| 字段 | 类型 | 含义 |
|---|---|---|
| `Start` | string | 覆盖期开始，如 `2026-09`；没有给空串 |
| `End` | string | 覆盖期结束；没有给空串 |

### 3.3 `Warnings[]`

| 字段 | 类型 | 含义 |
|---|---|---|
| `Code` | enum | 告警代码；见 §五枚举 |
| `Message` | string | 告警说明，写给人工复核 |

## 四、类型专属字段

### 4.1 `process_profile` 程序文件/流程文件

```json
{
  "KeyControls": [
    {
      "Control": "每年至少一次内外部环境分析与评价，重大变化时追加",
      "Clause": "4.1",
      "DocSection": "5.1",
      "Record": "外部因素识别监视评价总清单"
    }
  ],
  "RelatedDocs": [
    {
      "DocName": "风险机遇控制程序",
      "RelatedClause": "6.1"
    }
  ],
  "EvidencePointers": ["外部因素识别监视评价总清单"]
}
```

| 字段 | 类型 | 含义 | 分析要点 |
|---|---|---|---|
| `KeyControls` | array<object> | 3–5 个关键控制点 | 报告摘要和控制点引用的核心 |
| `KeyControls[].Control` | string | 控制点原文要求，≤60 字 | 不是模型建议 |
| `KeyControls[].Clause` | string | 该控制点对应的**标准**叶子条款 | 必须落在 `PrimaryClauses` 或 `SupportClauses` 内 |
| `KeyControls[].DocSection` | string | 该控制点在文档中的真实小节号，如 `5.1` | 用来区分文档编号与标准条款 |
| `KeyControls[].Record` | string | 原文真实记录名 | 找不到写“无记录” |
| `RelatedDocs` | array<object> | 正文“相关文件”中真实出现的文件 | 不编造文件名 |
| `RelatedDocs[].DocName` | string | 关联文件名 | 原文名称 |
| `RelatedDocs[].RelatedClause` | string | 该文件对应的标准条款 | 可为父/叶子，按原文语义 |
| `EvidencePointers` | array<string> | 原文真实出现的记录/表单名 | 0–6 个 |

### 4.2 `record_profile` 记录/表单

```json
{
  "Records": [
    {
      "RecordName": "机器设备维修记录表",
      "DocSection": "",
      "ProcessName": "设备维修",
      "OwnerDept": "品质部",
      "FormFields": ["序号", "日期", "故障现象/原因", "维修结果", "维修单位", "验收人", "费用", "备注"],
      "Period": "",
      "Batch": "",
      "RowCount": 1,
      "Samples": [
        {
          "Date": "08-02",
          "Batch": "",
          "Values": ["不工作", "已解决", "生产部", "黄勇"],
          "Conclusion": "已解决",
          "Signoff": "黄勇"
        }
      ],
      "Rows": [
        {
          "Date": "08-02",
          "Batch": "",
          "Values": ["不工作", "已解决", "生产部", "黄勇"],
          "Conclusion": "已解决",
          "Signoff": "黄勇"
        }
      ],
      "Signoff": ["使用人/责任人：黄勇", "编制：黄勇", "审核：胥加娟", "批准：潘明海"],
      "LinkedDoc": "",
      "EvidencePointers": ["机器设备维修记录表"],
      "RecordState": "filled"
    }
  ]
}
```

| 字段 | 类型 | 含义 | 分析要点 |
|---|---|---|---|
| `Records` | array<object> | 1–3 个记录类型 | 一个文件多张表可多条 |
| `Records[].RecordName` | string | 记录/表单名称 | 取原文标题 |
| `Records[].DocSection` | string | 该表在文档中的小节号 | 记录表通常为空串 |
| `Records[].ProcessName` | string | 该记录所属业务过程 | 与 `ProcessArea` 不同，可更具体 |
| `Records[].OwnerDept` | string | 记录责任部门 | 企业真实部门 |
| `Records[].FormFields` | array<string> | 表头真实字段 | 不按行业习惯补列 |
| `Records[].Period` | string | 记录覆盖期 | 原文没有给空串 |
| `Records[].Batch` | string | 批次/单号 | 原文没有给空串 |
| `Records[].RowCount` | int | 表格非空数据行总数 | 空白行不计 |
| `Records[].Samples` | array<object> | 1–3 条报告抽样 | 只用于报告引用，不是全量 |
| `Records[].Rows` | array<object> | 表格所有非空数据行 | 审核底稿核对用；最多 30 行 |
| `Samples[]` / `Rows[]` 的 `Date` | string | 日期/时间 | 逐字抄原文 |
| `Samples[]` / `Rows[]` 的 `Batch` | string | 批次/单号 | 没有给空串 |
| `Samples[]` / `Rows[]` 的 `Values` | array<string> | 该行字段值 | 建议按 `FormFields` 顺序 |
| `Samples[]` / `Rows[]` 的 `Conclusion` | string | 原文结论栏 | 不写系统判定 |
| `Samples[]` / `Rows[]` 的 `Signoff` | string | 原文签署人 | 没有给空串 |
| `Records[].Signoff` | array<string> | 表尾签署角色/姓名 | 原文真实出现 |
| `Records[].LinkedDoc` | string | 原文提到的关联文件 | 没有给空串 |
| `Records[].EvidencePointers` | array<string> | 原文真实记录/表单名 | 不编造 |
| `Records[].RecordState` | enum | `blank / partial / filled` | 空白表也保留字段和 `Rows=[]` |

> `Samples` 与 `Rows` 的区别：
> - `Samples` 是“报告只引用 1–3 条”的投影；
> - `Rows` 是“审核底稿可逐行核对”的全量非空行；
> - 当前 `Rows` 最多 30 行，超过时保留前 30 行并在 `Warnings` 记 `other`。

## 六、`Clauses[]` 手册条款结构

手册逐条款仍使用 `Clauses[]`，模式提取不使用。

| 字段 | 类型 | 含义 |
|---|---|---|
| `ClauseNumber` | string | 标准条款号，逐字取自输入清单 |
| `Title` | string | 标准条款标题 |
| `Anchor` | string | 原文锚点，10–40 字，能逐字定位 |
| `Excerpts` | array<string> | 原文摘录，可多段 |
| `ExcerptLocations` | array<object> | 摘录在 Markdown 中的定位结果 |
| `ExcerptLocations[].ExcerptIndex` | int | 对应 `Excerpts` 下标 |
| `ExcerptLocations[].Start` | int | Markdown 字符起点 |
| `ExcerptLocations[].End` | int | Markdown 字符终点 |
| `ExcerptLocations[].Status` | string | `matched / unverified` |
| `ExcerptLocations[].Kind` | string | 定位类型，如 `excerpt / section_candidate` |
| `Confidence` | number | 模型自评置信度 0–1，不是符合性结论 |

## 七、后处理会改什么

`DocExtractGuard.Sanitize` 会做确定性清洗，分析时要知道这些字段可能被改过：

| 处理 | 影响字段 |
|---|---|
| 删除模型猜测的条款关联 | `ClauseLinks` 一律移除 |
| 删除报告引用状态 | `ReportPresence` 一律移除 |
| 审核/评审去系统结论 | `Conclusion` / `Conclusions` 移除，保留 `RecordConclusions` |
| 部门归一 | `OwnerDept` / `SupportDepts` / `Entries[].Owner` 只保留可识别真实部门 |
| 章节层级归一 | `Chapters` 中三级叶子自动收成两级，如 `7.1.3 → 7.1` |
| 记录 Rows 截断 | 超过 30 行时只保留前 30 行，`Warnings` 记 `other` |

## 八、分析时的正确顺序

1. 先看 `ExtractionMode` / `PromptCode`：确认是不是模式提取，还是旧链。
2. 看 `DocSections`：文档自己有哪些章节。
3. 看 `Chapters`：模型认为对应哪些标准父章节。
4. 看 `PrimaryClauses` / `SupportClauses`：标准条款语义是否准确；不要把文档章节号当成标准条款。
5. 过程文件看 `KeyControls[].DocSection`：每个控制点能否在原文小节找到。
6. 记录文件看 `RowCount` / `Rows` / `Samples`：是否全量行、抽样是否代表。
7. 最后看 `Warnings`：缺部门、缺元数据、多章节、空表等问题。
