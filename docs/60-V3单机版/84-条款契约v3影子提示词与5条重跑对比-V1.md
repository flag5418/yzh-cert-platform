## 3. 逐条对比

### 3.1 `7.5.1` 生产和服务提供的控制

**Oracle（5）：**

1. 生产和服务提供控制程序
2. 装配作业指导书
3. 生产记录
4. 产品放行记录
5. 交付后活动记录

**v3.2（7）：**

1. 生产和服务提供控制程序
2. 生产记录（含每台/每批医疗器械）
3. 基础设施鉴定记录
4. 过程参数和产品特性监视与测量记录
5. 监视和测量设备使用与校准记录
6. 标记和包装操作记录
7. 产品放行、交付及交付后活动记录

**判断：**

- 有 `procedure + record + implementation`，证据链成立；
- `产品放行记录` 和 `交付后活动记录` 合并成 E7，报告侧无法分别抽样/覆盖；
- 缺 `装配作业指导书`，只有 E1 程序字段里的“控制方法”，不能替代作业指导；
- 多出的 E3/E4/E5/E6 是条款 a)–e) 分项，属于合理拆分，不是错。

### 3.2 `8.2.4` 内部审核

**Oracle（7）：** 程序、计划、签到表、检查表、不合格报告、内审报告、审核员任命/能力记录。

**v3.2（5）：** 程序、计划、检查表、报告、不符合项报告及纠正措施记录。

**判断：**

- 5 项都能和真实内审包对上；
- 缺 `内审签到表`：条款只说“保留审核记录”，没点名签到，但真实内审包需要它证明首次/末次会议；
- 缺 `审核员任命/能力记录`：条款明确写“审核员的选择…确保客观公正”，这是条款内要求，不是审核惯例；
- `Dependencies` 只剩 4.2.5，比第一轮干净，没有乱加 8.2.6。

### 3.3 `8.2.6` 产品的监视和测量

**Oracle（8）：** 程序、成品检验指导、过程检验规程、过程检验记录、成品检验记录、放行审核记录、检测设备使用/校准记录、第三方检验报告。

**v3.2（5）：** 产品监视和测量控制程序、产品检验规程、产品监视和测量记录、植入性医疗器械检验人员身份记录、产品放行记录。

**判断：**

- 结构上把“程序/准则/记录/放行/植入人员”都覆盖了；
- 但 `产品检验规程` 和 `产品监视和测量记录` 各只有 1 个泛化项，无法对应“过程检验”和“成品检验”两条真实记录链；
- 条款明确写“应记录有权放行产品的人员的身份”“记录应识别用于执行测量活动的检测设备”，生成结果只把这两个要求塞进 E3 的字段，没有独立 `EvidenceItem`；
- 条款明确写“对于植入性医疗器械”，生成结果把整条 `Applicability` 改成 `conditional`，`ApplicabilityCondition=对于植入性医疗器械`——这是**结构性错误**，会导致 8.2.6 对非植入器械企业被误判为条件适用。

**这是本轮最需要修的一条。**

### 3.4 `8.3.2` 交付前发现不合格品的响应措施

**Oracle（6）：** 不合格品控制程序、不合格品通知及评审处置表、让步接收申请表、报废申请单、返工/返修记录、进货/过程/成品不合格检验记录。

**v3.2（3）：** 不合格品处置记录、让步接收审批记录、不合格品隔离与标识记录。

**判断：**

- `a) 采取措施消除不合格` → 只生成 1 个泛化“处置记录”，没有拆出返工/返修记录；
- `b) 防止原预期使用或应用` → 只生成“隔离与标识记录”，没有拆出报废申请单；
- `c) 授权让步` → 让步接收审批记录有了；
- 缺 `不合格品控制程序`：条款是“响应措施”，程序是 establishment 项，不能只靠记录；
- 缺 `进货/过程/成品不合格检验记录`：这是不合格事实来源，属于同一证据链的 support，不是条款正文直接要求，但报告实际证据就是进货不合格检验记录。

### 3.5 `7.6` 监视和测量设备的控制

**Oracle（6）：** 程序、设备台账、周期检定计划、校准/检定记录、校准状态标识/使用记录、软件确认记录。

**v3.2（7）：** 程序、台账、校准/检定记录、标识记录、不符合设备处置记录、软件确认程序、软件确认记录。

**判断：**

- 校准、台账、标识、软件确认都覆盖；
- 缺 `计量设备周期检定计划`：条款写“按照规定的时间间隔…校准”，计划是 establishment 项，不是记录；
- `标识记录` 只覆盖“校准状态标识”，没有覆盖“使用记录/防护记录”；
- 多出“不符合设备处置记录”是条款“防止调整使测量结果失效”的合理支撑项。

## 5. 结论

1. **v3 结构可行**：`EvidenceItems[] + Dependencies[] + CrossChecks[] + AuditorRules` 能稳定输出，5 条都合法 JSON。
2. **`Process` 和条件子句是提示词级 bug，不是模型能力问题**：v3.1 修正 `Process` 后 5/5 合法；但 `8.2.6` 的 `conditional` 仍错，说明“条件子句只进 Condition”这条规则还没有压过旧 `Applicability` 判据。
3. **召回不足是主要问题**：13/32 直接对应，8.2.6/8.3.2 只有 2–3 项，无法支撑真实报告的证据包。
4. **提示词越补越大**：8.4KB → 16KB，靠继续加规则会失控；需要换成“两阶段”。

## 6. 建议的 v3.3：两阶段，不再堆规则

**第一阶段：条款原子提取**

```json
{
  "ClauseAtoms": [
    {"AtomId": "A1", "Subject": "组织", "Action": "建立并保留", "Object": "每台/每批医疗器械记录", "Timing": "每批", "Record": "生产记录", "Approval": "核验和批准"},
    {"AtomId": "A2", "Subject": "组织", "Action": "实施", "Object": "过程参数和产品特性监视测量", "Timing": "生产过程中", "Record": "过程监视测量记录", "Approval": "操作人员/审核人员"}
  ]
}
```

**第二阶段：由原子映射证据项**

- `Action=建立/形成文件` → `procedure/establishment`；
- `Action=实施/检验/处置` + `Record` → `record/implementation`；
- `Action=依据/符合` → `work_instruction/criteria`；
- `Approval` 非空 → 增加签署/授权字段或独立授权记录；
- `Object` 含“过程/成品/进货” → 拆成对应阶段记录；
- `Object` 含“返工/返修/报废/让步” → 拆成对应处置记录。

这样 `8.2.6` 的“过程检验/成品检验”、`8.3.2` 的“a/b/c 三种处置”会从条款原子自然拆出来，而不是靠提示词里堆“名词触发清单”。

**同时保留两条硬规则：**

- `Applicability` 只看主句；后置“对于…”只进 `EvidenceItem.Condition`；
- `Dependencies` 只写正文明确引用或同一证据链必需，不跨链硬加。
