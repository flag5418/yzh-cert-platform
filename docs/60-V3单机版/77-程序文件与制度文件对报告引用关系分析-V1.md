# 77-程序文件与制度文件对报告引用关系分析-V1

> 样本：尚龙 13485 案例。
> 目录：`2程序文件`（36 个文件，33 份 QP 程序 + 清单/封面）、`3制度文件（可根据企业实际修改）`（24 个文件，15 份 QD 制度 + 7 份检验/工艺/封面 + 受控清单）。
> 报告：`尚龙-ACM二阶段-结构化.md`，50 页，56 个条款段。
> 目的：看报告如何引用程序/制度文件、如何组织证据、哪些文件真正进入证据链。

---

## 0. 结论

1. **报告不是按文件组织，是按条款检查表组织。**
   每一段是一个条款，表头是 `NC/OFI | Clause Requirements | Audit Evidence`；文件只是“审核证据”列里的引用。

2. **程序文件主要证明“企业规定了”，记录主要证明“企业执行了”。**
   报告常用“编制/建立了《XX程序》”证明制度存在；用“提供/查见《XX记录》+日期/批次/数量/结论”证明执行。

3. **作业指导书/检验规程主要证明“验收准则”。**
   `8.2.6`、`7.5` 会先引程序，再引检验规程/作业指导书，最后引过程/成品检验记录。

4. **程序文件自带“相关文件/相关表单”，是天然的条款→程序→表单链。**
   例如 `QP-013` → `QR-020/021/022`；`QP-021` → `PR-025/026/028`；`QP-020` → `QR-006/007`。报告里的记录引用大多能在程序文件的“相关表单”里找到。

5. **报告引用范围大于这两个文件夹。**
   报告引用了 `手动轮椅车成品检验作业指导书`、`手动轮椅车过程检验规程`、`手动轮椅车原材料进货检验规程`、`手动轮椅车装配作业指导书`、`产品包装作业指导书`、设备操作规程等，这些不在 `3制度文件`，或名称/产品范围不一致。

6. **程序文件有 33 份，报告直接点名约 24 份；制度文件 22 份有效文档，报告只直接点名 2 份（QD-001、QD-008），其余多为“三级文件”泛称或间接支撑。**
   这说明：制度文件不是报告的主证据源，程序+记录+作业指导书才是。

7. **报告是双栏 PDF 抽取，文件标题会被拆行，并与英文要求交错。**
   例如 `《基础设施及设备控制程序》` 被拆成 `《基础设施及设备控制程` + 英文要求 + `序》`；精确字符串匹配会漏。必须做名称归一/别名，不能靠直接匹配。

## 1. 两类文件的结构

### 1.1 程序文件（QP）

以 `XASL-QP-013 不合格品控制程序` 为例，结构固定：

| 段 | 内容 | 对证据的作用 |
|---|---|---|
| 目的 | 对不合格品识别和控制，防止非预期使用或交付 | 说明程序管什么 |
| 范围 | 原材料、外协件、半成品、成品、交付后 | 确定适用对象 |
| 职责 | 质量部、仓库、总经理、相关部门 | 确定责任部门 |
| 程序 | 定义、处置方式、来料/在制品/成品/顾客处置 | 规定动作 |
| 相关文件 | `QP-025` | 程序之间的引用 |
| 相关表单 | `QR-020/021/022` | 条款→表单→记录的入口 |

**结论：** 程序文件的核心不是字段，而是“目的/范围/职责/程序/相关文件/相关表单”六段。这个结构跨企业、跨咨询公司高度稳定，适合轻提示词。

### 1.2 制度/作业指导文件（QD）

- 制度：目的/范围/职责/内容/相关文件；
- 检验规程：目的/适用范围/职责/工作程序/检验项目/验收标准/抽样/判定/记录；
- 工艺文件：产品/工序/参数/操作步骤/设备/记录。

**结论：** 制度文件是“操作规则”，作业指导书是“验收准则”，不是“记录”。文档分类必须先分清 `procedure / work_instruction / record`。

## 2. 报告如何引用文件：6 种方式

| 代号 | 报告写法 | 例子 | 证明什么 |
|---|---|---|---|
| `R1` | 编制/建立了《XX程序》 | “公司编制了《生产和服务提供控制程序》” | 制度存在（F1） |
| `R2` | 提供/查见《XX记录》+日期/批次/数量/结论 | “提供《手动轮椅车生产记录》23/06/2026，批号 20260623，100 台” | 执行存在（F2） |
| `R3` | 检验依据《XX规程/指导书》 | “检验依据《手动轮椅车成品检验作业指导书》” | 验收准则 |
| `R4` | 违反了《XX程序》 | “违反了《基础设施及设备控制程序》” | NC 依据（只作观察） |
| `R5` | 见《XX》 | “见《质量手册》”“见《记录控制程序》” | 交叉引用 |
| `R6` | 三级文件：如《XX》 | 4.2.1 列“《工作环境管理制度》《返工管理制度》...” | 文件层级 |

**报告引用特征：**

- 多数只写文件名，不写编号/版本；少数写 `XASL-QP-013`，还出现旧编号 `SJBJ-QP-001`。
- 记录名也常不带编号，例如 `《进货不合格检验记录》`、`《过程检验记录》`。
- 同一段证据常跨多个文件：程序 + 记录 + 现场/访谈。
- 文件标题会被双栏拆行，且与英文要求交错；不能只用正则精确匹配。

## 3. 报告如何组织：条款检查表，不是文件目录

报告每一段的结构：

```text
#### 条款 8.3.2 (P45)
- 要求：英文标准原文
- 证据：企业编制了《不合格品控制程序》...
- 证据续：提供《进货不合格检验记录》30/06/2026...
- 要求续：英文标准原文续...
- 证据续：...
```

它不是“先列文件，再逐文件说明”，而是：

1. **行 = 条款**；
2. **列 = NC/OFI / 条款要求 / 审核证据**；
3. **证据列 = 文件引用 + 记录引用 + 现场/访谈 + 结论**；
4. 程序文件只在需要证明“有规定”时出现；记录在需要证明“有执行”时出现；作业指导书在需要“验收准则”时出现。

**因此，报告的引用关系必须按“条款”重建，不能按“文件”重建。**

## 7. 审核员关注重心

| 文档类型 | 审核员先看什么 | 报告如何用 |
|---|---|---|
| 程序文件 | 目的/范围/职责/程序/相关表单；是否覆盖条款；是否现行版 | `R1` 证明“有规定”；通常不直接判执行 |
| 制度文件 | 是否与程序一致；是否可操作；是否现行版 | 作为三级文件/操作规则；少量直接引用 |
| 作业指导书/检验规程 | 检验项目、验收标准、抽样、判定、记录 | `R3` 作为验收准则；支撑 `8.2.6`/`7.5` |
| 记录 | 日期、批号、数量、结果、签署、追溯 | `R2` 证明“有执行”；是主证据 |
| 内审包 | 计划、签到、检查表、不合格报告、内审报告 | 多文档组合；单文档读不到结论 |

**报告的组织逻辑：** 先条款要求 → 再“有程序/有制度” → 再“有记录/有现场” → 最后结论。程序文件是“制度证据”，记录是“执行证据”，作业指导书是“准则证据”。

## 8. 对条款属性/提示词的设计含义

### 8.1 文档提示词：轻模型 + 文档角色

程序/制度文件不需要按格式穷举字段，只需要：

```json
{
  "DocClass": "procedure | work_instruction | record | policy | manual",
  "DocRole": "establishment | implementation | criteria | support",
  "Purpose": "一句话",
  "Scope": "适用范围",
  "Responsibilities": ["质量部","生产部"],
  "RelatedDocs": ["XASL-QP-025"],
  "RelatedForms": ["XASL-QR-020","XASL-QR-021"],
  "Applicability": "产品/过程/部门范围",
  "FillStatus": "filled | partial | blank | absent | unreadable",
  "SampleRows": []
}
```

- 程序文件：读“目的/范围/职责/程序/相关文件/相关表单”；
- 制度文件：读“目的/范围/职责/内容/相关文件”；
- 作业指导书：读“适用范围/检验项目/验收标准/抽样/判定/记录”；

### 8.4 匹配状态：增加“报告引用匹配”

文档事实之外，另设对账字段：

| 字段 | 值 | 用途 |
|---|---|---|
| `CitedInReport` | `true/false` | 报告是否点名 |
| `CitationName` | 报告里的写法 | 处理名称变体 |
| `NameMatch` | `exact/alias/mismatch/not_found` | 判断是否能自动对上 |
| `ApplicabilityMatch` | `same/different/unknown` | 产品/工序是否一致 |
| `EvidenceRoleInReport` | `R1/R2/R3/R4/R5/R6` | 报告怎么用 |

这样就能解释：为什么有些文件在文件夹里但报告没引用；为什么有些报告引用的文件不在文件夹里。
