# 51-手册旧提取效果诊断与父章节批量建议-V1

> 结论先说：**旧手册提取的叶子条款覆盖不差，但父条款 0 覆盖，关键子点有截断；不建议改成 60 次逐条款调用，建议改成“父章节批量”（约 8 次调用）。**

---

## 一、旧链路到底是什么

| 项 | 实测 |
|---|---|
| 文档 | `01管理手册QMS.doc`（`6e6a863b61584ad684261a665846b6b1`） |
| 提示词 | `doc_clause_extract`（旧主链） |
| 提取时间 | 2026-11-12 14:51:00 |
| 模型 | qwen-plus |
| 结果 | 60 条条款，23,092 字符 |
| 消息 | “提取 60 条条款；长文档已分 2 段提取” |

所以旧链路**不是 60 次模型调用**，而是：把手册条款清单 + 全文分 2 段，**每段一次调用**，模型按条款批量输出。成本很低，这是它最大的优点。

---

## 二、旧结果的质量

### 2.1 条款覆盖

标准 `iso9001` 库内 94 条：**26 条父条 + 68 条叶子**。

| 指标 | 数值 |
|---|---|
| 旧输出条款 | 60 |
| 父条覆盖 | **0 / 26** |
| 叶子覆盖 | 60 / 68（88.2%） |
| 剔除 8.3（不适用 6 条）+ 第 2 章（引用文件 1 条）后的适用叶子 | 60 / 61（98.4%） |
| 唯一漏掉的适用叶子 | `4.4.2` |

**父条 0 覆盖**是最大问题。旧输出有 5.1.1、5.1.2，但没有 5.1；有 6.1.1、6.1.2，但没有 6.1；有 8.5.1–8.5.6，但没有 8.5；有 9.1.1–9.1.3，但没有 9.1。检查项如果落父条，旧产物直接没有对应事实。

### 2.2 子点完整性

旧产物不是“每条都完整”，而是会截断：

| 条款 | 手册正文 | 旧输出 | 判断 |
|---|---|---|---|
| `4.1` | 4.1.1–4.1.5 + 4.1.3 a/b + 4.1.5 a–d | 只有 4.1.1、4.1.2、4.1.3 | **漏 4.1.4 监视评审、4.1.5 正面/负面要素及 a–d** |
| `5.1.1` | 5.1.1 + a–j | 只有引出句 + a、b | **漏 c–j 共 8 个分点** |
| `6.1.1` | 6.1.1 + a–d | 5 段，a–d 齐全 | 完整 |
| `4.3` | 4.3.1–4.3.3 + QMS/地址/不适用说明 | 3 段，含 QMS/地址/不适用 | 完整 |
| `8.5.1` | 8.5.1.1 + (1)–(7) | 1 段，括号分点都在同一段 | 事实在，但没有分点结构 |

旧提示词明确写了“同一条款最多 6 段摘录”，且输出结构只有 `Excerpts[]`，没有 `SubClauses`、`ParentSubClause`、`Coverage`、`ExtraFacts`。模型在 5.1.1 这种 10 个分点的条款上会主动截断。

### 2.3 8.3 的特殊情况

- 手册 `4.3` 明确写“**8.3 条款不适用**”，旧 `4.3` 已把这段不适用说明摘出来。
- 但手册第 8 章又抄了 8.3.1–8.3.6 的标准原文；旧链路没有输出 8.3。
- 这个处理**业务上是对的**：不能把“手册转抄标准原文”当成企业实际开展设计开发活动。
- 后续父章节批量跑第 8 章时，必须把 8.3 标成 `NotApplicable` / `ExtraFacts`，⛔ 不能生成设计开发活动证据。

## 三、新逐条款样本 vs 旧结果

新 `doc_extract_clause_full` 4 个调用（4.1 / 4.3 / 5.1 / 6.1）结果：

| 条款 | 新输出 | 旧输出 | 差异 |
|---|---|---|---|
| 4.1 | 11 个子条/分点，Coverage 11/11 | 3 段 | 新补 4.1.4、4.1.5、a–d |
| 4.3 | 7 个子条，3 ExtraFacts，7/7 | 3 段 | 新结构完整，QMS/地址/不适用进 ExtraFacts |
| 5.1 | 14 个子条，1 ExtraFacts，14/14 | 5.1.1（a、b）+ 5.1.2（a、b） | 新补 5.1.1 c–j、父条 5.1、k) |
| 6.1 | 9 个子条，1 ExtraFacts，9/9 | 6.1.1 完整、6.1.2 完整 | 结构更细，父条保留 |

结论：**新逐条款质量明显更好**，但每次调用 17–40 秒；60 条全跑约 17–40 分钟。对手册这一份文档，成本偏高。

## 四、父章节批量验证

用“父章节 + 本章顶层条款清单 + 本章正文”一次调用，输出 `Clauses[]`，每条内部再输出 `SubClauses[]`。

### 4.1 第 4 章

输入顶层条款：`4 / 4.1 / 4.2 / 4.3 / 4.4`。

结果：

| 条款 | 子条/分点 | Coverage |
|---|---|---|
| 4 | 1（章节标题） | 1/1 |
| 4.1 | 11 | 11/11，含 4.1.4、4.1.5、a–d |
| 4.2 | 8 | 8/8 |
| 4.3 | 7 + 3 ExtraFacts | 7/7 |
| 4.4 | 8 + 1 ExtraFact | 8/8，含 4.4.1、4.4.2 及 a–f |

第 4 章一次调用，结构与非逐条款样本基本一致。

### 4.2 第 5 章

第一次测试把 `5.1.1 / 5.1.2 / 5.2.1 / 5.2.2` 也放进顶层清单，模型把 5.1.2、5.2.2 当顶层条款，还自造了 `5.2.3`、`5.3.2`，层级漂移。

改成**只给顶层父条** `5 / 5.1 / 5.2 / 5.3` 后：

| 条款 | 子条/分点 | Coverage |
|---|---|---|
| 5 | 1（章节标题） | 1/1 |
| 5.1 | 17 | 17/17，5.1.1 + a–k、5.1.2 + a–b 全在 |
| 5.2 | 12 | 12/12，5.2.1 + a–c、5.2.2、5.2.3 + a–e |
| 5.3 | 7 | 7/7，5.3.1 + a–d、5.3.2 |

第 5 章一次调用，耗时 **91.8 秒**，输出 10,638 字符。

### 4.3 关键实现约束

1. **顶层清单只给父条**：`5 / 5.1 / 5.2 / 5.3`，不要给 5.1.1、5.1.2；否则模型会把子条提升成顶层，层级漂移。
2. **父条 `5` 的 Coverage 不能把 5.1/5.2/5.3 算 Missing**：5 只是章节标题，子条是独立顶层对象；建议代码侧清洗为 `Declared=1, Covered=1, Missing=[]`。
3. **8.3 必须按 4.3 的“不适用”处理**：第 8 章批量要特判，不能把 8.3 标准原文当企业活动。
4. **第 8 章需要拆组**：8.1–8.4 与 8.5–8.7 分两次，避免单次输出过大。

## 五、建议

### 5.1 不采用 60 次逐条款

理由：
- 旧链路 2 次调用已能覆盖 98.4% 适用叶子；
- 逐条款 60 次，时间 17–40 分钟，成本不划算；
- 手册只有 1 份，不值得为它把整条执行器改成逐条循环。

### 5.2 采用父章节批量

建议分组：

| 组 | 条款 |
|---|---|
| 4 | 4 / 4.1 / 4.2 / 4.3 / 4.4 |
| 5 | 5 / 5.1 / 5.2 / 5.3 |
| 6 | 6 / 6.1 / 6.2 / 6.3 |
| 7 | 7 / 7.1 / 7.2 / 7.3 / 7.4 / 7.5 |
| 8-1 | 8 / 8.1 / 8.2 / 8.3 / 8.4 |
| 8-2 | 8.5 / 8.6 / 8.7 |
| 9 | 9 / 9.1 / 9.2 / 9.3 |
| 10 | 10 / 10.1 / 10.2 / 10.3 |

约 **8 次调用**，按第 5 章 92 秒估算，约 8–12 分钟；比 60 次逐条快 2–3 倍，且保留父条/子条/分点结构。

### 5.3 落地方式

- 新增提示词 `doc_extract_clause_chapter`（或把 `doc_extract_clause_full` 扩展为 batch 模式），输入：
  `{{doc_profile}}`、`{{chapter_number}}`、`{{chapter_title}}`、`{{clause_list}}`（**只顶层父条**）、`{{chapter_text}}`。
- 输出：
  `{"Chapter":"4","Clauses":[{ClauseNumber,Title,SubClauses[],Coverage,ExtraFacts[]}]}`
- 执行器新增 `clause_chapter` 分支，只对手册/质量手册生效；其余 `clause_full` 文档保持旧链或按需逐条。
- 加确定性 guard：
  - `Clauses[].ClauseNumber` 必须在顶层清单内；
  - 父条只有标题时 Coverage 清洗为 1/1；
  - 8.3 统一转 `ExtraFacts/NotApplicable`；
  - 禁止 `Conclusion` 类字段。

## 六、验收口径

- 父条覆盖 26/26（或按“手册实际写到”的父条全覆盖）；
- 适用叶子覆盖 60/61，`4.4.2` 必须出现；
- 4.1 必须出现 4.1.4、4.1.5 及 a–d；
- 5.1.1 必须出现 a–k；
- 8.3 不得生成“设计开发活动”事实，只能作为不适用说明；
- 单章输出结构稳定，无顶层条款漂移；
- 总调用数 ≤ 10，耗时不高于 15 分钟。
