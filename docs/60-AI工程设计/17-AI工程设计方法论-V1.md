# AI 工程设计方法论 —— 体系认证审核平台

> 版本：V1.0 | 2026-07-27 | 面向 2 人 + AI Vibe Coding 的大型项目可控开发体系

---

## 一、核心理念：AI 是脚手架，规则是混凝土

**问题**：大模型没有记忆体，每次对话都是"失忆上岗"。若不给规则，它会在同一项目里写出 3 种不同风格的代码，引入未经设计的依赖，越写越失控。

**解法**：建立分层规则体系，让 AI 在任何一次对话中都能精准对齐项目约束。这不是"写好代码规范让人类遵守"，而是"写好机器可解析的约束让 AI 强制对齐"。

```
规则体系 = 项目宪法（不可变） + 领域知识库（可追加） + 设计系统（可引用） + 技能包（可加载）
```

## 二、项目宪法（Project Rules / .cursorrules）

### 2.1 宪法结构

文件位置：`项目根目录/.cursorrules`（或 Cursor/Continue/Windsurf/Claude Code 等效配置）

```yaml
# ========================================
# 体系认证审核平台 - 项目宪法
# AI 每次对话自动加载，不可绕过
# ========================================

project:
  name: "QMS Auditor"
  type: "ISO 管理体系认证审核自动化平台"
  target_users: "200+ 审核员，中型偏大认证机构（ACM 级）"
  team_size: 2
  development_mode: "AI Vibe Coding（代码生成器 60% + AI 辅助 30% + 人工核心 10%）"

# ------------ 技术栈全局锁定 ------------
tech_stack:
  backend:
    language: "C# 12"
    framework: "ASP.NET Core 9 Minimal API / VOL.Vue.NetCore"
    orm: "Entity Framework Core 9 + SqlSugar（VOL 自带）"
    database: "PostgreSQL 16"
    cache: "Redis（StackExchange.Redis）"
    message_queue: "RabbitMQ（P1 阶段引入）"
    auth: "JWT Bearer + Refresh Token"
    validation: "FluentValidation"
    background_jobs: "Hangfire"
    workflow: "Elsa Core（.NET 原生）"
  frontend:
    framework: "Vue 3.5 + Composition API + TypeScript 5.x"
    ui_library: "Element Plus 2.x"
    build_tool: "Vite"
    state_management: "Pinia"
    router: "Vue Router 4"
    http_client: "Axios（拦截器统一错误处理）"
    mobile: "UniApp（审核员现场取证端）"
  ai_engine:
    language: "Python 3.11+"
    framework: "FastAPI"
    llm: "通过 API 调用（支持多模型切换）"
    ocr: "PaddleOCR / Tesseract"
    nlp: "微调模型 + RAG"
    communication: "HTTP REST（AI 引擎独立部署，不耦合 .NET 进程）"
  infra:
    compose: "Docker Compose（开发/测试）"
    reverse_proxy: "Nginx"
    deployment: "自购服务器 + Docker + ZeroTier 组网"

# ------------ 代码生成策略 ------------
code_generation_rules:
  - "所有单表/主从 CRUD 由 VOL 代码生成器产出，**严禁手写**"
  - "自定义逻辑写在 Partial 目录（Controller/Service/Repository），不被生成器覆盖"
  - "Generic Service / Generic Controller 统一 CRUD 入口，不重复造轮子"
  - "视图模型与实体严格分离：Entity → ViewModel（AutoMapper）→ DTO（API 返回）"

# ------------ 命名与风格 ------------
naming:
  database:
    table: "PascalCase（如 AuditTask、NonconformityReport）"
    column: "PascalCase（与 Entity 属性完全一致）"
    primary_key: "Id / Code（雪花 ID + 业务 GUID 双主键）"
  backend:
    namespace: "QMS.Auditor.{Module}"
    controller: "{Entity}Controller（Partial）"
    service: "{Entity}Service（接口 + 实现）"
    repository: "{Entity}Repository"
    dto: "{Entity}Dto / {Entity}CreateDto / {Entity}UpdateDto"
    viewmodel: "{Entity}ViewModel"
  frontend:
    component: "PascalCase.vue（单文件组件）"
    composable: "use{Feature}.ts"
    store: "{module}.ts（Pinia）"
    api: "{module}.ts（按业务域拆分）"
    route: "kebab-case（URL 路径，如 /audit-tasks/:id）"

# ------------ 绝对禁止 ------------
forbidden:
  - "禁止手写单表 CRUD 代码（代码生成器 > 手写）"
  - "禁止在非 Partial 目录修改生成器产出的文件"
  - "禁止引入未经技术栈锁定的 NuGet/npm 包（新增依赖须先在宪法中审批）"
  - "禁止在 .NET 进程中直接调用 Python 模型（走 HTTP 调用 AI 引擎）"
  - "禁止使用 var 推断导致类型不可读的场景（Repository/Service 返回类型须显式声明）"
  - "禁止使用 'Any CPU' 编译目标（固定 x64）"
  - "禁止在 Controller 中写业务逻辑（Controller → Service → Repository，严格三层）"
  - "禁止在 Vue 模板中写复杂逻辑（提取为 computed 或 composable）"

# ------------ 必须执行 ------------
must:
  - "所有 API 返回统一格式：ApiResult<T> { Code, Message, Data, Timestamp }"
  - "所有数据库查询使用 AsNoTracking()（读）或完整 Entity 变更追踪（写）"
  - "敏感字段（密码/密钥）禁止出现在日志或 API 响应中"
  - "所有文件上传走分片 + 秒传 + 断点续传机制"
  - "所有删除操作软删除（IsDeleted + DeletedAt + DeletedBy）"
  - "所有审计日志写入独立 AuditLog 表（EF Core Interceptor 拦截）"
  - "前端所有 API 调用须在 axios 拦截器中统一处理 401 和网络异常"
```

### 2.2 宪法执行机制

| 层级 | 执行方式 | 负责方 |
|------|---------|--------|
| 编译时 | .editorconfig / Directory.Build.props | CI |
| 静态分析 | SonarQube / StyleCop 规则集 | CI |
| AI 生成时 | 宪法注入 System Prompt | AI |
| 代码审查时 | 宪法对照 Checklist | 人工 |

## 五、Skills 体系

### 5.1 Skill 设计原则

```
1. 单一职责：一个 Skill 只做一件事
2. 自包含：Skill 引用的所有规范必须包含在 Skill 文件内或指向明确路径
3. 可验证：Skill 包含输出检查清单
4. 可组合：多个 Skill 可以协同完成复杂任务
```

### 5.2 核心 Skill 清单

| Skill 名称 | 文件 | 触发词 | 用途 |
|-----------|------|--------|------|
| **vol-crud** | skill-vol-crud.md | "生成 CRUD"/"新建模块" | 基于代码生成器产出的模板，生成 Partial Controller/Service/ViewModel |
| **entity-design** | skill-entity-design.md | "设计表结构"/"新建实体" | 生成 Entity 类 + EF 配置 + 数据库迁移 |
| **vue-page** | skill-vue-page.md | "新建页面"/"Vue 页面" | 生成 Vue SFC（查询+表格+分页+弹窗） |
| **vue-form** | skill-vue-form.md | "表单"/"录入页面" | 生成复杂表单（校验/联动/动态字段） |
| **api-design** | skill-api-design.md | "API"/"接口设计" | 设计 RESTful API 端点 + DTO |
| **audit-log** | skill-audit-log.md | "审计日志"/"操作记录" | EF Core Interceptor 审计日志实现 |

| **nc-lifecycle** | skill-nc-lifecycle.md | "不符合项"/"NC" | NC 全生命周期状态机 |
| **report-template** | skill-report-template.md | "审核报告"/"报告模板" | 报告模板生成（Word/PDF） |

### 5.3 Skill 文件模板

```markdown
# Skill: vol-crud —— 代码生成器 + Partial CRUD

## 前置条件
- 代码生成器已产出 Entity / Generic Controller / Generic Service / Vue 列表页
- 需要自定义的字段/业务逻辑

## 输入
- Entity 类名（如 AuditTask）
- 自定义字段列表
- 特殊校验规则

## 约束（从宪法继承）
- Partial Controller: `Controllers/{Entity}Controller.cs`
- Partial Service: `Services/{Entity}Service.cs`
- ViewModel: `ViewModels/{Entity}ViewModel.cs`
- 禁止修改 `*BaseController.cs` / `*BaseService.cs`

## 输出规范
- Controller 只做参数绑定和调用 Service
- Service 包含业务逻辑
- ViewModel 继承 BaseViewModel 或 AutoMapper Profile

## 检查清单
- [ ] 命名符合宪法规范
- [ ] 软删除字段已处理
- [ ] AsNoTracking 用于只读查询
- [ ] ApiResult<T> 统一返回
- [ ] FluentValidation 校验规则已添加
```

## 六、开发工作流

### 6.1 需求 → 交付全链路

```
需求录入（人类）
    │
    ▼
[AI] 解析需求，对照宪法/知识库，输出：
    ├── 新增 Entity（entity-design skill）
    ├── 新增数据库迁移
    ├── 代码生成器产出 CRUD 基类
    └── Partial 自定义逻辑
    │
    ▼
[人类] 审查：宪法规避检查 + 业务逻辑合理性
    │
    ▼
[AI] 生成前端页面（vue-page / vue-form skill）
    │
    ▼
[人类] UI/UX 审查：设计系统对齐性
    │
    ▼
[AI] 生成单元测试 + 集成测试
    │
    ▼
[CI] 编译 → 静态分析 → 测试 → Build Image
```

### 6.2 Git 工作流

```
分支策略：
  main          → 生产就绪（Merge Request + 审查）
  develop       → 集成测试
  feature/{module}-{desc} → 功能开发

AI 生成代码的 Commit 规范：
  feat(audit-task): AI-新增审核任务 CRUD
  fix(nc): AI-修复不符合项状态流转逻辑
  refactor(report): AI-重构报告模板服务

  规则：所有 AI 生成的 commit 消息以 "AI-" 前缀标记，
       便于追溯哪些代码是 AI 生成的，方便出问题时快速审查。
```

### 6.3 AI 代码的审查重点

| 检查项 | 频率 | 说明 |
|--------|------|------|
| 是否手写了应由生成器产出的代码 | 每次 | 宪法禁止项 |
| 是否引入了未审批的 NuGet/npm 包 | 每次 | 宪法禁止项 |
| 命名是否对齐宪法 | 每次 | 命名表对照 |
| 安全漏洞（SQL注入/XSS/敏感泄露） | 每次 | 静态分析 |
| 事务边界是否正确 | 涉及写操作 | SaveChanges 范围 |
| 是否存在 N+1 查询 | 涉及列表 | EF Core 日志 |
| 是否正确使用 AsNoTracking | 只读查询 | 性能 |
| 软删除是否遗漏 | 删除操作 | 数据完整性 |

## 七、可控性保障体系

### 7.1 三层防线

```
第一层：AI 自我约束（宪法注入 + Skill 加载）
    ↓ 拦截 70% 的问题
第二层：静态分析（.editorconfig + SonarQube + ESLint）
    ↓ 拦截 25% 的问题
第三层：人类审查（宪法 Checklist + 业务合理性）
    ↓ 拦截剩余 5%
```

### 7.2 AI 失控的典型信号与应对

| 信号 | 含义 | 应对 |
|------|------|------|
| AI 引入 `Microsoft.AspNetCore.Mvc.NewtonsoftJson` | 试图绕过 System.Text.Json | 宪法中新增禁止项 |
| AI 在 Controller 中写 50 行+ | 业务逻辑越界 | 强制 Service 层抽取 |
| AI 自主选择了 Ant Design | 无视 UI 库锁定 | 宪法中增强锁定粒度 |
| AI 每次生成风格不一致 | 知识库未覆盖该模式 | 补充 Skill |
| 同一类代码 AI 写了 3 次 | 缺少 Skill 或 Skill 未被触发 | 优化触发词 |

### 7.3 版更与宪法演进

4. 全量回归检查（宪法禁止项扫描已有代码）
