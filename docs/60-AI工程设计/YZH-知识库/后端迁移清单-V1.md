## 〇、架构现状摘要

### 老后台（Vol Framework）
- 后端：vol.api/、.NET 8 + Vol + EF Core + MySql（端口 9992）
- 前端：vol.web/（保留不删，仅作历史参考）
- 架构：Partial Service + 代码生成 .jsx + VolController + ViewGrid

- 后端：yzh-core/YZH.Core.Web/ ← 手写 API（保留 Vol 后端 9992 并行运行）
- 前端：certplatform-web/（admin 9990 / auditor 9991）
- 架构：自研 YzhTable + YzhForm + YzhApiClient + 手写 Controller

## 六、验收标准

### 单条业务迁移完成标准

1. [ ] 新 Controller 提供 GetPageData 接口，返回格式符合 PageRequest → PageResponse
2. [ ] 前端 YzhTable 正确渲染后端数据
3. [ ] 老 Vol 页面不再使用（保留代码、路由可禁用）
4. [ ] `[Column]` 错误已清理、VIEW 已创建（如需要）
5. [ ] 编译通过（`dotnet build YZH.Core.csproj` 0 错误）

### 整体验收标准

1. [ ] admin 端所有菜单功能可由新后台支撑
2. [ ] auditor 端核心功能（待办/审核/报告）可运行
3. [ ] 老 vol.web 标记为 deprecated，不再接受新功能
4. [ ] 前端 YzhApiClient 统一走新 API 路径（/api/ 前缀）

## 七、执行约束

- 每完成一条业务迁移，立即验证编译 + API 可调用
- 后端修复 [Column] 时，先确认该表实际 MySQL 列名再改
- VIEW 列名必须 PascalCase（与 C# 属性名对应，EF 大小写不敏感但可读性优先）
- 保持 Vol 后端 9992 运行，新后端（yzh-core）在未稳定前不影响老业务
