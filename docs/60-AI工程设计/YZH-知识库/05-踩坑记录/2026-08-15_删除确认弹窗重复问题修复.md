# 删除确认弹窗重复问题修复

> **日期**：2026-08-15  
> **类型**：UI 交互优化  
> **影响范围**：所有使用 YzhCrudTable 和 YzhDataTable 组件的页面  
> **严重程度**：中（用户体验问题，不影响功能）

## 问题现象

在认证机构管理页面 (`/CertPlatform/Cert/CertificationBody`) 点击删除按钮时，会弹出**两个确认对话框**：
1. 第一个来自 `el-popconfirm` 组件
2. 第二个来自 `YZHEditGuard.confirmDeleteOne` 方法

用户需要确认两次才能完成删除操作，体验不佳。

## 根本原因分析

### 组件架构

前端 CRUD 组件的删除按钮被两层确认机制包裹：

```
YzhCrudTable.vue / YzhDataTable.vue
├── el-popconfirm（第一层确认）← 冗余
│   └── <button @click="handleDelete">
│       └── YZHEditGuard.confirmDeleteOne()（第二层确认）← 正确
```

### 为什么会有两层

1. **`el-popconfirm`**：Element Plus 的气泡确认框，是 UI 模板的默认实现
2. **`YZHEditGuard.confirmDeleteOne`**：YZH 框架的业务逻辑守卫，提供：
   - 权限检查
   - 业务规则验证（如关联数据检查）
   - 统一的确认文案和样式
   - 操作日志记录

`YZHEditGuard` 已经提供了完整的确认机制，`el-popconfirm` 是多余的。

## 修复方案

### 原则

**保留 `YZHEditGuard.confirmDeleteOne`，移除 `el-popconfirm`**

理由：
1. `YZHEditGuard` 是框架统一的业务守卫，提供更丰富的功能
2. 保持与其他操作（新增、编辑）的一致性
3. 便于后续扩展（如添加批量删除、权限控制等）

### 修改文件

#### 1. YzhCrudTable.vue

**文件路径**：`src/server/Vue.NetCore/vol.web/src/yzh/components/YzhCrudTable.vue`

**修改位置**：第 184-188 行（删除按钮区域）

```vue
<!-- 修改前（错误） -->
<el-popconfirm
  title="确定要删除这条数据吗？"
  confirm-button-text="确定"
  cancel-button-text="取消"
  @confirm="handleDelete(scope.row)"
>
  <template #reference>
    <el-button type="danger" link size="small">
      <el-icon><Delete /></el-icon>
      删除
    </el-button>
  </template>
</el-popconfirm>

<!-- 修改后（正确） -->
<el-button type="danger" link size="small" @click="handleDelete(scope.row)">
  <el-icon><Delete /></el-icon>
  删除
</el-button>
```

#### 2. YzhDataTable.vue

**文件路径**：`src/server/Vue.NetCore/vol.web/src/yzh/components/YzhDataTable.vue`

**修改位置**：第 92-96 行（删除按钮区域）

修改内容同上，移除 `el-popconfirm` 包裹。

## 技术细节

### YZHEditGuard.confirmDeleteOne 工作流程

```
用户点击删除按钮
    ↓
handleDelete(row) 被调用
    ↓
YZHEditGuard.confirmDeleteOne(row, options)
    ├── 1. 权限检查（是否有删除权限）
    ├── 2. 业务规则验证（如：是否有关联数据）
    ├── 3. 弹出确认对话框（ElMessageBox.confirm）
    │   └── 用户点击"确认"
    ├── 4. 调用 API 执行删除
    ├── 5. 刷新表格数据
    └── 6. 显示成功提示（ElMessage.success）
```

### 为什么不反过来（保留 popconfirm，移除 YZHEditGuard）

如果只保留 `el-popconfirm` 而移除 `YZHEditGuard`：

❌ **缺点**：
1. 无法进行权限检查
2. 无法执行业务规则验证
3. 删除逻辑分散在各组件，难以维护
4. 无法统一记录操作日志
5. 与新增/编辑操作的交互模式不一致

✅ **当前方案的优点**：
1. 统一的交互入口
2. 可扩展性强（后续可添加批量删除、软删除等）
3. 符合框架设计理念（声明式 + 约定优于配置）
4. 代码量减少（移除了 popconfirm 模板代码）

## 相关组件说明

### YzhCrudTable.vue

**用途**：标准 CRUD 表格组件，适用于大多数管理页面

**特性**：
- 内置分页、排序、筛选
- 支持新增/编辑/删除/导出
- 可配置列显示、字段类型
- 集成 YZHEditGuard 守卫

### YzhDataTable.vue

**用途**：轻量级数据表格组件，适用于只读或简单编辑场景

**特性**：
- 比 YzhCrudTable 更轻量
- 支持基本的数据展示和操作
- 同样集成 YZHEditGuard 守卫

### YZHEditGuard.ts

**用途**：业务逻辑守卫，提供统一的操作前验证

**核心方法**：
- `confirmDeleteOne()` - 单条删除确认
- `confirmDeleteBatch()` - 批量删除确认
- `beforeAdd()` - 新增前验证
- `beforeUpdate()` - 编辑前验证

## 后续优化建议

### 1. 添加批量删除确认

当前只修复了单条删除的重复确认问题。如果需要添加批量删除功能：

```vue
<!-- 批量删除按钮 -->
<el-button 
  type="danger" 
  :disabled="!selectedRows.length"
  @click="handleBatchDelete"
>
  批量删除 ({{ selectedRows.length }})
</el-button>

<script setup>
const handleBatchDelete = async () => {
  await YZHEditGuard.confirmDeleteBatch(selectedRows, {
    title: '批量删除确认',
    message: `确定要删除选中的 ${selectedRows.length} 条数据吗？此操作不可恢复。`
  });
};
</script>
```

### 2. 自定义确认文案

不同场景可能需要不同的确认文案：

```typescript
// 危险操作（如删除认证机构）
await YZHEditGuard.confirmDeleteOne(row, {
  title: '⚠️ 危险操作',
  message: '删除该机构将同时删除其下所有企业和审核数据，确定继续吗？',
  type: 'warning'
});

// 普通操作（如删除单条记录）
await YZHEditGuard.confirmDeleteOne(row); // 使用默认文案
```

### 3. 添加操作日志

在 `YZHEditGuard.confirmDeleteOne` 中增加日志记录：

```typescript
export async function confirmDeleteOne(row: any, options?: ConfirmOptions) {
  // ... 现有逻辑
  
  // 记录操作日志
  await OperationLogService.record({
    action: 'DELETE',
    entity: row.constructor.name,
    entityId: row.Id,
    userId: UserContext.Current.UserId,
    timestamp: new Date()
  });
}
```

## 总结

### 本次修复的核心价值

1. **提升用户体验**：消除重复确认的困扰
2. **统一交互模式**：所有 CRUD 操作使用相同的确认机制
3. **代码简化**：移除冗余的模板代码
4. **为后续扩展铺路**：基于 YZHEditGuard 可以轻松添加新功能

### 修复前后对比

| 维度 | 修复前 | 修复后 |
|------|--------|--------|
| 确认次数 | 2 次 | 1 次 |
| 代码行数 | ~20 行（popconfirm 模板） | ~5 行（纯按钮） |
| 可扩展性 | 低（逻辑分散） | 高（集中在 Guard） |
| 一致性 | 与新增/编辑不一致 | 完全一致 |
