## 一、常见路由问题汇总

### 1.1 前端 SyntaxError: Unexpected token '{'

**现象**：浏览器控制台报错 `SyntaxError: Unexpected token '{'`

**原因**：
- `viewGird.js` 文件末尾有多余的 `]` 或 `{`
- 数组未正确闭合
- 添加了重复的路由配置

**解决方案**：
```javascript
// ❌ 错误示例：重复的数组闭合
let viewgird = [
  { path: '/test', name: 'Test', ... }
]

// 额外添加的路由（多余）
{ path: '/test2', name: 'Test2', ... }
]  // 这个 ] 是多余的！

// ✅ 正确示例
let viewgird = [
  { path: '/test', name: 'Test', ... },
  { path: '/test2', name: 'Test2', ... }
]

export default viewgird
```

**检查方法**：
```bash
# 检查文件末尾是否有重复的闭合符号
tail -20 /path/to/viewGird.js

# 使用 node 语法检查
node -c /path/to/viewGird.js
```

### 1.2 路由 404: No match found for location with path

**现象**：
```
[Vue Router warn]: No match found for location with path "/CertPlatform/Standard"
```

**原因**：
- 数据库菜单 URL 在前端路由中不存在
- 路由路径不匹配（大小写、斜杠等）
- 路由数组未正确导出

**解决方案**：

**步骤 1：确认数据库菜单 URL**
```sql
SELECT Menu_Id, MenuName, ParentId, Url 
FROM Sys_Menu 
WHERE MenuName LIKE '%标准目录%';
```

**步骤 2：确认前端路由配置**
```javascript
// viewGird.js 中必须包含相同的 path
{
  path: '/CertPlatform/Standard',  // 必须与数据库 URL 完全一致
  name: 'StandardDirectory',
  component: () => import('@/views/cert/Standard/xxx.vue'),
  meta: { title: '标准目录管理' }
}
```

**步骤 3：检查路由导出**
```javascript
// 确保文件最后有这行
export default viewgird
```

### 1.3 HTTP 405 Method Not Allowed

**现象**：
```
POST http://localhost:9991/api/standard-directory/configs 405 (Method Not Allowed)
```

**原因**：
- Controller 中同时存在同路径的不同 HTTP 方法
- ASP.NET Core 无法区分路由

**解决方案**：

**❌ 错误示例**：
```csharp
[HttpPost("configs")]
public IActionResult GetConfigs() { }

[HttpPost("configs")]
public IActionResult CreateConfig() { }
// 两个方法都是 POST + configs，路由冲突！
```

**✅ 正确示例**：
```csharp
// GET 列表
[HttpGet("configs")]
public IActionResult GetConfigs() { }

// POST 创建 - 使用不同的子路径
[HttpPost("configs/create")]
public IActionResult CreateConfig() { }

// PUT 更新
[HttpPut("configs/{code}")]
public IActionResult UpdateConfig(string code) { }

// DELETE 删除
[HttpDelete("configs/{code}")]
public IActionResult DeleteConfig(string code) { }
```

**记忆技巧**：
```
GET    /api/resource        → 列表
GET    /api/resource/{id}   → 详情
POST   /api/resource/create → 创建
PUT    /api/resource/{id}   → 更新
DELETE /api/resource/{id}   → 删除
```

### 1.4 实体类缺少主键定义

**现象**：
```
The entity type 'StandardDirectoryConfig' requires a primary key to be defined.
```

**原因**：
- 自定义实体类继承 `BaseEntity`，但 `BaseEntity` 没有定义主键
- EF Core 无法自动识别主键

**解决方案**：

**方式 1：添加主键属性**
```csharp
public class StandardDirectoryConfig : BaseEntity
{
    [Key]
    [DatabaseGenerated(DatabaseGeneratedOption.Identity)]
    public long Id { get; set; }
    
    // 其他属性...
}
```

**方式 2：继承已有主键的基类**
```csharp
// 如果 BaseEntity 没有 Id，可以继承 YZHBaseEntity
public class StandardDirectoryConfig : YZHBaseEntity
{
    // YZHBaseEntity 已经定义了 Id 属性
}
```

**检查清单**：
- [ ] 实体类是否继承自有主键的基类
- [ ] 是否添加了 `[Key]` 特性
- [ ] 是否添加了 `[DatabaseGenerated]` 特性

### 1.5 Autofac 服务注册失败

**现象**：
```
Unable to resolve service for type 'ICodeGeneratorService' 
while attempting to activate 'StandardDirectoryService'
```

**原因**：
- 服务接口未继承 `IDependency`
- 实现类未继承 `IDependency`

**解决方案**：

**✅ 正确的接口定义**：
```csharp
using VOL.Core.Extensions.AutofacManager;

namespace VOL.Builder.IServices.CertPlatform
{
    public interface ICodeGeneratorService : IDependency
    {
        string GenerateDirectoryCode(string standardCode, string phaseCode);
    }
}
```

**✅ 正确的实现类定义**：
```csharp
using VOL.Core.Extensions.AutofacManager;

namespace VOL.Builder.Services.CertPlatform
{
    public class CodeGeneratorService : ICodeGeneratorService, IDependency
    {
        // 实现代码...
    }
}
```

**记忆技巧**：
```
所有 Service 接口必须继承 IDependency
所有 Service 实现必须同时继承接口 AND IDependency
```

## 二、完整配置流程检查清单

### Phase 1: 数据库菜单配置

```sql
-- 1. 确认父级菜单 ID
SELECT Menu_Id, MenuName FROM Sys_Menu WHERE MenuName LIKE '%体系认证%';

-- 2. 插入新菜单
INSERT INTO Sys_Menu (MenuName, ParentId, Url, OrderNo, Icon, MenuType, Enable, Creator, CreateDate)
VALUES ('标准目录管理', 305, '/CertPlatform/Standard', 90, 'el-icon-setting', 0, 1, '超级管理员', NOW());

-- 3. 插入子菜单
SET @parent_id = LAST_INSERT_ID();
INSERT INTO Sys_Menu (MenuName, ParentId, Url, OrderNo, Icon, MenuType, Enable, Creator, CreateDate)
VALUES 
('目录配置', @parent_id, '/CertPlatform/Standard/DirectoryConfig', 1, '', 1, 1, '超级管理员', NOW()),
('文件夹结构', @parent_id, '/CertPlatform/Standard/DirectoryTree', 2, '', 1, 1, '超级管理员', NOW());

-- 4. 分配权限
INSERT INTO Sys_RoleAuth (Role_Id, Menu_Id, AuthValue, Creator, CreateDate)
VALUES 
(10, @parent_id + 1, '["Search"]', '超级管理员', NOW()),
(20, @parent_id + 1, '["Search","Add","Delete","Update"]', '超级管理员', NOW());
```

**检查项**：
- [ ] 父菜单 URL 是否正确
- [ ] 子菜单 URL 是否与前端路由匹配
- [ ] 权限是否已分配给管理员角色（Role_Id=20）

### Phase 2: 前端路由配置

- [ ] 是否有重复的路由配置

### Phase 3: 后端 API 配置

```csharp
// StandardDirectoryController.cs
[Route("api/standard-directory")]
[ApiController]
[JWTAuthorize]
public class StandardDirectoryController : ControllerBase
{
    // GET 列表
    [HttpGet("configs")]
    public IActionResult GetConfigs() { }
    
    // GET 单个
    [HttpGet("configs/{directoryCode}")]
    public IActionResult GetConfig(string directoryCode) { }
    
    // POST 创建 - 注意路径不同
    [HttpPost("configs/create")]
    public IActionResult CreateConfig([FromBody] StandardDirectoryConfig config) { }
    
    // PUT 更新
    [HttpPut("configs/{directoryCode}")]
    public IActionResult UpdateConfig(string directoryCode, [FromBody] StandardDirectoryConfig config) { }
    
    // DELETE 删除
    [HttpDelete("configs/{directoryCode}")]
    public IActionResult DeleteConfig(string directoryCode) { }
}
```

**检查项**：
- [ ] 每个 HTTP 方法的路径是否唯一
- [ ] 是否添加了 `[ApiController]` 特性
- [ ] 是否添加了 `[JWTAuthorize]` 特性

## 三、问题排查流程图

```
前端页面报错
    │
    ├─→ SyntaxError
    │       └─→ 检查 viewGird.js 语法
    │               └─→ 是否有重复的 ] 或 {
    │
    ├─→ 404 No match found
    │       └─→ 检查数据库菜单 URL
    │               └─→ 检查前端路由是否匹配
    │                       └─→ 检查 export default 是否存在
    │
    ├─→ 405 Method Not Allowed
    │       └─→ 检查 Controller 路由冲突
    │               └─→ 确保同一路径只有一种 HTTP 方法
    │
    └─→ 启动失败
            └─→ 检查 Service 是否继承 IDependency
                    └─→ 检查实体是否有主键
```
