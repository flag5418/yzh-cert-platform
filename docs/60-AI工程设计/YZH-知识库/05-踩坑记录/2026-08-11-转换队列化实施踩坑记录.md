## 踩坑 1：循环依赖 VOL.Builder ↔ VOL.WebApi

### 现象
```
error CS0234: 命名空间"VOL"中不存在类型或命名空间名"WebApi"
error CS0246: 未能找到类型或命名空间名"HomePageMessageHub"
```

### 原因
`ConvertQueueManager` 在 `VOL.Builder` 项目中，需要引用 `HomePageMessageHub`（在 `VOL.WebApi` 中）。
但 `VOL.WebApi` 已经引用了 `VOL.Builder`，形成循环依赖。

### 解决方案：接口解耦
1. 在 `VOL.Builder/IServices/` 中定义 `IConvertNotifier` 接口
2. 在 `VOL.WebApi/Hubs/` 中实现 `ConvertNotifier : IConvertNotifier`
3. `ConvertQueueManager` 注入 `IConvertNotifier` 而非 `IHubContext<HomePageMessageHub>`

### 教训
- 跨项目引用 SignalR Hub 时，必须用接口解耦
- `VOL.Builder` 是业务层，不能引用 `VOL.WebApi` 表现层

## 踩坑 2：ControllerBase 没有 JsonNormal / Json 方法

### 现象
```
error CS0103: 当前上下文中不存在名称"JsonNormal"
error CS0103: 当前上下文中不存在名称"Json"
```

### 原因
- `JsonNormal()` 是 `VolController` 基类的 protected 方法
- `Json()` 是 `Controller` 类的方法（不是 `ControllerBase`）
- `SysConfigController` 和 `MessageController` 继承的是 `ControllerBase`，没有这些方法

### 解决方案
使用 `new JsonResult(object)` 替代：
```csharp
// 错误：
return JsonNormal(new { status = true });

// 正确：
return new JsonResult(new { status = true });
```

### 教训
- Vol 框架中，继承 `ApiBaseController<T>` 的控制器才有 `JsonNormal`
- 自定义 `ControllerBase` 控制器用 `new JsonResult()`

## 踩坑 3：MySQL 不支持 RETURNING 语法

### 现象
`FromSqlRaw` 中使用了 `UPDATE ... RETURNING *`，MySQL 报语法错误。

### 原因
`RETURNING *` 是 PostgreSQL 语法，MySQL 不支持。

### 解决方案：两步操作
```csharp
// 1. SELECT 查找（FOR UPDATE SKIP LOCKED）
var job = await db.Set<ConvertJob>()
    .FromSqlRaw("SELECT * FROM ... WHERE status='pending' FOR UPDATE SKIP LOCKED LIMIT 1")
    .FirstOrDefaultAsync();

// 2. UPDATE 更新状态
job.Status = "processing";
await db.SaveChangesAsync();
```

### 教训
- MySQL 的行锁用 `FOR UPDATE SKIP LOCKED`
- 不能用 PostgreSQL 的 `RETURNING` 语法

## 踩坑 4：端口 9991 冲突

### 现象
```
Failed to bind to address http://[::]:9991: address already in use
```

### 原因
- `Program.cs` 第 145 行硬编码 `builder.WebHost.UseUrls("http://*:9991")`
- 审核员前端也使用 9991 端口
- 两者不能同时运行

### 解决方案
全局修正 9991 → 9992：
| 文件 | 改动 |
|------|------|
| `Program.cs` (vol.api) | `UseUrls("http://*:9992")` |
| `Program.cs` (vol.api.sqlsugar) | `UseUrls("http://*:9992")` |
| `http.js` | `baseURL = 'http://localhost:9992/'` |
| `DirectoryManager/index.vue` | fallback `http://localhost:9992/` |
| `YZHConfigLoader.ts` | 注释 `http://localhost:9992/` |

### 教训
- 端口配置应从系统参数读取，不硬编码
- 速查表定义的端口（后端 9992）是最终标准

## 踩坑 5：HttpClient.Headers 不存在

### 现象
```
error CS1061: "HttpClient"未包含"Headers"的定义
```

### 原因
`YZH.Core/AI/Clients/QwenApiProvider.cs` 中使用了 `http.Headers.Authorization`，但 `HttpClient` 没有 `Headers` 属性。

### 解决方案
```csharp
// 错误：
http.Headers.Authorization = new AuthenticationHeaderValue("Bearer", apiKey);

// 正确：
http.DefaultRequestHeaders.Authorization = new AuthenticationHeaderValue("Bearer", apiKey);
```

### 教训
- `HttpClient` 用 `DefaultRequestHeaders` 设置全局请求头
- 单次请求用 `HttpRequestMessage.Headers`
