## 问题现象

1. **勾选/取消勾选后无法保存**：前端显示差异计算正常，但后端 API 返回 500 错误
2. **错误信息**：`Cannot create a DbSet for 'CertOrgStandard' because this type is not included in the model for the context`
3. **表格列显示问题**：分类和状态显示英文代码而非中文

## 根因分析（4 个问题叠加）

### 问题 1：实体未继承 BaseEntity（最严重）

**现象**: 后端返回 500 错误，`Cannot create a DbSet for 'CertOrgStandard'`

**根因**: 
- EF Core 通过反射扫描实体时，要求实体必须继承自 `BaseEntity`
- `CertOrgStandard` 和 `CertOrgStage` 只继承了 `BaseEntity`（空基类），但没有继承 `YZHBaseEntity`
- `VOLContext.OnModelCreating` 中的扫描逻辑：
  ```csharp
  assembly.GetTypes()
      .Where(x => typeof(BaseEntity).IsAssignableFrom(x)  // ← 必须继承 BaseEntity
                  && x != typeof(BaseEntity)
                  && !x.IsAbstract
                  && x.GetCustomAttribute<NotMappedAttribute>() == null)
  ```

**解决方案**: 让实体继承 `BaseEntity`（已有 `[Entity]` 属性）

```csharp
// ❌ 错误：只继承空类
public class CertOrgStandard { }

// ✅ 正确：继承 BaseEntity
public class CertOrgStandard : BaseEntity { }
```

**教训**:
- 所有需要 EF Core 管理的实体必须继承 `BaseEntity`
- 关联表、配置表等简单实体也需要继承 `BaseEntity`
- `[Entity]` 属性只是标记，不继承 `BaseEntity` 仍然无法被扫描

---

### 问题 2：实体缺少 [Entity] 属性

**现象**: 实体类存在但未被 EF Core 识别

**根因**: 
- `CertOrgStandard` 和 `CertOrgStage` 缺少 `[Entity]` 属性
- 没有 `[Entity]` 属性，EF Core 不会扫描到这个实体

**解决方案**: 添加 `[Entity]` 属性

```csharp
[Entity(TableCnName = "机构-标准关联", TableName = "cert_org_standard", DBServer = "VOLContext")]
[Table("cert_org_standard")]
public class CertOrgStandard : BaseEntity
{
    // ...
}
```

**教训**:
- `[Entity]` 属性是 EF Core 扫描的必要条件
- 必须指定 `DBServer = "VOLContext"` 才能注册到正确的 DbContext

---

### 问题 3：前端查询条件字段错误

**现象**: 机构树无法加载，返回空数据

**根因**: 
- 前端使用 `Enable` 字段过滤：`filter: [{ name: 'Enable', value: true, ... }]`
- 但实际数据库字段是 `Status`（枚举类型：active/inactive）

**解决方案**: 修改前端查询条件

```javascript
// ❌ 错误
filter: [{ name: 'Enable', value: true, displayType: '==' }]

// ✅ 正确
filter: [{ name: 'Status', value: 'active', displayType: '==' }]
```

**教训**:
- 开发前必须查看数据库表结构或实体定义
- 不要假设字段名，必须确认实际字段名

---

### 问题 4：前端表格列配置错误

**现象**: 分类和状态显示英文代码而非中文

**根因**: 
- 前端使用 `dataKey` 属性进行字典翻译：`{ field: 'Category', dataKey: 'stage_category' }`
- 但后端视图已返回翻译后的中文字段：`CategoryName`、`StatusName`
- 应该直接使用视图字段，不需要字典翻译

**解决方案**: 修改表格列配置

```javascript
// ❌ 错误：使用字典翻译
{ field: 'Category', title: '分类', dataKey: 'stage_category' }
{ field: 'Status', title: '状态', dataKey: 'stage_status' }

// ✅ 正确：使用视图字段
{ field: 'CategoryName', title: '分类', width: 120 }
{ field: 'StatusName', title: '状态', width: 100 }
```

**教训**:
- 使用 T+V 模式时，列表显示应该直接使用视图字段
- 字典翻译只在编辑表单和搜索表单中使用

## 经验总结

### 1. 实体注册的必要条件

EF Core 实体注册需要**同时满足**以下条件：

1. 继承 `BaseEntity`（或任何非抽象基类）
2. 添加 `[Entity]` 属性
3. `[Entity]` 属性中指定正确的 `DBServer`
4. 实体类必须公开（`public`）
5. 不能有 `[NotMapped]` 属性

**检查清单**:
- [ ] 实体继承 `BaseEntity`？
- [ ] 实体有 `[Entity]` 属性？
- [ ] `[Entity]` 的 `DBServer` 是否正确？
- [ ] 实体类是否 `public`？

---

### 2. T+V 模式的使用规范

**什么时候使用 T+V 模式？**
- 列表显示需要字典翻译 → 使用视图
- 编辑表单需要原始字段 → 使用实体

**视图字段 vs 实体字段的使用场景：**

| 场景 | 使用字段 | 示例 |
|------|---------|------|
| 列表显示 | 视图字段 | `CategoryName`, `StatusName` |
| 编辑表单 | 实体字段 | `Category`, `Status` |
| 搜索表单 | 实体字段 | `Category`, `Status` |

---

**什么时候提取公共组件？**
- 两个页面有 >70% 相同代码
- 业务逻辑相似但数据源不同
