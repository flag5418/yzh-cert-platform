## 1️⃣ P2-01 数据库字段命名全栈错位（根因级）

### 问题现象
`POST /api/CertCertificationBody/getPageData` 返回 500，MySQL 报错找不到 `CbCode`、`CreateDate` 等列。

### 根因分析
项目采用 **三层命名混叠**：
1. 早期 SQL 脚本使用 **snake_case**（`cb_code`, `create_time`）；
2. `YZHBaseEntity` 基类与 VOL 框架默认使用 **PascalCase**（`CbCode`, `CreateDate`）；
3. 前端 `options.js` 生成器输出为 **PascalCase**。

EF Core 默认走属性名→列名的 PascalCase 映射，生成的 SQL 引用 `c.CbCode`，而物理表列仍是 `cb_code`，直接炸裂。

### 解决方案

> ⚠️ **官方文档对照**：Vol 框架的 `repository.FindAsIQueryable(x => 条件)` 默认使用 C# 属性名作为 SQL 列名（见 [db.html](http://v3.volcore.xyz/docs/cs/dev/db.html)）。框架内置表（如 `Sys_Menu`、`Sys_User`）全部使用 PascalCase 列名。YZH 自建表应**遵循同一约定**。

**两种修复路径（本项目选择路径 A）**：

| 路径 | 方式 | 适用场景 |
|------|------|----------|
| **A（本项目采用）** | 三端强制对齐 PascalCase，删除 `[Column]` 特性 | 新项目，表可重建 |
| **B（备选）** | 保留 snake_case 列名，每个属性加 `[Column("snake_case")]` | 已有数据库不可改 |

**路径 A 具体操作**：

| 端 | 修复手段 | 工具/脚本 |
|----|----------|----------|
| 数据库 | 全量 DROP + 重建所有 Cert 业务表，列名统一 PascalCase | `scripts/fix_sql_v3.py` + `scripts/run_db_migration.py` |
| 后端实体 | 删除所有 `CertPlatform` 实体中的 `[Column("xxx")]` 特性，依赖 EF 默认映射 | 手工校验 `VOL.Entity/CertPlatform/**/*.cs` |
| 前端配置 | 确保 `options.js` `field` / `sortName` / `searchFields` 全部 PascalCase | 已由生成器保障，辅以 Grep 抽检 |

> **注意**：路径 A 中「删除 `[Column]` 特性」仅适用于列名与属性名一致的情况。若列名与属性名不同（如 snake_case 列名），**必须**使用路径 B 保留 `[Column]` 特性（参见 [2026-08-07 EF Core Column 映射踩坑](./2026-08-07_EF-Core-Column映射snake_case导致400错误.md)）。

**修正后的命名约定（宪法级）**：
```
审计字段：
  CreateID (BIGINT)  /  Creator      /  CreateDate (DATETIME)
  ModifyID (BIGINT)  /  Modifier     /  ModifyDate (DATETIME)

业务字段示例：
  cert_certification_body：Name, ShortName, CbCode, ContactName, ContactPhone
  cert_audit_task：TaskNumber, PhaseCode, AuditorId, Status, PlannedDate
```

### 预防措施
- 新增字段时：先改实体属性（PascalCase）→ 写 `ALTER TABLE` 脚本 → 前端加 field；
- 禁止直接在 Navicat 改表后反向生成实体。

## 2️⃣ P2-02 Partial Service 构造函数依赖注入丢失

### 问题现象
`ServiceBase<T>.GetPageData` 报 `repository` 为 null，`NullReferenceException`。

### 根因分析
Autofac 在解析 Partial 类的多层继承构造函数时，若显式声明了自定义构造函数而未使用 `ActivatorUtilitiesConstructor` 标记，框架回退到无参构造，导致 `repository`、`unitWork` 字段均未初始化。

> **官方文档对照**：[db.html](http://v3.volcore.xyz/docs/cs/dev/db.html) 「跨业务类库访问其他表」章节明确给出了 `[ActivatorUtilitiesConstructor]` 标记的模板代码。这是 Vol 框架的标准做法，非自定义。

### 解决方案
所有 CertPlatform 的 Partial Service 构造函数必须符合以下三点：

```csharp
// Partial/CertCertificationBodyService.cs (PATTERN)
using Microsoft.Extensions.DependencyInjection; // ActivatorUtilitiesConstructor

namespace VOL.Builder.Services.CertPlatform
{
    public partial class CertCertificationBodyService
    {
        [ActivatorUtilitiesConstructor] // ← 必须
        public CertCertificationBodyService(
            IRepository<CertificationBody> repository,
            IUnitWork unitWork
        ) : base(repository, unitWork) // ← 必须传参
        {
            this.repository = repository; // ← 显式兜底赋值，防止反射丢失
        }
    }
}
```

**同时**在 `GetPageData` 重写内加入 Autofac 手动解析兜底：
```csharp
public override PageGridData<CertificationBody> GetPageData(PageDataOptions options)
{
    if (this.repository == null)
    {
        this.repository = AutofacContainerModule.GetService<IRepository<CertificationBody>>();
    }
    return base.GetPageData(options);
}
```

### 预防措施
写 Partial Service 时一律复制上述模板，禁止手写空构造。

## 3️⃣ P2-03 EF 实体扫描误伤非数据库类

### 问题现象
启动时报 `InvalidOperationException: The entity type 'FilterOptions' requires a primary key to be defined.`

### 根因分析
VOLContext 扫描实体时，将 `VOL.Core/Objects/FilterOptions.cs` 等标记为内部类（未加 `[NotMapped]`）但继承链可落入扫描范围的类型强行映射，最终报 `object` 属性无法映射。

### 解决方案
在 `VOL.Core/EFDbContext/VOLContext.cs` 「OnModelCreating 扫描逻辑」中，将实体注册条件从“继承 BaseEntity”加了两层校验：

```csharp
// 已落地在 VOLContext.cs 中的实体准入规则：
1. typeof(BaseEntity).IsAssignableFrom(type)         // 继承链深度扫描
2. !type.IsDefined(typeof(NotMappedAttribute))        // 显式排除 NotMapped
3. type.GetProperty("DBServer") != null               // 过滤掉对象/DTO 容器类
```

### 预防措施
凡新建 `Options` / `DTO` / `VM` 类，第一行加 `[NotMapped]`。

## 4️⃣ P2-04 Vue 3 插槽 Fragment 引发 parentNode 崩溃

### 问题现象
点击左侧菜单切换路由后，控制台爆红色：
```
TypeError: Cannot read properties of null (reading 'parentNode')
  at componentUpdateFn (runtime-core.esm-bundler.js)
```

### 根因分析
Vol 框架的 `ViewGridProvider.jsx` 对插槽内容做了 DOM `parentNode` 手动遍历。而 **Vue 3 对多根节点 Fragment 的 v-if/循环卸载时机**与 `ViewGrid` 操作时机冲突，导致 Fragment 先卸载、后访问 parentNode，返回 null。

触发场景：
```vue
<!-- 错误写法：Fragment 无单根，v-if 空值时变成空 Fragment -->
<template #gridHeader>
  <el-alert v-if="xxx" ... />
</template>

<!-- 错误写法：btnLeft 直接放按钮（多数人习惯） -->
<template #btnLeft>
  <el-button ... />
</template>
```

### 解决方案
**CertPlatform 域所有 view-grid 插槽强制 <div> 单根包裹。**

涉及修复文件：
- `YZHBaseCrud.vue` 公共组件的 `gridHeader` 与 `btnLeft`；
- `CertificationBody.vue` / `CertApplication.vue` / `AuditTask.vue` / `ISOStandard.vue` / `ISOClause.vue` / `Enterprise.vue`；
- 模板写入 `vol-skill.md` §12.5 章节。

标准写法：
```vue
<template #gridHeader>
  <div>
    <el-alert v-if="desc" ... />
  </div>
</template>

<template #btnLeft>
  <div>
    <slot name="btnLeft" />
  </div>
</template>
```

### 预防措施
写任何 view-grid 插槽前，先敲 `<div>` 再写业务。

## 5️⃣ P2-05 formatter 不是函数 + vnode 解构崩溃

### 问题现象
```
TypeError: column.formatter is not a function  @ VolTable.vue:592
TypeError: Cannot destructure property 'type' of 'vnode' as it is null.
```

### 根因分析
生成器在 `options.js` 里给日期类字段加了 `formatter: true`（布尔值）。VolTable 渲染判断 `v-if="column.formatter"` 为真后直接 `column.formatter(row, col)` 调用，直接抛错。后续 Vue 3 vnode diff 收到异常节点，二次抛 `vnode.type` 解构失败。

> **官方文档对照**：[onInit 文档](http://v3.volcore.xyz/docs/view-grid/methods/onInit.html) 示例中 `formatter` 始终是**函数**：`x.formatter = (row) => { return '<a>' + row.Qty + '</a>' }`，不存在布尔值用法。

### 解决方案
**双保险**：
1. **清配置**：`sed -i '' '/formatter: true,/d'` 扫描全 src 所有 options.js，删除错误的布尔 formatter；
2. **加校验**：`VolTable.vue` 两处 formatter 渲染条件升级为：
   ```vue
   v-else-if="column.formatter && typeof column.formatter === 'function'"
   ```

### 预防措施
以后在 `onInit` 中动态给 `columns[i].formatter` 赋值时，必须先写 `typeof === 'function'`。

## 6️⃣ P2-06 API URL 缺尾斜杠导致路径拼接 404

### 问题现象
```
POST http://localhost:9991/api/ISOStandardgetPageData 404
```

### 根因分析
`VolTableLoadData.js` 对 URL 拼接逻辑是硬拼 `url + 'getPageData'`。当 `table.url = "/ISOStandard"` 时，结果为 `/ISOStandardgetPageData`；正确应为 `/ISOStandard/getPageData`。

> **官方文档对照**：[searchBefore 文档](http://v3.volcore.xyz/docs/view-grid/methods/searchBefore.html) 中 `param.url` 可重新设置查询 URL，但格式必须以 `/` 分隔。Vol 代码生成器默认生成的 `table.url` 已含尾斜杠，手改时易遗漏。

### 解决方案
所有 `views/**/options.js` 中 `table.url` 一律以 `/` 结尾：
```javascript
table: {
  key: "Code",
  url: "/ISOStandard/",   // ← 结尾 "/" 必写
  url_Order: "",
}
```

修复范围：`CertificationBody`, `ISOStandard`, `ISOClause`, `Enterprise`, `CertApplication`, `AuditTask` 共 6 个模块 × 2 端口（admin + vol.web）。

### 预防措施
写 options.js 后 Grep `url: "/[A-Z][a-zA-Z]+"[^/]` 正则自检。

## 7️⃣ P2-07 错误引入 YZHBaseCrud 导致的连环崩

### 问题现象
切换 `ISOStandard` / `AuditTask` 菜单连续出现：
```
Invalid prop: type check failed for prop "options". Expected Object, got Function
TypeError: Cannot read properties of undefined (reading 'clientHeight')
  at ViewGridProvider.jsx:449
```

### 根因分析
Phase 2 初稿复用了未充分测试的 `YZHBaseCrud.vue` 二次封装：
1. 父组件错误地将 `viewOptions` **函数引用** 传给 `:options`（未加括号执行），Prop 校验失败；
2. 二次封装内部生命周期与 Vol 原生 `nextTick` 获取 DOM 高度的逻辑冲突，导致 `clientHeight` 空指针。

> **官方文档对照**：[properties.html](http://v3.volcore.xyz/docs/view-grid/properties.html) 中 `height` 和 `tableMaxHeight` 属性由 Vol 内部 `onInited` 阶段计算，二次封装若在此阶段拦截会造成 `clientHeight` 读取异常。官方推荐直接在 `{表}.vue` 中使用 `onInit`/`onInited` 设置高度，不通过中间层。

### 解决方案
**CertPlatform 域彻底弃用 YZHBaseCrud.vue 二次封装，一律回归 Vol 原生 view-grid 写法。**

标准模板（已写入 `vol-skill.md`）：
```vue
<template>
  <view-grid ref="grid" :columns="columns" :table="table"
    :edit-form-fields="editFormFields" :edit-form-options="editFormOptions"
    :search-form-fields="searchFormFields" :search-form-options="searchFormOptions"
    :on-init="onInit" :row-click="rowClick">
    <template #gridHeader><div>...</div></template>
    <template #btnLeft><div><el-button ... /></div></template>
  </view-grid>
</template>

<script setup>
import { reactive, ref } from 'vue'
import viewOptions from './options.js'

const grid = ref(null)
const { table, editFormFields, editFormOptions, searchFormFields,
  searchFormOptions, columns, detail, details, extend
} = reactive(viewOptions())
const onInit = async ($vm) => { /* 这里挂 columns 事件 */ }
const rowClick = ({ row }) => { /* 选中行 */ }
</script>
```

修复范围：`ISOStandard.vue`、`AuditTask.vue`（admin 与 vol.web 端均已更新）。
