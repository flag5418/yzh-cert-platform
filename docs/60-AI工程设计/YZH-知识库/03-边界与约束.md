# 03 - 边界与约束

**版本**：V1
**日期**：2026-07-31
**状态**：正式发布

## 不可修改的 Vol 源码

| 文件 | 路径 | 原因 |
|------|------|------|
| ServiceBase | VOL.Core/BaseProvider/ApplicationServiceBase.cs | Vol 核心基础设施，YZH 通过钩子委托扩展 |
| ApiBaseController | VOL.Core/Controllers/Basic/ApiBaseController.cs | 路由注册依赖此基类 |
| ActionPermissionFilter | VOL.Core/Filters/ActionPermissionFilter.cs | 权限体系核心，只能扩展不能替换 |
| ExceptionHandlerMiddleWare | VOL.Core/Middleware/ExceptionHandlerMiddleWare.cs | 全局异常捕获，YZH 不重复实现 |
| Logger | VOL.Core/Services/Logger.cs | 日志基础设施（队列 + 批量写入 + SqlBulkCopy） |
| UserContext | VOL.Core/UserManager/UserContext.cs | 用户上下文与权限缓存（RBAC 基础） |
| DictionaryManager | VOL.Core/Infrastructure/DictionaryManager.cs | 字典缓存（版本号驱动，几乎完美） |
| JWTAuthorize | VOL.Core/Filters/JWTAuthorize.cs | JWT 认证基础设施 |
| ActionExecuteFilter | VOL.Core/Filters/ActionExecuteFilter.cs | 参数校验过滤器 |

## YZH 与 Vol 的硬边界

| 规则 | 说明 |
|------|------|
| YZH 不继承 Vol 业务 Service | YZH 是框架层，不涉及具体业务逻辑。业务 Service 继承 YZHServiceBase（间接继承 Vol.ServiceBase） |
| YZH 不修改 Vol 实体 | 认证平台实体从 vol.api 迁移到 YZH.CertPlatform，实体继承 YZHBaseEntity（间接继承 Vol.BaseEntity） |
| YZH 通过 Autofac 模块挂载 | 在 vol.api 的 Startup 中注册 YZHModule，不侵入 Vol 代码 |
| 中间件只能用 IAsyncActionFilter | 禁止在 YZH 中创建新的中间件管道，与 Vol 的 ActionPermissionFilter 风格一致 |
| Filter 注册优先级 | YZH Filter 注册在 Vol 权限 Filter 之前：`options.Filters.Add<YZHIdempotentActionFilter>(int.MinValue + 100)` |
| 响应格式不耦合 Vol | Controller 返回 IActionResult，通过 YZHOk() 扩展方法统一，不直接返回 WebResponseContent |

## 复用度评估

| 模块 | 复用率 | 策略 |
|------|--------|------|
| 权限系统（RBAC） | 85% | 直接复用，补充数据权限（多租户） |
| 字典服务 | 95% | 直接复用，几乎无需修改 |
| Service 基类（CRUD + 钩子 + 事务） | 90% | 继承复用，封装钩子为虚方法 |
| 过滤器体系（权限 + 认证 + 校验） | 75% | 复用权限/认证/校验，补充异常/幂等/审计 |
| 日志系统 | 60% | 基础设施保留（队列 + SqlBulkCopy），审计追踪层自研 |

## 已废弃方案

| 废弃内容 | 原因 | 替代方案 |
|------|------|------|
| YZHDecoratorMiddleware | 过度工程化，增加管道复杂度，且与 Vol 的 Filter 体系不兼容 | IAsyncActionFilter |
| 直接在 Vol 源码中修改 | 破坏 Vol 升级兼容性，违反独立性原则 | Autofac 模块挂载 + 继承扩展 |
| 自定义中间件管道 | 与 Vol 现有中间件冲突，维护成本高 | 统一使用 IAsyncActionFilter |
| YZH 自建 CRUD 基类（不继承 Vol） | Vol.ServiceBase 的 CRUD + 钩子 + 事务极其成熟，重复造轮子 | YZHServiceBase : ServiceBase |
| 在实体中直接定义审计字段（不继承 YZHBaseEntity） | 字段命名不一致（CreateDate vs CreatedAt），框架无法统一识别 | 统一继承 YZHBaseEntity |

## 继承关系约束

```
YZHBaseEntity : Vol.BaseEntity
YZHServiceBase<T> : Vol.ServiceBase<T, IRepository<T>>
YZHControllerBase : Vol.ApiBaseController (或包装)
```

- YZH 不允许**横向**修改 Vol 源码，只允许**纵向**继承扩展
- YZH 新增的类、接口、特性放在 `YZH.Core` 项目中，与 Vol 完全隔离
- `vol.api` 项目只能通过添加 NuGet 引用和 Autofac 模块注册来集成 YZH，不能直接引用 YZH 的源码

## 风险提示

| 风险 | 影响 | 缓解方案 |
|------|------|---------|
| Vol 版本升级导致 YZH 基类编译错误 | 高 | 锁定 EF Core 8.0 + Vol 当前版本；YZH 代码与 Vol 物理隔离 |
| Func 钩子 vs 虚方法 API 差异 | 中 | YZHServiceBase 提供双层 API：虚方法内部调用 Vol 的 Func 委托 |
| 响应格式不统一（WebResponseContent vs IActionResult） | 低 | YZHControllerBase 统一转换层 |
| Vol 后续版本加入同名特性 | 低 | YZH 前缀命名空间隔离，`.yzhusings` 优先 |
