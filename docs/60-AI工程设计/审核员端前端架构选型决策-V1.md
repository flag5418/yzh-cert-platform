## 一、决策背景

### 1.1 原始分歧

是否保留 `vol.web`（端口 9990）作为审核员端载体，还是独立开发 `src/auditor`（端口 9991）作为审核员端？

### 1.2 当前 codebase 实际状况（2026-09-03 确认）

| 维度 | vol.web（端口 9990） | src/auditor（端口 9991） |
|------|----------------------|--------------------------|
| 技术栈 | Vue 3.5 + Element Plus 2.11 + Vuex 4 + **Pinia 3（已装）** + Vite 6 + TS 5.6 | Vue 3.5 + Naive UI 2.45 + Pinia 4 + Vite 8 + TS 6 |
| 已完成模块 | 系统管理全套 + CertPlatform 认证管理全套（认证机构、ISO标准、阶段、标准目录、文档提取、NC规则、报告配置、Skill管理、Prompt模板、工作流设计器） | 仅 4 个占位页面 + DefaultLayout |
| 状态管理 | Vuex 4（主）+ Pinia 3（已安装） | Pinia 4 |
| 样式系统 | YZH 设计令牌（yzh.css + 4 个子文件），Element Plus 颜色已覆盖 | Naive UI 默认主题 |
| UI 组件 | Element Plus + LogicFlow 2.0 + ECharts 6 + wangeditor + SignalR | Naive UI（全部未使用） |
| 路由模式 | 扁平化 viewGird.js，菜单 URL = 路由路径 | 嵌套路由（待改造） |
| HTTP | 统一封装 `api/http.js`，走 Vuex token | 独立 `api/http.ts`，走 localStorage |
| 登录页 | 单登录页，所有角色共用 | 单登录页 |

### 1.3 关键发现

1. **vol.web 已完成大量业务系统**，特别是工作流设计器（LogicFlow 2.0）与审核员端业务强相关；
2. **vol.web 已安装 Pinia 3.0.3**，可与 Vuex 共存；
3. **vol.web 样式系统已深度定制**，Element Plus 配色已通过 YZH CSS 变量覆盖；
4. **src/auditor 几乎为空壳**，仅有路由骨架和占位页面；
5. **两套 UI 框架（EP + Naive）共存风险高**：样式冲突、包体积、维护成本。

## 二、方案对比

### 2.1 三种候选方案

| 方案 | 描述 | 包体积增量 | 开发周期估算 | 风险 |
|------|------|-----------|-------------|------|
| **A：独立 auditor** | 保留 src/auditor 作为独立前端，RBAC 全量重写 | +0（独立部署） | 8-12 周 | 高：需重写登录/权限/菜单/消息等 |
| **B：混合共存** | vol.web 管系统管理，auditor 管审核员，两套 UI 框架共存 | +400KB gzip | 6-8 周 | 中：样式冲突、token 同步 |
| **C：单前端多角色（选定）** | vol.web 为唯一前端，多登录入口，按角色切换 Layout/菜单/路由 | +0 | 3-4 周 | 低：复用现有 RBAC |

### 2.2 选定方案 C：单前端多角色

**核心原则**：
- **唯一前端应用**：`vol.web`（端口 9990）承载所有角色
- **多登录入口**：`/admin/login`、`/auditor/login`、`/enterprise/login`
- **动态 Layout**：登录后根据角色渲染不同主框架
- **UI 框架统一**：Element Plus + YZH 深度定制，抛弃 Naive UI
- **状态管理共存**：Vuex（全局用户/权限）+ Pinia（审核业务模块）
- **第三方组件补充**：LogicFlow 2.0（工作流）、ECharts（图表）、wangeditor（富文本）

#### 3.2.2 登录流程

```
用户访问 /auditor/login
  → 渲染 AuditorLoginLayout（审核员专属设计）
  → 提交登录 → 调用 /api/user/login（统一接口）
  → 返回 token + userType + roles
  → if userType=22 → 跳转 /Auditor/Workspace
  → else → 提示"请使用对应登录入口"

登录后初始化：
  → 写入 Vuex userInfo
  → 根据 userType 动态加载菜单
  → 动态注册审核员路由
  → 渲染 AuditorLayout
```

#### 3.4.2 职责划分

| Store | 职责 | 存储位置 |
|-------|------|----------|

| **Pinia: useMessageStore** | 消息列表、未读数 | 内存 + SessionStorage |

#### 3.43 Pinia Store 示例

```typescript
// src/yzh/store/auditTask.ts
import { defineStore } from 'pinia'

export interface AuditTask {
  code: string
  taskNumber: string
  enterpriseName: string
  standardName: string
  phaseName: string
  status: 'pending' | 'in_progress' | 'completed' | 'failed' | 'confirmed' | 'closed'
  isFocused: boolean
  queueProgress?: { current: number; total: number }
  ncCount?: number
  reportCount?: number
}

export const useAuditTaskStore = defineStore('auditTask', {
  state: () => ({
    focusList: [] as AuditTask[],
    currentTask: null as AuditTask | null,
    taskDetail: null as any,
    loading: false
  }),
  getters: {
    activeCount: (state) => state.focusList.filter(t => t.status === 'in_progress').length,
    pendingReviewCount: (state) => state.focusList.filter(t => t.status === 'completed').length
  },
  actions: {
    async fetchFocusList() {
      this.loading = true
      const res = await proxy.http.get('/api/AuditTask/focusList', null, false)
      this.focusList = res.data || []
      this.loading = false
    },
    async setFocus(code: string) {
      await proxy.http.post('/api/AuditTask/setFocus', { code }, false)
      await this.fetchFocusList()
    },
    async unfocus(code: string) {
      await proxy.http.post('/api/AuditTask/unfocus', { code }, false)
      await this.fetchFocusList()
    }
  }
})
```

#### 3.5.2 路由守卫

```javascript
// router/index.js
router.beforeEach((to, from, next) => {
  const userType = store.getters.getUserInfo()?.userType
  
  // 登录页面放行
  if (to.path.endsWith('/login')) return next()
  
  // 未登录跳对应登录页
  if (!userType) {
    return next('/auditor/login')
  }
  
  // 审核员路由权限校验
  if (to.path.startsWith('/Auditor') && ![20, 21, 22].includes(userType)) {
    return next('/admin/login')
  }
  
  // 管理员路由权限校验
  if ((to.path.startsWith('/Sys_') || to.path.startsWith('/CertPlatform')) 
      && [20, 21, 22, 30].includes(userType)) {
    return next('/auditor/login')
  }
  
  next()
})
```

## 五、核心决策总结

| 决策项 | 结论 | 理由 |
|--------|------|------|
| **前端载体** | vol.web 唯一前端 | 复用现有 RBAC，避免重复开发 |
| **UI 框架** | Element Plus + YZH 定制 | 抛弃 Naive UI，避免双框架风险 |
| **状态管理** | Vuex（全局）+ Pinia（业务） | Vuex 管 token/权限，Pinia 管业务状态 |
