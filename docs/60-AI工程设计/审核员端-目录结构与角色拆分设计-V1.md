## 一、核心决策

### 1.1 问题陈述

当前代码结构将管理员、审核员、框架示例代码混合存放：

```
vol.web/src/views/
├── cert/           # 管理员业务页面
├── sys/            # 系统管理页面
├── Login.vue       # 管理员登录（审核员也用？）
├── Home.vue        # 管理员首页
├── Index.vue       # 主布局（审核员也用？）
├── mes/            # 框架示例（需清理）
└── builder/        # 代码生成器
```

**问题**：
1. 管理员和审核员的 UI 完全不同，但混在一起
2. 审核员登录后不应看到管理员的菜单（机构管理、标准配置等）
3. 路由全在一个 `viewGird.js`，不易维护
4. 后端 Controller 也未按角色分组

### 1.2 解决方案

**完全迁移方案**：按角色建立独立文件夹空间，使用 Vol 现有角色权限体系控制菜单可见性。

```
┌──────────────────────────────────────────────────────────────┐
│                    角色与入口对应关系                          │
├──────────────┬─────────────────┬─────────────────────────────┤
│    角色       │    登录入口      │    主布局                   │
├──────────────┼─────────────────┼─────────────────────────────┤
│  管理员       │  /admin-login   │  admin/Index.vue            │
│  审核员       │  /auditor-login │  auditor/Layout.vue         │
│  企业（预留）  │  /ent-login     │  enterprise/Layout.vue      │
└──────────────┴─────────────────┴─────────────────────────────┘
```

## 五、登录后跳转逻辑

### 5.1 路由守卫

```javascript
// router/index.js - beforeEach
router.beforeEach(async (to, from, next) => {
  store.dispatch("onLoading", true);
  
  // 公开页面直接放行
  if (to.meta.anonymous) return next();
  
  // 未登录跳转登录页
  if (!store.getters.isLogin()) {
    return next({ path: '/admin-login' });
  }
  
  // 已登录，根据角色跳转
  const userRoleId = store.getters.getUserInfo?.roleId;
  
  if (to.meta.role === 'admin' && userRoleId !== AUDITOR_ROLE_ID) {
    return next();
  }
  
  if (to.meta.role === 'auditor' && userRoleId === AUDITOR_ROLE_ID) {
    return next();
  }
  
  // 角色不匹配，重定向到对应首页
  if (userRoleId === AUDITOR_ROLE_ID) {
    return next('/auditor/workspace');
  }
  
  return next();
});
```

### 5.2 登录成功后跳转

```javascript
// views/admin/Login.vue
const handleLoginSuccess = (result) => {
  store.commit('setUserInfo', result.data);
  
  const roleId = result.data.roleId;
  const AUDITOR_ROLE_ID = 100; // 与数据库一致
  
  if (roleId === AUDITOR_ROLE_ID) {
    router.push('/auditor/workspace');
  } else {
    router.push('/home');
  }
};
```

| 批量移动文件时遗漏引用 | 编译失败 | 用 IDE 全局搜索确认无残留引用 |
| 路由路径变更导致菜单 404 | 管理员无法操作 | 数据库同步更新 Sys_Menu.Url |
| 后端命名空间变更导致 DI 失败 | 接口 404 | 同步更新 Program.cs 中的扫描配置 |
| 审核员角色 ID 冲突 | 新用户分配到错误角色 | 数据库 Role_Id 固定，代码中硬编码常量 |

**回滚方案**：每次 Phase 完成后 Git 提交，失败可 `git revert` 回滚。
