## 第一部分：AI 证据溯源——"这个结论从哪来的？"

### 一、问题本质

当前 AI 生成审核发现时，审核员看到的是一段结论性文字：

```
审核证据：
"受审核方提供的审核资料清单中未包含《内部审核报告》文件，
仅有内审签到表，无法验证内审过程的完整性和结论的有效性。"
```

审核员的第一个反应一定是：**"你怎么得出这个结论的？依据是什么？"**

如果审核员需要手动翻阅几十份文件来验证这一句话，AI 的价值就被消解了一半。真正的生产力提升不是 AI 代替人写结论，而是 AI 写结论的同时把证据链挂上——让审核员一秒定位到源文件的相关段落。

### 二、溯源粒度设计

溯源不是简单的"这个发现来源于 XX 文件"，需要精确到：

```
证据溯源信息：
├── 来源文件：/证据库/内审相关/内审签到表.pdf          [查看文件]
├── 涉及段落：第 2 页，第 3-8 行                       [定位到原文]
│   ┌─────────────────────────────────────────┐
│   │ 内审签到表                                │
│   │                                         │
│   │ 审核日期：2024年6月15日                   │
│   │ 审核部门：生产部、质量部、行政部            │
│   │ **应到人数：12人  实到人数：10人**         │  ← 高亮加粗
│   │ **未包含内审报告、不符合项报告等输出文件**   │  ← 高亮加粗
│   └─────────────────────────────────────────┘
├── AI 推断逻辑：
│   "签到表仅记录人员到场，未包含审核结论、不符合
│    项、纠正措施等内审核心输出，因此判定：无法验证
│    内审完整性"
└── 关联文件（佐证或对比）：
    ├── /证据库/程序文件/内部审核控制程序.doc       [查看]
    │   "4.2 内审结束后应形成内审报告，内容包括..."
    └── /证据库/往年记录/2023年内审报告.pdf          [查看]
        "对比往年有完整报告，2024年仅有签到表"
```

### 三、技术实现

#### 3.1 AI 分析阶段的结构化输出

AI 分析文件时，不仅生成结论，还要输出证据锚点：

```json
{
  "finding_id": "F-2026-003",
  "clause": "ISO 9001:2015 / 9.3",
  "severity": "major_nc",
  "evidence_text": "未包含《内部审核报告》文件，仅有内审签到表...",

  "sources": [
    {
      "file_path": "/证据库/内审签到表.pdf",
      "page": 2,
      "line_range": [3, 8],
      "text_span": "应到人数：12人  实到人数：10人\n未包含内审报告、不符合项报告等输出文件",
      "role": "primary",          // primary = 主要证据, supporting = 佐证, contrast = 对比
      "highlight_ranges": [
        {"start": 18, "end": 40},  // "未包含内审报告"
        {"start": 0, "end": 18}    // "应到人数：12人  实到人数：10人"
      ]
    },
    {
      "file_path": "/证据库/内部审核控制程序.doc",
      "page": 1,
      "line_range": [12, 15],
      "text_span": "4.2 内审结束后应形成内审报告，内容包括审核结论...",
      "role": "supporting"
    }
  ],

  "ai_reasoning": "签到表仅记录人员到场情况，不包含审核结论、不符合项、纠正措施等内审核心输出内容。对照《内部审核控制程序》4.2条款要求，判定内审过程不完整。"
}
```

#### 3.2 关键约束

| 约束 | 说明 |
|------|------|
| **溯源不是 100% 精确** | PDF 的页码/行号是近似的，尤其扫描件 OCR 后行号可能偏移。UI 应标注"约第 X 页"，并允许审核员手动校正 |
| **无源发现标识** | AI 基于规则推断的发现（如"缺少某类文件"）没有具体文件来源，应明确标注"来源：AI 规则推断，无对应文件"，避免审核员困惑 |
| **隐私保护** | 溯源文件路径仅在审核系统内可见，导出报告时默认不包含完整证据链（文件过大），仅摘要溯源信息 |

## 第二部分：证书全生命周期管理

### 四、证书类型的完整图谱

一个企业从申请到持续持证，涉及多种证书状态和审核类型。它们之间有严格的时间线和逻辑关系：

```
企业首次申请
      │
      ▼
┌──────────────┐
│  初审（一阶段+二阶段）  │  审核通过 →
│  Initial Audit        │  颁发初始证书
└──────────────┘        │  有效期：3年（自认证决定日期起）
                        │
      ┌─────────────────┘
      ▼
┌──────────────┐
│  初始证书      │  Certificate Status: Active
│  No. ACM-001  │  颁发日期：2024-06-15
│  有效期至：     │  到期日：2027-06-14
│  2027-06-14   │
└──────┬───────┘
       │
       │ ⚠️ 必须在 2024-06-15 ~ 2025-06-14 之间完成
       ▼
┌──────────────┐
│  第一次监督审核  │  Surveillance 1
│  审核通过 →      │  证书保持有效
│  更新监督标记    │  不换发新证
└──────┬───────┘
       │
       │ ⚠️ 必须在 2025-06-15 ~ 2026-06-14 之间完成
       ▼
┌──────────────┐
│  第二次监督审核  │  Surveillance 2
│  审核通过 →      │  证书保持有效
│  更新监督标记    │  不换发新证
└──────┬───────┘
       │
       │ ⚠️ 到期前 3-6 个月启动
       ▼
┌──────────────┐
│  再认证审核       │  Recertification
│  审核通过 →       │  换发新证书
│  原证失效，新证生效 │  新有效期：3年
└──────────────────┘
```

### 五、证书状态与变更类型

| 状态 | 含义 | 触发条件 | 系统动作 |
|------|------|---------|---------|
| **Active** | 有效 | 审核通过 | 证书可用 |
| **Suspended** | 暂停 | 监督审核发现严重不符合且未整改、企业申请暂停、未按期接受监督审核 | 暂停期间证书不可用，最长 6 个月 |
| **Withdrawn** | 撤销 | 暂停期满未恢复、企业申请撤销、严重违规 | 证书永久失效，不可恢复 |
| **Restored** | 恢复 | 暂停原因消除并验证 | 从 Suspended → Active |
| **Expired** | 到期 | 到期未再认证 | 自动标记，不可恢复 |
| **Scope Changed** | 范围变更 | 企业增减认证范围 | 换发新证，新范围生效 |
| **Transferred** | 转移 | 企业从其他机构转入 | 新机构签发新证 |
| **Cancelled** | 注销 | 企业主动申请注销 | 证书失效，非处罚性质 |

### 六、各类审核的特点对比

| 审核类型 | 目的 | 范围 | 人天公式 | 产出物 | 与初审的区别 |
|---------|------|------|---------|--------|-------------|
| **初审（一阶段）** | 评估企业文件体系是否完备 | 全条款文件审查 | 100% 初审人天 × 30% | 一阶段审核报告 | 只看文件，不去现场（大部分） |
| **初审（二阶段）** | 验证体系运行有效性 | 全条款现场审核 | 100% 初审人天 × 70% | 二阶段审核报告 + 证书 | 全面深度审核 |
| **一监** | 维持证书，查关键条款 | 约 1/3 条款，侧重上次不符合项+核心过程 | 初审人天 × 1/3 | 监督审核报告 | 条款减量，但重点关注体系持续运行和改进 |
| **二监** | 维持证书，查另一批条款 | 约 1/3 条款，与一监错开 | 初审人天 × 1/3 | 监督审核报告 | 互补于一监的条款覆盖 |
| **再认证** | 换发新证，全面复查 | 全条款但可基于历史信任减量 | 初审人天 × 2/3 | 再认证报告 + 新证书 | 略轻于初审，但仍是全面审核 |
| **特殊审核** | 应对变更/投诉/事故 | 仅限变更涉及范围 | 按范围估算 | 特殊审核报告 | 非周期性，触发式 |
| **转机构审核** | 接收从其他机构转入的企业 | 按剩余有效期定 | 按比例折算 | 转机构报告 + 新证书 | 需审查原机构的历史审核记录 |

### 七、为什么必须管理证书

| 不管理的后果 | 具体表现 |
|------------|---------|
| **证书过期未监督审核** | 企业拿了到期证去投标，被废标 → 投诉认证机构 → CNAS 处罚 → 暂停资质 |
| **暂停/撤销未及时更新** | CNAS 抽查发现机构网站上仍挂着已撤销企业的证书 → 通报批评 |
| **监督审核排期遗漏** | 200 个获证企业，每个有不同的到期日和一监/二监窗口期，纯靠 Excel 必然遗漏 |
| **证书信息不一致** | 认证范围变了但证书没更新，企业拿旧证投标 → 虚假宣传 |
| **CNAS 评审抽证书** | CNAS 每年抽 5-10 份证书追溯全部审核过程，找不到记录 → 严重不符合 |

### 八、证书管理模块设计

#### 8.1 数据模型

```sql
CREATE TABLE certificates (
    id                UUID PRIMARY KEY,
    cert_no           VARCHAR(50) NOT NULL UNIQUE,    -- ACM-13485-2024-001
    enterprise_id     UUID NOT NULL,
    standard          VARCHAR(50) NOT NULL,           -- ISO 13485:2016
    cert_scope        TEXT NOT NULL,                  -- 认证范围
    accreditation     VARCHAR(20),                    -- CNAS / UKAS / 无
    
    issue_date        DATE NOT NULL,                  -- 颁发日期
    expiry_date       DATE NOT NULL,                  -- 到期日（通常 3 年）
    cert_status       VARCHAR(20) NOT NULL,           -- active/suspended/withdrawn/expired...
    
    -- 监督审核窗口
    surveillance_1_due DATE NOT NULL,                 -- 一监到期日
    surveillance_1_done DATE,                         -- 一监实际完成日
    surveillance_2_due DATE NOT NULL,
    surveillance_2_done DATE,
    recert_due        DATE NOT NULL,                  -- 再认证到期日
    
    -- 暂停/撤销记录
    suspended_at      DATE,
    suspended_reason  TEXT,
    restored_at       DATE,
    withdrawn_at      DATE,
    withdrawn_reason  TEXT,
    
    -- 关联审核项目
    initial_project_id UUID NOT NULL,                 -- 初审项目
    current_surveillance_id UUID,                     -- 当前监督审核项目
    
    created_at        TIMESTAMP NOT NULL
);
```

#### 8.2 关键功能

| 功能 | 说明 |
|------|------|
| **到期倒计时** | 首页显示即将到期的监督审核和再认证任务，按紧急度排序 |
| **监督审核窗口计算** | 初审通过后自动计算一监和二监的 legal due date |
| **到期提醒** | 到期前 60 天、30 天、7 天分别提醒相关审核员和机构管理员 |
| **状态变更流程** | 暂停 → 需要技术负责人审批 + 通知企业；撤销 → 需机构最高管理者审批 |
| **企业端查看** | 企业可在移动端查看自己证书的状态、有效期、下次审核时间 |
| **CNAS 上传接口预留** | CNAS 要求机构定期上报获证企业清单，预留数据导出格式 |
| **证书模板生成** | 审核通过后自动填充证书模板（企业名称、范围、标准、有效期），生成 PDF |

#### 8.3 到期提醒逻辑

```
系统定时任务（每天凌晨执行）：
  
  查询条件：
    cert_status = 'active'
    AND (
      surveillance_1_done IS NULL AND surveillance_1_due <= 今天 + 60天
      OR surveillance_2_done IS NULL AND surveillance_2_due <= 今天 + 60天
      OR recert_due <= 今天 + 90天
    )
  
  匹配结果 → 按剩余天数分组：
    剩余 ≤ 7 天  → 🔴 紧急，钉钉+短信+系统内标红
    剩余 ≤ 30 天 → 🟡 警告，钉钉通知
    剩余 ≤ 60 天 → 🔵 提醒，系统内通知
    剩余 ≤ 90 天 → ⚪ 仅展示在提醒列表（再认证）
```
