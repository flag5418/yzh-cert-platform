## 一、扫描口径说明

历史项目的控制器广泛使用 **Partial 分部类**：类级 `[Route]` 声明在 `XxxController.cs`，业务动作写在 `Partial/XxxController.cs`。同时一个类可能声明**多个类级路由**（如 `Sys_RoleController` 同时挂 `api/Role` 与 `api/Sys_Role`）。

因此扫描器必须满足三条，否则会产生大量假阴性：

1. 类级路由按**类名跨文件合并**（不能只看当前文件）
2. 一个类的**全部**类级路由都要展开（不能只取第一条）
3. `[HttpPost, Route("X")]` 行内的 `Route` 是**动作级**，不能误判为类级

> 早期版本（只看单文件、只取首条路由）分别得出 52 / 80 条缺口，均**低估**。本报告采用修正后的口径。

### 3.3 本轮修复的真 bug：`system-log.ts`

`cert-share/src/api/system-log.ts` 的 `getLogPage()` 存在**四处契约偏差**，任一都会导致 404 或空列表：

| # | 问题 | 原值 | 修正 |
|---|------|------|------|
| 1 | 路径缺 `/api` 前缀 | `/SysLog/filter` | `/api/System/Log/filter` |
| 2 | 控制器名错 | `SysLog` | `System/Log`（实际类级路由） |
| 3 | 直接读信封字段 | `res.Items` | `res.data.Items` |
| 4 | 用了不存在的入参字段 | `params.pageSize` | `params.rows`（`PageParams` 契约） |

**实测对比**：

```
[修复前] POST /SysLog/filter              → HTTP 404
[修复后] POST /api/System/Log/filter      → HTTP 200
         {"success":true,"data":{"Items":[],"TotalCount":0,"PageIndex":1,"PageSize":20,...}}
```

实现改为复用 `generic.ts` 的 `getEntityPage('System/Log', ...)`，返回 `Page<T>`（`{rows,total}`），与 `YzhTable` 数据加载器契约一致。

**浏览器端实测**（`/system/log`，fetch 探针 + `console.error` 钩子）：

```

console.error： []                                          ← 零错误

空态：      暂无数据（sys_log 表为空，正确）
工具栏：    查询 / 重置 / 导出 / 列设置
```

`cert-share` 独立 `vue-tsc` 复检 **0 错误**。

**回归确认**：`/business/nc-config` 仍正常 —— 树根 3 个机构（含「河北雄安尚龙认证有限公司」），展开后 level-1 渲染 3 个标准（`ISO 13485:2016 - 医疗器械 质量管理…` / `ISO 9001:2015 - 质量管理体系` / `TEST-TT-001 - 测试标准 TreeTa…`），零 `console.error`。本次改动未造成回归。

> **附注**：该函数当前**无任何调用方**（`system/log` 页面已迁移到 `SingleTableCore`），属「被 barrel 导出但无人使用」的活代码。修复而非删除，是为消除 `api/index.ts` 导出面的陷阱。若确认无规划用途，可连同 barrel 导出一并删除。
