## 0. 四条硬约束（用户裁定，本文档的验收标准）

| # | 约束 | 现状 | 结论 |
|---|---|---|---|
| **B1** | 专家端**不得**引用后台端逻辑；后台端**不得**引用专家端；共享**只能**经 `CertPlatform.Shared` | ❌ **违规**：`CertPlatform.Auditor.csproj:57` 引用 `CertPlatform.Admin.csproj`；Auditor 内 **24 处** `using CertPlatform.Admin.*` | 必须拆（阶段 6 闸门） |
| **B2** | **标准文档**（机构+标准+阶段+目录+文件）是核心资源，**提取方法必须在 Share 统一** | ❌ 后端 **4 套**组织树实现 + **17 个文件**直查 `cert_standard_directory_file`；前端 **14 处**各自拼树 | 必须归一（阶段 2/3） |
| **B3** | **四大规则**（NC / 报告 / 填写 / 提取）两端都可能频繁使用，**必须抽象到 Share** | ❌ 全部住在 `CertPlatform.Admin`，专家端反向引用 | 必须下沉（阶段 4） |
| **B4** | 改动巨大 ⇒ **先给完整计划，审批后执行** | —— | 本文档 |

> ⚠️ **B1 是其余三条的前提**。只要 `Auditor → Admin` 这条引用还在，"抽到 Share"就只是把代码从 Admin 的一个目录挪到另一个目录，
> **专家端依旧在依赖后台端**，问题会以另一种形态复发。

## 2. 目标架构

### 2.1 分层与边界

```
┌─────────────────────────── yzh.vue.core（前端框架层，不动）
│
├── CertPlatform.Shared          ★ 唯一共享层（实体 + 契约 + 业务内核 + 工作流引擎）
│      ├── Entities/**            一表一实体，全部在此
│      ├── Contracts/**           唯一函数接口（§2.2）
│      ├── Domain/Dir/**          标准目录 / 文件 / 槽位
│      ├── Domain/Org/**          机构 → 标准 → 阶段（组织树）
│      ├── Domain/Values/**       取值 / 判空 / 文件态（唯一口径）
│      ├── Domain/Extraction/**   提取规则内核
│      ├── Domain/Nc/**           NC 规则内核
│      ├── Domain/Rpt/**          报告规则内核
│      ├── Domain/Fill/**         填写规则内核
│      ├── Workflow/**            执行引擎（NodeExecutor / Interpreter / Skills）
│      └── Tenancy/**             IWorkspaceContext（接口；实现由宿主注入）
│
├── CertPlatform.Admin   → Shared only   （后台：设计器 + 管理端点）
├── CertPlatform.Auditor → Shared only   （专家端：执行 + 审核端点）
└── CertPlatform.Enterprise → Shared only（企业端，当前空壳）
```

### 2.2 目标 = **唯一函数清单**（这就是"一个唯一的标准"）

| 契约 | 唯一职责 | 现在有几种实现 |
|---|---|---|
| `IOrgStageCatalog.GetOrgStageTreeAsync()` | 机构→标准→阶段树（唯一 DTO，**PascalCase**） | 后端 4 · 前端 14 |
| `IDirectoryCatalog.GetTreeAsync(configCode)` | 阶段目录树（文件夹 + 文件 + 规则状态） | 2（admin stage-files / auditor standard-directory） |
| `IDirectoryCatalog.GetSlotsAsync(ent, std, stage)` | 企业槽位全集（带就位状态） | 2（stage-overview / standard-directory） |
| `IStandardFileState.GetStateAsync(...)` | 单个标准文件的唯一状态枚举 | **4 种「已上传」定义** |
| `IValueJudge.JudgeField/Table/Object` | 取值后的唯一判空（含 `-`/`N/A`/`待填写`） | 2（`EmptyJudge` vs `IsEmptySkill.Judge`） |
| `IExtractionGateway.GetField/GetTable` | 提取结果唯一取数 | 4 套 |
| `IExtractionScope.ResolveAsync(...)` | 规则四元组解析 | 1（已存在，位置错） |
| `IRuleCatalog.GetNc/GetReport/GetFill/GetExtraction` | 四大规则读取 | 各自散落 |
| `IWorkflowRunner.RunAsync(...)` | 执行引擎唯一入口 | 1（位置错） |
| `IWorkspaceContext` | 工作区（租户）上下文 | 1（Auditor 独占） |

> **判据（可自动化）**：上述 10 个契约之外，`Admin` / `Auditor` / `Enterprise` 内**不得**出现
> `GetListAsync<StandardDirectory*>` / `<*ExtractionResult>` / 自建 `BuildTree` / 自建判空 / 自建组织树查询。

## 3. 分阶段实施计划（7 阶段，**每阶段独立可验收**）

> **总原则**：① **只移动 + 转发（Facade），绝不复刻**；② 每阶段结束 `dotnet build` 0 错误 + 现有测试全绿 + 守卫通过；
> ③ 阶段 6 是**唯一**删引用的时机 —— 前面任何阶段提前删都会编译不过。

### 阶段 0 · 立规矩（不改业务逻辑，先让违规**可见**）

| # | 动作 |

| 0-1 | `guards.mjs` 新增：**R-B1** 跨端 `ProjectReference` 白名单（`Admin/Auditor/Enterprise` 之间互引 = 报错）；**R-B2** `[SugarTable]` 实体必须位于 `CertPlatform.Shared`；**R-B3** 同表禁双实体；**R-B4** 禁止在 Admin/Auditor 内 `using CertPlatform.{Admin,Auditor}` 互引 |

## 4. 依赖顺序与"为什么不能并行"

```
阶段0（规矩） → 阶段1（实体） ─┬─→ 阶段2（目录域） ─→ 阶段3（组织树）
                              └─→ 阶段4（四规则） ─→ 阶段5（引擎） ─→ **阶段6（拆引用=闸门）**
阶段7（前端）与阶段3/4 可并行，但**依赖阶段3-1 的 DTO 定稿**
```

- **阶段 2/3/4/5 都必须在阶段 1 之后**：实体还在 Admin 时下沉服务会造出 `Shared → Admin` 循环引用（编译直接失败）。
- **阶段 6 必须在最后**：提前删引用，Auditor 立即编译不过。
- **阶段 4 的 4 个子轮可以并行**（互不依赖），但**串行更稳**（每轮要跑端到端）。

## 5. 规模与风险

| 阶段 | 改动面 | 风险 | 可回滚 |
|---|---|---|---|
| 0 | 1 脚本 + 1 基线文件 | 极低 | ✅ |
| 1 | ~65 文件的 namespace/位置 | 低（无逻辑/无 DB 变化） | ✅ |
| 2 | 2 内核文件 + 4 判据 + 上传链 | 中（判据变更会改可见结果） | ✅ 按处回退 |
| 3 | 后端 4→1；前端 14→1 | 中（页面回归面广） | ✅ |
| 4 | 4 子轮，各含 1–3 服务 | 中 | ✅ 子轮独立 |
| 5 | **12,887 行 / 58 文件**一次性移动 | **高**（引擎是全系统心脏） | ✅（纯移动 + 编译验证） |
| 6 | csproj 1 行 + 删空壳 | **闸门**：不过就是前面漏了 | ⚠️ 无（回滚=回到阶段5末态） |
| 7 | 2 client + 若干组件 + 9 页面 | 中 | ✅ |

**最大风险点 = 阶段 5**。缓解：① 它是**纯物理移动 + namespace 重定向**，不改一行逻辑；② 分两步走（先移 skills，再移引擎）确保每步可编译；③ 移动前后用 `git diff --stat` 断言"**行数不变**"。
