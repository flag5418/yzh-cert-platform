## 一 事项 2：队列执行下沉 Shared

### 1.1 现状实测（两套并行）

| | 框架队列 | 专家任务队列 |
|---|---|---|
| 引擎 | `QueueManager`（`YZH.Core.DataBase/Services/`） | `ExpertTaskQueueRunner`（`CertPlatform.Auditor/Services/Expert/`） |
| 表 | `yzh_queue` / `yzh_queue_task` / `yzh_queue_resource_lock` | `cert_expert_task_queue` / `_item` |
| 契约 | `IYzhTaskExecutor`（`YZH.Core.Stand/Interfaces/`） | `IExpertItemExecutor`（`CertPlatform.Auditor/Services/Expert/`） |
| 调度特性 | `FOR UPDATE SKIP LOCKED`、跨表资源锁、多队列并发（`queue_max_concurrent` 默认 4） | **同队列串行**（该队列无 running 才领）、乐观抢占、**强制 OrgCode 过滤** |
| 进度重算 | `RefreshQueueProgressAsync`（队列级） | `RefreshQueueAsync` + `RefreshSubTaskAsync` + `RefreshTaskAsync`（**三层**：队列→标准子任务→任务） |
| 执行器 | Admin：`OfficeConvertTaskExecutor`；Auditor：`EnterpriseOriginalIngestExecutor` / `AnalyzeExecutor` / `FileExecutor` / `ExtractTaskExecutor` / `NormalizeExecutorAdapter` | Auditor：`ExpertNcCheckExecutor` / `ExpertReportExecutor` |

**`IExpertItemExecutor` 的源码注释自陈**（`ExpertItemExecutors.cs:31-37`）：

> 「为什么不实现框架的 `IYzhTaskExecutor`：那是 `yzh_queue` 的分发接口，而专家任务按 D10 用**专用队列表**（跨租户泄露 H12 + ScopeKey 双口径）。本接口与之**形状对齐、职责相同**，只是绑定的表不同。」

⇒ **「形状对齐、职责相同」= 用户说的「流程是一样的，可以共享」的准确落点。**

### 1.2 关键实测：业务逻辑的下沉阻力比想象小

`ExpertNcCheckExecutor` 的三条分支：
1. `JudgeMode = manual` → 跳过
2. 无 DAG → 跳过
3. 有 DAG → 调 **`IWorkflowRunner.CreateAndRunAsync`**

而 `IWorkflowRunner` **已在上一轮下沉到 `Shared.Services.Workflow`**（DI 注册在 Admin）。
⇒ NC 检查的**业务逻辑只依赖 Shared 契约**，与 `Auditor` 实体/队列的耦合仅剩「入参载体」（`CertExpertTaskQueueItem` + `ExpertItemPayload`）。

### 1.3 方案（三选一，**需裁决**）

| 方案 | 做法 | 收益 | 成本/风险 |
|---|---|---|---|
| **A · 只下沉执行器** | 把「业务执行逻辑」抽成 Shared 契约（`INcCheckRunner` / `IReportGenerateRunner` / 提取/规范化同类），Auditor 执行器变**薄壳**；两套调度器**保留** | 后端 NC 测试/章节流程测试可直接复用同一逻辑；改动面小 | 两套调度器仍在（`ExpertTaskQueueRunner` 的租约/退避/回收仍是第二遍实现） |
| **B · 执行器 + 调度内核都下沉** ★建议 | A + 把 `ExpertTaskQueueRunner` 的**调度内核**（租约/退避/回收/乐观抢占/三层进度重算）抽成 Shared 通用组件，两张表各自配置驱动 | 「执行」真正共享；两套调度器收敛为一份内核 + 两份表配置 | 调度内核要抽象出「表/字段映射」，工作量中等；⛔ 必须保留「同队列串行」「强制 OrgCode 过滤」两个专家端特性 |
| **C · 彻底合并到 `yzh_queue`** | 删 `cert_expert_task_queue*`，专家任务改用 `yzh_queue` | 只有一套表、一套契约 | ⛔ 与 D10 裁决冲突（跨租户泄露 H12 + ScopeKey 双口径）；需给 `QueueManager` 加「同队列串行」等语义；**回滚成本最高** |

**我的建议 = B**。理由：用户要的是「**执行**共享」，而 A 只共享了一半（业务逻辑），调度仍是两份；C 推翻了已裁决的 D10（专用表），风险与收益不匹配。

### 1.4 方案 B 的落地边界（若采纳）

**下沉到 `Shared`（新增 `Shared/Services/Queue/`）**：

```
Shared/Services/Queue/
  IQueueItemExecutor.cs        ← 通用契约（对齐 IExpertItemExecutor 形状：ItemType + ExecuteAsync + Outcome）
  QueueItemOutcome.cs          ← Success / Retryable / Message / IsSkipped（现 ItemExecOutcome）
  QueueScheduleKernel.cs       ← 调度内核（领取/抢占/租约/退避/回收）
  IQueueScheduleOptions.cs     ← 表与字段映射配置（表名、状态列、队列键列…）
  Runners/
    INcCheckRunner.cs          ← ★ 业务：一条规则 + 一家企业 → 一轮结果
    IReportGenerateRunner.cs   ← ★ 业务：报告生成
```

**保留在各端**：
- Auditor：`cert_expert_task_queue*` 表 + 执行器薄壳（解析 payload → 调 Runner → 包装 outcome）+ 三层进度重算（专家端特有）
- Admin：`yzh_queue` + 现有执行器

**后端 NC 测试 / 章节流程测试**：改为调 `INcCheckRunner`（同步跑）或入 `yzh_queue`（异步跑）—— **需裁决走哪种**。

### 6.3 ✅ 已执行：常量辨析 + 真正的去重

**用户提出**：「`YzhVirtualEnterprise.cs` 和 `CoreOrgCodes.cs` 是一个东西吧，如果一开始或文档写的是 `YZH-STD-ENT` 继续沿用 `YzhVirtualEnterprise` 的代码并清除重复代码」

**实测结论：⛔ 二者不是同一个东西，不可合并。**

| 项 | `YzhVirtualEnterprise.Code` | `CoreOrgCodes.StdEnv` |
|---|---|---|
| 字面量 | `YZH-STD-ENT` | `yzh-std-env` |
| 管哪一列 | **`EnterpriseCode`** | **`OrgCode`** |
| 维度 | 企业（config/file 表「模板行」标记） | 机构（后台标准级数据归属） |
| 裁决 | 2026-09-28 Q1（06 册 03 号 §四） | 2026-10-12（规则册 §二） |
| 守卫 | 字面量禁出现（引用常量） | **A-R9** 字面量只许在 `CoreOrgCodes.cs` |

**硬证据（可复算）**：
```sql
-- ① cert_standard_directory_file 根本没有 OrgCode 列 ⇒ 两常量物理上不可能同义
SELECT COUNT(*) FROM information_schema.COLUMNS WHERE TABLE_SCHEMA='yzh_cert_platform'
  AND TABLE_NAME='cert_standard_directory_file' AND COLUMN_NAME='OrgCode';   -- ⇒ 0
-- `SELECT … WHERE OrgCode='yzh-std-env'` ⇒ ERROR 1054 Unknown column 'OrgCode'
-- ② 该表 EnterpriseCode 现状 = 23 行全空串（既非 YZH-STD-ENT 也非 yzh-std-env）
```
**文档侧**：`docs/30-项目规则/跨端共享与核心资源检索规则-V1.md` 中 `yzh-std-env` 出现 **14 次**、`YZH-STD-ENT` **0 次**
⇒ 文档写的是 `yzh-std-env`；但**文档原本没有覆盖另一个常量** ⇒ 已补 **§2.7** 专节（含三种「看起来像去重」的错误合并）。
**前端侧**：`cert/cert-share/src/constants/` 只有 `virtualEnterprise.ts`，**无** `yzh-std-env` 前端常量 ⇒ 前端无重复。

**⇒ 本轮真正清掉的重复**（别名 ≠ 去重）：

| 位置 | 原形态 | 处置 |
|---|---|---|
| `Admin/Services/DocExtraction/DocExtractionRuleService.cs:55` | `public const string YzhStandardEnterpriseCode = YzhVirtualEnterprise.Code;`（同文件 6 处使用：`:321/611/618/724/727/803`） | **已删别名**，6 处直接引用 `YzhVirtualEnterprise.Code`（该文件已有 `using CertPlatform.Shared.Constants;`） |
