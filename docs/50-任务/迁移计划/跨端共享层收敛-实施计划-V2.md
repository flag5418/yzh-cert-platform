## 一 目标（两句话：目的 + 手段）

> ### 目的（用户原话，本计划的最高目标）
>
> **把体系认证的核心数据（主要是检索）统一到一个通用方法中**，作为公共方法 ——  
> 避免**不同逻辑里查到的结果不一致**。这种问题**极其隐蔽**，正式系统跑起来会让系统**非常不稳定**。
>
> ### 手段
>
> 让 `CertPlatform.Shared` 成为**唯一**的跨端共用面：两端都用的代码只能在 Shared；  
> Shared 不得反向依赖任何一端；两端之间零引用。并且**由守卫固化**（可执行、可回退、基线 0），**不靠自觉**。
>
> ⚠️ **顺序不能颠倒**：依赖方向收敛是手段，**检索口径唯一才是目的**。  
> 只把代码搬进 Shared、但同一份数据仍有 4 种查法 ⇒ **等于没做**。

### 3.3 四条边界判据（可操作，用于每次判断「该放哪 / 该不该新写一个查询」）

1. **两端都用 ⇒ 进 Shared；只有一端用 ⇒ 留在该端**（已有 R17 的判据，从实体扩展到服务/DTO）。
2. **Shared 里出现「当前登录人 / 当前工作区」等宿主语义 ⇒ 放错了** —— 这类信息必须由调用方以**参数**传入（例：`cert_fill_param_value` 的 `savedValue` 三入参就是正确形态）。
3. **Shared 里出现 `using CertPlatform.Admin` / `using CertPlatform.Auditor` ⇒ 一定放错了**（成环）。
4. **★ 要查「机构 / 标准 / 阶段 / NC规则 / 章节规则 / 填写规则 / 提取规则」⇒ 先看 `CoreResourceQuery` 有没有；没有就加在那里，⛔ 不许在调用方新写一个查询。**
