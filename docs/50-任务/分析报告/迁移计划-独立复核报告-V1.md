## 二 核心发现详述

### F1（P0）`cert_cert_stage`「双实体」是误判，且修法会重现已修 bug

**①号文档 §1.3 原文**：
> ⚠️ **实测发现：同一张表有两个实体定义** —— `cert_cert_stage` 同时定义在
> `Admin/Entities/Cert/CertStageView.cs:33` 与 `Shared/Entities/Cert/CertStage.cs:25`。
> 这是**定时炸弹**：改一处漏另一处 ⇒ 字段/映射静默漂移。全仓仅此 1 例，必须随迁移清除。

**§1-4 给的修法**：
> 消除 `cert_cert_stage` 双定义：保留 `Shared/Entities/Cert/CertStage.cs`，
> 把 `CertStageView` 改为**视图实体**（换表名/加 `IsIgnore`），或并入

**实测（`CertPlatform.Admin/Entities/Cert/CertStageView.cs:1-38`）**：

```csharp
/// 架构设计（T+V 模式）：
/// - T = CertStage（实体表，用于增删改，位于 CertPlatform.Shared/Entities/Cert/）
/// - V = CertStageView（视图，用于显示，包含关联字段）
/// 数据来源：v_cert_stage MySQL 视图
///
/// ★ 归属（2026-10-08 guards R17）：后台端独占（仅 CertStageController 消费）
///   ⇒ 按 24-后端实体归属清单 §一 从 Shared/Entities/Cert/ 下沉到本目录
/// ★ 2026-10-08 启用（用户裁决…）
[ViewName("v_cert_stage")]
[SugarTable("cert_cert_stage")]
[NotMapped]
public class CertStageView : CertStage   // ← 继承，不是第二个独立定义
```

三条反驳：

| # | 文档说 | 实测 |
|---|---|---|
| 1 | 「两个实体定义」 | `CertStageView` **继承** `CertStage`（`public class CertStageView : CertStage`）⇒ 是 **T+V 一个模型的两个面**，不是两份定义 |
| 2 | 「改为视图实体（换表名/加 `IsIgnore`）」 | 它**已经是**视图实体：`[ViewName("v_cert_stage")]` + `[NotMapped]` |
| 3 | 「加 `IsIgnore`」 | 注释原文：「⛔ 关键组合：`IsIgnore=true` 会把字段从 SELECT 也剔除 ⇒ **`/filter` 返回恒空串（2026-10-08 实测踩坑）**；`IsOnlyIgnore*` 只从 INSERT/UPDATE 剔除、SELECT 保留」 |

**⇒ 结论**：这是 **skill 铁律 #3「文档说有问题、代码其实是有意设计」** —— 最危险的一类错。
它已经过 **2026-10-08 的 guards R17 + 用户裁决**，`[SugarTable]` 显式写也是**刻意**的
（SqlSugar `GetTableName(inherit:false)` 不继承基类特性，不写会解析成表名 `CertStageView`，表不存在）。
**照文档做 ⇒ 破坏用户裁决 + 重现「`/filter` 恒空串」。**

> **登记为 C 类（修法唯一：不改）。** 若 ①号文档进入执行，必须先删掉它的 §1.3 与 §1-4。
