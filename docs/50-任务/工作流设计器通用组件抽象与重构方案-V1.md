## 〇、实施结果（2026-09-22 补充）

本方案已落地，最终形态与原始方案有两点偏差，以本节为准：

1. **通用组件位置**：不是放在 `nc-config/` 下，而是抽到 **`cert-share/src/components/workflow/`**，供管理员端与（后续）审核员端共用：
   - `WorkflowDesigner.vue`（画布主组件，props 驱动：`title`/`treeConfig`/`saveConfig`/`workflowType`/`executeConfig`）
   - `ExecutionResultPanel.vue` / `NodePropertyForm.vue` / `SkillPanel.vue` / `panels/*`
   - 逻辑层 `cert-share/src/composables/workflow/`（`compiler`/`serializer`/`topology`/`useWorkflowStore`/`specialNodes`/`nodeIdGenerator`）
2. **两个业务页面退化为薄包装层**：`nc-config/designer.vue` 与 `report-rule-config/index.vue` 各约 70 行，只声明 `treeConfig` / `saveConfig` / `executeConfig` 三个配置对象，不含任何工作流逻辑。
   这正是「三层同构 + 配置驱动」的落地形态。

**遗留清理项**：`cert-admin/src/pages/workflow/nc-config/` 下仍残留 9 个重构前的旧副本文件
（`ExecutionResultPanel.vue`、`NodePropertyForm.vue`、`SkillPanel.vue`、`adapters/branchNode.ts`、
`composables/{compiler,useWorkflowStore}.ts`、`panels/{PortControl,PromptRefEditor,CustomParamsEditor}.vue`），
**全项目零引用**（已用 grep 核实），其中 `ExecutionResultPanel.vue` 仍是 camelCase 旧版，
与 `cert-share` 同名文件形成误导性重复。待确认后删除。

## 三、新旧架构完整差异对比

> 本节对比历史项目（vol.web）与新架构（certplatform-web）在同一功能上的实现差异，供评审参考。

### 3.1 宏观架构差异

| 维度 | 历史项目（vol.web） | 新架构（certplatform-web） |
|------|---------------------|--------------------------|
| API 客户端 | `proxy.http.get/post`（Vol 框架注入） | `yzhApi.post/get`（`@yzh-core/api/client`） |
| 图标库 | `@/yzh/icons`（自封装 icon 前缀） | Element Plus 直引（`<el-icon><Setting /></el-icon>`） |
| 页面标题 | `<CertPageHeader>` 组件 | 手写 `.page-header` div |
| 路径结构 | `vol.web/src/views/cert/admin/business/Standard/` | `cert-admin/src/pages/workflow/` |
| 共享组件来源 | `@/components/workflow-designer/` | `@share/components/workflow/`（**已迁移至 cert-share**，nc-config 侧仅剩零引用旧副本待清理） |
| composable 来源 | `@/components/workflow-designer/store/` | `@share/composables/workflow/`（**已迁移至 cert-share**） |

### 3.2 API 调用方式变化

**历史项目：**
```js
proxy.http.get('/api/standard-directory/organization-tree', null, false)
// 返回 res?.Data || res?.data（大写 Data 兼容）
```

**新架构：**
```js
yzhApi.get('/api/Workflow/StandardDirectory/organization-tree')
// 后端实际返回 { success, message, data: [...] }，data 直接是数组
// WorkflowDesigner.loadTree 仍保留 res?.data?.Data || res?.data || res?.Data 三层兜底（防御性，非必需）
```

> ⚠️ 注意：组织树是**服务层手写 DTO（camelCase：`id`/`label`/`cbCode`/`stdCode`/`phaseCode`）**，
> 而实体接口（`/api/ValidationRule/filter`、`/api/ReportDefinition/section/by-context`）返回 **PascalCase**。
> 两者不同源，属 `项目全局规则.md` §16.9 已登记例外 E4。混用会导致过滤条件对不上（表现为「树点开后 0 条」）。

### 3.3 树加载接口映射差异

| 功能 | 历史项目 API | 新架构 API | 兼容性 |
|------|-------------|-----------|--------|
| Skill 列表 | `api/skill/query-nodes` | `/api/Workflow/WfSkill/filter` | ⚠️ 不同 |
| 分类列表 | `api/skill-category/list` | `/api/Workflow/WfSkillCategory/filter` | ⚠️ 不同 |
| 文档规则 | `api/DocExtractionRule/configured-rules` | `/api/Workflow/DocExtractionRule/configured-rules` | ✅ 一致 |
| 字段表格 | `api/DocExtractionRule/${code}/fields-tables` | `/api/Workflow/DocExtractionRule/${code}/fields-tables` | ✅ 一致 |
| 组织树 | `api/standard-directory/organization-tree` | `/api/Workflow/StandardDirectory/organization-tree` | ⚠️ 路径不同 |
| 章节列表 | `api/report-definition/section/by-context` | `/api/ReportDefinition/section/by-context` | ⚠️ 大小写+路径不同 |
| NC 规则列表 | `api/validation-rule/list?orgCode=...` | `/api/ValidationRule/filter`（`WorkflowDesigner` 的 `treeConfig.loadApi` 驱动，**非** `useYzhTreeTable`） | ⚠️ 路径+方法不同 |

interface Props {
  // 页面标题
  title: string
  
  // 左栏树配置
  treeConfig: {
    loadApi: string                // 树数据加载 API
    childrenApi?: string           // 子节点懒加载 API

  }
}

function initDiagram() {
  const ensureSizeThenInit = (attempt = 0) => {
    const el = canvasRef.value

      createLogicFlowInstance()
      return

    keyboard: { enabled: false },

  // 事件绑定...

    diagram.value.render({ nodes: [], edges: [] })

  // ResizeObserver（已有，保持）

  // 初始化后立即校准尺寸
  nextTick(() => {

      const { clientWidth, clientHeight } = canvasRef.value
      if (clientWidth > 0 && clientHeight > 0) {

### 6.4 执行验证功能

```javascript
// 新增状态
const executing = ref(false)
const executionResult = ref(null)

// 新增方法（含拓扑校验前置）
async function handleExecuteTest() {
  if (!currentSection.value) {
    ElMessage.warning('请先选择报告章节')
    return
  }
  if (!store.state.nodes.length) {
    ElMessage.warning('画布为空，请添加节点')
    return
  }

  // 前置拓扑校验（与 nc-config 对齐）
  const config = serialize(store.state.nodes, store.state.edges, {
    version: 1,
    workflowType: 'report'  // 注意：report 用 'report'，不是 'validation'
  })

  const analysis = analyzeWorkflowTopology(config)
  if (!analysis.validation.valid) {
    const errorMessages = analysis.validation.errors.map((e) => `  ✗ ${e.message}`).join('\n')
    ElMessageBox.alert(
      `拓扑校验失败，请先修复以下问题后再执行验证：\n\n${errorMessages}`,
      '执行验证 - 拓扑校验失败',
      { type: 'error', confirmButtonText: '确定' }
    )
    return
  }

  executing.value = true
  executionResult.value = null

  try {
    const res = await yzhApi.post('/api/Workflow/test/run', {
      taskType: 'TEST',
      ruleCode: currentSection.value.code || currentSection.value.Code,
      enterpriseCode: currentSection.value.enterpriseCode || 'YZH-STD-ENT',  // fallback 兜底
      standardCode: currentSection.value.standardCode || currentFilter.standardCode,
      phaseCode: currentSection.value.phaseCode || currentFilter.phaseCode,
      configJson: JSON.stringify(config)
    })

    if (res?.success !== false && res?.data) {
      executionResult.value = res.data
      if (res.data.isSuccess) {
        ElMessage.success(`执行完成：${res.data.status} (${res.data.durationMs}ms)`)
      } else {
        const errorMsg = res.data.ncResult?.error || res.data.status || '执行失败'
        ElMessageBox.alert(`工作流执行失败：\n\n${errorMsg}`, '执行验证 - 执行失败', {
          type: 'error', confirmButtonText: '确定'
        })
      }
    } else {
      const errorMsg = res?.error || res?.message || '执行失败'
      ElMessageBox.alert(`工作流执行失败：\n\n${errorMsg}`, '执行验证 - 执行失败', {
        type: 'error', confirmButtonText: '确定'
      })
    }
  } catch (e) {
    ElMessage.error('执行验证失败: ' + (e.message || e))
  } finally {
    executing.value = false
  }
}
```
