## 二、阶段一：执行日志真实性修复（P0）

### 2.1 目标

让 `wf_node_execution` 的每一行都**如实**反映该节点：真实状态、真实输出、真实耗时、真实时序、真实复用标记。

### 2.2 改动

**① `Models/NodeExecutionResult.cs` —— `PathResult` 增字段**

```csharp
/// <summary>路径内每个节点的执行明细（按执行顺序）</summary>
public List<NodeExecutionRecord> NodeResults { get; set; } = new();

public class NodeExecutionRecord
{
    public string NodeId { get; set; } = "";
    public bool Success { get; set; }
    public string? Error { get; set; }
    public Dictionary<string, object> Output { get; set; } = new();
    public int DurationMs { get; set; }
    public bool IsReused { get; set; }
    public DateTime StartedAt { get; set; }
    public DateTime CompletedAt { get; set; }
}
```

**② `WorkflowInterpreter.ExecutePathAsync` —— 填充 `NodeResults`**

在现有 `executedNodes[node.NodeId] = result` 之后追加记录，覆盖**复用分支**与**真执行分支**两种路径：

```csharp
// 复用分支
if (executedNodes.TryGetValue(node.NodeId, out var existingResult)) {
    pathResult.NodeResults.Add(new NodeExecutionRecord {
        NodeId = node.NodeId,
        Success = existingResult.Success,
        Error = existingResult.Error,
        Output = existingResult.Output,
        DurationMs = existingResult.DurationMs,
        IsReused = true,                  // ← 显式标记复用
        StartedAt = ..., CompletedAt = ...,
    });
    ...
}

// 真执行分支
var nodeSw = Stopwatch.StartNew();
var result = await _nodeExecutor.ExecuteAsync(...);
nodeSw.Stop();
pathResult.NodeResults.Add(new NodeExecutionRecord {
    NodeId = node.NodeId,
    Success = result.Success,
    Error = result.Error,
    Output = result.Output,               // ← 中间节点输出不再丢失
    DurationMs = (int)nodeSw.ElapsedMilliseconds,
    IsReused = false,
    StartedAt = ..., CompletedAt = ...,
});
```

**③ `WfExecutionTaskService.SaveNodeExecutionsAsync` —— 改为按 `NodeResults` 落库**

替换现有的「靠 `pathResult.Status` 反推」逻辑：

| 字段 | 现状 | 改为 |
|------|------|------|
| `ExecStatus` | 路径级状态（失真） | `record.Success ? "completed" : "failed"`（**逐节点真实状态**） |
| `OutputJson` | 仅路径最后节点 | `record.Output` 序列化（**每节点都写**） |
| `ErrorMessage` | 仅失败节点 | `record.Error` |
| `ExecutionTimeMs` | 硬编码 `0` | `record.DurationMs` |
| `IsReused` | 硬编码 `0` | `record.IsReused ? 1 : 0` |
| `StartedAt` / `CompletedAt` | 都是 `now` | `record.StartedAt` / `record.CompletedAt` |

保留现有 `savedNodeIds` 去重（同一节点在多路径共享时只存一次），但需注意：
**复用记录应覆盖真执行记录**（若某节点在路径 A 真执行、路径 B 复用，落库应是「真执行」那次，`IsReused=0`）。

**④ `WorkflowLogger` —— 补齐路径/节点级方法（G11）**

新增 `PathStart` / `PathDone` / `PathFail` / `NodeStart` / `NodeDone` / `NodeReuse` / `BranchDecision`，
把 `WorkflowInterpreter` / `NodeExecutor` 里散落的 `_logger.LogInformation("[PATH_...]")` 统一收敛过来，保证格式一致、可机器解析。

### 2.4 执行状态：✅ 已完成并 E2E 验证通过（2026-09-22）

**实现要点（与 §2.2 设计的差异，均为实现期优化）**

| 设计原案 | 实际实现 | 原因 |
|---|---|---|
| `NodeExecutionRecord` 手写 `new` | 加 `static From(nodeId, result, isReused)` 工厂 | 两处构造点（复用/真执行）避免字段漂移 |
| `ExecutePathAsync` 内 `Stopwatch` 测节点耗时 | `NodeExecutor.ExecuteAsync` **内部**记 `startedAt`/`completedAt` | 异常路径也要有时间；且耗时本就在执行器里最准 |
| 「保留现有 `savedNodeIds` 去重」 | 改为 `GroupBy(NodeId).Select(g => g.FirstOrDefault(r => !r.IsReused) ?? g.First())` | 原 `savedNodeIds` 是「先到先得」，会把复用记录当首条 → `IsReused` 反而错 |
| §2.2 ④ 列 7 个日志方法 | 实际补齐到 **32 个**（覆盖文档 §8.2 全部 Tag） | 文档已是可机器解析契约，半补无意义 |
| — | `FinishPath` 静态方法收口路径成功/失败两出口 | 两处 `return` 各自写耗时，极易漏改 |

> **⚠️ 重要认知修正**：`wf_node_execution` 有唯一键 `uk_task_item_node (TaskCode, ItemCode, NodeId)`，
> 同一节点跨多条路径**只能落一行**。去重时**优先保留真执行记录**，

## 七、建议执行顺序与依赖

```
阶段一 (日志真实性)  ─┬─→ 阶段二 (入口统一+落库) ─┬─→ 阶段四 (前端可视化)
                      │                            │
                      └─→ 阶段三 (路径表) ─────────┘
                                                    
阶段五 (剩余缺口)  ── 可并行，互不依赖
```

**理由**：阶段一修的是**数据真实性**——如果日志本身是错的（中间输出丢失、状态失真、耗时全 0），
阶段二/四建在其上的入口统一与可视化只会把错误数据放大。**必须先修数据。**

## 九、风险与注意事项

| 风险 | 说明 | 应对 |
|------|------|------|
| **同步→异步行为变更** | 队列化会让前端拿不到即时结果 | 分两步走（§3.3），先落库后队列化 |
| **`OutputJson` 体积膨胀** | 每节点都写输出，AI 节点输出可能很大 | ✅ 已实现：`SerializeOutput` 64KB 上限 + `_truncated` 合法 JSON 信封（见 §4.4 关键实现点 3）；定期归档策略仍待定 |
| **多路径共享节点的落库语义** | 同节点在多路径中出现，`wf_node_execution` 只能存一行 | ✅ 已解：节点表去重「优先保留真执行」，路径维度由 `wf_path_execution.ReusedCount` 承担（见 §4.4） |
| **`PathResult` 结构变更影响面** | `TaskPathResult`（响应 DTO）与 `PathResult`（内部模型）需同步 | ✅ 阶段一已同步新增 `NodeResults`/`DurationMs`/`StartedAt`/`CompletedAt`（前端无需为节点明细再发一次查询）。代价是响应体变大 —— 阶段四若要分页/懒加载，再改为独立查询端点 |
| **旧表 `wf_workflow_execution_log`** | 物理删除涉及存量数据 | 先标注 DEPRECATED（已在 DDL 脚本内完成），删除需用户确认 |
| **新建表 COLLATE 漏写** | MySQL 8 默认 `utf8mb4_0900_ai_ci`，与执行模型族的 `general_ci` 冲突 → 跨表 JOIN 报 1267 | 新增执行模型族表时**必须显式写 `COLLATE=utf8mb4_general_ci`** |
| **会话期间的并行编辑** | 本工作区存在另一路活跃编辑（见上一轮报告 §10.3） | 动 `cert-share` 前先确认 `useFileTree.ts` 等文件已稳定，避免互相覆盖 |
