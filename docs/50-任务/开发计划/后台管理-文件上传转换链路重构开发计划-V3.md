## 第二篇 ★ OCR 接口化设计（本版核心）

### 2.1 设计目标（对应你的三点要求）

| 你的要求 | 设计落点 |
|---|---|
| 「OCR 采用接口方式处理」 | 定义 `IOcrProvider` 接口 + `OcrResult` 契约 |
| 「默认成功即可」 | 提供 `DefaultOcrProvider`，**直接返回成功** + 占位 markdown |
| 「后续接入后不影响当前代码，自动执行」 | **DI 单点替换**（1 行），调用点零改动；存量文件可批量重转 |
| 「让当前的文件上传逻辑完整」 | 所有文件（含图片/扫描件）都能走到 `MarkdownStatus='completed'`，**无断点** |

### 2.2 接口契约（新建 `CertPlatform.Shared/DocExtraction/IOcrProvider.cs`）

```csharp
namespace CertPlatform.Shared.DocExtraction;

/// <summary>
/// OCR 识别提供者 —— 第三方付费 AI 的唯一接入点。
/// <para>本期由 DefaultOcrProvider 占位（默认成功）；接入第三方时只需替换 DI 注册的实现类。</para>
/// </summary>
public interface IOcrProvider
{
    /// <summary>是否已接入真实 OCR 服务（默认实现返回 false，可用于前端提示）</summary>
    bool IsAvailable { get; }

    /// <summary>识别图片 / 扫描件 → Markdown</summary>
    Task<OcrResult> RecognizeAsync(byte[] content, string fileName, CancellationToken ct = default);
}

/// <summary>OCR 结果</summary>
public class OcrResult
{
    public bool Success { get; set; }
    public string Markdown { get; set; } = "";
    public string Message { get; set; } = "";

    public static OcrResult Ok(string markdown, string message = "") => new() { Success = true, Markdown = markdown, Message = message };
    public static OcrResult Fail(string message) => new() { Success = false, Message = message };
}
```

### 2.3 默认实现（本期，新建 `CertPlatform.Shared/DocExtraction/DefaultOcrProvider.cs`）

```csharp
/// <summary>
/// 默认 OCR 实现：未接入第三方服务时的占位。
/// ★ 直接返回成功 —— 保证上传→转换→产物链路完整闭环，不产生断点。
/// ★ 接入第三方 OCR 时，替换 DI 注册即可，本类无需修改、调用方无需修改。
/// </summary>
public class DefaultOcrProvider : IOcrProvider
{
    public bool IsAvailable => false;

    public Task<OcrResult> RecognizeAsync(byte[] content, string fileName, CancellationToken ct = default)
    {
        var placeholder = $"""
            # {fileName}

            > ⚠️ 本文档为图片或扫描件，需要 OCR 识别。
            > 当前尚未接入 OCR 服务，暂无文本内容。
            > 接入后将自动重新生成。
            """;
        return Task.FromResult(OcrResult.Ok(placeholder, "OCR 未接入（占位内容）"));
    }
}
```

### 2.5 调用点（`OfficeConvertService.ConvertToMarkdownAsync`）

```csharp
// 1. 判断是否需要 OCR
var ext = Path.GetExtension(file.FileName ?? "").ToLowerInvariant();
bool needOcr = OcrImageExtensions.Contains(ext);          // 图片格式 → 直接 OCR
ConvertResult? anydocResult = null;

// 2. 非图片 → 先试 anydoc
if (!needOcr)
{
    anydocResult = await _convertClient.ConvertToMarkdownAsync(file.FileName, ms.ToArray());
    if (!anydocResult.Success)
        needOcr = true;                                    // anydoc 失败（扫描版等）→ 转 OCR
}

// 3. OCR 分支（★ 本期由 DefaultOcrProvider 保证成功）
string markdown;
if (needOcr)
{
    var ocrResult = await _ocrProvider.RecognizeAsync(ms.ToArray(), file.FileName);
    if (!ocrResult.Success)
    {
        file.MarkdownStatus = "failed";
        file.MarkdownMessage = ocrResult.Message;
        await _db.UpdateAsync(file);
        return false;
    }
    markdown = ocrResult.Markdown;
    file.MarkdownMessage = ocrResult.Message;              // 例："OCR 未接入（占位内容）"
}
else
{
    markdown = Encoding.UTF8.GetString(anydocResult!.Content!);
    file.MarkdownMessage = null;
}

// 4. 产物上传 MinIO + 回写（所有分支统一出口）
var targetPath = BuildProductPath(file.StoragePath, "markdown", ".md");
await _storage.UploadAsync(targetPath.TrimStart('/'), new MemoryStream(Encoding.UTF8.GetBytes(markdown)), ..., "text/markdown");
file.MarkdownPath = "/" + targetPath.TrimStart('/');
file.MarkdownStatus = "completed";
file.MarkdownDate = DateTime.Now;
await _db.UpdateAsync(file);
```

### 2.7 图片与扫描件的判定规则

| 文件类型 | PDF 产物 | Markdown 产物 |
|---|---|---|
| Office（doc/docx/xls/xlsx/ppt/pptx） | LibreOffice → `pdf/{stem}.pdf` | anydoc → `markdown/{stem}.md` |
| 文本类（csv/txt/rtf/odt/ods/odp/epub） | 不产（`ConvertStatus='skipped'`） | anydoc → `markdown/{stem}.md` |
| **PDF（有文本层）** | 透传（`PreviewPdfPath = StoragePath`） | anydoc → `markdown/{stem}.md` |
| **PDF（扫描版，anydoc 退出码 1）** | 透传（`PreviewPdfPath = StoragePath`） | **→ OCR**（本期占位成功） |
| **图片（jpg/jpeg/png/gif/bmp/webp）** | `PreviewPdfPath = StoragePath`（前端 `<img>` 渲染） | **→ OCR**（本期占位成功） |
| 压缩包等不支持格式 | 不产 | `MarkdownStatus='skipped'` |

## 第三篇 完整链路设计

### 3.1 数据模型（零 DDL）

| 字段 | 新语义 | 取值 |
|---|---|---|
| `StoragePath` | ①真实路径（原件） | 不变 |
| `PreviewPdfPath` | ②预览路径 | Office → `.../pdf/{stem}.pdf`；**PDF/图片 → 同 `StoragePath`**；文本类 → `NULL` |
| `ConvertStatus` | **PDF 产物**状态 | `pending`/`converting`/`completed`/`failed`/`skipped` |
| `MarkdownPath` | ③提取源路径 | `.../markdown/{stem}.md` |
| `MarkdownStatus` | **MD 产物**状态 | `none`/`pending`/`converting`/`completed`/`failed`/`skipped`（★**不新增 `ocr_required`**） |
| `MarkdownMessage` | 备注（失败原因 / **OCR 占位标记**） | 例："OCR 未接入（占位内容）" |
| `ConvertedStoragePath` | **遗留**（停止新增） | 存量保留 |

> `MarkdownMessage` 语义扩展：**`MarkdownStatus='completed'` 且 `MarkdownMessage` 非空** ⇒ 该产物是 OCR 占位内容（前端可据此提示）。

### 3.2 MinIO 存储结构（目标态）

```
cert-platform/
└── standard-directory/                    ← 文档库前缀（抽象层参数）
    └── {OrgCode}/{StandardCode}/{PhaseCode}/
        └── {FolderPath}/
            ├── XASL-QM 质量手册.doc        ← 原件（StoragePath）
            ├── pdf/
            │   └── XASL-QM 质量手册.pdf    ← 预览产物（PreviewPdfPath）
            └── markdown/
                └── XASL-QM 质量手册.md     ← 提取源（MarkdownPath）
```

**后续企业资料库（本期只预留结构，不落地）**：`enterprise-documents/{EnterpriseCode}/{OrgCode}/{StandardCode}/{PhaseCode}/{FolderPath}/...`（同一套 `pdf/` + `markdown/` 规则）

### 3.3 路径生成规则（★ 关键设计）

产物路径**从源文件 `StoragePath` 推导**：

```
BuildProductPath(storagePath, "pdf"|"markdown", ext)
  /a/b/c/1质量手册/XASL-QM 质量手册.doc
  → /a/b/c/1质量手册/pdf/XASL-QM 质量手册.pdf
  → /a/b/c/1质量手册/markdown/XASL-QM 质量手册.md
```

**四条理由（均有实测支撑）**：
1. **规避空参 bug** —— 现有 4 个入队点传 `("","","","")` → 产物路径丢层级（磁盘 154 个对象堆一层即为此故）
2. **文件夹重命名自动一致** —— 源路径变则产物路径跟着推导（踩坑记录 `2026-08-13` 正是此 bug）
3. **无需再查 config 取 StandardCode/PhaseCode** —— 少一次 DB 往返
4. **`OrgCode` 缺失不放大** —— 产物跟随源路径

### 3.4 双队列设计（你的第 1、2 点）

上传确认后建 **2 个队列**：

| 队列 | QueueType | QueueName | 每文件 Task | 资源锁 |
|---|---|---|---|---|
| A · PDF | `file_convert` | 文档预览转换-PDF-{N}个文件 | `ConvertType=office2pdf` | DIR + FILE |
| B · Markdown | `file_convert` | 文档提取转换-Markdown-{N}个文件 | `ConvertType=anydoc2md` | DIR + FILE |

**锁策略：串行**（两个队列都锁 DIR → A 完成才启动 B）。理由：避免 LibreOffice 与 anydoc 争抢 CPU/内存。
**若需并行**：队列 B 改为只锁 FILE（不锁 DIR）即可，无其他改动。

> 前端 `getActiveQueue` 需从「返回单个队列」改为「返回队列数组」。

### 3.5 文档库抽象（你的第 6 点）

```csharp
/// <summary>文档库定义（抽象层）</summary>
public sealed record DocumentLibrary(string RootPrefix, string DisplayName)
{
    public static readonly DocumentLibrary Standard   = new("standard-directory",   "标准目录");
    public static readonly DocumentLibrary Enterprise = new("enterprise-documents", "企业资料");
}

/// <summary>从存储路径反解所属文档库 —— 即「通过输入文件路径区分」</summary>
public static DocumentLibrary ResolveLibrary(string storagePath)
{
    var root = storagePath.TrimStart('/').Split('/', StringSplitOptions.RemoveEmptyEntries).FirstOrDefault();
    return root switch
    {
        "standard-directory"   => DocumentLibrary.Standard,
        "enterprise-documents" => DocumentLibrary.Enterprise,
        _ => throw new NotSupportedException($"未知文档库前缀：{root}")
    };
}
```

- `CodeGeneratorService` 路径方法增加 `rootPrefix` 参数
- `ControllerSafetyExtensions.IsAllowedStoragePath`（`StandardDirectoryController.cs:403-415`）→ 白名单改为遍历 `DocumentLibrary` 全集
- `DeriveOrgCodeFromPath`（`StandardDirectoryService.cs:2012-2021`）→ 复用 `ResolveLibrary`，消除已有的 `if/else if` 硬编码

**本期边界**：`DocumentLibrary.Enterprise` **只定义、不消费**（企业端未到开发阶段，避免历史包袱）。

### 3.6 提取链路（你的第 7 点）

`GetDocumentMarkdownAsync` 改为三段式：

```
1. MarkdownPath 非空且 MarkdownStatus='completed'
   → 读 MinIO 产物返回                                    ← 主路径（上传时已生成）
2. MarkdownPath 为空（存量文件 / 转换失败）
   → 补产：anydoc（或 OCR）→ 上传 MinIO → 回写 DB → 返回   ← 兜底，且落库
3. 均不可用
   → 返回明确错误（区分"无产物"与"OCR 占位"）
```

**关键**：兜底**必须落库**（现状不落库 → 每次重转，这是你观察到的"预览时才动态转"的根因）。
