### 1.1 现状

当前系统通过角色-菜单配置控制用户可访问的页面，但缺少**接口级权限控制**。为实现细粒度的安全防护，需要建设接口权限管理能力。

### 1.2 目标

| 目标 | 说明 |
|------|------|
| 接口自动发现 | 通过反射扫描所有 Controller 接口，自动生成接口记录 |
| 接口权限配置 | 支持为角色批量授权接口访问权限 |
| 自动清理 | 接口更新时自动清理无效的角色-接口关联 |
| 用户权限缓存 | 预计算用户权限列表，加速权限校验 |

## 二、数据库设计

### 2.1 sys_api（接口记录表）

> 存储所有通过反射发现的接口信息。

```sql
CREATE TABLE IF NOT EXISTS sys_api (
    id          BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
    code        VARCHAR(64) NOT NULL COMMENT '接口编码（ApiCode Hash）',
    method      VARCHAR(10) NOT NULL COMMENT 'HTTP方法: GET/POST/PUT/DELETE',
    path        VARCHAR(200) NOT NULL COMMENT '接口路径（如 /api/System/User/filter）',
    group_path  VARCHAR(200) NOT NULL COMMENT '业务分组（如 系统管理/用户管理）',
    name        VARCHAR(200) NOT NULL COMMENT '接口名称',
    author      VARCHAR(50) COMMENT '负责人（可选）',
    enable      TINYINT(1) DEFAULT 1 COMMENT '是否启用（0=禁用，前端不展示）',
    create_date DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_date DATETIME ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    UNIQUE INDEX uk_api_code (code),
    INDEX idx_api_group (group_path),
    INDEX idx_api_path (path)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='接口记录表';
```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| code | VARCHAR(64) | 接口唯一编码，基于 Route+Method+Action+Parameters 的 SHA256 Hash |
| method | VARCHAR(10) | HTTP 请求方法 |
| path | VARCHAR(200) | 完整接口路径 |
| group_path | VARCHAR(200) | 业务分组路径，从 `[ApiDescription(Group="系统管理/用户管理")]` 获取 |
| name | VARCHAR(200) | 接口名称，从 `[ApiDescription(Description="...")]` 获取 |
| author | VARCHAR(50) | 负责人（可选） |
| enable | TINYINT(1) | 是否启用，0=禁用（前端不展示、不可勾选） |

### 2.2 sys_role_api（角色-接口关联表）

> 存储角色与接口的多对多关联关系。

```sql
CREATE TABLE IF NOT EXISTS sys_role_api (
    id          BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
    role_code   VARCHAR(50) NOT NULL COMMENT '角色编码（关联 Sys_Role.Code）',
    api_code    VARCHAR(64) NOT NULL COMMENT '接口编码（关联 sys_api.code）',
    create_date DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    UNIQUE INDEX uk_role_api (role_code, api_code),
    INDEX idx_api_code (api_code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='角色-接口关联表';
```

### 2.3 sys_user_permission（用户权限缓存表）

> 预计算用户对接口的访问权限，格式：用户编码 + 接口编码。

```sql
CREATE TABLE IF NOT EXISTS sys_user_permission (
    id          BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
    user_code   VARCHAR(36) NOT NULL COMMENT '用户编码（关联 Sys_User.Code）',
    api_code    VARCHAR(64) NOT NULL COMMENT '接口编码（关联 sys_api.code）',
    create_date DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_date DATETIME ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    UNIQUE INDEX uk_user_api (user_code, api_code),
    INDEX idx_user_code (user_code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户权限缓存表（角色-接口关联的展开表）';
```

## 三、特性设计（Attribute）

### 3.1 ApiDescriptionAttribute

```csharp
// 位置：src/yzh-core/YZH.Core.Api/Attributes/ApiDescriptionAttribute.cs
[AttributeUsage(AttributeTargets.Method, AllowMultiple = false, Inherited = true)]
public class ApiDescriptionAttribute : Attribute
{
    /// <summary>接口名称</summary>
    public string Description { get; set; } = "";
    
    /// <summary>业务分组（如 系统管理/用户管理）</summary>
    public string Group { get; set; } = "";
    
    /// <summary>负责人（可选）</summary>
    public string Author { get; set; } = "";
    
    /// <summary>是否启用（默认 true）</summary>
    public bool Enable { get; set; } = true;
    
    public ApiDescriptionAttribute(string description = "", string group = "", string author = "", bool enable = true)
    {
        Description = description;
        Group = group;
        Author = author;
        Enable = enable;
    }
}
```

### 3.2 使用示例

```csharp
[ApiController]
[Route("api/System/[controller]")]
public class UserController : YzhControllerBase<Sys_User>
{
    [ApiDescription(Description = "获取用户分页列表", Group = "系统管理/用户管理", Author = "张三")]
    [HttpPost("filter")]
    public override async Task<ActionResult<ApiResponse<PagedResult<Sys_User>>>> Filter(
        [FromBody] FilterRequest request)
    {
        return await base.Filter(request);
    }

    [ApiDescription(Description = "（已废弃）旧版导出接口", Group = "系统管理/用户管理", Enable = false)]
    [HttpPost("export-old")]
    public async Task<ActionResult> ExportOld()
    {
        // 旧版接口，已禁用
        return Ok();
    }
}
```

**enable 字段使用场景**：
- 接口重构后，旧接口标记为 `Enable = false`
- 新业务已采用新接口，老业务还在使用旧接口
- 禁用后前端不展示、不可勾选，但不会删除记录

## 四、后端设计

### 4.1 接口同步服务（ApiSyncService）

#### 同步流程

```
点击【更新接口】按钮
       │
       ▼
┌─────────────────────┐
│ 1. ApiScanner.Scan()│  反射获取所有 Controller 接口
└─────────┬───────────┘
          │
          ▼
┌─────────────────────┐
│ 2. 对比差异          │  与 sys_api 表对比
│    - 新增接口        │
│    - 删除废弃接口    │  → 收集被删除的 api_code 列表
│    - 更新变化的接口  │
└─────────┬───────────┘
          │
          ▼
┌─────────────────────┐
│ 3. 清理无效关联      │  删除 sys_role_api 中引用了
│                      │  不存在 api_code 的记录
├─────────────────────┤
│ 4. 清理无效用户权限  │  删除 sys_user_permission 中
│                      │  引用了不存在 api_code 的记录
└─────────┬───────────┘
          │
          ▼
┌─────────────────────┐
│ 5. 更新 sys_api      │  删除废弃接口 + 新增/更新接口
└─────────┬───────────┘
          │
          ▼
┌─────────────────────┐
│ 6. 刷新权限缓存      │  重新展开用户权限到
│                      │  sys_user_permission 表
└─────────────────────┘
```

#### SyncResult 增强

```csharp
public class SyncResult
{
    public int Added { get; set; }      // 新增接口数
    public int Updated { get; set; }    // 更新接口数
    public int Deleted { get; set; }    // 删除接口数
    public int CleanedRoleApi { get; set; }     // 清理的角色-接口关联数
    public int CleanedUserPermission { get; set; } // 清理的用户权限记录数
    public string? Error { get; set; }
    public bool Success => string.IsNullOrEmpty(Error);
}
```

## 八、风险与注意事项

| 风险 | 说明 | 应对措施 |
|------|------|---------|
| 反射扫描性能 | 首次扫描可能耗时较长 | 异步执行 + 进度提示 |
| ApiCode 稳定性 | 接口签名变化导致 Hash 变化 | 自动清理无效关联 |
| 权限缓存一致性 | 关联变更后缓存未更新 | 同步完成后自动刷新缓存 |
| Swagger 跨域 | 新窗口打开可能有跨域问题 | 同域部署，无跨域风险 |
