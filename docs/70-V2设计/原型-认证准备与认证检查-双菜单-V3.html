认证准备 / 认证检查 · 界面设计说明

本版按 2026-11-02 的 8 条意见重做：界面只对审核员说话。模型、提示词、规则快照、装配计数、队列编号一律不上面；页面只回答四件事——这条条款要什么、手上有什么证据、哪里可疑、我该判什么。
一句话分工：认证准备帮审核员提前读懂条款、看清企业已经给了什么、把疑点列出来； 认证检查帮审核员快速录证据、一键分析、拿到证据与 NC 疑点，再把 NC 定下来。 两者都只有两个主动作：补充证据 与 分析（先后顺序不限）。

一 · 审核员在页面上只做两件事

动作做什么什么时候用
补充证据补充证据：上传文件 / 拍照 / 录音 / 写一段访谈记录；准备阶段还可以「请企业补资料」分析前先给料，或分析后发现证据不够再补。没有证据也能分析，只是结论会落到「待判断」
分析对勾选的检查项跑一轮自动分析，跑完直接出「证据 + 疑点 + 建议结论」资料齐了就分析；企业补了新资料、现场又取了证，再分析一次

收尾动作只有三个：锁定（人确认过的结论不再被后续分析改动）、导出报告（检查阶段）、生成入场计划（准备阶段的可选产出，不是必经步骤）。

二 · 两个菜单各自产出什么

菜单给审核员的东西用途不会出现
认证准备 ① 条款要点（这段条款到底要什么，人话）
② 认证证据（从企业资料里按条款抽出来的原文与出处）
③ 疑点（材料矛盾、缺失、看不出真假的地方）
④ 证据缺口（要企业补哪几份）		 让审核员在进场前就知道：这条要不要现场查、去了问谁、要什么材料。疑点 → 入场检查项是自然产物，不是强制流程 结论（符合/不符合）、NC 签发、整改要求
认证检查 ① 证据（现场取证 + 企业资料，按条款归档）
② NC 疑点（事实 + 违反哪条 + 建议档次 + 建议怎么问）
③ 建议结论（符合 / 观察项 / 不符合 + 严重度）
④ 项目总结论建议		 让审核员快速把现场变成可签发的东西：证据齐、疑点清、NC 一次签对 提示词、模型名、规则参数、装配命中数

三 · 这一版按 8 条意见改了什么

#意见落点
1审核员不需要执行细节，不用显示用了什么模型；关心什么时候完成、要用体系认证的专业术语界面移除模型 / 温度 / 提示词版本 / 规则快照 / 装配计数；改为「证据 · 疑点 · 结论 · 建议」；每处分析只给进度 + 预计完成时间（列表列「预计完成」，详情顶部「预计 4 分钟」）
2所有检查项可勾选，勾选后重新分析；锁定在检查项列表也能单独操作准备 / 检查详情表首列复选框，勾选后浮出蓝色操作条（重新分析已选 / 锁定已选 / 清除）；每行仍有独立锁定按钮，锁定到条款级
3可增加条款原文，只是一个小按钮，让审核员直接查看每个检查项后一个灰色小按钮「条款原文」，点开右侧窄抽屉（460px）：标准原文 + 关键要求 + 常见取证点 + 本企业已有证据数；不离开当前页
4入场计划不是必要结果；不要完整流程示意图；只有两个操作；部门与联系人在认证计划里定义好，准备可完善，审核员在详情可改删除两处步骤条；入场计划降级为「可选产出」，从准备详情导出，侧栏不再单列；计划页新增部门 / 联系人两列（事实源）；准备详情中「部门 · 联系人」「审核员」均带 可改，改的是本检查项
5准备是为审核员提供便利：快速了解条款细节、看分析出的档案证据，为制定入场计划做准备；检查是快速录入证据、全面分析、形成证据与 NC 疑点，辅助判断准备的抽屉改为四段：条款要点 / 企业资料里的证据 / 疑点 / 证据缺口；检查的抽屉为：证据 / NC 疑点 / 判定 / 已签 NC；两者共用「补充证据 → 分析」的交互
6执行 LLM 的逻辑和界面设计分开，先重点研究界面本文件只描述界面与交互；执行细节集中在「附录 · 术语对照」与本页第四节（后台实现），工作页面不出现
7只要执行一遍重新分析，可以是 1 轮自动分析「重新分析」= 一轮自动分析：一次提交、系统分批跑完勾选项，中途不用人盯；按钮文案统一为「开始分析（约 N 分钟）」
8准备的结论是认证证据与疑点；检查的 AI 结果也类似两端统一用「证据 + 疑点」这套语言；差异只在检查多一步「定 NC」

四 · 界面与执行的分界（后台的事，不上页面）

执行侧的事界面侧只呈现
用哪个模型、温度、提示词版本「分析」按钮 + 预计完成时间；失败时只说「分析未完成，可重试」
装配命中数（条款属性 / 切片 / 摘录条数）「本项有 2 份证据」「有 1 处疑点」——按条款汇总后的人话
规则参数、阈值、总结论算法「建议结论：一般不符合」+ 一句为什么；阈值未确认时只在报告页标「结论需复核」
队列编号与重试机制执行状态抽屉：进度 8/12、预计 10:56 完成、失败项可重试
分析留痕（输入快照、可回放）「谁在什么时候改过结论」——审计需要时才展开

五 · 界面语言约定

  • 证据：企业资料里读到的原文、现场拍的照、访谈记录。都带出处（文件 / 时间 / 部门）。
  • 疑点：需要人再看一眼的地方。写法固定三句：看到了什么 · 为什么可疑 · 建议怎么核实。
  • 建议结论：系统给的建议，永远可被审核员直接改掉，不留「你改了系统判断」的提示。
  • 待判断：材料不足以下结论时用，不等于不符合（灰，不是红）。
  • 不说「抓取 / 切片 / 装配 / 推理 / prompt」，说「资料里找到的原文 / 本项证据 / 分析」。

六 · 数据现实（影响界面预期，不影响交互）

企业资料的可读性目前偏低：119 份文档里只有 7 份能按条款定位原文。 所以界面上要能承受「证据很少、疑点很多、结论多为待判断」的状态——这不是异常，是当前常态。 因此准备详情把 证据缺口 放在显眼位置（要企业补什么），检查详情允许 0 份证据也能分析。

本原型只有界面与交互，无后端。所有按钮点击给出提示语，用于确认文案与位置； 数据结构（字段名、落库值）集中在「⑦ 附录 · 术语对照」，供开发对照，不进审核员视野。

五 · 一页能看完的交互口径

  • 分析 = 一轮自动跑完：不需要人分批点，提交后系统依次跑完全部勾选项，跑完提示。
  • 勾选 = 分析范围：勾了只跑勾选的，不勾就跑全部未锁定项；重新分析同理。
  • 锁定 = 人确认过的不再变：锁定到条款级；行内可单独锁，也可勾选后批量锁。
  • 补充证据随时可做：分析中也行；新证据并入下一轮，不会丢。
  • 结论可改：审核员改了就是最终结论，不弹对比、不做差异页。
  • 条款原文不离开页面：右侧窄抽屉，看完关掉，不丢当前过滤与勾选。
