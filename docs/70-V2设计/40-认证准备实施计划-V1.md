## 零、一句话

> **认证准备 = 以「一个企业的有效计划」为起点，把 237 份已提取的文档切片按条款装配起来，逐条款判「资料够不够、矛盾在哪、该问谁该看什么」，产出可被审核员增删改的「条款 × 部门」检查草案。**

它**不判符合性**、**不排班**、**不生成报告** —— 那是检查阶段（`inspect`）和入场计划（34 号 §四）。

## 二、边界：认证准备做什么、不做什么

| 做 | 不做 |
|---|---|
| 按计划把企业文档切片**装配到条款**上 | ⛔ 不判**符合性**（「做得对不对」留现场） |
| 判**资料完备性 + 一致性**（找到/部分/缺失/未查到） | ⛔ 不开 NC、不定结论 |
| 产出**疑点/检查点**（沟通 / 观察 / 访谈 / 核验） | ⛔ 不排班、不排半天、不分组长/组员（入场计划阶段） |
| 承接**人工线索**（沟通得来的一切）并入条款 | ⛔ 不存录音/照片（证据阶段） |
| 给「按部门过滤」提供维度 | ⛔ 不生成检查报告 |

### 2.1 锚点是「有效计划」，但结果不绑计划

- **run（批次）** 记 `PlanCode` —— 回答「这次是哪个计划触发的、跑到哪」；
- **gap / point（结果）** **只按 企业 + 标准 + 条款** 存，**不带 `PlanCode` / `StageCode`**（35 号 D-V3 不变）。

理由：**计划会变，资料不会**。带计划键 ⇒ 计划一改全部重算，而重算会覆盖审核员已经改好的结论。

## 三、三个页面的职责（用户指定：准备拆两页 + 后台提示词页）

### 3.1 专家端 · 认证准备（任务）`/readiness`

**一屏完成「选计划 → 过门禁 → 选范围 → 启动 → 看进度」**。

| 区块 | 内容 |
|---|---|
| 计划选择 | 只列 `IsValid=1` 的计划；**一企业一有效计划**，>1 直接报错 |
| **门禁面板** | 6 项检查（§四）：阻断项红、警告项黄；阻断项**可豁免**但必须填理由（落 `run.WaiverReason` + `Message`） |
| 范围选择 | 默认 = 计划明细的条款 ∪（`DocCheckMode≠none` 的叶条款）；可按树勾选/排除 |
| **Skill 勾选** | 勾「这次要不要查」的公共项（投诉记录/企业信用/行政处罚…）⇒ 结果作为该企业**补充线索**（P6） |
| 启动 | 建 `cert_readiness_run` → 入队分批跑，进度条 = `ClauseDone / ClauseTotal` |
| 失败重跑 | 只重跑 `failed` 条款；⛔ 不允许「全部重跑」按钮覆盖已审核结果（人工行受 P5 保护） |

### 3.2 专家端 · 认证准备结果审核 `/readiness-review`

**审核员在这里做四件事：删、补、归纳、定性。**

| 能力 | 说明 |
|---|---|
| **看缺口** | 条款树（四态着色：`found` 绿 / `partial` 黄 / `missing` 红 / `unknown` 灰）+ 命中文档 + **锚点可下钻原文件** |
| **看疑点** | 列表：条款 × 部门 × 方式（沟通/观察/访谈/核验）× 严重程度 × 预计分钟 |
| **删除** | `Status=dropped` + **`DropReason` 必填**（⛔ 不物理删 —— 复盘要能看出「谁在什么时候认为这条不用查」） |
| **补充/线索** | 新增行 `Origin=manual`；来源记 `SourceNote`（「电话沟通」「官网查询」「现场经验」）|
| **归纳到条款** | 未归条款的线索 → 选条款挂上去；也可把一条线索拆到多条款 |
| **批量设部门** | 按条款的 `Process`（相关过程）建议部门，人工批量确认（见 §九 Q3）|
| **定严重程度** | 模型给的 `SeveritySource=ai` **只做参考**；审核员改过 ⇒ `manual`，**只有 `manual`/`rule` 能进后续报告** |

### 3.3 后台 · 通用提示词中心 `/cert/prompt-center`（新建）

> ⚠️ 现有 `/business/prompt-template`（文档语义规则）与 `/business/extract-prompt` 类页面是 **V1 页面**，⛔ 不复用、不改（铁律零）。本页是 V2 的**唯一提示词维护入口**。

| 能力 | 说明 |
|---|---|
| 按分类看 | 分类**由 `PromptCode` 前缀推导**（⛔ 不加 `Category` 列）：`clause_attr_*` 条款属性 / `doc_*` 文档提取 / `readiness` 认证准备 / `inspect` 认证检查（后置） |
| 变量面板 | 解析正文里的 `{{var}}`，与**该类提示词的变量白名单**对照：缺变量 = 红字阻断保存；多余变量 = 黄字 |
| 作用域 | 平台级（`ScopeKey` 空）→ 标准级（`ScopeKey`=标准短码）→ 代码兜底；**用了兜底必须写进 `Message`** |
| 试跑（dry-run） | 传变量 → 只做**模板渲染**，返回渲染后正文 + 未解析变量 + 估算 token；**不调模型**（省钱、秒回） |
| 生效与留痕 | 同 `PromptCode` + 同作用域**只允许一条 `active`**；改正文保留旧行为 `Status=archived`，可回滚 |

## 四、门禁（6 项 · 阻断 / 警告）

| # | 检查 | 判据 | 等级 |
|:--:|---|---|:--:|
| G1 | 有效计划唯一 | `cert_audit_plan` 按企业 `IsValid=1` 且未删 **= 1** | **阻断**（0 条「先建计划」；>1 条「先停用多余计划」）|
| G2 | 计划带标准 | `Standards` 非空，且每个 `StandardCode` 在 `cert_iso_clause` 有条款 | **阻断** |
| G3 | 部门已建 | `cert_enterprise_dept` 该企业有效行 **≥ 1** | **阻断（可豁免）** |
| G4 | 部门有联系人 | 每个有效部门至少有 1 个 `cert_enterprise_dept_member` | **阻断（可豁免）** |
| G5 | 属性覆盖 | 目标标准「有 `DocCheckMode` 的叶条款 / 叶条款」≥ **80%**；< 30% 视为**阻断** | 警告 / 阻断 |
| G6 | L1 已跑 | `cert_document_extraction` 该标准 **≥ 1 行** | **阻断** |

**为什么 G3/G4 允许豁免**：35 号 坑 #6 已定「部门 0 行不阻塞链路」（`DeptCode` 可空、页面标「待建部门」）。硬阻断会让**第一次验证**（企业还没录部门）根本跑不起来。
⇒ **默认阻断，但可填理由豁免**，理由进 `run.WaiverReason` + 页面常驻提示。**⛔ 不许静默跳过。**

### 5.3 `cert_clause_point`（疑点 / 线索 —— 一张表承载两类）

|---|---|---|
| `Origin` | varchar(20) | `ai` / `manual` / `skill` —— **重跑保护的核心**（§八 R2）|

## 七、执行顺序 P0 → P7（**严格按序，⛔ 不许跳**）

> **为什么是这个顺序**（这是本节最该看的部分）：
> **① 数据先于代码** —— 否则引擎写好，跑出来 88 条 `unknown`，分不清是模型差还是数据空；
> **② 提示词先于执行器** —— 否则执行器写完无处可读，且「改了正文没变化」这类坑会拖到最后一刻才暴露；
> **③ 单条款先于批次** —— 否则一次烧 88 次调用，还不知道单条判得对不对；
> **④ 服务先于页面** —— 否则调试全靠刷新页面；
> **⑤ 审核闭环后于页面** —— 否则没有可改的东西；
> **⑥ Skill 最后** —— 否则勾选框挂的是空表，勾了没反应比没有更糟。

## 八、验收：V0 的四个数字（不到不放行）

| # | 指标 | 门槛 | 说明 |
|:--:|---|:--:|---|
| 1 | 8 条款全部出结论 | **8/8** | 有 `unknown` 可以，但**不许空行** |
| 2 | `unknown` 与 `missing` 可区分 | 抽查 **≥ 3 条**逐个看 `GapReason` | 文案骗人最容易发生在这一步 |
| 3 | 至少 3 条能拼 **≥ 2 份文档** | 3/8 | 证明切片装配真的跨文档，不是单文件回显 |
| 4 | `Severity` 100% 有来源 | **0 条** `SeveritySource=ai` 且值不在 `Severity` 属性内 | 红线 3 的机器化检查 |

**另外两个必查**：`DocCheckMode=none` 的条款**一条 `remote` 都不许有**；已删（`dropped`）行**不许**被重跑复活。

## 九、待裁决（开工前定，⛔ 不要边做边猜）

| # | 事项 | 我的建议 |
