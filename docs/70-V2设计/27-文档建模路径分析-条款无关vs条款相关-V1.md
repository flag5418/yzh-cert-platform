# 文档建模路径分析：条款无关 vs 条款相关（V1）

> **版本**：V1 ｜ **日期**：2026-10-28 ｜ **状态**：待审核（不拍板，仅陈述差异）
>
> **起因**：文档自动结构化方案存在两条路——"按条款无关建模"（通用提取 + 按需投影）vs "按条款相关建模"（直接按条款提取）。本文档用真实案例实证分析两条路的差异，不代用户裁决，仅呈现全貌供审核决策。
>
> **范围**：仅分析文档级数据的建模路径，不涉及 L0/L1 后台两层（已完成），也不涉及 L2/L3（暂缓）。

---

## 一、两条路一句话定义

| 路径 | 一句话 |
|---|---|
| **路径 A：条款无关** | 文档只提炼一次通用属性（内容概括、详实程度、过程、类型…），不同条款通过 Artifacts 提示词按需"投影"不同字段 |
| **路径 B：条款相关** | 文档直接按"份文档 × 条款"一条记录存储，提取时以条款为驱动，不同条款对同一份文档的提取结果在写入时就分开 |

---

## 二、真实案例实证

以下证据全部来自三份真实审核材料的原文提取（为去敏，部分名称以 X 代替）。

### 案例 1：一份《工序流转卡》被三个条款引用（科斯亚 8.5.1 条款）

**文件**：`04-记录文件/17生产和服务提供控制记录/07工序流转卡.doc`

该文件在同一次 8.5.1 条款审核中被引用了 **三次**，每次都提取不同的信息：

| 引用场景 | 审核关注点 | 提取的具体字段 | 判断目的 |
|---|---|---|---|
| **8.5.1 a) 可获得成文信息** | 产品特性、工艺要求是否成文化 | 工序名称、工艺参数规范、产品特性描述 | 证明规定已经存在 |
| **8.5.1 c) 适当阶段监视和测量** | 各阶段是否有检验点 | 工序中设置的"初检/中检/终检"检验栏 | 证明适当阶段有验证 |
| **8.5.1 g) 防止人为错误** | 操作人员是否凭经验操作 | 工序中是否明确规定了工艺要求（而非留空让操作员自行决定） | 防止操作人员随意操作 |

**关键发现**：同一份《工序流转卡》，在条款 a) 下看的是"有没有规定"，在 c) 下看的是"检验点怎么设"，在 g) 下看的是"规定是否足够详细以防错"。

> 按路径 A（条款无关）：文档属性卡描述"这是一份工序流转卡，规定了各工序的工艺要求和检验判定方式"；各条款通过 Artifacts 提示词按需投影不同字段。
> 按路径 B（条款相关）：直接生成三行——`(工序流转卡, 8.5.1a)→{规定完整性}`、`(工序流转卡, 8.5.1c)→{检验点设置}`、`(工序流转卡, 8.5.1g)→{防错充分性}`。

### 案例 2：一份《校准证书管理与预警台账》被两个条款引用（科斯亚 8.5.1 条款 / 7.1.5.2）

**文件**：`04-记录文件/03监视和测量设备控制记录/校准证书管理与预警台账(3).pdf`

该台账登记了 19 台监视和测量设备的校准信息：仪器名称、设备编号、校准证书编号、校准日期、有效期至、剩余天数及状态。

| 引用场景 | 审核关注点 | 提取的具体字段 |
|---|---|---|
| **8.5.1 b) 可获得适宜的监视和测量资源** | 是否有校准台账、校准是否在有效期内 | 设备数量（19台）、校准日期、有效期、临期预警规则 |
| **7.1.5.2 测量溯源** | 校准是否可溯源至国家标准、校准机构是否有资质 | 校准证书编号（能否对应到校准报告）、校准机构名称（是否法定机构） |

**关键发现**：同一份台账，在 8.5.1 b) 场景下看"数量够不够、有没有超期"，在 7.1.5.2 场景下看"证书是否真实、机构是否具备资质"。

### 案例 3：一份《环境因素识别及评价表》被多条款复用（北京中安质环 0721A）

**文件**：`《环境因素识别及评价表》编号:-004，编制：综合部，审批：日期：2025.11.10`

该文件在采购部审核（Q:5.3/6.2/8.4, ES:5.3/6.1.2/6.2/8.1）和生产部审核（Q:5.3/.../8.5.1, ES:5.3/6.1.2/../8.1）均被引用：

| 引用场景 | 部门 | 审核关注点 |
|---|---|---|
| **ES:6.1.2 环境因素辨识** | 采购部 / 生产部 | 该部门是否识别了自身环境因素 |
| **ES:8.1 运行策划和控制** | 采购部 / 生产部 | 对已识别的环境因素是否落实了控制措施 |

**关键发现**：同一份《环境因素识别及评价表》，在不同部门审核中读的是同一个文件的同一个部分——但也可能被不同的 Artifacts 投影（采购部关注"采购过程的环境因素"，生产部关注"生产过程的环境因素"）。

### 案例 4：一份《合规性评价报告》被多个条款交叉引用（北京中安质环 0721A）

**文件**：`《合规性评价报告》参加人员:XX/XX/XX，评审时间：2025.11.10`

该报告被以下引用：

| 引用场景 | 关注点 |
|---|---|
| **ES:6.1.3 合规义务** | 法律法规清单是否完整、是否存在废止标准（GB9078-1996 已废止但仍出现在清单中） |
| **ES:9.1.2 合规性评价** | 是否每年至少评价一次、评价结论是否可信 |
| **QES:6.2 目标策划** | 合规目标是否达成 |

**关键发现**：同一个《合规性评价报告》，在 6.1.3 下看"清单有没有疏漏"，在 9.1.2 下看"评价频次够不够、结论有没有依据"。6.1.3 场景中审核员发现了废止标准仍在清单中的问题——这是典型的"条款视角"。

### 3.4 关键验证结论（供决策参考）

基于上述 22 条交叉引用记录的实证分析：

1. **交叉引用是普遍规律，不是例外**：87.5% 的文档被 2 条以上条款引用。路径 A 的"按需投影"几乎一定会触发——不存在"一份文档只对应一条条款"的简单场景。

2. **同一条款内部的分项"微投影"是最细粒度的挑战**：
   - 8.5.1 a) 和 8.5.1 g) 看同一份《工序流转卡》，但 a) 看"工艺规定是否成文"，g) 看"规定是否足够详细以防错"
   - 这种"微投影"在路径 A 中只能靠 Artifacts 提示词在提取时动态实现；路径 B 中则需要在 L2 层区分 `clause_id = "8.5.1_a"` 和 `clause_id = "8.5.1_g"`

3. **跨体系引用加剧了复杂度**：Q（质量）和 ES（环境+安全）都引用同一份《培训记录》，但 Q 关注"培训后能力是否胜任"，ES 关注"环境/安全意识培训是否到位"——字段有重叠但**评价标准不同**

4. **"详实程度"确实是路径 A 的关键通用属性**：无论多少条款引用同一份文档，"这份文档包含了哪些时间段的数据、是否完整详细、是否有签名确认"这类通用描述几乎所有条款都需要。这验证了路径 A 的通用属性层设计是有价值的——它是所有条款投影的共同基础。

5. **存在一类"公因子文档"天然就是多条款共享的**：《设备台账》《培训记录》《法律法规清单》《受控文件清单》——这类文档在真实审核中几乎是"万能证据"，路径 B 直接建模会产生大量重复记录，路径 A 则天然匹配"提取一次、按需投影"的特性。

## 四、两条路详细对比

### 3.1 路径 A：条款无关（通用提取 + 按需投影）

#### 架构

```
企业文档 → 切块(Chunk) → 文档属性卡（8维，条款无关）→ 按条款的 Artifacts 投影
                                        ↓                              ↓
                                  cert_enterprise_doc_attr      cert_clause_doc_extract
```

#### 真实案例中的工作方式（以《校准证书管理与预警台账》为例）

**文档属性卡**（条款无关，只填一次）：

```json
{
  "docCode": "DOC-CAL-0037",
  "contentSummary": "记录全厂19台监视和测量设备的校准记录。含：仪器名称、设备编号、校准证书编号、校准日期、有效期至、剩余天数、状态。设置临期预警（0-30天标黄、<0天标红）。有效期跨度：2025-12-24 ~ 2027-05-14。",
  "detailLevel": {
    "timeSpan": "2025-12 ~ 2027-05",
    "recordCount": 19,
    "dataFields": ["仪器名称","设备编号","校准证书编号","校准日期","有效期至","剩余天数","状态"],
    "completeness": 1.0,
    "note": "19/19台均有校准证书"
  },
  "artifactType": "校准记录",
  "process": ["计量", "质检"],
  "evidenceFor": ["7.1.5.2", "8.5.1b"],
  "criticality": "高"
}
```

**投影**（按 Artifacts 提示词）：

```
→ 投影到 8.5.1b（关注校准台账完整性）：
   提取: {设备总数:19, 有效数:19, 临期数:2, 过期数:0}
   输出: "19台均在有效期内，2台临期（30天内），预警机制运行有效"

→ 投影到 7.1.5.2（关注校准溯源性）：
   提取: {校准证书编号:19个, 校准机构:["XX计量测试技术研究院", ...]}
   输出: "19份证书编号均可对应至校准报告，校准机构均为法定机构"
```

#### 优势

| # | 优势 | 实证依据 |
|---|---|---|
| A1 | **文档只提一次，所有条款共享算力** | 案例 1 中《工序流转卡》提一次，a/c/g 三个视角都直接用——路径 B 则需对三个条款各跑一次提取 |
| A2 | **同一套文档属性卡可用于未来的条款（今天没预见到的）** | 案例 4 中如果未来新增一个条款也要读《合规性评价报告》，投影提示词加一行就行，文档属性卡不需要改 |
| A3 | **文档更新时只需重提一次** | 企业下次监督审核更新了《校准证书管理与预警台账》，路径 A 重提属性卡 + 自动重投影；路径 B 要逐个检查受影响的条款对 |
| A4 |**详实程度（数据量/时间跨度/完整度）是文档天然属性，与条款无关** | 你之前提出的"详实程度"维度（包含多少台设备、时间跨度多少月）本质上是文档自身属性——你无法说"这份文档对 8.5.1b 的详实程度是 19 台/18 个月，对 7.1.5.2 是 19 台/24 个月"——详实程度只有一个真值 |

#### 劣势

| # | 劣势 | 实证依据 |
|---|---|---|
| A1 | **每次条款执行都要跑一次投影提示词** | 案例 1 中《工序流转卡》需要跑三次投影（对应 a/c/g），虽然共用切块但提示词要执行三次 |
| A2 | **文档属性卡是"中道"描述，可能丢失条款需要的细微差别** | 案例 1 中 g) 视角需要判断"工序流转卡的工艺规定是否足够详细以防人为错误"——这种"防错充分性"的评估无法在条款无关的属性卡中描述，只能靠投影提示词在提取时判断 |
| A3 | **投影的置信度需要单独管理** | 如果文档属性卡的 confidence=0.95，但某个条款的投影 confidence=0.70，需要分开存 |

### 3.2 路径 B：条款相关（直接按条款建模）

#### 架构

```
企业文档 → 切块(Chunk) → 条款×文档 直接对提取 → 写入时即以条款为维度切分
                                        ↓
                              cert_clause_doc_extract（只存此表）
```

#### 真实案例中的工作方式（以《校准证书管理与预警台账》为例）

```json
{
  "docCode": "DOC-CAL-0037",
  "clauseCode": "8.5.1b",
  "extractedAt": "2026-10-28T10:00:00Z",
  "docDescription": "记录全厂19台监视和测量设备的校准记录。有效期至2027-05-14。校准机构：XX计量测试技术研究院。",
  "completeness": "19/19有效，预警机制度运行正常",
  "confidence": 0.95,
  "evidenceChain": "1.查台账登记设备总数（19台）2.逐台核有效期（全部有效）3.查临期预警记录"
}
```

```json
{
  "docCode": "DOC-CAL-0037",
  "clauseCode": "7.1.5.2",
  "extractedAt": "2026-10-28T10:00:00Z",
  "docDescription": "全厂19台监视和测量设备均有校准证书。校准证书编号可对应至校准报告原件。校准机构：...（法定机构资质待核）",
  "completeness": "证书数量充分，机构资质原件需现场核对",
  "confidence": 0.88,
  "evidenceChain": "1.从台账随机抽5台 2.核对证书编号与报告原件 3.核校准机构资质范围"
}
```

#### 优势

| # | 优势 | 实证依据 |
|---|---|---|
| B1 | **每个条款的提取结果直接可用，无需再投影** | 案例 1 中三个条款视角的提取结果已经写入即——8.5.1b 审完直接取结果就行 |
| B2 | **每条记录携带该条款视角的置信度和证据链** | 每条记录的 confidence 只针对该条款的提取——不会出现"文档属性卡置信度 0.95 但投影到某个条款其实只有 0.70"的信息丢失 |
| B3 | **条款需要的细微差别直接在提取时被捕捉** | 案例 1 中 g) 视角的"防错充分性"在提取时就可以判断——这个判断在路径 A 中只能在投影阶段做 |
| B4 | **法律追溯最直接** | 当 CNCA 问"你为什么判 8.5.1b 符合"，路径 B 的答案直接指向 `cert_clause_doc_extract WHERE clauseCode='8.5.1b'`，该条记录自带完整的提取描述和证据链 |

#### 劣势

| # | 劣势 | 实证依据 |
|---|---|---|
| B1 | **文档被多个条款引用时，提取结果重复存储** | 案例 1 中《工序流转卡》的信息会被存三遍（a/c/g），但三遍的内容其实高度重叠（都是"规定了各工序工艺要求和检验点"） |
| B2 | **文档更新后，所有受影响条款对都需要重提** | 案例 2 中如果企业新版台账换了格式，(台账, 8.5.1b) 和 (台账, 7.1.5.2) 两个记录都需要重提 |
| B3 | **详实程度无法统一定义** | 你说要记录"文档包含 19 台设备、18 个月数据"——这个数据在路径 B 要写在每个条款对里。如果写重了就是数据冗余+对账负担；如果不写，条款对里只有"充分/不充分"的结论，信息量不够 |
| B4 | **"文档到底说了什么"这个最基础的事实被分散了** | 在路径 B 中，"这份文件是校准台账、包含 19 台设备、覆盖 2025-2027"这套基础事实散落在各个 `cert_clause_doc_extract` 记录的 `docDescription` 段中——想集中看"这份文件到底是啥"需要遍历该文档的所有条款对 |

## 五、用真实案例验证两条路的差异

回到科斯亚 8.5.1 条款的案例——一份《工序流转卡》（`07工序流转卡.doc`）在同一个 8.5.1 条款下被 a)、c)、g) 三个分项引用。

### 路径 A 如何处理

```
文档属性卡（只提一次）：
  docCode: DOC-CARD-001
  contentSummary: "规定了各工序的工艺要求和检验判定方式（初/中/终检），涵盖皮缝钉/钛钉/吻合钉生产全流程"
  detailLevel.recordCount: "14道工序"
  detailLevel.completeness: "各工序均有检验判定设置"
  process: ["生产"]
  evidenceFor: ["8.5.1a", "8.5.1c", "8.5.1g"]

投影到 8.5.1a：
  提取字段：{各工序是否规定了工艺要求？→ 是，14道均有}
  输出："14道工序均有工艺要求，成文信息充分"

投影到 8.5.1c：
  提取字段：{哪些工序设置了检验点？→ 初检+中检+终检三段}
  输出："各工序设置三段检验（初/中/终），适当阶段监视有效"

投影到 8.5.1g：
  提取字段：{工艺规定是否足够详细以防错？→ 参数数值化，未留主观判断空间}
  输出："工艺参数已量化（温度XX℃/压力XX MPa），留有人为判断空间较小，防错有效"
```

**路径 A 的体验**：审同一份文件三次，但每次都读出不同的东西。基础事实（14道工序、初/中/终检）共享，差异只在"看什么"（投影视角）。

### 路径 B 如何处理

```
（直接提取，没有中间属性卡）

提取 1 - (DOC-CARD-001, 8.5.1a)：
  docDescription: "规定了14道工序的工艺要求和检验判定方式。各工序均有明确规定，成文信息充分可用。"
  completeness: "充分"
  confidence: 0.95

提取 2 - (DOC-CARD-001, 8.5.1c)：
  docDescription: "各工序设置初检/中检/终检三段检验点。涵盖整个工艺流程，监视活动有明确准则。"
  completeness: "充分"
  confidence: 0.93

提取 3 - (DOC-CARD-001, 8.5.1g)：
  docDescription: "工艺参数已量化（温度、压力、时间）。但个别工序（焊接电流）标注为'调至合适'——存在人为判断空间，可能构成防错不足。"
  completeness: "基本充分，焊接电流参数需细化"
  confidence: 0.70
```

**路径 B 的体验**：三个视角三次独立提取，第三次的发现（焊接电流标注不精确）只有在这个视角下才会被注意到——因为提取是以"防错充分性"为目标驱动的。路径 A 要想做到这一点，必须确保投影到 g) 的提示词能够注意到"调至合适"这类措辞。

### 关键差异在这一刻体现

| | 路径 A | 路径 B |
|---|---|---|
| **焊接电流"调至合适"的发现者** | 取决于投影提示词是否设计了"是否有主观措辞"的检查 | 取决于提取时的主动判断——可能发现投影提示词没预见到的问题 |
| **丢失风险** | 如果投影提示词没想到这个维度，信息丢失 | 无丢失风险（提取是完整的） |
| **信息冗余** | 无冗余（基础事实只存一份） | 三次提取的"docDescription"中高度重复了"14道工序"、"初/中/终检" |

## 六、补充视角：两条路结合的第三条路

根据以上分析，存在一种可能的结合方案：

### 路径 C：基础层（条款无关）+ 差异层（条款相关补录）

```
层 1: 文档属性卡（条款无关）
       - 内容概括、详实程度、过程、类型、关键等级
       - 这些是文档"客观属性"，不受条款视角影响
       
层 2: 通用属性 8 维（目前的 ClauseIntent、Obligation、Artifacts...）
       - 这些属性在文档层面可做初步归纳
       - 如：这份文档涉及的过程、能支撑哪些条款
       
层 3: 条款投影补录层（按需触发）
       - 仅当条款投影发现"文档属性卡没有预见的差异"时写入
       - 例如：8.5.1g 发现"焊接电流标注'调至合适'"——这个信息不在文档属性卡中，只在防错视角下才有意义
       - 层 3 的存在理由是：条款视角下的独有发现需要有地方存放
```

**路径 C 的数据量估算**：

| 层 | 每文档平均行数 | 存储位置 |
|---|---|---|
| 层 1 + 层 2 | 1 行/文档 | `cert_enterprise_doc_attr` |
| 层 3 | 0.5 行/文档（平均一半条款有独有发现） | `cert_clause_doc_extract` |
| **路径 A 对比** | 1 行基础 + N 行投影 | `cert_enterprise_doc_attr` + `cert_clause_doc_extract`（所有条款投影） |
| **路径 B 对比** | N 行（无任何基础聚合） | `cert_clause_doc_extract`（所有条款直接提取） |

> 路径 C 的优势：平衡了"文档基础事实的唯一真值"和"条款视角的独有发现"。
> 路径 C 的劣势：三层架构更复杂，需要判断"什么信息该写属性卡 vs 什么信息该写投影补录"——即需要在提取时做层级归属判断（增加 LLM 提示词设计负担）。

## 八、与现有 8 属性模型的对齐关系

### 在路径 A 下

8 属性在文档侧的具体映射（已通过真实案例验证）：

| 属性 | 文档侧含义 | 案例中的提取结果（《工序流转卡》） |
|---|---|---|
| `ClauseIntent` | 在说什么事 | "规定了各工序的工艺要求和检验判定方式" |
| `Obligation` | 文档内的约束等级 | "工艺参数已量化——应级；焊接电流'调至合适'——宜级" |
| `Applicability` | 文档适用范围 | "适用于皮缝钉/钛钉/吻合钉全流程" |
| `ApplicabilityCondition` | 生效条件 | "自发布之日起施行" |
| `Process` | 涉及过程 | `[生产]` |
| `Artifacts` | 文档属于哪类材料 | `作业指导书`（ArtifactType 受控码） |
| `evidenceFor` | 能证哪些条款 | `["8.5.1a","8.5.1c","8.5.1g"]` |
| `criticality` | 关键等级 | "高——工序控制直接影响产品一致性" |

其中**只有** `evidenceFor` 是预判，其余 7 维都可以通过文档内容独立提取，无需知道条款要求。

### 在路径 B 下

8 属性仅在条款提取时填充，同一份文档在不同条款下的 8 个值**可能完全不同**。例如《工序流转卡》在 g) 视角下，Obligation 可能判为"部分宜级"（因为"调至合适"措辞），而在 a) 视角下判为"完全应级"（因为工艺要求已量化）。

> **这引发了路径 B 的一个根本性问题：Obligation 到底是文档自身的属性，还是条款对文档的判定？** 如果是前者，应该唯一；如果是后者，应该是视角相关。这个分歧本身就是路径选择的分水岭之一。

## 九、待审核的关键问题清单

以下问题需要在审核路径选择时逐项回答：

### 关于基础建模

| # | 问题 | 路径 A 的立场 | 路径 B 的立场 |
|:-:|---|---|---|
