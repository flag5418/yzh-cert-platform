一、两个分支的本质差异

认证准备认证检查
① 起点企业资料（企业上传，已齐）企业资料 + 审核员现场证据
② 先做系统分析（LLM 读企业资料）审核员先挂证据（拍照 / 访谈 / 抽样）
③ 再做审核员补充证据（要补件 / 电话确认）系统分析（企业资料 + 审核员证据）
④ 判定PrepState —— 资料够不够
found / partial / missing / unknown / na		Conclusion —— 符不符合
符合 / 观察项 / 一般不符合 / 严重不符合
⑤ 产出入场计划（查哪些条款、怎么查、查谁）认证报告
⑥ NC不签发（准备阶段不判 NC）逐条签发（一条 NC 对应一个检查项）

所以详情页顶部各有一条步骤条，顺序相反：

  • 准备：① 分析企业资料 → ② 补充证据 → ③ 判定是否入场 → ④ 生成入场计划
  • 检查：① 挂接证据 → ② 分析 → ③ 签发 NC → ④ 生成报告

检查侧有个硬约束：证据为 0 的检查项不允许分析，状态显示「待挂证据」，「自动分析」按钮对该行不可用。

二、你这 6 条反馈的落点

#你的意见怎么落的
1计划可调整、可独立查看，按钮多用下拉 计划列表操作列只留「查看计划」+「更多 ▾」；下拉里是编辑计划 / 开启准备 / 开启检查 / 停用。认证准备、认证检查两列的状态标签可点击，直接进对应详情，不再占按钮位
2可点击状态查看 列表里所有状态标签都可点，弹出「状态详情」抽屉：队列概览 / 执行轮次历史 / 每项状态与耗时 / 失败原因
3锁定放表格内部 两个详情表都多一列「锁定」，行内直接「锁定 / 已锁·解」。抽屉里也保留一个，双入口。队列运行时按钮置灰
4准备不签发 NC，检查逐条签发 准备详情没有 NC 列、没有签发按钮；检查详情多一列「NC」，结论为不符合时显示「签发」，点开单条签发弹窗（事实 / 条款 / 严重度 / 整改要求 / 期限），签发后显示 NC 编号
5数据流顺序相反、产出不同 见上表 + 步骤条；准备工具栏「自动分析 → 补充证据 → 生成入场计划」，检查工具栏「挂接证据 → 自动分析 → 签发 NC → 生成报告」
6可反复重新执行 列表操作下拉和详情工具栏都有「重新执行」；同一记录开新一轮（RunNo+1），列表不新增行，历史轮次在状态抽屉里看

四、检查项状态机（两边不同）

认证准备认证检查
待分析 → 分析中 → 已分析 → 待补充（资料缺失，等审核员补）→ 已复核 待挂证据（证据 0 份，不可分析）→ 待分析 → 分析中 → 已分析 → 已签发 NC

五、还需要你定 3 件事

这三条不定，落地时会有歧义
  1. 重新执行时，已签发的 NC 怎么处理？
    我的建议：NC 是正式产出，保留；如果重跑后该条结论不再是「不符合」，把 NC 标记为「建议撤回」让人确认，不自动删。因为 NC 可能已经发给企业了。
  2. 「必须挂证据才能分析」是硬卡还是软提示？
    我的建议：硬卡。证据 0 份时该行不可分析，但允许审核员手填一句「现场未见相关记录」作为证据，避免卡死。
  3. 入场计划里的「是否入场」由谁定？
    我的建议：系统先给建议（PrepState=found 且无疑点 → 建议免现场），审核员逐条确认，确认完才能生成入场计划。
