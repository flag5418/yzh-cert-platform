## 一、系统全景（V2）

### 1.1 一句话

> **把国标条款变成结构化属性，把企业资料变成条款级证据，替审核员完成「找、比、排、起草」，判定与签字留给人。**

### 1.2 V2 的链条（一条线，不是一堆功能）

```
标准侧（后台 admin 9990，无机构）
  M1 标准与条款 ──→ M2 条款属性（属性池 + 条款配置）
                        │
                        ├──→ M3 提示词模板（clause_attr_gen / doc_clause_extract）
                        └──→ M4 文档提取规则（标准侧"查什么"）

专家端（auditor 9991，一企业）
  M8 企业组织（部门/成员/专家组）
        │
        ├──→ M6 认证计划（一企业一有效计划 · 标准来源唯一入口）
        │         │
        │         └──→ M5 企业资料（上传 → 转换 → Markdown）
        │                   │
        │                   └──→ M7 文档提取 L1（一份文档 × 一标准 → 条款切片）
        │                             │
        │                             └──→ M9?【L2 认证准备 · 待建】缺口 + 疑点
        └──→ S1 AI 执行基建（模型/队列/用量）   S2 平台与权限
```

### 1.3 模块总数（V2 定稿口径）

| 类别 | 数量 | 编号 |
|---|:--:|---|
| **业务模块** | **8** | M1–M8 |
| **支撑模块** | **2** | S1–S2 |
| **合计** | **10** | —— |

> 一个模块 = **一组生命周期的表 + 一个"换企业还能不能复用"的判断边界**。
> ⚠️ 与旧版差异：V1 的「任务中心 / 报告审批 / 文档规范化 / 原始资料 / 工作流引擎」**不在 V2 模块表内**（见 §八）。

## 二、术语表（V2 唯一叫法 · AI 必须用这套词）

> ★ 这一节是高频交流的真正基础。名字不统一，每个 AI 都会重新发明一个概念。

### 2.1 条款与属性（M1 / M2）

| 术语 | 一句话定义 | 落点 | ⛔ 误用 |
|---|---|---|---|
| **条款** Clause | 国标里的一个编号条目，**系统唯一原子** | `cert_iso_clause`（`Code` GUID + `Number` 如 4.2.4） | 不要与"检查项"混 |
| **标准** Standard | 一套国标 | `cert_iso_standard`（`StandardCode` 短码如 `iso13485` + `Abbrev` 如 `m`） | ⚠️ `cert_iso_clause.StandardCode` 存的是 **GUID**，与前者不同口径 |
| **★ 属性池** AttrPool | **"条款可以有哪些维度"的字典**（全局一套，9 条） | **`cert_clause_attr_def`** | ⛔ 不是"某条款的属性值" |
| **★ 条款配置** ClauseConfig | **给某条款"挂"某个属性的值** —— 一行 = (条款, 属性, 值) | **`cert_clause_attr`**（EAV） | ⛔ 不叫"属性绑定/实例" |
| **属性值** AttrValue | 条款配置里的值（可为 markdown / JSON / 整段提示词） | `cert_clause_attr.AttrValue` | ⛔ 不要假定是 JSON |
| **V2 属性池 9 条** | `Applicability` 适用性 / `ApplicabilityCondition` 适用条件 / `Artifacts` 要哪些材料 / `ClauseIntent` 条款意图 / **`DocCheckMode`** / `EvidenceChain` 证据形态 / `Obligation` 强度(shall) / `Process` 相关过程 / `Severity` 严重程度 | `cert_clause_attr_def` | ⛔ 不要写成 12 条（旧文档口径） |
| **★ `DocCheckMode`** | **决定"要不要查资料"**：`required` / `optional` / `none` | 属性池字典 `clause_doc_check_mode` | ⛔ 不是布尔；`none` 少不代表缺陷 |
| **AI 预生成** | 按条款正文批量生成属性值（分批 20 条款/次） | `ClauseAttrGenerateService` + `ClauseAttrPromptService` | ⛔ 不要绕开 `cert_prompt_template` 直接读旧表 |

> **一句话记住**：**属性池 = 题库（有哪些维度）**；**条款配置 = 答卷（这条条款每题答了什么）**。

### 2.2 提示词（M3）

| 术语 | 一句话定义 | 落点 | ⛔ 误用 |
|---|---|---|---|
| **★ 提示词模板** PromptTemplate | V2 条款主链的**唯一提示词来源** | **`cert_prompt_template`**（`PromptCode` + `OrgCode` + `ScopeKey` + `Status` + 版本） | ⛔ 不要用 `wf_prompt_template` |
| **`PromptCode`** | 程序入口键：`clause_attr_gen` / `doc_clause_extract` / （V1 遗留）`doc_extract` | 同上 | ⚠️ **`doc_extract` ≠ `doc_clause_extract`**（前者是 V1 四元组定位规则） |
| **`ScopeKey`** | 细分作用域：空 = 平台级；标准短码 = 按标准；`ent:{企业Code}` = 按企业 | 同上 | ⛔ 不要另造作用域字段 |
| **解析顺序** | 标准级 → 平台级 → 代码兜底常量；**用了兜底必须写进 `Message`** | `DocExtractPromptService.ResolveAsync` | ⛔ 不许静默回退 |
| **`{{attr_pool}}`** | 属性清单由属性池**实时渲染**，不写死在正文里 | 提示词正文占位符 | 新增属性后若不渲染 ⇒ 模型不产该字段且静默缺失 |

### 2.3 企业资料与提取（M5 / M7）

| 术语 | 一句话定义 | 落点 | ⛔ 误用 |
|---|---|---|---|
| **企业资料** EnterpriseDoc | 企业实际上传的文件（**唯一一层：无阶段、无标准、无槽位**） | `cert_enterprise_doc` / `_version` / `_upload_task` | ⛔ 不要加回 `StageCode` |
| **标准来源唯一入口** | 上传/提取用哪些标准 = **当前有效认证计划的标准** | `GET EnterpriseDoc/plan-standards` | ⛔ 不要从机构反推（V1 做法） |
| **一企业一有效计划** | 建新计划即作废旧计划（**只作废不删行**，留痕在 `Remark`） | `AuditPlanController.InvalidateOtherPlansAsync` | ⛔ 不用唯一索引（MySQL 无部分唯一索引） |
| **L1 提取** Extraction | **一份文档 × 一个标准 → 一份 JSON**（条款切片 + 锚点 + 置信度） | **`cert_document_extraction`** | ⛔ 不要做成"文档 = 一份 JSON 含所有标准" |
| **切片** Slice | 某条款在本文档中的一条原文摘录（`text` + `anchor` + `why`） | `ContentJson.clauses[]` | ⛔ 切片里不产结论（只产"读到什么"） |
| **锚点** Anchor | 原文摘录，用于回到原文定位；比对需 **标点归一 + 三级递进**（exact → punctuation → reflow） | `anchor` 字段 / 前端 `locateAnchor` | ⛔ 不要直接 `IndexOf`（模型会输出中文引号） |
| **`SourceSha256` + `IsStale`** | 文档 hash 变 ⇒ 旧产物置 `IsStale=1` 待重跑；hash 不变 ⇒ 不重跑 | `cert_document_extraction` | ⛔ `IsStale` 优先级高于 `ExtractStatus`（否则旧结果显示成"已提取"） |
| **两段式提取** | **宽扫**（一文档 × 全条款清单 = 1 次调用）→ 深提取（只跑命中条款） | 当前 V2 = 宽扫 | ⛔ 禁止"每文档 × 每条款各调一次"（6.4 万次） |
| **L2 认证准备** Readiness | 按条款聚合切片 → 四态缺口 + 疑点（**待建**） | 35 号 §五 | ⛔ `unknown` 不许写成 `missing` |

### 2.4 计划与后续（M6 / 待建）

| 术语 | 一句话定义 | 落点 | ⛔ 误用 |
|---|---|---|---|
| **检查项 / 检查单元** CheckUnit | **条款组 × 部门组**（一次访谈能问完）；**计划项即检查单元** | `cert_audit_plan_detail`（`Clauses` / `Departments` 逗号多值） | ⛔ 不新增 `CheckUnit` 表 |
| **认证计划** AuditPlan | "**该查什么**"：企业 × 阶段 × 标准(多) → 检查单元 | `cert_audit_plan` / `_detail` | ⛔ 不是另一份清单的容器 |
| **入场计划** OnsitePlan | "**哪天谁去哪个单元查什么**"（V2 后置） | 未建 | ⛔ 不是第二套条款清单 |
| **证据** Evidence | 支撑某条款的一条事实（企业文档 / 访谈 / 观察 / 照片 / 录音） | 未建（拟 `cert_evidence`） | ⛔ 不要与"提取切片"混：切片是候选证据，证据是确认过的 |
| **疑点 / NC** | 疑点 = **未判定**的疑似不符合；NC = 人**判定后**的结论 | 未建（拟 `cert_finding` 单表双态） | ⛔ 系统永不自动开 NC |
| **适用性** Applicability | 条款对企业是否适用（属性 `Applicability` + 条件） | 属性层（表待建） | ⛔ 「不适用」不是软删除 |
| **双端** | **文件可判** / **必须现场判**（判断依据类型） | 属性层 | ⛔ 不是"远程/现场"（那是场所） |

## 四、各模块详解（只做 / 不做 / 落点）

### M1 标准与条款（admin）

| 项 | 内容 |
|---|---|
| **只做** | 标准登记（`StandardCode` 短码 + `Abbrev` 前缀）、条款树与正文、条款序号 |
| **不做** | 不管企业；不管属性值（M2）；不管提取（M4/M7） |
| **表** | `cert_iso_standard` / `cert_iso_clause` |
| **页面** | `/cert/standard-manage`、`/cert/iso-standard` |
| **后端** | `Admin/Controllers/Foundation/{ISOStandardController, ISOStandardTreeTableController, ISOClauseController}` |
| **V2 改动** | `cert_iso_standard.Abbrev`（iso9001→e / iso13485→m），用于条款序号前缀 `e 4.3` |
| **⚠️ 口径警告** | `cert_iso_clause.StandardCode` = **GUID**；`cert_iso_standard.StandardCode` / `cert_clause_attr.StandardCode` = **短码** ⇒ 直接 JOIN 会 0 行且不报错 |

### M2 条款属性（admin · V2 核心）

| 项 | 内容 |
|---|---|
| **只做** | ① 属性池维护（9 条，含 `ValueType` / `DictCode` / `PromptHint`）② 条款配置（给条款挂值）③ AI 预生成（分批）④ 提示词抽屉 |
| **不做** | 不生成检查项；不判断企业；不存提示词正文（M3） |
| **表** | **`cert_clause_attr_def`（属性池，9 条）** / **`cert_clause_attr`（条款配置）** |
| **页面** | `/cert/clause-attr-def`（条款属性池）、`/cert/clause-attr`（条款属性配置）、`/cert/clause-prompt` |
| **后端** | `Admin/Controllers/Cert/{ClauseAttrDefController, ClauseAttrController, PromptTemplateController}` + `Services/Cert/{ClauseAttrGenerateService, ClauseAttrPromptService}` |
| **实测** | iso13485：70 叶 − 3 前置 = **67 条应配，实配 67（100%）**，67×9 = **603 格**；`cert_clause_attr` 全表 683 行 / 77 条款（含 iso9001、iso14001 各 5×8） |
| **已知偏差** | `DocCheckMode` 实测 `required×50 / optional×17 / none×0`（`none=0` 是 ISO 13485 的客观事实，非缺陷）；iso9001/14001 的 `DocCheckMode` **未配齐** ⇒ 提取退化为"全部叶子条款" |
| **两条硬约束** | ① 属性清单只由 `{{attr_pool}}` 渲染（⛔ 不写死 JSON 骨架）② 提示词唯一来源 = `cert_prompt_template.clause_attr_gen` |

### M3 提示词模板（admin · V2 唯一来源）

| 项 | 内容 |
|---|---|
| **只做** | 按 `PromptCode + OrgCode + ScopeKey` 管理提示词正文、状态、版本 |
| **不做** | 不含业务判断；不做 Dify 工作流（那是 V1） |
| **表** | **`cert_prompt_template`**（`PromptCode` / `PromptName` / `OrgCode` / `ScopeKey` / `Template` / `Status` / `IsValid`） |
| **页面** | `/business/prompt-template`（文档语义规则） |
| **后端** | `Admin/Controllers/Cert/PromptTemplateController` + `Services/Cert/PromptTemplateService` |
| **在用 `PromptCode`** | `clause_attr_gen`（属性生成）、`doc_clause_extract`（L1 提取）；`doc_extract` 为 V1 遗留（四元组定位），⛔ 不要用在 L1 |
| **交付契约** | 只读投影 `Shared/Entities/Cert/CertPromptTemplateRow.cs` 给专家端用（Auditor ⛔ 引 Admin） |

### M4 文档提取规则（admin）

| 项 | 内容 |
|---|---|
| **只做** | 标准侧"提取什么字段 / 哪些表 / 定位规则"（V1 规则体系 + 前端适配） |
| **不做** | 不跑提取（M7）；不存企业结果 |

### M5 企业资料（auditor · V2 重写核心）

| 项 | 内容 |

## 六、依赖与调用规则

```
M1 标准与条款
  ├→ M2 条款属性 ──┐
  ├→ M3 提示词模板 ─┼→ M7 文档提取 L1
  └→ M4 提取规则 ──┘         ↑
                             │
M8 企业组织 ─→ M6 认证计划 ─→ M5 企业资料
                  ↑              │
                  └── 标准来源 ───┘（plan-standards）
```

| 规则 | 内容 |
|---|---|
| **D1 单向** | 依赖只能向下（专家端 → 标准侧）。⛔ 标准侧不许知道任何企业 |
| **D2 端不互引** | `Auditor` ⛔ 引 `Admin`；共享只能经 `CertPlatform.Shared`（只读投影，如 `ClauseAttrRow` / `CertPromptTemplateRow`） |
| **D3 唯一入口** | 机构/标准/阶段的取数只走 `CoreResourceQuery`；**同一个 WHERE 出现在第二处 = 违规** |
| **D4 不跨模块写表** | 写只写自己的表；读别人走服务或只读投影 |
| **D5 标准来源唯一** | 上传/提取用哪些标准 = `cert_audit_plan`（`plan-standards`），⛔ 不从机构反推 |
| **D6 提示词唯一** | 所有提示词走 `cert_prompt_template`，⛔ 不读 `wf_prompt_template` |
