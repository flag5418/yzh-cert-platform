> **V1.2 校正（用户指正 2 条，定系统定位）**：
> 1. **这是辅助系统，不是流程管控**：不设任何阻断，不要求"必须按 10 步走"，不要求"必须先准备才能入场"。审核员可以零准备直接到现场，也可以只用其中一段；系统在每一步都能单独提供价值。

> 1. **认证准备被写浅了**：它的真实内容是"事先不了解企业 → 读文档建画像 → 判条款适用性 → 分远程/现场 → 在阶段锁死的时间里把证据密度做到最大"。V1 把它压缩成了五个步骤，已重写（§二、§七、§八）。

> 4. **机构默认检查项后置**：当前核心是"分析准确、专家能信任"，不是模板管理（§8.5、§十四）。

>
> **这一版相对上一版的关键变化（3 条，都是用户明确补充的）**：
> 1. **条款必须是双端**：企业端（企业该有什么）+ 执行端（审核员怎么验）。只有一端 = 条款未就绪。
> 2. **文档 = 通用字段 + 条款级关键信息**：通用字段用来快速找回原始企业文档，条款级关键信息用来组装证据链。
> 3. **补上"认证计划"这一环**：条款规则配置 → 体系 × 阶段 → 合并/拆分 → 部门 → 分工 → 日程 → 机构模板。没有这一环，模型再准也落不到一次真实审核上。

## 零、这套系统与普通 AI 工具的区别

普通 AI 工具：给一段文字，问一个问题，答一次。换个企业、换个人、换个时间，答案就变。

本系统做的是四件普通工具做不到的事：

| 能力 | 具体表现 |
|---|---|
| **标准被拆开了** | 273 条条款逐条建模，每条都有"企业要有什么"和"审核员怎么验"两侧要求 |
| **判断有尺子** | 适用不适用、强制不强制、查到什么程度算过，都由规则配置决定，不由模型当场发挥 |
| **结论能追溯** | 每条结论必须挂在证据链上：条款 → 关键信息 → 文档锚点 / 现场事实 |
| **过程能复制** | 认证计划可存成机构模板，同一机构下次直接复用；换了企业只换数据，不换方法 |

一句话：**普通 AI 是在答题，这套系统是在建考场、出考卷、定评分标准、留证据、复核结论。**

## 一、三类主体、四层资产

### 1.1 三类主体

| 主体 | 在系统里是什么 | 关键属性 |
|---|---|---|
| **标准** | 国标及其条款（4 个标准 273 条），全局唯一，无机构无企业 | 条款号、正文、层级、所属章 |
| **企业** | 被审核方 | 部门、负责人、选择了哪些体系与阶段 |
| **机构** | 认证机构及其审核组 | 组长、组员、技术专家、证据组织习惯 |

### 1.2 四层资产

```
第一层  条款模型      标准要求什么（双端）
第二层  文档模型      这个标准该有哪些文档、文档里写着什么（通用字段 + 条款级关键信息）
第三层  规则配置      这条款适用谁、查到什么程度、什么情况开 NC
第四层  提示词资产    把上面三层组织成可执行的判断
```

前三层是**数据**，第四层是**方法**。四层合起来才是"专业系统"，缺任何一层都会退化成普通 AI。

### 1.3 系统定位：辅助，不管控（六条原则）

| # | 原则 | 具体含义 |
|:--:|---|---|
| 1 | **不设阻断** | 任何一步没做，都能继续做下一步；不出现"未完成 X 不能做 Y" |
| 2 | **不强制流程** | 从任意一步进入都能用；零准备直接到现场也能用（给条款要点 + 建议问题） |
| 3 | **不替人决定** | 系统给分析、给证据、给理由；结论由审核员定，改判不需要理由审批 |
| 4 | **完成 ≠ 合格** | 任务完成 = 时间内完成取证与判断；NC 是正常结论，不是系统失败 |
| 5 | **允许未覆盖** | 没查的条款显式标"未覆盖"，不默认符合、不假装查过 |
| 6 | **允许个性化** | 每个审核员风格不同，系统只提供素材与提示，不规定"应该怎么干" |

> 这六条是产品定位，不是客气话。凡是"必须 / 禁止 / 不给下发"的设计，都要先问一句：这是在帮审核员，还是在管审核员？

## 二、认证准备到底在做什么（先看这一节）

### 2.1 审核员的真实处境：四条硬约束

| 约束 | 含义 | 对系统的要求 |
|---|---|---|
| **事先不了解企业** | 不知道文档长什么样、组织怎么设、职能怎么分 | 能边读边建模：文档 → 组织 → 职责 → 过程 |
| **可能零准备入场** | 有的审核员到现场才开始看材料 | 现场也能用：条款要点、建议问什么、随手取证 |
| **企业性质决定条款适用** | 制造 / 贸易 / 服务 / 设计 / 施工，业务不同，适用条款不同 | 能做适用性建议，不能拿 273 条平均用力 |
| **现场时间紧且有上限** | 阶段天数、审核员全年可下场天数都是硬的 | 计划给"时间预算内证据密度最大"的建议 |
| **审核员对结果负责** | 漏查是风险，错判要担责 | 结论能追溯到证据；不确定显式标出 |

认证准备的本质就一句话：

> **在有限时间里，把"能远程拿到的"和"必须到现场看的"分开，然后把现场时间全部用在后者上。**

这就是"双端"的真正用途：企业端要求 → 远程可完成；执行端要求 → 必须现场。**它是分拣器，不是门槛。**

### 2.2 主线（10 步）

| # | 步骤 | 产出 | 在哪做 |
|:--:|---|---|---|
| 1 | 标准与条款建模 | 273 条 × 12 属性（双端） | 规则侧，一次性 |
| 2 | 文档建模 | 该标准该有哪些文档、该含什么 | 规则侧，一次性 |
| 3 | **企业研究** | 企业画像：性质 / 产品 / 工艺 / 组织 / 职能 / 范围 / 删减 | 远程 |
| 4 | **条款适用性裁剪** | 适用 / 不适用（有依据）/ 待确认 | 远程 |
| 5 | **资料索取** | 按企业端要求汇总的索取清单（分部门、标必交） | 沟通 |
| 6 | **文档研读与差异分析** | 缺口、矛盾、疑点 | 远程 |
| 7 | **认证计划** | 任务分拣 + 时间预算 + 分工 + 日程 | 远程 |
| 8 | **现场检查** | 观察 / 访谈 / 抽样证据 | 现场 |
| 9 | 判定与 NC | 预NC → 正式 NC | 现场后 |
| 10 | 报告与回归 | 按标准拆分的报告 + 可复现 | 收尾 |

### 2.3 这是理想路径，不是强制流程

顺序做全，效率最高；但**跳步不会被拦**，只影响效率：

| 跳过的步骤 | 代价 | 系统还能做什么 |
|---|---|---|
| 3 企业研究 | 适用性只能靠经验猜 | 按行业模板给一版初判，现场再改 |
| 4 适用性裁剪 | 可能把不适用的条款排进计划，现场白耗时间 | 现场标"不适用"并记理由 |
| 5、6 索取与研读 | 现场变成第一次读文件，时间通常不够 | 现场边看边提取，重点条款优先 |
| 7 认证计划 | 按条款号顺序走，时间到了还没取到关键证据 | 现场按"必查项 + 高风险"给实时提示 |

> 普通 AI 工具做不了第 3、4、7 步，因为它不知道"这家企业是什么、哪些条款该查、时间花在哪最值"。我们做的是**把这三种判断变成可用的建议**，不是把审核员绑在流程上。

## 三、条款模型：双端（本次最重要的改动）

### 3.1 为什么必须双端

一条条款在认证审核里同时问两个问题：

| 端 | 问题 | 谁能回答 | 载体 |
|---|---|---|---|
| **企业端** | 这条要求，企业该拿出什么？ | 企业 | 规则文档 + 内审记录 |
| **执行端** | 企业拿出来的东西是真的吗？按它执行了吗？ | 审核员 | 现场观察 + 访谈 + 抽样核对 + 记录比对 |

企业只能交"文档"，交不出"体系真的在运行"。所以：

> **企业端的材料永远只能证明"写了"，执行端的取证才能证明"做了"。**
> 一条条款如果只有企业端要求，审核员到了现场不知道该看什么；只有执行端要求，企业不知道该准备什么。两端缺一，条款就是废的。

### 3.2 企业端：只有两类载体

| 载体 | 例 | 回答什么 |
|---|---|---|
| **规则文档** | 质量手册、程序文件、制度、作业指导书、检验规程、工艺卡、计划 | 规定了什么 |
| **内审记录** | 内审方案、检查表、不符合报告、纠正措施、管理评审记录 | 自己查出过什么、改没改 |

> 校准证书、培训记录、检验记录这类执行留痕，按"内审记录"同性质处理（都是企业自述的执行证据），**不能替代现场取证**。

企业端只回答三件事：**有没有、全不全、是不是现行有效版本**。它不回答"做没做"。

### 3.3 执行端：只回答"真不真、做没做、有没有效"

| 检查深度 | 问什么 | 典型手段 |
|---|---|---|
| **存在** | 文件在不在、审批没审批、版本对不对 | 查文件、查受控清单 |
| **执行** | 实际做法与文件规定是否一致 | 抽记录、看现场、问操作人 |
| **有效** | 做了，但有没有达到目的（闭环了吗） | 看纠正措施是否验证有效、内审发现是否复发 |

> **检查深度是条款级的，不是审核员临场决定的。** 同一条"应保留记录"，在 7.5.7 灭菌确认要查到"有效"，在 4.2.4 文件控制查到"存在"即可。这个差异写进条款配置，不同审核员才不会给出不同结论。
>
> 当前建议**先用两档**（存在 / 执行），有效性并入 NC 分析；等专家觉得必要再拆第三档（见 §4.2）。

### 3.4 通用属性 12 条（含端归属）

| # | 属性 | 端 | 值类型 | 来源 | 决定什么 |
|:--:|---|:--:|---|---|---|
| 1 | `ClauseIntent` 条款作用 | 共有 | text | 固定 | 语义锚点、NC 理由出处 |
| 2 | `Obligation` 执行标准 | 共有 | dict | 固定 | 强制 / 应 / 宜 / 可 —— **开 NC 的闸门** |
| 3 | `Applicability` 适用范围 | 共有 | dict | 固定 | 通用 / 有条件 / 不适用 |
| 4 | `ApplicabilityCondition` 适用条件 | 共有 | text | 固定 | 条件原文，求值由程序读企业事实 |
| 5 | `Process` 适用过程 | 共有 | json | 固定 | 对应哪些部门（部门矩阵的唯一来源） |
| 6 | `Severity` 影响程度 | 共有 | dict | 固定 | 一般 / 严重 / 观察 |
| 7 | `RequirementItems` 分项要求 | 企业端 | json | 固定 | 条款内部判定清单（a/b/c…），不拆检查项 |
| 8 | `Artifacts` 企业须提供材料 | 企业端 | json | **参考** | 要哪些规则文档 / 内审记录 + 应含要素 |
| 9 | `EvidenceKinds` 要求形态 | 执行端 | dict | 固定 | 去哪个池子找证据：文件 / 记录 / 现场 / 人 |
| 10 | `CheckModes` 检查方式 | 执行端 | dict | 固定 | 查哪些维度：有无 / 完整 / 正确 / 时限 / 一致 / 可追溯 |
| 11 | `VerificationLevel` 检查深度 | 执行端 | dict | 固定 | 存在 / 执行（可选第三档：有效） |
| 12 | `EvidenceChain` 取证剧本 | 执行端 | text | 固定 | 看什么、问谁、抽几份、记在哪 |

**为什么 12 条而不是 9 条**：原来 9 条里，"适用过程"和"证据链"被降为专属层，"检查深度"根本没有。但**部门矩阵靠 `Process` 才能算，查到哪一步靠 `VerificationLevel` 才能定**——这两件是全系统每天都在用的，不能按条款族选择性配置。

**为什么只有第 8 条是参考值**：前 11 条都是标准自己说死的；只有"要哪些材料"标准给的是期望，真值在企业手里。

### 3.5 双端是分拣器，不是门槛

| 端 | 证据在哪拿 | 对应动作 | 占不占现场时间 |
|---|---|---|---|
| **企业端** | 文件、记录、内审资料 | 沟通索取 + 远程评审 | 基本不占（除非核对原件） |
| **执行端** | 现场、人、实物 | 观察、访谈、抽样、比对 | 占 |

四条推论：

1. **企业端做得越扎实，现场越省时间**：文件先评完，现场只验"是不是真这么做"。
2. **执行端不能用文档替代**：文件写了不等于做了，这是认证审核的根本。
3. **只有企业端要求的条款** = 我们没建模出"怎么验"，不是"不用现场"。
4. **只有执行端要求的条款** = 我们没建模出"企业该交什么"，现场会空手去。

**不设"缺一端禁止进计划"这种硬门槛**：没有任何企业会因为我们的属性没配完而暂停认证。正确做法是：

- 完备度视图标红，提示"该条款分拣信息不全"；
- 计划里标"高风险条款"，由组长决定照排、加时间，还是先补配置；
- **不阻断计划，但必须让人看见**。

> 这条改正是业务现实决定的：门槛挡不住审核，只会让系统被绕过。把"缺什么"变成可见的提示，比变成禁止更有用。

**零准备也能用**：如果审核员直接带着标准进场，系统仍能按条款给出"这条要求什么、通常看什么、可以问谁"，并支持现场随手取证。企业端没配全，结果是建议变粗，不是系统不可用。

### 3.6 属性池仍然分层

| 层 | 内容 | 何时补 |
|---|---|---|
| 通用（12 条） | 上面这一张表 | 第一批一次到位 |
| 条款族专属 | 8.3 设计开发 → 设计阶段/验证方式/评审记录；8.4 采购 → 供方评价方式；7.1.5 → 校准周期/溯源等级 | 试填 9001 第 7、8 章时按需补 |
| 标准专属 | 13485 → 灭菌方式/洁净级别；45001 → 危险源类型/防护层级 | 跑 13485 / 45001 时补 |

池子目标是 30–50 条。**池子大不丢人，配置小才是本事**——每个条款只挑自己那几条。

## 四、从条款到判据：先问三个问题

```
① 这条款对这家企业适用吗？        → 企业级判定（适用性裁剪）
② 适用的话，查到哪一步算查完？    → 条款级深度
③ 查到什么程度算不符合？          → 判据矩阵
```

三个问题必须分开答。混在一起，就会出现"把不适用的条款判成不符合"或"只看了文件就判符合"。

### 4.1 适用性：不是所有条款都要满足

适用性由**企业事实**决定，不由标准决定。ISO 9001 几乎任何企业都能申请，但"能申请"不等于"所有条款都适用、都要做到"：纯贸易企业和研发制造企业，同一套标准里真正要查的条款差别很大。

> 下表按 13485 编号举例；9001 对应为 8.3 设计开发 / 8.5.1 生产和服务提供 / 7.1.5 监视测量资源。

| 条款 | 适用条件（企业事实） | 不适用时 |
|---|---|---|
| 7.3 设计开发（9001 为 8.3） | 企业承担设计职责 | 删减，须有理由（体系范围） |
| 7.5.3 安装活动 | 有安装活动 | 不适用 |
| 7.5.5 无菌医疗器械 | 产品为无菌器械 | 不适用 |
| 7.5.9.2 植入性器械 | 产品为植入性 | 不适用 |
| 7.6 监视测量设备（9001 为 7.1.5） | 存在需溯源的测量设备 | 不适用 |
| 8.2.3 向监管机构报告 | 法规要求报告 | 不适用 |

**企业类型 → 典型裁剪**（只是初判，最终由审核员定）：

| 企业类型 | 业务实质 | 常见不适用 / 弱化 |
|---|---|---|
| 纯销售 / 贸易 | 采购成品转售，无生产无设计 | 8.3 设计、8.5.1 生产过程控制、7.1.5.2 溯源（可能）、7.5.6 特殊过程 |
| 研发型 | 只做设计，生产外包 | 8.5.1 生产控制（改为对外包方的控制）、部分 7.5.x |
| 生产型（OEM） | 按客户图纸生产，无自有设计 | 8.3 设计（须有删减理由）、部分 8.2 顾客沟通 |
| 生产型（自有产品） | 设计 + 生产 | 基本全覆盖 |
| 服务型 | 服务交付，无实物产品 | 7.5.5 无菌、7.5.9.2 植入、部分 7.1.5 |
| 多场所 | 总部 + 分支 / 车间 | 不是"不适用"，是**抽样与行程**要覆盖 |

> 表格的作用是给一个起点，不是给结论。审核员看一眼就能改，改完系统按新范围重算。

**三种状态，缺一不可**：

| 状态 | 判据 | 处置 |
|---|---|---|
| **适用** | 企业事实满足条件 | 进检查范围 |
| **不适用** | 事实明确不满足，且有依据（范围说明 / 删减理由） | 进裁剪清单，注明依据 |
| **待确认** | 事实不明（没问、没材料） | 进"沟通"任务 |

> **"待确认"绝不能写成"不适用"**。企业一句"我们不做设计"，如果不核对设计职责、是否 ODM、是否外包设计，就会整章漏掉。这是漏查最主要的来源。
>
> 但"待确认"**不阻断任何操作**：它只是一个显眼的标记，计划照排、现场照去，审核员现场问一句就能定。系统标出来是为了让人看见，不是为了拦住人。

企业研究要拿到的事实清单：

| 事实 | 用来判什么 | 从哪拿 |
|---|---|---|
| 组织类型（制造/贸易/服务/设计/施工/软件） | 条款族适用性 | 营业执照、范围、访谈 |
| 产品与服务范围 | 7.5.5 / 7.5.9.2 / 8.2.3 | 注册证、许可、范围 |
| 工艺与特殊过程（灭菌/焊接/热处理/表面处理） | 7.5.6 / 7.5.7 | 工艺文件、现场 |
| 是否承担设计职责 | 7.3 | 组织职责、外包协议 |
| 外包过程 | 7.4 / 8.4 | 采购清单、外包协议 |
| 场所数量 | 抽样与行程 | 组织图、地址 |
| 测量设备 | 7.6 | 设备清单 |
| 法规许可 | 8.2.3 / 13485 专属 | 许可证、注册证 |
| 人数与班次 | 抽样量、人日 | 花名册 |
| 体系范围与删减 | 全部 | 手册 4.3 |
| 多体系 | 条款集合 | 合同 |

### 4.2 检查深度：查到哪一步算查完

用大白话讲，就是三档：

| 深度 | 问什么 | 例：7.1.5.2 测量溯源 |
|---|---|---|
| **存在** | 有没有 | 有没有台账、有没有校准证书 |
| **执行** | 是不是按它做 | 台账 12 台，证书是否 12 份、是否都在有效期 |
| **有效** | 做完有没有用 | 超期设备是否停用、是否评估了对已检产品的影响 |

三点说明：

1. **深度不是让专家逐条手填**。同族条款给默认值（8.5.2 纠正措施默认到"有效"，4.2.4 文件控制默认到"存在"），专家只改例外。
2. **深度与适用性无关**。适用性回答"查不查"，深度回答"查到哪"。两者混在一起，就会出现"不适用的条款也配了深度"这种无意义配置。
3. **可以先用两档**（存在 / 执行）。有效性判断并入 NC 分析（8.5.2、9.2、9.3 这类本来就要看闭环的条款），等专家觉得有必要再拆出第三档。

### 4.3 判据矩阵

| 执行标准 | 需要的深度 | 事实 | 结论 |
|---|---|---|---|
| 强制 | 存在 | 无文件、无审批 | 不符合（严重） |
| 强制 | 执行 | 有文件，无执行记录 | 不符合（一般） |
| 强制 | 有效 | 有执行，问题未闭环 | 不符合（一般） |
| 应 | 执行 | 执行方式与规定不一致 | 不符合（一般） |
| 宜 | 存在 | 未建立 | 观察项 |
| 可 | 任意 | 未采用 | 符合（不判） |
| 任意 | 任意 | 查不到（没上传/没读到） | **待定，不得判 NC** |

这张表落 `cert_validation_rule`。提示词只做语义比对，不判这张表。

### 4.4 系统性失效

同一条款在多个部门、多个样本重复出现同一问题，不是"多处轻微"，而是体系性失效，候选升级为严重不符合，由人确认。

判据写进规则：`同条款命中部门数 ≥ 2` 或 `同条款不合格样本占比 ≥ 阈值`。

## 五、文档模型：通用字段 + 条款级关键信息

### 5.1 两个层次，用途完全不同

| 层次 | 内容 | 用途 |
|---|---|---|
| **通用字段** | 文档编号、名称、类别、版本、受控状态、审批状态、生效日期、归属部门、候选服务条款 | **快速找回原始文档**、判断文档身份与有效性 |
| **条款级关键信息** | 某条款在这份文档里具体要什么（灭菌参数、校准周期、审批人、内审发现数…） | **组装证据链** |

> 同一份《质量手册》，对 4.2.2 要的是"体系范围与删减说明"，对 5.3 要的是"方针原文与沟通证据"。所以**条款级关键信息必须按条款分别存**，不能塞进一个通用对象里。

### 5.2 通用字段（所有文档必填）

| 字段 | 说明 |
|---|---|
| `docCode` / `docName` | 文件编号 / 名称（原文） |
| `docCategory` | 规则文档 / 内审记录 / 记录 / 手册 / 程序 / 作业指导书 |
| `version` / `isControlled` / `approvalStatus` | 版本、受控、审批 —— 4.2.4 判据的三件套 |
| `effectiveDate` | 生效日期（判过期） |
| `processDept` | 归属部门（**必须取自企业档案**，不许模型自造） |
| `servedClauses` | 候选服务条款（初筛，最终以条款级关键信息为准） |
| `sourceFileCode` / `anchor` | 原始文件与页码，供回溯 |

### 5.3 条款级关键信息

每份文档 × 每个命中条款，产出一条：

```
条款号 | 关键信息（键值对） | 原文锚点 | 证据强度 | 可信度
7.5.7  | 灭菌方式=环氧乙烷；再确认=每年 | 第5章 §5.6 | direct | 0.86
```

证据强度三档：

| 强度 | 含义 | 下游怎么用 |
|---|---|---|
| `direct` | 文档直接规定/记录了该要求 | 可直接组链 |
| `indirect` | 间接体现（如流程图里出现该活动） | 需现场补证 |
| `mention_only` | 只提到名词，无实质内容 | 视为"写了个标题"，必须现场验 |

### 5.4 证据链是这三层的交汇点

```
条款（要求什么）
  ← 条款级关键信息（文档里写了什么）
    ← 文档锚点（哪份文件、第几页、哪张表）
  ← 现场事实（观察/访谈/抽样，带时间地点人物）
    ← 审核记录锚点
```

**一条完整的证据链 = 要求 + 文档事实 + 现场事实 + 锚点。**
缺现场事实的，只能出预NC；缺锚点的，报告写不出来，不得出结论。

### 5.5 文档的三层归属（不许混）

| 层 | 内容 | 有无机构 |
|---|---|---|
| 标准要求 | 该标准下应有哪些文档、该含什么要素 | 无 |
| 机构资料清单 | 这家机构按标准 × 阶段列的具体文件清单（含模板） | 有 |
| 企业上传 | 这家企业实际交了什么 | 有企业 |

标准要求是抽象，机构清单是实例化，企业上传是执行。三层通过"文档类别 + 服务条款"对齐，不互抄。

## 六、组织与人

### 6.1 机构侧：审核组

| 角色 | 职责 | 在计划里的作用 |
|---|---|---|
| **组长** | 统筹、终判、报告签署 | 分配检查项、确认系统性失效、定级 |
| **组员（审核员）** | 按分配执行检查、录证据 | 领取检查项、录现场证据 |
| **技术专家** | 专业条款支持（不独立开 NC） | 被咨询、出专业意见 |

机构的"证据组织习惯"（证据包分册、记录写法、抽样口径）挂在机构上，一次覆盖该机构该标准全部条款，**不逐条配**。

### 6.2 企业侧：部门与负责人

| 字段 | 说明 |
|---|---|
| 部门编码 / 名称 | **唯一来源**，模型不得自造（"生产部/制造部/车间"会被当三个部门） |
| 上级部门 | 支持两级（车间归属生产部） |
| 负责人（角色 + 姓名） | 沟通对象写角色为主，姓名为辅 |
| 负责过程 | 与条款的 `Process` 取交集 → 部门矩阵 |

### 6.3 部门 × 条款矩阵

```
条款声明它管哪些过程（Process，受控词表）
        ×
部门声明自己负责哪些过程（企业档案，人工确认）
        ↓
每格：本部门要准备什么 / 会被问什么 / 需要谁在场
```

这张矩阵同时服务三件事：**准备阶段派沟通任务、计划阶段排日程、现场阶段定访谈对象**。所以部门名与过程词表必须先统一，否则三处全错。

## 七、认证准备（远程阶段）：把能问到的先问完

### 7.1 三件事，按顺序

```
① 企业研究   性质、产品、工艺、组织、职能、体系范围、删减、外包
② 适用性裁剪 每条款：适用 / 不适用（有依据）/ 待确认
③ 索取与研读 按企业端要求汇总清单 → 拿到 → 提取 → 差异分析
```

### 7.2 企业研究：画像从哪来、建什么

审核员事先不知道企业文档长什么样，但画像也不是凭空来的。五个来源，从"不用求人"到"必须问人"：

| 来源 | 能拿到什么 | 成本 |
|---|---|---|
| **企业官网 / 公开信息** | 主营产品、业务模式、规模、场所与分支、宣传的资质 | 最低，先看 |
| **营业执照 / 许可证 / 注册证** | 经营范围、许可项目、产品类别、注册地址 | 低 |
| **提前与企业联系人沟通** | 组织架构、部门职能、设计/生产/外包、体系范围、多体系 | 中，但信息最准 |
| **企业提交的体系文件** | 手册 4.3、程序清单、组织图、工艺流程、设备与人员 | 中 |
| **现场首日观察** | 实际布局、在制品、标识、设备状态 | 高（已到现场） |

前三项通常在接到项目后半天内就能拿到，**足够做出一版可用的初判**；后两项用来修正。

| 读什么 | 建什么 |
|---|---|
| 营业执照 / 许可证 / 注册证 | 组织类型、产品范围、法规约束 |
| 官网 / 公开信息 | 业务模式、规模、场所数量 |
| 组织架构图 / 职责文件 | 部门、层级、职能、负责人 |
| 质量手册 4.3 | 体系范围、删减项与理由 |
| 工艺流程图 / 特殊过程清单 | 过程、特殊过程、外包 |
| 设备清单 | 测量设备、生产设备、是否需要溯源 |
| 花名册 / 班次 | 规模、抽样量、访谈对象 |

产出物是**企业画像**：组织类型、业务模式（销售/研发/生产/服务/贸易）、产品与服务、工艺与特殊过程、设计职责、外包、场所、测量设备、法规许可、人数、体系范围与删减、多体系清单。

> 这份画像是后面所有判断的地基：适用性靠它、部门矩阵靠它、抽样量靠它、人日估算靠它。**画像错了，后面全错且不报错。**
>
> 画像允许"先用粗的"：官网 + 执照先出一版，沟通后修正，现场再修正。不要求一次填对。

### 7.3 适用性裁剪：把范围定下来

按画像逐条判定，产出裁剪清单：

| 条款 | 状态 | 依据 | 来源 |
|---|---|---|---|
| 7.3 | 不适用 | 无设计职责，设计外包给 X，协议编号… | 手册 4.3 + 外包协议 |
| 7.5.5 | 适用 | 产品为无菌器械，注册证… | 注册证 |
| 7.5.9.2 | 待确认 | 是否含植入性部件未说明 | 待沟通 |

裁剪清单要能被审核组长复核，也要能作为报告"范围与删减"章节的依据。

### 7.4 资料索取：按企业端要求汇总

企业端的 `Artifacts` 汇总去重后，就是一张索取清单：

| 输出 | 说明 |
|---|---|
| 按文档类型分组 | 手册 / 程序 / 制度 / 作业指导书 / 记录 / 内审资料 |
| 按部门分组 | 哪个部门该交什么（部门矩阵的前身） |
| 标必交 / 宜交 | 来自 `Obligation` |
| 附模板 | 机构资料清单里的对应模板 |
| 标已知 | 已上传的不再重复索取 |

> 这一步是"远程把能拿的全拿到"的关键。**索取清单越准，现场越省时间。**

### 7.5 研读与差异分析

单份文档只看内部；差异必须跨文档看：

| 类型 | 例 | 判据 |
|---|---|---|
| 纵向不一致 | 手册说灭菌按 7.5.7 确认，程序没有确认章节 | 要求存在、下游缺失 |
| 横向不一致 | 程序写"每批灭菌"，记录显示"每周一次" | 规定 vs 执行频率 |
| 要素不一致 | 台账 12 台，校准证书 9 份 | 数量/编号/有效期对不上 |
| 版本不一致 | 现场在用 A 版，受控清单登记 B 版 | 版本与受控状态不符 |

### 7.6 疑点分拣：这一步直接决定现场怎么排

每条缺口或矛盾，判一个类型，同时判"能不能远程解决"：

| 类型 | 判据 | 能不能远程 | 去处 |
|---|---|---|---|
| **沟通** | 补交 / 书面说明即可 | 能 | 发企业，不进现场 |
| **观察** | 只能眼见为实：标识、状态、环境、设备 | 不能 | 现场任务 |
| **询问** | 需要人回答：职责、意识、授权、培训效果 | 不能 | 现场任务 |
| **验证** | 两处信息矛盾，必须交叉核对 | 部分能 | 现场任务（带 A/B 两种说法） |

**分拣错了的代价**：把"沟通"排进现场 = 白跑；把"观察"当"沟通" = 漏查。

### 7.7 预NC

三前置：适用（过裁剪）、强制（`Obligation` 为强制/应）、证据完备（文档 + 现场）。只有文档没有现场，只能出 `draft`。

## 八、认证计划：在时间预算内把证据密度做到最大

### 8.1 时间是硬约束，不是估算

```
现场预算 = 阶段规定天数 × 每天有效工时（扣除开场 / 末次 / 赶路）
每个现场任务 = 预估时长
Σ 任务时长 > 预算  →  必须砍，不能加天数
```

砍的顺序：**低风险条款 → 可远程补证的 → 抽样量可减的**。砍掉的要记录理由，写进计划备注（"因时间限制，7.x 采用抽样 3 份"）。

### 8.2 任务分拣表（计划的核心）

计划不是"条款清单"，是**一张可执行的任务表**：

| 列 | 来源 |
|---|---|
| 条款 | 适用性裁剪后的条款 |
| 执行端任务 | `EvidenceChain` / `EvidenceKinds` 生成的取证动作 |
| 远程还是现场 | 7.6 分拣结果 |
| 部门 / 对象 | `Process` × 企业部门 |
| 预估时长 | 机构基准 × 抽样量 |
| 审核员 | 分工结果 |
| 必查 | 法定必查项 |
| 风险 | 条款属性完备度 + 企业历史 |

### 8.3 排期四条原则

1. **按部门聚集**，不按条款号顺序——同一部门一次问完，减少往返。
2. **必查项先占位**：内审、管理评审、投诉与不良事件、灭菌确认（适用时）先锁时间。
3. **高风险前置**：证据可能不足的条款排在前面，留出补证时间。
4. **抽样定量**：台账抽几台、记录抽几个月、批次抽几个，写死在任务里，不留给现场临时决定。

### 8.4 分工

| 角色 | 分工依据 |
|---|---|
| 组长 | 分配任务、把控时间、终判、签报告 |
| 组员 | 按部门 / 专业领取任务、录证据 |
| 技术专家 | 被咨询，不独立开 NC |

> **审核员全年可下场约 180 天**，这是分派的天花板：同一审核员在计划期内的现场天数之和不得超过其可用天数。超了只能换人或改期——这也是"计划必须紧凑"的现实来源。

### 8.5 机构默认检查项：后置，不是核心

机构对某类体系有惯用的合并 / 拆分方式，可以作为**默认值**预填计划，减少重复劳动。但：

- 当前阶段**不做模板管理功能**；
- 先用通用判据（一份证据能否问完 + 要求形态 / 材料重合度）自动建议；
- 等"分析准确、专家愿意信"被验证之后，再决定要不要把机构习惯固化成模板。

> 核心指标不是"计划生成得多快"，而是"计划里的判断专家认不认"。模板能省时间，但省不出准确性。

### 8.6 多体系

一次现场、一个审核组、N 套条款集合与结论。行程可合并，结论和报告不合并。

## 九、现场检查：证据变成结论

### 9.1 证据完善四问

| 问 | 不够时的后果 | 动作 |
|---|---|---|
| 够不够 | 只有一个部门/一个批次 → 证明不了系统性 | 补抽、补部门 |
| 新不新 | 证据早于最近一次变更 → 不成立 | 要最近一期 |
| 一致不一致 | 现场与记录矛盾 | 转"验证" |
| 可否复核 | 无锚点 → 报告写不出 | 补锚点 |

### 9.2 疑点五种走向

| 走向 | 触发 | 结果 |
|---|---|---|
| `confirmed` | 证据闭合，满足三前置 | 正式 NC |
| `refuted` | 资料缺失但有等效控制 | 关闭，记录理由 |
| `downgrade` | 非强制，或仅单点 | 观察项 |
| `upgrade` | 同条款跨部门多处，指向系统失效 | 严重候选（人确认） |
| `pending` | 证据不足 | 写明还缺什么，不得默认 NC |

### 9.4 现场任务执行与时间控制

| 状态 | 含义 | 处置 |
|---|---|---|
| 待执行 | 计划内未开始 | — |
| 已取证 | 证据已录，锚点齐全 | 可进判定 |
| 需补证 | 证据不足（不够 / 不新 / 矛盾） | 排补证，占用剩余预算 |
| 超时 | 单项超预估 | 记录原因，组长决定是否压缩后续 |

> 现场最常见的失败不是"看不懂"，是"时间不够"。所以任务必须有预估时长和状态，超时要可见。

### 9.3 证据落点

每条证据固定带：条款号、类型（文档/记录/现场/访谈）、事实描述、锚点（时间/地点/人物/数值至少一项）、采集人、采集时间、关联证据链。

## 十、报告

| 内容 | 数据来源 |
|---|---|
| 封面与基本信息 | 企业档案 + 计划 + 审核组 |
| 各标准结论 | 按标准拆分的条款结论 |

## 十二、为什么专家能信任这套结果

准确不是一句口号，要能被量出来。核心四个指标：

| 指标 | 定义 | 为什么它是核心 |
|---|---|---|
| **漏查率** | 适用条款中没被任何检查项覆盖的比例 | 漏查是审核员最大的职业风险，必须为 0 |
| **一致率** | 系统给出的人工复核结论一致的比例 | 这是"专家愿不愿意用"的直接判据 |
| **可追溯率** | 结论能回指到证据链与锚点的比例 | 报告站不站得住，全靠这个 |
| **误判成本** | 被推翻的 NC 里，因"证据不足/适用性错"导致的比例 | 区分"业务判断分歧"和"系统缺陷" |

四条闭环支撑这四个指标：

| 闭环 | 怎么闭 |
|---|---|
| **要求 ↔ 实际** | 条款双端 + 文档关键信息，要求侧和实际侧永远分表 |
| **适用 ↔ 范围** | 适用性裁剪三态，待确认不许写成不适用 |
| **计划 ↔ 执行** | 计划从裁剪后的条款长出来，任务能回到条款，证据能回到任务 |
| **结论 ↔ 证据** | 每条结论必须挂证据链，无锚点不得出结论 |

### 12.1 完成 ≠ 合格

这一条必须写清楚，否则会被误读成"系统要求所有条款都通过"：

| 说法 | 正确理解 |
|---|---|
| "任务完成" | 在规定时间内完成计划内取证与判断，**包含判出 NC** |
| "覆盖率 100%" | 每个适用条款都有结论（符合 / 不符合 / 观察 / 不适用 / 未覆盖），不是都合格 |
| "未覆盖" | 时间不够没查，显式标注，不默认符合 |

企业确实没有的东西，判 NC 就是正确结果。系统不追求"让企业看起来合格"，只追求"结论站得住"。

> 模板、批量、自动排期都是效率手段，**准确性才是这套系统能卖钱的原因**。效率可以后补，信任补不回来。

## 十三、红线（违反 = 返工）

1. 条款只有企业端或只有执行端 → 分拣不出来（不知道该远程拿还是现场看），标红提示；**不阻断计划，但必须可见**。
2. 规则侧表出现 `OrgCode` / `EnterpriseCode`。
3. 要求企业提供"证据"（企业只能提供文档与记录，证据由审核员采集）。
4. 用企业自述代替现场取证就下结论。
5. **把"待确认"写成"不适用"** → 整章漏查，且不报错。
6. 部门名由模型自造（必须取自企业档案）。
7. `unknown` 当 `missing` 推 NC。
8. 三个口径（条款数 / 检查项数 / 证据条数）混用一个数报。
9. 多体系合并成一份结论或一份报告。
10. 结论无锚点、无证据链。
11. 用提示词定"什么算合格"（阈值与矩阵归规则表）。
12. 机构差异写进条款属性表。

## 十四、分期（核心先做准，效率后补）

| 期 | 内容 | 出口判据 |
|---|---|---|
| **P1 规则侧** | 条款双端 12 属性 + 条款配置 + 文档要求 + `cert_validation_rule` + 提示词 | 273 条属性红点可见；9001 第 7/8 章文档要求齐全 |
| **P2 企业研究** | 企业画像（性质/产品/工艺/组织/职能/范围）+ 部门表 + 审核组表 | 能从一企业的真实文档自动建出画像，且部门名与档案一致 |
| **P3 适用性裁剪** | 条款 × 企业事实 → 适用 / 不适用 / 待确认 + 依据 | 一企业三体系跑出裁剪清单，待确认项全部进沟通任务 |
| **P4 准备与计划** | 索取清单 / 研读 / 疑点分拣 / 时间预算 / 任务表 / 分工 | 计划能解释"为什么这条在现场、那条在远程"，且总时长不超预算 |
| **P5 现场检查** | 证据入库 / 证据链 / 五种走向 / 系统性失效 | 每条预NC能被推进到确认 / 推翻 / 待补 |
| **P6 报告与回归** | 报告按标准拆分 + 回归集 + 一致率统计 | 一致率、可追溯率、漏查率可量化 |
| **P7 效率增强（非核心）** | 机构默认检查项模板 / 批量排期 / 自动分工 | 前置六期验收通过后再做 |

**P1 不做完就做 P4，等于拿没校准的尺子排计划**：条款没分拣信息，计划排出来的就只是一堆编号。
