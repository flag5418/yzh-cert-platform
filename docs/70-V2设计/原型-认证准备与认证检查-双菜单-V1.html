认证准备 / 认证检查 · 双菜单

三、派生关系（关键）

认证准备、认证检查两个菜单不自己造数据，全部来自认证计划的「开启」动作：

  • 计划列表 → 点「开启准备」→ 建一条 cert_task(TaskKind='prep') → 跳 /audit-prep/:code
  • 计划列表 → 点「开启检查」→ 建一条 cert_task(TaskKind='onsite') → 跳 /audit-onsite/:code
  • 某计划从未开启过准备 → 准备列表里没有它；两个菜单都为空时，显示空态引导去认证计划

四、与原型的差异

你给的 原型-计划启动工作流.html 里，一列叫「PrepState / Conclusion」，是因为两个分支塞在同一张表。拆成两个菜单后：

  • 准备详情：只保留 PrepState（found / partial / missing / unknown / na），没有「建议NC / 严重度」—— 准备阶段不判 NC
  • 检查详情：Conclusion（符合 / 观察项 / 一般不符合 / 严重不符合 / 不适用）+ 建议NC + 严重度，没有 PrepState
  • 其余版式（部门联系人独立列、抽屉分区、底部队列条、锁定语义）完全沿用你的原型

五、需要你拍板的 4 件事

  1. 同一计划同一分支开启第二次，列表是新增一行还是复用原行？
    我倾向：复用原行、刷新「开启时间」，历史轮次进详情看（RunNo 已经有）。否则列表会被重跑刷屏。
  2. /audit-task 怎么处理？
    我倾向：保留但不进菜单，作为运维排查页（看 yzh_queue 批次），日常不用。
  3. 详情页路由用哪个主键？
    我倾向 cert_task.Code，因为它已经是「计划 × 分支 × 轮次」的天然载体。
  4. 「认证检查」这个词，是不是就是 onsite（现场检查）？
    数据库里是 prep / onsite。如果认证检查还包含非现场部分，路由名要另起。
