## 一、认证行业通用术语

### 合格评定
- **英文**：Conformity Assessment
- **定义**：证明产品、服务、过程、体系或人员符合规定要求的活动。
- **说明**：合格评定是一个"总称"，认证、检测、检验、校准都属于合格评定的具体手段。举例：说你家的水管合格了，可能经过了工厂检测、第三方实验室检验，或者拿到了某个权威机构的认证证书——这些都属于合格评定。
- **关联**：认证、认可、检验、检测

### 认证
- **英文**：Certification
- **定义**：由独立第三方出具书面保证，证明某个产品、服务或管理体系符合特定标准。
- **说明**：认证的核心是"第三方的书面保证"。比如一家工厂说"我的质量管理很厉害"，这不叫认证；但如果 SGS 或 ACM 这样的机构派人去查完，出具一份证书说"该工厂的质量管理体系符合 ISO 9001 标准"，这才叫认证。认证是有有效期的，到期需要重新审核。
- **关联**：认可、认证机构（CB）、认证证书、管理体系标准

### 认可
- **英文**：Accreditation
- **定义**：由权威机构正式承认某个组织具备从事特定认证/检测/检验活动的能力。
- **说明**：认可管的是"做认证的机构"，不是管企业的。常见的误解：以为企业拿到了 ISO 证书就是被"认可"了——实际上企业是被"认证"，认证机构才是被"认可"。在中国，CNAS（中国合格评定国家认可委员会）就是认可机构；国际上，UKAS（英国）也是知名的认可机构。
- **关联**：认证、认可机构（AB）

### 审核
- **英文**：Audit
- **定义**：系统的、独立的检查过程，用来判断实际活动是否符合预定安排和标准要求。
- **说明**：审核不是"找茬"。审核员的职责是对照着标准一条条核对企业的实际情况，把符合的地方记录下来，不符合的也记录下来，最终得出一个结论。审核讲究"证据说话"——不能凭感觉说人家不合格，必须有客观证据。
- **关联**：审核方案、审核准则、审核发现、审核证据

### 检验
- **英文**：Inspection
- **定义**：对产品、过程或设施进行观察和判断，通常伴随测量、测试。
- **说明**：检验更偏"实物检查"。比如检验一台机器是否符合设计图纸，检验一批零件的尺寸精度。和审核不同，审核更偏"体系层面"的系统性检查。
- **关联**：检测、合格评定

### 检测
- **英文**：Testing
- **定义**：按照规定的技术方法，对样品进行技术指标测定。
- **说明**：检测是最"硬"的手段——在实验室用仪器测数据。比如检测自来水的重金属含量是否超标。检测结果是审核证据的重要来源之一，但检测本身不等于审核。
- **关联**：检验、合格评定

### 第一方审核
- **英文**：First-Party Audit
- **定义**：组织自己对自己的内部审核。
- **说明**：也叫"内审"。企业自己的审核员按照标准要求，逐条检查自己的管理体系是否合规。内审的目的是自我发现问题、自我改进，不是拿证书。
- **关联**：第二方审核、第三方审核、审核

### 第二方审核
- **英文**：Second-Party Audit
- **定义**：由组织的客户或代表客户利益的人员进行的审核。
- **说明**：比如苹果公司派人去审核它的供应商富士康，这就是第二方审核。审核方和被审核方有直接的合同或利益关系。
- **关联**：第一方审核、第三方审核、审核

### 第三方审核
- **英文**：Third-Party Audit
- **定义**：由独立于供需双方的外部认证机构进行的审核。
- **说明**：这是最常说的"认证审核"。审核机构和企业没有利益关系，审核结果才具有公信力。ACM、SGS、TÜV 做的就是第三方审核。
- **关联**：第一方审核、第二方审核、认证机构（CB）

### 管理体系标准
- **英文**：Management System Standard
- **定义**：国际标准化组织（ISO）发布的、规定组织管理体系应满足什么要求的规范性文件。
- **说明**：最常见的是 ISO 9001（质量管理）、ISO 14001（环境管理）、ISO 45001（职业健康安全）这三件套。它们不规定企业具体怎么做，只规定"应该做到什么"——比如"你要有文件化程序""你要定期内审""你要做管理评审"。标准是审核员的"尺子"。
- **关联**：认证、审核准则

### ISO 9001
- **英文**：ISO 9001:2015 Quality Management Systems
- **定义**：国际通用的质量管理体系标准，规定组织应如何持续提供合格产品并提升客户满意度。
- **说明**：ISO 9001 是全球应用最广的管理体系标准，几乎所有行业的认证都从它开始。它涵盖领导作用、策划、支持、运行、绩效评价、改进六大板块。2015 版是最新版。
- **关联**：管理体系标准、认证

### ISO 14001
- **英文**：ISO 14001:2015 Environmental Management Systems
- **定义**：国际通用的环境管理体系标准，帮助组织管理其环境影响。
- **说明**：工厂、建筑企业、化工企业申请较多。关注废水、废气、噪声、固废等环境因素的管控。
- **关联**：管理体系标准、ISO 9001

### ISO 45001
- **英文**：ISO 45001:2018 Occupational Health and Safety Management Systems
- **定义**：国际通用的职业健康安全管理体系标准，帮助组织预防工伤和健康损害。
- **说明**：代替了原来的 OHSAS 18001。制造业、建筑业、矿山企业申请较多。
- **关联**：管理体系标准、ISO 9001

### ISO 13485
- **英文**：ISO 13485:2016 Medical Devices Quality Management Systems
- **定义**：医疗器械行业专用的质量管理体系标准。
- **说明**：比 ISO 9001 更严格，因为涉及人的生命安全。ACM 在 ISO 13485 领域较有竞争力，是核心业务线之一。
- **关联**：管理体系标准、ISO 9001

### 认证机构（CB）
- **英文**：Certification Body（CB）
- **定义**：经认可机构批准、有资格向申请组织颁发认证证书的第三方机构。
- **说明**：CB 是执行第三方审核并签发证书的主体。注意：CB 本身需要被认可机构（AB）认可，否则它签发的证书没有公信力。ACM 就是一个 CB。
- **关联**：认可机构（AB）、第三方审核、认证证书

### 认可机构（AB）
- **英文**：Accreditation Body（AB）
- **定义**：有权对认证机构的能力进行正式承认的权威组织。
- **说明**：在国内，CNAS（中国合格评定国家认可委员会）是认可机构。在国际上，UKAS（英国）、ANAB（美国）等也是认可机构。AB 是"管 CB 的"，就像监管机构管银行一样。
- **关联**：认证机构（CB）、认可

### 认证范围
- **英文**：Certification Scope
- **定义**：认证证书上所覆盖的产品类别、服务活动范围或场所。
- **说明**：认证不是"全公司所有活动都认证了"，而是有明确的范围界定，比如"XX 产品的设计、生产和销售"。审核员只能在这个范围内做审核，超出范围的活动不在证书效力之内。
- **关联**：认证证书、缩小范围

### 认证证书
- **英文**：Certificate
- **定义**：认证机构签发的证明文件，声明申请组织在认证范围内符合某管理体系标准。
- **说明**：证书有有效期（通常 3 年），到期前需要再认证审核。证书上会标注认证范围、签发机构、有效日期、认可标识等关键信息。
- **关联**：认证、认证标志、再认证审核、证书全生命周期管理

### 认证标志
- **英文**：Certification Mark
- **定义**：认证机构授权获证组织在产品、包装或宣传材料上使用的标识图案。
- **说明**：认证标志是"可以拿来宣传"的。比如产品包装上印了 ISO 9001 认证标志，代表该企业的质量管理体系通过了第三方认证。标志的使用有严格规范，滥用会被暂停或撤销证书。
- **关联**：认证证书、暂停

### 监督审核
- **英文**：Surveillance Audit
- **定义**：在证书有效期内，认证机构按年度对获证组织进行的定期复查。
- **说明**：证书有效期 3 年，但不等同于 3 年内没人管。每年至少要来一次监督审核，确认企业还在持续符合标准。如果把初次认证比作"考上大学"，监督审核就是"每学期的期末考试"。
- **关联**：初次认证审核、再认证审核

### 初次认证审核
- **英文**：Initial Certification Audit
- **定义**：组织首次申请认证时，认证机构进行的全面审核。
- **说明**：通常分两个阶段：第一阶段看文件是否齐全、现场是否准备就绪；第二阶段才是正式现场审核。只有两个阶段都通过，才能拿到证书。
- **关联**：监督审核、再认证审核

### 再认证审核
- **英文**：Recertification Audit
- **定义**：证书到期前，认证机构对获证组织进行的重新全面审核。
- **说明**：3 年证书到期前，企业需要接受一次"大考"，审核范围接近初次认证的全面程度，通过后换发新证。如果没通过，证书到期即失效。
- **关联**：监督审核、认证证书

### 特殊审核
- **英文**：Special Audit
- **定义**：因特殊情况（投诉、重大变更、法规要求等）触发的临时性审核。
- **说明**：不是定期安排的那种。比如有客户投诉产品质量问题、企业发生了重大安全事故、或者企业要扩证范围，都可能触发特殊审核。特殊审核往往"来者不善"。
- **关联**：监督审核、暂停

### 暂停
- **英文**：Suspension
- **定义**：认证机构对获证组织的证书进行临时中止的处理，通常有整改期限。
- **说明**：暂停期间证书暂时无效，企业不能使用认证标志，不能在宣传中以获证组织自称。暂停是有期限的（通常 3-6 个月），期限内改正可以恢复，超期仍未纠正则走向撤销。
- **关联**：撤销、注销、缩小范围

### 撤销
- **英文**：Withdrawal
- **定义**：认证机构永久取消获证组织的认证资格。
- **说明**：撤销是最严重的处理。一旦撤销，企业不再是认证客户，所有认证相关的权利全部消失。想重新获得认证，必须从头申请，之前的审核记录全部作废。
- **关联**：暂停、注销

### 注销
- **英文**：Cancellation
- **定义**：企业主动申请终止认证关系。
- **说明**：区别于暂停和撤销，注销是企业自己不想继续持证了——可能是不再经营相关业务，或者转去其他认证机构。
- **关联**：暂停、撤销

### 缩小范围
- **英文**：Scope Reduction
- **定义**：认证机构缩减认证证书所覆盖的产品或活动范围。
- **说明**：比如某企业原来证书覆盖 A、B、C 三类产品，但 B 类产品停产了，审核后证书范围改为仅覆盖 A 和 C。缩小范围通常是对企业持续符合能力下降的回应。
- **关联**：认证范围、暂停

### 审核人天
- **英文**：Audit Man-Day
- **定义**：一个审核员工作一天（8 小时）计为 1 个审核人天，是衡量审核工作量的标准单位。
- **说明**：认证机构根据企业规模和审核范围计算需要多少审核人天，这直接影响审核费用。比如一家 100 人的工厂做 ISO 9001 初次认证，大概需要 5-8 个审核人天。审核人天不够是不能发证的——这是认可机构的硬性规定。
- **关联**：审核方案、审核计划

### 多场所认证
- **英文**：Multi-Site Certification
- **定义**：一个组织在多个地点运行同一管理体系，认证机构通过抽样方式对所有场所进行认证的活动。
- **说明**：比如某集团在全国有 10 个分厂，认证机构不需要每个分厂都去从头审核一遍，可以按一定规则抽样。ACM 有 20 家分公司，支撑多场所认证的审核调度是系统核心能力之一。
- **关联**：认证范围、审核方案

### IMS 整合管理体系
- **英文**：Integrated Management System（IMS）
- **定义**：将两个或更多的管理体系（如质量、环境、职业健康安全）整合为一个统一的管理体系。
- **说明**：企业通常不会只做 ISO 9001，而是"三体系一起做"（9001 + 14001 + 45001）。整合审核可以一次审核同时覆盖三个标准，降低企业负担，也降低审核成本。
- **关联**：管理体系标准、审核方案

## 二、审核过程术语

### 审核方案
- **英文**：Audit Programme
- **定义**：对一个认证周期内（通常 3 年）所有审核活动的总体安排。
- **说明**：审核方案是"宏观计划"，告诉你这三年里哪年做初次审核、哪年做监督审核、哪年做再认证。它不是单次审核的计划，而是一个完整的周期规划。
- **关联**：审核计划、认证证书

### 审核计划
- **英文**：Audit Plan
- **定义**：单次审核的具体安排，包括审核时间、审核员分配、审核部门、审核条款等。
- **说明**：审核计划是"微观方案"，发给企业的——"我们哪天来、来几个人、审核哪个部门、看什么条款"。企业需要提前签字确认。
- **关联**：审核方案、审核人天

### 审核准则
- **英文**：Audit Criteria
- **定义**：用于与客观证据进行比较的一组政策、程序或要求。
- **说明**：简单说就是"对照什么来审"。管理体系标准是最主要的审核准则，此外还包括企业的内部文件、法律法规要求等。审核员不能说"我觉得不行"，必须说"根据 ISO 9001 第 X 条第 Y 款，这里不符合"。
- **关联**：审核证据、审核发现、管理体系标准

### 审核证据
- **英文**：Audit Evidence
- **定义**：审核过程中获取的、可验证的记录、事实陈述或其他信息。
- **说明**：审核证据必须是"可验证的"，不能是道听途说。比如看到一份缺少签字的检验报告——这是证据。听到员工说"我们从来没开过管理评审会议"——经过核实后也可以成为证据。证据是审核发现的基础。
- **关联**：审核发现、审核准则、证据链与证据固定

### 审核发现
- **英文**：Audit Finding
- **定义**：将收集的审核证据对照审核准则进行评价的结果。
- **说明**：审核发现就是"合格的"或"不合格的"——它是评价结果，不是原始数据。比如"该企业的内部审核程序缺少对纠正措施验证的要求"就是一个审核发现（不符合项）。
- **关联**：审核证据、审核结论、不符合项（NC）

### 审核结论
- **英文**：Audit Conclusion
- **定义**：考虑了审核目标后，基于审核发现得出的最终判断。
- **说明**：结论决定"能不能通过"——"推荐发证"、"有条件推荐（整改后发证）"或"不推荐发证"。审核结论是末次会议的核心内容。
- **关联**：审核发现、审核报告、末次会议

### 不符合项（NC）
- **英文**：Nonconformity（NC）
- **定义**：未满足审核准则要求的客观事实。
- **说明**：NC 是审核的核心产出之一。不是所有"做得不好"都算 NC，必须有明确的准则条款对应。NC 分严重和一般两种，严重 NC 可能导致不能发证。
- **关联**：严重不符合、一般不符合、观察项、纠正措施

### 严重不符合
- **英文**：Major Nonconformity
- **定义**：严重影响管理体系实现预期结果的能力，或存在系统性失效的不符合。
- **说明**：比如"整个生产部门从未做过内部审核"、"半数以上的产品出货记录缺失"——这些都是严重 NC。有一个严重 NC，通常意味着不能推荐发证，必须整改后再来现场验证。
- **关联**：不符合项（NC）、一般不符合、观察项

### 一般不符合
- **英文**：Minor Nonconformity
- **定义**：对管理体系实现预期结果的能力影响有限、属于个别或偶发性的不符合。
- **说明**：比如"某一份检验报告的审核人漏签了"——这是问题，但不表示整个体系崩了。一般 NC 需要整改，但不一定要再来现场验证，可以远程或文件验证。
- **关联**：不符合项（NC）、严重不符合、观察项

### 观察项
- **英文**：Observation / Opportunity for Improvement（OFI）
- **定义**：虽然不构成不符合，但存在改进空间或潜在风险的事项。
- **说明**：观察项不是 NC，不强制整改，但记录在案，下次审核会关注。比如"仓库的区域标识不太清晰，建议增加标识牌"——这就是观察项。
- **关联**：不符合项（NC）、严重不符合、一般不符合

### 纠正
- **英文**：Correction
- **定义**：为消除已发现的不符合所采取的具体动作。
- **说明**：纠正就是"把这个错误改掉"。比如一份报告漏签了，补签上——这就是纠正。但纠正不回答"为什么会漏签"，只是把眼前的问题解决了。
- **关联**：纠正措施、预防措施、不符合项（NC）

### 纠正措施
- **英文**：Corrective Action
- **定义**：为消除已发现不符合的根本原因，防止再发生所采取的措施。
- **说明**：纠正措施是"治本"。报告漏签了，不仅要补签（纠正），还要分析为什么漏签——是流程里没规定谁来签？还是签审人员离职了没人接手？然后修改流程或安排接手人——这才是纠正措施。审核员要的不是纠正，是纠正措施。
- **关联**：纠正、预防措施、根因分析、不符合项（NC）

### 预防措施
- **英文**：Preventive Action
- **定义**：为消除潜在不符合的原因，防止其发生所采取的措施。
- **说明**：预防措施针对的是"还没发生但可能会发生的"。比如发现隔壁车间因为潮湿导致产品受潮，你提前在自己的车间加装除湿机——这就是预防措施。ISO 9001:2015 不再单独要求"预防措施"这个术语，但思想融入了基于风险的思维。
- **关联**：纠正措施、纠正

### 根因分析
- **英文**：Root Cause Analysis（RCA）
- **定义**：系统性地追溯问题产生的深层次原因，而不是停留在表面现象的分析方法。
- **说明**：如果不符合项是"病症"，根因分析就是"查病因"。常用方法有 5 Why（连续追问五个"为什么"直到找到根因）和鱼骨图（人、机、料、法、环五个维度排查）。审核员最看重的就是企业的根因分析能力。
- **关联**：纠正措施、不符合项（NC）、5 Why、鱼骨图

### 5 Why
- **英文**：5 Whys
- **定义**：通过连续追问"为什么"来逐层深入寻找问题根本原因的方法。
- **说明**：一个例子：产品有划痕（为什么？）→ 搬运工操作不当（为什么？）→ 没培训（为什么？）→ 培训制度没规定新员工上岗前必须培训（为什么？）→ 管理层没把上岗培训当作强制要求——到这里才是根因。不是非要问五次，关键是追问到"再问就超出管理影响范围"为止。
- **关联**：根因分析、鱼骨图

### 鱼骨图
- **英文**：Fishbone Diagram / Ishikawa Diagram
- **定义**：以图形化方式展示问题原因与结果之间关系的因果分析工具，因形状似鱼骨而得名。
- **说明**：通常从五个维度排查：人员（Man）、机器（Machine）、材料（Material）、方法（Method）、环境（Environment）。鱼骨图的优势是能同时展示多个可能原因，适合头脑风暴式的根因分析。
- **关联**：根因分析、5 Why

### 审核轨迹
- **英文**：Audit Trail
- **定义**：记录审核活动全过程的完整证据链，包括谁在什么时间做了什么操作、产生了什么数据。
- **说明**：审核轨迹是"不可篡改的操作日志"。认证行业对轨迹要求极高——认可机构回头来查认证机构时，会抽查：这个审核员当时到底有没有去企业现场？他依据什么判的这个 NC？证据在哪里？轨迹缺失对认证机构是致命风险。
- **关联**：证据链与证据固定、审计追溯

### 审核报告
- **英文**：Audit Report
- **定义**：审核结束后由审核组编写的正式书面文件，记录审核过程、发现和结论。
- **说明**：审核报告是审核的最终输出物。它包含企业基本信息、审核范围、审核准则、审核发现汇总、NC 清单、审核结论等。这份报告会存档多年，是认可机构抽查的核心对象。
- **关联**：审核结论、不符合项（NC）、末次会议

### 首次会议
- **英文**：Opening Meeting
- **定义**：审核开始时，审核组与企业代表召开的正式沟通会议。
- **说明**：确认审核范围和计划、介绍审核方法、沟通配合事项。首次会议的签到表和会议记录本身就是审核证据之一，必须保留。
- **关联**：末次会议、审核计划

### 末次会议
- **英文**：Closing Meeting
- **定义**：审核结束时，审核组向企业通报审核发现和初步结论的正式会议。
- **说明**：这是"出成绩"的时刻——公布有哪些 NC、是严重还是一般、审核结论是什么。末次会议后，企业需要在一定期限内提交整改证据。
- **关联**：首次会议、审核结论、不符合项（NC）

### 现场审核
- **英文**：On-Site Audit
- **定义**：审核员到企业实际运营场所进行的面对面审核。
- **说明**：传统的认证审核都是现场审核——审核员亲自去工厂、车间、办公室查看实际情况，翻阅纸质记录，访谈员工。现场审核能获取最直接的证据。
- **关联**：远程审核、审核

### 远程审核
- **英文**：Remote Audit
- **定义**：审核员不亲临现场，通过视频会议、远程桌面、电子文档等方式进行的审核。
- **说明**：疫情推动了远程审核的普及。远程审核节省差旅成本，但对证据获取的完整性要求更高——你没法"随手翻翻角落的文件"。ISO 目前允许部分远程审核，但关键环节仍可能要求现场验证。
- **关联**：现场审核、审核

## 三、系统功能术语

### 不符合项整改流程
- **英文**：NC Correction & Corrective Action Workflow
- **定义**：从不符合项开出到企业提交整改证据、审核员验证关闭的完整闭环流程。
- **说明**：这是平台最核心的业务流程之一。流程包含：审核员开 NC → 企业填写纠正/纠正措施/根因分析 → 上传整改证据 → 审核员验证 → 关闭或退回。每一步都有时限要求，逾期自动催办。系统需要完整记录每一步的操作轨迹。
- **关联**：不符合项（NC）、纠正措施、证据链与证据固定、自研工作流引擎（DAG）

### 证据链与证据固定
- **英文**：Evidence Chain & Evidence Fixation
- **定义**：将审核过程中产生的所有证据按逻辑关系串联起来，并通过技术手段确保其不被篡改。
- **说明**：证据链回答"这个结论从哪来的"——一条审核发现要能追溯到源文件的具体段落、AI 的推断逻辑、审核员的确认动作。证据固定则通过哈希校验、时间戳等技术手段，确保证据一旦形成就不能再改。两者结合，满足认可机构对"可追溯、不可抵赖"的硬性要求。
- **关联**：审核轨迹、审核证据、审计追溯

### 证书全生命周期管理
- **英文**：Certificate Lifecycle Management
- **定义**：对认证证书从申请、审核通过、签发、年度监督、变更处理、到期再认证、暂停/撤销/注销的全过程进行系统化管理。
- **说明**：证书不是"发完就完了"——3 年有效期内的状态可能随时变化：范围可能调整、证书可能因 NC 未关闭被暂停、到期前要提醒再认证。平台需要在每个关键节点触发对应的工作流，并在状态变更时同步更新证书数据库。
- **关联**：认证证书、认证范围、监督审核、再认证审核、暂停、撤销、自研工作流引擎（DAG）

### 审核任务分配与调度
- **英文**：Audit Task Assignment & Scheduling
- **定义**：根据审核员资质、可用时间、地理就近性等因素，将审核任务合理分配给审核员的系统能力。
- **说明**：ACM 有 20 家分公司、全国审核项目，调度不合理会导致一个人跑断腿、另一个人闲着。调度引擎需要考虑：审核员的专业领域（是否有 ISO 13485 资质）、与企业的地理距离、排期冲突、审核人天配额等。多场所认证场景下调度复杂度更高。
- **关联**：审核人天、审核计划、多场所认证

### 人工干预与审计追溯
- **英文**：Manual Intervention & Audit Trail
- **定义**：系统为必要的人工操作提供入口，同时将干预动作完整记录，满足被抽查时的可追溯要求。
- **说明**：认证审核平台的定位是"AI 辅助 + 人做最终决策"。AI 的结论审核员可以接受也可以覆盖，但每次覆盖都要记录"谁、什么时候、为什么改了 AI 的建议"。审计追溯就是这套记录的查询和回放能力——当认可机构来查时，可以完整还原某次审核的全过程决策链。
- **关联**：审核轨迹、证据链与证据固定

## 四、技术术语

### VOL 框架
- **英文**：VOL Framework（Vue + .NET Core）
- **定义**：一套基于 Vue 3 前端和 .NET Core 后端的快速开发框架，提供开箱即用的后台管理系统基础设施。
- **说明**：VOL 框架内置了权限管理、代码生成器、工作流集成等能力。选择它的主要原因是能快速搭建认证审核平台的管理后台，减少从头造轮子的工作量。前端用 Vue 3 + Element Plus，后端用 ASP.NET Core。项目在此基础上进行 YZH-Framework 渐进式升级。
- **关联**：Vue.NetCore、YZH-Framework、自研工作流引擎（DAG）

### Vue.NetCore
- **英文**：Vue.NetCore
- **定义**：VOL 框架的技术组合简称，代表 Vue 3 前端 + .NET Core 后端的一体化开发模式。
- **说明**：这个名字不是指某个独立的库，而是对 VOL 框架技术栈的概括。前后端分离架构，前端静态资源由 Nginx 托管，API 请求走反向代理到 .NET Core 后端。
- **关联**：VOL 框架

### 自研工作流引擎（DAG）
- **英文**：Self-Developed Workflow Engine（DAG）
- **定义**：项目自研的轻量级工作流引擎，前端用 LogicFlow 设计器编排，后端以 DAG（有向无环图）JSON 解释器执行，通过 Skill 节点驱动数据提取、校验、报告生成。
- **说明**：项目早期曾考虑 Elsa 等开源工作流引擎，后经技术研究（见 `80-功能设计/01-系统管理/工作流管理/01-核心引擎/工作流引擎选型与技术研究-V1.md`）决定自研：前端不自研图形界面，选用 LogicFlow（MVP）封装为独立模块 `workflow-designer`，只暴露导入/导出 JSON 接口；后端自研轻量 DAG 解释器（读 JSON、排顺序、调 Skill、传数据、记日志）。审批流（状态机）与 DAG 引擎并行共存：审批流服务审核任务分配、NC 整改闭环、报告审核发布；DAG 引擎专司数据加工。核心数据结构：F-03 WorkflowDefinition（工作流 DAG JSON）、F-04 WorkflowExecutionLog（节点级执行日志）。
- **关联**：LogicFlow、Skill 节点、数据库表设计-V2（域 F）

### LogicFlow
- **英文**：LogicFlow
- **定义**：滴滴开源的前端流程图编辑组件，项目用它作为工作流设计器 MVP 基础。
- **说明**：选用 LogicFlow 是因为其对 Vue 2/3 支持好、节点面板/拖拽连线/属性表单开箱即用度高。项目将其封装为独立模块 `workflow-designer`，只暴露「导入 JSON / 导出 JSON」两个接口，不向业务页面泄漏内部 API；若 LogicFlow 社区维护停滞，可平替 Vue Flow，业务页面与后端零改动。
- **关联**：自研工作流引擎（DAG）

### Skill 节点
- **英文**：Skill Node
- **定义**：工作流 DAG 中的可执行能力节点，是数据提取、校验、报告生成的最小执行单元。
- **说明**：Skill 节点封装具体业务能力（如"按条款提取字段"、"规则校验"、"生成报告片段"），由后端 DAG 解释器按拓扑序调用。`60-AI工程设计/` 中的 Skills 是 AI 生成代码时使用的方法论技能；工作流中的 Skill 节点是运行时能力单元，两者命名相近但作用域不同，注意区分。
- **关联**：自研工作流引擎（DAG）、核心工作原理-V1（三大引擎）

### ACM（认证机构公司名）
- **英文**：ACM（Company Name）
- **定义**：本文档中 ACM 特指一家认证机构（Certification Body）公司。
- **说明**：ACM 是项目的目标客户画像/模拟客户，也是一个真实的认证机构。文档中"ACM 就是一个 CB"、"ACM 在 ISO 13485 领域较有竞争力"、"ACM 有 20 家分公司"均指该公司。注意：本表早期曾将 ACM 误标为"应用兼容性管理（Application Compatibility Management）"，那是早期架构调研的过时概念，与认证机构名冲突，V1.1 已删除该定义。
- **关联**：认证机构（CB）、多场所认证

### Docker Compose
- **英文**：Docker Compose
- **定义**：Docker 官方提供的容器编排工具，通过一个 YAML 文件定义和运行多个相互依赖的容器服务。
- **说明**：认证审核平台涉及多个服务：MySQL、Redis、MinIO、Nginx、.NET API，每个都需要独立运行。Docker Compose 用一个配置文件把所有服务编排好，一条命令全部启动。开发、测试、生产环境用不同的 Compose 配置文件覆盖差异参数。
- **关联**：Nginx、ACM（认证机构公司名）

### Nginx
- **英文**：Nginx
- **定义**：高性能的 HTTP 服务器和反向代理服务器。
- **说明**：在平台部署架构中，Nginx 充当入口网关：终止 HTTPS、反向代理 API 请求到 .NET Core 后端、托管前端静态文件、做 gzip 压缩和限流保护。它不对业务逻辑做任何处理，只管流量分发和安全防护。
- **关联**：Docker Compose

### JWT
- **英文**：JSON Web Token（JWT）
- **定义**：一种紧凑的、URL 安全的声明式令牌，用于在各方之间安全传递身份信息。
- **说明**：用户登录后，服务端签发一个 JWT，之后每次 API 请求在请求头携带这个 token，服务端验证 token 就能知道"你是哪个用户、你有什么权限"，不需要每次查数据库。JWT 自带过期时间，过期需要重新登录。移动端暂不开发（Phase 2+ 规划），届时审核员使用手机 App 时 JWT 是主要的认证方式。
- **关联**：RBAC

### RBAC
- **英文**：Role-Based Access Control（RBAC）
- **定义**：基于角色的访问控制模型，权限不直接授予用户，而是授予角色，用户通过拥有角色来获得权限。
- **说明**：认证审核平台的角色分五类：超级管理员、认证机构管理员、审核组长、审核员、企业用户。每个角色能看什么页面、能做什么操作，都由 RBAC 控制。比如企业用户只能看自己的证书和 NC 整改情况，不能看其他企业的。
- **关联**：JWT

### 分片上传
- **英文**：Chunked Upload / Multipart Upload
- **定义**：将大文件切割成多个小块分别上传，全部上传完成后再合并还原为完整文件的技术。
- **说明**：认证审核涉及大量附件上传——企业的程序文件、检验报告、整改证据等，单个文件可能上百 MB。分片上传的好处：每片小、上传失败只需重传这一片；可以并行上传多片加快速度；支持断点续传。MinIO 对象存储原生支持分片上传协议。
- **关联**：断点续传、MinIO

### 断点续传
- **英文**：Resumable Upload
- **定义**：网络中断后恢复上传时，从上次中断的位置继续传，而不是从头开始的机制。
- **说明**：与分片上传配合使用。系统记录已上传的切片信息，网络恢复后只传尚未成功的切片。这对审核员在外网环境较差时上传大文件尤为重要。
- **关联**：分片上传
