## 一、后端错误

### E001：EF Core / SqlSugar Column 映射 snake_case 导致 400 错误

| 项目 | 内容 |
|------|------|
| **现象** | 新增/修改请求返回 400，错误信息包含 "Column 'xxx' not found" |
| **根因** | 实体类属性名 PascalCase，但数据库列名 snake_case，未显式映射 |
| **修复** | 在属性上添加 `[SugarColumn("snake_case_column_name")]` |
| **示例** | `[SugarColumn("user_name")] public string UserName { get; set; }` |
| **关联文档** | [踩坑记录 2026-08-07](../30-项目规则/知识库/05-踩坑记录/2026-08-07_EF-Core-Column映射snake_case导致400错误.md) |

### E002：YZHBaseEntity 审计字段映射问题

| 项目 | 内容 |
|------|------|
| **现象** | CreateTime/UpdateTime/DeleteTime 未自动填充，或填充值错误 |
| **根因** | 实体未继承 BaseEntity，或属性名与 BaseEntity 中定义的不一致 |
| **修复** | 确保实体继承 `BaseEntity`，审计字段名称完全匹配 |
| **关联文档** | [踩坑记录 2026-08-12](../30-项目规则/知识库/05-踩坑记录/2026-08-07_YZHV2%20CrudTable%20导出空文件+排序+业务页简化.md) |

### E003：NOTracking 静默失效

| 项目 | 内容 |
|------|------|
| **现象** | 修改实体后调用 `Update()`，数据库无变化，无报错 |
| **根因** | 查询时使用了 NoTracking，实体未被追踪，Update 无法检测到变更 |
| **修复** | 查询时不使用 `.AsNoTracking()`，或使用 `GetByCode` 获取追踪实体后再修改 |
| **关联文档** | [踩坑记录 2026-08-13](../30-项目规则/知识库/05-踩坑记录/2026-08-13_NOTracking静默失效与文件夹重命名级联修复.md) |

### E004：关联表保存问题（T+V 模式）

| 项目 | 内容 |
|------|------|
| **现象** | 主表保存成功，关联表数据未写入 |
| **根因** | `OnAfterAdd` 钩子中未正确处理关联表事务 |
| **修复** | 在 `OnAfterAdd` 中使用独立的事务或确保关联表写入在同一事务中 |
| **关联文档** | [踩坑记录 2026-08-08](../30-项目规则/知识库/05-踩坑记录/2026-08-08_关联表保存问题与T+V模式修复.md) |

### E005：YZHV2 CrudTable 导出空文件

| 项目 | 内容 |
|------|------|
| **现象** | 点击导出按钮，下载的文件为空或格式错误 |
| **根因** | `ExportCore` 未实现，或导出的数据格式不正确 |
| **修复** | 实现 `ExportCore` 方法，确保返回有效 Excel 文件 |
| **关联文档** | [踩坑记录 2026-08-07](../30-项目规则/知识库/05-踩坑记录/2026-08-07_YZHV2%20CrudTable%20导出空文件+排序+业务页简化.md) |

### E006：软删除字段未用 `new` 重声明 → 软删除静默失效

| 项目 | 内容 |
|------|------|
| **现象** | 调用 `/delete` 返回"删除成功"，但列表仍能看到该行，数据库 `IsDeleted` 始终为 0 |
| **根因** | `BaseEntity` 把 `IsDeleted`/`DeleteTime`/`DeleteBy`/`CreateTime` 等标了 `[SugarColumn(IsIgnore = true)]`；子类不重声明则列**不被映射**。`SqlSugarDbOrm.IsDeletedCondition` 对 `IsIgnore` 属性直接返回 `_ => true`（跳过过滤），`SoftDelete()` 的 `UpdateColumns` 也写不进去 |
| **修复** | 子类用 `new` 重声明审计与软删除字段（不要带 `IsIgnore`），参考 `CertStage.cs` / `CertificationBody.cs` |
| **约束** | 见 [项目全局规则 §16.5](../../项目全局规则.md)（`new` 关键字规则） |
| **验证** | 删除后查库：`IsDeleted = 1` 且 `DeleteTime` 有值；列表不再返回该行 |

### E007：`GetByCodeAny` 报"表不存在"（`[SugarTable]` 未被识别）

| 项目 | 内容 |
|------|------|
| **现象** | `/toggle-valid` 等接口返回"记录不存在"；日志显示 `Table 'xxx.CertificationBody' doesn't exist` |
| **根因** | `EntityService.GetQueryTableName<T>()` 只读取 `[ViewName]` 与 EF 的 `[Table]`，**遗漏了 SqlSugar 的 `[SugarTable]`**，于是回退为类型名（如 `CertificationBody`）。该结果被用于 `GetByCodeAny` 的原生 SQL，导致表名错误 |
| **修复** | `GetQueryTableName` 优先级改为 `[ViewName]` → `[SugarTable]` → `[Table]` → 类型名（已修复） |
| **影响面** | 所有仅标 `[SugarTable]` 的实体（`CertificationBody`/`ISOStandard`/`ISOClause`/`CertStage`/`PhaseDefinition`/`SysConfig`/`AuditTask`/`AuditorProfile`/`Enterprise` 等） |
| **备注** | `/[controller]/filter` 走 SqlSugar `Queryable<T>(tableName)`，能容错；只有走原生 SQL 的路径（`GetByCodeAny`）会暴露 |

### E008：`GetListAsync` 缺 `includeDisabled` → 草稿（IsValid=0）永查不到

| 项目 | 内容 |
|------|------|
| **现象** | 上传确认/转换队列完成后，目录文件树/文件列表为空；DB 中文件夹仍 `IsValid=0` 且 `TaskId` 未清 |
| **根因** | `SqlSugarDbOrm.GetListAsync` 默认追加 `IsValid=1`（实现 `IIsValid` 的实体）。上传 init 创建文件夹/文件为草稿 `IsValid=0`；激活查询 `GetListAsync(x => x.TaskId == taskId)` 漏传 `includeDisabled: true`，永远返回空，激活循环空转 |
| **修复** | 按 `TaskId` 查草稿一律 `GetListAsync(..., includeDisabled: true)`；或原生 SQL / `GetOneIgnoreValidAsync` |
| **对照** | 同文件激活路径与 repair 重试路径已正确传 `includeDisabled: true`；`GetFoldersFlatAsync`/`GetFolderTreeAsync` 显示侧继续要求 `IsValid=1`（正确） |
| **存量数据** | `scripts/db/fix_draft_folder_activate_V1.sql`（JOIN 两表 `TaskId` collation 不同需显式 `COLLATE utf8mb4_0900_ai_ci`，否则 ERROR 1267） |
| **关联** | 历史同类：`docs/50-任务/项目文档管理-老项目对比与修复建议-V1.md` P1「全局过滤与上传流程冲突」 |
| **验证** | `GET .../configs/{code}/folders-flat` count>0；`GET .../stage-files/{code}` `Statistics.TotalFolders>0` |

## 二、前端错误

### E101：YzhTreeCheckboxTable 勾选回显与同步

| 项目 | 内容 |
|------|------|
| **现象** | 刷新页面后树节点勾选状态丢失，或勾选状态与后端数据不同步 |
| **根因** | 未正确维护树节点的 checked 状态，或未在加载后恢复勾选 |
| **修复** | 在 `loadTreeRoot` 后根据后端数据恢复 checked 状态 |
| **关联文档** | [踩坑记录 2026-08-08](../30-项目规则/知识库/05-踩坑记录/2026-08-08_YzhTreeCheckboxTable-勾选回显与同步.md) |

| 项目 | 内容 |
|------|------|
| **现象** | 访问页面返回 404，或菜单点击无响应 |
| **根因** | 未在 `router/index.ts` 中注册路由，或路由 path 与页面文件夹名不一致 |
| **修复** | 检查路由注册，确保 path 与 `pages/{domain}/{type}/` 一致 |
| **关联文档** | [踩坑记录 2026-08-09](../30-项目规则/知识库/05-踩坑记录/2026-08-09_前端路由配置完整指南.md) |

## 三、架构层错误

### E201：使用 Id 进行业务操作

| 项目 | 内容 |
|------|------|
| **现象** | 删除/修改操作误删其他记录 |
| **根因** | 使用了自增 Id 而非 Code 进行业务操作 |
| **修复** | **所有业务操作必须使用 Code**，禁止使用 Id |
| **约束** | 见 [01-架构总纲.md](./01-架构总纲.md) §2.1 |

### E202：前端硬编码表格列和表单字段

| 项目 | 内容 |
|------|------|
| **现象** | 修改字段需要改代码，无法通过配置调整 |
| **根因** | 在 Vue 模板中硬编码 `columns` 和 `formFields` |
| **修复** | 使用 `logic.columns` 和 `logic.formFields`，从后端配置获取 |
| **约束** | 见 [01-架构总纲.md](./01-架构总纲.md) §7.2 |

### E203：未使用 Split 增量更新

| 项目 | 内容 |
|------|------|
| **现象** | 删除/修改后表格全量刷新，用户体验差 |
| **根因** | 调用 `loadPage()` 而非 Split 方法 |
| **修复** | 删除用 `removeRowByCode(code)`，修改用 `replaceRowByCode(code, row)`，新增用 `insertRow(row)` |
| **约束** | 见 [01-架构总纲.md](./01-架构总纲.md) §7.2 |

## 四、快速排查流程

```
遇到错误
    │
    ▼
1. 查本表（E001~E203）→ 是否命中？
    │ 是 → 按修复方案处理
    │ 否 ↓
2. 查原始踩坑记录（docs/30-项目规则/知识库/05-踩坑记录/）
    │
    ▼
3. 检查三层同构
    ├─ Controller 继承是否正确？
    ├─ JSON 配置是否存在？
    ├─ 前端 API 路径是否正确？
    └─ 路由是否已注册？
    │
    ▼
4. 检查生命周期钩子
    ├─ OnBeforeAdd/Update/Delete 是否返回正确？
    ├─ OnQueried 是否翻译了字典？
    └─ OnBuildingFilter 是否正确注入过滤条件？
    │
    ▼
5. 检查数据契约
    ├─ 前端是否使用 PascalCase 访问字段？
    ├─ FilterRequest.Filters 格式是否正确？
    └─ TreeItemDto 是否包含所有必要字段？
```
