## 一、后端错误

### E001：EF Core / SqlSugar Column 映射 snake_case 导致 400 错误

| 项目 | 内容 |
|------|------|
| **现象** | 新增/修改请求返回 400，错误信息包含 "Column 'xxx' not found" |
| **根因** | 实体类属性名 PascalCase，但数据库列名 snake_case，未显式映射 |
| **修复** | 在属性上添加 `[SugarColumn("snake_case_column_name")]` |
| **示例** | `[SugarColumn("user_name")] public string UserName { get; set; }` |
| **关联文档** | [踩坑记录 2026-08-07](../60-AI工程设计/YZH-知识库/05-踩坑记录/2026-08-07_EF-Core-Column映射snake_case导致400错误.md) |

### E002：YZHBaseEntity 审计字段映射问题

| 项目 | 内容 |
|------|------|
| **现象** | CreateTime/UpdateTime/DeleteTime 未自动填充，或填充值错误 |
| **根因** | 实体未继承 BaseEntity，或属性名与 BaseEntity 中定义的不一致 |
| **修复** | 确保实体继承 `BaseEntity`，审计字段名称完全匹配 |
| **关联文档** | [踩坑记录 2026-08-12](../60-AI工程设计/YZH-知识库/05-踩坑记录/2026-08-12_YZHV2_CrudTable_导出空文件+排序+业务页简化.md) |

### E003：NOTracking 静默失效

| 项目 | 内容 |
|------|------|
| **现象** | 修改实体后调用 `Update()`，数据库无变化，无报错 |
| **根因** | 查询时使用了 NoTracking，实体未被追踪，Update 无法检测到变更 |
| **修复** | 查询时不使用 `.AsNoTracking()`，或使用 `GetByCode` 获取追踪实体后再修改 |
| **关联文档** | [踩坑记录 2026-08-13](../60-AI工程设计/YZH-知识库/05-踩坑记录/2026-08-13_NOTracking静默失效与文件夹重命名级联修复.md) |

### E004：关联表保存问题（T+V 模式）

| 项目 | 内容 |
|------|------|
| **现象** | 主表保存成功，关联表数据未写入 |
| **根因** | `OnAfterAdd` 钩子中未正确处理关联表事务 |
| **修复** | 在 `OnAfterAdd` 中使用独立的事务或确保关联表写入在同一事务中 |
| **关联文档** | [踩坑记录 2026-08-08](../60-AI工程设计/YZH-知识库/05-踩坑记录/2026-08-08_关联表保存问题与T+V模式修复.md) |

### E005：YZHV2 CrudTable 导出空文件

| 项目 | 内容 |
|------|------|
| **现象** | 点击导出按钮，下载的文件为空或格式错误 |
| **根因** | `ExportCore` 未实现，或导出的数据格式不正确 |
| **修复** | 实现 `ExportCore` 方法，确保返回有效 Excel 文件 |
| **关联文档** | [踩坑记录 2026-08-07](../60-AI工程设计/YZH-知识库/05-踩坑记录/2026-08-07_YZHV2_CrudTable_导出空文件+排序+业务页简化.md) |

## 二、前端错误

### E101：YzhTreeCheckboxTable 勾选回显与同步

| 项目 | 内容 |
|------|------|
| **现象** | 刷新页面后树节点勾选状态丢失，或勾选状态与后端数据不同步 |
| **根因** | 未正确维护树节点的 checked 状态，或未在加载后恢复勾选 |
| **修复** | 在 `loadTreeRoot` 后根据后端数据恢复 checked 状态 |
| **关联文档** | [踩坑记录 2026-08-08](../60-AI工程设计/YZH-知识库/05-踩坑记录/2026-08-08_YzhTreeCheckboxTable-勾选回显与同步.md) |

### E102：前端路由配置缺失

| 项目 | 内容 |
|------|------|
| **现象** | 访问页面返回 404，或菜单点击无响应 |
| **根因** | 未在 `router/index.ts` 中注册路由，或路由 path 与页面文件夹名不一致 |
| **修复** | 检查路由注册，确保 path 与 `pages/{domain}/{type}/` 一致 |
| **关联文档** | [踩坑记录 2026-08-09](../60-AI工程设计/YZH-知识库/05-踩坑记录/2026-08-09_前端路由配置完整指南.md) |

### E103：标准目录管理系统路由配置

| 项目 | 内容 |
|------|------|
| **现象** | 标准目录管理页面无法访问 |
| **根因** | 路由 path 与页面文件夹名不匹配，或缺少嵌套路由配置 |
| **修复** | 检查 `router/index.ts` 中的路径配置 |
| **关联文档** | [踩坑记录 2026-08-09](../60-AI工程设计/YZH-知识库/05-踩坑记录/2026-08-09_标准目录管理系统路由配置完整指南.md) |

## 三、架构层错误

### E201：使用 Id 进行业务操作

| 项目 | 内容 |
|------|------|
| **现象** | 删除/修改操作误删其他记录 |
| **根因** | 使用了自增 Id 而非 Code 进行业务操作 |
| **修复** | **所有业务操作必须使用 Code**，禁止使用 Id |
| **约束** | 见 [01-架构总纲.md](./01-架构总纲.md) §2.1 |

### E202：前端硬编码表格列和表单字段

| 项目 | 内容 |
|------|------|
| **现象** | 修改字段需要改代码，无法通过配置调整 |
| **根因** | 在 Vue 模板中硬编码 `columns` 和 `formFields` |
| **修复** | 使用 `logic.columns` 和 `logic.formFields`，从后端配置获取 |
| **约束** | 见 [01-架构总纲.md](./01-架构总纲.md) §7.2 |

### E203：未使用 Split 增量更新

| 项目 | 内容 |
|------|------|
| **现象** | 删除/修改后表格全量刷新，用户体验差 |
| **根因** | 调用 `loadPage()` 而非 Split 方法 |
| **修复** | 删除用 `removeRowByCode(code)`，修改用 `replaceRowByCode(code, row)`，新增用 `insertRow(row)` |
| **约束** | 见 [01-架构总纲.md](./01-架构总纲.md) §7.2 |

## 四、快速排查流程

```
遇到错误
    │
    ▼
1. 查本表（E001~E203）→ 是否命中？
    │ 是 → 按修复方案处理
    │ 否 ↓
2. 查原始踩坑记录（docs/60-AI工程设计/YZH-知识库/05-踩坑记录/）
    │
    ▼
3. 检查三层同构
    ├─ Controller 继承是否正确？
    ├─ JSON 配置是否存在？
    ├─ 前端 API 路径是否正确？
    └─ 路由是否已注册？
    │
    ▼
4. 检查生命周期钩子
    ├─ OnBeforeAdd/Update/Delete 是否返回正确？
    ├─ OnQueried 是否翻译了字典？
    └─ OnBuildingFilter 是否正确注入过滤条件？
    │
    ▼
5. 检查数据契约
    ├─ 前端是否使用 PascalCase 访问字段？
    ├─ FilterRequest.Filters 格式是否正确？
    └─ TreeItemDto 是否包含所有必要字段？
```
