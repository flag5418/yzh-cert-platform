## 二、命名三分法（★ 必须先分清）

> 这是全项目**最容易搞错**的一点。三种大小写规则并存，**各有各的原因**：

| 类别 | 命名 | 原因 | 例 |
|---|---|---|---|
| ① **API 信封顶层字段** | **camelCase** | 后端显式 `[JsonPropertyName("success")]` 输出 | `res.success` / `res.data` / `res.message` / `res.code` / `res.timestamp` |
| ② **业务实体 / 配置 / DTO** | **PascalCase** | 与 C# 属性名、DB 列名逐字一致（**铁律七**） | `row.UserName` / `col.FieldName` / `cfg.EnableField` / `node.Code` |
| ③ **字典 key**（`NewEntity` / `Schema`） | **camelCase** | 后端 `EntitySchemaHelper` 反射生成时显式 `ToCamelCase` | `{ code: "", userName: "", enable: 1 }` |
| ④ **FilterRequest / FilterItem** | **PascalCase** | 与 `YZH.Core.Stand/Request` 一致 | `req.Page` / `item.Field` / `item.Operator` |

**★ 判据**：
- 拿到的是 **HTTP 响应外层** → camelCase（`success`/`data`）
- 拿到的是 **`data` 里面**的业务对象 → PascalCase（`data.Items[0].UserName`）
- 拿到的是 **`NewEntity` / `Schema` 的 key** → camelCase（`formData.userName`）

**违反症状**：写 `res.Success` → 恒 `undefined` → **判成功永远失败**；写 `row.userName` → **渲染空行、零报错**。

## 四、与 WPF `YZH.Stand` 的命名分叉（★ 有意重构，须写明）

> 参考项目 `work/work/YZH架构/YZH.Stand/Models/DefineColumn.cs`（WPF 权威）vs 本项目 `YZH.Core.Stand/Models/Config/ColumnConfigDto.cs`（新架构）。

| 概念 | `YZH.Stand`（WPF） | `YZH.Core.Stand`（新） | 差异性质 |
|---|---|---|---|
| 显示标志 | `XSFlag` | `XsFlag` | **大小写** |
| 保存标志 | `BCFlag` | `BcFlag` | **大小写** |
| 允许为空 | `YXK` | `Yxk` | **大小写** |
| 默认值 | `MRZ` | `Mrz` | **大小写** |
| 顺序号 | `SXH` | ⛔ **无** | **能力未迁移** |
| 合计标志 | `SumFlag` | ⛔ **无** | **能力未迁移** |
| 选择配置 | `ChooseStr` | ⛔ **无** | **能力未迁移** |
| 查询操作符 | `OPERTYPE`（`OperType` 枚举） | 移到 `SearchFieldDto.Operator` | **位置迁移**（更合理） |
| 控件可用 | `EnableFlag` | `Enable` | **改名** |
| 掩码 | ⛔ 无 | `Mask` | **新增能力** |

**判定：不是 bug** —— 新架构是**有意重构**（`OPERTYPE` 移到搜索配置更合理，`Mask` 是新增能力）。

**★ 但必须遵守一条规则**：**本文是命名权威**。
未来 .NET 端（WPF / Avalonia）与 Vue 端互操作时，`XSFlag` ↔ `XsFlag` 这类差异会**静默不匹配** —— 正是铁律七要防的那类 bug。
→ **若将来做跨栈互操作，必须做一次显式映射层，不得依赖"看起来差不多"。**

## 七、契约变更流程（★ 改字段前必读）

```
① 改后端 DTO（YZH.Core.Stand/Models/…）        ← 唯一权威
② 同步改前端 types/*.ts                        ← 逐字段对照
③ 同步改 adapters/entityAdapters.ts            ← 若影响组件契约
④ 同步改本文 §三 对照表                        ← 保持文档与代码一致
⑤ 若有 JSON 配置 → 同步改 Assets/EntityConfigs/**
⑥ 跑 npm run typecheck:all + node scripts/guards.mjs
```

**★ 铁律**：**先改文档（本文），再改代码**。文档与代码不一致时，**以本文为准**；若本文错，先修本文。

**★ 自检命令**：
```bash

cat src/yzh-core/YZH.Core.Stand/Models/Config/ColumnConfigDto.cs

# 配置未加载（Title 等于类型名 ⇒ 没加载上）
```
