## 一、命名规范（铁律）

> **前后端一律使用 PascalCase，无 camelCase 转换。**
>
> 后端 C# 属性 `UserName` → JSON 输出 `UserName` → 前端 TypeScript `UserName`
>
> **禁止**在前端做任何字段名转换（不再需要 `toCamelCase` / `toSnakeCase`）。

| 层级 | 命名规则 | 示例 |
|------|---------|------|
| 后端 C# 属性 | PascalCase | `UserName`、`CreateTime` |
| JSON 字段 | PascalCase（与 C# 属性同名） | `UserName`、`CreateTime` |
| 前端 TypeScript 类型 | PascalCase（与 JSON 字段同名） | `UserName`、`CreateTime` |
| YzhTable column.prop | camelCase（Element Plus 约定） | `userName`、`createTime` |
| YzhForm field.prop | camelCase（Element Plus 约定） | `userName`、`createTime` |

> **注意**：YzhTable/YzhForm 的 `prop` 使用 camelCase 是 Element Plus 的约束，组件内部自动做 PascalCase ↔ camelCase 转换。业务逻辑层（Logic）直接使用 PascalCase 属性名。

## 三、过滤请求

```typescript
// 与后端 FilterRequest 一一对应
export interface FilterRequest {
    Page: number                          // 当前页（从 1 开始）
    PageSize: number                      // 每页条数
    SortField?: string                    // 排序字段（PascalCase）
    SortOrder?: 'asc' | 'desc'            // 排序方向
    Filters: FilterItem[]                 // 过滤条件
    ShowDisabled?: boolean                // 是否显示已禁用记录（可选，默认 false）
}

export interface FilterItem {
    Field: string                         // 字段名（PascalCase，与实体属性同名）
    Operator:
        | 'eq'        // 等于
        | 'neq'       // 不等于
        | 'gt'        // 大于
        | 'gte'       // 大于等于
        | 'lt'        // 小于
        | 'lte'       // 小于等于
        | 'like'      // 模糊匹配（自动添加 % 通配符）
        | 'in'        // 包含（Value 为逗号分隔字符串）
        | 'isnull'    // 为 null
        | 'isnotnull' // 不为 null
    Value?: any                             // 值
}
```

**前端构建过滤条件示例**：

```typescript
// 搜索框输入 "张三"  →  自动转换为 like 查询
const filters: FilterItem[] = [
    { Field: 'UserName', Operator: 'like', Value: '张三' },
    { Field: 'Enable', Operator: 'eq', Value: '1' }
]

const request: FilterRequest = {
    Page: 1,
    PageSize: 20,
    Filters: filters
}
```

## 五、EntityConfig — 页面配置（核心：后端驱动，前端自适应）

### 5.1 设计理念 — "后端驱动，前端自适应"

```
┌─────────────────────────────────────────────────────────────────────────┐
│  YzhControllerBase<V> 基类提供完整默认配置：                              │
│                                                                         │
│    1. Columns      ← JSON 文件（静态结构，管理员可编辑）                    │
│    2. SearchFields ← 基类智能推断（选前 3 个 XsFlag=true 字段）            │
│    3. RowButtons   ← 基类默认（Edit=true, Delete=true）                  │
│    4. Toolbar      ← 基类默认（Add=true, Delete=true）                   │
│    5. NewEntity    ← 后端反射生成（EntitySchemaHelper）                   │
│    6. Schema       ← 后端反射生成（字段类型描述）                           │
│                                                                         │
│  继承类只需 override 需要定制的部分：                                      │
│    - GetSearchFields()  ← 完全自定义搜索字段（如添加下拉选择）              │
│    - GetRowButtons()    ← 自定义行按钮（如隐藏删除、添加审核按钮）           │
│    - GetToolbar()       ← 自定义工具栏（如开启导出导入）                    │
│                                                                         │
│  前端读取 EntityConfigDto → 自动渲染表格、表单、搜索栏、按钮，零手写 UI     │
└─────────────────────────────────────────────────────────────────────────┘
```

**配置优先级**（从高到低）：
1. 子类 override 虚方法（代码控制）
2. 基类默认推断（智能规则）
3. JSON 文件静态配置（仅 Columns 必须）

### 5.2 EntityConfigDto 根结构

```typescript
export interface EntityConfigDto {
    // ── 静态配置（来源：JSON 文件） ──
    Title: string                              // 页面标题
    FillMode?: 'AutoFix' | 'PixFix'            // 列填充模式
    FormCols?: number                          // 表单列数（0=自动）
    Columns: ColumnConfig[]                    // 列/字段定义（核心配置）

    // ── 运行时注入（来源：后端反射） ──
    NewEntity?: Record<string, any>            // 空实体模板（前端初始化表单用）
    Schema?: Record<string, EntityFieldSchema> // 字段结构描述（校验/控件推断）

    // ── 运行时注入（来源：基类默认或子类覆盖） ──
    SearchFields?: SearchFieldDto[]            // 搜索字段配置
    Toolbar?: ToolbarConfigDto                 // 工具栏配置
    RowButtons?: RowButtonConfigDto            // 行按钮配置
    EnableField?: string                       // 启用/禁用字段名（默认 IsValid）

    // ── 兼容字段（历史遗留，新代码不使用） ──
    ConfigName?: string
    TableName?: string
}

// 行按钮配置
export interface RowButtonConfigDto {
    Edit?: boolean                          // 是否显示编辑按钮（默认 true）
    Delete?: boolean                        // 是否显示删除按钮（默认 true）
    CustomButtons?: Record<string, string>  // 自定义按钮：{ 方法名: 显示文字 }
}

// 工具栏配置
export interface ToolbarConfigDto {
    Add?: boolean                           // 显示新增按钮（默认 true）
    Delete?: boolean                        // 显示删除按钮（默认 true）
    Export?: boolean                        // 显示导出按钮（默认 false）
    Import?: boolean                        // 显示导入按钮（默认 false）
    CustomButtons?: Record<string, string>  // 自定义工具栏按钮
}

// 搜索字段配置
export interface SearchFieldDto {
    Label: string                           // 显示标签
    Field: string                           // 字段名（PascalCase）
    Operator: string                        // 查询操作符（like/eq/gt/lt/in）
    ControlType: string                     // 控件类型（input/select/date）
    Options?: SelectOptionDto[]             // 下拉选项（ControlType=select 时）
    Width?: number                          // 宽度（px）
}

// 字段结构描述
export interface EntityFieldSchema {
    Type: string        // string / number / boolean / datetime
    Default?: any       // 默认值
    Optional: boolean   // 是否可选
}
```

### 5.3 后端配置注入流程（YzhControllerBase.GetConfigCore）

```csharp
// YzhControllerBase<V>.GetConfigCore() 执行顺序：

// 1. 反射实体生成空实体模板
Config.NewEntity = EntitySchemaHelper.GetEmptyEntity<V>();

// 2. 反射实体生成字段结构描述
Config.Schema = EntitySchemaHelper.GetSchema<V>();

// 3. 注入搜索字段（调用虚方法，子类可覆盖）
Config.SearchFields = GetSearchFields();
//   默认行为：从 Columns 选前 3 个 XsFlag=true 且非 Other 的字段
//   - TextBox/Memo → like（模糊搜索）
//   - ComboBox/Cascader → select（下拉选择）
//   - DatePicker/DateTimePicker → date

// 4. 注入行按钮（调用虚方法，子类可覆盖）
Config.RowButtons = GetRowButtons();
//   默认：Edit=true, Delete=true

// 5. 注入工具栏（调用虚方法，子类可覆盖）
Config.Toolbar = GetToolbar();
//   默认：Add=true, Delete=true, Export=false, Import=false

// 6. 最后钩子（子类可覆盖以上所有配置）
OnConfigLoading(Config);
```

### 5.4 子类覆盖示例

```csharp
// 示例：自定义搜索字段

{
    return new RowButtonConfig
    {
        Edit = true,

{

    {
        Add = true, Delete = true, Export = true, Import = true
    };
}
```

### 5.5 JSON 文件职责边界

> **JSON 文件只负责静态结构配置**（Columns），行为配置由代码控制。

| 配置项 | JSON 文件 | 代码控制 | 说明 |
|--------|----------|---------|------|
| Columns | ✅ 唯一数据源 | ❌ 不参与 | 列定义**必须且只能**由 JSON 声明 |
| SearchFields | ❌ 不声明 | ✅ GetSearchFields() | 基类默认推断（前3个XsFlag=true字段），子类可覆盖 |
| RowButtons | ❌ 不声明 | ✅ GetRowButtons() + RegisterRowAction() | Edit/Delete/Enable 由虚方法控制；CustomButtons 由 RegisterRowAction 自动注入 |
| Toolbar | ❌ 不声明 | ✅ GetToolbar() | Add/Delete/Export/Import 由虚方法控制 |
| NewEntity | ❌ 不声明 | ✅ EntitySchemaHelper 反射生成 | 后端自动生成 |
| Schema | ❌ 不声明 | ✅ EntitySchemaHelper 反射生成 | 后端自动生成 |

> **⚠️ 强制规则**：JSON 文件中声明 `SearchFields`/`RowButtons`/`Toolbar`**不会生效**，
> 因为 `GetConfigCore()` 会用虚方法返回值覆盖它们。
> 如果发现 JSON 中有这些字段，说明是文档残留，应清理。

**配置来源总结**：
```
JSON 文件提供 → Columns（表格列定义）+ EnableField（启用字段名）+ Title/FillMode（页面设置）
Controller 提供 → RowButtons.Edit/Delete/Enable + Toolbar + SearchFields + CustomButtons（自动注入）
```

### 6.2 自动注入机制

> `CustomActions` 由后端 `TreeTableControllerBase.InjectTreeActionsToConfig()` 自动填充。

**流程**：
1. 开发者在 Controller 构造函数中 `RegisterTreeAction("disable", handler)` 注册操作
2. 后端 `GetConfig()` 被调用时，自动遍历 `_treeActions` 字典
3. 注入到 `TreeConfig.CustomActions`：`{ "disable": "禁用", "enable": "启用" }`
4. 前端读取 `config.treeConfig.customActions` 渲染节点操作按钮
5. 用户点击按钮 → 调用 `POST /tree/action/{methodName}`

**内置按钮映射**：
- `disable` → "禁用"
- `enable` → "启用"
- 其他自定义名称 → 直接使用原始名称

## 八、视图字段支持（重要）

### 8.1 设计原则

> **一个实体类可同时映射物理表和视图**：查询走视图，增删改走表。

```csharp
// 示例：Sys_User 实体映射到 v_sys_user 视图
[ViewName("v_sys_user")]  // ← 指定查询视图名
public class Sys_User : BaseEntity
{
    // ===== 物理表字段（持久化） =====
    public string Code { get; set; } = "";
    public string UserName { get; set; } = "";
    public string UserPwd { get; set; } = "";
    public int RoleId { get; set; }
    public string OrgCode { get; set; } = "";
    
    // ===== 视图字段（不持久化，查询后填充） =====
    [NotMapped]
    public string? RoleName { get; set; }
    [NotMapped]
    public string? OrgName { get; set; }
    [NotMapped]
    public string? EnableDesc { get; set; }
}
```

**关键特性**：
| 特性 | 说明 |
|------|------|
| `[ViewName("v_xxx")]` | 指定查询时使用的视图名，不指定则使用实体名 |
| `[NotMapped]` | 标记视图字段，不写入数据库，仅用于展示 |
| **查询** | 自动路由到视图（`FROM v_sys_user`） |
| **增删改** | 始终操作物理表（`INSERT/UPDATE/DELETE INTO sys_user`） |
| **配置驱动** | EntityConfig JSON 控制哪些字段显示、如何显示 |

### 8.2 GroupIndex 分组索引（重要）

> **设计目的**：通过 `GroupIndex` 控制表单字段在不同编辑模式下的可编辑性。

**前端实现**（`SingleTableCore.ts`）：

```typescript
// formFields 计算属性中的核心逻辑
const editMode = this.formGroupIndex.value  // 当前编辑模式
const fieldGroupIndex = c.GroupIndex || '0'
const isDisabledByGroupIndex = editMode !== '0' && fieldGroupIndex !== editMode
// disabled: !c.Enable || isDisabledByGroupIndex
```

**模式与 GroupIndex 关系**：

| formGroupIndex | 含义 | 可编辑字段 |
|----------------|------|------------|
| `'0'` | 新增模式 | 全部字段可编辑（GroupIndex 不起作用） |
| `'1'` | 编辑模式 | 仅 `GroupIndex='1'` 的字段可编辑 |
| `'99'` | 查看/详情模式 | 仅 `GroupIndex='99'` 的字段可编辑（通常为审计字段） |

**字段控制规则**：
- `GroupIndex='0'`：默认字段，在编辑模式下可编辑
- `GroupIndex='1'`：业务字段，需要切换到编辑模式才可编辑
- `GroupIndex='99'`：审计字段（CreateTime 等），在详情模式下才可编辑
- `GroupIndex` 未设置时默认视为 `'0'`

**示例**：
```json
{
  "Columns": [
    { "FieldName": "Id", "DesName": "ID", "GroupIndex": "0", "Type": "Other", "BcFlag": true },
    { "FieldName": "Code", "DesName": "编码", "GroupIndex": "0", "Type": "Other", "BcFlag": true },
    { "FieldName": "StandardCode", "DesName": "标准编号", "GroupIndex": "1", "BcFlag": true },
    { "FieldName": "StandardName", "DesName": "标准名称", "GroupIndex": "1", "BcFlag": true },
    { "FieldName": "CreateTime", "DesName": "创建时间", "GroupIndex": "99", "BcFlag": false }
  ]
}
```

**页面行为**：
- **新增**：`openAddDialog()` 设置 `formGroupIndex='0'` → 全部字段可编辑
- **编辑**：`openEditDialog()` 设置 `formGroupIndex='1'` → 仅 GroupIndex='1' 字段可编辑
- **查看**：`openDetailDialog()` 设置 `formGroupIndex='99'` → 所有字段只读

**关键方法**：
```typescript
// SingleTableCore.ts
openAddDialog() {
    this.formGroupIndex.value = '0'  // 全部可编辑
}
openEditDialog(row: V) {
    this.formGroupIndex.value = '1'  // 仅 GroupIndex=1 可编辑
}
openDetailDialog(row: V) {
    this.formGroupIndex.value = '99' // 全部只读
}
openDialogWithMode(row: V | null, groupIndex: string) {
    // 自定义模式，用于特殊场景
    this.formGroupIndex.value = groupIndex
}
```

### 8.3 Other 类型字段处理规则

| 场景 | BCFlag | 效果 |
|------|--------|------|
| 表格显示，表单不显示 | `false` | 列表中显示，编辑时隐藏 |
| 表格显示，表单只读显示 | `true` | 列表中显示，编辑时显示为只读文本 |
| 完全不显示 | `false` + `XSFlag=false` | 列表和表单都不显示 |

**保存控制**：
```
BCFlag=true 且 Type!=Other → 字段参与保存
BCFlag=false 或 Type=Other → 字段不参与保存
```

## 十一、JSON 配置文件生成规范（V1）

> **⚠️ 强制规范**：创建新的 EntityConfig JSON 文件时，**只允许声明以下字段**：
> `Title`、`FillMode`、`FormCols`、`EnableField`、`Columns`
>
> **禁止声明**：`SearchFields`、`RowButtons`、`Toolbar`、`NewEntity`、`Schema`
> 这些字段由后端运行时自动注入，JSON 中声明无效且会造成混淆。

### 11.1 JSON 文件标准模板

```json
{
  "Title": "页面标题",
  "FillMode": "AutoFix",
  "FormCols": 0,
  "EnableField": "IsValid",
  "Columns": [
    {
      "FieldName": "字段名",
      "DesName": "显示名称",
      "Type": "TextBox",
      "Sxh": 1,
      "XsFlag": true,
      "BcFlag": true,
      "Yxk": false,
      "Width": 150,
      "Row": 0,
      "Col": 0,
      "RowSpan": 1,
      "ColSpan": 1,
      "GroupIndex": "0",
      "Mrz": "",
      "Enable": true
    }
  ]
}
```

### 11.2 JSON 允许的根级字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `Title` | string | ✅ | 页面标题 |
| `FillMode` | string | ❌ | `AutoFix`（默认）或 `PixFix` |
| `FormCols` | number | ❌ | 表单列数（0=自动，1=单列，2=双列） |
| `EnableField` | string | ❌ | 启用/禁用字段名（默认 `IsValid`） |
| `Columns` | array | ✅ | 列/字段定义集合 |

### 11.3 JSON 禁止声明的字段（运行时注入）

| 字段 | 禁止原因 | 正确做法 |
|------|---------|---------|
| `SearchFields` | 基类智能推断 + 子类 override `GetSearchFields()` | 在 Controller 中 override |
| `RowButtons` | 基类默认 + 子类 override `GetRowButtons()` | 在 Controller 中 override |
| `Toolbar` | 基类默认 + 子类 override `GetToolbar()` | 在 Controller 中 override |
| `NewEntity` | 后端反射自动生成 | 不可配置 |
| `Schema` | 后端反射自动生成 | 不可配置 |

### 11.4 创建新页面的 JSON 生成步骤

```
步骤 1：确定实体类 V 的类型名（如 "CertificationBody"）
步骤 2：在对应模块的 Assets/EntityConfigs/{Domain}/ 目录下创建 {V}.json
步骤 3：写入根级字段（Title、FillMode、Columns）
步骤 4：定义 Columns 数组（每个字段的 FieldName、DesName、Type、XsFlag、BcFlag、Yxk）
步骤 5：不要添加 SearchFields/RowButtons/Toolbar！
步骤 6：如需自定义搜索/按钮行为，在 Controller 子类中 override 虚方法
```

### 11.5 常见错误示例

| 错误 | 说明 |
|------|------|
| ❌ JSON 中声明 SearchFields | 无效，会被 `GetSearchFields()` 覆盖 |
| ❌ JSON 中声明 RowButtons | 无效，会被 `GetRowButtons()` 覆盖 |
| ❌ JSON 中声明 Toolbar | 无效，会被 `GetToolbar()` 覆盖 |
| ❌ JSON 中声明 NewEntity | 无效，会被反射生成覆盖 |
| ✅ 只在 JSON 中声明 Columns | 正确 |
| ✅ 自定义搜索在 Controller 中 override | 正确 |
