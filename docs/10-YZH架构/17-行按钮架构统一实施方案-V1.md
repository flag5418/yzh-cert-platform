# 行按钮架构统一实施方案-V3

## 一、核心设计原则

| 原则 | 说明 |
|------|------|
| **文件合并** | `ToolbarConfig.cs` 和 `ToolbarConfigDto.cs` 合并为单一文件 `ToolbarConfig.cs` |
| **消除 DTO 变体** | 删除 `ToolbarConfigDto` / `RowButtonConfigDto`，前后端共用同一个 class |
| **RowButtons 永不为 null** | `EntityConfig.RowButtons` 默认 `new RowButtonConfig()`，JSON 不写也有默认值 |
| **默认值合理** | 编辑=有、删除=有、禁用=无（需显式开启），继承类按需 override |
| **后端 Controller 零冗余** | 基类 `ToggleIsValid` 已完整实现，禁止各 Controller 重写 |
| **前端状态二选一** | 行按钮按行状态二选一（启用行只显橙「禁用」、停用行只显绿「启用」），⛔ 禁止合并文案「禁用/启用」；确认弹窗文案动态显示 |
| **状态列配置驱动** | EnableField 列自动 `slot: true`，但**页面必须提供 `#column-字段名` 插槽**，否则 YzhTable 兜底渲染原值 1/0 |

## 五、前端动态标签与状态显示约定

> ★ 本节 2026-09-26 纠偏：原约定「行按钮固定显示"禁用/启用"」**已作废** ——
> 合并文案让用户看不出当前行是启用还是停用，且同一行永远出现同一个按钮。

- **行按钮**：按行状态**二选一**
  - 启用行（`IsValid=1` / `IsActive=true`）→ 只显 **warning 橙「禁用」**
  - 停用行（`IsValid=0` / `IsActive=false`）→ 只显 **success 绿「启用」**
  - 实现：`entityAdapters.ts` 的 `toRowActions` / `toTreeActions` 返回**函数**，
    `YzhTable.vue` / `YzhTreeTable.vue` 逐行求值；状态判据 `isRowEnabled`（int 0/1 与 bool 通吃）
  - 状态型 CustomButtons 键名**只认 `disable` / `enable`**（走 `POST /action/{method}`）；
    `RowButtons.Enable:true` 走 `toggle-valid`，两条路均被 adapter 收敛为二选一
- **确认弹窗**：动态显示"确认禁用"/"确认启用"（`toggleRowIsValidWithConfirm` /
  `toggleTreeNodeWithConfirm`，已按 `isRowEnabled` 判态）
- **状态列**：`#column-IsValid`（或 `#column-IsActive`）`<el-tag>` 绿「启用」/ 灰「禁用」
  - ⚠️ 内核只负责把 EnableField 列标成 `slot: true`，**页面不给插槽就渲原值 1/0**
- **禁用后必须可找回**：后端列表默认过滤 `IsValid=1` → 页面要配「显示已禁用」开关
  （`logic.showDisabled` + `#toolbar-right` + `YzhTable` 注入 `ShowDisabled=true`）
  - 左树（`GetViewList` 默认 `includeDisabled=true`）禁用节点仍可见，树上可直接启停
  - 例外：实体无 `IsValid` 字段（如 `ValidationRule` 用 bool `IsActive`）→ 后端不过滤，无需开关

→ CrudPageLogic.rowButtons → YzhTable → getRowActionType
