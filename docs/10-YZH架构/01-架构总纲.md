## 一、架构核心思想

### 1.1 设计哲学：五原则

```
┌─────────────────────────────────────────────────────────────────────┐
│                        YZH 架构五原则                                 │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  1. 配置驱动 UI    → 前端不硬编码，所有行为由后端 JSON 配置决定        │
│  2. 统一基类       → 单表/左树右表均继承统一控制器基类                 │
│  3. API 固定       → 方法名、请求/响应格式全局统一                    │
│  4. 业务差异隔离   → 差异只通过配置和 virtual 覆盖实现                 │
│  5. 增量更新       → 前端 Split 数据方法，不重新请求                  │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 1.2 前后端继承体系

```
后端继承体系：
┌──────────────────────────────────────────────────────────────┐
│   ControllerBase (ASP.NET Core)                              │
│       │                                                      │
│       ▼                                                      │
│   YzhControllerBase<V>        ← 单表 CRUD                    │
│       │  /config /filter /add /update /delete                 │
│       │  /export /import /action/{name}                      │
│       │  钩子：OnBeforeAdd / OnAfterUpdate / OnBeforeDelete  │
│       │                                                      │
│       ▼                                                      │
│   TreeTableControllerBase<T,V>  ← 左树右表                    │
│       │  继承单表全部能力                                      │
│       │  新增：/tree/root /tree/children /tree/add /tree/*    │
│       │  钩子：OnBeforeAddTree / OnBeforeDeleteTree          │
│       └── 必须配置：TreeConfig.NameField / CodeField         │
│               / ParentCodeField / RelateField                │
└──────────────────────────────────────────────────────────────┘

前端继承体系：
┌──────────────────────────────────────────────────────────────┐
│   CrudPageLogic<V>            ← 单表 Logic 基类              │
│       │  columns / formFields / searchFields / toolbarButtons │
│       │  loadPage() / add() / update() / delete()            │
│       │  Split 方法：insertRow / replaceRowByCode / removeRow │
│       │                                                      │
│       ▼                                                      │
│   TreeTableLogic<V>           ← 左树右表 Logic 基类           │
│       │  继承单表全部能力                                      │
│       │  新增：treeData / selectedNode / treeTableConfig     │
│       │       loadTreeRoot() / loadChildren()               │
│       │       onNodeClick() / loadPageWithTree()            │
│       │       addTreeNode() / updateTreeNode() / deleteTreeNode()
│       └── 必须覆盖：controllerName = 'XxxController'         │
└──────────────────────────────────────────────────────────────┘
```

## 二、YZH.Core 本地源码结构（AI 必读）

> **重要提示**：`YZH.Core` 是外部依赖，但在本地以完整源码形式存在（非 NuGet 包引用）。AI 在生成代码时容易混淆以下两个目录的关系：
> - `src/yzh-core/` — **YZH.Core 本地源码**（架构层，4 个子项目）
> - `src/certplatform-api/` — **业务项目**（调用 YZH.Core，3 个角色子模块）
>
> 两者**不是包含关系**，而是**引用关系**：certplatform-api 引用 yzh-core 编译出的 .dll。

### 2.1 YZH.Core 本地源码结构

```
src/yzh-core/                          ← YZH.Core 本地源码（框架层）
├── YZH.Core.Stand/                    基座：BaseEntity、EntityConfig、ITreeNode、ApiResponse
├── YZH.Core.DataBase/                 数据访问：EF Core 封装、IRepository、BaseRepository
├── YZH.Core.Api/                      Web 核心：YzhControllerBase、TreeTableControllerBase、EntityService
└── YZH.Core.Web/                      启动宿主：Program.cs + YzhWebBuilder（含基础业务示例）
    ├── Controllers/                   示例控制器：System/UserController、System/OrganizationController
    └── Assets/EntityConfigs/          示例配置：System/User.json、System/Organization.json
```

**关键理解**：
- `YZH.Core.Web` 是**通用系统层的宿主启动器**，演示如何使用 YZH.Core，但**不是业务项目的主入口**
- `YZH.Core.Api` 包含的核心类（`YzhControllerBase`、`TreeTableControllerBase`、`EntityService`）是业务项目继承的基类
- 编译后输出 `CertPlatform.*.dll`，业务项目通过项目引用（Project Reference）使用

### 2.2 业务项目结构（certplatform-api）

```
src/certplatform-api/                  ← 业务项目（调用 YZH.Core）
├── Cert.Platform.sln                  解决方案文件
├── CertPlatform.Shared/               共享层：实体、DTO、通用工具
├── CertPlatform.Admin/                管理员端子模块（端口 9990）
│   ├── Controllers/                   继承 YzhControllerBase / TreeTableControllerBase
│   ├── Services/                      业务服务（钩子实现）
│   └── EntityConfigs/                 管理员端 JSON 配置
├── CertPlatform.Auditor/              审核员端子模块（端口 9991）
│   ├── Controllers/
│   ├── Services/
│   └── EntityConfigs/
└── CertPlatform.Enterprise/           企业端子模块
    ├── Controllers/
    ├── Services/
    └── EntityConfigs/
```

### 2.3 启动入口关系

```
业务主入口：src/certplatform-api/Cert.Platform.sln
    └── Program.cs 中调用：
        builder.UseYzhCore(options => { ... })
        app.UseYzhPipeline()
    
YZH.Core.Web：src/yzh-core/YZH.Core.Web/
```

## 三、核心概念

### 2.0 视图结构支持（重要）

> **设计原则**：一个实体类可同时映射物理表和视图，查询走视图，增删改走表。

```csharp
// 示例：Sys_User 实体映射到 v_sys_user 视图
[ViewName("v_sys_user")]  // ← 指定查询视图名
public class Sys_User : BaseEntity
{
    // ===== 物理表字段（持久化） =====
    public string Code { get; set; } = "";
    public string UserName { get; set; } = "";
    public string UserPwd { get; set; } = "";
    public int RoleId { get; set; }
    public string OrgCode { get; set; } = "";
    
    // ===== 视图字段（不持久化，查询后填充） =====
    [NotMapped]
    public string? RoleName { get; set; }
    [NotMapped]
    public string? OrgName { get; set; }
    [NotMapped]
    public string? EnableDesc { get; set; }
}
```

**关键特性**：
| 特性 | 说明 |
|------|------|
| `[ViewName("v_xxx")]` | 指定查询时使用的视图名，不指定则使用实体名 |
| `[NotMapped]` | 标记视图字段，不写入数据库，仅用于展示 |
| **查询** | 自动路由到视图（`FROM v_sys_user`） |
| **增删改** | 始终操作物理表（`INSERT/UPDATE/DELETE INTO sys_user`） |
| **配置驱动** | EntityConfig JSON 控制哪些字段显示、如何显示 |

---

### 2.1 Code 作为业务主键（铁律）

> **所有业务操作统一使用 `Code`（Guid 字符串）作为业务唯一标识。**

| 字段 | 用途 | 说明 |
|------|------|------|
| `Id` | 自增主键 | 仅标识插入顺序，**不参与任何业务逻辑** |
| `Code` | 业务唯一标识 | 用于所有关联、引用、查询、更新、删除 |

```csharp
// ❌ 错误：使用 Id 进行业务操作
public async Task<ActionResult> Delete(int id) { ... }

// ✅ 正确：使用 Code 进行业务操作
public async Task<ActionResult> Delete(string[] codes) { ... }
```

后端实体基类 `BaseEntity` 已提供：
- `Id`（自动赋值 Guid）
- `Code`（新增时自动生成或手动设置）
- 审计字段：`CreateTime / CreateBy / UpdateTime / UpdateBy / DeleteTime / DeleteBy`

### 2.2 EntityConfig 配置驱动 UI

一份 JSON 配置同时驱动**表格列**和**表单字段**：

| 属性 | 表格 | 表单 | 说明 |
|------|------|------|------|
| `SXH` | 列排序号 ☑️ | - | 升序排列 |
| `XSFlag` | 显示 ☑️ | - | 控制列可见性 |
| `BCFlag` | - | 显示/编辑 ☑️ | 控制表单字段可见性 |
| `Type` | 列类型 | 控件类型 | `Other`=只读展示 |
| `Row/Col/ColSpan` | - | Grid 布局位置 | CSS Grid 表单布局 |
| `YXK` | - | 允许空 ☑️ | 必填校验依据 |
| `MRZ` | - | 默认值 | 新增时的预填充 |

**实体属性名 = JSON 字段名 = 数据库列名**，全部 PascalCase，无转换。

### 2.3 字段控制语义

```
XSFlag=true  → 表格中显示此列
BCFlag=true  → 表单中显示且可编辑（false=隐藏或只读展示）
Type=Other   → 纯展示字段，不在表单中渲染为可编辑控件
YXK=false    → 不允许空，表单必填校验
MRZ="1"      → 默认值，新增表单时的预填充值
```

### 2.4 EntityConfig 配置视图字段

> **重要设计**：EntityConfig JSON 不仅控制 UI 显示，还控制**哪些字段需要保存**。

```json
{
  "Title": "用户管理",
  "Columns": [
    {
      "FieldName": "Code",
      "DesName": "用户编码",
      "Type": "TextBox",
      "XSFlag": true,
      "BCFlag": true,
      "YXK": true,
      "Sxh": 1
    },
    {
      "FieldName": "UserName",
      "DesName": "用户名",
      "Type": "TextBox",
      "XSFlag": true,
      "BCFlag": true,
      "YXK": true,
      "Sxh": 2
    },
    {
      "FieldName": "RoleName",
      "DesName": "角色",
      "Type": "Other",
      "XSFlag": true,
      "BCFlag": false,
      "YXK": false,
      "Sxh": 3
    },
    {
      "FieldName": "OrgName",
      "DesName": "机构",
      "Type": "Other",
      "XSFlag": true,
      "BCFlag": false,
      "YXK": false,
      "Sxh": 4
    }
  ]
}
```

**Type=Other 字段处理规则**：
| 属性 | 行为 |
|------|------|
| `Type=Other` + `BCFlag=false` | 表格中显示，表单中不显示，不保存 |
| `Type=Other` + `BCFlag=true` | 表格中显示，表单中显示为只读，不保存 |
| `Type=Other` + `BCFlag=false` + `XSFlag=false` | 完全不显示 |

**保存控制**：
- `BCFlag=true` 且 `Type!=Other` → 字段参与保存
- `BCFlag=false` 或 `Type=Other` → 字段不参与保存

### 2.5 GroupIndex 分组索引（表单编辑权限控制）

> **设计目的**：通过 `GroupIndex` 控制表单字段在不同模式下的可编辑性。

**使用场景**：
| 场景 | GroupIndex 值 | 效果 |
|------|---------------|------|
| 新增模式 | `0`（默认） | 所有字段可编辑 |
| 编辑模式 | `0` 或 `1` | 根据配置控制 |
| 查看模式 | `99` | 所有字段只读 |

**字段控制规则**：
| GroupIndex | 新增 | 编辑 | 查看 |
|------------|------|------|------|
| `0`（默认） | 可编辑 | 可编辑 | 只读 |
| `1` | 可编辑 | 可编辑 | 只读 |
| `2` | 可编辑 | 只读 | 只读 |
| `99` | 可编辑 | 只读 | 只读 |

**示例**：
```json
{
  "Columns": [
    { "FieldName": "UserName", "DesName": "用户名", "GroupIndex": "0", "BcFlag": true },
    { "FieldName": "RoleId", "DesName": "角色", "GroupIndex": "0", "BcFlag": true },
    { "FieldName": "RoleName", "DesName": "角色名称", "GroupIndex": "1", "BcFlag": true },
    { "FieldName": "CreateTime", "DesName": "创建时间", "GroupIndex": "99", "BcFlag": false }
  ]
}
```

**前端处理**：
- 新增/编辑时，传入 `groupIndex=0` → 显示 `GroupIndex<=0` 的字段
- 查看时，传入 `groupIndex=99` → 所有字段只读

## 四、统一 API 端点

### 3.1 单表 CRUD API（YzhControllerBase<V>）

| API | 方法 | 请求体 | 响应 | 说明 |
|---|---|---|---|---|
| `/config` | GET | - | `ApiResponse<EntityConfigDto>` | 获取页面配置 |
| `/filter` | POST | `FilterRequest` | `ApiResponse<PagedResult<V>>` | 过滤查询（推荐） |
| `/add` | POST | V entity | `ApiResponse<V>` | 新增 |
| `/update` | POST | V entity | `ApiResponse<V>` | 修改 |
| `/delete` | POST | `string[] codes` | `ApiResponse<object>` | 批量删除 |
| `/action/{methodName}` | POST | V entity | `ApiResponse<object?>` | 自定义行操作 |
| `/export` | POST | `ExportRequest` | `FileStreamResult` | 导出（完整表结构） |
| `/import` | POST | `IFormFile` | `ApiResponse<ImportResult>` | 批量导入 |
| `/import/template` | GET | - | `FileStreamResult` | 下载导入模板 |

### 3.2 左树右表 API（TreeTableControllerBase<T,V> 新增）

| API | 方法 | 请求体 | 响应 | 说明 |
|---|---|---|---|---|
| `/config` | GET | - | `ApiResponse<TreeTableConfigDto>` | 覆盖，返回完整树+表配置 |
| `/filter` | POST | `FilterRequest` | `ApiResponse<PagedResult<V>>` | 自动注入树过滤 |
| `/tree/root` | POST | - | `ApiResponse<TreeItemDto[]>` | 加载根节点 |
| `/tree/children` | POST | `{ParentCode, Level}` | `ApiResponse<TreeItemDto[]>` | 懒加载子节点 |
| `/tree/add` | POST | T entity | `ApiResponse<TreeItemDto>` | 新增树节点 |
| `/tree/update` | POST | T entity | `ApiResponse<TreeItemDto>` | 修改树节点 |
| `/tree/delete` | POST | `string[]` | `ApiResponse<string>` | 删除树节点（含子节点） |
| `/tree/action/{methodName}` | POST | T entity | `ApiResponse<object?>` | 树节点自定义操作 |

> `/filter` 与 `/page` 功能重叠，**优先使用 `/filter`**，逐步废弃 `/page`。

## 五、生命周期钩子速查

### 4.1 单表钩子（YzhControllerBase<V>）

| 钩子 | 触发时机 | 可取消？ | 典型用途 |
|------|---------|---------|---------|
| `OnBeforeAdd(V entity)` | 新增前 | ✅ | 唯一性校验、密码加密、默认值填充 |
| `OnAfterAdd(V entity)` | 新增后（事务内） | ❌ | 写关联表、发送通知 |
| `OnBeforeUpdate(V entity)` | 修改前 | ✅ | 状态检查、并发校验 |
| `OnAfterUpdate(V entity)` | 修改后（事务内） | ❌ | 写操作日志 |
| `OnBeforeDelete(string[] codes)` | 删除前 | ✅ | 关联数据检查、级联判断 |
| `OnAfterDelete(int count)` | 删除后 | ❌ | 清理缓存 |
| `OnAfterCommitted()` | 所有写入后（事务外） | ❌ | 发送外部通知、清理缓存 |
| `OnQueried(PagedResult<V> result)` | 查询后 | ❌ | 字典翻译、手机号脱敏 |
| `OnBuildingFilter(List<FilterItem> filters)` | 查询前 | ❌ | 注入全局过滤条件（租户、ShowDisabled） |
| `OnConfigLoading(EntityConfig config)` | 配置加载后 | ❌ | 注入动态配置 |

### 4.2 树节点钩子（TreeTableControllerBase<T,V>）

| 钩子 | 触发时机 | 可取消？ | 典型用途 |
|------|---------|---------|---------|
| `OnBeforeAddTree(T entity)` | 新增树节点前 | ✅ | 同级名称唯一性校验 |
| `OnAfterAddTree(T entity)` | 新增树节点后（事务内） | ❌ | - |
| `OnBeforeUpdateTree(T entity)` | 修改树节点前 | ✅ | 防环校验 |
| `OnAfterUpdateTree(T entity)` | 修改树节点后（事务内） | ❌ | - |
| `OnBeforeDeleteTree(string[] codes)` | 删除树节点前 | ✅ | 检查是否有子节点 |
| `OnAfterDeleteTree(int count)` | 删除树节点后 | ❌ | - |

## 六、控制器实现示例

### 5.1 单表控制器（极简版）

```csharp
// src/yzh-core/YZH.Core.Web/Controllers/System/UserController.cs
[ApiController]
[Route("api/System/[controller]")]
public class UserController : YzhControllerBase<Sys_User>
{
    public UserController(EntityService<Sys_User> entityService, IUserContext userContext)
        : base(entityService, userContext) { }

    // 注册行操作
    public UserController(EntityService<Sys_User> entityService, IUserContext userContext, PasswordHelper pwd)
        : base(entityService, userContext)
    {
        RegisterRowAction("Enable", EnableUser);
        RegisterRowAction("Disable", DisableUser);
        RegisterRowAction("ResetPassword", ResetPassword);
    }

    // 覆盖钩子注入业务逻辑
    protected override async Task<(bool ok, string? msg)> OnBeforeAdd(Sys_User entity)
    {
        if (await Entity.ExistsByCodeAsync(entity.UserName))
            return (false, $"账号 {entity.UserName} 已存在");
        entity.UserPwd = _passwordHelper.AesEncrypt(entity.UserPwd ?? "123456");
        entity.Enable = 1;
        return (true, null);
    }

    protected override void OnQueried(PagedResult<Sys_User> result)
    {
        foreach (var item in result.Items)
            item.RoleName = item.RoleId switch { 1 => "超级管理员", _ => "未知" };
    }
}
```

## 八、开发约束清单

### 7.1 后端约束

| # | 约束 | 说明 |
|---|------|------|
| 1 | 单表控制器必须继承 `YzhControllerBase<V>` | 不允许直接继承 ControllerBase |
| 2 | 左树右表控制器必须继承 `TreeTableControllerBase<T,V>` | T 必须实现 `ITreeEntity`（Code + ParentCode） |
| 3 | 业务差异只能通过覆盖 virtual 方法实现 | 不允许绕过基类直接暴露新 API |
| 4 | 所有 API 必须遵循统一命名规范 | `/config /filter /add /update /delete /tree/*` |
| 5 | 树接口返回必须是 `TreeItemDto` | 不允许返回数据库实体 |
| 6 | `/config` 必须返回完整配置 | 前端据此渲染页面 |
| 7 | 行操作必须通过 `RegisterRowAction` 注册 | 不允许在 Controller 中暴露额外 POST 方法 |
| 8 | 树节点操作必须通过 `RegisterTreeAction` 注册 | 使用 `/tree/action/{name}` 统一入口 |
| 9 | 统一使用 Code 作为业务主键 | 废除 GetById/DeleteById，使用 GetByCode/DeleteByCode |
| 10 | 实体继承 `BaseEntity` | 获得审计字段和 Code 自动生成 |

### 7.2 前端约束

| # | 约束 | 说明 |
|---|------|------|
| 1 | 单表页面 Logic 必须继承 `CrudPageLogic<V>` | 不允许重新实现 loadPage/add/update/delete |
| 2 | 左树右表页面 Logic 必须继承 `TreeTableLogic<V>` | 不允许重新实现树加载/联动逻辑 |
| 3 | 工具栏/搜索栏/行操作必须由配置驱动 | 不允许在 Vue 模板中硬编码按钮 |
| 4 | 操作列按钮必须由配置驱动 | 不允许在模板中固定"编辑""删除" |
| 5 | 树操作按钮必须由 `TreeConfig` 驱动 | 不允许在模板中固定 |
| 6 | 页面加载后必须先调 `logic.init()` | init() = loadConfig + loadTreeRoot + loadPageWithoutTree |
| 7 | 树与表格必须使用分离的 API 接口 | 不允许同一接口同时服务树加载和表格加载 |
| 8 | 删除/修改后使用 Split 方法增量更新 | 不允许重新请求整个 `/filter` |

## 十、与主流框架对比

| 维度 | Spring Boot + Vue | .NET Boilerplate | YZH 架构 |
|------|-------------------|------------------|---------|
| CRUD 代码量（单表） | 8 文件 ~600 行 | 5 文件 ~400 行 | **1 文件 ~30 行**（实体+JSON+Controller） |
| 树形结构 | 各项目独立实现 | 无统一方案 | **统一基类** TreeTableControllerBase |

| AI 友好度 | 中（框架知识需学习） | 高 | **高**（规则固定，示例丰富） |

## 十一、常见错误速查

| 错误现象 | 根因 | 修复 |
|---------|------|------|
| 前端表格列为空 | 未调 `logic.init()` 或 JSON 配置中 `XsFlag=false` | 检查 init() 调用、检查 JSON 配置 |
| 表单字段不显示 | JSON 配置中 `BcFlag=false` | 改为 `BcFlag=true` |
| `/filter` 报 400 | 实体无 `Code` 属性或属性类型非 string | 确保实体继承 `BaseEntity` |
| 树节点点击后表格不刷新 | 未调用 `logic.onNodeClick(node)` | 在 `@tree-node-click` 中调用 |
| 删除后表格数据重复 | 未使用 Split 方法，直接 `loadPage()` | 改用 `removeRowByCode(code)` |
| 新增后表格无新行 | 未使用 Split 方法 | 改用 `insertRow(row)` |
