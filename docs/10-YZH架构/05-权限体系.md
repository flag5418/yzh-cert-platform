## 一、设计理念

### 1.1 YZH.Core 是「纯 RBAC 底座」，不感知业务

```
┌─────────────────────────────────────────────────────────────────────────┐
│                                                                         │
│   ┌──────────────────────────────┐     ┌────────────────────────────┐  │
│   │        YZH.Core 底座         │     │     业务层（Admin/Auditor） │  │
│   │                              │     │                            │  │
│   │  ▪ 机构-人员 关系建立         │     │  ▪ 业务实体定义            │  │
│   │  ▪ 角色-人员 关系建立         │◄───►│  ▪ 业务表 + Attach 扩展表  │  │
│   │  ▪ 角色-菜单 关系建立         │ RPC │  ▪ 建企业/用户时调标准接口 │  │
│   │  ▪ 角色-接口 关系建立         │     │  ▪ 业务特有数据权限控制     │  │
│   │  ▪ Token 签发与鉴权           │     │                            │  │
│   │  ▪ SSO 挤号 + Token 续租      │     │                            │  │
│   │                              │     │                            │  │
│   │  ★ 不知道「认证项目」是什么   │     │  ★ 知道业务，但不重复造轮子 │  │
│   │  ★ 不知道「维护人员」是什么   │     │  ★ 扩展通过 Attach 表完成  │  │
│   └──────────────────────────────┘     └────────────────────────────┘  │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 1.2 权限控制的两层分离

| 层 | 职责 | 实现方 |
|----|------|-------|
| **功能权限** | 你能看到哪些菜单？你能调用哪些接口？ | YZH.Core（标准 RBAC） |
| **数据权限** | 你能看到哪些数据行？你能操作哪些数据？ | 业务层独立实现 |

### 2.2 角色标识（⚠️ 2026-09-23 勘误，以数据库实测为准）

> **勘误说明**：本节此前给出 `src/yzh-core/YZH.Core.Stand/Constants/RoleIds.cs` 的 `RoleIds` 常量类代码。
> **实测该文件与 `Constants/` 目录均不存在**，且其编号（`ConfigMaintainer=11` / `OrgAdmin=20` / `EntAdmin=30` …）
> 与数据库 `Sys_Role.Id` **不一致**。下面改为**数据库实测值**。

**角色的唯一业务标识是 `Sys_Role.Code`（varchar，形如 `ROLE_*`），不是 Id。**

`Sys_Role` 结构：`Id`(int, PK) / `Code`(varchar(50), UNIQUE) / `RoleName` / `ParentCode` / `OrderNo` / `Enable` / `IsValid` / `IsDeleted`

| Id | Code | RoleName | 用途 |
|---:|------|----------|------|
| 1 | `ROLE_SUPER_ADMIN` | 超级管理员 | 绕过一切授权（超管） |
| 2 | `ROLE_000002` | 测试管理员 | 历史遗留 |
| 4 | `ROLE_000004` | 信息员 | 历史遗留 |
| 10 | `ROLE_ADMIN` | 体系管理员 | 平台管理 |
| 20 | `ROLE_000020` | 审核员 | 审核员 |
| 100–104 | `ROLE_000100`–`ROLE_000104` | 超级管理员 / 总管理员 / 运维人员 / 配置人员 / 质量专员 | Vol 遗留 |
| **200** | **`ROLE_AUDIT_CLIENT_ADMIN`** | **体系认证客户端管理员** | **专家端注册默认绑定** |
| 201 | `ROLE_000201` | 审核组长 | 审核组长 |
| 202 | `ROLE_000202` | 普通审核员 | 普通审核员 |
| 300 | `ROLE_000300` | 企业账号 | 企业端 |

**代码中如何判断角色**：

- 后端：常量 `MenuPermissionService.SuperAdminRoleCode`（= `ROLE_SUPER_ADMIN`）；角色来自 **`Sys_RoleUser`** 关联表，**不是** `Sys_User.RoleId`
- 前端：JWT 的 `role` claim（登录时由 `Sys_RoleUser` 填充）

> ⚠️ `Sys_User.RoleId` 列存在但**实体未声明**，仅 `v_sys_user` 视图用它取 `RoleName` 显示；**不要**用它做权限判断。

### 2.3 角色权限矩阵

> ⚠️ **下表是目标态设计，不是现状**。表中的 `ConfigMaintainer` / `AuditorAdmin` / `OrgAdmin` / `TeamLead` /
> `EnterpriseUser` 在 `Sys_Role` 中**没有同名 Code**；实际落地以 §2.2 的 `ROLE_*` 为准。
> 另：**接口级授权全站未启用**（`[RequirePermission]` 全库标注数 = 0），"接口范围"一列当前无强制力。

| 角色 | 菜单权限 | 数据范围 | 接口范围 | 配置权限 |
|------|---------|---------|---------|---------|
| **SuperAdmin** | 全部 | 全局 | 全部 | 全部（含核心配置） |

| **Auditor** | 审核菜单 | 被分配任务 | 审核执行 | 无 |
| **EnterpriseUser** | 企业菜单 | 本企业数据 | 企业相关 | 无 |

### 3.2 SSO 挤号机制

**核心原理**：每个用户在 Redis 维护一个版本号，登录时生成新版本写入 Redis + JWT，校验时比对。

```
设备 A 登录
  → BumpVersion() → Redis ver = "aaa111"
  → GenerateToken(ver="aaa111") → Token_A

设备 B 登录（同账号）
  → BumpVersion() → Redis ver = "bbb222"
  → GenerateToken(ver="bbb") → Token_B

设备 A 发起请求（Token_A ver="aaa111"）
  → ValidateVersion("aaa111") → 当前 ver="bbb222"
  → "aaa111" ≠ "bbb222" → HTTP 401 + "账号已在其他设备登录"
```

**关键代码**：

```csharp
// TokenVersionService.cs — Redis 版本号维护
public class TokenVersionService
{
    public async Task<string> BumpVersionAsync(string userCode)
    {
        var version = Guid.NewGuid().ToString("N");
        await _cache.SetStringAsync(
            $"token_ver:{userCode}", version,
            new DistributedCacheEntryOptions { AbsoluteExpirationRelativeToNow = TimeSpan.FromDays(30) });
        return version;
    }

    public async Task<bool> ValidateVersionAsync(string userCode, string tokenVersion)
    {
        var current = await _cache.GetStringAsync($"token_ver:{userCode}");
        return string.Equals(current, tokenVersion, StringComparison.OrdinalIgnoreCase);
    }
}

// AuthController.cs — 登录时挤掉旧 Token
[HttpPost("login")]
[YZHAnonymous]
public async Task<IActionResult> Login([FromBody] LoginRequest req)
{
    // ... 验证用户名密码 ...
    var ssoVersion = await _tokenVersion.BumpVersionAsync(userCode);
    var token = _jwt.GenerateToken(userCode, userName, new[] { roleId.ToString() }, ssoVersion);
    return Ok(ApiResponse<LoginResponse>.Ok(new LoginResponse { Token = token, ... }));
}
```

### 3.3 Token 自动续租

**场景**：用户正在操作，Token 即将过期，续租避免中断。

```
客户端请求
  → Token (剩余 25 分钟)
  → YzhAuthFilter 检查：剩余 < 30 分钟？
  → Yes → 生成新 Token（7天有效期）
  → 写入 Response.Headers["X-New-Token"]

客户端检测到 X-New-Token → 自动替换本地 Token（用户无感）
```

```csharp
// YzhAuthFilter.cs — 续租判断
private async Task TryRenewToken(AuthorizationFilterContext context, string userCode)
{
    var remaining = expDateTime - DateTime.UtcNow;
    if (remaining < TimeSpan.FromMinutes(30) && remaining > TimeSpan.Zero)
    {
        var userName = context.HttpContext.User.FindFirst(ClaimTypes.Name)?.Value ?? "";
        var roles = context.HttpContext.User.FindAll(ClaimTypes.Role).Select(c => c.Value);
        var tokenVer = context.HttpContext.User.FindFirst("ver")?.Value ?? "";
        var newToken = _jwt.RenewToken(userCode, userName, roles, tokenVer, TimeSpan.FromDays(7));
        context.HttpContext.Response.Headers["X-New-Token"] = newToken;
    }
}
```

## 六、配置保护机制

### 6.1 核心配置保护原则

| 操作 | SuperAdmin | Admin | ConfigMaintainer | 其他角色 |
|------|-----------|-------|------------------|---------|
| 查看配置 | ✅ | ✅ | ✅（scope 内） | ❌ |
| 新建配置 | ✅ | ✅ | ✅（草稿态） | ❌ |
| 编辑草稿配置 | ✅ | ✅ | ✅（scope 内） | ❌ |
| 发布配置 | ✅ | ✅ | ❌ **禁止发布** | ❌ |
| 删除配置 | ✅ | ✅ | ❌ | ❌ |
| 修改核心配置 | ✅ | ✅ | ❌ **绝对禁止** | ❌ |

### 6.2 实现

```csharp
// YzhConfigController.cs — 配置编辑保护
public async Task<IActionResult> UpdateConfig([FromBody] SysConfig config)
{
    var user = _userContext.GetCurrent();

    // 1. 核心配置仅 SuperAdmin 可修改
    if (config.IsCore && user.RoleId != RoleIds.SuperAdmin)
        return Forbid(ApiResponse.Fail("核心配置仅超级管理员可修改"));

    // 2. 配置维护员只能编辑草稿态
    if (user.RoleId == RoleIds.ConfigMaintainer)
    {
        var existing = await _repo.GetByCodeAsync(config.Code);
        if (existing != null && existing.Status == ConfigStatus.Published)
            return Forbid(ApiResponse.Fail("已发布配置维护员无法直接修改"));
        if (!await _configScopeService.CanMaintain(user.UserCode, config.Category))
            return Forbid(ApiResponse.Fail("该配置不在您的维护范围内"));
        config.Status = ConfigStatus.Draft;
        config.MaintainerCode = user.UserCode;
    }

    await _repo.UpdateAsync(config);
    return Ok(ApiResponse.Ok(config));
}

// 发布操作（仅 Admin 以上）
[HttpPost("publish")]
public async Task<IActionResult> PublishConfig([FromBody] string code)
{
    var user = _userContext.GetCurrent();
    if (user.RoleId == RoleIds.ConfigMaintainer)
        return Forbid(ApiResponse.Fail("维护员无权发布配置，请联系管理员"));

    var config = await _repo.GetByCodeAsync(code);
    if (config == null) return NotFound(ApiResponse.Fail("配置不存在"));

    config.Status = ConfigStatus.Published;
    await _repo.UpdateAsync(config);
    _eventBus.Publish(new ConfigPublishedEvent(config));
    return Ok(ApiResponse.Ok(config));
}
```

### 7.1 Token 续租自动处理

```typescript
// cert/cert-share/src/api/client.ts
import axios from 'axios'

const instance = axios.create({ baseURL: import.meta.env.VITE_API_BASE || '/api' })

    const token = tokenStore.get()

instance.interceptors.response.use(
    (response) => {
        const newToken = response.headers['x-new-token']
        if (newToken) {
            tokenStore.set(newToken)
            localStorage.setItem('YZH_TOKEN', newToken)
        }
        return response
    },
    (error) => {
        if (error.response?.status === 401) {
            const code = error.response.data?.code
            if (code === 4011) {
                store.dispatch('forceLogout', '您的账号已在其他设备登录')
            } else {
                store.dispatch('forceLogout', '登录已过期，请重新登录')
            }
            router.push('/login')
        }
        return Promise.reject(error)
    }
)
```

// cert/cert-admin/src/directives/permission.ts
export function setupPermissionDirective(app: App) {
    app.directive('permission', {
        mounted(el, binding) {
            const userStore = useUserStore()
            const required = Array.isArray(binding.value) ? binding.value : [binding.value]
            const hasPermission = required.some(p => userStore.permissions.includes(p))
            if (!hasPermission) el.parentNode?.removeChild(el)
        }
    })
}

## 八、安全红线清单

| 红线 | 说明 | 校验方式 |
|------|------|---------|
| **核心配置保护** | IsCore=true 的配置仅 SuperAdmin 可修改 | Controller 硬编码校验 |
| **维护员范围** | 维护员只能编辑指定 Category 的配置 | sys_maintainer_scope 校验 |
| **维护员禁止发布** | 维护员无法调用 Publish 接口 | 接口权限硬编码 |
| **业务数据权限** | 数据权限过滤由业务层独立实现，不依赖基类 | 业务 Service + SQL |
| **SSO 挤号** | 同账号新登录后旧 Token 全部失效 | TokenVersionService |
| **生产免认证失效** | RequireAuth=true 时 YZHAnonymous 无效 | appsettings 配置 |
| **审计日志** | 所有 UPDATE/DELETE/ConfigPublish 必须记录 | YzhAuditingFilter |
