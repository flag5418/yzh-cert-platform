## 二、SingleTableCore<V> — 单表 Logic 基类

### 2.1 类定义（★ 逐字段实测，`logic/SingleTableCore.ts`）

```typescript
// 文件：yzh.vue.core/src/logic/SingleTableCore.ts（实测 61 行起）
export abstract class SingleTableCore<V extends Record<string, any> = any> {
  // ──── 页面标识 ────
  abstract controllerName: string      // 子类必须设置（值 = 路由前缀，如 'System/User'）

  // ──── 后端配置 ────
  config = ref<EntityConfigDto | null>(null)

  // ──── 表格状态 ────
  rows = ref<V[]>([])                  // 数据行（PascalCase 字段）
  loading = ref(false)
  selectedRows = ref<V[]>([])

  // ──── 分页 / 搜索 / 排序 ────
  pagination = reactive({ page: 1, pageSize: 20, total: 0 })
  searchParams = reactive<Record<string, any>>({})   // PascalCase key
  sortField = ref<string | undefined>()              // PascalCase
  sortOrder = ref<'asc' | 'desc' | undefined>()

  // ──── 弹窗状态 ────
  dialogVisible = ref(false)
  dialogMode = ref<'add' | 'edit' | 'detail'>('add')   // ⚠️ 含 'detail'
  formGroupIndex = ref<string>('0')   // '0'=新增/编辑；'99'=详情（全只读）
  submitting = ref(false)

  // ──── ShowDisabled（★ 内核统一管理，子类无需实现）────
  showDisabled = ref(false)
  async toggleShowDisabled(): Promise<void> { this.showDisabled.value = !this.showDisabled.value; await this.refresh() }

  // ──── 表格引用（局部刷新）────
  protected _tableRef: any = null
  setTableRef(ref: any)                        // 由 useSingleTable 注入
  async refresh(): Promise<void>               // ★ 刷新方法名是 refresh()，不是 refreshTable()
}
```

> ⚠️ **旧版本 §2.1 的 3 处错误**：① 泛型漏了 `= any` 默认值（真实有）；② `dialogMode` 漏了 `'detail'`；③ 完全没有列出 `formGroupIndex` / `showDisabled` / `refresh()` / `setTableRef()`。

## 三、TreeTableCore<V> — 左树右表 Logic 基类（别名 TreeTableLogic 已废弃）

### 3.1 继承关系

```
SingleTableCore<V>                       ← 单表：列/表单/搜索/按钮 由后端 EntityConfig 驱动
    │
    ▼
TreeTableCore<V>                         ← 继承单表全部能力 + 叠加树能力
    │
    └─ 别名 TreeTableLogic（@deprecated，见 logic/TreeTableLogic.ts，待消费者迁移后删除）
```

> **实测签名**：`export abstract class TreeTableCore<V extends Record<string, any> = any> extends SingleTableCore<V>`
> —— 泛型只有一个且有默认值，所以 `extends TreeTableCore<any>` 与 `extends TreeTableCore` 都合法。

### 3.2 新增状态

```typescript
// 真实实现（yzh.vue.core/src/logic/TreeTableCore.ts）
// 树状态通过 TreeSide 混入持有，对外以 getter/setter 暴露（不是裸 ref）
export abstract class TreeTableCore<V extends Record<string, any> = any>
    extends SingleTableCore<V> {

    protected readonly treeSide = new TreeSide()

    // ──── 树状态（getter/setter 转发到 treeSide） ────
    get/set treeData: TreeNode[]
    get treeLoading
    get/set selectedNode: TreeNode | null

    // ──── 树节点弹窗状态 ────
    treeDialogVisible, treeDialogMode, treeSubmitting,
    treeFormData, treeParentNode, treeEditingNode
}
```

### 3.3 快捷访问器

```typescript
// 从 treeTableConfig 派生
protected get treeConfig(): any         // TreeBehaviorConfigDto
protected get treeFormConfig(): EntityConfigDto | null  // 树节点表单配置
protected get noSelectionBehavior(): 'empty' | 'all'    // 未选中时的表格行为
protected get relateField(): string     // 关联字段名（PascalCase）
protected get treeFormFields(): YzhFormField[]  // 树节点表单字段（从 treeFormConfig 派生）
```

### 3.4 核心方法

```typescript
// ──── 配置加载（覆盖父类）───
async loadConfig(): Promise<void>   // GET /config → 返回 TreeTableConfigDto

// ──── 树加载 ────
async loadTreeRoot(): Promise<void>          // POST /tree/root
async loadChildren(node: any, resolve?: Function): Promise<TreeNode[]>  // POST /tree/children

// ──── 树→表格联动 ────
async onNodeClick(node: TreeNode): Promise<void>   // 选中节点 → 加载表格
async loadPageWithTree(treeCode: string): Promise<void>  // 带树条件的查询
async loadPageWithoutTree(): Promise<void>          // 无树条件（按 NoSelectionBehavior）

// ──── 树节点 CRUD ────
async addTreeNode(parentNode: TreeNode | null, data: Record<string, any>): Promise<TreeNode | null>
async updateTreeNode(node: TreeNode, newName: string, extra?: Record<string, any>): Promise<void>
```

## 五、类型契约（★ 已收口，唯一权威见 `20-前后端契约权威表-V1.md`）

> **本节不再复制类型定义。** 契约类型的唯一权威是
> `yzh.vue.core/src/types/contracts.ts`（代码）+ `20-前后端契约权威表-V1.md`（文档）。
> 复制即漂移 —— 本节旧版本曾把 `ApiResponse` 写成 PascalCase、把 `PagedData` 写成 `Total/Page`、
> 并漏掉了 `Sxh`（当时误判为「已废」），属于典型的「文档反成错误源」。**禁止在本文件重新抄写类型。**

**命名三分法（唯一必须记住的判据）**：

| # | 类型 | 命名 | 例 |
|---|------|------|-----|
| ① | `ApiResponse` 信封顶层 | **camelCase** | `success` / `data` / `message` / `code` / `timestamp` |
| ② | 业务实体 / 配置 / DTO | **PascalCase** | `ColumnConfig.FieldName`、`TreeItemDto.Code`、`PagedData.Items` |
| ③ | `NewEntity` / `Schema` 字典 key | **camelCase** | `{ code: "", userName: "", orgCode: "root" }` |
| ④ | `FilterRequest` / `FilterItem` | **PascalCase** | `Page` / `PageSize` / `Filters[].Field` |

**权威文件位置**：`yzh.vue.core/src/types/{contracts.ts, tree.ts, Page.ts, association.ts}`
（⚠️ **不在** `cert-share/src/types/` —— 该目录只有业务类型 `cert.ts` / `role-tree.ts`）。

**高频误用（照旧版抄必错）**：

- `PagedData` 字段是 `Items / TotalCount / PageIndex / PageSize`（**不是** `Total` / `Page`）
- `TreeNode` 字段是 **PascalCase**：`Code` / `Name` / `ParentCode` / `IsLeaf` / `Extra` / `Children`
- `ColumnConfig` 当前**缺 `Sxh`**（G18 契约缺口，待补）—— 补上后**表格列顺序 = `Sxh` 升序**
- `ColumnConfig` 有 `Row`/`Col`/`RowSpan`/`ColSpan` 但**适配层不消费**（G19，待补）—— 表单应走 **WPF Grid 模型**
- 例外 E1：`ApiResponse` 是**唯一** camelCase 的业务载体，须注释标注「已登记例外」

## 七、页面开发模式

### 7.1 模式一：配置驱动（推荐）

适用于：标准 CRUD 页面，字段来自后端 JSON 配置。

```
┌──────────────────────────────────────────────────────────────┐
│  后端 Controller 继承 YzhControllerBase<V>                    │
│  → 提供 /config /filter /add /update /delete /action/*        │
│                                                              │
│  前端 Logic 继承 SingleTableCore<V>                             │
│  → 自动从 /config 获取 columns / formFields / searchFields    │
│  → 提供 dataLoader() / add() / update() / delete()            │
│                                                              │
│  前端 .vue 只需：                                              │
│  1. const { logic, tableRef } = useSingleTable(MyLogic)       │
│  2. <YzhTable ref="tableRef" :columns="logic.columns"         │
│       :data-loader="logic.dataLoader.bind(logic)" ... />      │
│  3. <YzhFormDialog v-model:visible=... :fields=... />         │
└──────────────────────────────────────────────────────────────┘
```

### 7.2 模式二：手写 API（当前已有页面）

适用于：后端尚未完成迁移、或特殊业务页面。

```
┌──────────────────────────────────────────────────────────────┐
│  前端直接调用 cert/cert-share/src/api/xxx.ts 中的手写 API 函数   │
│  → 自行管理 columns / searchFields / 弹窗状态                   │
│  → 不依赖 Logic 基类                                           │
│                                                              │
│  示例：foundation/iso-standard/index.vue                       │
│  → columns 硬编码                                              │
│  → 直接调用 getISOStandardPage(params)                         │
└──────────────────────────────────────────────────────────────┘
```

> **趋势**：新页面优先使用模式一（配置驱动），旧页面逐步迁移。
