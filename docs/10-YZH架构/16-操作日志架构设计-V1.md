# 操作日志架构设计

> **版本**：V1.2 | **日期**：2026-09-20 | **状态**：待审批
>
> 本文档定义操作日志（sys_log）的架构设计方案，涵盖切入阶段、数据流向、文件清单和执行计划。
> 前置文档：`02-后端架构.md`、`05-权限体系.md`
>
> **核心原则**：Code 是数据库唯一业务键，增删改操作必须记录 **「谁 + 对哪条 Code + 做了什么操作」**。
>
> **必要要素**：机构、用户、IP 地址、日期是每条日志的必填项，通过 UserContext 统一解析。

---

## 一、问题背景

### 1.1 现状

| 组件 | 位置 | 状态 | 问题 |
|------|------|------|------|
| `sys_log` 数据库表 | MySQL | ✅ 已存在 | 无数据写入 |
| `SysLog` 实体 | `CertPlatform.Shared/Entities/Sys/` | ✅ 已存在 | 字段已对齐 |
| `SysLogController` | `CertPlatform.Admin/Controllers/System/` | ✅ 已存在 | 只读查询正常 |
| `IYzhAuditLogger` | `YZH.Core.Api/Services/` | ✅ 已注册 | **仅写文件** |
| `YzhAuditingFilter` | `YZH.Core.Api/Filters/` | ⚠️ 代码存在 | **未注册为全局过滤器** |
| `EntityService` 审计 | `YZH.Core.Api/Services/` | ✅ 已调用 auditLogger | 只写文件 |
| `GlobalExceptionFilter` | `YZH.Core.Api/Filters/` | ✅ 已全局注册 | 只返回错误，不写 sys_log |

**根因**：项目有完整的审计日志基础设施（`IYzhAuditLogger` + `YzhAuditingFilter`），但所有审计调用只写文件日志，没有写入 `sys_log` 数据库表的代码路径。

### 1.2 架构约束

| 约束 | 原因 |
|------|------|
| `Program.cs` 不引用业务服务 | `YZH.Core.Web/Program.cs` 是启动器，只调用 `UseYzhCore()` 和 `AddCertPlatformAdminServices()`，不直接添加业务层 Filter |
| `YzhWebBuilder` 是核心注册器 | 负责注册核心服务（Filter、Auth、EntityService），可扩展但不应耦合具体业务 |
| 已有 MVC Filter 管线 | 项目有完整的 `IAsyncActionFilter` / `IExceptionFilter` 基础设施，应复用而非重建 |

## 二、行业最佳实践

> 来源：codingdroplets.com、fullstackhero.net、pietschsoft.com、developersvoice.com（2025-2026）

### 2.1 三层审计日志标准架构

```
┌──────────────────────────────────────────────────────────────┐
│  Layer 1: HTTP 请求级（Middleware / ActionFilter）             │
│  记录：谁 + 什么时间 + 请求了什么接口 + 响应状态 + 耗时        │
│  适用：所有 API 请求的访问审计                                  │
│  特点：安全网——即使业务代码遗漏，也能捕获所有 API 访问          │
├──────────────────────────────────────────────────────────────┤
│  Layer 2: 数据变更级（ORM Interceptor / AOP）                  │
│  记录：哪个实体 + Insert/Update/Delete + 变更前后值             │
│  适用：数据库操作的字段级审计                                    │
│  特点：与数据变更在同一事务中，保证原子性                        │
├──────────────────────────────────────────────────────────────┤
│  Layer 3: 业务事件级（Domain Event / Controller Hook）         │
│  记录：业务语义（审批通过、角色变更、配置修改）                   │
│  适用：合规要求的高价值业务操作                                  │
│  特点：用人能读懂的语言描述业务操作                              │
└──────────────────────────────────────────────────────────────┘
```

### 2.2 各层适用场景对比

| 层级 | 捕获范围 | 事务一致性 | 实现成本 | 推荐用途 |
|------|---------|-----------|---------|---------|
| HTTP 请求级 | 所有 API 请求 | ❌ 在事务外 | 低 | 访问审计、安全合规 |
| ORM 数据变更级 | 通过 ORM 的写操作 | ✅ 同一事务 | 中 | 字段级变更追踪 |
| 业务事件级 | 手动标记的业务操作 | ✅ 同一事务 | 高 | 合规审计、业务语义 |

### 2.3 关键设计原则

1. **审计日志必须在事务内写入**——写在事务外会导致主事务回滚时审计记录残留
2. **装饰器优于继承**——通过装饰器扩展 `IYzhAuditLogger`，不修改原有类
3. **DI 后注册覆盖先注册**——业务层通过重新注册接口替换核心层实现
4. **`IConfigureOptions<MvcOptions>` 自动合并**——多个实现共存，不覆盖已有 Filter

## 三、架构设计

### 3.1 请求生命周期中的日志切入阶段

```
HTTP Request
    │
    ▼
┌─ [Middleware 层] ──────────────────────────────────────────┐
│  ① 请求进入：记录 时间/IP/Method/Path/User-Agent            │
│  ② 认证通过后：记录 UserId/UserName                         │
└────────────────────────────────────────────────────────────┘
    │
    ▼
┌─ [Authorization Filter 层] ───────────────────────────────┐
│  ③ 权限校验：记录 权限校验结果（通过/拒绝）                   │
└────────────────────────────────────────────────────────────┘
    │
    ▼
┌─ [Action Filter 层] ─────────────────────────────────────┐
│  ④ 请求执行前：记录 请求参数（脱敏）                         │
│  ⑤ 请求执行后：记录 响应状态码/耗时/异常                      │
└────────────────────────────────────────────────────────────┘
    │
    ▼
┌─ [Controller 层] ────────────────────────────────────────┐
│  ⑥ 业务钩子：OnBeforeAdd/OnAfterAdd/OnBeforeUpdate/...     │
│     记录：新增/修改/删除了什么实体 + 业务语义                  │
└────────────────────────────────────────────────────────────┘
    │
    ▼
┌─ [EntityService 层] ─────────────────────────────────────┐
│  ⑦ 数据操作：Insert/Update/Delete 执行后                    │
│     记录：实体类型 + 操作结果 + 操作人 + IP                   │
└────────────────────────────────────────────────────────────┘
    │
    ▼
┌─ [ORM 层] ───────────────────────────────────────────────┐
│  ⑧ SQL 执行：SqlSugar AOP.OnLogExecuting/OnLogExecuted     │
│     记录：执行的 SQL + 耗时 + 参数                            │
│     （可选：生产环境关闭，开发环境用于调试）                    │
└────────────────────────────────────────────────────────────┘
    │
    ▼
┌─ [Exception 层] ─────────────────────────────────────────┐
│  ⑨ 异常捕获：GlobalExceptionFilter                         │
│     记录：异常类型 + 堆栈 + 请求上下文                        │
└────────────────────────────────────────────────────────────┘
    │
    ▼
HTTP Response
```

### 3.2 各层职责与数据流向

| 层级 | 切入机制 | 记录内容 | 写入目标 | 实现状态 |
|------|---------|---------|---------|---------|
| ①② 请求入口 | `ApiAuditFilter`（新） | 访问日志 | sys_log | 待实现 |
| ③ 权限拒绝 | `PermissionFilter`（已有） | 拒绝事件 | sys_log | 需扩展 |
| ④⑤ 请求执行 | `ApiAuditFilter`（新） | 请求参数+响应+耗时 | sys_log | 待实现 |
| ⑥ 业务钩子 | `YzhControllerBase` 钩子（已有） | 业务语义操作 | sys_log | 子类覆盖 |
| ⑦ 数据操作 | `SysLogAuditLoggerDecorator`（新） | CRUD 操作结果 | sys_log | 待实现 |
| ⑧ SQL 执行 | SqlSugar AOP（可选） | SQL + 耗时 | 日志文件 | P2 阶段 |
| ⑨ 异常捕获 | `ExceptionAuditFilter`（新） | 异常详情 | sys_log | 待实现 |

### 3.3 核心设计：装饰器模式扩展 IYzhAuditLogger

`IYzhAuditLogger` 是已有的审计接口，`EntityService` 已经在调用它。通过**装饰器模式**扩展，使其同时写文件+写数据库：

```
EntityService 调用 _auditLogger.Info(...)
        │
        ▼
┌─ SysLogAuditLoggerDecorator（业务层）──┐
│  1. 委托给原 YzhAuditLogger（写文件）    │
│  2. 同时写入 sys_log 数据库表            │
└────────────────────────────────────────┘
```

**关键机制**：`CertPlatformAdminServiceExtensions` 中重新注册 `IYzhAuditLogger` → `SysLogAuditLoggerDecorator`，DI 容器的**后注册覆盖先注册**，自动替换。

### 3.4 全局 Filter 注册方案（不改 Program.cs）

利用 `IConfigureOptions<MvcOptions>` 在 DI 中注入 Filter 配置：

```csharp
// CertPlatform.Admin/Configuration/ConfigureMvcFilters.cs
public class ConfigureMvcFilters : IConfigureOptions<MvcOptions>
{
    public void Configure(MvcOptions options)
    {
        options.Filters.Add<ApiAuditFilter>();
        options.Filters.Add<ExceptionAuditFilter>();
    }
}
```

**原理**：`ConfigureOptions<>()` 会自动合并多个 `IConfigureOptions<MvcOptions>` 实现，不会覆盖 Program.cs 中已有的 `GlobalExceptionFilter` 和 `PermissionFilter` 注册。

## 五、详细设计

### 5.1 IExtendedUserContext — 扩展用户上下文接口

```csharp
// CertPlatform.Admin/Services/Sys/IExtendedUserContext.cs
namespace CertPlatform.Admin.Services.Sys;

/// <summary>
/// 扩展用户上下文接口
/// 在 IUserContext 基础上增加机构层级信息
/// 
/// ★ 设计原则：
///   - IUserContext（核心层）：提供 UserId/UserCode/UserName/ClientIp
///   - IExtendedUserContext（业务层）：增加 OrgCode/OrgName/OrgPath/DisplayInfo
///   - 业务层通过包装器扩展，不修改核心层
/// </summary>
public interface IExtendedUserContext
{
    /// <summary>用户 Code（业务编码）</summary>
    string UserCode { get; }

    /// <summary>用户账号</summary>
    string UserName { get; }

    /// <summary>用户真实姓名</summary>
    string? UserTrueName { get; }

    /// <summary>用户显示名：账号/姓名（如 "zhangsan/张三"）</summary>
    string OperatorDisplay { get; }

    /// <summary>机构 Code</summary>
    string? OrgCode { get; }

    /// <summary>机构名称</summary>
    string? OrgName { get; }

    /// <summary>
    /// 机构层级路径（如 "映智汇/后台管理/审核员"）
    /// 从 Sys_Organization.OrgPath 解析，用 "/" 分隔
    /// </summary>
    string OrgDisplay { get; }

    /// <summary>客户端 IP</summary>
    string ClientIp { get; }

    /// <summary>User-Agent</summary>
    string? UserAgent { get; }
}
```

### 5.2 ExtendedUserContext — 扩展实现

```csharp
// CertPlatform.Admin/Services/Sys/ExtendedUserContext.cs
namespace CertPlatform.Admin.Services.Sys;

/// <summary>
/// 扩展用户上下文实现
/// 包装 IUserContext，通过数据库查询解析机构层级
/// 
/// ★ 生命周期：Scoped（每次 HTTP 请求创建一次）
/// ★ 缓存策略：同一请求内重复访问不查库
/// </summary>
public class ExtendedUserContext : IExtendedUserContext
{
    private readonly IUserContext _userContext;
    private readonly IDbOrm _dbOrm;

    // 请求级缓存（避免重复查库）
    private string? _orgCode;
    private string? _orgName;
    private string? _orgDisplay;
    private bool _resolved;

    public ExtendedUserContext(IUserContext userContext, IDbOrm dbOrm)
    {
        _userContext = userContext;
        _dbOrm = dbOrm;
    }

    public string UserCode => _userContext.UserCode;
    public string UserName => _userContext.UserName;
    public string? UserTrueName => _userContext.UserTrueName;
    public string ClientIp => _userContext.ClientIp;
    public string? UserAgent => _userContext.UserAgent;

    /// <summary>
    /// 操作员显示名："账号/姓名"
    /// 例："zhangsan/张三"
    /// </summary>
    public string OperatorDisplay
    {
        get
        {
            var account = _userContext.UserName ?? "unknown";
            var trueName = _userContext.UserTrueName;
            return string.IsNullOrEmpty(trueName)
                ? account
                : $"{account}/{trueName}";
        }
    }

    /// <summary>机构 Code（从 Sys_User 查询）</summary>
    public string? OrgCode
    {
        get
        {
            ResolveOrgInfo();
            return _orgCode;
        }
    }

    /// <summary>机构名称</summary>
    public string? OrgName
    {
        get
        {
            ResolveOrgInfo();
            return _orgName;
        }
    }

    /// <summary>
    /// 机构层级显示路径
    /// 例："映智汇/后台管理/审核员"
    /// 从 Sys_Organization.OrgPath 解析
    /// </summary>
    public string OrgDisplay
    {
        get
        {
            ResolveOrgInfo();
            return _orgDisplay ?? "";
        }
    }

    /// <summary>
    /// 延迟解析机构信息（第一次访问时查库，后续使用缓存）
    /// 
    /// 查询链路（统一使用 IDbOrm ORM 方法，不写 raw SQL）：
    ///   1. _dbOrm.GetOneAsync&lt;Sys_User&gt;(u => u.Code == UserCode) → 获取 OrgCode
    ///   2. _dbOrm.GetOneAsync&lt;Sys_Organization&gt;(o => o.Code == orgCode) → 获取 OrgName, ParentCode
    ///   3. 递归查询 ParentCode → 构建完整路径
    /// </summary>
    private void ResolveOrgInfo()
    {
        if (_resolved) return;
        _resolved = true;

        try
        {
            // 1. 查询用户的 OrgCode（ORM 方法，自动过滤 IsDeleted）
            var userResult = _dbOrm.GetOneAsync<Sys_User>(
                u => u.Code == UserCode).Result;

            if (!userResult.Success || userResult.Data == null)
                return;

            _orgCode = userResult.Data.OrgCode;
            if (string.IsNullOrEmpty(_orgCode))
                return;

            // 2. 查询当前机构 + 构建层级路径
            _orgDisplay = BuildOrgPath(_orgCode);
        }
        catch
        {
            // 机构解析失败不影响主流程
        }
    }

    /// <summary>
    /// 构建机构层级路径
    /// 例："映智汇/后台管理/审核员"
    /// </summary>
    private string BuildOrgPath(string orgCode)
    {
        var pathParts = new List<string>();
        var currentCode = orgCode;

        // 递归查询父级（最多10层，防止死循环）
        for (int i = 0; i < 10 && !string.IsNullOrEmpty(currentCode); i++)
        {
            // 使用 ORM 方法查询（自动过滤 IsDeleted）
            var orgResult = _dbOrm.GetOneAsync<Sys_Organization>(
                o => o.Code == currentCode).Result;

            if (!orgResult.Success || orgResult.Data == null)
                break;

            pathParts.Insert(0, orgResult.Data.OrgName);
            currentCode = orgResult.Data.ParentCode;
        }

        _orgName = pathParts.LastOrDefault();
        return string.Join("/", pathParts);
    }
}
```

**设计说明**：

| 特性 | 说明 |
|------|------|
| 延迟初始化 | 第一次访问 OrgCode/OrgName/OrgDisplay 时才查库 |
| 请求级缓存 | 同一请求内多次访问不重复查库 |
| 失败安全 | 机构解析失败不影响主流程，返回空值 |
| 递归查询 | 从当前机构向上遍历父级，构建完整路径 |
| 不修改核心层 | 通过包装 IUserContext 实现，核心层无感知 |

```csharp
// CertPlatform.Admin/Services/Sys/ISysLogService.cs
namespace CertPlatform.Admin.Services.Sys;

/// <summary>
/// 操作日志数据库写入服务
/// 职责：将审计事件持久化到 sys_log 表
/// </summary>
public interface ISysLogService
{
    /// <summary>记录操作日志</summary>
    Task LogAsync(SysLogEntry entry);
}

/// <summary>操作日志条目</summary>
public class SysLogEntry
{
    public string Module { get; set; }        // 模块（实体名 / Controller 名）
    public string Action { get; set; }        // 操作（Insert / Update / Delete / 查询 / 异常）
    public string? TargetCode { get; set; }   // ★ 操作目标的 Code（数据库唯一业务键）
    public string? TargetType { get; set; }   // 目标类型（实体类型名）
    public string? Detail { get; set; }       // 详情（变更内容 / 耗时 / 异常信息）
    public bool IsSuccess { get; set; } = true;
}
```

**关键设计**：`TargetCode` 存储实体的 `Code` 字段值（GUID 业务键），而非自增 `Id`。这样可以通过 Code 追溯「这条记录被谁操作过」。

### 5.2 SysLogService — 写入 sys_log 表

```csharp
// CertPlatform.Admin/Services/Sys/SysLogService.cs
namespace CertPlatform.Admin.Services.Sys;

public class SysLogService : ISysLogService
{
    private readonly IDbOrm _dbOrm;
    private readonly IExtendedUserContext _userContext;

    public SysLogService(IDbOrm dbOrm, IExtendedUserContext userContext)
    {
        _dbOrm = dbOrm;
        _userContext = userContext;
    }

    public async Task LogAsync(SysLogEntry entry)
    {
        try
        {
            var userId = long.TryParse(_userContext.UserCode, out var uid) ? uid : (long?)null;

            var log = new SysLog
            {
                Module = entry.Module,
                Action = entry.Action,
                TargetType = entry.TargetType,
                TargetCode = entry.TargetCode,       // ★ 业务 Code（唯一键）
                Detail = entry.Detail,
                // ──── 必要要素（通过 IExtendedUserContext 统一解析） ────
                OperatorDisplay = _userContext.OperatorDisplay,  // "账号/姓名"
                OrgDisplay = _userContext.OrgDisplay,            // "机构层级路径"
                IpAddress = _userContext.ClientIp,               // IP 地址
                UserAgent = _userContext.UserAgent,              // 浏览器标识
                UserId = userId,
            };

            await _dbOrm.InsertAsync(log);
        }
        catch (Exception ex)
        {
            // 日志写入失败不能影响业务流程，仅输出到控制台
            Console.WriteLine($"[SysLog] 写入失败: {ex.Message}");
        }
    }
}
```

### 5.3 SysLogAuditLoggerDecorator — IYzhAuditLogger 装饰器

```csharp
// CertPlatform.Admin/Services/Sys/SysLogAuditLoggerDecorator.cs
namespace CertPlatform.Admin.Services.Sys;

/// <summary>
/// IYzhAuditLogger 装饰器
/// 拦截 EntityService 的 Info/Warning/Error 调用，同时写入数据库
/// 
/// ★ 核心原则：增删改操作必须记录 Code（数据库唯一业务键）
/// EntityService 的审计调用格式：
///   Info("新增SysConfig记录", userCode, userName, ip, "Id=1, Code=abc123")
///   Info("更新SysConfig记录", userCode, userName, ip, "Id=1, Code=abc123")
///   Error("删除SysConfig", ex, userCode, userName, ip)
/// </summary>
public class SysLogAuditLoggerDecorator : IYzhAuditLogger
{
    private readonly IYzhAuditLogger _inner;
    private readonly ISysLogService _sysLogService;

    public SysLogAuditLoggerDecorator(
        IYzhAuditLogger inner,
        ISysLogService sysLogService)
    {
        _inner = inner;
        _sysLogService = sysLogService;
    }

    public void Info(string action, string? userCode = null, string? userName = null,
                     string? ipAddress = null, string? extra = null)
    {
        _inner.Info(action, userCode, userName, ipAddress, extra);  // 写文件
        WriteToDb(action, extra, isSuccess: true);                  // 写数据库
    }

    public void Warning(string action, string? userCode = null, string? userName = null,
                        string? message = null)
    {
        _inner.Warning(action, userCode, userName, message);
        WriteToDb(action, message, isSuccess: false);
    }

    public void Error(string action, Exception? ex = null, string? userCode = null,
                      string? userName = null, string? ipAddress = null,
                      string? requestParams = null, int? statusCode = null)
    {
        _inner.Error(action, ex, userCode, userName, ipAddress, requestParams, statusCode);
        WriteToDb(action, ex?.Message, isSuccess: false);
    }

    public void LogApiCall(AuditLogEntry entry)
    {
        _inner.LogApiCall(entry);
        WriteToDb(entry.Action, entry.RequestParams, entry.IsSuccess);
    }

    public Task LogApiCallAsync(AuditLogEntry entry)
    {
        _inner.LogApiCallAsync(entry);
        WriteToDb(entry.Action, entry.RequestParams, entry.IsSuccess);
        return Task.CompletedTask;
    }

    private void WriteToDb(string action, string? detail, bool isSuccess)
    {
        var (module, actionName) = ParseAction(action);

        // ★ 从 extra/detail 中提取 Code（EntityService 传入 "Id=1, Code=abc123"）
        var targetCode = ExtractCode(detail);

        _sysLogService.LogAsync(new SysLogEntry
        {
            Module = module,
            Action = actionName,
            TargetCode = targetCode,   // ★ 业务 Code
            Detail = detail,
            IsSuccess = isSuccess
        });
    }

    private static (string module, string action) ParseAction(string action)
    {
        if (action.Contains("新增")) return (ExtractEntityName(action, "新增", "记录"), "Insert");
        if (action.Contains("更新")) return (ExtractEntityName(action, "更新", "记录"), "Update");
        if (action.Contains("删除")) return (ExtractEntityName(action, "删除", ""), "Delete");
        if (action.Contains("批量")) return (ExtractEntityName(action, "批量", ""), "Batch");
        return ("System", action);
    }

    private static string ExtractEntityName(string action, string prefix, string suffix)
    {
        var start = action.IndexOf(prefix, StringComparison.Ordinal) + prefix.Length;
        var end = string.IsNullOrEmpty(suffix) ? action.Length :
                  action.IndexOf(suffix, start, StringComparison.Ordinal);
        return start < end ? action[start..end] : "Unknown";
    }

    /// <summary>
    /// 从 EntityService 的 extra 参数中提取 Code 值
    /// extra 格式："Id=1, Code=abc123" 或 "Id=1, Code=abc123, Name=xxx"
    /// </summary>
    private static string? ExtractCode(string? detail)
    {
        if (string.IsNullOrEmpty(detail)) return null;

        foreach (var part in detail.Split(','))
        {
            var trimmed = part.Trim();
            if (trimmed.StartsWith("Code=", StringComparison.OrdinalIgnoreCase))
            {
                return trimmed["Code=".Length..];
            }
        }
        return null;
    }
}
```

### 5.4 ApiAuditFilter — API 请求级审计过滤器

```csharp
// CertPlatform.Admin/Filters/ApiAuditFilter.cs
namespace CertPlatform.Admin.Filters;

/// <summary>
/// API 请求级审计过滤器
/// 记录所有 API 请求的访问日志到 sys_log
/// </summary>
public class ApiAuditFilter : IAsyncActionFilter
{
    private readonly ISysLogService _sysLogService;

    // 排除路径（不记录日志）
    private static readonly string[] ExcludedPaths =
        ["/api/health", "/swagger", "/favicon", "/api/test"];

    public ApiAuditFilter(ISysLogService sysLogService)
    {
        _sysLogService = sysLogService;
    }

    public async Task OnActionExecutionAsync(
        ActionExecutingContext context,
        ActionExecutionDelegate next)
    {
        var path = context.HttpContext.Request.Path.Value ?? "";

        // 排除不需要审计的路径
        if (ExcludedPaths.Any(p => path.StartsWith(p, StringComparison.OrdinalIgnoreCase)))
        {
            await next();
            return;
        }

        var startTime = DateTime.UtcNow;

        // 执行 Controller
        var executedContext = await next();

        var durationMs = (DateTime.UtcNow - startTime).TotalMilliseconds;
        var statusCode = executedContext.HttpContext.Response.StatusCode;
        var httpMethod = context.HttpContext.Request.Method;

        // 从路由提取 Module 和 Action
        var (module, action) = ExtractRouteInfo(context);

        // 构造详情
        var detail = $"{httpMethod} {path} → {statusCode} 耗时{durationMs:F0}ms";

        // 如果有异常，附加异常信息
        if (executedContext.Exception != null && !executedContext.ExceptionHandled)
        {
            detail += $" 异常:{executedContext.Exception.Message}";
        }

        await _sysLogService.LogAsync(new SysLogEntry
        {
            Module = module,
            Action = action,
            Detail = detail,
            IsSuccess = statusCode < 400
        });
    }

    private static (string module, string action) ExtractRouteInfo(
        ActionExecutingContext context)
    {
        var controllerName = context.Controller.GetType().Name.Replace("Controller", "");
        var actionName = context.ActionDescriptor.RouteValues["action"]?.ToString() ?? "unknown";
        return (controllerName, actionName);
    }
}
```

### 5.5 ExceptionAuditFilter — 异常审计过滤器

```csharp
// CertPlatform.Admin/Filters/ExceptionAuditFilter.cs
namespace CertPlatform.Admin.Filters;

/// <summary>
/// 异常审计过滤器
/// 捕获所有未处理异常，写入 sys_log
/// 与 GlobalExceptionFilter 并存，不替换
/// </summary>
public class ExceptionAuditFilter : IExceptionFilter
{
    private readonly ISysLogService _sysLogService;

    public ExceptionAuditFilter(ISysLogService sysLogService)
    {
        _sysLogService = sysLogService;
    }

    public void OnException(ExceptionContext context)
    {
        var httpContext = context.HttpContext;
        var path = httpContext.Request.Path.Value ?? "";

        // 排除健康检查和 Swagger
        if (path.StartsWith("/api/health") || path.StartsWith("/swagger"))
            return;

        var controllerName = context.Controller?.GetType().Name.Replace("Controller", "") ?? "Unknown";
        var exceptionType = context.Exception.GetType().Name;

        _sysLogService.LogAsync(new SysLogEntry
        {
            Module = controllerName,
            Action = $"Exception:{exceptionType}",
            Detail = context.Exception.Message,
            IsSuccess = false
        });
    }
}
```
