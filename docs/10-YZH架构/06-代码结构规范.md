# 代码结构规范

> **版本**：V1.0 | **日期**：2026-09-10 | **状态**：编写中
>
> 本文档定义三层同构的代码组织结构，是 `docs/30-项目规则/前后端代码结构统一规则-V1.md` 的精简版。
> 新增模块时必须同时创建三层，禁止跳过任何一层。

---

## 一、层级定位

```
src/
├── yzh-core/                    ← 架构层（跨项目复用，可提取为 NuGet 包）
│   ├── YZH.Core.Stand/          基座：BaseEntity、EntityConfig、ITreeNode
│   ├── YZH.Core.Api/            业务通用层：YzhControllerBase、TreeTableControllerBase、EntityService
│   └── YZH.Core.Web/            启动入口 + 基础业务控制器
│       ├── Controllers/
│       │   ├── AuthController.cs           全局认证
│       │   └── System/                     基础管理（每项目都需要）
│       │       ├── UserController.cs
│       │       ├── RoleController.cs
│       │       ├── OrganizationController.cs
│       │       ├── MenuController.cs
│       │       ├── MenuManagementController.cs
│       │       └── DictionaryController.cs
│       └── Assets/EntityConfigs/
│           └── System/
│               ├── User.json
│               └── OrganizationForm.json
│
└── certplatform-api/            ← 项目层（认证平台业务，不可提取）
    └── CertPlatform.Admin/
        └── Controllers/
            ├── Foundation/         ISO标准体系主数据
            │   ├── ISOClauseController.cs
            │   ├── ISOStandardController.cs
            │   ├── CertificationBodyController.cs
            │   └── CertStageController.cs
            └── Workflow/          审核业务流程
                ├── EnterpriseController.cs
                ├── WorkflowController.cs
                ├── NcConfigController.cs
                └── ...
```

**黄金判断法则**：问自己"如果明天做一个完全不同的项目（CRM、ERP），这段代码还需要吗？"
- 需要 → 放 `YZH.Core.Web`（架构层）
- 不需要 → 放 `CertPlatform.Admin`（项目层）

## 三、三层同构规则

```
后端 Controller 文件路径  =  前端 API 文件路径  =  前端 Pages 文件夹路径

示例（重构后）：
  后端：YZH.Core.Web/Controllers/System/UserController.cs     → /api/System/User
  前端：cert/cert-share/src/api/system/user.ts                → /api/System/User
  前端：cert/cert-admin/src/pages/system/user/index.vue       → /system/user
```

### 域映射表

| 后端文件夹 | 前端 API 文件夹 | 前端 Pages 文件夹 | 路由前缀 |
|-----------|----------------|------------------|---------|
| `Controllers/System/` | `cert/cert-share/src/api/system/` | `cert/cert-admin/src/pages/system/` | `/system/` |
| `Controllers/Foundation/` | `cert/cert-share/src/api/cert/` | `cert/cert-admin/src/pages/foundation/` | `/foundation/` |
| `Controllers/Workflow/` | `cert/cert-share/src/api/workflow/` | `cert/cert-admin/src/pages/workflow/` | `/workflow/` |

> 注意：后端用 `Foundation/`，前端 API 用 `cert/`（kebab-case 更简洁）。

## 四、命名规范

### 4.1 文件/文件夹命名

| 层级 | 类型 | 命名规则 | 示例 |
|------|------|---------|------|
| 后端 | 控制器文件夹 | `Controllers/{Domain}/` (PascalCase) | `Controllers/System/` |
| 后端 | 控制器文件 | `{Type}Controller.cs` (PascalCase) | `UserController.cs` |
| 后端 | 实体文件夹 | `Models/{Domain}/` (PascalCase) | `Models/System/` |
| 后端 | 实体文件 | `{Type}.cs` (PascalCase) | `User.cs` |
| 后端 | EntityConfig | `Assets/EntityConfigs/{Domain}/{Type}.json` | `System/User.json` |
| 前端 | API 文件夹 | `cert/cert-share/src/api/{domain}/` (kebab-case) | `cert-share/src/api/system/` |
| 前端 | API 文件 | `{type}.ts` (kebab-case) | `user.ts` |
| 前端 | 页面文件夹 | `cert/cert-admin/src/pages/{domain}/{type}/` (kebab-case) | `cert-admin/src/pages/system/user/` |
| 前端 | 路由 path | `{domain}/{type}` (kebab-case) | `/system/user` |

### 4.2 类名/路由名命名

| 项 | 规则 | 示例 |
|----|------|------|
| Controller 类名 | `{Type}Controller` | `UserController`、`ISOClauseController` |
| 实体类名 | `{Type}` | `User`、`ISOClause` |
| API 导出函数 | `{action}{Type}` | `getUserPage`、`addISOClause` |
| Vue Router name | `{Domain}{Type}` | `SystemUser`、`FoundationIsoClause` |
| 路由 path | `{domain}/{type}` | `/system/user`、`/foundation/iso-clause` |

## 五、路由约定

> **前端 import alias（当前）**：`@share` → `../cert/cert-share/src`、`@yzh-core` → `../yzh.vue.core/src`

```
控制器位置                              Route 特性                        最终 URL
────────────────────────────────────────────────────────────────────────────────
YZH.Core.Web/Controllers/AuthController.cs        [Route("api/[controller]")]      /api/Auth
YZH.Core.Web/Controllers/System/UserController.cs  [Route("api/System/[controller]")] /api/System/User
CertPlatform.Admin/Controllers/Foundation/ISOClauseController.cs  [Route("api/Foundation/[controller]")] /api/Foundation/ISOClause
CertPlatform.Admin/Controllers/Workflow/EnterpriseController.cs   [Route("api/Workflow/[controller]")]   /api/Workflow/Enterprise
```

> `[controller]` 自动替换为类名去掉 "Controller" 后缀。

## 六、新增模块完整流程

### 场景：新增「ISO条款管理」模块

**Step 1：创建后端实体**

```
src/yzh-core/YZH.Core.Api/Models/Foundation/ISOClause.cs
```

```csharp
[SugarTable("Cert_ISOClause")]
public class ISOClause : BaseEntity
{
    public string ClauseCode { get; set; } = "";
    public string ClauseName { get; set; } = "";
    public string StandardCode { get; set; } = "";
    public int Enable { get; set; } = 1;
}
```

**Step 2：创建 EntityConfig JSON**

```
src/yzh-core/YZH.Core.Web/Assets/EntityConfigs/Foundation/ISOClause.json
```

**Step 3：创建后端 Controller**

```
src/certplatform-api/CertPlatform.Admin/Controllers/Foundation/ISOClauseController.cs
```

```csharp
[ApiController]
[Route("api/Foundation/[controller]")]
public class ISOClauseController : YzhControllerBase<ISOClause>
{
    public ISOClauseController(EntityService<ISOClause> entityService, IUserContext userContext)
        : base(entityService, userContext) { }
}
```

**Step 4：创建前端 API 文件**

```
src/certplatform-web/cert/cert-share/src/api/cert/iso-clause.ts
```

```typescript
import { yzhApi } from '@yzh-core/api/client'
import type { ApiResponse, PagedData } from '@share/types/contracts'

export function getISOClausePage(params: any) {
    return yzhApi.post<ApiResponse<PagedData<ISOClause>>>('/api/Foundation/ISOClause/filter', params)
}

export function addISOClause(data: Partial<ISOClause>) {
    return yzhApi.post<ApiResponse<ISOClause>>('/api/Foundation/ISOClause/add', data)
}

export function updateISOClause(data: Partial<ISOClause>) {
    return yzhApi.post<ApiResponse<ISOClause>>('/api/Foundation/ISOClause/update', data)
}

export function deleteISOClause(codes: string[]) {
    return yzhApi.post<ApiResponse<string>>('/api/Foundation/ISOClause/delete', codes)
}
```

**Step 5：创建前端页面**

```
src/certplatform-web/cert/cert-admin/src/pages/foundation/iso-clause/index.vue
```

```vue
<script setup lang="ts">
import { YzhTable } from '@yzh-core/components/table'
import { onMounted, ref } from 'vue'
import { ISOClauseLogic } from './logic'

const logic = new ISOClauseLogic()
onMounted(async () => { await logic.init() })
</script>

<template>
  <YzhTable
    :columns="logic.columns"
    :data-loader="logic.loadPage.bind(logic)"
    :search-fields="logic.searchFields"
  />
</template>
```

**Step 6：注册路由**

```typescript
// cert/cert-admin/src/router/index.ts
{ path: 'foundation/iso-clause', component: () => import('@/pages/foundation/iso-clause/index.vue') }
```

## 八、Foundation 域 vs Workflow 域区分

| 域 | 定位 | 数据特征 | 示例 |
|----|------|---------|------|
| **Foundation** | ISO 标准体系主数据 | 静态、变化少 | ISO标准/条款/认证机构/认证阶段 |
| **Workflow** | 审核业务流程配置与运行 | 动态、频繁变更 | 企业/工作流/NC规则/模板/报告规则/目录/提取规则/技能/队列 |
