# 前端分层与宿主接入规范 V1

> **本文回答两个问题**：① 为什么有 `yzh.vue.core`？② 它和前端项目（宿主）到底怎么结合？
> **本文是「接缝」的唯一权威** —— 三层边界、引用方式、宿主接入步骤、6 个接缝契约。
> **上游**：`18-YZH架构规则-V1.md` §二（结构规则）｜**下游**：`03-前端架构.md`（内核与组件细节）

---

## 一、三层结构与存在理由

### 1.1 三层定义

```
src/certplatform-web/
├── yzh.vue.core/                 ← ① 框架层（跨项目复用；不启动、不感知后端地址）
│   ├── src/components/           ← 原子组件（零领域依赖，守卫 R1）
│   ├── src/logic/                ← 逻辑内核（SingleTableCore / TreeTableCore / …）
│   ├── src/adapters/             ← 适配层（EntityConfig → 组件契约，纯函数）
│   ├── src/api/                  ← 原子 API（yzhApi + configureYzhApi + auth + system/*）
│   ├── src/pages/ layouts/ router/ ← 原子界面与路由（system 11 页 + 登录 + 应用壳）
│   ├── src/composables/          ← 装配层（useSingleTable / useTreeTable / …）
│   └── src/{types,utils}/        ← 契约类型与工具
│
├── cert/cert-share/              ← ② 跨端业务共享层（admin + auditor 共用）
│   └── src/{api,components,composables,types,utils}/
│
└── cert/cert-admin/              ← ③ 宿主（独立可运行；端口 9990）
    cert/cert-auditor/            ←    端口 9991
    cert/cert-enterprise/         ←    ⚠️ 未开工
```

### 1.2 为什么必须有 `yzh.vue.core`（三个理由）

**理由 ①：一份代码三端复用。**
`admin` / `auditor` / `enterprise` 三端要跑**同一套 system 11 页 + 登录页 + 应用壳**。
没有 core → 三份拷贝。**证据已经在发生**：

| 已重复的文件 | 行数 | 现状 |
|---|---|---|
| `cert-admin/src/App.vue` ↔ `cert-auditor/src/App.vue` | 15 | **逐字相同** |
| `cert-admin/src/store/auth.ts` ↔ `cert-auditor/src/store/auth.ts` | 20 | **逐字相同**（且都自述"薄适配层"） |

→ 这两个文件的正确归宿就是 core。

**理由 ②：架构约束需要物理载体。**
约束要能被机器检查，就必须有一个**可扫描的物理边界**。
守卫 **R1**（原子组件零领域依赖）的扫描根就是 `yzh.vue.core/src/components/` —— **没有这个目录，R1 无从下手**。
→ **core 是"约束的抓手"，不只是"代码的容器"。**

**理由 ③：与参考项目家族同构。**

| 参考项目（`work/work/`） | 本项目 | 角色 |
|---|---|---|
| `YZH架构/YZH.WPF.Core` | **`yzh.vue.core`** | 框架层（跨项目） |
| `房产测绘系统/src/Share/YZH.Survey.Lib` | **`cert-share`** | 跨项目业务共享层 |
| `测绘成果管理系统/YZH.SurveyResult.Lib` | **cert-admin / cert-auditor / cert-enterprise** | 业务项目（宿主） |
| `YZH架构/YZH.Stand` | `YZH.Core.Stand`（后端） | 跨栈共享契约 |

证据：`YZH.SurveyResult.Lib.csproj` 同时 `ProjectReference` 三者 → **三层分明，不是临时堆叠**。

### 1.3 ★ 结论

> **不是"要不要 core"的问题，而是"core 与宿主之间的接缝没有写下来"。**
> 本文 §三 把 6 个接缝逐个写成契约。

## 二、现在实际是怎么结合的（三条链路）

### 2.1 构建期：源码 alias（不走 dist）

| 位置 | 配置 |
|---|---|
| `yzh.vue.core/package.json` | `"main": "src/index.ts"`（**源码入口**） |
| 宿主 `vite.config.ts` | `{ find: '@yzh-core', replacement: '../../yzh.vue.core/src' }`<br>`{ find: '@share', replacement: '../cert-share/src' }` |
| 宿主 `tsconfig.json` | `paths: { "@yzh-core/*": ["../../yzh.vue.core/src/*"], "@share/*": ["../cert-share/src/*"] }` |

→ **App 构建从源码编译核心库**，`yzh.vue.core/dist/` 不参与宿主构建。

### 2.2 启动期：宿主注入后端地址（core 零硬编码）

```ts
// 宿主 src/main.ts（每个端都要有）
import { configureYzhApi } from '@yzh-core/api/client'
configureYzhApi({ baseURL: import.meta.env.VITE_API_BASE ?? '' })   // 缺省 '' 走 vite proxy / 同源
```

守卫 **R11** 保证 `yzh.vue.core/src` 内不出现 `127.0.0.1` / `localhost:port` / `http(s)://`。

### 2.3 装配期：宿主拼路由

core 导出 `yzhLoginRoute` / `yzhHomeRoute` / `yzhSystemRoutes` / **`createYzhRoutes(options)`**。
`createYzhRoutes` 一次组装：登录页 + `YzhAppLayout` 壳 + 首页 + system 11 页 + 宿主业务页。

## 三、接缝契约（6 条，逐条写死）

### S1 引用方式：**alias 唯一**

| 目标 | ✅ 唯一正确写法 | ⛔ 禁止 |
|---|---|---|
| 框架层 | `@yzh-core` / `@yzh-core/api/client` / `@yzh-core/composables/*` | `yzh.vue.core/*` |
| 共享层 | `@share` / `@share/components/*` / `@share/api/*` | `@certplatform/share` |

**为什么**：两套机制并存时**改一处不会改另一处**。
**实测违规**：`@certplatform/share` 在 4 个 `package.json` 里声明为 workspace `file:` 依赖，**代码 0 引用**；`yzh.vue.core/types` 有 2 处（`cert-share/src/api/workflow/{job-skill,ai-usage}.ts`）。
**守卫**：待补 **R13**。

**⚠️ 待决策**：`package.json` 里 `file:` 依赖是否一并删除（见计划 D-02）。

### S2 宿主装配：**用 `createYzhRoutes`，不手写 routes 表**

**契约**：
```ts
// ✅ 推荐
const routes = createYzhRoutes({
  menuTag: 'admin',
  branding: { appTitle: '映智汇认证平台' },
  businessRoutes: [
    { path: 'cert/iso-standard', component: () => import('@/pages/foundation/iso-standard/index.vue') },
  ],
  home: false,      // 或传自定义首页 RouteRecordRaw
})

// ⛔ 现状（cert-admin/src/router/index.ts）：手写整张表，只借用了 yzhSystemRoutes
```

**为什么**：`path` 必须**单一来源**（core 的注释原文："二选一，永不双注册同一 path"）。手写表会让 core 新增 system 页时宿主漏挂，且 path 容易与 core 冲突。

**⚠️ 例外**：宿主**有意**要换皮肤 / 改首页时，按 core 契约"整条手写覆盖本 path"是允许的（path 单一来源原则优先）。

### S3 依赖安装：**禁止跨项目 symlink**

**契约**：每个包用**自己的** `node_modules`（npm workspaces 已提供提升），**不得**把 `node_modules` 软链到旧项目。

**现状违规**：3 处 `node_modules_link` 指向 `src/server/Vue.NetCore/vol.web/node_modules`（`yzh.vue.core` / `cert-auditor` / `cert-share`）。
**副作用证据**：两个 `vite.config.ts` 都加了 `cacheDir` 并注释 **"避免符号链接导致的路径解析问题"** = 已经踩过坑。
**处置**：清理涉及旧项目目录，风险 > 收益 → **暂缓**，但**新端禁止再建 symlink**。

### S4 宿主完整性：**新端必须四件套齐备**

| 文件 | 必需 | 说明 |
|---|---|---|
| `package.json` | ✅ | 含 `dev` / `build`（`build` 首步必须是 `node ../../scripts/guards.mjs`） |
| `index.html` | ✅ | **项目根**，Vite 约定位置（⛔ 不要放在 `src/`） |
| `vite.config.ts` | ✅ | `@` / `@yzh-core` / `@share` 三个 alias + `server.port` + `/api` proxy |
| `tsconfig.json` | ✅ | `paths` 与 vite alias **一一对应** |

**现状违规**：`cert-enterprise` **缺 `index.html` 与 `vite.config.ts`** → `npm run dev` 结构性不可能成功；且 `package.json` 缺 `element-plus`（而 `@certplatform/share` 的 `peerDependencies` 要求它）。
**处置**：标注"未开工" + 移出 `workspaces`（见计划 D-04）。

### S5 类型检查范围：**core 必须被 typecheck**

**契约**：`core` 的 `typecheck`（`vue-tsc --noEmit`）**必须独立跑**，且纳入 `npm run typecheck:all`。

**现状问题**：宿主 `tsconfig.json` 的 `include: ["src/**/*.ts", "src/**/*.vue", "vite.config.ts"]` + `skipLibCheck: true` → **宿主 `vue-tsc` 不检查 core 源码**。
→ 若 core 自身有类型错误，宿主构建**照样通过**。
**验证**：`cd src/certplatform-web && npm run typecheck:all`（`--workspaces --if-present`）

### S6 守卫范围：**新增端必须登记**

**契约**：新增宿主端 → 必须在 `scripts/guards.mjs` 的 `PAGE_ROOTS` / `API_ROOTS` 登记，否则该端处于**守卫盲区**。

**当前盲区（实测 6 处）**：`core/logic`｜`core/utils`｜`core/types`+`adapters`｜`cert-share/src/{components,composables,utils,logic}`｜`cert-admin/src/{store,composables,router,layouts}`｜`package.json`。
→ 修复见 `18-YZH架构规则-V1.md` §7.2（R12/R13/R14 + 扩 roots）。

## 四、宿主接入 checklist（新端从零开始）

```bash
# 1. 建目录（与 cert-admin 同构）
mkdir -p cert/cert-xxx/src/{pages,api,store,router,layouts}

# 2. 四件套（见 S4）
#    package.json / index.html / vite.config.ts / tsconfig.json
#    vite.config.ts 的 alias 必须与 tsconfig.json 的 paths 一一对应

# 3. main.ts（与 cert-admin/src/main.ts 逐行一致，仅品牌文案不同）
#    configureYzhApi({ baseURL: import.meta.env.VITE_API_BASE ?? '' })
#    注册 Element Plus + 图标 + zhCn 语言包

# 4. router（用 createYzhRoutes，见 S2）
#    menuTag 决定侧栏菜单 Tag 分流

# 5. 登记守卫（见 S6）：把 pages/ 与 api/ 加进 guards.mjs

# 6. 验证
cd src/certplatform-web
node scripts/guards.mjs          # → 1 行通过
npm run typecheck:all            # → 含 core
npm run dev:xxx                  # → 起得来
```

## 五、边界速查（"该放哪"）

| 我有一段代码… | 放哪 | 判据 |
|---|---|---|
| 所有项目都需要（表格/表单/树/弹窗/分页） | `yzh.vue.core/src/components/` | **零领域依赖**（守卫 R1） |
| 所有项目都需要（CRUD 编排/生命周期） | `yzh.vue.core/src/logic/` | 换个业务实体**原样复用** |
| 所有项目都需要（System 域页面/登录/壳/路由） | `yzh.vue.core/src/{pages,layouts,router}/` | 换个项目**照抄不改** |
| 本项目多端共用（认证业务/工作流） | `cert/cert-share/src/` | 跨端（admin+auditor） |
| 单端专属 | `cert/cert-{admin,auditor,enterprise}/src/` | 只此一端用 |
| 不确定 | **先放宿主，出现第二个消费方再上移** | 上移成本 < 猜错成本 |

**★ 上移规则**：出现**第二个消费方**时才上移，且上移时**必须同步**：`package.json exports` / `vite alias` / `tsconfig paths` / `guards.mjs roots`。
