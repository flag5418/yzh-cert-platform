## 二、设计不合理（P1）— 建议本次迭代修复

### P1-001：基类方法异常捕获设计（已确认，无需修改）

| 项目 | 内容 |
|------|------|
| **位置** | `YzhControllerBase.cs` 每个 Core 方法 |
| **设计说明** | try-catch 是**有意设计**，用于精准捕获原子操作异常，返回具体业务错误信息 |
| **架构原则** | 双层防御：基类捕获「已知异常」→ 全局过滤器兜底「未知异常」 |
| **结论** | ✅ 设计合理，无需修改 |

```csharp
// 当前设计（保持）
public virtual async Task<Result<V>> AddCore(V entity)
{
    try
    {
        var (valid, msg) = ValidateEntity(entity);
        if (!valid) return Result<V>.Fail(msg);

        var (ok, cancelMsg) = await OnBeforeAdd(entity);
        if (!ok) return Result<V>.Fail(cancelMsg ?? "操作已取消");

        var result = await Entity.Insert(entity, UserContext.ClientIp);
        if (!result.Success) return Result<V>.Fail(result.Error);

        await OnAfterAdd(result.Data!);
        await OnAfterCommitted();

        return Result<V>.Ok(result.Data!);
    }
    catch (Exception ex)
    {
        // 精准捕获：返回具体错误信息，前端可定位问题
        return Result<V>.Fail($"新增异常：{ex.Message}");
    }
}

// 全局过滤器职责：
// - 捕获基类未处理的异常（如数据库连接失败、空指针等）
// - 记录完整堆栈日志
// - 返回兜底响应格式
```

### P1-002：EntityService 使用 dynamic 填充审计字段

| 项目 | 内容 |
|------|------|
| **位置** | `YZH.Core.Api/Services/EntityService.cs` |
| **现象** | `dynamic dyn = entity; try { dyn.CreateTime = ... } catch { }` |
| **风险** | 属性名拼写错误静默失败，审计字段不填充，数据库审计日志缺失 |
| **修复** | 改用 `GetProperty()` 反射，属性不存在时记录警告日志 |

```csharp
// 修复方案
private void FillCreateAudit(T entity)
{
    var type = typeof(T);
    var createTimeProp = type.GetProperty("CreateTime");
    if (createTimeProp != null)
        createTimeProp.SetValue(entity, DateTime.UtcNow);
    else
        _logger.LogWarning("实体 {Type} 缺少 CreateTime 属性", typeof(T).Name);
    // ... 其他字段同理
}
```

### P1-003：TreeTableControllerBase 树过滤逻辑与基类冲突

| 项目 | 内容 |
|------|------|
| **位置** | `YZH.Core.Api/Controllers/TreeTableControllerBase.cs` |
| **现象** | `FilterCore` 覆盖后修改 `request.Filters`，但基类又会再次调用 `OnBuildingFilter`，可能导致条件重复注入 |
| **风险** | 树过滤条件与租户隔离等全局条件冲突，数据查询结果错误 |
| **修复** | 将树过滤逻辑提取为 `OnInjectTreeFilter` 虚方法，在基类 `FilterCore` 中统一调用 |

```csharp
// YzhControllerBase.cs — 新增虚方法
protected virtual void OnInjectTreeFilter(List<FilterItem> filters) { }

// 在 FilterCore 中调用
filters = OnInjectTreeFilter(filters);  // 新增
filters = OnBuildingFilter(filters);     // 原有
```

### P1-004：硬编码默认密码和 JWT Key

| 项目 | 内容 |
|------|------|
| **位置** | `YZH.Core.Web/YzhWebBuilder.cs` |
| **现象** | `PasswordSecret` 和 `JwtSettings:SecretKey` 有硬编码默认值 |
| **风险** | 默认 Key 泄露后攻击者可伪造 Token，所有系统使用相同 Key |
| **修复方案** | 移除默认值，强制要求配置 |
| **用户决策** | ⚠️ 通过 git 限制提交，暂不修改代码 |

```csharp
// 当前代码（有兜底默认值）
var passwordSecret = builder.Configuration["PasswordSecret"] ?? "C5ABA9E202D94C43A3CA66002BF77FAF";
var secretKey = jwtSettings["SecretKey"] ?? "AA3627441FFA4B5DB4E64A29B53CE525";

// 推荐修复（移除兜底）
var passwordSecret = builder.Configuration["PasswordSecret"]
    ?? throw new InvalidOperationException("必须配置 PasswordSecret");
var secretKey = jwtSettings["SecretKey"]
    ?? throw new InvalidOperationException("必须配置 JwtSettings:SecretKey");
```

### P1-005：JWT ClockSkew 不一致

| 项目 | 内容 |
|------|------|
| **位置** | `Program.cs` vs `JwtHelper.cs` |
| **现象** | JWT 中间件 `ClockSkew = 5分钟`，但 `JwtHelper.ValidateToken` 使用 `ClockSkew = 0` |
| **风险** | 时间不同步时部分请求验证失败，行为不一致 |
| **修复** | 统一使用 `ClockSkew = TimeSpan.FromMinutes(5)` |
