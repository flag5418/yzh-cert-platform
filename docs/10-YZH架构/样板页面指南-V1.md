# 样板页面指南 - V1

> **本文件是新建前端页面的唯一入口。** AI 编码助手在生成任何 `pages/**` 代码前**必须先读本文件**。
>
> **一句话规则**：新建页面 = **照抄下面指定的 1 个样板，改 5 处**。
> **不要**参考其他任何页面，**不要**自创写法。样板之外的页面都是待迁移的历史形态。

## 一、样板指定（唯一权威）

> ✅ **2026-09-24 P8 收口**：system 11 页面已全部迁入 `yzh.vue.core/src/pages/system/`。
> 单表/纯树样板**正式切换至 core**；宿主（cert-admin 等）只组装路由，不再持有 system 页面源码。

| 场景 | 唯一样板 | 规模 | 说明 |

| **纯树节点 CRUD**（左树 + 右详情） | `yzh.vue.core/src/pages/system/role/` | `index.vue` 183 行 + `logic.ts` **16 行** | logic **零覆写**；`index.vue` 里大部分是布局与 CSS，可直接照搬骨架 |

**没有样板可抄的情况** → 先在此文件登记新样板，再写代码。不要"先写一个再看看"。

## 二、照抄单表样板（标准流程）

### 步骤 1：后端先就位（前端抄之前必须完成）

1. 后端控制器：`src/certplatform-api/CertPlatform.Admin/Controllers/{域}/{实体}Controller.cs`
   - 继承 `YzhControllerBase<{实体}>`（**禁止**裸 `ControllerBase`）
   - 三层同构：`{域}/{实体}` 与前端页面目录同名同路径
2. EntityConfig：`src/yzh-core/YZH.Core.Web/Assets/EntityConfigs/{域}/{实体}.json`
   - `Columns[]` 驱动表格列 + 表单字段 + 搜索字段
   - `XsFlag` = 是否在表格显示；`BcFlag` = 是否在表单显示/可编辑

> 后端没就位就写前端 → 必然手搓 `yzhApi` 调用，**这是 AI 绕过架构的头号入口**。

### 步骤 2：前端照抄

```bash
# 系统底座页（system/**）→ 抄 core 样板，落 core 或宿主均可，路径与后端 System 控制器同构
cp -r yzh.vue.core/src/pages/system/user yzh.vue.core/src/pages/{域}/{实体}
# 业务页 → 抄 core 单表样板，落宿主 pages/{域}/{实体}
cp -r yzh.vue.core/src/pages/system/user cert/cert-admin/src/pages/{域}/{实体}
```

然后按下面「必须改的 5 处」逐项修改。

### 步骤 3：自检

```bash
cd src/certplatform-web
node scripts/guards.mjs          # 必须 0 违规
cd cert/cert-admin && npm run build   # 必须通过（含 vue-tsc）
```

## 三、照抄时必须改的 5 处（漏一处就跑不起来）

| # | 文件 | 位置 | 改成什么 |
|---|---|---|---|
| **1** | `logic.ts` | 类名 `export class UserLogic` | 改成 `{实体}Logic`（如 `PhaseDefinitionLogic`） |
| **2** | `logic.ts` | `controllerName = 'System/User'` | 改成后端控制器路径（如 `'Foundation/PhaseDefinition'`） |
| **3** | `logic.ts` | 末行 `export default UserLogic` | 同步改成新类名 —— **最常漏的一处** |
| **4** | `logic.ts` | `protected override get defaultValues()` | 按业务改新增默认值；**无默认值就删掉整个 override**（不要留空对象） |
| **5** | `index.vue` | `import { UserLogic } from './logic'` + 根节点 `class="user-page"` | 同步改类名；`user-page` 改成 `{实体}-page`（含 `<style scoped>` 里的选择器） |

> **不要改**：`useSingleTable(...)` 的调用方式、`YzhTable` / `YzhFormDialog` 的 props 与事件绑定。
> 那些是内核契约，改了就会失去"零手写 CRUD"。

## 四、左树右表怎么抄

只抄 **3 样**，其余自己写：

```ts
// logic.ts —— 抄这 3 样
import { TreeTableLogic } from '@yzh-core'

export class XxxLogic extends TreeTableLogic<any> {
  controllerName = '{域}/{实体}'

  // ① 覆写 dataLoader：右表数据源（左树选中项 → 右表行）
  async dataLoader(params: {...}): Promise<{ rows: any[]; total: number }> { ... }

  // ② 覆写 rowActions：追加自定义行按钮（先展开基类 super.rowActions）
  override get rowActions(): YzhAction[] { ... }

  // ③ 覆写 formFields：改写个别字段控件（先展开基类 super.formFields）
  override get formFields(): YzhFormField[] { ... }
}
export default XxxLogic
```

`index.vue` 照抄 `yzh.vue.core/src/pages/system/role/index.vue` 的 `YzhTreeTableLayout` 骨架 + `useTreeTable(XxxLogic)`。
**不要**自己 `new XxxLogic()` + 手搓 ref（`iso-standard/index.vue` 就是这种旧写法，属待收敛项）。

## 五、硬约束（守卫生效，违规即构建失败）

`src/certplatform-web/scripts/guards.mjs` 已接入**全部 4 个前端包的 `build`**，以下为机器强制：

| 规则 | 内容 |
|---|---|
| **R1** | `yzh.vue.core/src/components/**` 原子组件**零领域依赖**：禁 `@share/*`、`@/api`、`*/logic`、`pinia`、`vue-router` |
| **R2** | `TreeNode` 一律 **PascalCase** 读取：`node.Code` / `node.Name` / `node.Extra` / `node.Children` / `node.IsLeaf` / `node.ParentCode`。禁 `node.code` 等小写 |
| **R3** | 统一 `ApiResponse` 契约：**禁** `res.code === 200`，判成功用 `res.success` |
| **R4** | **禁 `axios`** —— 一律 `yzhApi`（`@yzh-core/api/client`） |
| **R5** | **禁 `.vue` 内直接 `fetch(`** —— 走 `yzhApi` 或 `api` 模块 |
| **R6** | **禁页面内联 `<el-table`** —— 一律 `YzhTable`（含 `<el-table-column>`，正则 `/<el-table\b/`） |

### 5.1 守卫的执行入口与零噪音契约

**三个入口**（缺一不可，任何入口都无法绕过）：

| 入口 | 触发时机 | 说明 |
|---|---|---|
| 包级 `build` | 每次构建 | `cert-admin` / `cert-auditor` / `cert-enterprise` / `cert-share` / `yzh.vue.core` 各自的 `npm run build` 首步 |
| `pre-commit` | 每次提交 | 由 `bash scripts/install-hooks.sh` 安装到 `.git/hooks/pre-commit`；跳过用 `git commit --no-verify` |
| 手动 | 按需 | `npm run guard` / `npm run guard:report`（全量盘点） |

**⛔ 严禁挂到 `dev` 脚本**——Vite 热更新会反复触发，刷屏干扰调试。

**🔇 零噪音契约**（机器保证，勿破坏）：

- 通过 → **只输出 1 行**（`✓ 前端架构守卫通过（7 条规则 / N 个文件）`），不产生任何 WARN
- 失败 → 只输出失败规则及 `文件:行号` 定位，不输出通过项
- 债务盘点（已知待修项）→ **仅 `--report` 可见**，绝不出现在日常构建中

> 目的：守卫输出「要么为空，要么全是真问题」，避免调试时把历史债务误判为新错误。

### 5.2 规则启用铁律：基线必须为 0

新增规则前**必须先量基线**。基线 ≠ 0 时：

- 存量走 `debt` 白名单豁免（路径包含匹配），**随修复逐条删除**
- 禁止为「先跑起来」而调低阈值或加 `--report` 到构建链路

反例：R6 的 `<el-table` 在 `cert-admin` 存量 **97 处 / 11 文件**（已冻结，见 `debt`）；
在 `cert-auditor` / `cert-enterprise` 基线为 **0**，故可立即强制。
若当初把 cert-admin 一并强制，97 条报错会淹没真问题 → 规则立即失效。

**例外（不受 R3 约束，必须注释标注「已登记例外」）**：

- **E6** 裸 JSON `{ img, uuid }` —— `api/User/getVierificationCode`（登录页用）。判法：`curl` 看顶层有无 `success`/`data`，没有 → 字段就在顶层。
- **E7** `{ code, data, message }`（**有 `code` 无 `success`**）+ PascalCase payload —— `DocExtractionRuleController` 全系列 15 端点。判法：必须用 `res.code === 200`、读 `res.data`，**禁止 `res.success`**（恒 `undefined` → 静默走失败分支且不报错）。

**铁律**：DB列名 = C#属性名 = TS字段名 = **PascalCase 逐字一致**。
→ 前端读业务行一律 `row.RuleName`、`row.StandardCode`；写成 `row.ruleName` 会**渲染成空行且无任何报错**。

**数据访问分层**（`logic.ts` 注释里已写明，照抄时保留）：

- `res.data` → `ApiResponse` 顶层（camelCase：`success`/`message`/`data`/`code`/`timestamp`）
- 业务行 `r` → PascalCase 字段（`r.Code`、`r.StandardCode`、`r.Enable`）
- `TreeNode` → 统一 PascalCase
- `formData` → PascalCase key（`YzhForm` 双向绑定）

## 七、AI 常见犯错对照表

| AI 常写的 | 正确写法 |
|---|---|
| `import axios from 'axios'` | `import { yzhApi } from '@yzh-core/api/client'` |
| `.vue` 里 `await fetch('/api/...')` | 交给 `logic.ts` + `SingleTableCore`/`yzhApi` |
| 手写 `handleAdd` / `handleBatchDelete` / `handleRowAction` / `handleSubmit` | **全部删掉**，由 `useSingleTable` 内核派发 |
| `if (res.code === 200)` | `if (res.success)` |
| `row.ruleName` / `node.name` | `row.RuleName` / `node.Name` |
| `class XxxLogic extends SingleTableCore<T>` 后自己写 `dataLoader` | 单表**不要**覆写 `dataLoader`，交给 EntityConfig |
| 新建 `pages/{域}/{实体}/api.ts` | 放 `cert-share/src/api/{域}/{实体}.ts` |
| 页面里 `import { useStore }` 取用户信息 | 页面层不直接取 store；需要时走 `logic.ts` |
| 页面里内联 `<el-table>` / `<el-table-column>` | 一律 `<YzhTable>`（守卫 **R6** 强制） |
| 用 `view-grid` / `VolBox` / `VolForm` / `VolProvider` | ⛔ V4 已彻底废弃，一律 `YzhTable` + `YzhForm` |
| 后端控制器一律硬套 `: ControllerBase`，或反过来把「没继承基类」当违规 | 按职能选：CRUD 形态用 `: YzhControllerBase<{实体}>` / `: TreeTableControllerBase<T, V>`；职能特殊的直继承 `ControllerBase` **属正常**，详见下方说明 |

### 7.1 后端基类的正确认知（2026-09-23 澄清，勿再误判）

**抽象基类只覆盖一部分后端形态。「未继承基类」≠ 违规。**

`YzhControllerBase<V>` / `TreeTableControllerBase<T,V>` 抽象的是**单表 / 左树右表**这两类最常见形态，
解决不了全部后端问题。以下控制器因职能不同，**直接继承 `ControllerBase` 是允许的**：

`QueueMonitorController`（队列监控）、`WorkflowTestController`（工作流测试）、
`AuditorAuthController`（专家端认证）、`StandardDirectoryController`（目录树，33 端点）、
`DocExtractionRuleController`（文档提取规则，15 端点）、`ReportDefinitionController`、
`AIUsageController`、`DirectoryTemplateController`、`CertOrgStageController`、`CertOrgStandardController`。

**判断一个控制器是否合规，看行为契约，不看 `:` 后面写了什么：**

| # | 行为契约 | 机器保障 |
|---|---|---|
| ① | 未登录一律 **401** | 全局 `PermissionFilter`（`Program.cs` 注册），无需逐控制器声明 |
| ② | 响应走 `ApiResponse` 信封 | 已登记例外 E6 / E7 除外 |
| ③ | DB列名 = C#属性名 = TS字段名（PascalCase 逐字一致） | `BizNamingRules`（启动期）+ 守卫 R2 |

> ⚠️ **反向提醒**：`RequirePermission` 是 **opt-in**，全仓声明数为 **0** → 当前**授权（角色隔离）未启用**，
> 只要登录即可访问任意端点。这是待补的 P0 项，与「继承哪个基类」无关。
