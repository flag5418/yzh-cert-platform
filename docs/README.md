## 一、七层结构

按**维度**划分——看主题即可归位，不需要记阅读顺序。

| 层 | 目录 | 回答什么问题 | 变更频率 |
|:--:|------|--------------|:--------:|
| 0 | [`00-工程体系/`](./00-工程体系) | 项目全貌、怎么启动、术语、文档规范 | 低 |
| 1 | [`10-YZH架构/`](./10-YZH架构) | **YZH 框架**：怎么写代码 + 框架自己长什么样 | 中（随框架版本） |
| 2 | [`20-体系认证/`](./20-体系认证) | **业务系统**：总体设计、数据库、详细设计、业务知识 | 高（随业务需求） |
| 3 | [`30-项目规则/`](./30-项目规则) | 编码规范、命名规则、代码结构规则、技术知识库 | 中 |
| 4 | [`40-实施/`](./40-实施) | 各阶段实施报告、问题追踪 | 低（归档性） |
| 5 | [`50-任务/`](./50-任务) | 当前待办、迁移工作台 | 高 |
| 6 | [`90-归档/`](./90-归档) | 历史项目资料、旧版本、废弃内容 | 只增不改 |

### 边界判定

| 疑问 | 规则 |
|------|------|
| 这条内容归框架还是项目？ | 问"**换个项目还成立吗**"——成立归 `10-YZH架构/`，不成立归 `20-体系认证/` |
| 这是规范还是知识？ | **强制遵守**的归 `30-项目规则/`；**按需查阅**的归 `30-项目规则/知识库/` |
| 这份文档过期了吗？ | 本项目旧版本 → `90-归档/旧版本/`；旧系统知识（长期有效）→ `90-归档/历史项目/` |

## 三、当前状态提示

> ⚠️ **YZH 框架处于半成品状态**。近阶段工作重心即为完善其底层支撑体系。
> 判断某项能力是否可用，**以 [`10-YZH架构/12-框架能力清单-V1.md`](./10-YZH架构/12-框架能力清单-V1.md) 为准**。

> 1. `10-YZH架构/11-接口权限自动同步设计-V1.md` 是**未落地的设计稿**（`sys_api` 等三张表不存在）。

## 五、维护约定

1. **新增文档**：先判断归属层，再放入对应目录，并在该层 `README.md` 登记。
2. **文档命名**：强制 `-V1` 后缀（见 [`00-工程体系/文档生命周期管理规范-V1.md`](./00-工程体系/文档生命周期管理规范-V1.md)）。
3. **文档文头**：建议加 YAML front-matter（`doc` / `version` / `status` / `impl` / `layer` / `role` / `domain` / `updated` / `owner` / `related`）。
4. **废弃文档**：**不删除**，移入 `90-归档/` 对应子目录。
5. **状态标记**：`生效` / `编写中` / `设计稿` / `已废弃`。
