## 问题回顾

### 问题1：http.js中put未定义
- **现象**：前端报错 `Uncaught ReferenceError: put is not defined`
- **原因**：修改export语句时写成了 `export default { post, get, put, ... }` 而非 `put: ajax.put`
- **教训**：
  1. 修改框架代码前必须先理解原有结构
  2. 使用`git diff`查看修改内容
  3. 修改后立即语法检查

### 问题2：MinIO客户端未注册到DI容器
- **现象**：启动失败 `Unable to resolve service for type 'Minio.IMinioClient'`
- **原因**：创建了`MinIOHelper`类但忘记注册`IMinioClient`
- **教训**：
  1. 新增Helper服务时必须同时注册依赖
  2. 使用`builder.Services.AddSingleton<IMinioClient>(...)`注册
  3. 启动后立即检查日志

### 问题3：Force属性缺少[NotMapped]特性
- **现象**：查询报错 `Unknown column 'c.Force' in 'field list'`
- **原因**：在实体类中添加了临时属性但未标记`[NotMapped]`
- **教训**：
  1. 添加临时/计算属性时必须使用`[NotMapped]`
  2. 区分数据库字段和业务逻辑字段
  3. 实体类修改后要理解EF Core的映射机制

### 问题4：重命名功能API返回成功但数据库未更新（最严重）
- **现象**：API返回`{"Status":true,"Message":"更新成功"}`但数据库值不变
- **原因**：
  1. 调试代码修改后没有正确编译
  2. 构建缓存问题导致旧DLL被加载
  3. 没有系统性地验证代码变更是否生效
- **教训**：
  1. 每次修改代码后必须检查编译输出
  2. 使用`ls -la`检查DLL时间戳
  3. 使用`strings`命令验证DLL内容
  4. 清理构建缓存：`rm -rf */bin */obj`

## 调试方法论问题

### 错误做法
1. **过度依赖Console.WriteLine**
   - ASP.NET Core中应该使用`ILogger`
   - Console输出可能不会显示在日志文件中

2. **没有系统性验证**
   - 修改代码后没有检查编译是否成功
   - 没有验证DLL是否包含新代码
   - 没有检查进程是否加载了最新的DLL

3. **调试工具使用不当**
   - 过度依赖curl，忽略了Python requests的可靠性
   - 没有在关键路径添加验证点

4. **没有版本控制意识**
   - 频繁修改代码但没有及时提交
   - 修改前后没有备份关键文件

### 正确做法
1. **修改前先备份**
   ```bash
   git diff > /tmp/changes.patch
   cp file.cs file.cs.backup
   ```

2. **修改后验证编译**
   ```bash
   dotnet build --no-incremental
   ls -la bin/Debug/net8.0/*.dll
   strings *.dll | grep "关键词"
   ```

3. **使用正确的调试方式**
   - 使用ILogger而不是Console.WriteLine
   - 使用断点调试而不是日志打印
   - 使用`dotnet watch run`自动重启

4. **系统化验证**
   - 检查编译输出
   - 检查DLL时间戳
   - 检查进程加载的DLL
   - 检查日志文件
   - 验证数据库状态

## 改进建议

### 1. 代码变更管理
- 每次修改前提交当前状态
- 使用feature branch而不是main分支
- 修改后先编译再测试

### 2. 调试流程
```
修改代码 → 编译检查 → DLL验证 → 重启服务 → 测试 → 验证结果
    ↓           ↓          ↓          ↓          ↓         ↓
 git commit  dotnet    ls -la    pkill      curl     python
             build     strings   dotnet    -test    verify
```

### 3. 质量检查清单
- [ ] 编译是否成功？
- [ ] DLL时间戳是否更新？
- [ ] DLL是否包含新代码？
- [ ] 进程是否重启？
- [ ] 测试结果是否符合预期？
- [ ] 数据库状态是否正确？

### 4. 避免的问题
1. **不要修改框架代码** - 尽量使用扩展方法
2. **不要依赖Console.WriteLine** - 使用ILogger
3. **不要跳过编译检查** - 每次修改后必须编译
4. **不要忽视构建缓存** - 定期清理bin/obj目录
