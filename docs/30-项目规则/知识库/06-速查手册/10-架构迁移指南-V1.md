# 架构迁移指南（V1）— vol 弃用 / 自研 V4 全面接管

> **版本**：V1.0 | **日期**：2026-09-04 | **状态**：试点完成（系统管理 6 页面）
>
> 本文档定义：如何从 vol 旧框架（view-grid、VolProvider、VolBox、edit.vue）彻底迁移到自研 V4 架构（YzhTable / YzhForm / YzhApiClient / 手写 API）。
> **本指南同步覆盖知识库踩坑目录的重组**。

---

## 一、为什么弃用 vol

| 问题 | 后果 |
|------|------|
| view-grid 内部依赖 .jsx / mixin / provider 三件套 | TS 类型推断失效，IDE 报错 |
| 字段配置 + 数据加载 + 事件回调 全部耦合在一个 json | 一个按钮调整影响 3-5 个文件 |
| 表单由 edit.vue 字符串模板驱动 | 字段顺序/校验规则散落 |
| 自动生成的 `extension/sys/system/*.jsx` | 业务无法定制，必须复制源码 |
| 一份 grid 配置 800+ 行 | 改一个分页参数需通读全文 |

## 二、V4 新架构定位

| 层 | 名称 | 替代物 |
|----|------|--------|
| 表格 | `YzhTable` | view-grid |
| 表单 | `YzhForm` | edit.vue + VolForm |
| 搜索栏 | `YzhSearchBarV4` | view-grid 的 search 配置 |
| 工具栏 | `YzhToolbarV4` | view-grid 的 toolbar 配置 |
| 分页 | `YzhPaginationV4` | view-grid 的 pagination |
| API 客户端 | `YzhApiClient`（fetch） | vol 的 http.js（axios） |
| 业务 API | `@/yzh/api/*.ts`（手写） | extension 自动生成的 .jsx |
| 样式 | `@/yzh/styles/*.css` | VolBox/ViewGrid CSS |

## 三、迁移步骤（单页面）

### 3.1 新建 API 封装

```ts
// src/yzh/api/system-user.ts
import { yzhApi } from './client'
import type { Page, PageParams } from '../components/table/types'

export interface SysUser { /* ... */ }

export async function getUserPage(params: PageParams): Promise<Page<SysUser>> {
  return yzhApi.post<Page<SysUser>>('/api/Sys_User/getPageData', params)
}
export async function saveUser(user: Partial<SysUser>) { /* ... */ }
```

### 3.2 写页面（< 150 行）

```vue
<script setup lang="ts">
import { YzhForm } from '@/yzh/components/form'
import YzhTable from '@/yzh/components/table/YzhTable.vue'
import { deleteUser, getUserPage, saveUser, type SysUser } from '@/yzh/api/system-user'

const tableRef = ref()
const columns: YzhTableColumnV4<SysUser>[] = [
  { prop: 'userName', label: '用户名', sortable: true, fixed: 'left' }
]
async function load(params: PageParams) { return getUserPage(params) }
</script>

<template>
  <YzhTable ref="tableRef" :columns="columns" :data-loader="load" />
</template>
```

### 3.3 路由替换

```js
// router/viewGird.js
{ path: '/Sys_User', component: () => import('@/pages/system/user/index.vue') }
```

## 五、踩坑（已解决）

1. **InstanceType 不支持 generic 组件**：`ref<InstanceType<typeof YzhTable>>` 推断失败。
   - **解法**：直接 `ref()` 不带类型（TS 自动推断）。

2. **tsconfig.json 缺 paths**：`@/yzh/...` 找不到。
   - **解法**：在 `tsconfig.json` 配 `baseUrl + paths: { "@/*": ["src/*"] }`，并加 `allowJs: true, noEmit: true`。

3. **Vue SFC generic 组件类型与 InstanceType 冲突**：
   - **解法**：不要在外部用 `InstanceType<typeof Xxx>`，统一用 `ref()`。

4. **YzhTableColumn 类型与旧 YzhDataTable 冲突**：
   - **解法**：用 `YzhTableColumnV4` 命名空间别名。

5. **V4 排序值 'ascending'/'descending' 与后端 'asc'/'desc' 不一致**：
   - **解法**：DefaultSort.order 类型扩展为 `asc | desc | ascending | descending`。

## 六、YzhApiClient 设计要点

- 兼容 vol 响应格式 `{ status, msg, rows, total, data }`，通过 `legacy: true` 开启。
- 401 自动清理 token 并触发 onUnauthorized。
- Token 存 `localStorage['YZH_TOKEN']`，统一管理。
- baseURL 默认 `http://127.0.0.1:9992`，可被 `VITE_API_BASE` 覆盖。
