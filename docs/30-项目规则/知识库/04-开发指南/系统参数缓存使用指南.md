# 系统参数缓存使用指南

> 创建时间：2026-08-14
> 适用版本：SysConfigService V2（全局缓存模式）

## 一、设计原理

### 缓存策略

```
首次访问 → 数据库全量加载 → ConcurrentDictionary 内存缓存
         ↓
后续读取 → 直接走内存（零数据库查询，线程安全）
         ↓
保存参数 → 写数据库 → 自动刷新缓存
         ↓
应用重启 → 缓存清空 → 首次访问自动重建
```

### 核心特性

| 特性 | 说明 |
|------|------|
| 全量加载 | 首次访问时一次性加载所有系统参数到内存 |
| 线程安全 | 使用 `ConcurrentDictionary`，读取无锁，高并发安全 |
| 自动刷新 | `SetAsync` 和 `UpdateBatchAsync` 保存后自动刷新缓存 |
| 零数据库查询 | 运行期间读取参数不访问数据库 |
| 手动刷新 | 提供 `RefreshCache()` 方法，可手动触发全量刷新 |

## 二、使用方法

### 2.1 注入服务

`ISysConfigService` 实现了 Vol 的 `IDependency` 接口，会被自动注册到 DI 容器。

```csharp
// 在任意 Service 或 Controller 中注入
public class MyService
{
    private readonly ISysConfigService _config;

    public MyService(ISysConfigService config)
    {
        _config = config;
    }
}
```

### 2.2 读取参数

```csharp
// 字符串
var apiKey = _config.Get("ai_api_key");

// int（带默认值）
var maxTokens = _config.GetInt("ai_max_tokens", 4096);

// bool（带默认值）
var enableCache = _config.GetBool("enable_cache", true);

// 泛型（自动推断类型）
var temperature = _config.Get<decimal>("ai_temperature");
```

### 2.3 保存参数

```csharp
// 单个保存（自动刷新该 key 的缓存）
await _config.SetAsync("ai_api_key", "sk-new-key");

// 批量保存（自动全量刷新缓存）
await _config.UpdateBatchAsync(new List<CertConfigUpdateDto>
{
    new() { ConfigKey = "ai_api_key", ConfigValue = "sk-new-key" },
    new() { ConfigKey = "ai_model_name", ConfigValue = "qwen-plus" }
});
```

### 2.4 手动刷新缓存

```csharp
// 全量刷新（从数据库重新加载所有参数）
_config.RefreshCache();
```

### 2.5 通过 AutofacContainerModule 获取（静态方式）

```csharp
var config = AutofacContainerModule.GetService<ISysConfigService>();
var apiKey = config.Get("ai_api_key");
```

## 三、常见参数 Key

### AI 模型配置（category: ai_model）

| Key | 类型 | 说明 |
|-----|------|------|
| `ai_provider` | string | AI 服务商（qianwen/deepseek/openai） |
| `ai_api_key` | string | API 密钥 |
| `ai_base_url` | string | API 基础地址 |
| `ai_model_name` | string | 模型名称（qwen-turbo 等） |
| `ai_max_tokens` | int | 单次请求最大 token 数 |
| `ai_temperature` | string | 温度参数（0-1） |

### 文件转换配置（category: convert_queue）

| Key | 类型 | 说明 |
|-----|------|------|
| `convert_concurrency` | int | 转换并发数 |
| `convert_timeout` | int | 转换超时（秒） |

## 四、性能对比

| 场景 | 旧方案（IMemoryCache 5分钟过期） | 新方案（全局缓存） |
|------|----------------------------------|---------------------|
| 首次读取 | 查数据库 1 次 | 查数据库全量 1 次 |
| 5分钟内读取 | 走内存 | 走内存 |
| 5分钟后读取 | **再次查数据库** | 走内存 |
| 保存后读取 | **5分钟内仍读旧缓存** | 立即读新值 |
| 并发读取 | 线程安全 | 线程安全（ConcurrentDictionary） |
| 多人高频使用 | 可能触发缓存过期重建 | 零数据库查询 |

## 五、注意事项

1. **不要直接操作数据库表**：如果直接 SQL 修改了 `cert_sys_config` 表，需要调用 `RefreshCache()` 或重启应用
2. **只读参数无法通过 API 修改**：`IsReadonly = 1` 的参数会抛出异常
3. **管理页面查询不走缓存**：`GetByCategoryAsync` 直接查数据库，确保管理页面看到最新数据
4. **保存时自动刷新**：`SetAsync` 刷新单个 key，`UpdateBatchAsync` 全量刷新
