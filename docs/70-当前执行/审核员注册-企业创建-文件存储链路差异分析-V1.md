## 一、实际业务链路还原

### 1.1 审核员注册 → 企业创建 → 文件上传完整链路

```
① 认证机构初始化（平台管理员操作）
  cert_org_config 表 (OrgCode='CB001', org_name='尚龙认证')
  ↑ Sys_User 表中审核员记录的 OrgCode 和 OrgId 关联到此

② 审核员注册（注册到已初始化的认证机构）
  cert_registration 表 → 审核通过 → 创建 Sys_User 记录
  Sys_User 字段：
    - UserType = 20/21/22 (审核管理员/审核组长/普通审核员)
    - OrgCode = 'CB001' (关联到认证机构)
    - OrgId = cert_org_config.id
  ⚠️ 审核员只能注册到一个认证机构（1:1关系，通过 OrgCode 绑定）

③ 审核员创建企业（一个审核员可建多个企业）
  cert_enterprise 表（旧表，实际在用）：
    - Code = GUID
    - Name = 企业名称
    - CreditCode = 统一社会信用代码
    - OrgCode = 'CB001'（关联到审核员所在的认证机构）
  ⚠️ 同时还有 ent_enterprise 表（V2 设计的新表，但当前无数据）
  ⚠️ cert_enterprise 和 ent_enterprise 两张表并存！

④ 企业申请认证（创建申请单 → 生成项目）
  cert_application 表：
    - CbCode = 认证机构 Code
    - StandardCode = ISO标准 Code
    - EnterpriseCode = 企业 Code
    - CertType = 'QMS'
    - Status = submitted/accepted/...
  audit_project 表：
    - ApplicationCode = cert_application.Code
    - CurrentPhase = 'application_review' (当前阶段)
    - ProjectManagerId = 审核员 Sys_User.User_Id
    - Status = active

⑤ 选择阶段开展审核（项目 → 阶段）
  ⚠️ 当前实现：audit_project.CurrentPhase 存阶段名称
  V2 设计：ent_enterprise_phase 表独立记录企业阶段
  ⚠️ ent_enterprise_phase 表已建但无数据

⑥ 审核任务（阶段 → 任务）
  audit_task 表（V2 设计表，已建）：
    - PhaseCode = 企业阶段 Code
    - TaskNumber = 任务编号
    - AuditorId = 审核员 Sys_User.User_Id
  ⚠️ audit_task 表已建但无数据

⑦ 上传企业资料文件
  当前实现：cert_standard_directory_file 表（标准目录文件表）
    - FileCode = 'FL-FD-SDC-ISO134852016|STAGE01|L01|S001|陪审人员.doc'
    - DirectoryCode = 'SDC-ISO134852016|STAGE01'
    - StoragePath = '/CB001/ISO134852016/STAGE01/CS河北雄安.../陪审人员.doc'
  V2 设计：ent_enterprise_file 表（企业文件表）
  ⚠️ cert_standard_directory_file 同时承担了"标准目录模板"和"企业实际文件"双重职责！

⑧ 文件内容提取（B-08/B-09）
  ent_extraction_result 表（B-08）：字段级提取结果
  ent_table_extraction_result 表（B-09）：表格级提取结果
  ⚠️ 两表已建但无数据，且缺少 enterprise_code/phase_code 字段
```

### 1.2 当前 MinIO 存储路径实际结构

```
当前路径格式（从数据库实际数据确认）：
  /{OrgCode}/{StandardCode}/{PhaseCode}/{FolderPath}/{FileName}

实际示例：
  /CB001/ISO134852016/STAGE01/CS河北雄安尚龙医疗科技有限公司13485体系材料/陪审人员.doc

分析：
  第1级 CB001 = 认证机构编码（cert_org_config.OrgCode）
  第2级 ISO134852016 = 标准编码（去特殊字符）
  第3级 STAGE01 = 阶段编码
  第4级 CS河北... = 用户上传时指定的文件夹路径
  第5级 文件名

⚠️ 当前路径以"认证机构编码"开头，而非"审核员编码"或"企业编码"
```

## 二、核心差异分析

### 2.1 差异一：双企业表并存（cert_enterprise vs ent_enterprise）

| 维度 | cert_enterprise（旧表，在用） | ent_enterprise（V2 新表，空表） |
|------|-------------------------------|-------------------------------|
| **主键** | Id bigint | Id bigint |
| **唯一编码** | Code char(36) | Code varchar(36) |
| **多租户** | OrgCode varchar(50) | OrgCode varchar(50) |
| **审计字段** | CreateID bigint / CreateDate | CreateID int / Creator / CreateDate + YZHBaseEntity 全套 |
| **逻辑删除** | 无（Status tinyint） | Enable + DeleteID + DeleteTime |
| **字段差异** | 有 province/city/IndustryType/EmployeeCount | 有 ArchiveDate + YZHBaseEntity 全套 |
| **实际数据** | ✅ 有 1 条测试数据 | ❌ 空表 |
| **代码引用** | cert_application.EnterpriseCode 关联此表 | ent_enterprise_phase.EnterpriseCode 关联此表 |

**问题**：两个企业表并存，业务流程实际使用 `cert_enterprise`，而 V2 设计中 `ent_enterprise_phase`、`ent_enterprise_document`、`ent_enterprise_file` 都关联到 `ent_enterprise`。

### 2.2 差异二：审核员与企业关系缺失

**V2 设计**：
- `ent_enterprise` 表只有 `CreateID`（创建人），通过 `Sys_User.User_Id` 关联
- 没有独立的"审核员-企业"关联表
- 一个审核员创建多个企业 = 多条 `ent_enterprise` 记录的 `CreateID` 相同

**你的业务需求**：
- 审核员注册到认证机构（1:1）✅ 已实现（Sys_User.OrgCode）
- 审核员创建多个企业（1:N）⚠️ 通过 CreateID 隐式关联，但无显式关联表
- 企业应该属于审核员而非认证机构？

**当前实现**：
- `cert_enterprise.OrgCode = 'CB001'` → 企业属于认证机构，而非审核员个人
- `cert_application` 没有审核员字段，`audit_project.ProjectManagerId` 才关联审核员
- 没有直接表达"审核员创建了哪些企业"的关系

### 2.3 差异三：标准目录文件表承担双重职责

**当前实现**：
- `cert_standard_directory_file` 表既存"标准目录模板定义"又存"企业实际上传文件"
- 文件上传时直接在标准目录文件表中新增记录
- StoragePath = `/CB001/ISO134852016/STAGE01/...` → 以认证机构编码开头

**V2 设计**：
- `cert_standard_directory_file` 应该只存"标准目录模板"（文件要求定义）
- 企业实际上传文件应存入 `ent_enterprise_file` 表
- StoragePath 应以企业编码开头：`/{EnterpriseCode}/{StandardCode}/{PhaseCode}/...`

**你的期望**：
> 企业的文件存储应该是 `审核员code-任务code-文件夹-文件`

这意味着你期望的路径结构是：
```
/{AuditorCode}/{TaskCode}/{FolderPath}/{FileName}
或
/{EnterpriseCode}/{TaskCode}/{FolderPath}/{FileName}
```

### 2.4 差异四：企业阶段关系表

**当前实现**：
- `audit_project.CurrentPhase` 直接在项目表里存当前阶段名（字符串）
- `ent_enterprise_phase` 表已建但无数据

**V2 设计**：
- `ent_enterprise_phase` 独立记录企业在每个阶段的状态
- `audit_task.PhaseCode` 关联到 `ent_enterprise_phase.Code`

### 2.5 差异五：企业文档目录

**当前实现**：
- `cert_standard_directory_config` + `cert_standard_directory_folder` 定义标准目录模板
- 上传文件时直接在 `cert_standard_directory_file` 表新增记录
- 没有"企业文档目录实例化"的过程

**V2 设计**：
- `ent_enterprise_document` 表记录企业实例化的目录结构
- `ent_enterprise_file` 表记录企业实际上传的文件
- 企业目录 = 标准目录模板实例化

### 2.6 差异六：MinIO 存储路径格式

| 维度 | 当前实现 | V2 设计 | 你的期望 |
|------|---------|---------|---------|
| **第1级** | 认证机构编码 (CB001) | 标准编码 | 审核员编码 或 企业编码 |
| **第2级** | 标准编码 (ISO134852016) | 阶段编码 | 任务编码 |
| **第3级** | 阶段编码 (STAGE01) | 文件夹路径 | 文件夹 |
| **第4级** | 文件夹路径 | 文件名 | 文件名 |
| **第5级** | 文件名 | — | — |

## 三、你描述的目标业务链路

基于你的描述，完整还原你期望的业务链路：

```
① 认证机构初始化
  cert_org_config (CB001 尚龙认证)
  ↑ 系统预置

② 审核员注册到认证机构
  Sys_User (UserType=22, OrgCode='CB001')
  ↑ 审核员注册时选择认证机构，1:1 绑定
  ↑ 一个审核员只能在一个认证机构中

③ 审核员创建企业（1:N）
  企业表 (审核员创建多个企业)
  ↑ 需要显式记录"哪个审核员创建了哪个企业"
  ↑ 企业应关联到审核员，而非直接关联到认证机构

④ 选择企业 + 选择阶段 → 开展体系审核
  企业阶段表 (企业 Code + 阶段编码 + 标准编码)
  ↑ 每个企业可以有多个阶段（初审S1 → 一监 → 二监...）

⑤ 创建审核任务
  审核任务表 (企业阶段 Code + 审核员 ID + 任务编号)
  ↑ 一个企业阶段下可以有多个审核任务

⑥ 上传企业资料文件
  路径格式：/{审核员Code}/{任务Code}/{文件夹}/{文件}
  或：/{企业Code}/{任务Code}/{文件夹}/{文件}
  ↑ 自动根据标准目录提取规则，进行文件存储

⑦ 文件内容提取存储
  B-08 ent_extraction_result (字段级，enterprise_code = 企业 Code)
  B-09 ent_table_extraction_result (表格级，enterprise_code = 企业 Code)
  ↑ 一个文件对应多条字段存储记录 + 一条表格数据(JSON)
```

## 五、存储路径格式分析

### 5.1 当前路径

```
/CB001/ISO134852016/STAGE01/CS河北雄安.../陪审人员.doc
│      │             │        │               │
│      │             │        │               └─ 文件名
│      │             │        └─ 文件夹路径
│      │             └─ 阶段编码
│      └─ 标准编码
└─ 认证机构编码
```

### 5.2 你的期望路径

```
/{审核员Code}/{任务Code}/{文件夹}/{文件}
```

### 5.3 路径方案对比

| 方案 | 路径格式 | 优势 | 劣势 |
|------|---------|------|------|
| **A. 当前** | /CB001/标准/阶段/文件夹/文件 | 已实现 | 以认证机构开头，无法区分审核员和企业；无任务维度 |
| **B. 审核员+任务** | /{AuditorCode}/{TaskCode}/{文件夹}/{文件} | 审核员维度清晰 | 同一审核员不同标准/阶段文件混在审核员目录下；MinIO 无目录层级时全量扫描效率低 |
| **C. 企业+任务** | /{EnterpriseCode}/{TaskCode}/{文件夹}/{文件} | 企业维度清晰；文件属于企业而非审核员（符合认证行业逻辑） | 审核员更换时历史文件仍在企业下（正确行为） |
| **D. 企业+阶段+任务** | /{EnterpriseCode}/{PhaseCode}/{TaskCode}/{文件夹}/{文件} | 层级最完整；每级都对应数据库实体 | 路径较长；MinIO 对象名不宜过长 |

### 5.4 推荐方案：C（企业+任务）

```
/{EnterpriseCode}/{TaskCode}/{FolderPath}/{FileName}

示例：
  /086badc8-8ef1-11f1-a2e2-e6bd9a193da2/TASK-2026-001/质量手册/XASL-QM.docx

理由：
  1. 认证行业中，文件属于企业，不属于审核员（审核员只是操作者）
  2. 企业 Code 是 GUID，天然全局唯一，不与认证机构冲突
  3. TaskCode 关联到具体审核任务，便于按任务归档
  4. 同一企业不同阶段的文件通过 TaskCode 隔离
  5. 从 StoragePath 可直接反推 EnterpriseCode 和 TaskCode
```

### 5.5 与标准目录的关系

```
标准目录模板（配置层，不变）：
  cert_standard_directory_config (SDC-ISO134852016|STAGE01)
  cert_standard_directory_folder (文件夹树结构)
  cert_standard_directory_file (文件要求定义，不含实际文件)

企业文件实例（业务层，新建）：
  ent_enterprise_file
    EnterpriseCode = 企业 Code
    TaskCode = 审核任务 Code
    FolderCode = 标准目录文件夹 Code（关联到模板）
    StoragePath = /{EnterpriseCode}/{TaskCode}/{FolderPath}/{FileName}
```

## 六、缺失的"审核员-企业"关联设计

### 6.1 问题

当前设计中，审核员创建企业只通过 `CreateID` 隐式关联，这导致：
- 查询"审核员创建的企业列表"需要 `WHERE CreateID = {userId}`，但 CreateID 可能被其他操作覆盖
- 无法表达"审核员负责但非自己创建的企业"（如组长分配给组员的企业）
- 多租户隔离基于 `OrgCode`（认证机构级别），而非审核员级别

### 6.2 方案对比

| 方案 | 说明 | 优势 | 劣势 |
|------|------|------|------|
| **A. ent_enterprise 新增 AuditorCode 字段** | 企业表直接存审核员 Code | 简单，一次查询 | 审核员离职后无法转移企业 |
| **B. 新建 ent_auditor_enterprise 关联表** | 独立关联表 | 支持多审核员负责同一企业；支持角色（创建者/负责人/参与者） | 多一次 JOIN |
| **C. 复用 Sys_User.ParentUserId** | 企业账号的 ParentUserId = 审核员 ID | 不用新建表 | 仅适用于企业账号模式，Phase 1 无企业账号 |

### 6.3 推荐：方案 A + 后续扩展 B

```
短期（Phase 1）：
  ent_enterprise 新增字段：
    AuditorCode varchar(36) NOT NULL COMMENT '创建审核员编码（关联 Sys_User）'

长期（Phase 2+）：
  新建 ent_auditor_enterprise 关联表（支持多审核员、角色、有效期）
```

## 七、完整目标数据库结构建议

### 7.1 实体关系图（目标态）

```
cert_org_config (认证机构)
  ↑ OrgCode
Sys_User (审核员)
  ↓ AuditorCode (新增字段)
ent_enterprise (企业，统一表)
  ↑ EnterpriseCode
ent_enterprise_phase (企业阶段)
  ↑ PhaseCode
audit_task (审核任务)
  ↑ TaskCode
ent_enterprise_file (企业文件，新建)
  ↑ FileCode
ent_extraction_result (B-08，字段级提取)
ent_table_extraction_result (B-09，表格级提取)
```

### 7.2 需要做的变更清单

## 八、对 YZH 标准企业方案的影响

### 8.1 路径变化

原方案中 YZH 标准企业的 MinIO 路径没有涉及。现在需要明确：

```
YZH 标准企业的文件存储路径：
  /YZH-STD-ENT/STD-TASK/标准目录文件夹/文件名

  或直接复用标准目录模板的 MinIO 路径（因为标准目录文件已经上传到 MinIO 了）：
  /CB001/ISO134852016/STAGE01/文件夹/文件名
```

**建议**：YZH 标准企业直接复用标准目录模板的 MinIO 路径，不另外复制文件。提取结果落 B-08/B-09 时 `file_code` 使用标准目录文件的 `FileCode`，`enterprise_code = 'YZH-STD-ENT'`。

### 8.2 实体关联

```
YZH 标准企业提取结果落库时：
  ent_extraction_result:
    enterprise_code = 'YZH-STD-ENT'
    phase_code = 'STD' (标准阶段，不区分实际阶段)
    task_code = null (标准目录数据不属于任何任务)
    file_code = cert_standard_directory_file.FileCode
    label_tag = cert_doc_field_def.FieldCode
    extracted_value = AI 提取值
```
