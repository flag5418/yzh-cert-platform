## 一、系统概述

### 1.1 业务背景

标准目录管理系统是体系认证审核平台的核心功能模块，用于管理认证机构、标准和阶段关联的文件目录结构。通过标准化的目录模板，规范企业档案上传流程，为后续的提取规则定义、NC生成和报告生成提供数据基础。

### 1.2 核心目标

| 目标 | 说明 |
|------|------|
| **目录标准化** | 基于机构-标准-阶段组合，定义统一的文件夹结构 |
| **文件规范管理** | 支持文件的上传、下载、预览、版本管理 |
| **数据复用性** | 文件夹树组件可复用于多个业务场景 |
| **扩展预留** | 为文件预览、在线编辑、提取规则预留接口 |

### 1.3 用户角色

| 角色 | 权限 |
|------|------|
| **系统管理员** | 配置标准目录模板、管理所有文件 |
| **认证机构** | 查看和维护本机构的标准目录和文件 |
| **审核员** | 查看已上传的企业档案文件 |

## 二、数据库设计

### 2.1 核心表结构

#### 2.1.1 标准目录配置表 (cert_standard_directory_config)

```sql
CREATE TABLE `cert_standard_directory_config` (
  `Id` bigint NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  
  -- 编码字段
  `Code` varchar(36) NOT NULL COMMENT '全局唯一编码（GUID）',
  `DirectoryCode` varchar(100) NOT NULL COMMENT '目录编码（SDC-{StandardCode}|{PhaseCode}）',
  
  -- 关联字段
  `StandardCode` varchar(50) NOT NULL COMMENT '标准编码',
  `PhaseCode` varchar(50) NOT NULL COMMENT '阶段编码',
  
  -- 目录配置
  `RootFolderName` varchar(200) DEFAULT NULL COMMENT '根文件夹名称',
  
  -- 状态字段
  `Status` enum('draft','active','archived') DEFAULT 'draft' COMMENT '状态',
  `Enable` tinyint(1) DEFAULT 1 COMMENT '是否启用',
  
  -- 审计字段
  `CreateID` int DEFAULT NULL,
  `Creator` varchar(50) DEFAULT NULL,
  `CreateDate` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `ModifyID` int DEFAULT NULL,
  `Modifier` varchar(50) DEFAULT NULL,
  `ModifyDate` datetime DEFAULT NULL,
  `DeleteID` int DEFAULT NULL,
  `Deleter` varchar(50) DEFAULT NULL,
  `DeleteTime` datetime DEFAULT NULL,
  `Status_field` varchar(50) DEFAULT 'active',
  `Enable_field` tinyint DEFAULT 1,
  `Sort` int DEFAULT 0,
  `Remark` text COMMENT '备注',
  
  PRIMARY KEY (`Id`),
  UNIQUE KEY `uk_code` (`Code`),
  UNIQUE KEY `uk_directory_code` (`DirectoryCode`),
  UNIQUE KEY `uk_standard_phase` (`StandardCode`, `PhaseCode`),
  KEY `idx_standard_code` (`StandardCode`),
  KEY `idx_phase_code` (`PhaseCode`),
  KEY `idx_status` (`Status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='标准目录配置表';
```

**预留字段说明**：

| `TemplateVersion` | varchar(50) | 目录模板版本号（预留） |

## 六、编码规则

### 6.1 编码生成规则

| 编码类型 | 格式 | 示例 |
|---------|------|------|
| 目录编码 | `SDC-{StandardCode}\|{PhaseCode}` | `SDC-ISO9001\|PH01` |
| 文件夹编码 | `FD-{DirectoryCode}\|L{Level}\|S{Seq}` | `FD-SDC-ISO9001\|PH01\|L01\|S001` |
| 文件编码 | `FL-{FolderCode}\|{FileName}` | `FL-FD-SDC-ISO9001\|PH01\|L01\|S001\|营业执照正本.pdf` |

### 6.2 MinIO 存储路径规则

```
/{StandardCode}/{PhaseCode}/{FolderCode}/{FileName}

示例：
/ISO9001/PH01/FD-SDC-ISO9001|PH01|L01|S001/营业执照正本.pdf
/ISO9001/PH01/FD-SDC-ISO9001|PH01|L01|S001/营业执照副本.pdf
/ISO13485/PH01/FD-SDC-ISO13485|PH01|L01|S001/生产许可证.pdf
```

### 6.3 编码规则说明

| 规则 | 说明 |
|------|------|
| **目录编码** | 标识"哪个标准的哪个阶段"，如 ISO9001 的初审阶段 |
| **文件夹编码** | 标识文件夹在目录结构中的位置，包含层级和序号 |
| **文件编码** | 唯一标识一个文件，由文件夹编码+文件名组成 |
| **文件替换** | 直接覆盖原文件，不保留历史版本 |
| **存储路径** | 标准/阶段/文件夹编码/文件名，结构清晰 |

### 6.4 设计简化说明

相比原版编码规则，进行了以下简化：

| 简化项 | 原版 | 简化版 | 原因 |
|--------|------|--------|------|
| 文件编码 | `FL-{FolderCode}\|{Hash}\|v{Version}` | `FL-{FolderCode}\|{FileName}` | 文件名在同级目录下已能区分 |
| 存储路径 | `/{标准}/{阶段}/{机构}/{文件夹}/{文件名}-{哈希}-v{版本}/{文件名}` | `/{标准}/{阶段}/{文件夹}/{文件名}` | 标准目录是通用模板，机构无关 |
| 版本管理 | 支持多版本 | 直接覆盖 | 标准文件无需版本追溯 |
