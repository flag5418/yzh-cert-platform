## 一、现有编码体系

### 1.1 编码格式

| 编码类型 | 格式 | 示例 | 生成时机 |
|---------|------|------|---------|
| DirectoryCode | `SDC-{标准}\|{阶段}` | `SDC-ISO134852016\|STAGE01` | 创建目录配置时 |
| FolderCode | `FD-{DirectoryCode}\|L{depth:D2}\|S{sequence:D3}` | `FD-SDC-ISO134852016\|STAGE01\|L02\|S003` | 创建文件夹时 |
| FileCode | `FL-{FolderCode}\|{FileName}` | `FL-FD-SDC-ISO134852016\|STAGE01\|L02\|S003\|营业执照.pdf` | 创建文件记录时 |
| StoragePath | `/{StandardCode}/{PhaseCode}/{FolderCode}/{FileName}` | `/ISO134852016/STAGE01/FD-SDC-...\|L02\|S003/营业执照.pdf` | 上传文件到 MinIO 时 |
| FullPath | `{文件夹路径}/{文件名}`（从根到文件的完整业务路径） | `4记录文件/内审记录/营业执照.pdf` | 上传时前端传入 |

### 1.2 各字段作用

| 字段 | 作用 | 是否暴露给外部 |
|------|------|---------------|
| FileCode | 内部技术编码，用于 DB 查询和 MinIO 路径映射 | 否 |
| StoragePath | MinIO 对象存储路径，用于文件读写 | 否 |
| FullPath | 业务路径，人类可读，用于路径匹配和唯一性判定 | 可选 |
| BusinessKey | **（待新增）** 稳定业务标识，用于工作流引擎等外部系统引用 | 是 |

## 二、编码与物理存储的关系

```
机构 > 标准 > 阶段
  └─ 📂 ISO 13485:2016                    ← 标准
       └─ 📂 STAGE-01                      ← 阶段
            ├─ 📂 4记录文件                 ← 一级文件夹 (Depth=1)
            │    ├─ 📂 内审记录             ← 二级文件夹 (Depth=2)
            │    │    ├─ 📄 营业执照.pdf    ← 文件
            │    │    └─ 📄 受控清单.xls
            │    └─ 📂 管理评审
            └─ 📂 7产品实现

MinIO 存储结构：
/ISO134852016/STAGE01/
  └─ FD-SDC-ISO134852016|STAGE01|L01|S001/        ← 4记录文件
       ├─ FD-SDC-ISO134852016|STAGE01|L02|S001/   ← 内审记录
       │    ├─ 营业执照.pdf
       │    └─ 受控清单.xls
       └─ FD-SDC-ISO134852016|STAGE01|L02|S002/   ← 管理评审
```

**OSS 层面的唯一性由物理路径保证**：同一标准+阶段下，不可能出现两个同路径文件。

## 三、FileCode 的更新策略

### 3.1 原则

> FileCode 是技术编码，当且仅当文件的**物理位置发生变化**时才更新。

### 3.2 触发更新的场景

| 场景 | 是否更新 FileCode | 原因 |
|------|------------------|------|
| 文件首次上传 | 创建 | 初始赋值 |
| 文件在同一文件夹内重命名 | **更新** | FileName 变了，FileCode 包含 FileName |
| 文件移动到其他文件夹 | **更新** | FolderCode 变了 |
| 文件夹重命名 | **更新** | FolderCode 变了，影响下属所有文件 |
| 文件夹移动（换父级） | **更新** | FolderCode 变了 |
| 替换文件（同名同位置） | 不更新 | FolderCode 和 FileName 不变 |

### 3.3 更新时的影响范围

```
文件夹重命名：
  FolderCode: FD-SDC-...|L02|S001 → FD-SDC-...|L02|S001（ FolderCode 不含 FolderName，不会变）
  但：该文件夹下所有文件的 FileCode 包含旧 FolderCode → 需要级联更新

  实际上 FolderCode 的格式是 FD-{DirectoryCode}|L{depth}|S{seq}，
  不包含文件夹名称，所以文件夹重命名不影响 FolderCode。
  只有 FileCode 中的 FileName 部分需要更新。
```

### 3.4 结论

- **文件夹重命名**：不影响 FolderCode，只影响显示名称，不需要级联更新
- **文件重命名**：只更新该文件的 FileCode（FileName 部分）
- **文件移动**：更新该文件的 FileCode（FolderCode 部分）+ StoragePath
- **文件夹移动**：更新该文件夹的 ParentCode，不影响 FolderCode 本身

> FolderCode 的格式 `FD-{DirectoryCode}|L{depth}|S{seq}` 不包含文件夹名称和父级信息，所以文件夹的重命名和移动**不会导致 FolderCode 变化**，进而不会影响下属文件的 FileCode。

## 四、BusinessKey 设计（待实现）

### 4.1 定义

```
BusinessKey = "BIZ-" + DirectoryCode + "|" + MD5(FullPath)
```

示例：
```
BIZ-SDC-ISO134852016|STAGE01|a3f8c1d2e5b74f6a...
```

### 4.2 特性

| 特性 | 说明 |
|------|------|
| 与结构无关 | 不依赖 FolderCode、SortOrder、Depth |
| 稳定 | 只要 FullPath 不变，BusinessKey 不变 |
| 全局唯一 | DirectoryCode + FullPath 的组合在系统中唯一 |
| 可读 | 前缀 `BIZ-` 标识类型，DirectoryCode 可读，Hash 用于判重 |

### 4.3 适用场景

- 工作流引擎：作为自定义参数引用文件
- 外部系统集成：提供稳定标识，不暴露内部编码
- 数据同步：跨系统比对时作为唯一键

### 4.4 不适用场景

- 内部 DB 查询（用 FileCode 或 Id）
- MinIO 文件访问（用 StoragePath）
- 前端展示（用 FileName + FullPath）

## 五、上传层级问题分析

### 5.1 问题描述

用户在二级文件夹（如 `4记录文件/内审记录`）内触发上传，选择本地文件夹 `新文件夹A/子文件夹1/file.pdf`。

**浏览器行为**：`webkitRelativePath` 返回 `新文件夹A/子文件夹1/file.pdf`（相对于选择的文件夹根，不包含当前目录上下文）。

**后端处理**：根据 path 创建文件夹，`parentCode` 从 `folderMap` 查找，找不到则默认为空（根级）。

**结果**：`新文件夹A` 被创建为根级文件夹，而非 `内审记录` 的子文件夹。

### 5.2 影响评估

| 维度 | 影响 | 说明 |
|------|------|------|
| 已有文件夹层级 | ✅ 无影响 | parentCode 不变 |
| 已有文件夹排序 | ✅ 无影响 | SortOrder 不变 |
| 已有文件归属 | ✅ 无影响 | FolderCode 不变 |
| 新文件夹位置 | ⚠️ 位置错误 | 出现在根级而非当前目录 |
| FullPath 冲突 | ✅ 安全 | 不同路径不会误判为重复 |

### 5.3 推荐解决方案

**方案 A：前端传递 currentFolderCode（推荐）**

```javascript
// 前端 submitUpload
const initRes = await http.post('/api/standard-directory/upload-init', {
  directoryCode,
  parentFolderCode: currentFolderCode.value,  // 新增
  folders,
  files
})
```

后端处理：
- 当 `parentFolderCode` 非空时，所有根级文件夹的 `parentCode` 设为该值
- `depth` 需要加上父级文件夹的实际深度

## 六、工作流引擎参数引用规范

### 6.1 参数定义

| 参数 | 类型 | 说明 | 示例 |
|------|------|------|------|
| BusinessKey | string | 唯一标识，跨系统引用 | `BIZ-SDC-ISO134852016\|STAGE01\|a3f8...` |
| FullPath | string | 人类可读定位 | `4记录文件/内审记录/营业执照.pdf` |
| StoragePath | string | 技术访问路径 | `/ISO134852016/STAGE01/FD-...\|L02\|S003/营业执照.pdf` |
| FileCode | string | 内部技术编码 | `FL-FD-SDC-...\|L02\|S003\|营业执照.pdf` |
| FileName | string | 文件名（不含路径） | `营业执照.pdf` |
| DirectoryCode | string | 所属目录编码 | `SDC-ISO134852016\|STAGE01` |

### 6.2 使用建议

- **工作流定义时**：使用 `BusinessKey` 作为引用参数
- **工作流运行时**：通过 `BusinessKey` 查询得到 `StoragePath`，再访问 MinIO
- **前端展示时**：使用 `FullPath` + `FileName`
- **内部逻辑时**：使用 `FileCode` 或数据库 `Id`
