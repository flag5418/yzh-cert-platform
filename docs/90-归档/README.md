## 二、⚠️ 术语警告：三个 "YZH"

项目中存在**三个**都叫 "YZH" 的东西，务必区分：

| 名称 | 位置 | 状态 | 说明 |
|------|------|:----:|------|
| **YZH.Core**（新） | `src/yzh-core/` | ✅ 当前唯一开发目标 | 本文档体系 `10-YZH架构/` 描述的对象 |
| **YZH-Framework**（旧） | `src/old/server/YZH-Framework/` | 🗄️ 已归档 | v1.0.0-alpha.1，"Vol 之上的增量增强层，不是替代品" |
| **YZH 认证平台** | 整个项目 | ✅ | 项目名"映智汇认证审核管理系统" |

> 见到 "YZH" 先确认指哪一个。`10-YZH架构/` **只描述第一个**。

## 三、归档检索机制

**默认不参与日常检索**——归档内容不应污染当前 AI 上下文。

进入方式只有一条路径：

```
需要迁移旧代码 / 理解历史决策
        ↓
50-任务/迁移工作台/
        ↓
90-归档/历史项目/
        ↓
定位到具体设计文档
```

> **给 AI 的提示**：不要在无明确指令时读取本层内容。需要历史参考时，从
> [`50-任务/迁移工作台/`](../50-任务/迁移工作台) 进入，按图索骥。

## 四、归档目录的组织原则

### 4.1 三种归档原因

| 原因 | 去处 | 例 |
|------|------|-----|
| 旧**系统**的知识，长期有效 | `历史项目/` | Vol 框架速查手册 |
| 本项目**旧版本**，已被取代 | `旧版本/` | `总体设计-V1.md`、`数据库表设计-V1.md` |
| **非文档**的参考资料 | `案例资料/` | 企业体系材料 |

### 4.2 命名约定

- 旧版本保持原文件名，便于追溯
- 整目录归档时保留原目录名（如 `归档-2026-09-08-TreeTable架构演进/`）
- 归档日期前缀格式：`归档-YYYY-MM-DD-简述`

---

## 五、维护约定

1. **禁止删除**归档内容。确需清理时先与项目负责人确认。
2. **禁止**从归档目录被活跃文档直接引用——活跃文档应引用活跃文档。
3. 归档内容**不要求维护时效性**，其价值在于"当时是怎么想的"。
4. 若某份归档文档被重新启用，应**复制**到对应活跃层并更新版本号，而非直接移出。
