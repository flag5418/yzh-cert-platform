## 二、架构映射：旧 → 新

### 2.1 技术栈差异对照

| 维度 | 旧 vol.api | 新 certplatform-api | 移植动作 |
|---|---|---|---|
| ORM | EF Core（VOLContext，EF 实体 EntityBase） | **IDbOrm（SqlSugar）**，实体混用 EF 风格 `[Table]/[Column]`（Shared 层）与 `[SugarTable]`（Skill） | `db.Set<T>()` LINQ → `_db.GetOneAsync<T>()/GetListAsync<T>()/InsertAsync<T>()/UpdateAsync<T>()`；共享层实体（WfExecutionTask 等）已是 EF 注解但由 SqlSugar 按 `[Table]/[Column]` 特性解析（SqlSugarDbOrm.GetColumnName 支持 TableAttribute + 列名映射，已核实） |
| DI 注册 | `Program.cs` AddScoped 七连 | `src/yzh-core/YZH.Core.Web/Program.cs`（业务服务注册处，已有 DocExtractionRuleService 先例） | 同位置追加 6 行注册 |
| LLM | ILlmClient（YZH.Core.AI，多 Provider：Qwen/Ollama/Mock） | **LlmInvokeService**（Shared 层，OpenAI 兼容直连，LlmInvokeRequest/Response） | AiNodeExecutor 的 LLM 调用改写为 LlmInvokeService；模型名从"节点 config.model → cert_sys_config.ai_model_name 兜底"改为 GetAiSettingsAsync 六键模式（对照 DocExtractionRuleService.AI.cs L121-148 已有实现，直接复用其模式） |
| 提示词渲染 | IPromptInterpreter（YZH.Core.AI.Prompt） | **无对应组件** | `Render()`（30 行 `{{name}}` 正则替换）+ `ParseAsync`（JSON 围栏提取）内联为引擎内 `PromptRenderer` 静态类（或 Shared 层），正则原样搬运 |
| Skill 反射 | SkillExecutor（[Skill]/[SkillParam] 特性 + 静态方法反射 + [FromService] DI 注入） | **无** | 移植 SkillAttributes + SkillExecutor + SkillContext/SkillResult + 4 个 Skill；**Skill 类放 `CertPlatform.Admin/Services/Workflow/Skills/`**（业务层，因 GetField/GetTable 依赖 Ent 实体）；反射执行器可先放 Shared 或 Admin（见 §3 决策 D-3） |
| 缓存 | CSRedis（RedisHelper 静态） | **无 Redis**（MemoryCacheNoSql / IMemoryCache） | TEST 同步执行生命周期内改用 `IMemoryCache` 或**进程内 Dictionary**（任务结束即清理，无需跨进程）；TaskCacheService 接口形状保留，实现替换 |
| 响应包装 | `Ok(new { success, data })` | `ApiResponse<T>`（success/message/data/code/timestamp，JsonNamingPolicy=null PascalCase） | Controller 返回改 `ApiResponse<TaskExecutionResponse>.Ok(...)`；前端 `res?.data` 读取兼容（data 内字段保持 camelCase JSON，通过 System.Text.Json 属性名原样输出——需确认 PascalCase 策略下 DTO 属性命名，见 §3 决策 D-5） |
| 认证 | [Authorize] + AllowAnonymous | 全局 PermissionFilter（未标记 RequirePermission 仅要求已认证） | 新 Controller 不加 AllowAnonymous 即可，无额外动作 |
| 用户上下文 | — | IUserContext | 写 task.creator 审计字段 |

## 四、接口契约（迁移后对外形态）

### 4.1 `POST /api/Workflow/test/run`

请求（前端现状零改动）：
```json
{
  "taskType": "TEST",
  "ruleCode": "NC-xxx-001",
  "enterpriseCode": "YZH-STD-ENT",
  "standardCode": "...",
  "phaseCode": "AP",
  "configJson": "{\"version\":1,\"workflowType\":\"validation\",\"nodes\":[...],\"edges\":[...]}"
}
```
响应：`ApiResponse<TaskExecutionResponse>`，data 内：
`TaskCode, ItemCode, Status("completed"|"failed"), IsSuccess(bool), NcResult{success,error,result,executedPaths,successPaths,failedPaths}, PathResults[{pathIndex,status,failedAtNodeId,error,output,nodeIds}], DurationMs`（PascalCase 键）。

### 4.2 `POST /api/Workflow/test/node`

请求 = 旧 NodeTestRequest（NodeId/NodeType/Title/SkillCode/Config/Inputs/InputTypes/InputPorts/OutputPorts）。
响应 data：`{ Success, Error, Output, DurationMs }`。

### 4.3 `POST /api/Workflow/test/ai-node`

请求 = 旧 AiNodeTestRequest（含 WorkflowContext.RuleJson/ContextParams/MockOutputs）。
响应 data = AiNodeTestResponse：`Success/Error/Result/DurationMs/Debug{RenderedPrompt,ParamPool,LlmResponse,ConvertedResult}`。
保留旧版关键行为：mockOutputs 为空时按 ruleJson 反向 BFS 自动执行上游节点（docField/docTable/skill 常量回退）。

### 4.4 `GET /api/Workflow/health`（AllowAnonymous）

引擎自检：返回模块清单，用于部署冒烟。

### 4.5 执行链路（内部）

```
TestRun → WfExecutionTaskService.CreateAndRunAsync(req)
  ① WorkflowConfigParser.Parse(configJson)      → 解析失败返回友好错误（不落库）
  ② 建 wf_execution_task + wf_execution_task_item（status=executing, IDbOrm InsertAsync）
  ③ TaskCacheService.WarmUpAsync（docField/docTable/skill 节点数据预热，IMemoryCache）
  ④ contextParams = { enterpriseCode, phaseCode, standardCode }
  ⑤ WorkflowInterpreter.ExecuteItemAsync        → 逐路径 → NodeExecutor.ExecuteAsync 逐节点
  ⑥ SaveNodeExecutionsAsync → wf_node_execution（HashSet 去重共享节点；end 输出/失败节点错误落 OutputJson/ErrorMessage）
  ⑦ 回写 task/item 终态（ResultSummary/ErrorMessage/DurationMs/IsSuccess）
  ⑧ TaskCacheService.CleanUpAsync
  → TaskExecutionResponse
```

## 六、风险与对策

| # | 风险 | 对策 |
|---|---|---|
| R-1 | Shared 层 Wf 实体是 EF 注解风格（`[Table]/[Column]`，EntityBase 基类含 CreateID 等 EF 列），SqlSugar 读写映射未在真实表上验证过 | 阶段 5 先写一次性 SQL 抽查脚本；若列映射失败，回退方案：引擎内部用 `SqlQueryAsync<T>` 原生 SQL 读写三张执行表（绕开 ORM 映射） |
| R-2 | wf_skill_reflection FK 指向 wf_skill.skill_code，但 001 建表唯一键是 `code` 列；实体 Skill.cs 主键声明 code varchar(100) 与 DDL id bigint 冲突史（迁移审核报告 P0） | 阶段 7 前先 `SHOW CREATE TABLE wf_skill/wf_skill_reflection` 核对实际库；种子脚本按实际列名编写，必要时先出列对齐 ALTER |
| R-3 | LlmInvokeService 与旧 ILlmClient 语义差异（无 Provider 路由/重试/熔断；ForceJson 默认 true） | AI 节点调用 ForceJson=false 保持旧 JsonMode=false 行为；超时 120s 对齐；若 LLM 未配置（六键缺 Key），返回友好错误而非异常（LlmInvokeService 已内置） |
| R-4 | 全局 PermissionFilter 对新端点要求登录——设计器已在登录态内，无影响；但 Swagger 直调需 token | health 端点 AllowAnonymous；其余保持认证 |
| R-5 | 路径枚举在复杂图（多条无分支出边扇出）下的路径爆炸 | 旧版即有 visitedInPath 防环 + 拓扑校验前置；补一个节点数上限（如 100）防御性校验，超限返回明确错误 |
| R-6 | 并发编辑/重复点击运行导致 task 重复创建 | TEST 场景可接受（每次运行都是新 task）；幂等键属后续队列化范围，本期不做 |
