## 二、「不能预览」的三层根因（全部已修复）

预览链：`前端 → file-preview 端点 → MinIO 取源文件 → LibreOffice/LibreOffice 容器转 PDF → 返回字节 → 前端渲染`

### 2.1 后端：容器转换命令被 shell 拆参（致命）

**现象**：`file-preview` 返回 `{code:400,"libreoffice 未产出文件（容器退出码 0 但无 .pdf 产物）"}`；`file-markdown` 返回 `anydoc: one document per invocation: unexpected second input '质量手册.doc'`。

**根因**：`DocumentConvertClient.ExecDockerAsync` 用
```csharp
Arguments = $"exec {container} sh -c \"{args}\""   // 旧写法
```
`ProcessStartInfo.Arguments` 是**单个字符串**，.NET 会再做一次引号解析，`sh -c "..."` 内嵌套的引号被吃掉 → 容器内 sh 把 `XASL-QM 质量手册.doc` 按空格拆成两个参数 → soffice/anydoc 找不到输入文件，退出码 0 且无产物。

**修复**：改用 `ProcessStartInfo.ArgumentList` 逐参传递（.NET 负责正确转义），三处调用点（pdf / markdown / 格式化转换）同时受益。

**验证**：`file-preview` → `%PDF-` 600KB；`file-markdown` → 22KB 正常 Markdown。

### 2.2 前端：`<iframe src>` 无法携带 JWT（致命）

**根因**：本平台鉴权走 `Authorization: Bearer` 头（`YZH.Core.Api/Filters` JWT），`iframe/img` 由浏览器直接发起请求，**无法带头** → 实测无鉴权请求 401（`application/problem+json`）。历史项目正是因此改用「axios blob（带认证）+ 本地渲染」。

**修复**：
- `yzh.vue.core/src/api/client.ts` 新增 **`getBlob(url, params)`**：带 Token 取二进制；`content-type: application/json` 时按业务错误解析 message 抛出（避免把错误体当文件渲染）。
- 预览统一「先取 Blob → `URL.createObjectURL` → 交给渲染器」。
- 顺带修复 `downloadFile` / `downloadTemplateFile`：原实现把 `responseType: 'blob'` 塞进了 `params`（fetch 客户端不支持），实际请求变成 `storagePath=[object Object]` → 下载必失败。

### 2.3 环境：转换容器零 CJK 字体（中文全变方块）

**根因**：`yzh-libreoffice` 基于 `woahbase/alpine-libreoffice:latest`，`fc-list` 193 项字体中 **CJK 字体数为 0** → 中文文档转 PDF 后汉字渲染成「豆腐块」（数字/英文正常，极易被误判为「文件本身有问题」）。

**修复**：新增 `docker/libreoffice/Dockerfile`（基线 + `apk add font-noto-cjk`），`docker/compose.yml` 改为 `build: ./libreoffice`。

**验证**：镜像内 `fc-list | grep -ci cjk` = **30**；容器内转换中文 HTML 生成的 PDF 中检出内嵌字体 **`NotoSerifCJKsc`**。

## 五、连带修复的数据层缺口

### 5.1 `cert_file_requirement` 列名与模板列缺失

- **现象**：日志持续刷 `Unknown column 'template_file_name'`（实测 246 次/小时）。
- **根因**：旧架构该表列名为 snake_case（`template_file_name` / `template_storage_path` / `standard_code`），新库建表采用 **PascalCase**（`FolderCode` / `FileNameTemplate` / `IsRequired` …），且**模板文件三列在建表时丢失**；`FileRequirement` 实体仍映射 snake_case → 该表任何 ORM/原生查询都失败。
- **修复**：
  1. `CertPlatform.Shared/Entities/Cert/FileRequirement.cs` 列映射改为 PascalCase（与 `cert_sys_config` / `cert_standard_directory_file` 惯例一致）；
  2. 新增迁移脚本补回 `TemplateStoragePath` / `TemplateFileName` / `StandardCode`（幂等，information_schema 守卫）；
  3. `GetFileInfoAsync` 的 FR 查询改为真实列名。
- **验证**：重启后日志异常计数归零；FR 分支在无数据时自然降级到「标准目录实际文件」。

### 5.2 同类风险提示

`CertPlatform.Shared/Entities/Cert` 下仍有 **15 处 snake_case 列映射**（vs 20 处 PascalCase），与数据库 PascalCase 列不一致 → 同类 `Unknown column` 会按表逐个暴露。建议列入迁移收尾清单（§6.4）。

## 六、仍待完善（建议优先级）

1. **预览产物落库缓存（性能）**：`GetFilePreviewPdfAsync` 实时转换后未回写 `PreviewPdfPath`，每次预览都重转。建议按 `OfficeConvertService.ConvertToPdfAsync` 的既有约定（`BuildSiblingPath(StoragePath, ".pdf")` → `_storage.UploadAsync` → `file.PreviewPdfPath = ...` → `_db.UpdateAsync`）落库，第二次预览秒开。
2. **转换队列积压**：库里 1500+ 转换任务使 soffice 长期占用，on-demand 预览被拖慢（观察到的「一直加载中」多为此原因，非代码缺陷）。建议：限制队列并发/优先级，或让预览请求走队列产物优先。
3. **AIAnalysisTab / PromptVerifyTab 细节对齐**：历史版字段卡片含「字段名称 / 唯一编码 / 类型（中文选项）/ 必填开关 / 描述 / 提取值」，表格卡片含「表格名称 / 唯一编码 / 描述 / 列定义 / 添加列 / 提取数据预览折叠」；新版结构相同但字段更紧凑、类型选项为英文（string/number/date）、提取数据预览默认收起。建议按历史版微调文案与默认展开策略。
4. **实体列名统一（迁移收尾）**：见 §5.2，建议逐个表核对 `Entity vs SHOW COLUMNS`。
5. **目录树队列锁定 UI**：历史版有「队列执行中，文件暂不可操作」锁定条与节点锁图标（对应 `useYzhQueue`），新版未移植。
6. **测试工具链**：`cert-admin` 的 `vitest` 未安装（devDependency 已声明），`npm test` 无法运行，`vue-tsc` 对 `index.test.ts` 报 `Cannot find module 'vitest'`。建议补装或移出 typecheck 范围。
