## 三、本轮改动清单

**页面改造** `pages/workflow/directory/index.vue`
1. 目录树搜索过滤（`filteredTree` 计算属性，历史项目搜索框的实际行为）
2. 转换队列状态条：`getActiveQueue(directoryCode)` + 5s 轮询 + `cancelConvert(queueCode)` + 跳转队列监控
3. 工具栏：新增「导出打包」「使用帮助」，接入 `isBusy` 忙碌保护
4. 表格：新增「状态」列（图标 + 文案），文件行新增「替换」「AI 分析」
5. 批量删除：统一确认 → 逐项调用 delete API → 汇总失败数
6. 文件重命名：`updateFile(code, { FileName, Description })`，保留 `force=true` 二次确认通道
7. 底部状态栏：项目数 / 文件夹数 / 文件数 + 总大小
8. AI 分析弹窗：默认载入该文件已保存规则的 Prompt → `verifyPrompt` → 展示提取字段与表格
9. 布局修正：`queue-banner` 与左右栏改为「列 + 行」两级 flex，避免状态条挤压三栏布局

**新增组件** `pages/workflow/directory/components/ConfigTab.vue`
- 目录配置（`cert_standard_directory_config`）列表 / 新建 / 编辑 / 删除（对应 `/StandardDirectory/configs*`）

**共享层** `cert-share/src/composables/useDirectoryApi.ts`
- `createFolder` / `updateFolder` / `deleteFolder` / `updateFile` / `deleteFile` / `createDirectoryConfig` / `updateDirectoryConfig` / `deleteDirectoryConfig` 统一返回 `BizResult { code, msg, data }`
  > 这些端点**始终返回 HTTP 200**，业务成败在 body 的 `code` 字段；旧封装丢弃了 body，导致失败也提示「成功」。
- 新增 `retryFailedConversions()`（文档提取规则页共用）

**全局** `cert-admin/src/main.ts`
- 注册 Element Plus 中文语言包 `zh-cn`：`app.use(ElementPlus, { locale: zhCn })`
  > 修复前：`ElMessageBox` 按钮为 Cancel/OK、分页/表格空态等内置文案均为英文（历史项目全中文）。

## 五、仍待完善（建议优先级）

### 5.1 上传队列通知栏（UploadQueueBanner，旧 446 行）
历史项目在页面顶部提供「逐文件上传进度 + 队列名 + 进度条 + 取消任务 + 清理已完成」的常驻通知栏，是本页最重的交互差异。
新架构可复用：`getUploadStatus(taskId)`、`getConvertProgress(taskId)`、`cancelConvert(queueCode)`、`uploadCancel(taskId)`；建议按「上传任务列表 + 转换队列」两段实现，并沿用现有 5s 轮询。

### 5.2 转换进度面板（ConvertProgressPanel，旧 248 行）
按文件/队列展示转换明细（成功/失败/耗时/错误原因），便于排查「文档提取失败」类问题。可基于 `getConvertProgress(taskId)` 实现。

### 5.3 文件「替换」功能
历史项目此按钮为「功能开发中」占位，本轮保持一致。若要做实：`POST /files/{code}` 只能改文件名/备注，替换文件内容需要新的端点（复用 `upload-file-v2` + 覆盖 StoragePath 并重建转换队列）。

### 5.4 后端缺口：提示词模板无接口 —— ✅ **本轮已修复**（见 §六）
前端 `@share/api/workflow/prompt-template.ts` 调用 `/api/PromptTemplate/getList` **实测 404** —— 新后端此前只有实体 `CertPlatform.Shared/Entities/Wf/PromptTemplate.cs`，没有对应 Controller（`wf_prompt_template` 表有 7 条存量数据却无人能读）。
→ 影响：AI 分析弹窗的「提示词模板」下拉为空；提示词模板管理页同样不可用。
→ 已于本轮补齐 `PromptTemplateController`（getList/save/delete/activate/active/{type}），实体映射同时改写为新架构 SqlSugar 风格。

### 5.5 目录模板导入
历史项目 `ConfigTab` 之外还有目录模板（`cert_directory_template`）的维护入口，新架构后端已有 `DirectoryTemplateController`（0 数据），前端仅在 API 层可用，建议补页面。

### 5.5.1 操作列可见性（本轮已修）
用户反馈「页面没有 AI 分析按钮」。复核：按钮一直在（与历史一致，仅文件行有），但**看不到**——列宽合计 740px 超过窄窗口下面板宽度，`操作` 列被挤出可视区且横向滚动条默认隐藏。
→ 已修：操作列 `position: sticky; right: 0`（对齐历史 `el-table fixed="right"`）+ 表格 `min-width: 760px` + 容器 `overflow: auto` + 名称列单行省略 + 左侧树宽 `clamp(180px, 20vw, 280px)`。
→ 详因与证据见《文档提取office转Markdown全链路-测试与修复记录-V1.md》§1.2。

### 6.2 新增：Prompt 模板后端（修复 `/api/PromptTemplate/*` 404）

| 文件 | 变更 |
|---|---|
| `CertPlatform.Shared/Entities/Wf/PromptTemplate.cs` | 映射方式由旧 DataAnnotations（`[Table]`/`[Column]`）**改写为新架构 SqlSugar**（`[SugarTable]`/`[SugarColumn]`），命名空间与属性名保持不变（对齐 `Entities/Dir` 惯例）；**不声明 `IsValid`** —— 该表无此列，声明后框架会自动追加 `IsValid = 1` 导致 `Unknown column`（本轮之前已踩过同类坑） |
