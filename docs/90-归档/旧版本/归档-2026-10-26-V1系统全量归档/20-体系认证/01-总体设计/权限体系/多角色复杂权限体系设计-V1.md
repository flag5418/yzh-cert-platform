## 〇、设计理念与设计思想

### 0.1 核心定位：YZH.Core 是「纯 RBAC 底座」，不感知业务

```
┌─────────────────────────────────────────────────────────────────────────┐
│                                                                         │
│    ┌──────────────────────────────┐     ┌────────────────────────────┐  │
│    │        YZH.Core 底座         │     │     业务层（Admin/Auditor） │  │
│    │                              │     │                            │  │
│    │  ▪ 机构-人员 关系建立         │     │  ▪ 业务实体定义            │  │
│    │  ▪ 角色-人员 关系建立         │◄───►│  ▪ 业务表 + Attach 扩展表  │  │
│    │  ▪ 角色-菜单 关系建立         │ RPC │  ▪ 建企业/用户时调标准接口 │  │
│    │  ▪ 角色-接口 关系建立         │     │  ▪ 业务特有数据权限控制     │  │
│    │  ▪ Token 签发与鉴权           │     │                            │  │
│    │  ▪ SSO 挤号 + Token 续租      │     │                            │  │
│    │                              │     │                            │  │
│    │  ★ 不知道「认证项目」是什么   │     │  ★ 知道业务，但不重复造轮子 │  │
│    │  ★ 不知道「维护人员」是什么   │     │  ★ 扩展通过 Attach 表完成  │  │
│    └──────────────────────────────┘     └────────────────────────────┘  │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

**设计意图**：

| 层 | 职责 | 边界 |
|----|------|------|
| **YZH.Core** | 通用 RBAC：机构树、人员、角色、菜单注册、接口注册、登录鉴权 | 不知道业务语义，只知道「某用户属于某机构，有某些角色」 |
| **业务层** | 定义业务实体（企业/审核员/标准/...），管理页面和流程 | 建立实体时通过标准接口写入 Sys_Org / Sys_USER / Sys_User_Role |

**核心思想**：权限控制（能看什么菜单、能调什么接口）由 **YZH.Core 标准 RBAC** 完成；业务数据的特殊可见性规则由 **业务层独立实现**。

### 0.2 Attach 扩展机制：业务实体的存储策略

**YZH.Core 定义标准表**：`Sys_Org`（机构）、`Sys_User`（人员）、`Sys_User_Role`（用户-角色关联）

**业务层定义扩展表（Attach）**：

```
┌─────────────────────────────────────────────────────────────────�
│                         Attach 表设计                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   �─────────────────────┐       ┌─────────────────────┐        │
│   │   attach_org 基类    │       │   attach_user 基类   │        │
│   │   ────────────────  │       │   ────────────────  │        │
│   │   id                │       │   id                │        │
│   │   code (↔ Org.Code) │       │   code (↔ User.Code)│        │
│   │   org_code          │       │   user_code         │        │
│   │   attach_type       │       │   attach_type       │        │
│   │   [公共字段...]      │       │   [公共字段...]      │        │
│   └──────────┬──────────┘       └──────────┬──────────┘        │
│              │                             │                    │
│   ┌──────────┴──────────┐       ┌──────────┴──────────┐        │
│   │  attach_ent_org     │       │  attach_maintainer  │        │
│   │  (企业扩展字段)      │       │  (维护人员扩展字段)  │        │
│   ├─────────────────────┤       ├─────────────────────┤        │
│   │  business_scope     │       │  scope_level        │        │
│   │  registered_capital │       │  department         │        │
│   │  legal_person       │       └─────────────────────┘        │
│   └─────────────────────┘                                       │
│                                                                 │
│   ★ Attach = 业务特有字段扩展，一对一关联 Sys_Org / Sys_User    │
│   ★ 每类业务实体（企业、维护人员、审核员...）对应一张 Attach 子表│
└─────────────────────────────────────────────────────────────────┘
```

**Attach 表与标准表的关系**：

| 标准表 | Attach 基类 | Attach 子类示例 |
|--------|------------|-----------------|
| Sys_Org | attach_org | attach_ent_org（企业）、attach_auditor_org（审核机构） |
| Sys_User | attach_user | attach_maintainer（维护人员）、attach_auditor（审核员） |

### 0.3 创建流程：业务实体 → YZH.Core 标准表

**核心原则**：Attach 实体的创建接口独立编写，在创建 Attach 记录时**同步写入 YZH.Core 标准表**并建立角色关联。

```
�─────────────────────────────────────────────────────────────────────────┐
│                        Attach 实体创建流程                               │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   业务层接口（独立编写，无继承）                                          │
│   ┌───────────────────────────────────────────────────────────────┐     │
│   │ POST /api/biz/ent-org/create                                 │     │
│   │                                                               │     │
│   │ using var tran = BeginTransaction()                          │     │
│   │                                                               │     │
│   │ 1. INSERT INTO attach_org (code, org_code, attach_type='ent')│     │
│   │ 2. INSERT INTO attach_ent_org (code, business_scope, ...)    │     │
│   │ 3. ★ 调用 YZH.Core 标准接口 → INSERT INTO Sys_Org            │     │
│   │ 4. IF 有管理员用户                                           │     │
│   │    ├── INSERT INTO Sys_User                                  │     │
│   │    └── INSERT INTO Sys_User_Role (绑定 ENT_ADMIN 角色)        │     │
│   │ 5. tran.Commit()                                             │     │
│   └───────────────────────────────────────────────────────────────┘     │
│                                                                         │
│   结果：                                                                │
│   ▪ Attach 表记录业务扩展数据                                           │
│   ▪ Sys_Org 有该机构记录                                                │
│   ▪ Sys_User 有该用户记录                                               │
│   ▪ Sys_User_Role 绑定了角色 → 自动获得菜单+接口权限                     │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

**关键设计点**：
- 每个业务实体（企业/维护人员/审核员/...）都有**独立的管理页面和创建接口**
- 这些接口**没有任何基类可继承**，所有方法单独编写
- 创建时必须**在事务内**完成 Attach 表 + Sys_Org/Sys_User + Sys_User_Role 的写入
- 用户一旦建立并绑定了角色，**立即拥有该角色的菜单权限和接口权限**

### 0.4 权限控制的两层分离

```
┌─────────────────────────────────────────────────────────────────────────�
│                           权限控制分离模型                               │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   层 1：功能权限（YZH.Core 负责）                                        │
│   ─────────────────────────────────────────────────────────────────     │
│   ▪ 你能看到哪些菜单？           → Sys_Role_Menu                        │
│   ▪ 你能调用哪些接口？           → Sys_Role_Api                         │
│   ▪ 如何控制？                   → 用户绑定角色，角色绑定菜单和接口       │
│   ▪ 业务层是否需关心？           → 否，自动继承                          │
│                                                                         │
│   层 2：数据权限（业务层负责）                                           │
│   ─────────────────────────────────────────────────────────────────     │
│   ▪ 你能看到菜单中的哪些数据行？  → 业务层独立实现                        │
│   ▪ 你能操作哪些数据？           → 业务层独立实现                        │
│   ▪ 实现方式？                   → 手写 SQL 或 Attribute + 配置表        │
│   ▪ YZH.Core 是否介入？          → 完全不介入                            │
│                                                                         │
│   ★ 分离原因：                                                          │
│   ▪ 不同业务场景的数据权限规则差异巨大                                    │
│   ▪ YZH.Core 是通用底座，不应感知业务规则                                │
│   ▪ 业务层可以灵活选择最合适的实现方式                                    │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 0.5 设计原则汇总

| 原则 | 说明 |
|------|------|
| **底座无业务** | YZH.Core 只做 RBAC，不知道"认证项目""维护人员"等业务概念 |
| **Attach 扩展** | 业务字段通过 Attach 表挂载到 Sys_Org / Sys_User |
| **创建即授权** | 建 Attach 实体时同步建立标准表记录 + 角色绑定 |
| **功能权限标准化** | 菜单权限 + 接口权限由 RBAC 统一管控，自动继承 |
| **数据权限自主化** | 业务层独立决定数据过滤策略，YZH.Core 不介入 |
| **接口独立编写** | 每个业务实体的管理接口单独编写，不依赖基类 |

### 2.2 SSO 挤号机制

**核心原理**：每个用户在 Redis 维护一个版本号，登录时生成新版本写入 Redis + JWT，校验时比对。

```
┌─────────────────────────────────────────────────────────────────────┐
│                          SSO 挤号流程                                │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│     设备 A 登录                  Redis                    设备 B     │
│        │                    token_ver:xxx                  │        │
│        │ 用户名+密码                                      │        │
│        ▼                           │                      │        │
│   ┌─────────────�                  │                      │        │
│   │ AuthController│                 │                      │        │
│   └──────┬──────┘                  │                      │        │
│          │                         │                      │        │
│          ├─ BumpVersion() ────────►│  ver = "aaa111"      │        │
│          │                         │                      │        │
│          ├─ GenerateToken(ver=aaa) │                      │        │
│          │                         │                      │        │
│          ▼                         │                      │        │
│   Token_A (ver="aaa111")           │                      │        │
│                                    │                              │
│                          设备 B 登录（同账号）                       │
│                                    │                      │        │
│                          用户名+密码 �─────────────────────�        │
│                                    │                              │
│                           BumpVersion() ──────────────► ver = "bbb222"  │
│                                    │                      │        │
│                           GenerateToken(ver=bbb)             │        │
│                                    │                      │        │
│                                    │            Token_B (ver="bbb222") │
│                                    │                              │
│     设备 A 发起请求                 │                              │
│        │                           │                              │
│        │ Token(ver="aaa111")       │                              │
│        ▼                           │                              │
│   ┌─────────────�                  │                              │
│   │ YzhAuthFilter│                 │                              │
│   └──────┬──────┘                  │                              │
│          │                         │                              │
│          ├─ ValidateVersion("aaa111") ──────────────► 当前 ver="bbb222" │
│          │                         │                              │
│          │ aaa111 ≠ bbb222        │                              │
│          │                         │                              │
│          ▼                         │                              │

│                                                                     │

```

**关键代码**（已实现）：

```csharp
// TokenVersionService.cs - Redis 版本号维护
public class TokenVersionService
{
    // 登录时：生成新版本 + 写入 Redis
    public async Task<string> BumpVersionAsync(string userCode)
    {
        var version = Guid.NewGuid().ToString("N");
        await _cache.SetStringAsync($"token_ver:{userCode}", version, 
            new DistributedCacheEntryOptions { AbsoluteExpirationRelativeToNow = TimeSpan.FromDays(30) });
        return version;
    }
    
    // 校验时：比对版本号
    public async Task<bool> ValidateVersionAsync(string userCode, string tokenVersion)
    {
        var current = await _cache.GetStringAsync($"token_ver:{userCode}");
        return string.Equals(current, tokenVersion, StringComparison.OrdinalIgnoreCase);
    }
}

// AuthController.cs - 登录时挤掉旧 Token
[HttpPost("login")]
[AllowAnonymous]
public async Task<IActionResult> Login([FromBody] LoginRequest req)
{
    // ... 验证用户名密码 ...
    
    // ★ 生成新版本号 → 所有旧 Token 失效
    var ssoVersion = await _tokenVersion.BumpVersionAsync(userCode);
    var token = _jwt.GenerateToken(userCode, userName, new[] { roleId.ToString() }, ssoVersion);
    
    return Ok(ApiResponse<LoginResponse>.Ok(new LoginResponse { Token = token, ... }));
}

// YzhAuthFilter.cs - 请求时校验
public async Task OnAuthorizationAsync(AuthorizationFilterContext context)
{
    // ... 跳过 Anonymous ...
    
    var isValid = await _tokenVersion.ValidateVersionAsync(userCode, tokenVersion);
    if (!isValid)
    {
        context.Result = new JsonResult(new SSOExpiredResponse
        {
            Code = 4011,
            Message = "您的账号已在其他设备登录，请重新登录"
        }) { StatusCode = 401 };
    }
}
```

### 2.3 Token 自动续租

**场景**：用户正在操作，Token 即将过期，续租避免中断。

**实现**：剩余有效期 < 30 分钟时，自动签发新 Token 写入 Response Header。

```
┌─────────────────────────────────────────────────────────────────────�
│                         Token 续租流程                                │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   客户端请求                                                          │
│      │                                                              │
│      │ Token (expires in 25min)                                     │
│      ▼                                                              │
│   ┌─────────────┐                                                   │
│   │ YzhAuthFilter│                                                  │
│   └──────┬──────┘                                                   │
│          │                                                          │
│          ├─ 检查 Token.Exp - Now < 30min ?                         │
│          │   Yes → 生成新 Token（7天有效期）                        │
│          │         写入 Response.Headers["X-New-Token"]              │
│          │                                                          │
│          ▼                                                          │
│   响应头：X-New-Token: eyJhbG...                                   │
│                                                                     │
│   客户端检测到 X-New-Token → 替换本地 Token                          │
│   （前端 YzhApiClient 自动处理，用户无感）                            │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

**关键代码**：

```csharp
// YzhAuthFilter.cs - 续租判断
private async Task TryRenewToken(AuthorizationFilterContext context, string userCode)
{
    var remaining = expDateTime - DateTime.UtcNow;
    
    if (remaining < TimeSpan.FromMinutes(30) && remaining > TimeSpan.Zero)
    {
        var userName = context.HttpContext.User.FindFirst(ClaimTypes.Name)?.Value ?? "";
        var roles = context.HttpContext.User.FindAll(ClaimTypes.Role).Select(c => c.Value);
        var tokenVer = context.HttpContext.User.FindFirst("ver")?.Value ?? "";

        // ★ RenewToken 保持 SSO 版本号不变，只延长有效期
        var newToken = _jwt.RenewToken(userCode, userName, roles, tokenVer, TimeSpan.FromDays(7));
        context.HttpContext.Response.Headers["X-New-Token"] = newToken;
    }
}

// 前端 YzhApiClient 自动续租处理
this.instance.interceptors.response.use((response) => {
    const newToken = response.headers['x-new-token'];
    if (newToken) {
        // 替换本地存储的 Token
        localStorage.setItem('YZH_TOKEN', newToken);
        tokenStore.set(newToken);
    }
    return response;
});
```

// PermissionFilter.cs
public class PermissionFilter : IAsyncAuthorizationFilter
{
    private readonly IRolePermissionService _permission;
    
    public async Task OnAuthorizationAsync(AuthorizationFilterContext context)
    {
        var user = context.HttpContext.User;
        if (!user.Identity?.IsAuthenticated ?? true) return;
        
        // SuperAdmin 跳过接口校验
        var roleId = user.FindFirst("role_id")?.Value;
        if (RoleIds.IsSuperAdmin(int.Parse(roleId ?? "0"))) return;
        
        // 获取当前请求的 API Code
        var method = context.HttpContext.Request.Method;
        var path = context.HttpContext.Request.Path.Value?.ToLower();
        var apiCode = $"{method} {path}";
        
        // 检查角色是否有该接口权限
        var roleCodes = user.FindAll(ClaimTypes.Role).Select(c => c.Value);
        var hasPermission = await _permission.HasApiPermissionAsync(roleCodes, apiCode);
        
        if (!hasPermission)
        {
            context.Result = new JsonResult(new ApiResponse
            {
                Success = false,
                Code = 4031,
                Message = "无权访问此接口"
            }) { StatusCode = 403 };
        }
    }
}

## 四、数据权限设计

### 4.1 设计理念：数据权限由业务层独立实现

根据 **设计理念 §0.4**，YZH.Core 不负责数据行的过滤控制。数据权限完全由业务层根据具体场景独立实现。

### 4.2 实现方式选择

| 方式 | 说明 | 适用场景 |
|------|------|---------|
| **手写 SQL** | 在 Service/Repository 中直接编写数据过滤逻辑 | 简单、一次性、规则固定的场景 |
| **Attribute + 配置表** | 通过自定义特性（如 `[BizAuthorize]`）+ 配置表动态过滤 | 需要运行时配置、多维度授权的场景 |

### 4.3 实现原则

- **核心标准**：数据权限过滤逻辑写在业务层 Service/Repository 中，不依赖任何基类钩子
- **事务边界**：涉及多表关联的权限过滤，应在业务层手动维护事务一致性
- **性能考量**：复杂的权限过滤推荐使用 SQL 直接过滤，减少 ORM 带来的额外查询
- **代码组织**：建议在每个业务模块的 Service 中集中处理该模块的数据权限逻辑

### 4.4 典型场景示例

**场景示例 1**：维护人员只能看到被授权的标准配置

### 5.3 保护实现

```csharp
// YzhConfigController.Base.cs - 配置编辑保护
public async Task<IActionResult> UpdateConfig([FromBody] SysConfig config)
{
    var user = _userContext.GetCurrent();
    
    // 1. 核心配置仅 SuperAdmin 可修改
    if (config.IsCore && user.RoleId != RoleIds.SuperAdmin)
    {
        return Forbid(ApiResponse.Fail("核心配置仅超级管理员可修改"));
    }
    
    // 2. 配置维护员只能编辑草稿态
    if (user.RoleId == RoleIds.ConfigMaintainer)
    {
        var existing = await _repo.GetByCodeAsync(config.Code);
        if (existing != null && existing.Status == ConfigStatus.Published)
        {
            return Forbid(ApiResponse.Fail("已发布配置维护员无法直接修改，请联系管理员"));
        }
        
        // 维护员只能修改指定分类
        if (!await _configScopeService.CanMaintain(user.UserCode, config.Category))
        {
            return Forbid(ApiResponse.Fail("该配置不在您的维护范围内"));
        }
        
        // 维护员修改后强制回到草稿态
        config.Status = ConfigStatus.Draft;
        config.MaintainerCode = user.UserCode;
    }
    
    // 3. 执行更新
    await _repo.UpdateAsync(config);
    return Ok(ApiResponse.Ok(config));
}

// 发布操作（仅 Admin 以上）
[HttpPost("publish")]
public async Task<IActionResult> PublishConfig([FromBody] string code)
{
    var user = _userContext.GetCurrent();
    
    // 维护员禁止执行发布
    if (user.RoleId == RoleIds.ConfigMaintainer)
    {
        return Forbid(ApiResponse.Fail("维护员无权发布配置，请联系管理员"));
    }
    
    var config = await _repo.GetByCodeAsync(code);
    if (config == null) return NotFound(ApiResponse.Fail("配置不存在"));
    
    config.Status = ConfigStatus.Published;
    await _repo.UpdateAsync(config);
    
    // ★ 发布后触发配置变更事件（刷新缓存等）
    _eventBus.Publish(new ConfigPublishedEvent(config));
    
    return Ok(ApiResponse.Ok(config));
}
```

### 6.1 Token 续租自动处理

```typescript
// yzh.vue.core/api/client.ts
import axios from 'axios';

const instance = axios.create({
    baseURL: import.meta.env.VITE_API_BASE || '/api',
    timeout: 15000,
});

// 请求拦截器：注入 Token
instance.interceptors.request.use((config) => {
    const token = tokenStore.get();
    if (token) {
        config.headers.Authorization = `Bearer ${token}`;
    }
    return config;
});

// 响应拦截器：处理续租 Token
instance.interceptors.response.use(
    (response) => {
        // ★ 后端返回新 Token 时自动替换
        const newToken = response.headers['x-new-token'];
        if (newToken) {
            tokenStore.set(newToken);
            localStorage.setItem('YZH_TOKEN', newToken);
        }
        return response;
    },
    (error) => {
        // SSO 挤号 → 4011 特殊处理
        if (error.response?.status === 401) {
            const code = error.response.data?.code;
            if (code === 4011) {
                // 账号已在其他设备登录
                store.dispatch('forceLogout', '您的账号已在其他设备登录');
            } else {
                // Token 过期
                store.dispatch('forceLogout', '登录已过期，请重新登录');
            }
            router.push('/login');
        }
        return Promise.reject(error);
    }
);
```

### 6.2 前端权限指令

```typescript
// share/directives/permission.ts
import type { App } from 'vue';

export function setupPermissionDirective(app: App) {
    // v-permission="['admin', 'config_edit']"
    app.directive('permission', {
        mounted(el, binding) {
            const userStore = useUserStore();
            const { value } = binding;
            
            if (!value || (Array.isArray(value) && value.length === 0)) return;
            
            const required = Array.isArray(value) ? value : [value];
            const hasPermission = required.some(p => userStore.permissions.includes(p));
            
            if (!hasPermission) {
                el.parentNode?.removeChild(el); // 无权限则移除元素
            }
        }
    });
}
```

## 八、安全红线清单

| 红线 | 说明 | 校验方式 |
|------|------|---------|
| **核心配置保护** | IsCore=true 的配置仅 SuperAdmin 可修改 | Controller 硬编码校验 |
| **维护员范围** | 维护员只能编辑指定 Category 的配置 | sys_maintainer_scope 校验 |
| **维护员禁止发布** | 维护员无法调用 Publish 接口 | 接口权限硬编码 |
| **业务数据权限** | 数据权限过滤由业务层独立实现，不依赖基类 | 业务 Service + SQL |
| **SSO 挤号** | 同账号新登录后旧 Token 全部失效 | TokenVersionService |
| **生产免认证失效** | RequireAuth=true 时 YZHAnonymous 无效 | appsettings 配置 |
| **审计日志** | 所有 UPDATE / DELETE / ConfigPublish 必须记录 | YzhAuditingFilter |
