## 零、强制约定

| 约定 | 内容 | 依据 |
|---|---|---|

### 0.1 ★★ `OrgCode` 语义陷阱（每个写这段代码的人必读）

```csharp
// CertPlatform.Shared/Entities/Doc/ExtractionResult.cs:20-23
[Required, StringLength(36)]
[SugarColumn(ColumnName = "OrgCode")]
[Description("企业编码（非机构编码）")]     // ★ 评审 #1 补充
public string EnterpriseCode { get; set; }
```

**`cert_extraction_result.OrgCode` 列里存的是「企业 Code」，不是「认证机构 Code」，也不是「专家工作区 Code」。**

三个 `OrgCode` 在本系统里指的是**三个不同的东西**：

| 表 | `OrgCode` 实际含义 | 取值来源 |
|---|---|---|
| `cert_extification_body` / `cert_validation_rule` | **认证机构 Code** | `cert_certification_body.Code` |
| `cert_expert_task` / `cert_expert_task_item` | **专家工作区 Code** | `WorkspaceContextService.Resolve()` |
| **`cert_extraction_result`** | ★ **企业 Code** | `cert_enterprise.Code` |

**因此本模块所有涉及提取结果的 SQL，参数名必须用 `@EnterpriseCode`（不是 `@OrgCode`）—— 参数名即语义**：

```sql
-- ✅ 正确
SELECT ExtractedValue FROM cert_extraction_result
WHERE OrgCode = @EnterpriseCode      -- ← 语义直白：这一列存的是企业
  AND StandardCode = @StandardCode
  AND PhaseCode = @StageCode
  AND IsValid = 1
  AND IsDeleted = 0;

-- ⛔ 错误（虽然能跑通，但埋雷）
WHERE OrgCode = @OrgCode
```

> **原因**：该表原名 `ent_extraction_result`（企业域），`OrgCode` 语义随 `ent_` → `cert_` 改名被保留（见 `fix-restore-extraction-result-2026-09-25.sql`）。改名时列语义未变，导致列名与内容不符。
>
> ⛔ **不改列名**（会破坏企业资料管理模块的所有查询）。
> ✅ **用注释 + 参数名 + `[Description]` 三重防御**（评审 #1 建议，已采纳）。
> 📖 完整说明见 [05 号 §2.1](05-详细设计-补录与日志-V1.md) + [13 号 E0-3](13-执行计划与障碍清单-V1.md)。

### 0.3 ★★★ 信封契约（★ 原设计通篇写错，必须先纠正）

> 依据：`src/yzh-core/YZH.Core.Stand/Models/Result/ApiResponse.cs`（**实测**）

```csharp
[JsonPropertyName("success")]   public bool Success { get; init; }   // ★ 唯一判据
[JsonPropertyName("message")]   public string Message { get; init; } = "";  // 成功提示
[JsonPropertyName("err")]       public string Err     { get; init; } = "";  // ★ 失败原因【唯一出口】
[JsonPropertyName("data")]      public T?    Data     { get; init; }
[JsonPropertyName("code")]      public int    Code     { get; init; }      // ★ 注释写明「前端禁止读」
[JsonPropertyName("timestamp")] public DateTime Timestamp
```

**构造封闭的三条不变量**（`ApiResponse.cs:8-19` 注释）：

| 条件 | 保证 |
|---|---|
| `success:false` | ⇒ `Err` 非空 |
| `success:true` | ⇒ `Err` 为空 |
| `success:false` | ⇒ `Message` 为空（★ 错误文本只从 `err` 出） |

**⛔ 由此推出 4 条前端铁律**：

```ts
// ✅ 唯一正确的判据
if (res.success) { /* ... */ } else { ElMessage.error(res.err) }

// ⛔ 禁止读 res.code 判断业务（它是 int 200/400/500，注释明确「前端禁止读」）
if (res.code === 200) { }

// ⛔ 禁止读 res.message 拿错误文案（失败时它恒为 ""）
ElMessage.error(res.message)   // ← 永远弹空

// ⛔ 禁止用字符串错误码 switch（res.code 是 int，不是 'DATA_GAP_UNRESOLVED'）
switch (res.code) { case 'DATA_GAP_UNRESOLVED': }
```

**业务错误码的正确位置**：`data.errorCode`

```json
{
  "success": false,
  "err": "还有 12 条结果未认可",
  "data": { "ErrorCode": "REVIEW_INCOMPLETE", "PendingCodes": ["t1i3...", "t1i5..."] },
  "code": 400
}
```

```ts
// ✅ 正确写法
if (!res.success) {
  switch (res.data?.ErrorCode) {
    case 'REVIEW_INCOMPLETE': /* ... */ break
    case 'DATA_GAP_UNRESOLVED': /* ... */ break
    default: ElMessage.error(res.err)
  }
}
```

> ⚠️ `data` 内的字段**一律 PascalCase**（铁律七），但 `ErrorCode` / `PendingCodes` 的**值**可以用字符串枚举（那是值不是字段名）。

### 0.4 ★ 响应 `data` 字段的类型规范（评审 O2）

| 场景 | `data` 类型 | TS 定义 |
|---|---|---|
| 单个对象 | `T` | `XxxDto` |
| 列表（不分页） | `T[]` | `XxxDto[]` |
| **分页列表** | ★ `PagedResult<T>`（见下） | `PagedResult<T>` |
| 动作无返回 | `null` | `void` |
| 动作有返回 | `T`（最小对象） | `XxxActionResult` |

```ts
// cert-share/src/types/common.ts
export interface PagedResult<T> {
  Total: number
  PageIndex: number
  PageSize: number
  List: T[]        // ★ PascalCase
}
```

> ⚠️ 信封字段（`success`/`message`/`err`/`data`/`code`/`timestamp`）是 **camelCase 框架契约**（例外 E1）；
> `data` 内部的自定义字段**一律 PascalCase**（铁律七）。两者不冲突。

**前端 API 必须显式声明返回类型**：

```ts
// ✅ 有显式返回类型，结构变了编译就报错
export async function getNcItems(q: NcItemQuery): Promise<PagedResult<NcItemDto>> {
  return yzhApi.get('/api/ExpertTask/nc-items', { params: q })
}

// ⛔ 无返回类型 → 调用方要写 as，结构变了编译也不报错
export async function getNcItems(q: NcItemQuery) { ... }
```

## 一、错误码表

> ⛔ **下表的 `code` 列不是 `ApiResponse.code`**（那是 int 且前端禁止读，§0.3）。
> 它是 `data.errorCode` 的**取值**，用于前端业务分支。

| `data.errorCode` | HTTP | 含义 | 前端处理 |
|---|---|---|---|
| `OK` | 200 | 成功 | — |
| `PARAM_INVALID` | 200 | 参数校验失败 | 提示 message |
| `BIZ_LOCKED` | 200 | **业务锁占用**（02 号 §6） | 提示占用中的任务编号 |
| `STANDARD_NOT_ASSIGNED` | 200 | 标准未分配给该企业该阶段 | 提示 |
| `CROSS_STANDARD_NOT_ALLOWED` | 200 | **局部任务跨标准**（D03） | 提示只能选一个标准 |
| `PARTIAL_ITEM_NOT_FOUND` | 200 | 勾选项无效或不属于该范围 | 提示 |
| `STAGE_INVALID` | 200 | 阶段无效 | 提示 |
| `NO_STANDARD_TEMPLATE` | 200 | 该标准无可用报告模板 | 提示（该标准被排除） |
| `DATA_GAP_UNRESOLVED` | 200 | **还有未处理缺口**（O2） | 弹补录清单 |
| `REVIEW_INCOMPLETE` | 200 | **还有未认可结果**（O3） | 跳转未认可列表 |
| `TASK_FROZEN` | 200 | ★ 任务已**归档/作废**，禁止写（D31：无「批准」状态） | 提示 |
| `TASK_STATUS_INVALID` | 200 | 状态不允许该操作 | 刷新页面 |
| `REVIEW_INCOMPLETE` → 已移至结果菜单 | — | ★ 归档前置校验（任务系统不再阻断） | — |
| `ALREADY_REVIEWED` | 200 | 已被他人处理 | 刷新 |
| `CONCURRENT_MODIFIED` | 200 | 并发修改冲突 | 刷新 |
| `QUEUE_NOT_FOUND` | 200 | 队列不存在 | 提示 |
| `ITEM_NOT_IN_TASK` | 200 | 任务项不属于该任务 | 提示 |
| `EXPORT_FAILED` | 200 | 导出失败 | 提示 |
| `UNAUTHORIZED` | 401 | 未登录 | 跳登录 |
| `FORBIDDEN` | 403 | 无权限 | 提示 |
| `NOT_FOUND` | 404 | 资源不存在 | 提示 |

> **业务失败一律 HTTP 200**（信封规范）。HTTP 401/403/404 只用于真正的传输层问题。

## 九、错误响应的统一处理

### 9.1 后端

```csharp
// 业务异常统一抛出，由全局过滤器转信封
throw new BizException("BIZ_LOCKED", "该企业在该阶段存在进行中的任务【TSK-20260929-0001】，请先完成后再操作");
```

HTTP 恒为 200，`success=false`，`code` 为本文件 §1 的错误码之一。

### 9.2 前端

```ts
// ★★ 信封三不变量（§0.3）：判据只读 success，失败文案只读 err
const res = await expertTaskApi.submit(taskCode)
if (res.success) {
  ElMessage.success(res.message)          // ✓ 成功提示走 message
  return
}

// ✓ 失败文案走 err（不是 message，失败时它恒为 ""）
ElMessage.warning(res.err)

// ✓ 业务分支走 data.ErrorCode（不是 res.code，那是 int 且禁止读）
switch (res.data?.ErrorCode) {
  case 'DATA_GAP_UNRESOLVED':
    router.push({ name: 'TaskGapFill', params: { code: taskCode } })
    break
  case 'BIZ_LOCKED':
    refreshLockState()
    break
  case 'REVIEW_INCOMPLETE':
    openPendingDrawer(res.data.PendingCodes)   // ★ PascalCase
    break
}
```

> ⛔ **四条禁止**（详见 §0.3）：
