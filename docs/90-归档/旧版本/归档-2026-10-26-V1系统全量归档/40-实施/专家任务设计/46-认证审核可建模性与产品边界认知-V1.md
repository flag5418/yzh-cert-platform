## 一、第一性认知：审核的元问题

> **成文规范（标准/法规/企业承诺） × 实体证据（记录/现场/事实） → 差距 → 规范文书 + 整改闭环**

企业文档两分法（ISO 13485 4.2.1 与 4.2.5 之别）：

| 类 | 本质 | 审核角色 |
|---|---|---|
| 规范性文档（手册/程序/制度） | **应然**——它承诺了什么 | 对照基准 |
| 事实文档（记录/报告/验收单） | **实然**——它实际做了什么 | 比对对象 |

**审核 = 拿实然对照应然找差距。** 这是引擎的数据模型地基：一边规则基线、一边证据包、中间差距。一切功能（NC、报告、资料、证据链）都是这一公式的展开。

## 二、监管传导链：国家出考纲，不发题库

一次认证的四方角色：

| 角色 | 比喻 | 手里有什么 |
|---|---|---|
| 国家（认监委/NMPA） | 出考纲 + 巡考 | 法律、认证规则、标准、处罚权 |
| 认证机构（含 ACM/外资） | 出题 + 监考的老师 | 自有规则、模板、检查表、判定口径 |
| 企业 | 考生 | 按自己的格式备考 |
| 监管抽查 | 教委巡考 | 查监考越界、阅卷公正、档案完整 |

五层传导链：

```
① 法规层（认证认可条例）——顶层规矩
② 规则层（QMS规则/6项体系规则/13485按GMP）——硬约束：阶段·间隔·人日·范围·人员·结论·NC整改
③ 标准层（ISO 13485/YY/T 0287 + 法规）——应然基准，公开
④ 机构层（规则/模板/专业判断）——"怎么查"机构自定
⑤ 企业层——按自己的格式准备
```

**关键判断：国家从不发布检查题库和统一报告格式，且是制度性刻意不发布**——若公布题库，全行业背题应付，正是监管要打的"两张皮"。国家只规定底线（范围级、区块级），方法放开。

**产品映射**：规则基线层 = ②③ 的公文化数字化（全国一副）；机构模板层 = ④ 的自定义（ACM 风格=第一套配置）；企业层 = ⑤ 只读映射。**产品本质 = 这条三级传导链的 articulation 层（咬合件），不是又一个工具。**

## 三、可建模边界：三带模型（回答"审核能否建模"）

| 带 | 内容 | 建模策略 |
|---|---|---|
| **完全可建模**（引擎主战场） | 合规基线覆盖 / 标准映射 / 缺口检测 / 报告结构 / 人日间隔等计算 / 证据四要素 / 常见 NC 模式（案例库积累） | 规则引擎 + 知识库 |
| **半可建模**（受限 AI 专属） | 记录异常（重复/雷同/时间线矛盾）/ 证据链完整性推断 / 提问引导清单 / NC 候选草稿 | 规则约束 + LLM 语义判断 + 人工确认 |
| **无规律（⛔ 永不建模）** | NC 最终定性与分级 / 访谈对峙 / 系统性嗅觉 / 特殊情形 / 造假终审 | 人的手艺，碰了就是用泥捏飞机 |

**产品总纲：软件保底线，专家争上限。** 软件把 60 分的人拉到 80 分（不漏必备项），95→99 分是人。行业过去没工具，是因为所有厂商建模"流程管理"（错层），没人建模"覆盖与映射"（对层）。

"怕没有规律可循"的解答：审核 90% 的规律集中在覆盖面与映射层；"全是人为"的部分集中在最终判断层——那本来就不是建模对象，是专家本人，也是他们敢用工具的底线。

## 四、NC 项与报告的本质：标准驱动、机构调味

- **引哪一条开 NC，由标准决定，不由机构决定。** 13485 的 7.5.1 就是 7.5.1，国内机构、ACM、外资系一个引法。
- 机构差异只在调味料：术语（Major/Minor vs 严重/一般）、分级阈值、报告结构、检查表组织风格（ACM 过程导向+风险思维，老机构条款流水账）。

**结论：规则库建一次、全机构通用；换机构 = 加一套模板配置，⛔ 不需要找该机构专家重建规则。** 需找新机构专家做的，只是复核"调味口径"。机构间互通形成的行业默契 ⇒ 通用基线已成熟 ⇒ 规则正确是入场券，不是护城河。

## 五、审核员水平差异的来源（回答"同一检查项为何不同结果"）

| 变量 | 厉害专家 | 新手 | 软件可补 |
|---|---|---|---|
| 覆盖度 | 知道哪些过程必须组合查、记录必须成链 | 漏项、按表走账 | ✅ 检查单预制+覆盖提醒，直接拉平 |
| 挖掘深度 | 从 1 条异常追出系统性问题 | 查到单条就停 | ⚠️ AI 提示记录链，追问靠人 |
| 提问/观察技巧 | 三问问出矛盾，现场看出记录外的东西 | 访谈像聊天 | ❌ 人的手艺；提供问题库+追问模板 |

**统一检查项下结果不同，因为覆盖度、抽样深度（3 批 vs 30 批记录）、追问深度不同。** 软件价值不是统一结果，是拉平覆盖度 + 留下每个人的抽样痕迹。产品定义因此更锐利：**软件不把新手变高手，软件让新手不漏 essentials。**

## 六、法律责任边界：工具中立 + 建议者身份

**底层判据（唯一的一条线）：你是"建议者"还是"判断者"。**

| 身份 | 法律后果 | 现实锚 |
|---|---|---|
| 纯工具（存储/格式/检索） | 零责任 | Word 从不替伪造合同担责 |
| 建议者（草稿/候选/提示） | 责任在采信者 | 导航指错路免责——你可以不信 |
| 判断者（合规/不合格/结论） | 共担风险 | 自动驾驶替你决策，声明也挡不住赔 |

**三件真护盾（其余皆是无用功）：**

1. 输出永远停在"候选/建议"档——禁输出结论句式（"以下证据与 XX 条款存在差距，请审核员判断"）；
2. 修改必须可能——允许一键全部推翻重写；
3. 留痕——唯一法律作用是证明"最终文件产生于人的决策"（防客户把责任推回软件）。

**无用功黑名单（砍掉）**：过长免责条款、每步弹窗、AI 痕迹"原样采纳"分级、任何试图阻止"不改直接提交"的设计（防不住也不该你防）。

**决策规则一句话：对每个 AI 输出问"用户完全信它、错了，我该不该赔"——该赔，降格为建议；不该赔，删掉护盾别加戏。**

**话术红线（终身）**：⛔ "保证通过/包过"（25 号文打击对象+认证决定权在机构）；⛔ "一键补齐记录/迎检神器"（诱导造假证据）；✅ 统一口径 = "AI 干粗活，人做判断。"

## 七、双端/三端服务的合规结论

**软件公司（非认证机构、非咨询机构）同时服务企业、机构、专家，合法，无准入障碍。** 17021-1、9 号文、条例的约束对象是认证机构，不穿透工具供应商。四条红线：

1. **股权穿透**：⛔ 与认证机构形成股权/控制关系（否则变相"既咨询又认证"）；
2. **数据不跨端**：企业资料不进专家端库、专家端记录不进企业端库；企业**主动导出**给审核员是正常业务流程（内审记录本就是审核对象）；
3. **不撮合配对**：⛔ 审核员-企业配对推荐（执业回避雷区+居间责任）；
4. **不替判定**：认证决定永远人工。

**企业端全功能合法的依据**：内审是 ISO 13485 8.2.4 法定义务、模拟审核是标准鼓励实践；25 号文打击"包过"（审核放水）而非"企业自查自纠"。唯一功能边界是**产物命名**：企业端只叫"内审/自查问题项"，⛔ 禁叫"认证 NC/认证报告"（认证报告是机构法定输出物）。

**法律终审确认**：监管从不审计企业资料的作者身份（谁代写/辅导均合法无备案），穿透的是真实运行（最高管理者熟悉方针目标、运行 ≥3 个月、现场证据、记录真实性）。产品核心机制——**起草→评审→批准→发布四段留痕**，工具只参与起草，后三段必须是企业真实角色。这是客户被倒查时的标准答案："文件借助工具起草，评审批准实施的是企业自己。"

## 八、架构三层新模型（替代"统一标准格式"设计）

```
① 规则基线层    标准条款 × 法规 × 过程        ← 全国通用，唯一知识资产，唯一要维护的
        ↓ 映射
② 机构模板层    报告骨架 / NC 术语 / 检查表风格  ← 配置数据，ACM=第一套
        ↓ 适配
③ 企业模板层    企业自己的目录/编号/审批链       ← 纯输入，⛔ 永不"改造"
```

**企业资料规范化的新流程**：读企业自己的模板 → 建"企业文档 ↔ 条款/法规"映射 → 缺口检测（缺记录/缺批准链/缺覆盖）→ 缺的部分**按企业自己的风格**生成草稿。"规范化" = 把企业的格式翻译成机构/监管能验收的语言，不是统一格式。

**维护成本反转**：高维护来自旧设计（固定格式 = N机构×M标准×K企业格式组合爆炸）；新模式下每家企业只是数据，维护收敛为"1 个规则库 + 一堆配置"。

**IP 边界**：✅ 可用标准/法规原文/行业通行惯例；⚠️ 专家素材须为其自有经验整理；⛔ 不照搬机构内部受控文件、不声称对齐某机构内部规范（除非书面授权）、不提机构真名与 logo。**不提机构名 = 法律边界（商业秘密/不正当竞争）+ 保护朋友职业前途 + 产品品牌不被锁死的三位一体决策。**

## 十、产品方法论：知识库全、功能尖

- **知识库全**：所有条款进引擎（覆盖判定需要）；**功能尖**：只做 1-2 个共识痛点。不矛盾——全库是弹药库，柜台只亮一把刀。
- **共识痛点四条件**：高频（每次必碰）× 高重复（每次从零做）× 公认烦（专家点头）× 可演示（30秒看懂）。
- 13485 候选池（请专家排序）：报告草稿生成 / 进厂前资料研读与缺口清单 / NC 条款引用与定级辅助 / 企业迎审资料包。
- **30 秒定律**：真专家打开 30 秒内辨真伪。demo 铁律 = 打开 → 一个真实案例 → 一个结果 → 结束。超过两步、需要配置、需要教学的 demo 都死在 30 秒。
- **引擎通用、产品垂直**：元问题跨行业通用（药企GMP/17025/PIPL/ESG 是候选第二战场），但 12 个月内不启动第二行业；唯一启动信号 = 13485 客户主动问"能不能做 XX"。
