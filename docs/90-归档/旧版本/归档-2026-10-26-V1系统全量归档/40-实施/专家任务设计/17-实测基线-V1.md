## 二、★ 五条推翻原设计的基线错误

### E-1 ★★★ `cert_validation_rule.IsValid` 全为 `NULL`

```sql
SELECT Code, RuleCode, IsActive, IsValid FROM cert_validation_rule;
```

| Code | RuleCode | IsActive | IsValid |
|---|---|---|---|
| `88606ca948a1...` | `NC-846dec4b-...-001` 复审规则01 | 1 | **NULL** |
| `5adf2b308deb...` | `NC-846dec4b-...-002` 复审规则02 | 1 | **NULL** |

**危害**：`SqlSugarDbOrm` 的 `IsValidCondition<T>()` 自动追加 `WHERE IsValid=1`（`Implementations/SqlSugarDbOrm.cs:82,164,183`）→ **这两条规则永远查不出来**。

> ⛔ 原设计 06 号 §4.2 写「`ADD COLUMN IsValid`」是错的 —— **列已存在**，会 `ERROR 1060`。

**修复 SQL**：
```sql
UPDATE cert_validation_rule SET IsValid = 1 WHERE IsValid IS NULL;
-- 验收：SELECT COUNT(*) FROM cert_validation_rule WHERE IsValid IS NULL; → 0
```

### E-2 ★★★ 提取结果的阶段列名是 `StageCode`，不是 `PhaseCode`

```sql
SHOW COLUMNS FROM cert_extraction_result;
-- Code / OrgCode / FileCode / StandardCode / StandardFileCode / ★StageCode / ...
```

⛔ **无 `PhaseCode` 列**。原设计 05 号 §2.2 / 06 号 §4.3 / 07 号多处写 `PhaseCode` → 全部会 `ERROR 1054 Unknown column`。

**正确口径**：
```sql
SELECT * FROM cert_extraction_result
WHERE OrgCode      = @enterpriseCode   -- ★ 存的是企业 Code
  AND StandardCode = @standardCode
  AND StageCode    = @stageCode       -- ★ 是 StageCode
  AND IsValid = 1 AND IsDeleted = 0;
```

**填充率实测**（好消息）：14 行中 `StageCode` 与 `StandardCode` **全部有值**，无需回填。

### E-3 ★★★ 阶段码迁移 SQL 是静默 no-op

```sql
SELECT DISTINCT PhaseCode FROM cert_validation_rule;  -- → '03'（2 行）

SELECT Code, StageCode, StageName FROM cert_cert_stage;
```

| Code（GUID） | StageCode（业务码） | StageName |
|---|---|---|
| `c42582d5f95f...` | `jd01` | 初审 |
| `fa7931c884d0...` | `jd02` | 预审 |
| `29c1bcc3a189...` | **`03`** | **复审** |

**真相**：`cert_validation_rule.PhaseCode='03'` 存的是**业务码**，对应 `cert_cert_stage.StageCode='03'` / `Code='29c1bcc3...'` / `StageName='复审'`。

```sql
SET vr.PhaseCode = cs.Code, vr.UpdateBy='fix_stage_20260929', vr.UpdateTime=NOW()
```

#### 4.3 ★★★ D7 是架构级问题（★ 原判断的真正焦点）

```

  「下游读取口径（NC/报告唯一入口）：GetActiveAsync」

实际：

  ② 工作流引擎的 docField 节点 —— 根本没接入，自己查库 ❌

     → 完备性检查说"缺数据"（走 GetActiveAsync，严格）
```

> ⛔ **不该**在 `NodeExecutor` 里再补一遍 WHERE 条件 —— 那是又造第二套。

**归属**（★ 用户裁决「前后端共用一套表结构」）：
