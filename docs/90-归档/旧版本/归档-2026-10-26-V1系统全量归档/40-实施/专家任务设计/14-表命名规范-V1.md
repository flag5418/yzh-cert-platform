# 14 表命名规范（权威源）

> ⚠️ **V1 遗留说明**：本文部分位置仍用 `cert_expert_task_item` 指代任务项。
> ★ 12 号已拆为 4 张（实体 + 结果 × NC + 报告），阅读时请按下表替换：
> | 上下文 | 实际表 |
> |---|---|
> | NC 检查项 / NC 结论 | `cert_expert_nc_item`（实体）/ `cert_expert_nc_result`（结果轮次） |
> | 报告章节 / 章节正文 | `cert_expert_report_section_item` / `cert_expert_report_result` |
> | 任务包含哪些项 | ⛔ 不再有独立表，通过结果表 `TaskCode` 反查 |
> | 认可/修改日志 | `cert_expert_task_log`（`TaskItemCode` → 结果行 `Code`） |


> 目的：**表名一旦定错，后期改名成本 = 全量数据迁移 + 全部代码 + 全部文档**。本篇是唯一的表名裁决源。
> 状态：已定稿（2026-09-29 用户裁决）

## 一、总原则

| # | 原则 | 说明 |
|---|---|---|
| **N1** | ⛔ **体系认证业务表一律 `cert_` 开头** | 违反即返工。`audit_`/`rpt_`/`ent_` 一律不得用于体系认证业务表 |
| **N2** | 框架自有域保持原前缀 | `wf_`（工作流引擎）· `sys_`（系统管理）· `yzh_`（YZH 框架）—— **本期不动** |
| **N3** | 专家系统专用表用 `cert_expert_` 前缀 | 归属明确，一条 `LIKE 'cert_expert_%'` 就能捞出全部专家系统表 |
| **N4** | 后台管理配置层**不加** `expert_` 前缀 | 与现有 `cert_validation_rule` 保持对称 |
| **N5** | 配置层与执行层同名时，执行层加 `_item` 后缀 | 如 `cert_report_section` vs `cert_expert_report_section_item` |
| **N6** | 列名 PascalCase · 业务键用 `Code` · 启用标志用 `IsValid` | AGENTS.md 铁律七 / 准则 A / 铁律九 |
| **N7** | 字符集 `utf8mb4` + `utf8mb4_general_ci`，**必须显式 COLLATE** | AGENTS.md 铁律八 |
| **N8** | `OrgCode` 是**三域同名不同义**列（认证机构 / 专家工作区 / 企业） | 见 §六 N8。★ 2026-09-29 裁决「方案乙」：保留列名，不改 `EnterpriseCode` |

> **N1 的历史例外**（本期不处理，另开任务）：`wf_*`（12 张）· `sys_*`（5 张）· `yzh_*`（5 张）—— 这三个是框架/系统层，不属体系认证业务。

## 五、配置层 vs 执行层（同名区分）

```
【配置层】后台管理维护 · 专家端只读 · 不加 expert 前缀
  cert_validation_rule        NC 检查规则（★已有，2 条）
  cert_report_section         报告章节定义（★由 cert_report_section 改名）

【执行层】专家系统产生 · 全部 cert_expert_ 前缀
  cert_expert_nc_item              ← 与 cert_validation_rule 配对
  cert_expert_nc_result
  cert_expert_report_section_item  ← 与 cert_report_section 配对（★_item 区分，N5）
  cert_expert_report_result
```

**三层的完整视图**（以报告为例）：

```
配置层  cert_report_section                    实体层  cert_expert_report_section_item        结果层  cert_expert_report_result
         (OrgCode=认证机构,                          (EnterpriseCode, StageCode,
          StandardCode, PhaseCode)                   StandardCode, SectionCode)
         SectionName  ← 空白模板                     SectionName（快照）
         SectionContent ← 示例正文                  SectionTemplateContent（快照）
         WorkflowCode ← 生成规则
                                                 RoundNo=1 ← AutoContent
                                                 RoundNo=2 ← ModifiedContent
                                                 RoundNo=3 ← CurrentContent
                                                          ReviewStatus / ReviewBy / ReviewTime
```

## 六、命名对照速查（写代码时对照）

| 场景 | ✅ 正确 | ⛔ 错误 |
|---|---|---|
| 任务头 | `cert_expert_task` | ~~`tsk_task`~~ / `task` |
| **域①** 配置层租户列 | `cert_validation_rule.OrgCode` = **认证机构 Code** | = 工作区 / 企业 Code |
| **域②** 专家端租户列 | `cert_expert_task.OrgCode` = **工作区 Code** | = 认证机构 / 企业 Code |
| **域③** 提取结果租户列 | `cert_extraction_result.OrgCode` = ★**企业 Code 或 `YZH-STD-ENT`** | 任何其他 |
| 不符合项 | `cert_nc` | ~~`audit_nonconformity`~~ / `nc_table` |
| 报告章节（配置） | `cert_report_section` | ~~`rpt_report_section`~~ |
| 报告章节（实体） | `cert_expert_report_section_item` | `cert_report_section`（会与配置层混） |
| 启用标志 | `IsValid` | `Enable` / `enable` / `IsActive` |
| 业务键 | `Code` | `Id`（⛔ 绝不进 WHERE） |
| 虚拟企业标记 | `YzhVirtualEnterprise.Code` | ⛔ 字符串 `"YZH-STD-ENT"` 字面量 |

### ★ N8 `OrgCode` 三域语义（N1 的必要补充）

> **2026-09-29 用户裁决：选方案乙**（保留 `OrgCode` 列名，视作「机构/归属代码」）。
> 完整规范见 [02 号 §9.1](02-详细设计-任务与队列-V1.md)。

| 域 | 表 | 存什么 | 来源 |
|---|---|---|---|
| ① 认证机构域 | `cert_validation_rule` · `cert_report_section` · `cert_doc_extraction_rule` | 认证机构 Code | `cert_certification_body.Code` |
| ② 专家工作区域 | `cert_expert_*` 全系列 | 专家工作区 Code | `WorkspaceContextService.Resolve().OrgCode` |
| ③ 企业域 | `cert_extraction_result` · `cert_table_extraction_result` · `cert_extraction_change_log` | 企业 Code **或** `YZH-STD-ENT` | `cert_enterprise.Code` / `YzhVirtualEnterprise.Code` |

**实测证据**（域③ 实际值）：

| `OrgCode` 值 | 行数 | 语义 |
|---|---|---|
| `42833c3d3fe241b1bcfa707f6b92e4c3` | 15 | 某企业 |
| `TEST-ENT-0001` | 7 | 测试企业 |
| ★ `YZH-STD-ENT` | 1 | 模板/样例数据 |

**⚠️ 方案乙的已知代价（必须登记，不得遗忘）**：

| # | 代价 | 对策 |
|---|---|---|
| 1 | ⛔ 铁律七表面违规：`ExtractionResult.OrgCode`（DB）≠ `EnterpriseCode`（C# 属性） | 已在实体用 `[SugarColumn(ColumnName = "OrgCode")]` 显式映射；**新增实体照此办理** |
| 2 | ⛔ `YZH-STD-ENT` 硬编码 | ⛔ 一律 `YzhVirtualEnterprise.Code`（`YzhVirtualEnterprise.cs:8` 已明令禁止字面量） |
| 3 | ★ 模板数据与企业数据**读法不同** | 企业资料管理 S2.5 收口 `docField` 时**必须显式分叉**（02 号 §9.1 末） |

> 📌 **`YZH-STD-ENT` 的定位仍待裁决**（模板行标记 vs 虚拟机构）—— 见 [02 号 §9.2](02-详细设计-任务与队列-V1.md)。
