### H1（P0）`食品标准 × 复审` 无目录模板 ⇒ 需求 3「多标准分发」无法现场验收

- **现象**：点 `复审` 弹出/常驻提示「食品标准（iso4001-2016）：该机构未配置标准目录，请先在管理端「标准目录管理」维护」。
- **证据**：
  - live：`POST /api/Auditor/EnterpriseFile/stage-overview`（企业 `42833c3d…` × 阶段 `29c1bcc3…`）返回
    `食品标准 Configured=false + 上述 Message + Required=0`，而 `9001标准 Configured=true / Required=167 / Live=6 / Missing=161`；
  - DB：`cert_standard_directory_config` 的**全部模板行**（`EnterpriseCode='YZH-STD-ENT'`）`StandardCode` **只有** `846dec4b…`（9001标准），**没有任何** `475da4fe…`（食品标准）模板行；
  - 关联：`cert_enterprise_stage` 中 `G4测试企业甲(42833c3d) × 复审(29c1bcc3)` 关联了 `9001标准` **和** `食品标准` 两行（`IsValid=1`）。
- **影响**：这是 `README §8.3 N4` 早就记录的缺口 —— **一个文件夹里含两个标准文件、各存一份** 的核心场景没有真实数据可验；同时该标准行会长期以「不可用」形态出现。
- **建议修法（择一）**：
  - **A（根治）**：管理端「标准目录管理」为 `机构 906e8b2a… × 食品标准 × 复审` 建模板并 seed 文件定义（可复制 9001 那套 11 文件夹 / 167 行结构），再跑一次多标准 E2E；
  - **B（止血）**：把 `cert_enterprise_stage` 该行 `IsValid=0` 解绑，提示消失但多标准仍不可验。
- **归属**：数据种子（N4），非代码缺陷。

### H2（P1）「有模板行但模板内容为空」与「没有模板行」两种缺失语义混淆 → **文案侧已修（E21/E22/E23），语义区分仍待做**

> **已改**：三种状态的文案现在都能自解释，且**不再谎称需要「重新关联」**。
> ① 关联页：`template_missing`（无模板）**静默**，因为关联是成功的；`org_unbound` 提示去「企业管理」补机构；其余才报错。
> ② 资料页常驻条：`食品标准（iso4001-2016）：管理端未配置该标准的目录模板` +「关联本身是好的、不必重建 —— 模板补齐后刷新本页即自动生成」。
> ③ 资料页空态（初审那种 0 槽位）：「管理端还没有为该标准配目录文件定义（关联有效；补齐模板后刷新本页即自动生成槽位）」。
> **仍待做**：`template_missing` 与「模板存在但 0 文件定义」在**数据上**仍返回同一个 `Configured=true/文件夹空` 形态，需要后端区分两个态才能真正区分。

- **现象**：点 `初审` 不报错，只显示空态；用户原本无法区分「管理端压根没配」和「配了但没内容」。
- **证据**：模板行 `f45744e3…`（机构 `906e8b2a…` × 9001标准 × 初审）**存在**，但 `cert_standard_directory_folder` / `cert_standard_directory_file` 中该 `ConfigCode` **0 行**（有内容的模板只有 `3881ecae…`：11 文件夹 / 167 文件）。
- **影响**：① 页面无法自解释（文案侧已修）；② 更隐蔽的是 —— ensure 会据此**创建一个 0 槽位的企业目录**（`3dffeb2c…` 就是这样来的），该目录此后被视为"已完成初始化"，管理端补模板后**不会自动回填槽位**（对账只在 ensure 时按 `StandardFileCode` 差集跑一次，需再触发一次 ensure 才补）。
- **建议修法**：① 页面区分两种空态文案（文案侧已做）；② **明确「模板补内容后如何回填已有企业目录」的重对账入口**（管理端动作或企业侧按钮）—— 这条仍未做，是本条剩下的实质缺口。
- **归属**：后端对账触发策略。

### H3（P1）企业目录行的 `OrgCode` 与 `cert_enterprise.OrgCode` 不一致（历史脏数据）

- **现象**：企业目录能正常打开，但库里机构口径是两套。
- **证据**：`G4测试企业甲` 的 `cert_enterprise.OrgCode = 66bbf572…`（`Sys_Organization`「尚龙认证 · 王卿权」，`OrgCode=CB001`，`OrgType=VirtualOrg`）；而它的企业目录行 `667005414afe…`（复审）、`3dffeb2c…`（初审）`OrgCode = 906e8b2a…`。当前**靠 `NormalizeOrgCodeAsync` 兜住**：`66bbf572 → Sys_Organization.OrgCode('CB001') → cert_certification_body.CbCode='CB001' → Code=906e8b2a…`（河北雄安尚龙认证有限公司）。
- **影响**：`cert_standard_directory_config` 的唯一键是 `uk_enterprise_std_stage (OrgCode, EnterpriseCode, StandardCode, StageCode)` —— **含 OrgCode**。一旦归一结果变化（认证机构 `CbCode` 改动、企业改挂机构、工作区切换），ensure 会认为"没有企业目录"并**新建一个空目录**，而带 167 行槽位 + 归档版本 + 存储对象的旧目录成为孤儿（页面看不到、文件还在桶里）。
- **建议修法**：① 一次性数据修复：把企业目录行的 `OrgCode` 校正为其企业当前归一机构；② 归一算法加"旧机构行迁移"分支（查到异机构同企业同标准同阶段行时改 `OrgCode` 而非新建）；③ 审计脚本定期比对 `cert_enterprise.OrgCode` 归一结果与目录行 `OrgCode`。
- **归属**：数据修复 + 服务层健壮性。

### H4（P2）不可配置标准清单只在加载时算一次

- **现象**：管理端补完模板/关联后，页面不会自动感知；需要手动点「刷新」或切阶段。
- **证据**：`logic.unconfiguredStandards` 只在 `loadOverview → loadDirectories` 内赋值；`reloadStandard`（单标准局部刷新）与 5s 轮询**都不更新**它。
- **影响**：修好数据后提示条仍可能挂着，形成"提示与事实不一致"。
- **建议修法**：`refreshOverviewCounts` 顺带重算不可配置清单，或把清单收敛到 `overview.Standards` 的派生计算（单一数据源）。

### H5（P2）转换轮询是「每个标准一次串行请求」

- **现象**：转换进行中每 5s 逐个标准请求 `standard-directory`。
- **证据**：`startPolling()` 内 `for (const s of stds) await standardDirectory(...)`；标准数 = N 时单轮 N 次串行往返（当前 N=2 无感，多标准会是问题）。
- **影响**：多标准/企业资料多时页面卡顿、后端压力线性上升。
- **建议修法**：后端补一个「阶段下全标准槽位摘要」批量端点，轮询只拉增量。

### H6（P2）未归属文件没有人工指派出口（= N2）

- **现象**：`所有标准上传` 里未命中的文件只能"被忽略"，用户没有"我就要把它放进某标准某文件夹"的出口。
- **证据**：`upload/plan` 的 `Unmatched` 只读展示；后端 `upload/init` 的指派模式（只传 `FolderCode` 不传 `SlotCode`）**已可用**，前端未接。
- **影响**：需求 3 的另一半缺失，专家被迫手工改文件名再重传。
- **建议修法**：未归属区加「指派到 → 标准 + 文件夹」行内操作，复用四段式上传。
