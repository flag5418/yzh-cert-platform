# 05 — 接口与代码结构 V1

> **三层同构**：Controller 文件 ↔ 前端 API 文件 ↔ 前端 Pages 文件夹 **同名同路径**（`docs/30-项目规则/前后端代码结构统一规则-V1.md`）。
> **契约**：响应统一 `ApiResponse` 信封（`success` 为唯一判据；业务失败 HTTP 200）；字段 **PascalCase 逐字一致**（例外 E1–E7 除外）。

## 三、复用边界：四段式上传与企业库

| 方案 | 做法 | 评价 |
|---|---|---|
| **A（推荐）泛化 Admin 四段端点** | `StandardDirectoryController` 的 `upload-init/upload-file-v2/upload-confirm/upload-cancel` 增加 `library` 参数（缺省 `standard-directory`），`library=enterprise-documents` 时用 `PathBuilder.EnterpriseFile` 生成路径；企业端直接调用或薄封装转发 | 单一实现、单一 bug 面；`DocumentLibrary`/`PathBuilder` **已为此预留**；缺点是 Admin 控制器多两个分支 |
| B 企业侧自建 4 段 | 在 `EnterpriseFileService` 内复制 Step1–4 | 双份维护；历史已证明"两处规则漂移"是主要 bug 源（如 `NeedsConversion` 判据曾两处不一致） |
| C 抽 Shared 服务 | 新增 `CertPlatform.Shared/Storage/DocumentUploadService`，两端共同调用 | 最干净，但改动面最大（Admin 侧需同步改造） |

> **建议 A（P2 落地）**：`library` 参数 + `PathBuilder` 分派；若审批选 C，则 P0 增加一天。

**前端调用规范**

- 统一 `yzhApi`（`@yzh-core/api/client`）；FormData 场景（Step2/替换）可用裸 `fetch` + `Authorization: Bearer {token}`，但**必须** `if (!res.ok || !json?.success) throw new Error(json?.err || json?.message)`（禁止丢弃失败）。
- 读值一律 `row.Code`、`row.FileName`、`node.FolderName` 等 **PascalCase**；⛔ 禁止 `row.ruleName` 式 camelCase（会渲染空白且零报错）。
- `.vue` 内禁止直接 `fetch(`（守卫规则）；`axios`/`view-grid`/`VolBox`/`VolForm`/`VolProvider` 一律禁止。

## 七、权限（`[RequirePermission]` + ApiSync）

| 步骤 | 说明 |
|---|---|
| 1 | 控制器每个端点标注 `[RequirePermission("<ApiCode>")]`；`ApiCode` = `ApiScanner.GenerateApiCode` 的 SHA256 原像 `"{METHOD}|EnterpriseFile|{action小写}"` |
| 2 | 启动时 ApiSync 自动登记 `sys_api`（⚠️ `sys_api` 需迁移 `Enable → IsValid`，见 `AGENTS.md` 铁律九待办） |
| 3 | 「角色-接口」页勾选授权（专家角色 `ROLE_AUDIT_CLIENT_ADMIN`） |
| 4 | 改动作名/控制器名 ⇒ 旧 ApiCode 失效 ⇒ **必须重跑 ApiSync 并重关联**（否则静默 403） |
| 5 | 验收：未授权账号访问返回 401/403（出口门 G4） |
