## 二、左树规格

| 项 | 规格 |
|---|---|
| 数据源 | `POST /api/Auditor/Enterprise/filter`（企业，工作区隔离）+ `POST /api/Auditor/EnterpriseStage/check/all`（企业×阶段×标准关联） |
| 层级 | 一级 = 企业（`Code`/`Name`）；二级 = 阶段（`StageCode` 业务码 / `StageName`），**不出现第三级** |
| 节点键 | `node-key="Code"`；企业用 `cert_enterprise.Code`，阶段用**合成键** `STD:{stageCode}`（避免与其它节点 Code 冲突） |
| 默认展开 | 企业层全展开（与 `directory-manager` 的"默认展开机构层"一致） |
| 选中 | `highlight-current`；点击阶段 = `selectStage()`；点击企业 = 只切换企业（清空阶段选中与右区） |
| 图标 | 企业 `OfficeBuilding`（#e6a23c）；阶段 `Calendar`（#67c23a）—— 沿用 `CertBizTree` 的图标色规范 |
| 空态 | 无企业：`el-empty description="暂无企业数据"`；有企业无阶段：`description="该企业尚未关联认证阶段，请先在「阶段标准关联」页配置"` |
| 禁用态 | 若某阶段下**0 个标准**：节点置灰（`el-tag type="info"`「未关联标准」），点击提示不进入 |
| 搜索 | 顶部输入框过滤企业/阶段名（沿用 `CertBizTree` 的 `filter-node-method`） |

## 三、右区规格

### 3.1 全局汇总条

| 字段 | 来源 | 说明 |
|---|---|---|
| 标准 N 个 | 该阶段的关联标准数 | — |
| 应上传 | Σ 各标准模板文件定义数（`IsRequired=1`） | 模板行数量 |
| 已就位 | Σ 企业文件行中 `StoragePath` 非空且 `ConvertStatus='completed'` | 见 04 §状态机 |
| 转换中 | Σ `ConvertStatus in ('pending','converting')` | — |
| 缺失 | 应上传 − 已就位 − 转换中 | 红字 |
| 未归属 | 本次分发未匹配的文件数（会话内计数） | — |

### 3.2 标准卡片（每个标准一张，不用 Tab）

> **为何不用 Tab**：需求要求"顶部对所有标准上传 + 每标准独立上传"并存；Tab 会隐藏其他标准的缺口，无法一眼看全局进度。

| 区域 | 内容 |
|---|---|
| 卡头 | 标准名（`StandardName`）+ 标准编号（`StandardNo`，如 `iso9001-2015`）+ 右侧 `[上传文件夹]` `[上传文件]` |
| 卡头副行 | 进度：`已就位 3/5 · 转换中 1 · 缺失 2` + 细进度条（`el-progress :percentage`） |
| 卡体 | 模板文件夹树（含三级），**按模板结构渲染**；文件夹行可折叠，默认展开一级/二级、折叠三级 |
| 文件行（模板文件定义） | 未上传：灰字 + 文件名 + `[上传]`；已上传：文件名 + 大小 + 状态标签 + `[预览][下载][替换][版本][删除]` |
| 状态标签 | 见 §五 状态与文案 |
| 行操作可见性 | 操作列 **sticky 右侧**（照抄 `directory-manager` 修过的"操作列吸附"方案：`position: sticky; right: 0` + 表格 `min-width`） |

### 3.3 未归属区（D4）

仅当本次分发存在未匹配文件时出现；每行：文件名 + 匹配失败原因（无同名/无关键词/模板外）+ `[指派到标准 ▾]` `[指派文件夹 ▾]` `[忽略]`。
**约束**：未指派⇒**不入库、不上传**（禁止把非本标准文件塞进所有标准 —— 需求 3 硬约束）。

## 四、上传交互（三种入口）

### 4.1 入口 A：标准卡片内「上传文件夹」（单标准）

```
┌ 上传到：9001标准（iso9001-2015） ─────────────────────────────┐
│ [选择文件夹]  已选：2026体系材料/（18 个文件，3 级目录）        │
│ ──────────────────────────────────────────────────────────── │
│ 匹配结果：命中 12 / 未命中 6                                   │
│ ┌ 原始相对路径 ────────────┬ 目标文件夹 ─────┬ 目标标准文件 ──┐ │
│ │ 1质量手册/XASL-QM 质量手册.doc │ 1质量手册      │ XASL-QM 质量手册.doc │ │
│ │ 4记录文件/技术类/XASL-TR-001…doc│ 4记录文件/技术类│ XASL-TR-001…doc │ │
│ │ 其它/旧版清单.xls        │ —（未命中）     │ —              │ │
│ └──────────────────────────┴────────────────┴────────────────┘ │
│ 说明：仅命中的 12 个文件会入库上传；未命中默认不处理（可勾选"忽略"）│
│ [取消]                                   [确认上传（12 个文件）] │
└──────────────────────────────────────────────────────────────┘
```

### 4.2 入口 B：标准卡片内「上传文件」（单标准多选文件）

同上，但无目录结构：目标文件夹由用户在弹窗内选择（**下拉来自该标准模板的真实文件夹树**，含三级；⛔ 不再硬编码"1质量手册/2程序文件/3制度文件/4记录文件"）。
未选文件夹 ⇒ 落在该标准根（`FolderCode=''`）。

### 4.3 入口 C：顶部「所有标准上传」（多标准分发，需求 3 核心）

```
┌ 所有标准上传（多标准自动分发） ─────────────────────────────────────────────┐
│ [选择文件夹]  已选：2026体系材料/（18 个文件）                                │
│ 目标阶段：初审   涉及标准：9001标准 / 14001标准 / 45001标准（该阶段关联的全部）  │
│ ──────────────────────────────────────────────────────────────────────────│
│ ▾ 9001标准（命中 6）                                                       │
│   ┌ 上传文件 ─────────────┬ 目标文件夹 ──────┬ 目标标准文件 ──┬ 匹配 ┐      │
│   │ XASL-QM 质量手册.doc   │ 1质量手册        │ XASL-QM 质量手册.doc │ M1 │      │
│   │ XASL-TR-001 年度验证计划.doc│ 4记录文件/技术类│ XASL-TR-001 …      │ M1 │      │
│   └───────────────────────┴─────────────────┴───────────────┴─────┘      │
│ ▾ 14001标准（命中 4）  …（同构）                                            │
│ ▾ 45001标准（命中 3）  …（同构）                                            │
│ ⚠ 同一文件命中多标准：营业执照.pdf → 9001 + 14001（将各存一份，共 2 份）      │
│ ▾ 未归属（5）  [指派到标准 ▾] [指派文件夹 ▾] [忽略]                          │
│ ──────────────────────────────────────────────────────────────────────────│
│ 汇总：将上传 13 个文件到 3 个标准（含跨标准重复 1 个文件）                    │
│ [取消]                                                      [确认上传]      │
└────────────────────────────────────────────────────────────────────────────┘
```

| 规则 | 说明 |
|---|---|
| 逐标准独立判定 | 对每个标准，只保留命中**该标准**模板定义的文件；未命中不进入该标准（需求 3 硬约束） |
| 同文件多标准 | 产出多条（每标准一份，MinIO 各存一份）→ 满足"3 个标准都有则传 3 份" |
| 匹配层级 | M0 文件夹路径强匹配 / M1 文件名精确（归一）/ M2 文件名主词包含 / M3 文件夹一层+扩展名（标黄需确认）—— 详见 04 §六 |
| 冲突 | 同一标准内多文件命中同一目标 → 弹"选择保留哪一份 / 全部上传" |
| 模板外文件 | 默认不入任何标准；仅人工指派后落库（`TemplateFileCode` 留空，D8） |

## 五、状态与文案

### 5.1 文件就位状态（前后端统一取值）

| 状态 | 判定（后端） | 标签 | 颜色 | 图标 |
|---|---|---|---|---|
| `missing` 缺失 | `StoragePath` 为空 | 缺失 | `#909399` 灰 | 无 |
| `uploading` 上传中 | `UploadStatus='uploading'` 或 `'pending'` | 上传中 | `#409eff` 蓝（旋转） | `Loading` |
| `uploaded` 已上传 | `UploadStatus='uploaded'` 且 `ConvertStatus in (null,'')` | 已上传 | `#67c23a` 绿 | `CircleCheck` |
| `converting` 转换中 | `ConvertStatus='pending'/'converting'` 或 `MarkdownStatus='pending'/'converting'` | 转换中 | `#409eff` 蓝（旋转） | `Loading` |
| `ready` 已就绪 | `ConvertStatus='completed'` | 已就绪 | `#67c23a` 绿 | `CircleCheck` |
| `convertFailed` 转换失败 | `ConvertStatus='failed'` | 转换失败 | `#f56c6c` 红 | `CircleClose` |
| `mdFailed` 提取链失败 | `MarkdownStatus='failed'`（不阻塞就位） | 提取失败 | `#e6a23c` 橙 | `Warning` |

> **就位（ready）不以 Markdown 成功为条件** —— 上游只要求"资料就位可供 NC/报告消费"；提取链失败单独提示，不阻塞进度（D10 相关）。

### 5.2 关键文案（统一固定，禁止同义替换）

| 场景 | 文案 |
|---|---|
| 未选阶段 | 请先在左侧选择企业下的认证阶段 |
| 该阶段无标准 | 该阶段尚未关联标准，请先在「阶段标准关联」页配置 |
| 上传成功 | 已上传 N 个文件，正在转换… |
| 分发无命中 | 未匹配到该阶段任何标准的目录定义，请在「未归属」区人工指派 |
| 模板外文件 | 该文件不属于任何标准的目录定义，默认不上传 |
| 替换确认 | 替换后原文件将归档为历史版本（可在「版本」中下载） |
| 队列占用 | 该目录正在转换中，请稍后重试（队列：{QueueCode}） |
| 配置缺失 | 未找到「机构 × 标准 × 阶段」的标准目录模板，请联系管理员配置 |

## 七、与现状（`resources` 原型页）的差异对照

| 项 | 现状 | 目标（本分册） |
|---|---|---|
| 左区 | 企业平铺列表 + 阶段 `el-radio-group` | **企业→阶段两级树**（`el-tree`），阶段为上传前置条件 |

| 全局上传 | "批量上传"对话框，`[确认上传]` 直接关闭（**不执行任何上传**） | **分发预览表 + 真实分发提交** |

| 提取结果抽屉 | 有（消费假数据） | **移除**（D10：本模块不做提取） |
| 缺失/就位检查 | `FileCheck` 接口（因 B1 恒返回空） | 修正后作为「就位检查」面板 |
