## 一 模型定稿（10-13 用户澄清版）

### 1.1 唯一分类判据

> 用户原话：「**只要 `EnterpriseCode` 有值，就是企业端的数据**」。

```
EnterpriseCode 非空  ⇒  企业行
EnterpriseCode 为空  ⇒  非企业行（机构行 or 平台标准级）
```

### 1.2 三态 + 机构冗余（★ 用户澄清修正了「两列互斥」）

> 用户原话：「很多时候，企业的信息里面存储了真实机构 code，其实**并不能算错误**，因为我们需要通过机构 code 快速获取后台的规则或标准，**算是一种冗余**」。

| `OrgCode` | `EnterpriseCode` | 含义 | 实例 |
|---|---|---|---|
| **机构 code** | 空 | **机构行** | `cert_doc_extraction_rule`（规则属机构） |
| 空 | 企业 code | **企业行**（无机构冗余） | 企业目录（若未带机构） |
| **机构 code** | 企业 code | **企业行 + 机构冗余** ← ⛔ **合法** | `cert_fill_param_value`（已存在） |
| **空** | **空** | **平台标准级** | `cert_iso_clause` 141 行 |

⇒ ⛔ **不是「两列互斥」**，而是「**`EnterpriseCode` 是分类判据，`OrgCode` 是规则来源**」。
⇒ ⛔ **不存在**「`OrgCode` = 机构 且 该行不是企业行 且 平台级」的第四种组合。

### 1.3 ★★ 现成样板：`cert_fill_param_value`

实测该表**已经**是目标形态 —— 这是「模型可行」的最强证据：

```
cert_fill_param_value.OrgCode        varchar(50)  ★机构编码（租户隔离键，⛔禁NULL）
cert_fill_param_value.EnterpriseCode varchar(36)  ★企业Code（cert_enterprise.Code，⛔禁NULL）
```

两列**同时有值**，且 `OrgCode` = 机构 ⇒ **本模型在库里有先例，不是新发明**。

### 1.4 三态 vs 旧模型

| 维度 | 旧（`yzh-std-env` 两值模型） | 新（三态） |
|---|---|---|
| 平台标准级 | `OrgCode = 'yzh-std-env'`（magic value） | 两列都空 |
| 机构行 | `OrgCode = 'yzh-std-env'` + `OwnerOrgCode = 机构`（**本批刚加**） | `OrgCode = 机构`（**少一列**） |
| 企业行 | `EnterpriseCode = 企业` | 同 |
| 机构冗余 | 无此概念 | 企业行可带 `OrgCode` = 机构 |

## 三 `OrgScope` 改造（判据唯一入口）

**现状**（`Shared/Domain/Scope/OrgScope.cs`，14 文件 / 24 处引用）：

| 成员 | 现判据 | 新模型下 |
|---|---|---|
| `IsEnterpriseRow(enterpriseCode)` | 非空白 | ✅ **保留，升格为唯一分类判据** |
| `IsBackendBuilt(orgCode)` | `== StdEnv` | ⚠️ **改名 `IsPlatformLevel`**，判据 = 非企业行 且 `OrgCode` 空白 |
| `IsEnterprise(orgCode, enterpriseCode)` | `orgCode == enterpriseCode` | ⚠️ **退役**（旧模型把企业 code 填进 `OrgCode` 的遗留判据） |
| `IsLegacyUnassigned(orgCode)` | 空白 = 历史形态 | ⚠️ **退役**（新模型下「空」是**正解**，不是缺陷） |
| `IsBackendBuiltCompat(orgCode)` | `StdEnv` 或 空 | ⚠️ **退役** |
| `Describe(orgCode)` | 三态文案 | 🔧 改三态（机构行 / 企业行 / 平台标准级） |

**新增**：

```csharp
/// 机构行：OrgCode 有值（≠ 企业行时即机构）
public static bool IsOrgRow(string? orgCode) => !string.IsNullOrWhiteSpace(orgCode);

/// 平台标准级：非企业行 且 OrgCode 空
public static bool IsPlatformLevel(string? orgCode, string? enterpriseCode)
    => !IsEnterpriseRow(enterpriseCode) && !IsOrgRow(orgCode);
```

> ★ **为什么 `IsBackendBuilt` 要「改名」而不是「改判据」**：24 处调用方的语义是「这是后台标准级吗」，
> 新模型下答案从「等于常量」变成「为空」。**保留原名 + 改判据 = 静默改变 24 处行为**；
> **改名 = 编译期强制逐处复核**。这与本项目「静默失败是头号风险」一致。
