# 68 · 定位决策书与收尾计划（V1）

> **性质**：**决策书**，不是设计文档。只回答三件事：**做什么、不做什么、先做什么。**
> **权威关系**：执行细节以 [`64-专家端企业资料规范化实施规格-V1`](./64-专家端企业资料规范化实施规格-V1.md) 为准；**范围与优先级以本册为准**。两者冲突时，范围听本册，实现听 `64`。
> **配套**：[`00-实现现状对照表-V1`](./00-实现现状对照表-V1.md)（表/列/端点实测）· [`67-文档约束与依赖企业文档-字段收敛设计-V1`](./67-文档约束与依赖企业文档-字段收敛设计-V1.md)（四路分流与依赖判据）

---

## 一、一句话定位

> **把企业交上来的散乱真实资料，按标准条款组装成「来源可追溯」的规范化文档，并给出缺口清单。**

三个限定词**都不能丢**，丢一个定位就变了：

| 限定词 | 含义 | 丢了会变成什么 |
|--------|------|----------------|
| **真实资料** | 输入是企业实际交的东西 | 变成模板生成 —— 头部战场（ISOPilot ¥990/年、14 体系） |
| **可追溯来源** | 每个值能回答「从哪来」 | 变成黑箱生成 —— 客户无法验证，无溢价 |
| **缺口清单** | 交付物是「还差什么」 | 变成「保证通过」—— 法律承诺，不可承诺 |

---

## 二、为什么定这条线（判据）

**唯一判据：问题出在「方向层」还是「执行层」。**

| 线 | 方向层问题（致命·不可解） | 执行层问题（可解·可迭代） | 结论 |
|----|--------------------------|--------------------------|------|
| **专家端**（审核 / NC / 报告） | ✅ 有：① IAF MD5 锁死人日 ⇒ **提效不换钱**；② 签字担责 ⇒ **判定深度受限**；③ 大部分审核员是外部合作方 ⇒ 机构无付费动机 | — | ⛔ **方向层有问题** |
| **企业资料规范化** | ❌ 无 | ✅ 有：竞品 990/年、需渠道、获客慢、证据粒度待补 | ✅ **可做** |

> **判据的意义**：方向层问题再努力也解不开；执行层问题可以边做边解。
> 这条线是全部候选中**唯一「问题都在执行层」**的——这就是定它的理由，与沉没成本无关。

## 三、做什么 / 不做什么

### 3.1 ✅ 做

| 做 | 说明 |
|----|------|
| 真实企业资料 → 标准文档的**组装** | 输入是企业实际交的，输出按 `cert_doc_template` 空白模板落位 |
| **逐锚点来源账本** | 值 / 来源 / 证据 / 可信度 / 人工覆盖 五维 |
| **缺口清单**（Pendings） | 交付物核心：还差什么、该去哪补 |
| **四路分流** | `DocumentFillRouter`（依赖×fixed 四象限），已实现且有单测 |
| **ISO 13485 深度** | 首批标准：13485 正文 + **ISO 14971 风险管理**（+ 医疗器械 GMP 作接口） |
| 一个标准一个标准做透 | 不铺广度，先做深一个 |

### 3.2 ⛔ 不做（**这一节比上一节重要**）

| 不做 | 原因 |
|------|------|
| ❌ **模板库建设** | 头部战场，且 ISO 9001:2026 已发布 ⇒ 模板全要换版。**模板是输入，不是资产** |
| ❌ **承诺「能通过认证」** | 认证取决于审核员判断与现场，不取决于文档质量。**只能说「完备性达 X%」** |
| ❌ **AI 凭空生成内容** | 《认证及认证培训、咨询人员管理办法》第十四条（三）「编造失实的文件、记录」⇒ **撤销执业资格**。必须「真实采集 → 工具整理」 |
| ❌ **给审核员做企业侧文件代写** | 第八条「以任何方式从事认证咨询活动」⇒ 停业 1–2 年 / 撤销资格 |
| ❌ **专家端作为商业主线** | 方向层问题不可解（见 §二）。**降级为规则采集器** |
| ❌ **自建销售团队 / 投放** | 单人 + 熟人行业，投放 ROI 为负。走咨询公司 / 协会渠道 |
| ❌ **多标准并行铺开** | 资源不足 ⇒ 每个都做不深，等于都没做 |

## 四、当前家底（2026-10-20 代码级实测）

### 4.1 九环链路

| # | 环节 | 状态 | 落点 |
|---|------|:----:|------|
| 1 | 上传 → 转换（PDF + MD） | ✅ | `file_convert` → `OfficeConvertTaskExecutor` |
| 2 | 提取 → 画像 | ✅ | `doc_extract` → `cert_extraction_result` / `cert_enterprise_doc_profile` |
| 3 | 模板 + 锚点 | ✅ | `cert_doc_template`（`published` 门槛）+ `cert_doc_template_anchor` |
| 4 | 填写规则（4 来源 + 参数） | ✅ | `SourceSpec` + `cert_fill_param_*` |
| 5 | **四路分流** | ✅ | `DocumentFillRouter.Of`（纯函数）+ `DocumentFillRouterTests` |
| 6 | **取值（两路）** | ⚠️ | 主干通；`self` / `sibling` / `compute` 未实现 |
| 7 | **Office 落笔** | ✅ | `WordFillWriter` / `ExcelFillWriter` + `RealDocumentSmokeTests` |
| 8 | 自验收 + 清示例 | ✅ | `Verified==false ⇒ partial`；`SampleData=1` 无条件清空 |
| 9 | 回写 + 账本 | ✅ | `cert_doc_fill_value` + `cert_doc_normalize_action` |

**完整度 ≈ 75–80%。** 全仓 `TODO` / `NotImplementedException` 零命中。

### 4.2 四个洞（按严重度）

| # | 洞 | 证据 | 影响 |
|:--:|----|------|------|
| 1 | **编排器零单测** | `DocumentFillOrchestrator.cs` 2258 行，`Admin.Tests` 无对应测试文件 | 唯一不可替换核心**无回归保护**，改任何一行都不敢 |
| 2 | **来源种类不全** | `ResolveByEntryAsync:1287` default 报「未实现的来源：self/sibling/compute」 | 合计/日期推算/交叉引用锚点**全部未命中**，直接拉低完成率 |
| 3 | **两路 kind 集合不一致** | 文档驱动仅 `ai/headerFooter/replace/global`；锚点驱动多 `manual`/`profile` | 配 `profile`/`manual` 时**预览报「无此参数」而真填能取到**（静默漂移） |
| 4 | **证据粒度不足** | 账本记「值 + 来源标签」，未记「文件 / 页 / 段」 | 对外只能讲「来源可查」，讲不了「证据可追溯」 |

> ⚠️ 另有一处**隐性单点依赖**：`FixedMatch` 只读画像已有结论（`:822`），无匹配走 `unmatched` 兜底 ⇒ **画像不准则整条链退化为人工指定**。

## 五、排期（按性价比，不按技术趣味）

| 优先级 | 事项 | 为什么在这个位置 |
|:------:|------|------------------|
| **P0** | 编排器单测：四路 × 七步，先覆盖 happy path + 每路跳过分支 | 它现在是**唯一不敢动的地方**。不补，后面所有扩展都在裸奔 |
| **P1** | 补 `compute`（合计 / 日期推算 / 编号序列） | 模板里这类锚点最多，性价比最高 |
| **P2** | 统一两路 kind 注册表（单一事实来源） | 消除静默漂移，改动小、收益大 |
| **P3** | 证据定位到「文件 + 页 / 段」 | 这是「可追溯」定位的地基，不做则差异化是空的 |
| **P4** | `self` / `sibling`（文档内交叉引用） | 可人工兜底，不急 |

### 5.1 三十天节奏（建议）

| 周 | 目标 | 出口判据 |
|:--:|------|----------|
| W1 | P0 前半：四路分流 × 七步的 happy path 测试 | `dotnet test` 全绿，编排器覆盖 ≥ 主干路径 |
| W2 | P0 后半：每路的跳过分支（锁定 / 无模板 / 无锚点 / 未匹配） | 四类跳过各有断言 |
| W3 | P1 `compute` + 用一份真实模板验证 | 该模板的 `FillCompletion` 由 X% 上升到 Y%（需实测基线） |
| W4 | 真实企业跑一遍端到端 + 记三个指标基线 | 产出**第一组真实数字**（见 §六） |

> ⚠️ 三十天里**不要开新功能**。这一个月只做「补测试 + 补一个来源 + 测基线」。

## 六、验证指标（没有这三个数，验证就是「感觉还行」）

| # | 指标 | 定义 | 目标 |
|:--:|------|------|------|
| 1 | **缺口召回率** | 人工找出的缺口，系统找到多少 | ≥ 80% |
| 2 | **误报率** | 系统报的缺口里，多少是假的 | ≤ 20% |
| 3 | **人工复核时间** | 同一份资料，纯人工 X 小时 vs 辅助后 Y 小时 | **Y ≤ 0.5X** |

> ★ **第 3 项最关键**：复核时间降不下来，前两项再漂亮也没用——复核成本会吃掉全部收益。
> ★ 三项都必须**掐表实测**，⛔ 不接受估算。

| 检查点 | 触发条件 | 动作 |
|--------|----------|------|
| 技术验证 | 复核时间降不到 0.5X | **产品逻辑不成立**（不是执行问题）⇒ 停 |

## 八、附带结论：专家端降级

| 项 | 结论 |
|----|------|
| 商业定位 | ⛔ **不作为商业主线**（方向层问题不可解） |
| 保留职能 | ✅ **规则采集器**：服务少量审核员，把「实际怎么判」沉淀为规则库，反哺企业端 |
| 价值锚点 | 若做，锚点从「效率」移到「**合规留痕**」（机构愿为可追溯付钱，不愿为省时间付钱） |
| 禁止表述 | ⛔ 「AI 验证专家结论」—— 身份威胁触发词 |
| 交付形态 | 若做，只做「**疑点 + 依据**」，⛔ 不出「符合 / 不符合」结论 |
