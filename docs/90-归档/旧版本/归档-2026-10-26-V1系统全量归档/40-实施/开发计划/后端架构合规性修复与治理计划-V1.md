## 二、根因（三条，按杠杆率排序）

### R1｜「债务基线」被读成了「待办清单」⇒ 工作量系统性低估

- A-R6 用 `debtBudget`（`guards.mjs:1973-2008`）按**文件 → 允许的最大命中数**冻结存量，R-A/R-B 用整文件 `debt` 冻结。
- 基线越高，新增违规越能**静默通过**（只有 `处数 > 预算` 才拦）。原报告把「8 处」当作可一次替换的 TODO，但其中 4 处语义不等价（校准 #5/#6），替换前必须先扩 `ICoreResourceQuery`。
- **杠杆**：先校准基线（删死条目、下调已修条目），再动业务代码。

### R2｜把「判据分裂」定性成「数据泄露」⇒ 优先级被高估、方案被简化

- 8 处 P0 无一携带越权谓词；真正的风险是**同一个 WHERE 出现在第二处**（铁律 L5 / A-R6），以及**默认过滤差异**（`IsValid`）在收口时被静默引入。
- 后果：若按「泄露」紧急度直接替换，反而会**悄悄改变禁用行的可见性**（校准 #6）——这才是真 bug。

### R3｜守卫「地盘」有盲区 ⇒ 控制器层无纪律

- `R-A`（禁单参 `UpdateAsync`）`roots` 仅 `Services/**`（`guards.mjs:358-371`）⇒ 控制器 5 处**无人扫**。
- `R-B`（禁裸 `ControllerBase`）靠**文件名白名单** `/Auth|Health/i` 放行（`guards.mjs:383`）⇒ `AuditorAuthController` 被「豁免」但原报告当作违规；同时框架层 `MenuController`/`ApiSyncController` 无统一归属（D5 已定：**纳入本轮**）。
- 免认证机制存在**两条并行概念**易混：`[YZHAnonymous]`（开发期 `?usercode=` 冒充机制，**0 处使用**）与 `[AllowAnonymous]`（ASP.NET 标准匿名，登录/验证码刚需）。D2 裁定**删除前者**、保留后者最小子集。
- **杠杆**：把这几条的覆盖面写成明确判据，而不是散落在文件名正则里。

### D1｜「禁用行」在显示类取数里要不要露出来？→ ✅ **A（统一走默认过滤）**
显示类（机构名 / 标准名 / 标准号）一律走 `CoreResourceQuery` 默认方法（含 `IsValid=1`）；**禁用行不显示名（值为空）**。§三 1.2 表中带「加 `IsValid=1`（决策 D1）」的 5 处按此执行，视为**预期行为，非回归**。

### D2｜强制认证 + 免认证机制 → ✅ **接受强制认证；`YZHAnonymous` 彻底取消**
- `WebControllerBase` 的类级 `[YZHAuthorize]` 可接受；`WorkflowTestController.health` 亦走 JWT（**删 `[AllowAnonymous]`**）。

- ⚠️ **`[YZHAnonymous]` ≠ `[AllowAnonymous]`**：后者是 ASP.NET 标准匿名标记，登录/验证码/注册**必须保留**，不在删除范围（收敛见 D6）。

## 五、坑（按踩中概率排序）

1. **默认过滤静默变更**（D1）：`IsValid=1` 一加，禁用行的名字从「有」变「空」且**两端都不报错**。这是本计划最高频的回归源。
2. **列清单写错 = 静默丢字段**（第 3 批）：`UpdateAsync(entity, fields)` 只写 `fields`，漏一列就丢一列。以「端点入参 DTO 实际改动的列」为准，宁可多写不可漏写。
3. **迁移基类改变认证行为**（第 2 批）：`WebControllerBase` 自带 `[YZHAuthorize]`。按 D2，`health` 也走 JWT，**不是**加 `[YZHAnonymous]`；唯一保留匿名的是 §四 D6 的公开集。
3b. **`[YZHAnonymous]` 与 `[AllowAnonymous]` 混淆**：前者是开发期 `?usercode=` 冒充旁路（要删），后者是登录/验证码刚需（要留）。删错一个 = 登录直接不可用。
4. **误信「审计人字段待 DB 验证」**：原报告该行无结论。`CreateBy/UpdateBy/DeleteBy` 同键方五处一致（AGENTS ⑥），本轮**不新增写点**即可；若第 3 批改到 `UpdateBy` 相关列，须跑 `scripts/db/verify/verify_createby.sql`。
5. **守卫输出「有下降」不等于通过**：A-R6/R-A 是「预算内放行」，修复后**必须主动下调预算**，否则等于把额度留着给未来的回归。
6. **`_db.Client.Queryable<T>` 在 `CoreResourceQuery` 内是合法的**（它是唯一实现体）；端内出现即违规。判据看**文件位置**，不是看 API 名。
