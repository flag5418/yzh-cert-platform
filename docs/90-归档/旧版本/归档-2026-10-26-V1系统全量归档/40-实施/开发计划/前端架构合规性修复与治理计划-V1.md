## 二、根因（三条，按杠杆率排序）

### R1｜守卫「地盘」不一致 ⇒ 共享层处于盲区

- `R6`（禁内联 `<el-table>`）扫 `PAGE_ROOTS` = `cert-admin/pages`、`cert-auditor/pages`、`cert-enterprise/pages`、`yzh.vue.core/pages`、`yzh.vue.core/layouts`。
- `R20`（S03–S11 法条）扫 `STYLE_ROOTS` = 四个包的整个 `src`。
- 后果：`cert-share/src/components` 的 `<el-table>` **无人扫描**（P0-② 之所以要靠人工发现），而同一目录的 `<el-dialog>` 被 S07 扫到。
- **这是「共享层应率先垂范」落空的机制性原因**：越是被复用的组件，越不在最严的规则覆盖内。

### R2｜基线被当成豁免 ⇒ 债务表本身已失真

- `guards.mjs` 输出「**12 个文件已下降，可收基线**」，例如 `iso-standard` S07 `2 → 1`、`queue/index.vue` S07 `1 → 0`、`enterprise-fill-params` S07 `1 → 0`。
- 说明历史上修过一批，但**没人收基线** ⇒ 基线里留着已修好的条目（`queue/index.vue`、`enterprise-fill-params` 现在已是 0 处）。
- 风险：基线高于实际时，**未来新增 1 处违规不会报警**（只有 `处数 > 基线` 才拦）。基线虚高 = 静默放行。

### R3｜组件有，但没有「正确写法」

- 4 个组件都在，缺的是「什么场景用哪个 + 必须显式传什么」：
  - 表单型弹窗 → `YzhFormDialog`（内含 `YzhForm` + 页脚提交），不是 `YzhDialog`
  - 只读抽屉 → `YzhDrawer` + **`:show-footer="false"`**（默认 true，会凭空长出「保存/取消」）
  - 无 `prop` 的展示列 → 当前 `YzhTable` 无法表达（`v-for` key 与 slot 名都依赖 `prop`）
- 缺这份对照表，每个页面作者都在重新发明，且发明结果不一致。

### D1｜「继承基类」要哪种语义（**最关键**）

**白话**：基类像**精装房的预制模块**——它默认你家墙上有对应的水管接口（`/treepconfig`、`/tree/root`、`/filter`）。`enterprise-review` 这栋房子是**自建的、压根没那两个接口**（当初明确决定不为它加端点）。于是只有三种走法：

| 走法 | 做什么 | 代价 | 得到什么 |
|------|-------|------|---------|
| **A 真收口** | 后端补 `treepconfig` + `tree/root` 端点，前端继承后几乎不覆写 | 1.5–2d/页 | 真 CRUD 能力、真可测、真统一 |
| **B 形式收口** | 只继承生命周期壳（`init`/`loading`/`reportError`），树与表全部覆写 | 0.5d/页 | 代码「看起来」统一，**该测的还是测不了** |
| **C 只拆分不收口** | 不继承，把 500+ 行拆成「纯函数 + 薄类」 | 1d/页 | 可测性（纯函数可单测），无统一性 |

**建议**：`enterprise-fill-params` 与 `enterprise-review` 走 **A**（它们的树是「一个字段的两次分组」，后端一个端点就能给，且能顺带解决 `GET tasks` 单页 200 行上限的静默截断）；`resources` 走 **C**（它的树是四套资源拼装，补端点成本高于收益，收益主要在拆分）；`enterprise-original` 走 **A 或 C**，但**必须去掉模块级单例**。

#### 手段：AST **位置插入**，不再做行级重写

前四版 codemod 全部翻车，症状都是**结构性破坏**（联合类型被吃掉只剩一个分支 / 函数体被截断 /
签名丢参数），而 `vue-tsc` 对「少了一段代码」往往不报错 —— 这类破坏只能靠人肉 diff 才发现。
⇒ 第五版换思路：**一个字符都不重建**，只用 TS 编译器 API 算出需要加 `this.` 的 `Identifier`
的**精确字符偏移**，从后往前插入 `this.`（插入不影响前面的偏移）。

分类规则（`/tmp/transform-ast5.js`）：
- 顶层 `const X = ref/reactive/computed(...)`、`let X` → 类字段（**保持原声明顺序**，否则饿初始化会拿到 `undefined`）
- 顶层函数 → 求「引用字段」的**传递闭包**：闭包里碰到字段 ⇒ 类方法；否则留模块层
- `type` / `interface` / 普通 `const`（`STATUS_TEXT`）→ 留模块层

#### `index.vue` 适配：状态解构 + 方法加 `logic.`

| 类别 | 做法 | 理由 |
|------|------|------|
| 状态（58 个被页面用到的） | `const { files, statusBar, … } = logic` | ★ **解构后每个名字本身是顶层 ref ⇒ 模板自动解包**。231 处引用**一个字都没改** |
| 方法（32 个） | 模板与脚本一律 `logic.xxx()` | 不能解构（丢 `this`）；模板里 `@click="logic.refresh"` 走的是成员访问，`this` 自然绑定到实例 |
| 纯函数（6 个） | 保持裸名 | 仍是模块层导出 |

> ★★ **最容易踩的一条**：**模板不会解包「非 ref 的 setup 绑定」里的内部 ref**。
> 写 `logic.files` 会渲染成 `[object Object]`（`v-if="logic.files.length"` 恒真、`v-for` 直接报错），
> 而且**不报任何编译错**。`enterprise-review` 用的是 `logic.x.value` 写法，也能跑通 ——
> 两种写法都合法，但**同一页面里必须选一种**，混用会出现「有的地方要 `.value` 有的不要」的幻觉。

#### 三处必须手改的地方

1. **`onDelete` 与基类撞名** → 改名 `deleteFile`。
   基类有 `protected onDelete(_codes: string[]): boolean | Promise<boolean>`（删除后钩子），
   本页的 `onDelete(row: OriginalFile)` 是「删单个文件」的流程方法，语义完全不同。
   TS 报 `TS2416`（参数不兼容），**但只在 `extends` 之后才暴露** —— 这也是「先继承、再让编译器指路」的价值。
2. **错误出口统一**：14 处 `ElMessage.error((e as Error).message)` → `this.reportError(e, '<场景化兜底>')`。
   `reportError` 会打 `handled` 标记（铁律 F-3「谁 catch 谁弹、只弹一次」），
   原写法绕过了这个标记 ⇒ 与 `unhandledrejection` 兜底叠加时**会弹两次**。
   ⚠️ `onDownload`（模块层纯函数）那处**保持原样** —— 它没有 `this`，且不在页面流程里。
3. **首屏改走 `init()`**：`onMounted(() => { logic.loadTree(); … })` → `void logic.init()`。
   基类 `init()` = `loadConfig()`（本页置空）→ `onAfterInit()`（= `loadTree()`），
   且外层有 `try/catch → reportError`；直接调 `loadTree()` 抛错就是 unhandled rejection（白屏无提示）。

#### 本轮新增的坑（已并入 §五 心智模型）

| 坑 | 现象 | 判据 / 解法 |
|----|------|-------------|
| codemod 用行级正则改代码结构 | 联合类型被截断 / 函数体丢失，**`vue-tsc` 不报错** | ⛔ 只要改动涉及「跨行结构」，一律 AST + **位置插入**，不重建原文 |

| macOS 自带 BSD `grep` 不支持 `\|` | `grep -n "a\|b" file` 静默返回空 ⇒ 误判成「代码丢了」 | 用 `grep -E "a|b"`（本项目 `Grep` 工具无此问题） |

#### 三个设计决定（都不显然，写下来）

1. **状态由 composable 造，别名挂回类**：`readonly batchFiles = this._uploadState.batchFiles`。
   ⇒ 实例化即建状态（随页面生灭），而模板仍写 `logic.batchFiles`。

2. **方法用「一行转发」而不是 `Object.assign`**：`Object.assign` 会把对象字面量的 **getter 求值后当数据属性拷过去**
   （`singleFolderLabel` / `batchPlanRowGroups` / `selectedBatchCount` 会**冻在构造那一刻的值**）—— 这是静默错误。
