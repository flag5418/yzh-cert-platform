## 2. 三层同构清单

本册**新建**模块四件套（同名同路径）：

| 层 | 路径 | 说明 |
|----|------|------|
| Controller | `CertPlatform.Auditor/Controllers/Ent/{StandardDocContract,EntDocProfile,MatchCandidate,MatchDecision}Controller.cs` | 后端入口（**契约维护除外，见下**） |
| Service | `CertPlatform.Auditor/Services/Ent/…` | 业务实现（Controller 薄壳） |
| API（前端） | `cert/cert-share/src/api/ent/{standard-doc-contract,ent-doc-profile,match-candidate,match-decision}.ts` | 手写 API，用 `yzhApi` |
| Pages（前端） | 见 §5（契约在 `cert-admin`，画像/裁决在 `cert-auditor`） | 页面文件夹 |

**模块划分与文件命名**：

| 模块 | Controller | Service | api/ent/*.ts | pages |
|------|-----------|---------|--------------|-------|
| 标准文档契约 | `StandardDocContractController`（**Admin** 端，配置类） | `StandardDocContractService` | `standard-doc-contract.ts` | `cert-admin/src/pages/ent/standard-doc-contract/` |
| 文档画像 | `EntDocProfileController` | `EntDocProfileService` | `ent-doc-profile.ts` | `cert-auditor/src/pages/ent/ent-doc-profile/` |
| 匹配候选 | `MatchCandidateController` | `MatchRecallService` / `MatchRankService` / `MatchArbitrateService` | `match-candidate.ts` | 并入 `match-review/` |
| 匹配裁决 | `MatchDecisionController` | `MatchDecisionService` | `match-decision.ts` | `cert-auditor/src/pages/ent/match-review/` |

> **domain 取 `ent`**：实体目录 `CertPlatform.Shared/Entities/`（契约在 `Dir/`，画像与匹配在新建 `Ent/`、`Match/`），前端 `ent/`，一处定名全域通用。
> **端归属**：契约维护属**配置**（Admin）；画像与裁决属**业务**（Auditor，与 06 册线同端，便于复用企业上下文与左树骨架）。

**实体位置**（`02` §8.3）：

| 实体 | 路径 |
|------|------|
| `StandardDocContract` | `CertPlatform.Shared/Entities/Dir/`（与契约宿主同域） |

## 3. 后端结构与基类选型

| Controller | 端 | 继承 | 理由 |
|------------|----|------|------|
| `StandardDocContractController` | Admin | `YzhControllerBase<StandardDocContract>` | 单表 CRUD + 状态流转钩子 |
| `EntDocProfileController` | Auditor | `ControllerBase`（职能特殊） | 只读查询 + 重跑触发，无标准 CRUD 语义 —— `AGENTS.md` ③ 允许，**类注释须写明理由** |
| `MatchCandidateController` | Auditor | `ControllerBase`（职能特殊） | 纯查询（双视角/冲突清单）+ 触发 |
| `MatchDecisionController` | Auditor | `ControllerBase`（职能特殊） | 动作型端点（accept/reject/…），不暴露通用增删改 |

> ⚠️ 06 册线的 `EnterpriseFileController` 继承 `WebControllerBase`（已登记为 `AGENTS.md` ③ 例外）—— **本册不改它**。

**服务层**：

```text
CertPlatform.Auditor/Services/Ent/
  EntDocProfileService.cs         C2 指纹 + C3 画像 + 落库（列白名单）
  MatchRecallService.cs           C4 多路召回（纯计算）
  MatchRankService.cs             C5 精排批调用 + 解析校验
  MatchArbitrateService.cs        C6 阈值/冲突分流
  MatchDecisionService.cs         C7 裁决事务（07 §3 六步）

CertPlatform.Admin/Services/Ent/
  StandardDocContractService.cs   契约 CRUD + 状态校验 + 冗余同步

CertPlatform.Auditor/Tasks/Ent/
  EntDocProfileTaskExecutor.cs    队列消费（照抄 OfficeConvertTaskExecutor 模板）
  EntDocMatchTaskExecutor.cs      召回 + 精排任务
```

**新增队列任务类型**：`ent_doc_profile`、`ent_doc_match` —— 注册照抄 `CertPlatformAdminServiceExtensions.cs:54-61`，中文名同步 `CertQueueNotifier.cs:17-22`（`02` §4.4）。

**回写纪律（全模块统一）**：状态回写用**指定列更新**（列白名单见 `03` §4.3、`07` §3），⛔ 禁止 `UpdateAsync(整实体)`；业务状态在 `ExecuteAsync` 内完成，`OnTaskStateChangedAsync` 不承载业务。

**统一表守卫（R-14 / T-06）**：凡写 `cert_standard_directory_file`，WHERE 必须带 `EnterpriseCode`；模板行（`YzhVirtualEnterprise.Code`）**拒绝**企业侧上下文写入。

## 4. 端点定义

> 路由前缀 = Controller 名去 Controller；`ApiCode` = 路由全路径（改名即断权限关联，须重跑 ApiSync —— `AGENTS.md` ②）。
> 全部返回 `ApiResponse` 信封；业务失败 HTTP 200 + `success=false`（`22-接口返回规范-V1.md`）；新增 vs 更新按业务键分流（`GetByCode` / `StandardFileCode`），`Id` 不进 WHERE。

### 4.1 标准文档契约（Admin）

| 方法 | 路由 | 说明 | 权限点 |
|------|------|------|--------|
| GET | `/StandardDocContract/Page` `/Detail` | 契约查询 | `Contract/Query` |
| POST | `/StandardDocContract/Save` | 保存（按 `StandardFileCode` 分流 + `active` 前置校验） | `Contract/Save` |
| POST | `/StandardDocContract/Status` | 状态流转 draft→review→active→archived | `Contract/Save` |

| POST | `/StandardDocContract/TestMatch` | 选 1 份样本文件试跑指纹/精排（模板校验用） | `Contract/Test` |

## 5. 前端页面与样板

| 页面 | 端 | 路由 | 样板 | 说明 |
|------|----|------|------|------|
| 契约维护 | cert-admin | `/ent/standard-doc-contract` | 单表 CRUD `system/user/` + 详情抽屉 | 五要素编辑；指纹/提示词测试按钮 |
| 文档画像 | cert-auditor | `/ent/ent-doc-profile` | 单表 CRUD `system/user/`（零手写内核） | 只读列表 + 重跑动作 |
| 匹配裁决 | cert-auditor | `/ent/match-review` | 左树右表变体（`07` §2.2 结构） | 按标准文档视角 + 候选列表 + 证据抽屉 |
| 企业资料库 | cert-auditor | 已实现（`pages/resources/`） | —— | **06 册线，本册不改** |

**硬约束**（`AGENTS.md` ①）：

- 单表 CRUD **零手写** `handleAdd/handleSubmit/...`，一律 `useSingleTable` 内核派发；
- ⛔ 禁 `view-grid/VolBox/VolForm/VolProvider/axios`、`.vue` 内禁直接 `fetch(`；
- 左树右表**只抄 `logic.ts` 的 `dataLoader` 骨架**，`index.vue` 不抄；
- API 用 `yzhApi`，信封读取按 L1–L4 顺序（`22-接口返回规范`）；
- 字段名 PascalCase 逐字一致（`row.MatchState`、`formData.StandardFileCode`），写 camelCase → **渲染空行且无报错**。

**新增路由/菜单**：注册后必跑 `node scripts/guards.mjs`（R12 路由↔菜单双向）+ `./scripts/db/verify/sync_menu_urls.sh` 刷新菜单快照。

**P4 影响**：若企业端（`cert-enterprise`）启用上传，同款页面在其端复用（`cert-share` API 不变），仅路由与菜单归属不同；首期按「审核员代传」实施则企业端零改动。

## 6. 权限点与 ApiSync

1. 每个端点定 `ApiCode`（上表）；**新增接口后重跑 ApiSync 同步 `sys_api`**，再在角色-接口页关联（`AGENTS.md` ②）；
2. 菜单 + 按钮级权限点按 `07` §7 三角色矩阵配置：企业端无 `MatchDecision/*`、审计仅管理员；
3. ⚠️ `sys_api` 若仍有 `Enable` 列，按铁律九迁移为 `IsValid` 后再配（`README` §3.3）；
4. 改端点/动作名 = ApiCode 变化 = 权限静默断裂 → **改名必须重跑 ApiSync + 重关联**，并在合并说明中显式声明。
