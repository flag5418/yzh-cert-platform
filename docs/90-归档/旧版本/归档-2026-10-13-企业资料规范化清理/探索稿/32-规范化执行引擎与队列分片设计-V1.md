# 规范化执行引擎与队列分片设计-V1.md

> **状态**：**工程级深度设计 —— 待审批**
> **目标**：实现高可靠、可追溯的文档规范化执行引擎，支持灵活的任务作用域分发。

---

## 一、 任务作用域与分片 (Job Scoping)

规范化动作根据触发点不同，被封装为不同粒度的 `yzh_queue` 任务。

### 1.1 作用域定义
| 触发点 | 作用域 (Scope) | 任务负载 (Payload) |
| :--- | :--- | :--- |
| **阶段节点** | `Stage` | 循环该阶段下的所有标准，分发 N 个标准级子任务 |
| **标准节点** | `Standard` | 循环该标准下的所有目录，分发 M 个目录级子任务 |
| **目录节点** | `Directory` | 循环该目录下的所有文件，分发 X 个单文件子任务 |
| **文件节点** | **`File` (核心)** | 执行单份文件的规范化（填充、生成、存入规范化库） |

---

## 二、 规范化执行管线 (Normalization Pipeline)

针对单文件的执行逻辑：
1.  **Context 准备**：拉取 `EnterpriseInfo` + 生效的全局参数 + 文档画像数据。
2.  **锁定检查**：如果 `cert_standard_directory_file.IsLocked == 1`，**跳过执行**并记录日志。
3.  **模板匹配**：寻找对应的 `cert_doc_template`。
4.  **填充执行**：调用 `DocumentFillEngine` 进行锚点替换。
5.  **落库与预览**：生成规范化后的文件存入 `enterprise-documents` 库，同步触发 PDF 转换。

---

## 三、 锁定机制与并发控制

### 3.1 锁定状态机
- **状态：未锁定**：生成引擎可覆盖。
- **状态：已锁定**：专家手动确认后加锁，任何自动化生成均不可触碰。
- **强制覆盖**：管理员权限下可执行“解锁并重跑”。

### 3.2 并发保护
使用 Redis 分布式锁 `lock:normalize:{EntCode}:{StdCode}:{FileCode}`，确保同一份产物不会被多个队列消费者同时写入。

---

## 四、 监控与审计
- **执行日志**：每一条规范化记录必须关联 `ExecutionTaskCode`，可下钻查看填充时的取值路径。
- **失败重跑**：队列支持失败自动重试（指数退避），并在 UI 上通过“红色徽标”实时反馈。
