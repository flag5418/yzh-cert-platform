### 缺口 2 · 可信度在报告边界被丢弃，单元格级可信度**无处落库**

**实测证据**（`CertPlatform.Shared/Office/OfficeFillModels.cs`）：

`FillValue.Confidence` 的注释逐字写着：

> 「层 2 给出的可信度（0~1）。**层 1 不读它**，仅随报告回传供界面展示与审计。」

⇒ **但层 1 构造 `OfficeFillHit` 时并没有把它带出来。** 这是一处**真实的实现缺口**，不是设计缺口。

**再往下：`cert_doc_fill_log` 是聚合表，没有逐行**

```sql
-- DB/mysql/phase11_doc_fill_tables.sql:188
`TotalAnchors` int / `ResolvedCount` int / `PendingCount` int / `Completion` decimal(5,4)
`LeftoverTokens` json / `PendingsJson` json / `RetrievedDocCodes` json / `SkillTrace` json
                          ↑ 全是 JSON 汇总，⛔ 无「一行一锚点」的结构
```

⇒ **三重结论**：

| 层 | 缺什么 |
|----|-------|
| `FillValue` → `OfficeFillHit` | `Confidence` 字段（**改 1 行**：`OfficeFillModels.cs:246` 那个类加一个属性） |
| `OfficeFillReport` | 逐锚点的**完整记录**（现在有 Hits/Pendings，够用，但 ⛔ 区域填充 `Regions` 无值记录） |
| 数据库 | ★ **没有任何表能存「某个锚点取了什么值、来源是谁、可信度多少、谁改过」** |

**唯一有部分字段的表是 `cert_doc_ai_suggestion`**（`phase11:234`）—— 但它**只管 AI 建议**（`SkillCode = src_ai_field/src_ai_table`），
而 25 号实测 **98.6% 的锚点是确定性来源**（编号/日期/人名/公司名）⇒ **98.6% 的取值没有账本**。

⇒ **本册的活**：新建 `cert_doc_fill_value`（`41-01` §一·1），作为**全来源通用**的取值账本，`cert_doc_ai_suggestion` 降级为「AI 候选池」。

## 五 ★ 原型阶段自检发现的 4 个真实缺陷（2026-10-04 补充）

> 这 4 个缺陷由原型的三套自检脚本跑出（`check.js` / `smoke.js` / `verify-tree.js`），
> **不是设计缺陷，是实现缺陷** —— 若留到 Vue 实现阶段，排查成本会高一个量级。
> 记录在此作为「静默 bug」的典型样本。

| # | 缺陷 | 症状 | 根因 | 修法 |
|---|------|------|------|------|
| 1 | `render()` 漏调 `renderTree()` | ★ **左树整棵空白**，展开/折叠无反应 | 函数写好了但无人调用 | 补调用 |
| 2 | `renderSubMenu()` 清空 `.main` 的 `innerHTML` | 切到「规范化日志」再切回，**左树与右区所有节点从 DOM 消失** | `innerHTML=''` 会**移除节点**（不是隐藏） | 改 `style.display='none'` |
| 3 | `switchMenu()` 绕过 `render()` | 切菜单时右区未隐藏 | 直接调 `showDrawer()` | 统一先跑 `render()` |
| 4 | `$()` 取 `innerHTML` 注入的元素 | 改值/重写抛错，「更新文档」按钮失效 | `$()` 只查 HTML 里**静态存在**的 id | 改用 `querySelector` |

### ★ 一条方法论教训

> **自检脚本的 DOM 桩必须严格**：`getElementById` 找不到就返回 `null`（与浏览器一致）。
> 宽松桩（找不到就造一个元素）会把这一整类缺陷挡在门外 —— 本次 4 个缺陷里有 3 个是被宽松桩掩盖的。
>
> ⇒ 已把 `smoke.js` 改成严格模式，并加一条「运行期每次 `getElementById` 都必须命中真实节点」的断言。
