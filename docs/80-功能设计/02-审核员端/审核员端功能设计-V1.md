## 一、功能概述

### 1.1 产品定位

审核员端（auditor 端）是**审核员个人的辅助工具**，不是认证机构管理系统：

| 维度 | 定位 |
|---|---|
| 服务主体 | 审核员个人（注册制，绑定一个认证机构） |
| 核心价值 | 减轻审核员工作负担：企业资料 → 工作流驱动的 NC 检查 → 报告内容生成 |
| 不做的事 | 不发证、不做审核组派组、不做认证决定、不做机构级企业主数据管理 |
| 可信度机制 | 每条 NC 检查项、每段报告内容均由独立自定义工作流生成，可溯源到"哪个文档的哪一项内容"（点击即审计） |
| 风险边界 | 企业资料完整性不做强制约束（辅助工具定位）；未来通过"企业信息导出/导入"解决审核员之间的资料迁移 |

> **主体定位决策（2026-09-01 用户确认）**：同一企业可先后在不同机构认证、同机构不同年份换审核员，各为独立档案；不做机构级企业资料完整性限制，风险更小、推广更容易。后续如开发体系认证机构管理系统，另立项目。

### 1.2 左侧导航（8 模块）

```
审核员端（auditor，端口 9991，Vue3 + TS + Naive UI）
├─ ① 当前任务     审核员关注的任务清单（快速操作入口）
├─ ② 企业管理     企业档案、企业人员、联系方式、企业归档/激活
├─ ③ 工作平台     任务管理：新建任务、查看任务、任务归档、提升为当前任务
├─ ④ 协同系统     与企业的交互：交流、文件传输（P2）
├─ ⑤ 企业资料     针对企业查看/管理资料（跨企业资料库）
├─ ⑥ 费用管理     按次计费：账户、扣次、充值（P2）
├─ ⑦ 系统日志     操作日志 + 队列执行日志
└─ ⑧ 系统管理     个人信息、消息提醒设置、权限管理（企业用户权限）

右上角常驻：消息铃铛（消息提醒入口）+ 个人设置头像
```

> **企业维度组织（2026-09-01 用户确认）**：关注核心是企业，不是任务。页面导航按企业维度组织为 5 项——工作台（企业维度聚合：待办 + 每家企业最近任务状态）/ 企业管理（企业档案 + 企业资料库）/ 资源管理（跨企业资料全局检索）/ 消息中心（会话 + 系统通知）/ 个人中心（信息、账户、设置）；8 功能模块与 5 项导航的映射见《审核员端界面设计-页面结构-V1.md》§2。功能模块结构（8 模块）保持不变，导航组织按企业维度重组。

| 模块 | 页面 | 优先级 |
|---|---|---|

## 二、业务背景与目标

### 2.1 业务背景

体系认证审核员的日常工作：管理多家受审核企业 → 按标准（ISO 9001/14001/45001/13485…）推进认证阶段（初审/监督/再认证）→ 收集企业资料 → 逐条款检查符合性 → 开具 NC 并跟踪整改 → 撰写审核报告。其中资料翻阅、条款比对、报告撰写占用了大量重复劳动。

本系统将上述过程自动化：资料上传后由后台配置好的自定义工作流（NC 检查规则、报告章节配置）自动执行字段提取与规则校验，审核员的角色从"逐条判定执行者"变为"自动结果的复核者"。

### 2.2 已确认的关键决策

| # | 决策 | 内容 |
|---|---|---|
| D1 | 企业归属 | 企业档案为审核员私有语义：查询一律按 `create_id`（创建审核员）过滤；**数据库 `credit_code`/`enterprise_no` 全局唯一约束维持不变**（不做改造）；**界面展示"企业编号"为审核员维度编号，不做全局唯一约束展示**（企业编号一致性由审核员控制）；同一企业换机构/换审核员 = 新建独立档案；未来通过"企业信息导出/导入"功能迁移资料 |
| D2 | 多标准 | 一个企业可同时进行多个 ISO 标准的认证（三体系结合审核为市场主流），数据模型 `ent_enterprise_phase(enterprise, standard, phase)` 三元组已天然支持；专项设计见《多标准认证-结合审核-功能设计-V1》 |
| D3 | 阶段推进 | 不设"单活跃阶段"硬约束；各标准下各阶段独立推进，可并存多个进行中阶段 |
| D4 | 计费 | 按次计费（NC 检查 1 次/报告生成 1 次），P2 落地；MVP 阶段不拦截 |
| D5 | 消息提醒 | 不占左侧导航，置于右上角（与个人设置同区）；提醒类型可在系统管理中配置开关 |

### 2.3 目标

1. 审核员登录后 3 秒内看到自己关注的工作（当前任务清单）；
2. 单个任务的全部操作（看企业、传资料、看队列、看 NC、看报告、查条款、打包导出）在一个任务详情页内闭环，不需要跨页面跳转；
3. AI/工作流的每条结论可点击溯源到源文件具体位置；
4. 归档可逆：企业归档可重新激活，任务归档也可重新激活。

## 四、业务规则

### 4.1 核心业务模型

```
审核员（注册制，绑定一个认证机构 CB，机构决定可用标准集）
  └─ 企业档案（审核员私有语义，多个；查询按 create_id 过滤）
      └─ 标准绑定（1..N，一个企业可同时认证多个 ISO 标准）
          └─ 阶段（各标准独立推进；pending → in_progress → completed → closed）
              └─ 任务（NC 检查任务 / 报告任务，异步队列执行）
                  ├─ NC 检查项（自动结果 + 人工复核，可溯源）
                  └─ 报告章节（内容 + 来源溯源）
```

### 4.2 任务关注机制（当前任务的核心）

| 规则 | 说明 |
|---|---|
| 关注即当前 | "当前任务" = 审核员对该任务点了关注（`audit_task.is_focused=1`），与任务执行状态无关 |
| 状态无关 | 清单中可同时存在：已结束的任务（查结论/报告/导出）、刚开始的任务（补资料）、执行中的任务（盯队列） |
| 数量不限 | 关注数量不做硬限制；超过 20 个时前端软提示（仅提醒） |
| 新任务默认关注 | 从当前任务页或工作平台新建的任务，创建后自动置为关注 |
| 取消关注 | 任务详情页"取消关注"仅移出当前任务清单，**不影响任务本身**（任务仍在工作平台） |
| 提升为当前任务 | 工作平台任务列表的"设为当前任务" = 打开关注标志；重复关注幂等 |
| 企业维度最近任务 | 工作台/企业列表以**企业为行维度**，每家企业展示**最近一个任务的状态**（刚开启/执行中/已结束）；取该企业各标准各任务中最近创建的一条的状态（2026-09-01 用户确认：关注核心是企业） |

### 4.3 任务状态机

```
pending(排队中) → in_progress(执行中) → completed(成功) → 【待复核】→ confirmed(已确认)
                      │
                      └→ failed(失败) → 一键重试（不重复扣次，P2 计费上线后生效）
```

- 提交即返回：发起任务只创建任务记录并立即返回任务 ID，不阻塞等待；
- "待复核"为强制环节：工作流自动产出的 NC 检查项/报告内容必须经审核员复核/修订后方可生效；
- 原始自动结果永久保留：人工修正后原值可对照（修订留痕：原值→新值、操作人、时间）。

### 4.4 阶段状态机与归档规则

```
pending(待开始) → in_progress(进行中) → completed(已完成) → closed(已归档)
                                                              │
              ┌───────────────────────────────────────────────┘
              └→ 重新激活（取档）：closed → in_progress
```

| 规则 | 说明 |
|---|---|
| 企业归档 | 企业所有标准所有阶段处理完毕后可整体归档（`ent_enterprise.status=archived`）；归档后资料只读 |
| 企业激活 | 归档企业可重新激活（V2.2 规则：激活后自动创建新阶段），档案、历史阶段、历史任务全部恢复可见 |
| 任务归档 | 任务可独立归档（`audit_task.status=closed`），不要求阶段先归档 |
| 任务激活 | 归档任务可重新激活（closed → pending/in_progress），历史结论保留 |
| 归档冻结 | 阶段归档后禁止对该阶段发起新任务；已归档企业/任务下资料不可上传替换 |

### 4.5 NC 与报告规则

| 规则 | 说明 |
|---|---|
| NC 严重度 | major(严重) / minor(一般) / observation(观察项) 三级（DB 现状）；improvement(改进机会) 作为 P2 枚举扩展评估项 |
| NC 闭环 | open → rectifying → rectified → pending_verification → closed；整改证据由企业回传（P2 协同系统上线前由审核员代传） |
| NC 溯源 | 每个 NC 关联 `source_check_code`（触发的合规检查记录）→ `rule_code`（规则）→ 工作流执行记录 → 源文件位置（页/行/单元格） |
| 报告独立 | 每个标准独立出报告（行业现实：每张证书独立）；报告内容从已复核字段组装，不重新提取 |
| 导出 | NC 检查项、报告均可导出；打包类导出走异步队列（见 §6.6） |

### 4.6 多标准规则（摘要，详见专项文档）

- 企业建档时可选 1..N 个标准，各标准独立绑定阶段、独立执行 NC 检查、独立生成报告；
- 任务详情页顶部展示该任务对应标准；条款 Tab 按该标准展示条款树；
- 结合审核（一次任务覆盖多标准通用条款）为 P2 能力，当前阶段各标准独立发起任务。

### 4.7 费用规则（P2）

| 规则 | 说明 |
|---|---|
| 计费单位 | 1 次 NC 检查任务 = 1 次；1 次报告生成 = 1 次 |
| 扣次时机 | 任务提交时扣减；失败自动退回；重试不重复扣 |
| 免费额度 | 注册赠送；数量、套餐档位与计费单价由**后台管理系统配置控制**（前端不写死）；优先消耗 |
| 配置来源 | 免费额度、余额阈值、扣次规则均读后台配置项，前端仅展示 |
| 拦截 | 余额为 0 拦截发起并引导充值（充值入口预留，点击提示"开发中"）；≤3 次弱提醒 |

### 4.8 预留功能与入口（P3，核心完成后完善）

> 2026-09-01 用户确认：微信绑定/支付、标准目录导出等属核心完成后的完善项，**仅预留入口，不实现**。预留入口原则：按钮存在但点击提示"功能开发中"，不阻塞主流程；免费额度/收费方式等由后台配置控制，前端不写死。

| 功能 | 处置 | 入口 |
|---|---|---|
| 微信绑定 | 预留按钮/字段位，可跳过 | 注册流程 Step3、个人中心 |
| 微信推送 | 置灰 | 消息中心 |
| 支付/充值 | 预留入口；余额不足引导"开发中" | 个人中心·账户、发起任务拦截弹窗 |
| 消费记录 | 列表框架占位（空态） | 个人中心·账户 |
| 标准目录导出 | 模板预览可展示，导出按钮占位 | 阶段详情·标准目录 Tab、企业详情 |
| 企业用户管理 | 框架占位 | 企业详情·企业用户 |
| 企业信息导出/导入 | P2/P3，决策 D1 配套 | 企业详情 |

## 六、接口设计

> 路由风格对齐既有 `api/Enterprise/*`；所有接口走 auditor 端 `/api` 代理（9991 → 9992）；响应统一 `{ status, message, data }`；错误处理：参数缺失返回 400 语义 message，权限校验失败返回 401，服务端异常由 YZH 全局过滤器脱敏返回统一 message。

### 6.1 当前任务模块

| 接口 | 方法/路径 | 请求 | 响应 data | 失败场景 |
|---|---|---|---|---|
| 关注清单 | GET `/api/AuditTask/focusList` | query: `groupBy=status\|standard`(可选) | 任务数组（任务号、企业名、标准、阶段、状态徽标、队列进度、NC/报告计数、focused_at），按 focused_at 倒序 | 无关注任务返回空数组（非错误） |
| 设为当前任务 | POST `/api/AuditTask/setFocus` | body: `{ code }` | `{ focused: true }` | 任务不存在/非本人任务 → "任务不存在或无权操作" |
| 取消关注 | POST `/api/AuditTask/unfocus` | body: `{ code }` | `{ focused: false }` | 同上 |
| 任务详情聚合 | GET `/api/AuditTask/detail` | query: `code` | `{ task, enterprise, contacts, phase, filesSummary, queueTrace, ncItems, report, partial }` | 任务不存在；聚合各段失败降级返回部分数据 + `partial:true` |

## 七、数据流 / 时序

### 7.1 新建任务（含多标准）

```
审核员                auditor端              后端(9992)            队列/工作流
  │ ①工作平台/当前任务页发起
  │  选企业 → 选标准(1..N) → 选阶段 → 任务类型
  ├──────────────►  create 请求
  │                  校验：企业归属(create_id)、阶段状态、(P2:余额)
  │                  ent_enterprise_phase 确认/创建
  │                  audit_task 创建(is_focused=1, status=pending)
  │                  提交队列 ─────────────────►  wf_execution_task
  │  ◄── 返回 taskCode/taskNumber（立即）
  │                  前端跳转任务详情页·执行情况Tab
  │                                                       节点执行→完成
  │  ◄── 消息铃铛：任务完成待复核（cert_message）
```

### 7.2 任务详情页聚合加载

```
GET /api/AuditTask/detail?code=
  ├─ task + phase + enterprise（JOIN phase → standard）
  ├─ contacts（联系人）
  ├─ filesSummary（资料计数：已传/应传/待确认）
  ├─ queueTrace（若执行中：节点级进度）
  ├─ ncItems（若已完成：检查项+复核状态）
  ├─ report（若已生成：章节摘要）
  └─ partial 标记（任一数据源失败时 true）
  条款树懒加载：Tab 切到⑥时再取 clauseTree
```

### 7.3 复核闭环（检查结论 Tab）

```
审核员点开某检查项
  → 展示：判定 + 证据 + 来源（文件/页/行高亮定位）
  → [确认] 或 [修正]（带原值留痕）或 [标记NC]（写入 audit_nonconformity）
  → 全部复核完成 → 任务状态 confirmed
  → 报告生成时仅引用已确认字段
```

## 八、边界与异常处理

| 场景 | 处理 |
|---|---|
| 关注任务数过多 | 不硬限制；>20 前端软提示"关注较多，建议整理" |
| 已归档企业上操作 | 所有写接口（上传/替换/新建任务）统一拦截，返回"企业已归档"；读接口放行 |
| 已归档阶段上发起任务 | 拦截："阶段已归档"；提示可重新激活阶段或新建阶段 |
| 执行中任务点归档 | 拦截："任务执行中"；提供"终止任务"二次确认入口（终止走队列取消） |
| 队列执行失败 | 任务详情·执行情况 Tab 展示失败节点与原因；一键重试（重试不重复扣次）；重试仍失败转人工排查入口 |
| 聚合接口部分数据源失败 | 降级返回 partial:true + 缺失段说明，页面该 Tab 显示"数据加载失败，点击重试" |
| 多标准企业的标准上下文 | 条款树/报告/NC 均带 standardCode 过滤；任务详情顶部展示该任务的标准，避免上下文混淆 |
| 联系人重复 | uk_ent_contact 唯一约束兜底；前端保存前做同名同号提示 |
| credit_code 缺失 | 允许 NULL（现状）；企业查重仅前端弱提示，不做强校验（辅助工具定位，决策 D1） |
| 企业用户越权（P2） | ent_user_permission 校验，越权返回 403 语义 message |
| 消息轮询风暴 | unreadCount 轮询 60s 间隔 + 页签不可见时暂停（visibilitychange） |
| 导出包超大 | 打包走异步队列 + MinIO 临时链接（有效期 24h）；超 2GB 拒绝并提示分批导出 |

## 九、测试要点

1. **关注机制**：关注/取消关注往返；新建任务默认关注；工作平台"设为当前任务"幂等；已结束/执行中/刚开始任务混排展示。
2. **任务详情六 Tab**：各状态任务（排队/执行/完成/失败/已确认）下 Tab 的可用性与降级；聚合接口 partial 场景；条款树懒加载。
3. **归档/激活往返**：企业归档→激活（自动开新阶段，历史全量可见）；任务归档→激活（历史结论保留）；归档企业写操作全接口拦截（负向用例集）。
4. **溯源链路**：NC 检查项点击溯源 → 源文件高亮定位（页/行/单元格）；报告章节来源面板跳转；人工修正后原始结果可对照。
5. **多标准**：一个企业挂 3 标准，各标准独立阶段推进；条款树按标准过滤；报告按标准独立；新建企业标准多选。
6. **联系人**：主联系人切换回写冗余字段；唯一约束冲突提示。
7. **导出**：四类导出的成功/空数据/失败提示；异步进度查询；超大包拦截。
8. **消息**：角标轮询、已读同步、提醒设置开关生效性。
9. **权限**（P2）：企业用户仅见授权资料/模块。
