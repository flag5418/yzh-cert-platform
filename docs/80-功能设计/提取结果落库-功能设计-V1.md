## 一、功能概述

规则保存（`SaveExtractionRuleAsync`）时，将 AI 从**标准目录文件**中提取到的**真实字段值/表格数据**落库到 B-08（`ent_extraction_result`）和 B-09（`ent_table_extraction_result`），挂在虚拟企业 **YZH 标准企业（YZH-STD-ENT）** 名下，为自定义工作流的 `get_field` / `get_table` 节点提供可查询的验证数据。

## 二、业务背景与目标

### 2.1 问题

当前规则保存只持久化**字段/表格定义**（`cert_doc_field_def` / `cert_doc_table_def`），AI 实际提取到的**真实数据**（analyze 的预览值、verify 的提取结果）仅在前端展示后丢弃，数据库无任何落库：

```
工作流设计器 get_field[label_tag] → 查 B-08 → 无数据 → 永远"未找到"
```

### 2.2 目标

1. 规则保存后，B-08/B-09 中该文件的真实提取数据**立即可查**（无需等待企业上传链路）；
2. 工作流设计器测试运行注入 `enterprise_code='YZH-STD-ENT'` 即可取到真实数据，打通"文件 → 提取 → 落库 → 查询"全链路；
3. 标准目录提取值成为**参照基线**，后续企业提取可对比差异。

## 四、业务规则

1. **数据来源与优先级**（单一数据入口，后端校验、前端透传）：
   - 优先：**verify 结果**（用户点"验证 Prompt"，AI 用已确认 Prompt 实际提取，最准确）——`ExtractionData { Fields: {code→value}, Tables: {code→rows} }`；
   - 兜底：**analyze 预览值**——`FieldDefDto.ExtractedValue` / `TableDefDto.ExtractedData`；
   - 两者皆无：不写 B-08/B-09（不阻塞规则保存）。
2. **全量删除再插入**：保存时按 `(enterprise_code='YZH-STD-ENT', file_code=@fileCode)` 先物理删除旧提取结果，再插入新数据，确保不产生冗余（同一文件只保留最新一次提取）。
3. **表约束硬保障**：DB 层唯一约束兜底（§5.2），即使逻辑遗漏/并发重复，数据库拒绝重复插入——逻辑控制是软保障，表约束是硬保障。
4. **一致性过滤（后端权威）**：落库时只接受**已保存字段/表格定义中存在**的 field_code / table_code，丢弃定义外的脏键；值内容来自 AI（verify/analyze），键合法性由后端把关（单一约束原则）。
5. **物理删除，不用软删除**：B-08/B-09 有 `delete_time` 软删除列，但提取结果是**快照数据**（可随时重新提取），且软删除残留会与唯一约束冲突（旧记录未物理删除时重插必撞唯一键）——必须 `RemoveRange` 物理删除。
6. **label_tag**：当前阶段 `label_tag = field_code`（简化方案，工作流节点直接填 field_code）；F-02 `wf_field_label_mapping` 完善后生成 `[标准_文档_字段]` 格式（见支撑文档 §6）。
7. **version_number**：标准目录数据固定 `= 1`（人工确认数据，无版本演进）。

### 5.2 表约束（DB 层兜底，硬保障）

```sql
-- B-08：同一企业 + 同一文件 + 同一字段 最多一条（幂等重写的基础）
ALTER TABLE ent_extraction_result
  ADD UNIQUE KEY uk_ent_ext_ent_file_field (enterprise_code, file_code, field_code);

-- B-09：同一企业 + 同一文件 + 同一表格序号 最多一条
ALTER TABLE ent_table_extraction_result
  ADD UNIQUE KEY uk_ent_tbl_ent_file_idx (enterprise_code, file_code, table_index);
```

> 说明：唯一键是"先删后插"的硬保障——即便保存逻辑漏删，重复插入也会被 DB 拒绝（配合 §4.5 物理删除，不产生软删除残留冲突）。

## 六、接口设计

### 6.1 DTO 变更：`SaveExtractionRuleRequest`（ExtractionRuleDto.cs）

```csharp
/// <summary>验证/分析时的提取数据（可选）。有值则保存规则时同步落 B-08/B-09（YZH 标准企业）</summary>
public ExtractionData ExtractionData { get; set; }
```

### 6.2 `POST /api/DocExtractionRule/save`（现有接口，请求体扩展）

```json
{
  "fileCode": "FL-...|附录三 程序文件清单.doc",
  "skill": "word",
  "fields": [...], "tables": [...], "prompt": "...", "isValid": true,
  "extractionData": {
    "Fields": { "appendix_no": "附录三", "doc_title": "程序文件清单" },
    "Tables": { "proc_file_list": [{"seq": "1", "name": "质量手册", "code": "QM-001"}] }
  }
}
```

**响应**：不变（`{ success, message }`）。

**错误处理**：
- extractionData 为 null → 跳过落库，规则正常保存；
- extractionData 中 code 不在已保存定义内 → 该条丢弃（一致性过滤），不报错；
- 唯一键冲突（并发重复保存）→ 事务回滚，返回"保存失败"，由重试解决（先删后插天然幂等）。

### 6.3 工作流消费（下一阶段，本功能不实现）

```
get_field[label_tag]  → SELECT extracted_value FROM ent_extraction_result

get_table[table_code] → SELECT extracted_json FROM ent_table_extraction_result
                        WHERE enterprise_code='YZH-STD-ENT' AND rule_code=@rule AND table_index=@idx
```

## 七、数据流 / 时序

```
管理员：DocExtractionRule 页面
  ├── AI 分析 → 返回 Fields(含 ExtractedValue) + Tables(含 ExtractedData) → 前端展示
  ├── 生成 Prompt → 验证 → 返回 ExtractionData { Fields, Tables } → 前端展示 + 保留原始数据
  └── 保存规则（saveRule）
       │  payload = { fileCode, fields, tables, prompt, isValid, extractionData(verify优先/analyze兜底) }
       ▼
后端 SaveExtractionRuleAsync（单事务）
  ├── 1~4. 现有逻辑不变（规则 + 字段/表格定义 删旧写新）
  ├── 5.【新增】SyncExtractionResultToB08B09Async(ruleCode, fileCode, extractionData)
  │     ├── 5a. 物理删除 B-08/B-09 WHERE enterprise_code='YZH-STD-ENT' AND file_code=@file
  │     ├── 5b. 一致性过滤（仅保留定义中存在的 code）
  │     ├── 5c. 字段 → B-08 每字段一条（field_code/label_tag=field_code/extracted_value）
  │     └── 5d. 表格 → B-09 每表格一条（table_index 1..N / extracted_json）
  └── 提交事务
       ▼
工作流设计器测试运行（注入 enterprise_code='YZH-STD-ENT'）
  └── get_field[label_tag] → ✅ 查到真实提取值
```

## 八、边界与异常处理

| 场景 | 处理 |
|------|------|
| 用户未点验证直接保存 | 前端用 analyze 预览值兜底；仍无数据则不写 B-08/B-09，规则正常保存 |
| 同一文件规则反复修改保存 | 先物理删除再插入，只留最新一次提取（唯一约束兜底） |
| 并发重复保存同一文件 | 两事务同时执行：后提交者 DELETE 后 INSERT 覆盖，唯一键防止中间态重复 |
| YZH-STD-ENT 记录不存在 | 保存时插入前校验，缺失则返回明确错误提示执行前置 SQL（§5.3） |
| extractionData 含定义外 code | 丢弃该条，不报错（一致性过滤） |
| B-08/B-09 已有该企业历史数据（未来企业上传） | 保存时仅按 YZH-STD-ENT + file_code 删除，不触碰真实企业数据 |
| 提取值为空字符串 | 空值不写 B-08（避免噪音数据），表格 extracted_json 为空数组不写 B-09 |

## 九、测试要点

1. 前置：执行 §5.3 SQL → `SELECT * FROM ent_enterprise WHERE Code='YZH-STD-ENT'` 有 1 条；
2. 前置：执行 §5.2 SQL → 两张表唯一约束存在；
3. 保存规则（带 verify 提取数据）→ 断言 B-08 每字段一条、B-09 每表格一条，enterprise_code='YZH-STD-ENT'；
4. 再次保存（修改字段后）→ 断言旧数据被物理删除、新数据无重复（数量 = 字段数 + 表格数）；
5. 只传 analyze 预览值（无 verify）→ 断言兜底数据落库；
6. 传含定义外 code → 断言被过滤；
7. 模拟工作流查询：`WHERE enterprise_code='YZH-STD-ENT' AND label_tag='{field_code}'` 命中真实值；
8. 回归：不传 extractionData 保存 → 规则正常保存、B-08/B-09 无新增。
