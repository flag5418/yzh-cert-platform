## 一、需求溯源与设计对齐

### 1.1 需求来源

- `docs/20-架构决策/核心工作原理-V1.md` §三「引擎一：数据提取」定义完整提取链路：资料质量预审（强制第一步）→ 按文件类型选 Skill → 按提取规则提取字段/表格 → 存储提取结果（含位置信息 + 可信度）。
- `docs/20-架构决策/数据库表设计-V2.md` 定义结果承载表：
  - **B-08 ExtractionResult**（`ent_extraction_result`）：字段级提取结果，每个字段一条记录，含提取值 + 置信度 + 位置信息；
  - **B-09 TableExtractionResult**（`ent_table_extraction_result`）：表格内容提取结果；
  - **A-08 ExtractionRule / A-09 ExtractionField**：提取规则配置（规则级/字段级指定 Skill）；
  - **F-01 Skill**：节点能力库，`skill_code = get_field / get_table` 等消费提取结果；
  - **StandardDirectoryFile.ExtractionRules / ExtractionEnabled / PreCheckRequired / ComplianceRequired**：标准目录文件级提取配置字段，已建未实现。
- `docs/20-架构决策/工作流引擎选型与技术研究-V1.md`：提取引擎 = 文件 → 字段（文件上传 → 预审 → Skill 提取 → B-08/B-09），异步队列执行；`get_field` Skill 从提取结果读取字段。

### 1.2 本模块职责边界

| 职责 | 是否属于本模块 | 说明 |
|------|:---:|------|
| 文件类型识别（magic bytes） | ✅ | `FileTypeDetector`，不信任扩展名 |
| Word/Excel/PDF（文本层）/纯文本提取 | ✅ | `NpoiWordExtractor` / `NpoiExcelExtractor` / `PdfPigPdfExtractor` / `PlainTextExtractor` |

| 提取结果落库（B-08/B-09） | ❌ | 属上传管道 Service 层 |
| 工作流编排（get_field 等 Skill） | ❌ | 属 DAG 引擎（工作流引擎选型文档 §七） |

## 三、接口清单（方法签名 / 参数 / 返回值）

### 3.1 `IFileExtractor`（统一入口，消费方唯一依赖）

```csharp
namespace YZH.Core.Extractor;

public interface IFileExtractor
{
    Task<FileExtractionResult> ExtractAsync(
        string filePath,
        ExtractionOptions? options = null,
        CancellationToken ct = default);

    Task<FileExtractionResult> ExtractAsync(
        Stream stream,
        string fileName,
        ExtractionOptions? options = null,
        CancellationToken ct = default);
}
```

- `filePath`：源文件绝对路径（走路径入口时 `result.FilePath` 会回填）。

- `fileName`：源文件名（类型识别兜底 + 展示用）。
- 返回 `FileExtractionResult`：见 §五。

## 五、统一提取结果模型 `FileExtractionResult`

```csharp
namespace YZH.Core.Extractor.Models;

public class FileExtractionResult
{
    public string? FilePath { get; set; }              // 源文件绝对路径（字节流提取为 null）
    public string FileName { get; set; } = string.Empty; // 源文件名
    public ExtractSourceType SourceType { get; set; }  // magic bytes 识别类型
    public ExtractStatus Status { get; set; }          // Success / OcrRequired / Unsupported / Failed / Cancelled / None
    public string? FullText { get; set; }              // 全文拼接文本
    public List<ExtractedField> Fields { get; set; } = new();   // 字段级结果（→ B-08）
    public List<ExtractedTable> Tables { get; set; } = new();   // 表格级结果（→ B-09）
    public ExtractionSourceInfo SourceInfo { get; set; } = new(); // 页数/文本层/OCR 标记
    public string? Message { get; set; }               // 失败/需 OCR 说明
    public string? ErrorMessage { get; set; }          // 仅 Failed 填充
    public long DurationMs { get; set; }               // 耗时（毫秒）
    public DateTime ExtractedAt { get; set; }          // 完成时间
}
```

## 七、各提取器实现说明

### 7.1 Word（`NpoiWordExtractor`）[DONE]

- **docx（OOXML）**：`XWPFDocument` 按文档顺序遍历 `BodyElements`，段落文本加入 `FullText`，表格写入 `Tables`（`PositionInfo` 含 table 序号）。`SourceInfo.StructureCount` = 段落/文本块数。
- **doc（OLE2）**：检测到 OLE2 头返回 `Unsupported`，`Message` 提示转存 .docx（NPOI 无 HWPF）[TODO:P2]。

### 7.2 Excel（`NpoiExcelExtractor`）[DONE]

- `WorkbookFactory.Create` 自动识别 HSSF(xls) / XSSF(xlsx)，xls/xlsx 统一代码路径。
- 逐工作表（跳过隐藏表，可配）逐行逐单元格，`DataFormatter.FormatCellValue` 取显示值（公式取缓存结果）。
- 每张表输出一个 `ExtractedTable`（`SheetName` + `PositionInfo` 含 row_count），`FullText` = 每行 Tab 连接。

### 7.3 PDF（`PdfPigPdfExtractor`）[DONE]

- **文本层探测**：遍历每页 `page.Letters`，任一页存在 Letters 即 `HasTextLayer = true`。
- 有文本层：逐页提取 `page.Text` 拼接 `FullText`（每页带 `===== 第 N 页 =====` 分隔），`StructureCount` = 已扫描页数。
- 无文本层（扫描件）：返回 `OcrRequired` + 页数 + `OcrRequired = true`，供上层转异步 OCR [TODO:P1/P2]。
- `MaxPdfPageCount > 0` 时扫描到上限即停止（此时 StructureCount 为已扫描页数）。

### 7.4 纯文本（`PlainTextExtractor`）[DONE]

- 自动识别 UTF-8/UTF-16LE/UTF-16BE BOM，无 BOM 默认 UTF-8；`StructureCount` = 行数。

## 十一、与工作流 Skill（get_field 等）的衔接方式

### 11.1 数据流位置

```
文件上传 → [上传管道] FileExtractorService.ExtractAsync
        → FileExtractionResult（FullText / Fields / Tables）
        → 持久化 B-08 ExtractionResult（字段级）+ B-09 TableExtractionResult（表格级）
        → 工作流执行时 get_field Skill 读取 B-08/B-09 → 校验引擎 / 报告引擎消费
```

### 11.2 映射约定

| 提取层模型 | 落库目标 | 工作流消费 |
|------------|----------|------------|
| `FileExtractionResult.Fields[].FieldValue` | B-08.ExtractedValue | `get_field` 输出端口 |
| `FileExtractionResult.Fields[].LabelTag` | B-08 关联 F-02 label_tag | 工作流节点引用键（标签不变，提取方法可换） |
| `FileExtractionResult.Fields[].Confidence` | B-08.Confidence | 校验规则可对低置信度发起人工复核 |
| `FileExtractionResult.Fields[].PositionInfo` | B-08.PositionInfo | 复核定位（页/行/单元格） |
| `FileExtractionResult.Tables[].RawJson` | B-09.ExtractedJson | `get_table` 输出端口 |
| `FileExtractionResult.SourceInfo.OcrRequired` | 文件记录标记 | 触发异步 OCR 队列，完成后回填 |

### 11.3 Skill 注册对齐

工作流引擎 `ISkillRegistry`（工作流引擎选型文档 §七）注册 `get_field / get_table` 时，其执行器内部调用 `IFileExtractor` 或直接读取 B-08/B-09 数据。本模块不注册 Skill（不感知业务），只提供提取能力原子服务。
