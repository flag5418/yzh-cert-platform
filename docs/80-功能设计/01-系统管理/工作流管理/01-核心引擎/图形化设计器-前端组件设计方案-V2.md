## 一、功能概述

### 1.1 定位

`WorkflowDesigner` 是**项目级前端组件**（`src/components/workflow-designer/`），为 NC 规则配置、报告内容配置等页面提供图形化工作流编排能力。

**组件边界**（纯函数模型）：

```
configJSON ──反编译──▶ 业务层（节点/连线数组）──派生──▶ 画布层（LogicFlow 图数据）
    ▲                                                        │
    └──────────────── 操作层（唯一变更入口）◀────────────────┘
```

- **组件负责**：画布渲染、节点增删改、连线、端口绑定、类型化属性面板、操作日志、自动布局、单节点测试、JSON 编译/反编译、脏标记。
- **组件不负责**：左栏业务树（NC 规则树 / 报告章节树）、数据库读写、后端 API 调用、业务校验逻辑。
- **页面负责**：左栏树、选中规则/章节后加载 config、保存时调后端 API、测试/试运行时调后端 API。

**"不操作数据库"原则**：组件是纯函数 `configJSON → 画布`、`画布 → configJSON`，页面负责读写数据库。保存结构未最终定稿前（见 TODO），组件照常开发，只差最后一层序列化对接——内存模型即未来落库 JSON 结构。

### 1.2 复用场景

| 场景 | 页面 | 左栏（页面自建） | workflowType |
|------|------|----------------|--------------|
| NC 规则配置 | `NCConfig/index.vue` | 机构→标准→阶段→NC检查项 | `validation` |
| 报告内容配置 | `ReportDefinition.vue` | 机构→标准→阶段→报告章节 | `report` |

### 1.3 页面与组件交互契约

```
┌─ NCConfig/index.vue ────────────────────────────────────────┐
│                                                              │
│  ┌─ 左栏（页面自建）─┐   ┌─ WorkflowDesigner ────────────┐   │
│  │                  │   │                               │   │
│  │  NC规则树         │   │  SkillPanel + Canvas +        │   │
│  │  (4级懒加载)      │   │  NodePropertyForm(类型化)      │   │
│  │                  │   │  + EdgePropertyForm            │   │

│  │                  │   │                               │   │
```

## 二、业务背景与目标

### 2.1 需求来源（用户核心要求）

| # | 要求 | 定稿结论 |
|---|------|---------|
| 1 | 布局时不能操作数据库 | 组件纯函数，页面负责落库（§1.1） |
| 2 | 同一节点可多次放置，必须有固定编号 | 节点 id = `{classCode}_n{同类序号}`，不可变、进 JSON（§4.2） |
| 3 | 前端建立合理数据结构 | 统一外壳 + 类型化 config + 操作层封闭集合（§4.4/§4.8） |
| 4 | 保存前调用解释器验证 | 双校验：前端即时拦截 + 后端保存权威校验（§4.10） |
| 5 | 详细操作日志 | 操作层统一记录，before/after 预留 undo（§4.8） |
| 6 | 项目级组件复用 | WorkflowDesigner 独立组件，ReportDefinition 复用（§1.2） |
| 7 | 合理代码拆分 | 四层拆分：model / 操作层 / logicflow 适配层 / ui（§4.12） |
| 8 | 节点命名、连线结构等必要信息保存 | 坐标、重命名、连线、端口全部进 JSON（§5.2） |

### 2.2 设计讨论确定的模型（2026-08-18 定稿）

1. **坐标进 JSON**：节点记录含 x/y，保存一次全量落库，告别"布局丢失"。
2. **输入参数由连线约束**：无连线仅手动输入（字面量/ctx）；有连线仅可选择该端口入边上游节点的输出（下拉显示"节点别名.输出端口"）；节点只有一个参数时连线即自动关联。
3. **节点编号 = classCode + 同类递增序号**：`get_field_n1`、`get_field_n2`、`compare_n1`；永远以同类最大编号 +1，删除不复用；编号进 JSON，解释器靠 `id + classCode` 定位执行逻辑。
4. **后端返回功能节点目录，特殊节点前端硬编码**：后端只返回功能性 Skill 目录（输入/输出/约束），特殊节点（start/end/logic/ai/docField/docTable）前端硬编码面板和渲染。
5. **每个节点可单独测试**：无连线 = 手动输入参数独立执行；有连线 = 从 start 按连线逐个执行到当前节点，输出结果，验证前置流程正确性。
6. **多 end + 提前结束**：end 允许多个；如 NC 校验中"关键问题不合格直接结束"，即任意分支到达 end 即结束并输出该 end 上游节点结果。
7. **AI 节点提示词预初始化**：提示词引用节点执行结果（`{{别名.端口}}`），引擎先解析引用、执行被引用节点、注入真实数据，再按提示词语义执行（规则见《AI提示词规则-功能设计-V1.md》）。
8. **强前后端约束**：约束数据化（目录下发）→ 前端操作层即时拦截（UX）→ 后端保存校验（权威）。

### 2.3 目标

1. 形成可落地的图形化工作流设计器组件架构与数据契约。
2. 根治现有页面三个问题：3 栏布局高度、自动布局断线、缺清空功能。
3. 特殊节点（AI / 自定义字段 / 自定义表格 / 逻辑判断 / 开始 / 结束）均有明确的约束与定制面板设计。
4. 按 M1-M6 分步实施，每个里程碑可运行、可验收。

## 四、业务规则

### 4.1 节点三层模型

| 层 | 内容 | 规则 |
|----|------|------|
| **节点 ID** | 系统身份，如 `get_field_n1` | 不可变、永不复用；连线和输入引用都存它；进 JSON |
| **显示名（title）** | 画布上显示的名称，可重命名 | 画布内**唯一**；只改显示不改引用——引用存 ID，显示时映射成别名 |
| **Skill class** | 后端目录里的类（开始/结束/逻辑判断/功能/AI/自定义字段/自定义表格） | 前端只存 classCode；渲染样式、面板、约束全部来自目录 |

### 4.2 节点编号规则

- **同类唯一编码**：id = `${classCode}_n${同类序号}`，示例：`get_field_n1`、`get_field_n2`、`compare_n1`。
- 每类一个计数器；**永远以同类最后一个最大编号 +1**；删除不复用（删除 `get_field_n2` 后新增为 `get_field_n4`）。
- 加载时按类扫描取最大序号重置计数器。
- 旧数据（`n${Date.now()}` 时间戳 id）加载时**迁移重编号**，迁移结果写入操作日志。
- 前缀用 classCode（英文编码），不用中文 skill 名。
- id 是创建时快照，生成后永不变；将来如需改变节点类型 = "删旧建新"，绝不改 id。

### 4.3 class 目录驱动（约束的唯一来源）

后端下发**功能节点**目录，特殊节点前端硬编码。功能节点目录条目结构（详见 §5.5）：

```json
{
  "classCode": "logic", "className": "逻辑判断", "category": "logic",
  "color": "#E6A23C", "icon": "diamond",
  "singleton": false, "maxOut": 2, "testable": true,
  "inputPorts":  [{ "name": "valueA", "type": "any", "maxIn": 1, "sourceModes": ["static","ctx","upstream"] }],
  "outputPorts": [{ "name": "success", "label": "成功", "type": "signal", "anchor": "right-top" },
                  { "name": "failure", "label": "失败", "type": "signal", "anchor": "right-bottom" }],
  "configSchema": [{ "key": "conditions", "type": "conditionsEditor", "required": true }]
}
```

- `maxIn`（端口最多入边数，普通=1，end 汇聚=N）、`maxOut`（节点最多出边数，默认 1，logic=2）、`singleton`、`sourceModes`（输入允许来源）、`testable`（是否支持独立测试）——**所有约束都是数据，不是代码**。
- `configSchema` 定义属性面板渲染的字段类型，前端按类型渲染对应控件——**面板也是数据驱动**。
- **引用与显示分离（V2.1）**：底层引用一律使用节点 id（`classCode+编号`，如 `get_field_n1`），界面下拉/显示一律使用 `className`/`title` 中文别名；序列化保持 id，仅展示层映射中文，重命名不破坏任何引用。
- > V2.1 注：`configSchema` 属于画布设计器阶段实现，Skill 管理页面不涉及此字段。功能节点的输入表单已由 `wf_skill_input` 表驱动。

### 4.4 统一外壳 + 类型化 config

**① 统一外壳**（操作层、连线、缓存、日志只认这层，不感知类型差异）：

```json
{ "id": "get_field_n1", "classCode": "get_field", "title": "获取企业名称",
  "x": 200, "y": 150, "config": {}, "inputs": {} }
```

**② 类型化 config**：config 是"不透明数据"，具体结构由该类型的面板编辑、后端 schema 校验，核心引擎不解析它。

**③ 面板注册表**（前端组件，按 classCode 注册）：

| classCode / 类型 | 面板组件 | 说明 |
|------------------|---------|------|
| `docField` | DocFieldPanel | 文档→字段级联选择 |
| `docTable` | DocTablePanel | 文档→表格→勾选列 |
| `ai` | AiPromptPanel | 提示词编辑器 + 插入节点引用（遵循《AI提示词规则-功能设计-V1.md》） |
| `logic` | LogicConditionPanel | conditions 结构化编辑器 |
| `start` / `end` | 简单面板 | 只读 / end 无结论配置 |
| `*`（功能节点） | GenericSchemaForm | 由 configSchema 驱动，零定制 |

新增**功能**节点类型 = 后端加目录条目 +（必要时）前端注册面板/渲染组件；**通用功能节点前端零改动**。特殊节点前端硬编码，不在此体系内。

**④ 画布渲染注册表**：start 圆 / end 圆 / logic 菱形双锚点（成功/失败）/ docField 显示"文档名.字段名" / ai 显示提示词摘要。每个类型一个渲染器，按 classCode 注册。

### 4.5 输入绑定规则（isConnected 条件约束）

每端口的输入控件由 `isConnected(端口)` 一个条件切换：

| 状态 | 输入控件 | 规则 |
|------|---------|------|
| **无入边** | 手动输入（字面量 / ctx 选择器） | 只允许手动输入，禁止选择节点引用 |
| **有入边** | 下拉选择该端口入边上游节点的输出（显示"**别名.输出端口**"） | 只能选择已连线的上游节点输出，值自动 = `{id}.{端口}` |

- **连线时**：若目标节点该端口未绑定 → 自动写入引用；若该节点**只有一个输入端口 → 连线即完成绑定**（自动关联）。
- **断开连线时**：该端口引用自动清空，标"未绑定"，提示用户改用手填或 ctx。
- **修改绑定 = 换边**：断旧边 → 连新边 → 改引用，操作层一步完成、记一条日志。
- **下拉选了未连线的节点**：自动创建连线（体验最顺）。
- 输入值只允许三种形态，引擎才解析得了：**字面量** / `ctx.上下文字段` / `{节点id}.{输出端口}`。

**存储**：JSON 里 `inputs[端口名]` 存引用字符串（`get_field_n3.fieldValue` / `ctx.xxx` / 字面量），保存时由操作层从连线推导写入 → **JSON 自包含**，引擎不用合并两处数据。后端校验"inputs 引用与 edges 必须一致"兜底。

### 4.6 连线约束

- 端口级连线：`{ source, target, sourceHandle, targetHandle }`（与 V4 §5.5 一致）。
- **一个输入端口至多 1 条入边**（`maxIn=1`）；end 信号端口例外（`maxIn=N`，允许多条入边汇聚）。
- 禁止自连、禁止重复边（同 source+target+sourceHandle 组合）。
- 端口类型兼容校验（source 输出类型 vs target 输入类型，不兼容时报警）。
- **logic 节点固定 2 个出边**（success/failure），画布渲染双锚点（成功绿 / 失败红），**从锚点拖线即绑定分支**——"必须指定哪个节点成功后执行"在画布层面显式化。
- `maxIn`/`maxOut` 全部数据化（目录下发），前端操作层执行。

### 4.7 特殊节点约束表

| 节点 | 输入 | 输出 | config（表单） | 前端交互 | 硬约束 |
|------|------|------|---------------|---------|--------|
| **开始** | 无 | 1（start 信号） | 无 | 固定图标 | **全局唯一且必须存在 1 个**；操作层禁止删除唯一的 start |
| **结束** | 1 信号口（maxIn=N，允许多条入边汇聚） | 无 | `{}`（无结论配置） | 无 | **允许多个**（≥1）；每个 end 必须可达；执行到任意 end 输出该 end 上游节点结果并结束 |
| **逻辑判断** | conditions 的 valueA/valueB（三态绑定） | **2 固定**：success/failure | `conditions[]`（8 操作符 + and/or） | 画布双锚点拖线即绑定分支 | 完整 = 1 入边 + success/failure 各 1 出边；**至少 3 条线**，保存校验强制 |
| **功能节点** | 按 schema，每口 maxIn=1 | 1 | 通用字段表单（configSchema 驱动） | 通用 | 端口类型兼容 |
| **AI** | 可连线（可选） | 默认结果 content/result | `promptEditor`（提示词 + 插入引用） | 提示词编辑器 + "插入节点引用"下拉（显示别名） | 提示词遵循《AI提示词规则-功能设计-V1.md》；提示词内每个引用必须可解析到存在的节点+端口；**依赖图 = 入边 ∪ 提示词引用** |
| **自定义字段** | 无/上下文 | 1（fieldValue:string） | `docFieldPicker`：选文档 → 选字段（级联） | 级联选择器 | 必须先选文档再选字段；第一版输出固定 string |
| **自定义表格** | 无/上下文 | 1（rows:table） | `tableColumnPicker`：选文档 → 选表格 → **勾选需要的列** | 级联 + 复选 | 同上；rows 类型供 AI 节点集合处理消费 |

**多 end 提前结束语义**：

```
start → 提取 → logic ──失败──→ end_n2「不合格」（提前结束）
                    └──成功──→ 后续节点 → end_n1「检查通过」
```

- 每个 end 是独立终止点，执行到任意一个就输出该 end **上游节点**的输出作为工作流结果并结束（end 自身不配置结论）。
- end 节点 title 仍可为"不合格"/"检查通过"（界面中文别名），但结论值来自其上游节点输出。
- 校验：每个 end 必须**可达**（从 start 有路径）；logic 双分支必连且各自最终可达某个 end；不存在"悬空链"（有出边却到不了任何 end 的链要提示）。

**AI 预初始化语义**：

```
引擎执行到 AI 节点
  → 解析提示词里的占位符 → 按依赖图执行被引用的节点（可跨分支、不要求连线）
  → 取真实输出注入为上下文（"先定义提示词的含义"）
  → 再让 AI 按提示词语义执行
```

- 提示词引用语法：编辑显示 `{{企业名称.fieldValue}}`（别名），**落库转 `{{get_field_n3.fieldValue}}`（id）**——与 inputs 同一套"存 id 显示别名"机制，重命名不破坏任何引用。
- 校验：保存/测试时提示词每个引用必须解析到存在的节点+端口，否则报错列出。

### 4.8 操作层封闭集合

**所有变更（UI 点击、拖拽、LogicFlow 事件、代码调用）只能走操作层方法，禁止绕过**。每个操作统一四步：

```
前置校验 → 改 model（业务层） → 触发画布副作用（派生渲染） → 记日志 + 置脏
```

| 操作 | 校验 | 副作用 |
|------|------|--------|
| `addNode(classCode, x, y)` | class 存在、singleton 检查 | 编号分配、画布添加 |
| `removeNode(id)` | 唯一 start 禁止删除 | 级联删除关联边、输入引用回退 |
| `renameNode(id, title)` | 画布内唯一 | 画布文本 + 引用显示映射 |
| `moveNode(id, x, y)` | 无 | 画布坐标（**markDirty，坐标进 JSON**） |
| `connect(source, target, sourceHandle, targetHandle)` | 自连/重复/类型/maxIn/maxOut/singleton | 自动绑定目标端口输入（单参数自动关联） |
| `disconnect(edgeId)` | 无 | 目标端口输入回退"未绑定" |
| `setInputValue(id, port, value)` | 三态格式校验 | 画布属性同步 |
| `setConfig(id, config)` | configSchema 校验；AI 节点提示词按《AI提示词规则-功能设计-V1.md》校验（语法闭合/引用存在且 visible/无环/长度限制） | 画布节点显示同步 |
| `clearCanvas()` | 二次确认 | 清空 model + 画布 + 重置编号器 |
| `autoLayout()` | 无 | 只重算坐标、重派生画布层（见 §4.9） |
| `loadConfig(config)` | 结构校验 + 旧数据迁移 | 重置编号器 + 全量渲染 |
| `exportConfig()` | 保存前校验 | 序列化 config JSON |

**收益**：① 每个操作天然有 before/after → **undo/redo 顺带实现**；② 详细操作日志就是这一层的 hook，不用单独设计；③ 一致性由架构强制（UI/LF 不能直接改状态），而非靠自觉。

### 4.9 两层模型分离（根治自动布局断线）

- **业务层**：节点/连线数组（id、classCode、title、坐标、config、inputs）——唯一真相。
- **画布层**：LogicFlow 图数据，由业务层**派生**。改业务 → 重新派生渲染。
- **自动布局只重算坐标、重新派生，永远不碰业务层**——连线断开、id 冲突这类问题从根上消失。
- **禁止整图 render 做布局**：只更新节点坐标（遍历 `setNodeData`），或 render 后按 source/target 重建边并回填 properties。
- LogicFlow 的边 id 创建后不可修改：**state 以 LogicFlow 边 id 为 key**（放弃 e1/e2 边编号，边不需要业务编号）。

### 4.10 保存与校验（双校验）

- **前端（操作层，UX）**：连线前检查 maxIn/maxOut/类型/singleton；logic 缺分支时画布以虚线/橙色标"待连成功分支"；保存前强制跑结构校验（环、引用存在性、端口完整、start/end 数量、logic 双分支完整、提示词引用可解析），不通过禁止保存。
- **后端（保存，权威）**：V4 §5.4 八项校验扩展为——singleton（恰好 1 个 start、≥1 个 end）、maxIn/maxOut、logic 双分支完整、端口类型匹配、inputs 引用与 edges 一致、提示词引用可解析、outputConfig 端口存在、end 可达性。
- **保存流程**：`emit('save', config)` → 页面 POST → 页面成功后调组件 `markClean()`（组件不自行 markClean，避免页面保存失败时脏标记被清）。

### 4.11 单节点测试

每个节点属性面板提供"**测试此节点**"按钮，使用**当前画布内存状态**（不落库、不依赖已保存数据）：

| 场景 | 执行方式 |
|------|---------|
| **无连线** | 引擎只执行目标节点，输入取手动填写的值（字面量/ctx），返回输出 |
| **已连线** | 引擎从 start 按依赖拓扑执行到 nodeId 停止，返回**每个已执行节点的输入/输出快照** |

- `overrides` 允许注入某节点输出——没有真实数据（如 OCR 未跑）也能测后续逻辑（"调参重跑"）。
- 结果展示：画布标注已执行节点（成功绿/失败红）；结果面板展示目标节点真实输入（解析后的值）、输出、前置节点轨迹（可折叠）。
- flow 测试遇 logic 分支时靠 conditions 真实执行定路径；依赖节点输入不足时提示补 override，不静默失败。
- 引擎未支持"执行到某节点"前，先做 standalone（单节点独立执行），flow 模式标记 TODO，测试按钮按后端能力降级。

```json
{
```

字段语义：

| 字段 | 说明 |
|------|------|
| version | 固定 1（协议版本，非业务版本） |

| edges[].id | 边标识（LogicFlow 自动 id，不进业务语义） |
| edges[].source/target/sourceHandle/targetHandle | 端口级连线 |
| outputConfig | 工作流整体输出映射（**保留兼容，语义以 end 上游节点输出为准**） |

**变量引用语法（与 V4 §5.5 一致）**：

| 场景 | 语法 | 示例 |
|------|------|------|
| inputs 引用上游输出 | `{id}.{端口}`（无大括号） | `"get_field_n2.fieldValue"` |
| inputs 引用上下文 | `ctx.fieldName`（无大括号） | `"ctx.extraction.label_tag"` |
| AI 提示词引用 | `{{别名.端口}}`（显示）/ `{{id.端口}}`（落库），语法与校验规则见《AI提示词规则-功能设计-V1.md》 | `{{企业名称.fieldValue}}` |
| nc_description_template 引用工作流输出 | `{{output.端口}}`（双大括号） | `"{{output.isViolated}}"` |

### 5.5 class 目录元数据 schema（后端下发）

```json
{
  "classCode": "get_field",        // 唯一编码（id 前缀来源）
  "className": "获取字段值",        // 面板显示名
  "category": "functional",        // logic | functional | ai | special
  "color": "#409EFF", "icon": "rect",
  "singleton": false,              // start/end 为 true
  "maxOut": 1,                     // 节点最多出边（logic=2）
  "testable": true,                // 是否支持单节点测试（start 无意义=false）
  "inputPorts": [
    { "name": "labelTag", "type": "string", "required": true, "maxIn": 1,
      "sourceModes": ["static", "ctx", "upstream"] }
  ],
  "outputPorts": [
    { "name": "fieldValue", "type": "string", "label": "字段值", "anchor": "right" }
  ],
  "configSchema": [
    { "key": "docCode", "label": "文档", "type": "docFieldPicker", "required": true }
  ]
}
```

- `sourceModes`：该输入端口允许的来源（static 字面量 / ctx / upstream 上游引用）。
- `anchor`：画布锚点位置（logic 用 right-top/right-bottom 区分成功/失败分支）。
- `outputDynamic`（预留）：自定义字段/表格节点输出由 config 决定，第一版固定化，后续启用动态推导。

### 5.6 特殊节点 config 结构

| classCode | config 结构 | 说明 |
|-----------|------------|------|
| start | `{}` | 无配置；start 全图唯一、不可删除 |
| end | `{}` | 无结论配置；执行到该 end 输出其上游节点结果并结束 |
| logic | `{ "conditions": [{ valueA, operator, valueB }], "conditionLogic": "and" }` | 8 操作符：eq/neq/gt/gte/lt/lte/contains/notEmpty；valueA/valueB 三态绑定 |
| ai | `{ "prompt": "{{企业名称.fieldValue}}...", "model": "..." }` | 提示词遵循《AI提示词规则-功能设计-V1.md》；落库转 `{{id.端口}}`；默认输出 content/result |
| docField | `{ "docCode": "D001", "fieldCode": "F001" }` | 文档→字段级联 |
| docTable | `{ "docCode": "D001", "tableCode": "T001", "columns": ["C1","C2"] }` | 文档→表格→勾列 |

### 6.5 单节点测试

| 项 | 内容 |
|----|------|
| 方法/路径 | `POST /api/workflow/run-node` |
| 请求 | `{ "config": { ...workflow_config }, "nodeId": "get_field_n2", "overrides": { "compare_n3": { "result": true } } }` |
| 响应 | `{ "nodeId", "status": "success"|"failed", "inputs": { 真实输入 }, "outputs": { 端口: 值 }, "trace": [ { nodeId, status, inputs, outputs } ] }` |
| 失败场景 | 400：目标节点不存在 / 输入未绑定 / 引用不可解析（列出具体端口与节点）；500：引擎执行异常（返回节点错误信息）；无连线模式不受"缺少 start"约束，有连线模式校验 start 存在 |
| AI 节点测试 | 提示词引用解析：依赖图 = 边 ∪ 提示词引用（`{{别名.端口}}`），先解析引用、执行被引用节点、注入真实值，再组装三段式提示词调 LLM（规则见《AI提示词规则-功能设计-V1.md》） |

### 6.6 配置校验

| 项 | 内容 |
|----|------|
| 方法/路径 | `POST /api/workflow-config/validate` |
| 请求 | `{ "config": { ...workflow_config } }` |
| 响应 | `{ "valid": true|false, "errors": [ "定位到节点/边/端口的信息" ] }` |
| 失败场景 | JSON 结构非法 → 400 + 结构错误明细 |

### 6.7 试运行（整流程）

| 项 | 内容 |
|----|------|
| 方法/路径 | `POST /api/workflow-config/run` |
| 请求 | `{ "config": { ... }, "context": { "enterpriseCode": "YZH-STD-ENT", "orgCode", "standardCode", "phaseCode" } }` |
| 响应 | 各节点输出 + 最终 outputConfig / end 上游节点输出 |
| 失败场景 | 执行失败返回节点错误信息；注入 `enterpriseCode='YZH-STD-ENT'` 取验证数据（V4 已实施） |

## 七、数据流 / 时序

### 7.1 加载工作流

```
页面选中规则/章节
  → GET api/validation-rule/{code}（含 ruleJson）
  → loadConfig(ruleJson)
       → serializer 反编译 + 旧数据迁移重编号（进日志）
       → 重置同类编号器
       → 若有 docField/docTable 节点 → GET /api/extraction/docs 加载文档清单
       → 操作层初始化 model → 派生渲染画布
```

### 7.2 连线（端口绑定）

```
用户从 A 输出锚点拖线到 B 输入锚点
  → LogicFlow edge:add 事件 → 操作层翻译为 connect(A, B, sourceHandle, targetHandle)
       → 校验（自连/重复/类型/maxIn/maxOut）
       → 写 model：边记录 + B 该端口输入自动绑定（单参数自动关联）
       → 派生画布（回填 properties）
       → 记日志 + 置脏
  → 右侧面板自动切换 EdgePropertyForm，确认端口
```

### 7.3 保存

```
用户点"保存"
  → 操作层前置校验（结构/环/start/end/logic 完整/提示词引用）→ 不通过禁止保存
  → exportConfig() 序列化 config JSON（含坐标）
  → emit('save', config)
  → 页面 POST 业务 API（后端权威校验）→ 成功 → 组件 markClean()；失败 → 保持脏
```

### 7.4 单节点测试

```
用户点节点属性面板"测试此节点"
  → emit('test-node', { nodeId, overrides })
  → 页面 POST /api/workflow/run-node（config 取当前画布内存状态）
  → 结果回传组件：画布标注已执行节点（绿/红）+ 结果面板（真实输入/输出/轨迹）
```

### 7.5 自动布局

```
用户点"自动布局"
  → 操作层：拓扑分层重算坐标（只改 model 的 x/y）
  → 派生渲染：只更新节点坐标（setNodeData），边对象原样保留 → 连线不断开
  → 记日志 + 置脏
```

## 八、边界与异常处理

| 场景 | 处理 |
|------|------|
| 旧数据（`n${Date.now()}` id） | 加载时迁移重编号为 `{classCode}_n{序号}`，迁移记录进操作日志 |
| 历史 JSON 缺 x/y | 加载时自动布局兜底 |
| 引用的 class 目录不存在 | 校验失败，列出缺失 classCode；画布上该节点标"无效节点" |
| 唯一 start 被删除 | 操作层拦截（提示"工作流必须有开始节点"） |
| 无 end 节点 | 保存/测试拦截（提示"工作流必须至少一个结束节点"） |
| logic 缺 success/failure 分支 | 画布虚线提示 + 保存校验拦截 |
| 输入端口已连线但引用缺失 | 操作层自动回填；数据异常时后端校验兜底 |
| 下拉选择未连线节点 | 操作层自动创建连线 |
| 断线后端口未补填 | 该端口标"未绑定"，测试/保存提示 |
| 画布在 keep-alive 切换后 DOM 失效 | onUnmounted 销毁 LogicFlow 实例并释放引用 |
| 大量节点（50+） | LogicFlow 虚拟渲染；限制单工作流节点数（后端目录或配置约束，具体值后续定） |
| 测试无真实数据 | overrides 注入节点输出；不静默失败 |
| 移动节点/自动布局后未保存 | markDirty（坐标进 JSON，必须保存布局） |
| 保存失败 | 页面告知组件，保持脏标记，不 markClean |
