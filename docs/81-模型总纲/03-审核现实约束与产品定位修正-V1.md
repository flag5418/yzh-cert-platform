# 03 · 审核的现实约束与产品定位修正

> 03 号改的是**默认值**，比改结构重要。
> 01 号假设"系统要去发现问题"，02 号假设"系统要逐条款取证"。
> 你这段话说明：这两个假设都不对。真实情况是——**默认所有检查项符合，系统要把"符合"这句话写得有出处。**

---

## 一、被改掉的默认值

| | 原来的默认 | 修正后的默认 |
|---|---|---|
| 系统目标 | 发现问题、给出判定 | **为每条条款生成一段有出处的符合性证据** |
| 起点假设 | 每条条款都要验 | **默认符合，只对少数风险点深查** |
| 疑点地位 | 核心产出（要做准） | **副产品（顺手发现，供审核员取舍）** |
| 证据作用 | 支撑判定 | **给"符合"这句话找出处** |
| 成败标准 | 疑点精确率 | **条款覆盖率 + 溯源率** |
| 时间分配 | 均摊到条款 | **按风险和成熟度倾斜** |

**这一改，四次实跑全 ofi 的病因就彻底解释清了：**

不是召回丢了文档（那是技术原因），是**模型默认"要找问题"，于是它看到什么都要挑刺**，挑不出来就写"未见记录"。而正确默认是"要找符合"，看到《供应商评审表》就该写"查见……符合"。

**同一个输入，默认值不同，产出完全相反。**这比改提示词重要一百倍。

## 二、审核的真实运行逻辑（四条）

### 2.1 第一条：先判断，后取证

审核员进企业，通常 30 分钟内就形成判断：这家准备得怎么样、大概能不能过、哪里可能有问题。

这个判断不是靠条款，是靠**现场观感 + 文件受控状态 + 记录填写痕迹 + 两个问题的回答**。

之后的所有工作，都是**为这个判断找材料**。不是"先查完再判断"。

**产品含义**：系统应该支持"先录入一个总体印象"，然后据此分配深度。而不是一上来就 56 个检查项一视同仁地跑。

### 2.2 第二条：目标是"能通过"，不是"查干净"

认证是企业的市场准入条件，卡在企业脖子上。但企业可以换机构。

所以机构的真实约束是：**既要保证审核质量、不担风险，又要让企业能过。**一个把企业拒掉的机构，会失去客户。

**产品含义**：系统不能设计成"发现问题的机器"。它发现的问题越多，审核员越不敢用——因为每一条问题都意味着他要决定开不开、要承担什么。

### 2.3 第三条：风险导向，而不是全面覆盖

审核员控制风险的方式不是"多查"，是"**挑几条关键的开不符合项**"，其余写符合。

为什么这样能控风险：**只要开了 NC 且企业整改闭环，审核记录就是完整的、可辩护的。**没开 NC 的条款写了符合，也没人质疑。

挑哪几条？大致是：
- 法规硬指标（许可证、强制标准、特种设备、消防、危化）
- 明显与能力不符的（小企业声称做了很多体系工作）
- 容易出安全事故的
- 上一周期开过 NC 的条款（看是否真闭环）
- 与认证范围强绑定的（核心工艺、特殊过程、外包）

**这才是"风险"的真实含义：不是"这条款重要不重要"，是"这条款万一出事，审核员担不担责任"。**

### 2.4 第四条：时间根本不够逐条覆盖

一个三体系项目 2–3 天、40–60 个检查项、几百条条款。按条款逐项查，物理上不可能。

所以审核员实际做的是**抽样 + 代表性论证**：查 5 份记录，然后写"抽查 5 份，均符合"。他不声明"我查了全部"，他只声明"我抽了这些"。

**产品含义**：系统产出的证据，句式必须是"**抽查 N 份，其中……**"，而不是"经全面核查……"。前者是审核语言，后者是虚假陈述。

## 三、三个新维度（原来没有的）

### 3.1 维度一：企业成熟度预判（决定查多深）

审核员一进门就在做的事，可以建模成三档：

| 档 | 特征 | 深度策略 |
|---|---|---|
| **优** | 体系运行 2 年以上、有内审管评闭环、记录填写完整、现场有序 | 只做"证明符合"，深查 2–3 条 |
| **中** | 首次认证或换版、资料由咨询公司代做、记录有但填写单薄 | 正常查，深查 5–6 条 |
| **差** | 明显应付、资料缺项多、现场与管理文件脱节 | 谨慎，深查 8–10 条，且如实记录缺口 |

**这不是"放水"，这是抽样策略。**成熟度高的企业，抽样少也有代表性；成熟度低的企业，抽样少就没有代表性。审核员凭经验在调这个样本量，系统可以把它显式化。

**怎么做预判**（可机械化的信号）：
- 记录填写密度（多少格是空的）
- 签署完整率（该签的地方签了没）
- 文件受控痕迹（版本号、发放记录、作废标识）
- 内审/管评是否闭环（有没有 NC、有没有验证）
- 日期分布（是否集中在某几天补的）

**这几个信号全是规则能算的**，不需要模型。这可能是系统最能立刻产生价值的一块——**帮审核员在 30 分钟内把"感觉"变成"数据"**。

### 3.2 维度二：风险度（决定查哪几条）

跟"可判定度 A/B/C"是两回事：

- **可判定度** = 这条款能不能判（能力边界）
- **风险度** = 这条款值不值得判（注意力分配）

风险度可以打分：

| 因子 | 权重 |
|---|:--:|
| 法规/强制标准硬指标 | 高 |
| 涉及安全（消防、危化、特种设备、职业危害） | 高 |
| 上周期开过 NC | 高 |
| 与认证范围强绑定（核心工艺、特殊过程） | 中 |
| 企业能力与声称明显不符 | 中 |
| 一般管理类条款 | 低 |

**系统的用法**：把 40–60 个检查项按风险度排序，高风险的 5–8 个做深度核查（出疑点供审核员决定），其余只做"证明符合"。

### 3.3 维度三：注意力分配（决定证据量）

三个变量相乘，决定一个检查项该花多少力气：

```
力气 = 成熟度（反比） × 风险度（正比） × 可判定度（正比）
```

落成数字：

| 情形 | 证据量 | 时间 |
|---|:--:|:--:|
| 成熟度高 + 风险低 | 2–3 条 | 8 分钟 |
| 成熟度高 + 风险高 | 5–6 条 | 20 分钟 |
| 成熟度低 + 风险高 | 8–10 条 | 30 分钟 |
| 成熟度低 + 风险低 | 3–4 条 | 10 分钟 |

**这比"按章节均摊"更接近真实。**

## 四、证据的角色变了

### 4.1 原来理解错了

我原来把证据理解成"支撑判定的材料"，所以设计了"三道闸门 + 结论矩阵"，本质是**判定导向**。

你的实际需求是：**证据是"符合"这句话的出处。**

这两个理解差在哪：

| | 判定导向 | 出处导向（正确） |
|---|---|---|
| 证据用途 | 证明符合或不符合 | 让这句话有据可查 |
| 合格标准 | 能支撑结论 | **能指回原文、能被人复核** |
| 需要多少 | 够判定就行 | 够写满这一句就行 |

**出处导向下，"三道闸门"仍然成立，但意义变了：**
- 定位闸 → 保证这句话不是编的（最硬的一条）
- 完整闸（5W1H）→ 保证这句话有具体内容（不是"管理规范"这种空话）
- 归属闸 → 保证这句话挂对了条款

**三条闸门的本质是"防编造"，不是"防漏判"。**这一点必须拧过来。

### 4.2 句式也随之变了

出处导向下，90% 的句子是这个形状：

> 查见《XX程序》（编号），规定了……；
> 抽查 N 份《YY表》，其中 M 份……，结论……。

**注意"抽查 N 份，其中 M 份"这个结构**——它自带诚实性：说了抽几份，没说查全部。

而现在的系统输出"未见记录""未提供任何成文信息样本"——这是**全面否定的句式**，等于声称"我查了全部且都没有"。这在审核语言里是危险的，因为一旦企业拿出记录，这句话就站不住。

**所以输出必须禁止"全面否定句式"**，除非确实有覆盖矩阵证明"应有 N 份、实有 0 份"。

## 五、KPI 也要换

| | 原 KPI | 新 KPI |
|---|---|---|
| 主指标 | 疑点精确率、证据覆盖率 | **① 条款覆盖率：多少条款生成了可用证据句** |
| | | **② 溯源率：多少句子能唯一指回原文** |
| 辅指标 | — | ③ 句式合规率（无全面否定、无空话） |
| 反向指标 | — | ④ 全面否定句出现次数（应为 0） |

**为什么换**：因为你的目标不是"发现问题"，是"减轻审核员写报告的负担"。那么衡量标准就该是"多少条款不用他动手了"，而不是"发现了多少问题"。

**12-15 那个 70–80% 的目标，对应的是"条款覆盖率"，不是"报告整体相似度"。**这一点我之前表述含糊，现在明确了。

## 六、那"证据发现 + 疑点"还做不做？

做，但**降级**。

原来的定位：核心产出，要做准。
现在的定位：**副产品，顺手发现，供审核员取舍。**

具体三个变化：

1. **数量要少**。一次项目报 20–40 条疑点（5–8 个高风险检查项），不是每个检查项都出。现在的系统一个检查项出 2–3 条，56 项就是 100 多条——审核员看不过来，反而会关掉不用。

2. **只报"有据可查的矛盾"**，不报"推断"。比如：
   - ✅ 名录 12 家，评审表只有 3 家（对不上，可指出来）
   - ✅ 4 个部门同一天签署（异常，可指出来）
   - ❌ "管理可能不到位"（推断，不报）

3. **永远不预判"开不开 NC"**。只报"这里有个对不上的地方"，开不开由审核员定（95 号 R-C）。

**比例的合理值大约是 9:1——九成工作在写符合，一成在提示疑点。**现在的系统是反过来的。

## 七、例外：13485 这类标准不能默认符合

你特别提到"13485 之类的国标规定的硬性检查指标"。

这一类要单独对待，因为它们和 19001 的性质不同：

| | 19001（管理体系标准） | 13485（产品/行业标准） |
|---|---|---|
| 性质 | 管理有效性 | **法规符合性 + 产品安全** |
| 判定 | 体系是否运转 | **硬指标是否达标** |
| 风险 | 管理风险 | **法律风险、召回风险** |
| 能否"默认符合" | 可以（抽样策略） | **不行**（硬指标必须逐项核） |

所以模型里要有"**标准类型**"这一维：

- 管理体系标准（19001/24001/45001）→ 默认符合 + 风险导向
- 产品/行业标准（13485/16949/22000/强制性国标）→ 硬指标逐项核，不能默认

**这一维加进去，"默认符合"就有了边界，不会失控。**

## 八、必须守住的底线

把行业的真实运行逻辑写进模型，不等于帮它"走捷径"。三条线不能碰：

1. **不许编造出处**。每句话必须能指回原文。做不到就写"未取得"，不写"符合"。
2. **不许替审核员做"开不开 NC"的决定**。系统只提示矛盾，决定权在人。
3. **不许生成"全面否定句"或"全面肯定句"**。"经全面核查均符合"和"未提供任何记录"都是虚假陈述，只有"抽查 N 份"是真的。

**这三条是产品和"AI 代写报告"的根本区别。**守住这三条，产品的价值是"效率 + 可复核"；守不住，就是"帮人糊弄认证"，那既做不长久，也有法律风险。

## 十、还没定的三件事

1. **成熟度预判要不要做？** 它需要"录入总体印象"这个动作，可能被审核员嫌麻烦。折中方案：不让他录，系统自己从资料算（记录密度、签署完整率、日期分布），算完给他看，他不认可以改。**我倾向做，因为这是最快能建立信任的一步。**

2. **风险度谁来定权重？** 这是机构风格，得做成配置。但默认值可以先给一套，让专家改。

3. **"默认符合"的表述怎么让专家接受？** 关键在话术：不是"系统认定符合"，是"系统帮你把符合的证据整理好，你确认"。**系统永远只出草稿，不出结论。**这一点在前端措辞上必须体现。
