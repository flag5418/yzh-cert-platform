# 05 · 机构差异与内核建模

> 这一份是对 04 号的**自我纠正**。
> 04 号只看了 ACM 一家，就下了"报告 = 骨架 + 槽位"的结论。加上脱敏版（北京中安质环）对照后，我发现：
> **骨架库只是最后一层皮，它不构成模型。**你这句话是对的——"即使看出套路句型，也不解决建模还是没用"。

---

## 一、我错在哪

两个错误，都是方法上的：

1. **用一个样本推全体。** ACM 三家企业的高度一致（4.1/4.2 逐字对应），我把它当成了"行业规律"。实际上那只是"**同机构规律**"。
2. **把投影当模型。** 我看到"固定句式 + 变量槽位"，就以为找到了结构。其实那只说明**输出格式可以复制**，没有说明**判断过程可以复制**。

而你的诉求从一开始就是后者：**这个部门、这个条款，应该有什么证据，我怎么知道它有没有，缺的时候我怎么区分"企业没有"和"我没找到"。** 这是模型；句式是模型跑完之后的美化。

---

## 二、两家机构，实测对照

材料：ACM（`ACM/QR-04-70 A/0`）× 科斯亚/双尼/尚龙；北京中安质环（`ZAZH—SHH/JL 006.2019`）× A公司/B公司。

| # | 维度 | ACM | 北京中安质环 | 是否可通用 |
|:--:|---|---|---|---|
| 1 | 表单列结构 | 4 列：`Clause条款 / Requirements要求 / Audit Evidence审核证据 / NC,OFI` | 3 列：`过程要求 / 检查清单 / 审核记录（不符合描述用N标记）` | 不可 |
| 2 | 第二列内容 | **中英双语审核提问**（"列举组织如何确定……？"） | **只有条款标题**（"组织的岗位、职责、权限"） | 不可 |
| 3 | 分块方式 | `Process Area` 块（含负责人、审核员） | `受审核部门/场所` 页（含陪同人、审核人、日期、该部门条款清单） | 不可 |
| 4 | 体系前缀 | `Q / E / H`（H = 职业健康安全） | `Q / ES`（ES 合并环境与安全） | 不可 |
| 5 | 检查项聚合粒度 | 一行 **1 个条款**（少数合并写成 `Q5.2.1/2`） | 一行 **1–5 个条款**（如 `Q：7.1.2 / Q：7.1.6 / QES:7.2 / QES:7.3 / QES:7.4` 合一行） | 不可 |
| 6 | 不合格表达 | 独立 `NC/OFI` 列，填编号（`OFI1`、`m01`） | **记录正文里标 N**（表头注明"不符合描述用N标记"） | 不可 |

再加两条句式层面的：

| 维度 | ACM | 北京中安质环 |
|---|---|---|
| 访谈起句 | "**与最高管理者**张庆捷**面谈沟通，经其介绍**……" | "**经与负责人交流**，公司根据管理体系方针制定了相应的总目标……" |
| 抽样编号 | "1、2、3、" | "**抽1. / 抽2.**"、"抽内审计划" |
| 独有定性句 | "**与实际相符**"（高频） | 基本不用这句 |

**六处硬差异，全是结构级的，不是措辞级的。**你的判断准确：提问不是每家都做（第 2 条），机构设计的是自己的"考法"（第 5 条最典型）。

## 三、但有三件事，两家完全一样

这才是重点。

### 3.1 检查项 = 条款 × 部门（多条款可聚合）

两家都是这个结构，只是呈现不同：

- ACM：`Process Area = 管理层` 块下，`4.1`、`4.2`、`4.3` 各占一行。
- ZAZH：`受审核部门/场所：行政部` 页眉写着 `Q：5.3/6.2/7.1.2/7.1.3/7.1.4/7.1.6/7.2/7.3/7.4/7.5/9.2`，表内把 7.2/7.3/7.4/7.1.2/7.1.6 压成一行。

**同一件事：先在审核计划里定"哪个部门查哪些条款"，再按这个清单逐条要证据。**块 vs 页、单条款 vs 聚合，只是排版。

### 3.2 一条证据 = 来源 + 事实 + 定性

| | ACM | ZAZH |
|---|---|---|
| 来源 | 与{X}面谈沟通 / 查见《…》/ 抽查N份 / 经现场核实 | 经与负责人交流 / 查见《…》/ 抽1. / 现场查见 |
| 事实 | 文件编号、编制/批准人、日期；批号、数量、实测值 | 同（`XXKJ-CX-03`、编制部门/审核/批准/日期、LEC 法、抽样明细） |
| 定性 | 与实际相符 / 基本符合要求 / 控制基本符合要求 | 基本符合要求 / 查其内容规定基本符合标准要求 |

**动词库不同，三段结构相同。**三段结构相同的原因不是行业习惯，而是**取证逻辑只有这一种**：你说"符合"，必须交代（a）你从哪儿看到的（b）看到的具体是什么（c）所以你判它符合。

### 3.3 符合是默认，不符合是少数

- ACM：NC/OFI 列填充约 8%（邝敏威全文约 50 条，4 个值）。
- ZAZH：表头专门写"不符合描述用 N 标记"，说明**N 是例外标记，不是常规字段**；实际记录里绝大多数条目没有 N。

两家都默认"合格"，都把"不合格"做成一个**附加记号**。

## 四、所以模型的地基只有三个不变量

```
【不变量 1】检查项 = {条款集合} × {部门}
     └ 机构自由度：条款集合怎么聚合（1 条还是 5 条）

【不变量 2】证据 = {来源} × {事实} × {定性}
     └ 机构自由度：用什么动词、什么句式、写在哪一列

【不变量 3】判定 = f(应有, 实有, 一致)
     └ 机构自由度：不合格怎么标（独立列 / 正文标 N / 不标）
```

**三个不变量之外的一切，都是投影参数。**投影参数一家一套，可以替换；三个不变量是所有机构共用的地基。

---

## 五、模型必须回答的五个问题（这是验收标准）

如果模型建对了，它一定能为任意一个检查项回答下面五句。**答不上来的，就是没建模，只是在模仿**：

| # | 问题 | 为什么必须回答 |
|:--:|---|---|
| 1 | 这个条款，在这个部门，**应该有什么**？ | 没有"应有清单"，就不知道什么算缺 |
| 2 | 企业实际**有什么**？ | 这是文档抽取的产出，要能落到"证据类型 + 具体对象" |
| 3 | 两者**对得上吗**？ | 对账。不是模型判断，是集合比对 |
| 4 | 对不上时，是**企业没有**还是**我没找到**？ | **这一条最难，也最关键**——它决定要不要写"未见" |
| 5 | 写进报告的那句话，**指得回哪一处**？ | 溯源。指不回去的句子不许进报告 |

**这五个问题与机构无关、与标准无关、与句式无关。**句型只影响第 5 句之后的"怎么写"。

对照一下你系统的现状：四次实跑全 ofi，本质是**第 1 题没答案**——系统不知道 8.4.1 在采购部"应该有什么"，所以它拿"我看到的"直接当"应有的"，看到的不够就写"未见"。**这不是召回问题，是模型缺第 1 题。**

## 六、模型的可交付物：4 张资产表 + 1 张投影表

"建模"不是写文档，是产出这五张表。前四张是资产（换机构、换标准都还在），第五张是耗材（一家一张）。

### 表 1 · 条款 → 应有证据（核心资产）

| 条款 | 部门适用范围 | 应有的证据类型 | 具体对象（通用层） | 强度 | 缺失时怎么写 |
|---|---|---|---|---|---|
| 8.4.1 | 采购 | 制度 + 记录 | 采购控制程序；合格供方名录、供方评价记录、业绩监视记录 | A | 名录无 → 待定；有制度无记录 → 仅见制度 |
| 7.1.5.1 | 设备/品质 | 制度 + 记录 | 监视测量资源控制程序；仪器台账、校准证书 | A | 校准过期 → 记录异常 |
| 5.1 | 管理层 | 访谈 + 文件 | 方针、目标、管评记录、资源投入 | C | **不判缺，只判覆盖面** |

这张表是产品最核心的资产。它**不依赖任何机构的报告**，可以从 GB/T 原文的动词（"应建立""应保留""应确定"）推出来——因为条款本身就在说"必须有什么"。机构样本只用来**补具体对象名**（那家企业的程序叫什么）。

**要分两层：**
- **通用层**（条款客观含义）：8.4.1 必须有"供方评价"这件事的客观证据。**这是国标决定的，谁都一样。**
- **机构层**（具体要求到哪份文件）：某机构要求"必须见合格供方名录且经批准"。**这是机构设计，一家一样。**

通用层是内核，机构层是配置。**你说"国家对怎么考没规定"，正解就在这：国标规定"必须有客观证据"，机构规定"算哪份文件"。前者可建模，后者只可配置。**

### 表 2 · 文档 → 证据标签

一份抽取结果要能回答："它是什么证据、对哪个条款、强度多少"。
字段至少：`证据类型（制度/记录/现场/访谈/结论）` + `条款归属` + `对象名` + `时间` + `强度`。
这张表的产出方式是从抽取结果打标，不是模型自由发挥。

### 表 3 · 对账与判定规则

```
应有 ∩ 实有 → 符合（可写证据）
应有 − 实有，且能证明"应有 N 份、实有 0" → 缺（可写"未查见"，进疑点）
应有 − 实有，且不能证明覆盖 → 待定（不许写"未见"）
实有 ∩ 矛盾（日期集中/数量不符/签署缺） → 异常（进疑点）
```

**第 3 行是命门。**它在机制上禁掉了"我没找到 = 企业没有"这个错误推论。ACM 报告里 4 次"未见"、ZAZH 里 N 标记，都是**有覆盖依据才敢写的**。

### 表 4 · 事实字段契约（5W1H 落地）

谁 / 何时 / 什么文件 / 编号 / 抽几份 / 实测值 / 谁签的 / 结论短语。
每个字段声明：从抽取结果的哪个字段来、取不到时怎么降级（改句式，不编值）。

### 表 5 · 机构投影表（耗材，一家一张）

| 内核字段 | ACM 落点 | ZAZH 落点 |
|---|---|---|
| 条款集合 | `Clause` 列，一条一行 | `过程要求` 列，可多条款一行 |
| 部门 | `Process Area` 块头 | 页眉 `受审核部门/场所` |
| 要求文本 | `Requirements`，双语提问 | `检查清单`，仅条款标题 |
| 证据三段 | 合并成一段写 `Audit Evidence` | 合并成一段写 `审核记录` |
| 定性短语库 | 含"与实际相符" | 不用该句 |
| 不合格 | `NC,OFI` 列填编号 | 正文标 `N` |
| 体系前缀 | `Q/E/H` | `Q/ES` |
| 抽样编号 | `1、2、3、` | `抽1. 抽2.` |

**换一家机构 = 换表 5。表 1–4 不动。**这才是"内核/外壳分离"的真实含义。

## 七、最容易踩错的一条：多条款聚合必须在核心里

ZAZH 把 `7.2 / 7.3 / 7.4 / 7.1.2 / 7.1.6` 压成一行。如果内核按"一条款一证据"设计，遇到这种机构就会散成五行，报告对不上。

所以内核必须支持：

```
检查项 = { ClauseCode[] , DeptCode , RequirementText }
```

- 证据按**检查项**生成（不是按条款）；
- 判定按**检查项**给一个结论；
- 但内部保留逐条款的落点（因为 ACM 那种机构要拆开显示）。

**聚合粒度是配置，聚合能力是内核。**这是"换机构不改系统"的关键技术点，也是最容易被忽略的一条。

## 八、句型库的正确位置：第 6 层，10% 工作量

把整条链从上到下排一遍，你会看到句型在哪：

```
L1 应有清单     条款在这个部门要什么                ← 模型（资产）
L2 实有清单     企业资料里有什么                    ← 抽取（已基本可用）
L3 对账         应有 vs 实有，缺多少                ← 规则（资产）
L4 缺口性质     企业没有 / 我没找到                  ← 覆盖矩阵（资产）
L5 判定         符合 / 基本符合 / 待定 / 异常        ← 规则（资产）
──────────────────────────────────────────────
L6 成文         用哪套动词、哪套定性短语、写哪一列    ← 句型库（耗材，10%）
L7 排版         表格、页眉、块头、编号风格            ← 模板（耗材，5%）
```

04 号我讲的全是 L6 + L7。**它能决定"像不像"，但决定不了"对不对"。**

这解释了你在 12-15 那个目标上为什么会卡：

- 如果目标是"报告 70–80% 符合需求"，L6 做得好就能骗过眼睛——但专家一眼看见"未见"，就会问"你查了吗"，L5 一崩，信任就没了。
- 如果 L1–L5 做实了，L6 差一点（句式不像），专家的反应是"格式我得改改"，仍然愿意用。

**优先级应该是 L1 > L3 > L4 > L5 > L6 > L7。**现在的系统是 L6 最厚、L1 空缺，所以怎么调都不对。

## 十、下一步（按依赖顺序，不是按工作量）

1. **先建表 1 的最小集**：不是 846 条，是先做**一个部门 × 一个章节**（比如采购部 × 8.4），把"应有证据"列全。这是 1–2 天的事，但它是所有判断的前提。
2. **拿双尼/科斯亚的真实资料去核这张表**：看企业实际有什么、表里列的有没有对上。对不上，先怀疑表 1，不要怀疑召回。
3. **加覆盖矩阵（表 3 第 3 行）**：`应有 N 份、实有 0 份` 才允许写"未查见"。这一条加进去，"未见"会立刻少 90%。
4. **最后才做投影**：等 1–3 稳了，挑一家机构（建议先 ACM，因为材料齐）做表 5，出成品报告。

**你现在最该做的不是再调提示词，是坐下来把"采购部 8.4 应该有什么"这句写清楚。**写不清这一句，任何模型都救不了。

## 十一、留给你判断的两件事

1. **表 1 的"通用层"到底能推多细？** 我倾向：能推到"证据类型 + 对象的抽象名"（制度/记录/现场，如"供方评价记录"），但推不到"具体文件名"。前者靠国标，后者必须靠机构样本或专家。**你认可这个边界吗？**

2. **"待定"要不要出现在报告里？** 表 3 第 3 行会大量产出"待定"。但真实报告里没有"待定"这个词——ACM 和 ZAZH 都是要么写符合、要么写"未见/标 N"。**所以"待定"可能只能作为系统内部状态，出报告时要么转成"基本符合"，要么让审核员手填。这是产品形态问题，比技术问题更关键。**
