# 04 · 审核报告模板的结构逆向

> 这一份回答你上一条的原话："我们还是没有彻底搞清楚这个报告模板的结构。"
> 结论先说：**报告不是写出来的，是填出来的。**一份审核报告 = 固定骨架 + 变量槽位。
> 骨架和槽位都能从你手上这 4 份材料里逆向出来，而且我已经开始了。

---

## 一、先划清两个产品

| | 产品 A（我们要做的） | 产品 B（另一套系统） |
|---|---|---|
| 谁用 | 审核员，现场前 + 现场后 | 机构，收报告之后 |
| 干什么 | **把企业资料变成一份像样的报告** | 校验这份报告有没有漏洞 |
| 规则来源 | 本机构同类报告 + 机构培训材料 | 机构内审规则、CNAS/飞检要点 |
| 输出 | 证据段落草稿 | 风险清单、退回意见 |
| 判定 | 不判定，只组织材料 | 判定"能不能发证" |

你说得对，**NC 根本不在产品 A 的范围里**，逐条校验是产品 B 的事。产品 B 的客户是机构，产品 A 的客户是审核员，两套规则、两套数据、两个交付。

所以从现在起，**产品 A 的目标只有一个：让 90% 的条款都有"看起来是本人写的"那段证据。**剩下 10% 里出现的疑点，是顺手带的，不是任务。

---

## 二、报告的真实骨架（四层）

我把 4 份材料叠起来看，结构是四层，不是三层：

```
第 1 层  报告外壳
   封面 / 认证合同与条款 / 审核计划 / 首末次会议签到 / 审核结论 / 不符合报告 / 附录

第 2 层  过程区域分块（Process Area）
   | 过程/区域 | 负责人 | 审核员 |
   一个块 = 一个部门或一个过程。全报告通常 4–8 块。

第 3 层  块内条款行
   | Clause条款 | Requirements要求 | Audit Evidence审核证据 | NC/OFI |
   块内按条款号顺序排列。同一条款会在多个块里重复出现。

第 4 层  一个条款的证据段落
   200–700 字，内部还有三段式结构（见下文）。
```

**第 2 层的分块顺序，就是审核计划的部门分组顺序。**这解释了一件事：审核计划和报告不是两个东西，是同一个东西的两次出现——计划里排"哪个部门查哪些条款"，报告里按同一顺序落"每个条款的证据"。**所以审核计划的数据结构直接就应该是报告的骨架，不需要另建。**

---

## 三、发现一：同一条款会在多个块里重复

邝敏威模板里，`E6.1.2`（环境因素）出现了 **4 次**：

| 块 | 该块写的证据（节选） |
|---|---|
| GM/MR | 编制了《环境因素识别与评价控制程序》……识别的重大环境因素：火灾爆炸、废气排放……**与实际相符。** |
| 行政财务、安环运行 | 同上内容 ……**行政和办公过程涉及的有：火灾、固废排放，与实际相符。** |
| 生产部、质量部、设备部、研发部 | 同上内容 ……**生产部、质量管理部、设备部均有涉及。研发部涉及的有火灾爆炸、固废排放、化学品泄露。与实际相符。** |
| 采购、销售 | 同上内容 ……**采购销售过程涉及火灾、固废排放，与实际相符。** |

**这是全报告最重要的结构特征。**它说明：

1. 检查项的最小单位不是"条款"，是"**条款 × 过程区域**"（这跟你系统里的 `检查项 = 多条款 + 部门` 完全一致）；
2. 同一条款的共同部分（程序文件叫什么、识别出哪些因素）**在 4 个块里逐字重复**，只有最后一句话是各块特有的"落到我这个部门涉及什么"；
3. 所以**同一条款的多块证据，可以一次生成、按块加一句归属句**。这里的可复用率是 100%（前三段）+ 1 句（归属句）。

**这一条直接决定了产品形态**：不是 56 个检查项各生成一遍，是**先按条款生成一次"条款主体证据"，再按块补一句"本过程涉及……"**。工作量立刻降到 1/4 以下。

## 四、发现二：Requirements 列是机构的固定检查表

三家企业的 Requirements 列，**逐字相同**。

科斯亚 4.1 的 Requirements：
> Understanding the organisation and its context / 理解组织及其环境
> How the organisation has determined external and internal issues relevant to the business purpose and strategic directions that affect its ability to achieve the intended result(s)?
> 列举组织如何确定与业务目标和战略方向相关的内外部问题，会影响其实现预期结果的能力吗？

邝敏威 4.1 的 Requirements：**一模一样，连"列举"两个字都一样。**

而这不是 GB/T 19001 的原文。标准原文是"组织应确定与其宗旨和战略方向相关并影响其实现质量管理体系预期结果的能力的各种外部和内部因素"。**这一列是机构把标准条款改写成的"审核提问"，中英对照，一题一问。**

**这意味着一件很值钱的事：**
- 这一列**不需要任何智能**，它就是一张表（条款号 → 英文提问 → 中文提问）；
- 你手上的邝敏威模板 docx（195KB）**就是这份表的一份完整副本**，覆盖 4.1 到 10.3；
- 建这张表 = 一次性工作量，全机构复用，永不变化。
- 而你系统里现在的 `cert_iso_clause`（846 条）存的是**标准原文**，不是**审核提问**。这是一个明确的缺口，补起来最容易，收益也最直接——审核员打开系统看到的将是"该问什么"，而不是"标准怎么写的"。

## 五、发现三：证据段落是"骨架 + 槽位"，不是创作

这是最硬的一条证据。三家不同企业、不同审核员，写同一条款 4.1，产出如下（我把企业事实保留原样，只把骨架部分加粗）：

**邝敏威（药用辅料，江苏连云港）**
> **与最高管理者**张庆捷**面谈沟通，经其介绍，企业成立于**2015年06月15日**，法定代表人为**何飞**，是一家专业从事**药用辅料**的生产企业。**产品包括**……**公司位于**江苏省连云港市灌云县临港产业纬五路10号……**公司办公加生产面积总计约**3.2万平方**。经沟通确认，场所为自有，提供有产权证。经现场核实：营业执照等证件均在有效期内。**

**科斯亚（吻合钉，江苏常州）**
> **与最高管理者**潘明海**面谈沟通，经最高管理者介绍，位于**江苏省常州市武进经济开发区夏萧村赵墅村西边厂房三楼**，成立于**2020年07月06日**，营业执照：91320412MA21WN6P1P**。是一家从事**吻合器（含电动）用吻合钉的加工**的企业**……公司厂房位于工业园区内，办公与生产位于同一楼层，无水源保护区、自然保护区等敏感区域。公司办公及生产区域均为租赁，面积约**1000㎡**。**

**双尼（油烟净化设备，广东深圳）**
> **与总经理**唐骞**面谈沟通：企业成立于**2015年08月28日**，法定代表人为**谢艳芳**，主要从事**静电式餐饮业油烟净化设备……的销售**。**公司租赁办公场所，租赁方：**麦\*\*，租期到：2028年6月30日，**办公场所位于**广东省深圳市光明区公明街道上村社区华发北路27号1001，**办公室面积约为**150平方米**，公司所在地为商业楼，水、电、通讯配套设施齐全。提供的办公场地条件可满足体系运行与产品的销售需求。**

**抽象出来的骨架：**

```
与{职务}{姓名}面谈沟通{，经其介绍/：}，企业成立于{日期}，法定代表人{姓名}，
{是一家从事/主要从事}{业务}[的企业]。
公司{位于/租赁}{地址}，{面积约}{数值}{㎡}。
{场所性质：自有/租赁}{周边环境：工业园区/商业楼}{证件有效性}。
[结论短语：与实际相符/可满足体系运行需求]
```

**三家填法完全一致。**再看 4.2：

> **组织/公司识别了相关方及其要求和期望，保留有"**{表名}**"，编制：**{人}**，[批准：{人}，]日期：**{日期}**，识别的相关方如：**{列表}**。**

- 邝敏威：保留有"相关方需求和期望监测表"，编制：行政人资部，10/12/2025，识别的相关方如：顾客、供方、员工、政府主管部门、周边相关方。
- 科斯亚：保留有"相关方的需求和期望清单"，编制：张丹，批准：潘明海，日期：2026年06月10日，识别的相关方如：顾客、外部供方、员工、政府机构（生态环境、水务、供电等）等。

**除槽位外一字不差。**

### 这就回答了"风味为什么一样"

风味不是文采，是**固定句子的库存量足够大**。机构的资深审核员把自己写熟的句子冻成了模板，实习审核员学的就是这个——**"这个条款，开头必须这么起，中间必须带编号和日期，最后必须落到一句定性"。**

所以：

| 问 | 答 |
|---|---|
| 为什么一个机构那么多审核员写出来风味差不多 | 因为用的是同一套骨架句 |
| 为什么实习审核员半个月到一个月就能写 | 因为要学的是"填法"，不是"判断" |
| 为什么豆包+模板+一个提问就能出像样的结果 | 因为任务本质是**填空**，不是创作 |
| 为什么手写长提示词达不到 | 因为你在让模型**创作**，它在自由发挥，你在"填槽" |

**这是整个项目最重要的一次认知对齐。**

## 六、发现四：证据段内部的"三段式"

把每个证据段拆开，几乎都是三层：

```
① 来源句   —— 凭什么这么说
      与{X职务}{姓名}面谈沟通 / 查见《{文件}》/ 抽查{N}份《{记录}》/
      经现场核实 / 现场查看 / 经沟通获知

② 事实句   —— 具体到什么程度
      文件编号 + 版本 + 编制人 + 批准人 + 日期
      记录条数 + 抽样明细（批号、数量、结论值）
      数值与限值对比（要求 1.043–1.049，实测 1.047）

③ 定性句   —— 一句短结论
      与实际相符 / 基本符合要求 / 符合标准要求 / 控制基本符合要求 /
      现场控制良好 / 满足体系运行要求
```

**这个三段式，就是 5W1H 的真实落地形态。**我在 01 号里讲的"完整闸（5W1H）"，到这里才具体：

| 5W1H | 在报告里落在哪 |
|---|---|
| Who | ① 里的被面谈人、② 里的编制人/审核人/批准人/操作人 |
| When | ② 里的日期，几乎每句一个 |
| What | ② 里的文件名/记录名 + 编号 |
| Where | ① 里的"现场"、② 里的车间/仓库/岗位 |
| How many | ② 里的"N 份""抽 3 批""0.398 吨" |
| How | ① 里的动作（面谈/查阅/抽查/现场核实） |
| 结论 | ③ 那一句 |

**校验实现就变成了机械动作**：一段证据里若缺 ① 或 ② 或 ③，就不合格；② 里若没有日期、没有编号、没有人名，就是空话，退回重写。**不需要模型判断，正则就能挡。**

## 七、发现五：NC/OFI 列基本是空的

邝敏威模板全文档约 50 个条款行，NC/OFI 列只有 **4 个值**（`m01`、`OFI1`、`OFI2`、`OFI3`），填充率约 **8%**。其余全空。

再查真实报告里的"审核发现"字样：

| 报告 | "审核发现"出现 | "未见/未提供"出现 | "不符合"出现（含条款原文） |
|---|:--:|:--:|:--:|
| 科斯亚 | 0 | 4 | 23 |
| 双尼 | 2 | 7 | 29 |
| 尚龙（13485） | 0 | 4 | 18 |

**结论：疑点在真实报告里根本没有独立位置。**它有两种存在方式：

1. **嵌在证据段中间一句话**："审核发现：食堂人员健康证刚过期(28/07/2026)，经沟通了解，近期已安排体检相关工作，预约体检日期：03/08/2026。"
   —— 注意这个写法：**发现问题 + 紧接着写企业的解释/整改安排**。语气是软化的，不是判决。
2. **进 NC/OFI 列一个编号**，正文仍写在证据段里。

还有第三种：**根本不写**。健康证那条就没有对应任何 NC/OFI 编号。

**这一条彻底证实了 03 号文档的"默认符合"判断，而且给出了比例：92% 空，8% 有值。**你系统现在四次实跑全 ofi，等于把这个比例倒过来了。

## 八、发现六：13485 的报告结构与 19001 不同

尚龙（13485）与另外三家（19001/24001/45001）对比，有三处硬差异：

| | 19001/24001/45001 | 13485 |
|---|---|---|
| Requirements 列 | **审核提问**（"列举组织如何确定……？"） | **标准原文**（"4.1.1 The organization shall document a quality management system..."） |
| 条款密度 | 30–40 个条款块 | **51 个条款块**（13485 条款更细、1/2/3 级更多） |
| 证据重点 | 体系是否运转、管理是否闭环 | **硬指标是否达标、法规符合性** |
| 可否"默认符合" | 可以（抽样策略） | **不行，逐项核** |

**所以"标准类型"这一维必须建在模型里**（03 号已提），而且它不是"风格差异"，是**结构差异**：两个不同模板，两套骨架，不能共用。

## 九、把"风味"拆成可枚举的 7 个要素

"写得像"是可以被拆开的，只有 7 个要素，全部可枚举、可配置：

| # | 要素 | 具体内容 | 是否可机械生成 |
|:--:|---|---|:--:|
| 1 | **句首来源词** | 与…面谈沟通 / 查见 / 抽查/抽见 / 经现场核实 / 现场查看 / 经沟通获知 / 见 | 是（枚举 8–10 个） |
| 2 | **引用格式** | 《文件名》+ 编号 + 版本；"记录表名"+ 编制/批准 + 日期 | 是（结构化字段拼） |
| 3 | **抽样表述** | 抽查 N 份 / 抽见 3 批 / 抽 2 个岗位；抽样覆盖的具体产品名称：… | 是（数量 + 样本清单） |
| 4 | **数值表述** | 要求 X–Y，实测 Z，结论：符合规定 | 是（限值 + 实测） |
| 5 | **定性短语** | 与实际相符 / 基本符合要求 / 符合标准要求 / 控制基本符合要求 / 现场控制良好 | 是（按证据强度选 5–6 个） |
| 6 | **段落长度** | 200–700 字，3–8 个分句 | 是（配额控制） |
| 7 | **人称与时态** | 第三人称、过去/完成时（"编制了""查见""提供了"）、不出现"我"、不出现"未提供"式的全面否定 | 是（禁词表） |

**你看，一个都不是"写作能力"，全是"拼装规则"。**

这就是为什么模型在里面只承担一小部分：它只需要做**"从原文里认出槽位值"**这一件事（2、3、4 三项），其余 4 项是代码拼。

## 十、产品的真实形态：装配，不是生成

到这里，产品结构就清楚了——和 03 号说的"装配报告"完全一致，但现在有了具体骨架：

```
① 骨架库（Skeleton）
   一个条款 × 一类过程 → 一套骨架句（3–6 句）
   来源：从 4 份材料逆向；一个机构一套，500–800 条

② 槽位表（Slot）
   每套骨架声明需要哪些槽位：文件编号 / 编制人 / 批准人 / 日期 /
   抽样份数 / 样本清单 / 限值与实测 / 部门涉及项 / 定性短语
   每个槽位声明：从哪取（文档抽取结果 / 条款属性池 / 审核计划）、
   取不到时怎么降级（改句式，不编值）

③ 填充器（Filler）
   拿槽位值填进骨架 → 得到候选句
   缺关键槽位 → 该句不输出（不是硬编一个值）

④ 校验器（Guard）
   ① ② ③ 三段是否齐；日期/编号/人名是否在；有无禁词（未提供/未见/经全面核查）
   字数是否在区间；定性短语是否在允许集内

⑤ 装配器（Assembler）
   条款主体证据生成一次 → 按过程区域复制 → 加"本过程涉及…"归属句
   → 按审核计划的块顺序排 → 出报告草稿
```

**模型只在 ②→③ 之间工作，而且只是"认值"，不是"造句"。**

按这个结构，工作量分布完全变了：

| 环节 | 工作量 | 说明 |
|---|:--:|---|
| 骨架库 | 大（一次性） | 但从 4 份材料逆向，不是从零发明 |
| 槽位表 | 中 | 跟条款属性池同源，可复用 |
| 填充器 | 小 | 字符串拼装 |
| 校验器 | 小 | 正则 + 规则 |
| 装配器 | 中 | 块复制 + 排序 |
| 模型调用 | **最小** | 只认值，且允许失败 |

**这正是"1 个月能到 70–80%"的唯一可能路径**——因为你不再需要模型在 56 个检查项上都表现出色，只需要它在识别槽位值时不出大错，而槽位值错了也能被校验器挡住。

## 十一、骨架从哪来：4 步逆向法（可执行）

这是这份文档最实操的部分。你已经有的材料足够跑完这 4 步：

**第 1 步：同条款对齐（1 天）**
把 4 份材料按条款号切开，同一条款的多份证据并排。已经有 3 份 4.1、3 份 4.2、3 份 9.2、3 份 9.3、2 份 7.2。**对齐过程会自动显出骨架**——因为差异只出现在槽位位置。

**第 2 步：替换槽位（1 天）**
把对齐后的公共文本里，凡是"人名/日期/编号/文件名/数值/部门名"换成占位符。剩下的就是骨架。我在这份文档里已经手工做了 4.1 和 4.2 两条，方法可复制。

**第 3 步：定义槽位来源（2 天）**
每个占位符标注"从哪取"，只有三个来源：文档抽取结果（`cert_document_extraction`）、条款属性池（`cert_clause_attr`）、审核计划（`cert_audit_plan_detail`）。**标不出来源的槽位，就是必须让审核员手填的，要在界面上显式留空。**

**第 4 步：定性短语归集（0.5 天）**
把 4 份材料里所有"最后一句"抽出来，统计成 5–6 个短语，每个对应一种证据强度（齐全/基本齐全/仅见制度/仅见现场）。**这一句是"风味"最敏感的地方**，必须从真实语料里抄，不能自己造。

**四步总计 4.5 天，产出是 500–800 条骨架 + 一张槽位表。**这是我判断 1 个月可行性的核心依据——因为它不需要"理解 GB/T"，只需要"抄骨架"。

## 十二、还需要你确认的三件事

1. **骨架库要不要按机构分库？** 从材料看，ACM 这一套在 3 家企业上都成立；但换成另一家机构，Requirements 列的提问就已经不一样了。我的判断是：**骨架分机构库（外壳），槽位定义和文档抽取（内核）通用**。这样"一个机构一个机构突破"的成本 = 抄一遍骨架，而不是重做系统。

2. **13485 要不要现在做？** 它是另一套结构（原文条款 + 硬指标），骨架不能复用。**建议先只做 19001/24001/45001 三体系，13485 放第二批。**你朋友的客户结构决定这个优先级。

3. **"条款主体证据 + 归属句"的复制策略，你接受吗？** 这是把工作量降到 1/4 的关键，但它有一个风险：四个块里的前三段一模一样，如果机构内部审报告的人逐块读，会觉得"复制粘贴"。**邝敏威实际就是这么写的**（我核对过 4 个块的 E6.1.2，前三段完全相同），所以这是行业惯例，不是偷懒。但要不要保留这个"完全相同"，还是每块做轻微改写，需要你和专家确认。
