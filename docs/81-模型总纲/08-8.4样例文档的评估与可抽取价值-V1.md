# 08 · 8.4 样例文档的评估与可抽取价值

> 评估对象：`ISO9001_8.4审核证据_20261121.md`（66,708 字节 / 331 行，受审核组织：常州科斯亚自动化科技有限公司）
> 一句话结论：**这是一份"专家级手工取证"的优秀样本，但不是"系统产出"的样本。它的价值不在文本，在它暴露出来的六型疑点和一个模型缺口。**

---

## 一、它是什么

结构八节，实际是**两个产品混装在一起**：

| 节 | 内容 | 属于哪个产品 |
|:--:|---|---|
| 一–三 | 8.4.1 / 8.4.2 / 8.4.3 逐节取证 + 符合性声明 | **产品 A**（审核员工具） |
| 四 | 证据清单 16 项，带完整文件路径 | A |
| 五 | 证据缺口清单 14 项 | A |
| 六 | 证据组织方法（要求项拆解 / 一供一档 / 七层清单 / 三条硬约束 / 三个设计要点） | **A 的方法论** |
| 七 | 简化的审核证据（浓缩版） | A 的输出形态尝试 |
| **八** | **二阶段审核记录的三方比对与真实性核验** | **产品 B**（机构内审） |

**这个混装不是失误，是它最有价值的地方**——它同时把两条产品线各做了一遍，让你能直接看到两者的差别。

## 二、它做对的四件事

### 2.1 它真的读进去了，粒度远超我的预期

我 07 号给的"应有清单"是抽象的（"评价记录""名录""监视记录"）。它给的是**这家企业的真实对象**：

- 程序 KSY-QMS-P-15 第三条规定的归口部门与参评部门
- 三阶文件 KSY-QMS-WI-10（6 个 sheet）里的抽样基准 **MIL-STD-105E 一般检查水平Ⅱ**、**AQL 值参照具体作业指示书**、**CR/MAJ/MIN 三级不良分级**、**免检的三种情形**、**七种不合格处置路径**、**2% 不良率判定阈值**、**六类记录保管 3 年**
- 评审表六项勾选的具体结论（资质符合 / 供货能力基本满足 / 成批供应 / 产品质量优 / 服务情况优 / 按时交货较好）
- 考核表四项得分 **30 / 40 / 13 / 13，总分 96，A 级**
- 进料检验报告两份，**四项检验项目、数量同为 150、四个追溯字段全空、检验日期 2025-06-23 与 2025-03-19**

**这条事实很重要**：它说明**抽取层完全撑得起这个深度**。你系统里 99 份文档的 Markdown 化不是白做的——三阶文件里的 AQL、CR/MAJ/MIN 这些内容，只要抽到位，就能被引用。

**所以"数据不够"不是当前的瓶颈。**瓶颈在下文第三节。

### 2.2 它找到的矛盾，全部是"逻辑上必缺"，不是"我没找到"

这是它最硬的部分。六条：

| # | 它发现的矛盾 | 比对的是 |
|:--:|---|---|
| 1 | 《合格供应商清单》在册 1 家，而实际供货覆盖 316L / 钛丝 / 纸箱 / 自封袋 / 塑料盒五类 | 清单 vs 采购与检验记录 |
| 2 | 管理手册附件一"外包过程：无" vs 内审检查表（采购部）"经查本公司电镀为外包" | **两个文件互相冲突** |
| 3 | 考核表备注"本考核每年进行一次" vs 考核时段 06-10 → 09-30（不足四个月） | 声明频次 vs 实际跨度 |
| 4 | 同一行"配合态度：慢" vs "回应速度：快"，且服务配合度得 13/15 | **同一表格内语义相反** |
| 5 | 两份进料检验报告日期 2025-03-19 / 2025-06-23，**早于体系文件发布日 2026.6.10**，却引用了 2026.6.10 才生效的编号 | **时序矛盾** |
| 6 | 内审检查表审核时间 2026.9.14，却引用了 2026-09-30 才形成的考核结果（**早 16 天**） | **时序矛盾** |

**没有一条是"我没找到记录"，全部是"根据你自己的材料推出你应该有，但你没有"，或者"你自己写的两句话互相打架"。**

这正好印证 03 号说的"疑点五来源全规则可算"，并且把它做实了。**这六条我后面会改写成可执行规则（第四节）。**

### 2.3 它提出了一个我漏掉的组织维度：对象为主键

6.2 那句"**以外部供方为主键，一供一档**，证据不按条款散放，而是以对象聚合、反向映射条款"——这比我 07 号的"按条款顺序排段"多了一个维度。

我 07 号的排序是**输出顺序**（条款顺序，为了让读的人顺着条款点头）；
它的组织是**数据主键**（供方档案，七段：识别 → 准入 → 控制 → 信息 → 监视 → 再评价 → 措施）。

**两者不冲突，是两个层：数据按对象，输出按条款。**这是"内核 vs 投影"的又一次印证。

### 2.4 它诚实地标了证据等级

第 330 行备注和 8.3 都写明：三笔采购单"在本目录内无原件可验证……暂按来源单一、待原件复核处理"。

**这一点比很多人工报告都严谨。**真实 ACM 报告是把二阶段记录里的采购单和实物记录混着写的，它至少分了来源。

## 三、它做错的四件事（都跟产品化有关）

### 3.1 量级差了 100 倍

| | 量 |
|---|---|
| 这份文档，8.4 一个条款 | **66,708 字节 / 331 行** |
| 它的"浓缩版"（七节），8.4.1+8.4.2+8.4.3 三节 | 约 2,200 字 |
| 真实 ACM 报告 8.4 段 | **约 400 字，一段** |
| 中安质环 A 公司 8.4 段 | **约 400 字，一段** |

**取证深度与输出深度是两件事，这份文档把它们焊在一起了。**

它把"后台读了多少文档、核了多少字段"全部写进了"输出"。结果是：一份完美的取证报告，一份完全不能用的审核记录。

**这是产品化上最致命的一条。**因为审核记录是有版面、有习惯、有机构模板的——400 字的格子，塞不进 2,200 字。

### 3.2 它自创了一个不存在的判定档位："符合，附条件"

真实报告里只有两种：**符合** / **开 NC（一般/严重）**。ACM 是"写结论句 + NC/OFI 列填编号"，中安质环是"写记录 + 标 N"。

"附条件符合"这个东西，**在任何一家机构的表单上都没有格子。**

更麻烦的是它的语气："上述四项**须在整改期内补齐或书面澄清**，否则 8.4.1 的充分性不成立"——这是**审核员对企业的口吻**。工具说这句话，等于替审核员做了决定。

7.4 结尾那句更明显："**前三项完成前，8.4 条不具备判定为'符合'的证据充分性。**" —— 这是判定，不是取证。

**这违反 95 号 R-C（不符合只能审核员现场定），也违反 03 号的产品定位（工具只出材料，不出结论）。**

### 3.3 它把"需补充提供"当成常规句式

全文出现大量"需补充提供""需书面澄清""须补齐"。

作为审核现场发给企业的整改清单，这是对的（第五节 14 项就是一份很好的整改清单）。
但**作为审核记录，这句话不会出现**——记录里只写"未见"，不写"需补充"。

**这暴露一个产品设计问题：同一份取证结果，要有两个出口。**
- 出口 A → 审核记录（"查见……未见……"，400 字一段）
- 出口 B → 整改/缺口清单（"需补充提供……"，14 项）

**它现在只有出口 B 的形态，却试图当出口 A 用。**

### 3.4 证据等级在前七节没标，只在第八节标了

8.3 承认三笔采购单"来源单一"，但第一节（8.4.3 取证）已经把它们当作"要素已具备"的依据写了，只在括号里写"目录顶层二阶段审核记录"。

**严格说，一至三节的证据里混了两种：受审核方提交的原件（B），和审核员上次记录的内容（A）。**这两者的证据力完全不同——A 本身可能就是错的（第八节恰好证明了它确实错）。

它自己发现了这个问题，但只用一句备注处理，没有在前七节逐条标注。

**产品上必须硬性分开**：`来源=企业原件` 与 `来源=上期记录` 是两个字段，不能混排。

## 四、它最值钱的产出：六型疑点，可以写成规则

这份文档真正该被抽走的不是文本，是**这六条矛盾背后的检测逻辑**。

我把它们改写成机器可执行的规则：

| 型 | 规则名 | 判定逻辑 | 需要的输入 | 误报风险 |
|:--:|---|---|---|---|
| **T1 覆盖缺口** | 清单 vs 实际 | 名录里供方/物资集合 ⊄ 采购记录∪检验记录∪合同里的集合 → 缺 | 名录 + 采购/检验 | 低（集合运算） |
| **T2 跨文档冲突** | 同一事实两处表述 | 提取"外包过程"类事实，若 A 文件="无" 且 B 文件="有/XX为外包" → 冲突 | 多份文档的同名事实字段 | 中（需先定义"同名事实"） |
| **T3 频次与跨度不符** | 声明周期 vs 实际区间 | 声明"每年/每季/每月" → 期望跨度；实际考核时段跨度偏离 >50% → 异常 | 制度声明 + 记录日期区间 | 低 |
| **T4 同行语义反向** | 同一行两个字段极性相反 | 预设极性词典（快/慢、符合/不符合、合格/不合格）→ 同行反极 → 异常 | 表格结构化 | 低（需词典） |
| **T5 时序倒置（前）** | 记录日期 < 文件生效日 | 记录上写的编号属于某文件，而记录日期早于该文件发布日 → 异常 | 记录日期 + 文件版本日期 | 低 |
| **T6 时序倒置（后）** | 引用者日期 < 被引用者日期 | 记录 A 引用记录 B，但 A 的日期早于 B 的形成日期 → 异常 | 引用关系 + 双方日期 | 低 |

**六型里五型的误报风险是"低"，因为全是日期、集合、极性的机械比较。**

**这是整份文档最值得抽走的东西，比它的证据文本值钱得多。**它们可以立刻写进校验器，而且不需要模型参与。

而且它给出了每条规则的**真实触发实例**——这是回归测试的现成用例。

## 五、它暴露了我的一个模型缺口

我 05 号说"检查项 = 条款 × 部门"，二维。这份文档证明**少了一维**。

看它的 6.2：

```
外部供方档案
├── ① 识别    本案：清单 1 家，实际供货 4 类物资
├── ② 准入    本案：仅金祺达一家有评审表
├── ③ 控制    本案：具备
├── ④ 信息传递 本案：部分
├── ⑤ 绩效监视 本案：具备，但频次矛盾
├── ⑥ 再评价   本案：缺
└── ⑦ 措施    本案：缺
```

**七个段落是围着"一个供方"转的，不是围着"一个条款"转的。**

所以真实的结构是三维：

```
检查项 = {条款集合} × {部门} × {对象}
                             ↑
                    供方 / 设备 / 工序 / 产品批次 / 人员
```

- **对象维度是内核需要的**：因为"缺 4 家评审表"这个判断，必须落在"对象 × 条款"的格子上——是韦恩堡缺 8.4.1 的准入，不是采购部缺 8.4.1。
- **但对象维度不能进输出**：报告是按条款写的，不按供方写。

**这正好把"内核/投影"讲透了：对象是内核的第三维，投影时被压平成"条款 + 抽查 N 家"。**

"抽查 5 家，其中 1 家见评审表"——这一句就是三维压二维的结果：**数字（数量）承担了对象维度的信息。**

这也解释了真实报告为什么都写"抽查 N 份/抽见 X 家"：**这是把对象维度压缩进一维的唯一办法。**我 03 号说"抽查 N 份是审核语言的基本单位"，现在有了结构上的原因。

## 六、这份文档的三个正确用法

### 用法 1：当"应有证据空间的上限"（表 1 的 super-set）

它的 6.1 六项要求、6.3 七层清单，是 8.4 的**证据全集**。

正确做法：**把它当上限，从里面挑 4 段写进报告。**
- 必写：① 识别（名录）、② 准入（评审表）、⑤ 监视（考核）、⑦ 结论
- 条件写：③ 控制（三阶文件，只在 8.4.2 单独出时写）、④ 信息（合同/订单要素）、⑥ 再评价（缺则一句）
- 不写进报告：AQL 数值、CR/MAJ/MIN 分级、七种处置路径、2% 阈值——**这些是"审核员心里的判断依据"，不是"报告的记录内容"**

**这个"必写/条件写/不写"的三分，是这份文档最该被吸收的结构。**

### 用法 2：当疑点规则的回归集

六条矛盾 → 六条规则 → 六个测试用例。**这是现成的、真实的、有人工验证过的金标准。**

### 用法 3：第八节当"产品 B"的原型

第八节做的三件事，全部属于机构内审，不属于审核员工具：

- 逐项比对矩阵（A 声称 vs B 实物）
- 缺失与遗漏（"清单家数差 4 家""评审表差 2 份"）
- **冗余与失真**（"不可复现的确定性断言""结论与自身发现矛盾"）

而且它抓到了产品 B 最该抓的东西：

> "A 同一段内既记载'组织未能提供纸箱供应商森木包装厂的供应商评审表'，又在段末下'**采购过程控制符合要求**'的结论。**缺一家评审表本身即构成 8.4.1 成文信息不完整，与'符合要求'不能并存。**"

**"结论与自身发现矛盾"是机器最该抓的一类，因为它比任何文风问题都硬**——它不需要判断证据是否充分，只需要判断**同一段落里的两句话是否互斥**。

这一条如果做成规则，机构内审能立刻用上。**而这恰好是我 05 号说的"另一套系统"里最有价值的一条，比我当时列的"契约校验"具体得多。**

## 七、产品化时必须切开的两层

这是这份文档给产品最重要的教训：

```
┌─ 取证层（后台，用户看不见）───────┐
│  读全部文档、核全部字段、算全部矛盾  │   ← 这份文档做的（66KB 的料）
│  产出：证据集合、缺口清单、矛盾清单  │
└──────────────────────────────┘
              ↓  压缩（9:1）
┌─ 输出层（前台，进报告）──────────┐
│  400 字一段，抽查 N 家，抽见 X 份    │   ← 真实报告做的
│  产出：可进报告的句子               │
└──────────────────────────────┘
```

**压缩比大约是 9:1 到 20:1。**这份文档如果直接当输出，压缩比是 1:1，那是不可用的。

**而压缩的规则是确定的**：留"对象名 + 数量 + 签署 + 日期 + 结论"，删"判定依据的论证过程"。

举例——从它的 8.4.2 长段压到真实报告口径：

> **它的原文（约 900 字）**：三档控制、MIL-STD-105E、AQL 参照、免检三情形、CR/MAJ/MIN、2% 阈值、七种处置、IQC/采购/仓库职责、记录保管 3 年……
>
> **报告口径（约 120 字）**：查见《来料检查作业指示书》（KSY-QMS-WI-10，A/0）规定了来料检查的抽样基准与免检、抽样、全数三档控制方式，明确了不良分级与不合格处置路径；抽查《进料检验报告》2 份，检验项目为外观、包装、材质证明、数量，结果均为合格。

**同一份取证，两种口径。**后者才是能进格的。

**这意味着产品必须有两个渲染器**：`分析视图`（给审核员自己看，可以长）和 `报告视图`（进报告，必须短）。

它只做了一个，而且是错的那个。

## 八、对我 07 号的四处修正

| # | 07 号原来写的 | 改成 |
|:--:|---|---|
| 1 | 8.4.1 拆 9 个义务点，6 段排完 | 补三维：**对象（供方）是第四维**，输出时压平成"抽查 N 家" |
| 2 | 判定档位：齐 / 有制度无记录 / 都没有 | **删掉"符合，附条件"这种中间态**，中间态只能是"未见 X"，不是"附条件" |
| 3 | 缺口用"未见 XX 记录"一句表达 | **缺口要单独走一份清单**（14 项那种），不塞进证据段 |
| 4 | 疑点五来源（缺失/矛盾/异常/比例/痕迹） | 换成**六型具体规则**（T1–T6），可直接实现 |

**第 3 条最重要**：它让我意识到"证据段"和"缺口清单"是两个不同的交付物，**不该揉在一起**。

真实报告里之所以"未见"那么少（ACM 4 次、中安质环 3 次、这份文档 0 次进报告），是因为**缺口被拿出去单列了**——企业拿到的是整改清单，报告里只留一句结论。

**这是个机构作业习惯，不是文风。**我 07 号把它当成句式选择，判断错了。

## 九、如果只从这份文档拿三样东西

1. **T1–T6 六型疑点规则**（第四节）——可以立刻写进校验器，五型误报低，且有现成测试用例。
2. **三分结构：必写 / 条件写 / 不写**（第六节用法 1）——它把"证据空间"和"报告内容"分开了，这是压缩的依据。
3. **"结论与自身发现矛盾"这一条校验**（第八节）——产品 B 最硬的一条规则，比我原来想的任何契约校验都具体。

**不要拿的是它的文本。**它的文本是 66KB 的取证分析，任何机构的报告格子都装不下。

## 十、一个留给你的判断

这份文档证明了一件让你安心的事：**深度取证是能做到的，而且不需要你是专家**——它把 KSY-QMS-WI-10 里的 AQL、CR/MAJ/MIN、七种处置路径全读出来了，这些是文档里写着的，不是专家才能看懂的。

但它同时证明了一件让你不安的事：**做到这个深度，一个条款就要 66KB。**845 条不可能这么做。

**所以真正的产品命题不是"能不能做到深度"，是"深度做到之后，怎么压成 400 字"。**

压缩规则是可以定义的（留对象名/数量/签署/日期/结论，删论证过程），但它需要你先承认：**取证深度 ≠ 输出深度。**这份文档最大的价值，就是把这个区别摆在了你面前。
