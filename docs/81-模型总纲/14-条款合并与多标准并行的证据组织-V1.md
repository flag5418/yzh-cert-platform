# 14 · 条款合并与多标准并行的证据组织

> 四个问题，四个规则。全部是可写死的，不需要"设计智慧"。
> 附一条对 13 号的自我修正：锚点只是召回器，不是判定器。

---

## 一、规则一：一行一个条款（你的建议成立，且有硬理由）

### 1.1 形态

一个检查项（条款 × 部门）如果含 3 个条款，就输出 **3 行**：

```
8.4.1  查见《外部提供过程产品服务控制程序》（KSY-QMS-P-15，A/0，2026.6.10），
       规定了外部供方评价、选择、绩效监视和再评价的准则…（约 150 字）

8.4.2  查见《来料检查作业指导书》（KSY-QMS-WI-10），明确了抽样基准与
       免检、抽样、全数三档控制…抽查《进料检验报告》2 份，结果均为合格（约 150 字）

8.4.3  查见采购合同/技术协议，规定了验收标准、变更通知义务…（约 120 字）
```

**每行前缀保留条款号。这是关键的小动作**——它让每一行都能被独立定位、独立核对、独立改成 NC。

### 1.2 为什么不做二次合并加工（三条硬理由）

| 理由 | 说明 |
|---|---|
| **丢归属** | 合并成通顺一段后，"这句是哪个条款的"就答不出来了。内审要逐条核对，一合就废 |
| **无法定位错误** | 一旦某句写错，合并后不知道改哪 |
| **合并本身会引入新错** | 合并需要"读懂两段再重写"，这一步是模型最容易编的地方 |

**而且这台机器在合并上一定做不好**：合并要求"理解两段的语义关系再重组"，正是 LLM 最容易产生幻觉的动作。**生成已经可能错，再合并一次就是错上加错。**

### 1.3 但要区分两种"合并"

| 类型 | 做法 | 判据 |
|---|---|---|
| **结构性合并**（一行装多条款，用条款号分隔） | **可以做**，机械拼接 | 合并后还能回答"这句属于哪条" |
| **语义性合并**（融成一段通顺的话） | **不做** | 合并后答不出归属 |

**一个检验：合并后的每一句，能不能指回某一条条款？能 → 可以合；不能 → 不许合。**

### 1.4 两种输出形态并存，按机构选

| 机构 | 形态 | 出处 |
|---|---|---|
| ACM | **一行 1 条款** | 表单 `ACM/QR-04-70 A/0` |
| 中安质环 | 一行 1–5 条款聚合 | 表单 `ZAZH—SHH/JL 006.2019` |

**所以"一行一条款"和"聚合行"不是对错问题，是机构配置项。**默认用"一行一条款"，因为更安全、可追溯；机构模板要求聚合时才合。

**不要写死一种。**这是产品配置，不是逻辑。

## 二、规则二：三体系的同号条款 —— 共享池 + 分流出

### 2.1 问题在哪

Q/E/H 三体系的 4.x 章，条款号相同、标题相同，但要求不同：

| 条款 | 9001 要求 | 14001 要求 | 45001 要求 |
|---|---|---|---|
| 4.1 | 理解组织及其环境（**质量相关**内外部因素） | 理解组织及其环境（**环境因素**） | 理解组织及其环境（**危险源**） |
| 4.2 | 相关方需求期望 | 相关方（含合规义务） | 相关方（含工作者协商） |
| 4.3 | 体系范围 | 环境管理体系范围 | OH&S 体系范围 |

**而企业通常只有一份手册，同时写三套。**

### 2.2 解法：证据共享，输出分流

```
【共用证据池】（取一次）
  管理手册 4.1 章节
  组织架构 / 职责权限
  内外部因素识别监视评价总清单
  相关方需求期望识别表

【各自特有证据】（各取各的）
  Q：质量风险与机遇分析评价表
  E：环境因素识别评价表
  H：危险源辨识及风险评价表
```

**输出成三行：**

```
Q4.1  查见《管理手册》4.1 及《内外部因素识别监视评价总清单》，识别了…（共用部分）
      另查见《质量风险与机遇分析评价表》，对…（Q 特有）

E4.1  查见《管理手册》4.1 及《内外部因素识别监视评价总清单》，识别了…（共用部分，与上同）
      另查见《环境因素识别评价表》，识别了重要环境因素…（E 特有）

H4.1  查见《管理手册》4.1 及《内外部因素识别监视评价总清单》，识别了…（共用部分，与上同）
      另查见《危险源辨识及风险评价表》，识别了重大风险…（H 特有）
```

**关键：前一句可以完全相同，差异只在"特有那份记录"。**

### 2.3 成本判断（这条很重要）

**三体系不是一个检查项做三遍。**

| 部分 | 次数 | 占比 |
|---|:--:|---|
| 共用部分（手册、组织、相关方） | **1 次** | 约 50% |
| 特有部分（因素识别表 ×3） | 3 次 | 约 50% |

**所以三体系的取证成本约是单体系的 1.5–2 倍，不是 3 倍。**这是一个实际的商业优势——**卖三体系，成本不是三倍。**

### 2.4 三个实现点

1. **共用池要显式标出来**：哪些证据被多标准共用（手册、组织架构、相关方清单、法规清单）
2. **特有证据的判据是可枚举的**：不是靠语义判断，是靠"这个标准的标志物"——E 看"环境因素/重要环境因素/合规义务"，H 看"危险源/风险/工作者协商"，Q 看"质量风险/顾客要求"
3. **同号不同标准必须分行**，绝不能合成一行。因为判定可能不同（Q 判符合、E 开 NC 是常见情况）

## 三、规则三：同体系多条款合并 —— 只做结构拼接

### 3.1 三种情况要分清

| 情况 | 例子 | 做法 |
|---|---|---|
| **A. 检查项合并**（机构把几个条款并成一项） | 7.5.1+7.5.2+7.5.3 合为"文件化信息" | 输出**一行一条款**（3 行），各自带号 |
| **B. 模板要求聚合**（机构表单一行装 1–5 条款） | 中安质环 | 输出**1 行**，内部按条款号升序分段 |
| **C. 语义合并**（融成通顺一段） | — | **不做** |

### 3.2 情况 B 的具体形态

如果机构要求聚合，行内这么组织：

```
8.5.1/8.5.2/8.5.4  查见《生产和服务提供控制程序》…（8.5.1 内容）…
                  对 8.5.2 条：查见《产品标识和可追溯性控制程序》，标识方法为…（8.5.2 内容）
                  对 8.5.4 条：查见《产品防护控制程序》，防护措施包括…（8.5.4 内容）
```

**规则：每段以"对 X.X 条："开头。**这样即使聚合成一行，归属仍然清晰。

### 3.3 一条不能破的底线

**合并只允许"顺序拼接 + 条款号标注"，不允许"改写"。**

判据：合并后的文字，逐句能倒推回某一条款；倒推不回去的句子，就是被改写过了，删掉重写。

## 四、规则四：不省 token，但要花对地方（并修正 13 号）

### 4.1 先修正我上一轮的说法

13 号我说"途径 ② 归档位置免费、命中率高"。**这个说法太粗，要改。**

**目录名匹配只能产生候选，不能定案。**理由：

- 目录名可能不准（实测：进料检验报告归在"21 放行"，内容是 8.4.2）
- 目录名只能覆盖记录类，程序/三阶/手册覆盖不到
- **一份文档可能同时属于多个条款**（内审检查表、管理评审记录、手册）

**所以正确的分工是：**

| 环节 | 干什么 | 目标 |
|---|---|---|
| **锚点（①–⑤）** | 把 99 份缩到 10–20 份候选 | **高召回，宁滥勿缺** |
| **语义分析（⑥）** | 逐份确认"这份到底相不相关、相关到哪条" | **高精确** |

**锚点是召回器，语义是精确器。两个作用相反，都不能省。**

### 4.2 现在的系统错在哪（这是根本诊断）

**现在的过滤是"精确优先"：只认条款号，号空了就整份丢弃。**

结果：**召回率 13/99 = 13%，漏了 87%。**

**应该是"召回优先"：先宽进（锚点全上，甚至放宽），再严出（语义逐份确认）。**

**这个方向一改，整个系统的行为就变了**——从"因为找不到就丢弃"变成"因为可能相关就先留着，再判断"。

### 4.3 token 该怎么花（分层）

不是"所有文档全文硬灌"，是**按文档在证据里的角色分配预算**：

| 层级 | 范围 | 做什么 | 预算 |
|---|---|---|---|
| **L1 全量头部** | 99 份全部 | 只抽文件名/目录/编号/日期/类型 | **极低**（规则，几乎无 token） |
| **L2 主证据** | 锚点命中的 5–10 份 | **全文语义分析，逐义务点抽答案** | **主要预算在这里** |
| **L3 候选确认** | 锚点弱命中的 10–20 份 | 只判断"相不相关、相关哪条"（不看全文细节） | 中 |
| **L4 手册** | 1 份 | **只读条款对应章节**，不整本读 | 中 |
| **L5 三阶/外来** | 若干 | 只读被引用的那几节 | 低 |

**关键：钱花在 L2。**L2 就是"报告里那几句话的来源"，必须读全、读细、抽准。

**L1 和 L4 省下来的钱，全部投到 L2。**

### 4.4 你说的"不能单看标题"要落到具体动作

**动作：每份候选文档，必须回答三个问题才算确认：**

1. 这份文档讲的是什么过程/对象？
2. 它涉及哪一条（可以多选）？
3. 它在证据里扮演什么角色（制度依据 / 实施记录 / 交叉验证）？

**三个问题都答了，才算"确认相关"。答不出第 3 个的，不进证据段，只进候选池。**

**这就是"不能单看标题"的落地方式——不是"多读一点"，是"必须回答角色问题"。**

## 五、四条规则合起来的样子

```
一个检查项（条款集合 × 部门 × 标准）
  │
  ├─ 若是三体系同号 → 拆成 3 行（Q/E/H 各一），共用池取一次
  ├─ 若是同体系多条款 → 拆成 N 行（一条款一行），或按机构模板聚合（对 X.X 条：分隔）
  │
  ▼
每行独立走：锚点召回 → 语义确认 → 打勾 → 拼 150 字
  │
  ▼
不做语义合并、不做二次加工
```

**输出最小单位 = 一行 = 一个条款 × 一个标准 × 一个部门。**

**这个单位越稳定，整套系统越好做。**因为：
- 可追溯（每行有条款号）
- 可核查（内审逐条对）
- 可局部重跑（哪行错重跑哪行）
- 可局部改判（哪行要开 NC 就改哪行）

## 六、这四条对你 12 月 15 日线的意义

**这四条都是"减负"规则，不是"加功能"规则：**

| 规则 | 减掉什么 |
|---|---|
| 一行一条款 | 减掉"多条款融合成一段"的重写工作（最难的部分） |
| 不做二次合并 | 减掉一轮可能引入错误的加工 |
| 三体系共享池 | 减掉 50% 的重复取证 |
| 锚点召回 + 语义确认 | 减掉"因为找不到而丢弃"的漏检 |

**四条全是把复杂度往下压。**这和你上一条说的一致——**制约在不在实现，在设计。这四条设计，都是在把实现变简单。**

**特别是第一条。**"一行一个条款"这个决定，把"如何组织多条款证据"这个看起来最难的问题，变成了"根本不需要回答"——因为不合并，就不存在合并怎么组织的问题。

**这是最省力的做法，也是最接近真实报告的做法。**
