# 13 · 匹配是核心 —— 六种途径与优先级

> 12 号说错了一件重要的事（手册）。这份先改错，再把问题收缩到**一个动作：怎么从一堆文档里找到该进报告的那几句话。**
> 属性池退到次要位置——它不参与"找"，只参与"找到之后打勾"。

---

## 一、先改错：12 号把手册说反了

我 12 号写"手册 5 万字一个字不用读，只取 4 个字段"。**这是错的。**

你指出的才是事实：**质量手册是真实报告里引用最多的东西。**

因为它承载的是只有手册才有的那部分内容：

| 条款 | 报告里的答案从哪来 | 能不能编 |
|---|---|---|
| 5.1 领导作用与承诺 | 最高管理者怎么做的、资源给了什么 | **不能**，企业自己写的 |
| 5.2 方针 | 方针原文、怎么沟通、怎么获取 | **不能** |
| 6.1 风险和机遇 | 企业认为的风险和机遇是什么、怎么应对 | **不能** |
| 6.2 目标 | 目标数值、怎么实现、怎么评价 | **不能** |
| 4.3 范围 | 体系覆盖什么、不覆盖什么及理由 | **不能** |
| 5.3 职责权限 | 谁管什么 | **不能** |

**这些审核员一个字都编不出来**，因为它们是这家企业根据自己管理形成的。审核员也不能否定企业的管理过程和作业指导——**企业资料是先于审核存在的既有材料**。

**所以手册的读法取决于条款性质：**

| 条款类型 | 手册的角色 | 怎么读 |
|---|---|---|
| 4.x / 5.x / 6.x（制度、领导、策划） | **主源，唯一来源** | 读对应章节，**要读原文** |
| 7.x（支持） | 主源之一 | 读对应章节 |
| 8.x（运行）、9.x、10.x | 只供"制度存在"半句 | 取编号 + 1 句 |

**8.4.1 手册确实只支撑半句——但 5.1、5.2、6.1 这些条款，离开手册就没有证据。我把一个条款的观察当成了通则。**

## 二、把产品定义缩到一句话

你说的这句是本轮最重要的一句：

> 我们做审核报告其实就一个目的，根据不同的条款，找到合适的证据信息，加工成证据而已，原理非常简单。

**所以产品只有三个动作：**

```
① 找（匹配）：这条款该看哪几份文档
② 勾（核对）：这几份文档里，有没有这条款要的东西
③ 拼（成文）：把"有"的部分拼成报告那几段
```

**疑点不属于这三个动作。** 它是加分项，一期不做（第七节）。

**现在系统的状态：①几乎没做（只靠一个锚点）、②做了但没拆、③没做（导出接口是空实现）。**

## 三、六种匹配途径（你说的 3 种 + 我补的 3 种）

你提出三种：条款匹配、过程/部门/作用匹配、LLM 语义匹配。**确实还有三种，而且其中一种是最强锚点，现在被完全浪费了。**

### 途径 1 · 条款直连（文档自己标了条款号）

| 判据 | 出处 |
|---|---|
| 文档目录/章节标了"8.4" | 程序文件目录、体系文件清单 |
| 文档写了"本文件适用于 8.4" | 三阶文件适用范围栏 |
| 检查表按条款排列 | 内审检查表、机构审核检查表 |

- **命中**：制度类证据（准则/职责/频次）
- **可靠性**：最高（文档自己声明）
- **现状**：系统只用它，且只有它

### 途径 2 · 归档位置（目录路径就是条款标签）★ 最强，且被浪费

**看真实归档结构（科斯亚实测）：**

```
04-记录文件/
  └─ 15 外部提供过程和产品服务的控制记录/   ← "15" = 8.4
       ├─ 01供应商评审表.doc
       ├─ 02合格供应商清单.doc
       └─ 03供应商业绩定期考核评估表.doc
```

**目录名"15"就是条款号，后面就是条款标题。机构归档就是按条款分的。**

- **命中**：记录类文档，命中率极高
- **成本**：不需要读内容，不需要模型，不花一秒
- **现状**：完全没用

**这条价值最大。** 86/99 份"覆盖条款为空"被整份丢弃，**但它们的目录路径全都写着条款号。**

**不是"抽不出条款"，是"没去读路径"。**

### 途径 3 · 引用链（制度文件规定要留什么记录）

**真实报告的核心写法就是这个：**

> 程序规定"应保留供方评价记录" → 查见《供应商评审表》

**匹配链条是：**

```
条款 → 找到程序 → 读程序里"应保留/应形成"的句子
     → 得到"该有哪些记录"的清单
     → 拿这个清单去记录库里找
```

- **命中**：实施类证据（评价/选择/监视/再评价/措施）
- **可靠性**：高（企业自己规定的）
- **额外收益**：清单上有、库里找不到 = 一个真实缺口

**这条是"从制度反查记录"，正好补上"记录不知道去哪找"的问题。**

### 途径 4 · 表单结构（表单字段 = 条款义务点的镜像）

**企业做表单时会照着条款设计字段。** 所以：

- 《供应商评审表》字段：资质 / 供货能力 / 产品质量 / 服务 / 交货 → **就是 8.4.1"评价准则"的项**
- 《进料检验报告》字段：外观 / 包装 / 材质证明 / 数量 → **就是 8.4.2"控制程度"的落点**

**"表头字段清单"可以直接匹配条款义务点。** 这既是匹配，也是取证捷径：**字段存在 = 该项被控制；字段为空 = 该项未执行。**

- **命中**：记录类，尤其是表单
- **可靠性**：中高（字段名是语义近似，要做同义词映射）
- **额外收益**：空字段数 = 免费的疑点

### 途径 5 · 过程/部门反推

- 程序文件名《外部提供的过程、产品和服务控制程序》→ 文件名点了过程
- 记录表头写"采购部"→ 部门标签
- 检查表按部门装订 → 部门页

- **命中**：找不到条款号时
- **可靠性**：中（部门对条款是多对多，需要"条款归哪个过程"的映射）
- **现状**：这条你已经有，但它只挂在计划详情页，没进真正喂模型的链路

### 途径 6 · 语义匹配（LLM 判断内容相关）

**兜底用，只用在前 5 种都失败的残余上。**

| 为什么放最后 |
|---|
| 慢（每次读全文，120 秒的来源） |
| 不可解释（说不出为什么相关） |
| 会编（"相关"和"编造"同源） |

**但有一种情况必须用它**：三阶作业指导、外来文件。文件名不带条款、目录不带条款、内容也不写"适用于 8.4"，但内容确实是。

比如《来料检查作业指示书》——**文件名没有 8.4，但它的抽样方案、不良分级就是 8.4.2 的控制程度。这种只能靠语义。**

## 四、什么时候用哪种：优先级链

**这是你问的那个问题的答案——"想不明白什么时候用什么方式"。**

```
① 条款直连      文档自己标了     → 命中即用，不判断
       ↓ 未命中
② 归档位置      目录/文件名带条款 → 命中即用
       ↓ 未命中
③ 引用链        从制度反查该有哪些记录 → 去库里对
       ↓ 未命中
④ 表单结构      表单字段 vs 义务点   → 同义词映射命中
       ↓ 未命中
⑤ 过程/部门反推  这条款归哪个过程/部门 → 取该部门的文档
       ↓ 未命中
⑥ 语义匹配      LLM 读内容判断     → 只在前 5 种都空时
```

**为什么这个顺序：**

- 前 4 种**全是规则可算**，不需要模型，快、准、可解释
- **①→②几乎零成本**（读路径、读目录，不读正文）
- ③ 最能直接产出"报告句式"（它给的就是"程序规定→查见记录"结构）
- **⑥ 放最后，因为它是唯一会花 120 秒且会编的**

**理想状态下，90% 的匹配应该在 ①–④ 完成，⑥ 只处理 10% 的残余。**

**现在系统的实际情况：只有 ①，命中率 13/99。**

## 五、概念分离：匹配 ≠ 打勾（这就是"风马牛不相及"的原因）

你说："我们的条款属性和文档结构就是风马牛不相及的东西。"

**这句话点中了我模型最严重的错：我把两个动作混成一个了。**

| 动作 | 用什么 | 输入 | 输出 | 要模型吗 |
|:--:|---|---|---|:--:|
| **匹配（找）** | 条款号 / 目录路径 / 引用链 / 表单字段 / 过程名 | 条款 + 文档清单 | 该看的 3–8 份 | **不要** |
| **打勾（核）** | **属性池（问句）** | 那 3–8 份的文本 | 有/无/是什么 + 出处 | 要 |

**属性池不该参与"找"，它只参与"核"。**

我之前说"条款 → 属性 → 对每份文档逐项打勾"，等于让属性池去当搜索器——**这就是"风马牛不相及"的来源**：拿"准则是否事先成文"这种问句去文档库里搜，当然搜不到，因为这问句里没有文件名、没有条款号、没有部门。

**正确的链是：**

```
条款 ──①条款号 ②目录 ③引用链 ④表单字段──▶ 锁定 3–8 份文档
                                              │
                                              ▼
                                     用属性池逐项打勾（核）
                                              │
                                              ▼
                                 有 / 无 / 是什么 + 出处 → 拼段
```

**先靠锚点找到材料，再用问句核对材料。两步用的东西完全不同。**

## 六、这解释了 86/99 为什么被丢

实测：99 份企业文档，86 份"覆盖条款为空"，被整份丢弃。

**但它们的目录路径全都写着条款号：**

```
04-记录文件/15 外部提供过程和产品服务的控制记录/   ← 15 = 8.4
04-记录文件/21 产品和服务的放行控制记录/           ← 21 = 8.6
```

**所以不是算法问题，是漏了一个免费锚点。** 只要加上途径 ②，那 86 份里的大部分立刻能救回，零模型成本。

## 七、疑点降二期（你的判断是对的）

你说："疑点有是加分项，没有，不影响审核员使用，他们看重的是结果。"

**接受。而且理由很硬：**

| | 一期（做） | 二期（不做） |
|---|---|---|
| 找文档 | 必须 | — |
| 打勾取证 | 必须 | — |
| 拼段成文 | 必须 | — |
| **跨文档矛盾（T1–T6）** | — | 加分项 |
| 缺口清单 | 一句"未见"即可 | 完整清单 |

**疑点的成本远高于收益：**

- 成本：要跨文档比对、要日期校验、要语义冲突检测，每一项都要单独实现
- 收益：审核员不看。他要的是"这段能进报告"

**所以一期只做一件事：让 25 条高频条款都能拼出可进报告的四段。**

**疑点如果顺手能出（途径 ④ 的空字段数、途径 ③ 的"清单有库里无"），就白送；出不来就拉倒。**

## 八、一期的完整闭环（缩到最小）

```
输入：企业文档包 + 条款
  ↓ ① 条款直连
  ↓ ② 归档位置        ← 新增，救回 86 份
  ↓ ③ 引用链          ← 新增，产出"程序规定→查见记录"结构
  ↓ ④ 表单字段        ← 新增，字段即义务点
  ↓ ⑤ 过程/部门（已有，接进链路）
  ↓ ⑥ 语义（残留兜底）
得到：每条款 3–8 份候选文档
  ↓ 用属性池逐项打勾（属性池每条只写"问句 / 归属类型 / 抽什么"）
得到：事实清单（有/无/是什么 + 出处）
  ↓ 按 4 段 1:2:2:1 排序 + 句式库
得到：可进报告的四段
```

**三个新增的匹配途径，全部是规则，不需要模型。** 这是这个方案里最便宜、收益最大的一块。

## 九、下一步该验证什么（一个即可）

**只验证一件事：途径 ② 能不能把 86 份救回来。**

**做法（不需要跑模型，半天）：**

1. 扫一遍那 99 份文档的**完整路径**
2. 用"目录名里的数字 + 目录名里的关键词"去匹配条款号和条款标题
3. 统计：99 份里能匹配上的有几份，8.4 能匹配到几份

**判据：**

- ✅ 8.4 匹配到 ≥ 3 份（评审表、名录、考核表）→ **途径 ② 成立**，一期的地基有了
- ❌ 匹配到 0–1 份 → 说明归档不规范，要靠途径 ③④ 补

**这个验证连模型都不用，纯读路径。半小时能出结论。**

**如果它成立，那"设计"这件事就可以停了——因为剩下的全是实现。**

## 十、一句话收

**产品不是"条款属性 + 文档属性"两个模型对接，是"六个锚点找材料 + 一套问句核材料 + 一套句式拼报告"。**

**匹配靠锚点，不靠属性。属性只管核对。** 这一句就是对我前面所有错误模型的修正。
