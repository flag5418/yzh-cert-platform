## 一、结论先行

1. **原型已完成、详细设计已可开发，但代码落地只走了约 15%**：审核员端在 `vol.web` 中实际只有 `Login.vue`(471 行) + `Workspace.vue`(431 行) 两个页面，其余目录（`TaskDetail/`、`Enterprise/`、`Message/`、`Profile/`、`components/`）**全是空壳**，`viewGird.auditor.js` 是 15 行空占位。
2. **两条线必须并行**：主线是审核员端功能落地（依赖后端接口，后端 `AuditTaskController` 目前是 21 行框架空壳，`AuditTaskService` 只有 `GetPageData`）；支线是 vol.web 工程化治理（工具链断裂、5 个巨型组件、259 处 `any`）。支线不阻塞主线，但**工具链必须在主线开工前修通**，否则新代码继续裸奔。
3. **有 8 项冲突必须先拍板**（文档之间、文档与代码之间互相打架），其中 5 项来自评测报告 P0，3 项是本次实测新发现。拍板前不动业务代码。
4. **建议总排期：6 个里程碑 / 约 32-42 人天**（M0 收口 2 天 → M1 地基 3 天 → M2 后端 8 天 → M3 前端主体 12 天 → M4 消息与导出 5 天 → M5 联调验收 5 天），质量治理穿插在 M1-M5 的空档执行。

## 八、质量红线（贯穿全程，不可违反）

1. **不碰 Vol 核心**：`components/basic/*`、`views/mes`、`extension/*`、`api/http.js`（行为等价重构除外）、`src/types` 只登记不改。整改集中在 `yzh/`、`certcore/`、`views/auditor/`、`views/admin/cert/`。
2. **后端只改 Partial**：禁改框架生成文件与 `.jsx`；新接口写在 `Controllers/**/Partial/` 与 `Services/**/Partial/`。
3. **SQL 一律放 `scripts/db/`**，禁止散落；脚本必须可重复执行。
4. **启停走脚本**：后端用 `scripts/backend/restart-backend.sh`，禁止手动 `kill` 或裸 `dotnet run &`。
5. **每阶段开始前 `git commit` 打 tag**，保证可回滚（沿用 `backup/before-*` 命名）。
6. **文档即宪法**：发现文档与实现不一致，改文档（或经确认后改代码），不静默迁就。
7. **新代码零 `any`、零 `console`**（门禁由 M1.1/1.3 保证）。
